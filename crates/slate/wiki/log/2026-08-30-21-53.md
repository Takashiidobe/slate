# macOS filesystem and directory ABI

_2026-08-30 21:53:46_

slate-sfzn.6.6: implemented Darwin sys/stat.h, dirent.h, fcntl.h, and
sys/statvfs.h layouts, derived from the bootstrapped XNU/Libc oracle
sources under target/macos-oracle (struct stat via __DARWIN_STRUCT_STAT64,
struct dirent via __DARWIN_STRUCT_DIRENTRY, real Darwin O_*/F_*/AT_*
values). sys/types.h already had correct Darwin scalar typedefs from
earlier stdio/locale work (slate-sfzn.6.3), so no changes needed there.

Added bits/darwin/{stat,dirent,fcntl,statvfs}.h following the existing
bits/darwin/stdio.h pattern, wired into the shared headers behind
__SLATE_LIBC_DARWIN. Excluded Linux-only surface that doesn't exist on
Darwin (getdents, posix_getdents, openat2/open_how, posix_fadvise/
posix_fallocate, splice/vmsplice/tee/fallocate, statx flags, F_SETLEASE/
seal/pipe-hint families) and fixed access-constant (F_OK/R_OK/W_OK/X_OK)
and seekdir/telldir visibility, which were gated behind _BSD_SOURCE even
though Darwin never auto-defines it.

Added libc-shim/macos-filesystem-headers.txt manifest, a header-compiles
test, and tests/fixtures/macos/filesystem.c with _Static_assert layout/
offset/ABI checks for struct stat (144 bytes), struct dirent (1048 bytes),
struct statvfs (64 bytes), and O_*/F_*/AT_FDCWD values, all confirmed
against the XNU oracle headers.

Fixed a latent gap in tests/differential.rs's macOS target-check helper:
it ran bare `rustc --crate-type=lib` with no libc crate, which broke the
moment a fixture's generated Rust referenced `libc::timespec` (Slate's
CLIB_RECORD_TYPES rewrite for struct timespec, used by struct stat). Now
builds a throwaway `cargo check` crate with libc = "0.2", matching what
the rest of the differential harness already does.

Also extended tools/probes/macos-libc.c with filesystem struct/function
coverage for when SLATE_MACOS_SDK becomes available.

fmt clean, clippy clean, libc profile 20/20, rewrites profile 90/90,
lowering profile 10/10.
