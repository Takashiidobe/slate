# Finish disable-passes regression fixup (slate-77g3)

_2026-09-04 22:06:52_

Closed out the raw-CIR pipeline regression sweep. Three real gcc-torture
bugs fixed:
- Local (non-global) const arrays of computed-goto label addresses
  (#cir.block_addr_info in a cir.const, stored via cir.store) weren't
  tracked - only the pre-hoisted-global case was. Added
  block_addr_array_values to propagate labels from cir.const into
  local_block_addr_arrays at the store site.
- Packed-struct volatile field access used read_volatile/write_volatile
  on misaligned addresses -> "unsafe precondition violated" abort.
  MemberPtr now carries an unaligned flag (record.packed vs field's
  natural alignment) and lower_load/lower_store fall back to
  read_unaligned/write_unaligned when set.
- __SlateVaArgs::next_arg skipped incrementing self.index for
  zero-sized struct varargs, desyncing every later va_arg read by one
  slot (va-arg-22).

Regenerated all 112 stale FileCheck fixtures via update_filecheck.py
(one manual catch: tests/fixtures/macos/fundamental_types.c shares a
basename with the bionic variant and needed its own pass).

Found and fixed a real precision bug this exposed: long_double_complex
mul/div were falling back to a naive component formula instead of
__slate_cf80_mul/div, because raw CIR now emits generic cir.complex.mul/
div ops (previously the disabled CIR pipeline pre-lowered these to
__mulxc3/__divxc3 calls, which calls.rs already mapped to the shim).
Added complex_cf80_binop in expressions.rs to route both through the
C shim, matching C99 Annex G's special-value handling for the two
multiplicative ops. add/sub/neg/conj/eq don't need this - no Annex G
exception applies, and they're already shim-backed per component.

lowering profile: fully green (10/10). rewrites profile has 3
pre-existing failures (one real: a pointer-to-reference idiomization
pass doesn't check for escape into a *mut field) - out of scope here,
not caused by this change, tracked separately.
