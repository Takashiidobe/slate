# Def-use edges added to the rewrite arena

_2026-08-27 22:28:14_

slate-y0qs.3.1: arena now tracks incrementally-maintained def-use edges,
closing a real gap in the target architecture's core loop (step 5:
"requeue: structural parent + def-use neighbors"), not just parallelism prep.

Mechanism (src/backend/engine/arena.rs):

- New `Expr::collect_vars`/`stmt_collect_vars` in rust_ast.rs mirror the
  existing `reads_var`/`stmt_reads_var` traversal exactly (same shape,
  same closure-shadowing handling) but collect the ident set instead of
  testing one name -- reuses proven traversal logic instead of a fresh
  hand-rolled walk.
- `Slot` caches each node's own-level `reads: Vec<Ident>` (not descending
  into child NodeIds); `Arena.def_uses: HashMap<Ident, Vec<NodeId>>` is
  the reverse index, kept in sync by `Arena::touch(id)` (diffs old vs new
  reads, called from `fill` at build time and after every successful
  rule application in `run_worklist`) and by `take(id)` (drops the node's
  entries on removal). `touch_subtree` covers rules that mutate a
  different node's content than the one dispatch matched on.
- `NodeKind::declared_name()` identifies Let/LetIf/For bindings.
  `run_worklist` snapshots `arena.def_use_neighbors(name)` before calling
  a candidate rule's `apply`, then requeues those neighbors afterward
  alongside self + structural parent -- unconditionally, whether the
  edited node survives the edit or not.
- `EarlyInlineTemps::apply` (inline_temps.rs) is the one existing rule
  that mutates a _different_ node's content (substitutes into
  `found.consumer_id`, possibly deep in its subtree) -- added an explicit
  `arena.touch_subtree(found.consumer_id)` call there so its cached reads
  stay correct; the generic per-`id` touch in run_worklist doesn't see it.

Query is a single HashMap lookup (O(uses)), not a full-function walk.
`cargo nextest r --release --profile rewrites` stays 110/110.
