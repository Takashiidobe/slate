# qualifier-preserving memchr/strchr/strstr etc via _Generic

_2026-08-26 20:19:28_

Corrected an earlier wrong claim that C23 qualifier-preserving memchr et al.
needed _Generic support slate doesn't have. False: _Generic is resolved by
Sema before CIR is emitted, so nothing generic survives to lowering time.
slate already uses it (tgmath.h, stdbit.h, tests/fixtures/c11.c).

Implemented the C23 gate (__STDC_VERSION__ >= 202311L) in string.h for
memchr/strchr/strrchr/strpbrk/strstr and in wchar.h for
wcschr/wcsrchr/wcspbrk/wcsstr/wmemchr, each as a self-referential
function-like macro: `_Generic((s), const T*: (const T*)(fn)(...), default:
(fn)(...))`. The inner call reuses the same name as the macro — valid C,
since the preprocessor "paints" a macro name during its own expansion so it
isn't re-expanded recursively. No __REDIR/asm-label indirection needed.

Verified: cargo run -- translate on a standalone _Generic+memchr snippet
lowers to a single ordinary `memchr` call (cast applied around it), then
extended tests/fixtures/c23_library.c to exercise both const and
non-const call sites for memchr/strchr/strstr/wcschr/wcsstr. Full
`--profile lowering` (10 tests) and `--profile rewrites` (118 tests) pass
with no regressions.
