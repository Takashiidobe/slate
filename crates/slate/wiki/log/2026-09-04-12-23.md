# compile-time selection builtins fold away before CIR

_2026-09-04 12:23:51_

Investigates slate-04q.47.7: __builtin_choose_expr, __builtin_types_compatible_p,
and _Generic all resolve entirely during Clang Sema/CodeGen, before CIR is
emitted -- confirmed by dumping -emit-cir for each construct directly (not
just reading generated Rust): the chosen branch's value/global appears as a
plain cir.const/cir.get_global, with zero ChooseExpr/TypeTraitExpr/GenericSelect
trace. This matches the C standard: __builtin_choose_expr's selector and
__builtin_types_compatible_p are both required to be compile-time constant
expressions, and _Generic's controlling expression's type is resolved
statically -- so there is no valid C program where any of these reach CIR as
a runtime construct. No lowering handling is needed or possible.

The Clang AST JSON (c_ast.rs's source-fact side) does retain ChooseExpr/
TypeTraitExpr nodes, but c_ast.rs's Node::kind is a plain String match, not
an exhaustive enum, so unrecognized kinds parse fine and are simply never
consulted -- no crash risk from the surviving AST nodes.

Added tests/fixtures/compile_time_selection_builtins.c using
@lowering-fn-begin/@rewrite-fn-begin (plain in-body markers failed --
"@lowering annotation 0 selected no checks" -- because mem2reg already
promotes these trivial locals to bare constants with no distinct statement
per source declaration, so the fn-scope marker was needed instead). Both
profiles green.
