# Integer and bool conversions on the slate frontend

_2026-09-30 14:52:24_

slate-p58o.3.5. Audited ValueKind::Convert for integer/bool kinds: sema already decomposes conversions into widen/truncate/reinterpret steps and lowers int->bool as a != 0 compare, so the existing 'as' chain matches C modular semantics. No Convert change was needed.

The only barrier found was not<bool> (C '!' on a _Bool), which the 3.4 Unary arm rejected; Unary now accepts Bool as well as integers. not<bool> is always logical: C '~' promotes _Bool to int first. Rust '!' on bool is logical not.

Added tests/fixtures/int_bool_conversions.c (truncation, widening, signed/unsigned reinterpretation, promotions, _Bool from int/u8/i64, from_bool, logical not). ctype_classify_fixup promoted. Named fixtures: bool.c already passed; casts.c blocks on float constants (3.6/3.28); uchar_conversions.c on struct mbstate_t (3.15/3.16).

Found slate-parser-dfrt: effects.rs Store arm returns the unhoisted RHS as the assignment result, so 'b = f()' calls f twice and 'a = b = f()' three times. Upstream IR bug, not a slate lowering bug. lowering profile green.
