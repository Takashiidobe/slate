# libc-shim: fill in easy features.md gaps

_2026-08-26 20:13:02_

Audited docs/src/features.md `[~]` items for pure declaration gaps (vs. real
feature work) and added:

- error.h: error(), error_at_line(), and their three globals — ordinary
  linkable glibc symbols, header-only.
- mcheck.h: mcheck(), mcheck_pedantic(), mcheck_check_all(), mprobe(),
  mcheck_status enum — same, header-only.
- stdlib.h: on_exit() declaration.
- string.h: strdupa/strndupa (slate-ig43) were plain extern decls but glibc
  only ships them as alloca-based macros (link fails). Replaced with real
  macros: strdupa = `strcpy(alloca(strlen(s)+1), s)`; strndupa uses alloca
  sized by strnlen + a static inline helper to memcpy/null-terminate,
  avoiding GNU statement-expressions (unsupported by slate's frontend).

Confirmed via research agent: libc-shim additions are pure header work
unless the function needs special call-site codegen
(function_identity.rs's Known table is only for optional static analysis).

Fixtures: tests/fixtures/gnu_libc_process_diagnostics.c (on_exit + mcheck +
error/error_at_line, ends via error()'s implicit exit(5)); extended
gnu_libc_platform.c for strdupa/strndupa. Both pass under --profile
lowering. Skipped qualifier-preserving memchr/strchr/etc (needs _Generic)
and attribute diagnostics for common/cleanup/etc (needs a new
variable/statement-attribute pass) as real feature work.
