# vendor gcc.dg c23 conformance tests

_2026-09-05 07:32:04_

Vendored GCC's C23-conformance test corpus alongside the existing
gcc.c-torture/execute one: gcc.dg/c23-*.c at GCC commit
76466425366d0f30effcdc1cfe729be28db4b88e, scoped to the dg-do run subset
(the other ~220 c23-*.c files are dg-do compile diagnostic checks -- nothing
to differential-test).

Added tools/filter-gcc-dg-c23.sh: selects dg-do run c23-*.c candidates, then
reuses filter-gcc-torture.sh's admission gate unchanged. Of 70 candidates, 42
admitted (28 rejected: 3 need dg-additional-sources we don't link, several
#include an unvendored sibling test file, the rest are genuine clang/GCC
divergences on corner cases). Differential classification split the 42 into
22 supported / 20 unsupported.

New suite tests/gcc_dg_c23_suite.rs mirrors gcc_torture_suite.rs's three-test
shape exactly (supported/unsupported/triage-report), wired into the lowering
nextest profile. Factored dg_option_flags()/dg_target_clause_applies()/
is_semantic_dg_flag() out of gcc_torture_suite.rs into tests/support/mod.rs
so both suites share the same dg-options parsing (added -fsignaling-nans and
-pthread to the semantic-flag allowlist for c23 cases that need them).

Provenance and COPYING3 documented in tests/fixtures.gcc-dg-c23/README.md,
matching the c-torture corpus's conventions.

Root-causing the 20 unsupported cases (upstream ClangIR blockers vs. genuine
Slate gaps: float.h/math.h constants, tag-alias duplication, complex-op
parameter hygiene, C23 unreachable()) is deliberately deferred to a follow-up
triage session -- no beads filed yet for the individual gaps.
