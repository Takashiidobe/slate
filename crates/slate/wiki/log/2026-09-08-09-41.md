# Fix glibc utmpx ut_tv compat32 layout, gated per-arch

_2026-09-08 09:41:25_

(slate-b66b.13.16) Probed struct passwd/struct group/struct utmpx in
tools/probes/linux-libc-abi.c, ran libc-abi-matrix across all 4 arches x
2 libcs.

passwd and group already matched both libcs exactly (POSIX-standard
shapes, no bug). utmpx already matched musl byte-for-byte (shim's
utmpx.h was a verbatim transcription of musl's header already).

Real bug: glibc's struct utmpx has an arch-dependent (not wordsize-
dependent) `ut_session`/`ut_tv` layout controlled by
__WORDSIZE_TIME64_COMPAT32, which is hardcoded per-arch in glibc's own
bits/wordsize.h -- 1 for x86, x86_64, AND arm (all three, despite x86_64
being 64-bit), 0 only for aarch64 (confirmed by cross-compiling a probe
against the real aarch64 glibc sysroot: WORDSIZE_TIME64_COMPAT32=0 there,
=1 on native x86_64). When set, ut_session is a bare int32 with no
padding, and ut_tv is a compact {uint32 tv_sec; int32 tv_usec} struct
(8 bytes total) instead of `int, int; struct timeval` (16 bytes) --
shim was using the wider musl-shaped scheme unconditionally, off by 4
bytes on ut_tv/ut_addr_v6 offsets and struct size on affected arches.

Fixed by gating on __SLATE_LIBC_GLIBC && (X86_64 || X86 || ARM), keeping
the existing scheme (matches musl and glibc/aarch64) as the else branch.

Also had to fix tests/fixtures.libc-test/api/supported/utmpx.c, which
asserted ut_tv is exactly `struct timeval` -- true for musl and
glibc/aarch64, but never true for real glibc x86_64/i386/arm. The old
shim's bug happened to make this always-struct-timeval assertion pass;
fixing the ABI exposed a wrong test assumption inherited from musl's
libc-test suite. Patched with the same __SLATE_LIBC_GLIBC-gated pattern
already used in sys_socket.c.

Verified: tools/libc-abi-matrix.py green for struct_passwd/struct_group/
struct_utmpx on all 4 arches x 2 libcs (3429/3429 records), cargo
nextest --profile libc 37/37, cargo fmt --check clean.
