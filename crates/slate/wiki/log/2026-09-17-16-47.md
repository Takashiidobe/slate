# Forward -m32 to the glibc-i386 oracle link step

_2026-09-17 16:47:59_

tests/support/libc_probe.rs resolve() built the i386 native-gcc link command from --sysroot alone, never passing -m32, so any i386 declaration/abi/runtime probe linked against the host's 64-bit libc paths and failed with 'cannot find ... inside <sysroot>'. Now the linker_env branch prepends extra_compiler_args(arch), which is already -m32 for Architecture::X86 and empty everywhere else, so ARM/AArch64/x86_64 are unaffected. Verified fully green end-to-end with SLATE_I686_SYSROOT=/ (this host's real multilib root); the shared .env still ships SLATE_I686_SYSROOT=/usr, which double-prefixes the sysroot onto gcc's absolute /usr/lib32 multilib path and still fails -- that value is also used by tests/differential_i686.rs for a different purpose (QEMU -L), so I left it untouched rather than risk that suite. libc_test_regression_suite's printf-fmt-n/syscall-sign-extend/tls_get_new-dtv failures are pre-existing (confirmed via git stash), unrelated to this change.
