# Pointer lattice: cast-peeling and PtrCopy/WriteBytes dst write detection (y0qs.4.6)

_2026-08-28 16:50:03_

Two bugs in src/backend/interproc/pointer*lattice.rs's ClassifyCtx, both
"evidence never reaches tracked/observe*\*" shapes:

1. try_alias only matched Expr::Var(source) exactly. CIR always bridges
   libc calls through a cast temp (`let _v1 = p as *mut c_void; free(_v1)`),
   so the alias never registered and observe_free never fired for any
   pointer whose C type wasn't already void\*. Fixed by adding a
   source_var() helper (mirrors raw_ptr_alias::source_var) that peels
   Cast before matching Var, used in try_alias.

2. CopyNonoverlapping/PtrCopy/WriteBytes dst was walked with the generic
   self.expr(dst), which is a no-op for a bare Var -- so memcpy/memmove/
   memset-style writes through `dst` never called observe_write. This
   made plan.mutable false for params only ever written via ptr::copy,
   which the y0qs.4 lift pass then cast to *const, producing calls like
   `std::ptr::copy(addr_of_mut!(f), arg0 as *const S, 1)` that fail to
   compile (dst wants \*mut). Fixed with observe_write_target(), which
   peels casts via source_var() and calls observe_write on the canonical
   binding instead of just recursing.

This was root cause of the two pre-existing gcc_torture/c_testsuite
compile failures (pr58365.rs, case_00204.rs) -- confirmed via git stash
that both failed identically before this session's changes.

Added tests/fixtures/ptr_lattice_free_cast_bridge.c for (1). Verified (2)
via full rewrites/lowering nextest profiles: 110/110 and 10/10 green,
fmt/clippy clean.
