# Un-ignore link.rs, add project-mode partial translation

_2026-09-06 14:43:43_

slate-i3nv.5: un-ignored tests/link.rs's link_fixture_runs_match_c (stale
"rewrite passes disabled" reason -- rewrites are exercised throughout the
rest of the suite). Diagnosing the failure surfaced two real, pre-existing
long-double bugs unrelated to the CLI consolidation work; filed as
slate-i3nv.5.1 (long double constant lowering leaves an SSA temp
unmaterialized when no Clang AST FloatingLiteral matches, hit by ++/--
desugaring on volatile long double) and slate-i3nv.5.2 (struct-of-two-
long-doubles corrupted across the extern "C" Rust<->C boundary -- Rust's
r.b ends up holding C's correct r.a, r.a stays at the unmodified input).
Both fixtures (long_double, long_double_aggregate) are skipped in the loop
via KNOWN_BROKEN_FIXTURES pointing at those bug ids; long_double_callback
still runs and passes.

Extended link.rs with a second test, link_project_partial_translation_runs_match_c,
composing the "link the rest as native C" capability with compile_commands
project mode instead of single-file lowered_program: tests/fixtures.link.project/partial
has a 3-file compile_commands.json (main.c, translated_b.c, native.c) plus a
translate.list marking which stems get translated. The test filters the
database to just the translated subset, runs it through
translate_project_from_database (real cross-TU project pipeline, not
single-file), compiles the excluded native.c to an object, links it into
the generated crate via a build.rs emitting cargo:rustc-link-arg (no cc
crate dependency needed since no C shim is involved), and diffs against an
all-C reference built from all three sources via compile_c_multi.

Verified: cargo nextest --release --profile rewrites, 85/85 passed, fmt/clippy clean.
