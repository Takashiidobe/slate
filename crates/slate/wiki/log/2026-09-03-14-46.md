# gnu_x86_intrinsics.c / gnu_x86_target.c: both blocked on single ClangIR builtin NYI

_2026-09-03 14:46:36_

slate-2o6o.7 triage: ran `cargo run -- translate` directly on both
tests/fixtures.unsupported/gnu_x86_intrinsics.c and gnu_x86_target.c to see
current state.

Both get much further than expected -- SSE2/SSSE3/AVX2 intrinsics via
immintrin.h, __attribute__((target("..."))) single-target selection,
__builtin_cpu_supports/__builtin_cpu_is, __get_cpuid*, the __builtin_ia32_*
fence/rdtsc/pause family, __builtin_nontemporal_load/store, __seg_fs/__seg_gs
segment pointers, and named register variables all lower through
clang -emit-cir fine already (slate's existing intrinsics_table.rs coverage
is broad). Each file fails on exactly one specific ClangIR codegen NYI:

- gnu_x86_intrinsics.c:33 `_pdep_u32` -> bmi2intrin.h's
  __builtin_ia32_pdep_si -- CIRGenBuiltin NYI
- gnu_x86_target.c:50 `__builtin_readcyclecounter()` -- CIRGenBuiltin NYI

Both errors come from clang's own CIRGenBuiltin, before slate's
frontend/lowerer ever sees CIR -- upstream gap, not fixable in slate. Same
class as slate-6v25.3 (atomic inc/dec) and slate-6v25.2/slate-pcek.21
(naked-function codegen). Marked slate-2o6o.7 blocked. Worth re-testing both
files after any upstream clang bump, since each may have further NYI
builtins hiding past the first one.
