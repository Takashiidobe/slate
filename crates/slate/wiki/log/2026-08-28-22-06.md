# StringOwned signature lift with UTF-8 content gate (y0qs.4.4)

_2026-08-28 22:06:15_

Implemented the char\*->String ptr_len signature lift, gated on a UTF-8 content proof, in interproc/length_lattice.rs.

Prior state: pointer_lattice resolved owned+freed byte buffers with string-shaped usage to ResolvedPtrType::StringOwned, but the consumer never lifted it -- StringOwned was excluded from collect_fn's buffer_ptrs pairing filter and both codegen sites were todo!(). So it silently stayed a raw \*mut i8 (differential-green only because REWRITES FileCheck is disabled).

Changes:

- Admit StringOwned to the pairing filter + has_owned/calls_free gating (kind.owned()); param type String, mut binding; String::from_raw_parts(ptr as \*mut u8, len, len) bridge; free removal reuses the owned path.
- Content gate (utf8_owned_fill_proof): at the Exact malloc call site, require the caller to fill the buffer with exactly one memcpy/memmove(dst==buf, n==len) whose source literal is valid UTF-8 over [0,len), exactly one candidate (ownership-transfer) call touching the buffer, no other buffer-touching calls, and no deref/index writes to the buffer (root-resolved through offset-temps + renames). Otherwise the Exact proof is withheld and the binding falls back to a raw pointer, matching the Str reject precedent.
- Kept specialize_string's !write guard (callee mutation not yet proven char-safe); the content gate only proves caller-provided content. Full write-source VALID classification (toupper/tolower/etc.) remains future work.

Fixtures: ptr_len_string_owned_worklist now lifts to String; added ptr_len_string_owned_invalid_reject (0xff fill) which stays \*mut i8. rewrites 110/110, fmt/clippy clean.
