# Pointer lattice: let FREE+unique precede ESCAPE in resolved() (y0qs.4.7)

_2026-08-28 17:00:27_

resolved() (src/backend/interproc/pointer_lattice.rs) short-circuited to a
raw-pointer Representation whenever self.escape was set, before ever
consulting write/unique/free/offset. escape is tainted by any call argument
passed to a non-candidate function (public, non-static, or lacking a raw ptr
param) as a conservative default in classify_call_arg's fallback -- so a very
common idiom (borrow a pointer into an ordinary helper, then free it later in
the same function) permanently pinned the pointer to RawConst/RawMut even
after 4.6 fixed FREE visibility.

Fix: only take the early escape-raw exit when NOT (unique && free). When
unique && free both hold, the free-gated rows in the match table already
account for offset (Owned vs Vec) regardless of write, so it's safe to let
that classification override the pessimistic escape default. When unique is
false (multiple live aliases observed), we still can't trust the free as
uniquely-owned, so the conservative raw fallback still applies -- preserves
existing behavior for the genuinely ambiguous case.

Verified via SLATE_PTR_LATTICE_DEBUG=1 on the exact repro from the bug
(touch(y) non-candidate borrow, then free(y) in use_and_free): now resolves
to Owned instead of RawConst. Did not confirm this end-to-end as a Box<i32>
in generated output -- lift_kind() returns None for ResolvedPtrType::Owned/
Vec, so this pass doesn't actually rewrite param types for free-gated rows
yet (that's y0qs.4.2, still open). Added tests/fixtures/
ptr_lattice_escape_then_free.c as a differential regression fixture (with
REWRITES-DAG/-NOT documentation lines, currently inert since REWRITES
FileCheck enforcement is intentionally off pending the fixup-pass migration).

Full rewrites (110/110) and lowering (10/10) nextest profiles green,
fmt/clippy clean.
