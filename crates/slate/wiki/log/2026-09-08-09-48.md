# Probe utsname/tms/mntent/ENTRY/aiocb/mq_attr and wait/mman/langinfo macros

_2026-09-08 09:48:42_

Added slate-b66b.13.17/.18/.19 ABI probe records to tools/probes/linux-libc-abi.c:
struct utsname/tms/mntent/ENTRY sizes/aligns/offsets, struct aiocb/mq_attr layout,
and WIFEXITED/WEXITSTATUS/etc macros, MAP_*/PROT_* flags, and nl_item values
(CODESET/D_T_FMT/ABDAY_1/etc). Validated with the full 4-arch x 2-libc matrix
(tools/libc-abi-matrix.py) against real glibc/musl oracles -- 4117 records, all pass.

Found and fixed a real bug: shim's struct aiocb (libc-shim/include/aio.h) was 4
bytes short of real glibc's size on 32-bit glibc only (i386/arm) -- all field
offsets matched but trailing reserved padding differs from musl's layout on
32-bit glibc specifically (64-bit glibc and both musl widths matched exactly
with no changes). Added a __SLATE_LIBC_GLIBC && __SLATE_WORDSIZE_32 gated
4-byte pad to close the gap.

Also found that WIFSTOPPED(status) needs a realistic stopped-process encoding
(signal in the upper byte, e.g. 0x137f) as the probe input -- the degenerate
value 0x7f alone is a genuine glibc/musl boundary-behavior divergence that
isn't a shim bug (real musl agrees with the shim there), so probing it would
have produced a false-positive mismatch.
