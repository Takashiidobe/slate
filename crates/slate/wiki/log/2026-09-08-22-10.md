# Bidirectional declaration matrix: reverse probes, macro checks, arpa/nameser.h fix

_2026-09-08 22:10:06_

Completed slate-b66b.14.9 (.4-.6): reverse-direction typedef/record/enum
probes (extract_shim_type_surface, reusing render_type_surface_probe
unchanged), bidirectional macro presence+value checks
(select_shim_object_macro_value_probes, select_cross_checkable_shim_macros,
diff_macro_names), and a new always-run test bidirectional_declaration_checks
in tests/libc_declaration_matrix_suite.rs scoped to arpa/nameser.h on
glibc-x86_64/musl-x86_64.

Fixed libc-shim/include/arpa/nameser.h: removed the unconditional
getopt.h/pthread.h/signal.h/unistd.h includes (unused, and absent from real
glibc's own header). Validated pre-fix (clean, specific failures naming the
leak) and post-fix (all four bidirectional checks green on both libc
profiles, no glibc regression).

Two bonus bugs found via the new checks and fixed:
- libc-shim/include/stdint.h + bits/types.h: INT_FAST16/32_MIN/MAX,
  UINT_FAST16/32_MAX and the underlying __int_fast16_t/__int_fast32_t
  typedefs used the LP64/glibc 64-bit convention for musl too; real musl
  uses 32-bit fast16/32 on all architectures. Added a __SLATE_LIBC_MUSL
  branch in both files.
- libc-shim/include/aio.h: struct aiocb's ABI-padding field used the public
  off64_t/off_t macros, which off64_t is only defined when
  _LARGEFILE64_SOURCE is set -- a real compile failure on every arch. Fixed
  by switching to the always-defined internal __off64_t/__off_t, matching
  what real glibc's own aiocb struct uses (padding must be feature-macro
  invariant).

Full `cargo nextest r --release --profile libc`: 45/46 pass. The one
remaining failure (declaration_matrices) is pre-existing and unrelated --
needs tests/fixtures.libc-static-test/* fixtures that were never
generated/committed for this repo, out of scope here.

Known limitations documented but not fixed: AST-dump file-attribution gap
under-counts typedefs for headers with deep transitive includes; oracle vs
shim macro-extraction scope asymmetry produces noisy but non-blocking
false-positive macro-name diffs for baseline headers like stdint.h.
