# FileCheck annotation comments leaking into generated Rust as doc comments

_2026-09-04 14:21:04_

The lowering profile's nextest suite had 17 fixtures failing FileCheck with a
stray `/// -fn-begin` (or similar) doc comment appearing right before a
function definition in generated Rust.

Root cause: `-fparse-all-comments` (used for genuine C-to-Rust doc comment
carrying) makes Clang attach *any* `//` comment immediately preceding a
declaration as a FullComment, including the `@lowering-fn-begin` /
`@rewrite-fn-begin` FileCheck region markers used by
tools/update_filecheck.py. Clang's doc-comment parser treats `@rewrite` as an
unknown inline command, swallows it, and leaves the remainder (`-fn-begin`)
as literal comment text, which the lowerer then emitted as a `///` doc
comment on the following function.

Fix: in `src/frontend/c_ast.rs::attached_comment`, skip FullComment nodes
that contain an `InlineCommandComment` named `lowering` or `rewrite` — these
are always our FileCheck annotation markers, never real documentation.

Separately, `branch_hint_builtins` was a genuinely stale FileCheck snapshot:
the fixture pins `-O1` via `fixture_clang_arg_overrides` in
tests/differential.rs, and at that opt level `__builtin_expect`'s CIR now
materializes its second (expected-value) operand as its own temp.

Previously regenerating a fixture with a clang-arg override meant manually
passing `SLATE_CLANG_ARGS` to `update_filecheck.py`. Added
`FIXTURE_CLANG_ARG_OVERRIDES` to tools/update_filecheck.py, a Python mirror
of `fixture_clang_arg_overrides()` in tests/differential.rs, so the script
picks up per-fixture extra args automatically by stem. Had to thread a
`fixture_path` through `translate_output`/`translate_instrumented` too, since
statement-level `@lowering-begin` fixtures translate a tempfile whose stem
doesn't match the real fixture name — without that the override would silently
no-op for any fixture using in-body markers.
