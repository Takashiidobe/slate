# Gate SysV IPC struct layouts by libc/wordsize

_2026-09-08 09:31:23_

(slate-b66b.13.13) Probed struct ipc_perm/shmid_ds/msqid_ds/semid_ds in
tools/probes/linux-libc-abi.c and ran tools/libc-abi-matrix.py --libc all
across all 4 arches x 2 libcs.

ipc_perm itself already matched both libcs (no bug there, despite the bead's
initial suspicion). The real bug was in shmid_ds/msqid_ds/semid_ds on 32-bit
(arm, i386): the shim's single unconditional layout was musl-shaped
(separate lo/hi placeholder pair per timestamp, followed by the real
32-bit time_t fields at the end of the struct). Real 32-bit glibc instead
inlines each timestamp immediately followed by one `_high` word
(shm_atime, __shm_atime_high, shm_dtime, ...) with no trailing real-time
fields and no leading lo/hi pair -- a different field count and order,
not just different names.

Fixed by gating bits/{x86,arm,riscv32}/{shm,msg,sem}.h and the generic
bits/msg.h fallback on __SLATE_LIBC_GLIBC, keeping the existing shape as
the musl branch (already verified correct) and adding the derived glibc
shape. Also found sys/msg.h's `#define __msg_cbytes msg_cbytes` alias was
unconditional; real glibc never defines it (field is bare __msg_cbytes
there), so gated it to !__SLATE_LIBC_GLIBC.

64-bit (x86_64, aarch64) already matched both libcs identically, no change.

Verified: tools/libc-abi-matrix.py green for all 4 structs on all 4 arches
x 2 libcs (2765/2765 records), cargo nextest --profile libc 37/37.
