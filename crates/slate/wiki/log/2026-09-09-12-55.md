# cfg-test filecheck migration

_2026-09-09 12:55:37_

Ported tests/directive_translate.rs's generated-Rust shape assertions from
rust.contains()/matches() to FileCheck, reusing the existing
support::filecheck harness rather than the @lowering/@rewrite region-marker
autogen tool (tools/update_filecheck.py has no notion of --targets=
multi-value splicing or SLATE_RAW_LOWER, so those invocations can't go
through it).

Two patterns used:
- Default-arg fixtures (error_unconditional, error_conditional,
  warning_directives, common_directives, unsupported_conditional) got
  handwritten `// COMMON[-NOT]:` lines appended to the .c fixture, matching
  the DIRECTIVES-DAG precedent already in warning_directives.c. COMMON is
  always active regardless of the `prefixes` arg passed to
  has_checks_with_prefixes, so these are picked up for free by the existing
  generated_directive_filecheck auto-collector test with no harness changes.
- Non-default invocations (-DFAIL_BUILD, -DPACKED_LAYOUT, --targets=,
  SLATE_RAW_LOWER, and plain add.c through the cfg CLI) can't be embedded in
  a fixture (the auto-collector always translates with default args), so
  added a check_rust_shape() helper that calls
  support::filecheck::check_generated_rust with an inline check string
  built in the test body.

Deliberately NOT ported: exact occurrence-count assertions
(rust.matches(...).count()) and stderr/diagnostic-text assertions
(translate_err output) — FileCheck only targets generated Rust, and COUNT
isn't in the DAG/NOT/NEXT directive set this harness supports.

Verified the new checks are load-bearing by breaking one on purpose
(generated_directive_filecheck failed) and restoring it (passed).
