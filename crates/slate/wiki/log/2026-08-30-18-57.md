# Revert speculative nested-scope dispatch fix in control_flow.rs

_2026-08-30 18:57:47_

While investigating slate-clvn, I added a lower_dispatch/lower_dispatch_inner
split plus lower_scope routing (nested cir.scope regions with >1 block got
their own dispatch state machine). Testing showed it had zero effect on the
statement_expr_local_label.c fixture (the real bug was upstream in CIRGen's
label naming, see the getOrCreateCIRLabelName llog entry), and it caused a
real regression: tests/fixtures.c-testsuite/case_00199.c has a nested
{ int c; goto outer; } scope where "outer" is a label in the *enclosing*
function scope. Treating the nested scope as a self-contained dispatch
produced todo!("cir.goto: unknown label") since the nested state machine
never sees labels outside its own region.

Slate already flattens function-level cir.scope nesting containing gotos via
an external cir-opt --cir-flatten-cfg --cir-goto-solver pass before the
lowerer runs (src/frontend/cir_input.rs), so lower_scope doesn't need to
special-case multi-block regions itself. Reverted control_flow.rs back to
unconditionally calling lower_region_ops in lower_scope.
