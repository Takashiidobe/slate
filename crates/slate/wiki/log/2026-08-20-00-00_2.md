# yarpgen fuzzing harness

_2026-08-20 00:00:00_

Added `src/bin/yarpgen_fuzz.rs` (905 lines) as a new fuzzing binary wrapping the [yarpgen](https://github.com/intel/yarpgen) random C/C++ generator, plus `tools/yarpgen-fuzz.sh` as the entry point (sets `SLATE_CLANG`/`YARPGEN_BIN` and runs `cargo run --release --bin yarpgen_fuzz`).

Pipeline per generated case: yarpgen generates a random C program from a seed → compile+run it with the host C compiler → translate it with slate → compile+run the Rust → diff stdout/exit code, same differential contract as the rest of the test suite. `CaseFailure` distinguishes failure stage (`YarpgenGen`, `CCompile`, `CRuntime`, `SlateTranslate`, `RustCargo`, `RustRuntime`, `OutputMismatch`) so a failing seed can be triaged by which pipeline stage broke rather than just "seed N failed". Supports a single seed, a seed range/count, or `--continuous` running, parallelized across `jobs` worker threads, with `--stop-on-failure` and a `--export-fixture` path to save a minimized failing case into the regular fixture tree.

`058d2229` grew `src/bin/seeds.txt` from an initial ~550 seeds to ~2000 after running the harness for a while — these are just recorded seed values known to generate valid, non-trivial programs, not curated regression cases (failures get exported as real fixtures instead, via `--export-fixture`).

This complements the gcc-torture/c-testsuite/chibicc/libc-test corpora with generated coverage rather than hand-picked cases — different failure surface than the earlier alive2/BNF fuzzer removed on `1fe29101`, since this generates and differentially runs whole realistic C programs rather than validating individual IR transforms.
