# wire g/imr output constraints for maybe_memory addresses

_2026-09-06 21:33:07_

slate-3f8g.4.15.4: fixed a silent miscompile for output constraints with a
memory alternative that also allows a register (=g, =imr, +g, ...).

Root cause: CIR groups cir.asm operands as out/in/in_out; only addressed
(maybe_memory) operands appear in out. The old code flattened all three
groups into one input_operands list and derived output_count from
raw_constraints.len() - input_operands.len(), which actually computed
*register*-output count, not total output count. Any addressed output with
a register alternative fell out of the output slice entirely and was parsed
as an input, reading its address as data with no deref and no error.

Fix: count real output arity from the '=' prefix, split out_group from
true inputs, and track an `indirect` flag on Constraint::Reg from the raw
constraint's '*' marker. Addressed+reg-eligible outputs bind straight to
the target place via place_or_deref_expr (no temp, no write-back
statement needed — out(reg)/inlateout(reg) write into the place directly).
Pure-memory addressed outputs keep the existing address-passthrough form.

Added tests/fixtures/asm_g_imr_output.c (=g, =imr, +g cases). Updated
wiki/concepts/inline-asm-support.md with the operand-group design. Full
rewrites profile (85 tests) passes.
