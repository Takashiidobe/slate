# temp-inlining stale __v prefix regression

_2026-09-05 13:17:54_

Rewrite-engine-v2 temp inlining (LateInlineTemps/EffectfulTempForward),
structure_dispatch's switch temp detection, and the interproc pointer
lattice's is_temp_name all matched compiler temps via strip_prefix("_v").
Commit 49a4c7e9 renamed the lowerer's temp scheme from _v{n} to __v{n}
(next_temp in src/frontend/lowerer/values.rs) but didn't update these three
detectors, so every temp silently stopped matching is_temp_name and no
inlining/switch-temp/pointer-lattice logic fired on any temp again -
regressing add.c and everything like it back to fully unfused lets.

Fix: added a single shared temp_index/is_temp_name pair in
src/backend/rust_ast.rs (strip_prefix("__v")) and pointed inline_temps.rs,
structure_dispatch.rs, and pointer_lattice.rs at it instead of each keeping
a private, driftable copy of the prefix logic.

Verified via `cargo run -- translate tests/fixtures/add.c`: main collapses
back to `printf(c"%d\n".as_ptr(), add(2, 3)); exit(0)` instead of five
separate lets. tests/fixtures/add.c's DAG-style FileCheck blocks are
handwritten (not tool-generated) and already tolerate either shape, so no
regen was needed there.
