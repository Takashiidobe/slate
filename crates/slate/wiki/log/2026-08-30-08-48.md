# cross-block liveness must follow inlined address-forwarding ops

_2026-08-30 08:48:58_

slate-a28e.3: temps referenced outside defining dispatch block (E0425, 25x in zstd_double_fast/zstd_opt). Root cause: at -O3 mem2reg promotes a const pointer to an SSA temp (e.g. %828 dictMatchState). A get_member off it (%829 = &dms->cParams) is inlined as a member_ptr, not materialized, and its base expr (*_v83) is captured at def time. cross_block_live_values only flagged direct CIR operands per top-level block, so %829's use in a later flattened block (--cir-flatten-cfg/--cir-goto-solver split bb0 into dispatch states) was NOT attributed to %828. %828 stayed a local 'let' in state 0 while the inlined expansion (*_v83).cParams referenced it in state 7 -> out of scope. Fix (src/frontend/lowerer/analysis.rs): after building def/use sets, fixpoint-propagate a result's use-blocks back to the base operands of inlined address-forwarding ops (GetMember.addr, GetElement.base+index, ComplexReal/ImagPtr.operand). Now the base gets hoisted cross-block. Test: tests/fixtures/goto_temp_cross_state.c (two-level member chain across a goto). This bug only shows at -O2+, so added a per-fixture clang-arg override map in tests/differential.rs (fixture_clang_arg_overrides) passing -O2 for it. zstd E0425 count 25->0; unmasked errors filed as slate-a28e.4-.8.
