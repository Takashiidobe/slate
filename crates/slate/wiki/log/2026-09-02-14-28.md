# Wide _BitInt case values lower as const patterns

_2026-09-02 14:28:22_

slate-c6jq.2. A `_BitInt` wider than 128 bits lowers its selector to
`bitint::BInt`/`BUint`, for which no Rust numeric literal exists, so every such
switch emitted `todo!("cir.switch: unrepresentable case value")`.

Two defects, both fixed here:
- `case_value_digits` matched only `Attr::Int`, but CIR case values arrive as
  `Attr::CirInt`. The entire bitint case-pattern path had therefore never once
  fired, at any width.
- Even reached, `Pattern::Guarded` was the wrong representation. `from_decimal_str`
  is a `const fn` and `BInt` derives `PartialEq`/`Eq` over `[u8; BYTES]`, so a
  hoisted `const` item is a legal structural-match pattern.

`Pattern::Const(Ident)` is new; codegen prints it as a path. Deliberately not
`Pattern::Binding`, which renders identically but would be mis-analysed as an
irrefutable binding. Const names are a pure function of width, signedness and the
decimal digits (`__CASE_B256_1701...`, `N` prefix for negatives), so no interner
state is threaded and equal values dedup across functions. `cir_ops` collects them
into a `Vec<BitintCaseConst>` sink that `control_flow` hands to
`Lowerer::register_bitint_case_consts`; `Item::Const` already existed.

Ranges still lower to `Pattern::Guarded` — slate-c6jq.3.

arm, a lone value, and a negative). Found and filed slate-763o on the way: `BInt <<
