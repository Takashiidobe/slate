# Migrate fixtures to compile_commands.json, fix shared-types anon-record naming

_2026-09-06 13:55:08_

Completed slate-i3nv.3: migrated every tests/fixtures.multi/* (28 dirs) and
applicable tests/fixtures.library/* dir to a checked-in compile_commands.json,
generated via `bear` against a real clang invocation (directory relativized
to "." so the fixture stays portable). tests/support/mod.rs's
translate_project* helpers now transparently prefer a fixture's own
compile_commands.json and fall back to synthesizing one on the fly for
directories that don't have one (chibicc corpus, yarpgen-generated cases) --
so most call sites needed zero changes. Rewrote the ~15 cross_tu.rs tests
that still built ad hoc commands or used --lib/--target/--source-manifest
directly onto the unified --compile-commands entry point; deleted
library_project_source_manifest_selects_translation_units (tested the
removed --source-manifest flag) and uart_library_preserves_exported_volatile_io
(duplicate of the now-fixed generated_library_filecheck sweep, which now
actually compiles each library fixture instead of only FileChecking it).
Removed the source_manifest and uart fixtures (orphaned by those deletions).
Also fixed yarpgen.rs and its failure-repro script, which were broken by the
plain-dir CLI removal but out of this issue's named scope.

Also fixed slate-5efu (shared_anonymous_record): the project-wide shared-types
pass built shared_records straight from raw AST-fact records, so an anonymous
member's field type kept its AST-fact name (e.g. "_unnamed_at_read.c:5:3_")
instead of the per-TU CIR-local ordinal name ("anon_0") that per-TU lowering
and field codegen actually use, leaving types.rs referencing an anon type it
never defined (E0425). Now runs reconcile_anonymous_member_types (exported
from frontend) against shared_records for every loaded module before the
transitive referenced-type pull-in, exactly mirroring what per-TU
lower_with_project already did for its own local records.

Verified: full rewrites nextest profile passes (93/93; previously 2 failures,
both now fixed -- the anon-record bug, and an unrelated stale gcc.dg
FileCheck snapshot regenerated via tools/update_filecheck.py per user
direction). cargo fmt/clippy clean.
