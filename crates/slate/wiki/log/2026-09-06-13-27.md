# Unify translate-project into one compile_commands path

_2026-09-06 13:27:38_

Collapsed the 4 near-duplicate translate-project implementations in
src/main.rs (plain-dir bin, plain-dir --target bin, manifest-based --lib,
compile_commands --lib) into one `translate_project_with_compile_commands` +
`translate_project_command` dispatcher. --lib, --target, --source-manifest,
and plain-dir input are gone; every project translation now requires
--compile-commands, and crate shape (bin vs lib) is auto-detected from
whether any translation unit defines main, mirroring Rust's own main.rs vs
lib.rs distinction.

Adopted the compile-commands path's per-variant fact tracking (more correct
than the old plain-dir global-fact approach) for both shapes, and a single
record/enum shared-type threshold (1 occurrence for lib, 2+ for bin, since a
lib's modules are all pub and any named type could be part of the public
surface).

Dropped the tests/-dir auto-discovery + separate integration-test-crate
generation feature (ProjectInfo.shared_type_crate/cross_module_crate): it
only existed in the now-deleted manifest-based --lib path. Confirmed with
user to not port it forward; superseded by the link-test extension to
project mode (slate-i3nv.5).

Verified via manual smoke test (no test fixtures reference the new CLI shape
yet, that's slate-i3nv.3): lib-mode multi-database cfg merging still works
and the generated crate type-checks; bin-mode auto-detection works and a
plain bin fixture compiles; shared_anonymous_record still reproduces its
pre-existing anon-record-naming bug unchanged, confirming this refactor
didn't alter lowering behavior, only entry points.
