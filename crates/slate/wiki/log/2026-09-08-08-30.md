# Fix glibc/musl msghdr field-type mismatch in libc-shim

_2026-09-08 08:30:22_

libc-shim/include/sys/socket.h gated msg_iovlen/msg_controllen/cmsg_len
type on __SLATE_WORDSIZE_64 alone, so 64-bit musl got size_t like glibc.
Real musl always keeps int/socklen_t and pads with an explicit int field
on LE64 to preserve layout size; glibc genuinely widens the field itself.
Regated on __SLATE_LIBC_GLIBC && WORDSIZE_64 for the size_t branch, added
matching padding fields for the non-glibc (musl/bionic/generic) branch.

Also fixed tests/fixtures.libc-test/api/supported/sys_socket.c (slate-b66b.13.1):
the libc-test API fixture was a straight musl-derived import asserting
int/socklen_t unconditionally, which never matched glibc's real ABI.
Gated the same three fields on __SLATE_LIBC_GLIBC to match reality per libc.

Verified: full `libc` nextest profile now 37/37 passing (previously failed
sys_socket compile for x86_64_glibc).
