# fix complex__pr47473: recover CIR-synthesized imaginary-negation constants from AST

_2026-09-05 14:15:07_

slate-7jv4.13: `0.2L - 0.3iL` failed with `todo!("long double constant
without Clang AST value")`. CIRGen decomposes real-minus-imaginary complex
subtraction into a synthesized real=0 constant and a directly negated
imaginary constant, both stamped with the BinaryOperator's location instead
of the literal's, so the loc-keyed `floating_literals` lookup always missed
-- and CIR's own printed fp text is double-precision-lossy there, unlike
literal-derived long-double consts (~19-digit precision).

Fix: added a per-function ordered fact queue (`imaginary_promotion_consts`,
c_ast.rs) populated by recognizing `FloatingLiteral - ImaginaryLiteral`
(`_Complex long double`) directly in AST traversal order, carrying the
full-precision literal text negated via the existing
`negate_floating_literal_fact`. `lower_const` (storage.rs) now tries
`next_imaginary_promotion_const` before giving up, gated by a
numeric-plausibility check against CIR's own `Attr::CirFloat` text so a
mismatch degrades to the old `todo!()` instead of a wrong value. Mirrors
the existing `next_macro_const_expr`/`next_enum_const_expr` pattern.

Also found (and hand-fixed for this fixture) a real bug in
`tools/update_filecheck.py`: blanking `@lowering-fn-begin` marker comments
during instrumentation changes which leading file comment Clang attaches
to `main`, so generated CHECK lines can assert content the real translator
never emits. Generator bug itself is unfixed -- follow-up.

Promoted `complex__pr47473.c` to `tests/fixtures.gcc-dg/`; both suite
tests pass under `lowering` and `rewrites` for this fixture.
