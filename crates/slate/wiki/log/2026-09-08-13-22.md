# 8-way runtime differential matrix

_2026-09-08 13:22:29_

Widened slate-b66b.5 from musl-only to the full 4-arch x {musl, glibc}
runtime differential matrix, since libc_probe::resolve() already builds
working glibc cross toolchains for arm/aarch64/i686 (proven by the ABI
matrix) and rustup already ships musl std for all 4 arches on this host.

Added tests/libc_runtime_matrix_suite.rs (new `libc_runtime_matrix` test,
wired into the `libc` nextest profile). For each (arch, libc) pair it:
- resolves the C oracle toolchain via libc_probe::resolve (reused as-is)
- resolves a matching Rust CrossTarget (musl: plain clang + lld, no
  slate-musl sysroot needed since rustup's musl targets are self-contained;
  glibc: reuses config.linker/linker_args from the same resolve() call)
- translates + builds + runs 3 small portable fixtures (cstr_literal_arg,
  alias_global, extern_char_ptr_ffi) against both, comparing stdout/exit
- skips a target gracefully (not a failure) when its sysroot/rust-target/
  toolchain prerequisites are missing

Bumped `build_batch` in tests/support/mod.rs to `pub` so the new suite can
drive Cargo cross-builds directly instead of duplicating the batch-crate
machinery.

Key finding: musl-clang/musl-gcc wrapper scripts for x86_64/i686 silently
drop clang's auto-injected `-lc`/libgcc from the link line unless `-lc`/
`-lgcc` are passed explicitly by the caller (musl-gcc's own -l-user
marker logic only wraps args when the caller supplies at least one -l*
flag). libc_probe::resolve()'s existing linker_post_args already work
around this; a naive single-command `clang -static ... -lm` invocation
does not. AArch64 musl needs libc_probe's fully manual -nostdlib link
(bypassing musl-gcc.specs) because the host's aarch64-linux-gnu-gcc
defaults pull in a nonexistent -latomic_asneeded.

All 8 targets pass locally: 3 fixtures x 4 arch x 2 libc, ~5-15s total.
