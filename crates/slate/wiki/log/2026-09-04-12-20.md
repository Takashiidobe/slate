# safe slice idioms for local-buffer mem* rewrites

_2026-09-04 12:20:46_

Implements slate-04q.47.8: libc_call.rs now tries a safe rewrite before
falling back to the existing raw-pointer intrinsic for memcpy/memmove/memset.

CallCtx::lifted_local_array(i) chases an arg through peel_ptr_view like
lifted_arg does, but stops at a Let whose type is Type::Array (unwrapping the
aligned::Aligned<A,[T;N]> wrapper large stack buffers get), returning (var,
elem type, len). Only Prim::U8/I8 qualify -- Bool is excluded since `as bool`
isn't valid Rust and would break a memset fill cast.

Fires only when both operands resolve to *distinct* local arrays (separate
stack allocations can't alias, so no overlap check needed) with matching
element type, and the count is a compile-time literal <= both lengths.
memcpy requires distinct arrays; memmove also accepts dst==src (self-copy
no-op) via `arr.copy_within(0..n, 0)`. Offset pointers, runtime lengths,
heap pointers, and length mismatches fall through unchanged.

Replacement still lands inside the pre-existing `unsafe {}` block (matches
the existing StrCmp rewrite) -- stripping now-superfluous unsafe wrappers is
a separate, larger cleanup.

Added tests/fixtures/mem_safe_slice_idioms.c and regenerated
local_libc_mem.c's REWRITES block. rewrites profile (93 tests) and lowering
profile green, aside from a pre-existing unrelated branch_hint_builtins
FileCheck failure left over from before this session's /clear.
