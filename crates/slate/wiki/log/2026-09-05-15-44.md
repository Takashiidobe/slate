# slate-1gfo: fix 5 directive_translate failures

_2026-09-05 15:44:19_

Two independent root causes.

1. query_macros() in src/frontend/toolchain.rs checked clang's exit
   status BEFORE parsing stdout. An active #error/#warning directive
   makes clang exit nonzero while still emitting a complete, valid
   -dM -E macro dump on stdout. Reordered: parse macros first, only
   treat nonzero exit as failure when the macro map came back empty.
   Fixed 4/5 failing tests. Confirmed via strace on the failing
   nextest run that clang's argv/exit code matched this exactly;
   manual repro without nextest had masked it.

2. raw_lower_skips_fixups_for_directive_translation asserted
   `let _v0: i32 = ...` (single underscore). Raw lowering (no
   fixups) names temps via values.rs `format!("__v{}", ...)`
   (double underscore); `_v{}` is the rewrite-engine's naming
   (structure_dispatch.rs), which never runs under
   SLATE_RAW_LOWER=1. Stale assertion, not a code regression.
   Updated the literal to `__v0`.

All 29 directive_translate tests pass under --profile rewrites.
