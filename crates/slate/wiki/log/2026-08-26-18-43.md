# cir.address_of_return_address reachable but harness-blocked (slate-3i0x.10)

_2026-08-26 18:43:01_

_AddressOfReturnAddress (X86LibBuiltin, void*()) reaches cir.address_of_return_address cleanly with just -fms-extensions plus a hand-declared prototype -- works even on the default x86_64-unknown-linux-gnu target, no MSVC cross-compile needed, and produces a normally runnable binary. However tests/differential.rs has no per-fixture clang-arg mechanism: FixtureFlavor (Default/Bionic/Macos/Msvc) bakes one fixed target+define set shared by every fixture in that flavor. The existing msvc/ fixtures only do static _Static_assert layout checks via FileCheck (LOWERING-MSVC prefixes), not real execution -- there's no Windows runtime to run a binary against for a true differential. Adding -fms-extensions to the Default flavor globally to reach this one op risks subtly changing semantics for the entire existing corpus (anonymous structs, __declspec, etc). Repro:  +  prototype + a call. Todo fallback retained; a real fix needs a per-fixture extra-clang-args field added to the harness, which is a separate, broader change.
