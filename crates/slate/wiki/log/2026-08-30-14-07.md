# slate-a28e.7: type void*-view element from the actual dereference cast, not the void* param

_2026-08-30 14:07:05_

E0508 in zstd_compress_literals.rs: an interprocedural pass (apply_view in
length_lattice.rs) synthesizes a bounds-tracked byte-view local
(`__argN_view = from_raw_parts(...)`) for pointer params that get indexed
via matched offset arithmetic, then rewrites `*offset_temp` reads to
`view[idx]`. It typed the view using the pointer *parameter's own declared
type* — for `void*` params that's `core::ffi::c_void`, which is neither
Sized nor Copy, so `view[idx]` used at a value position moved a non-Copy
element (E0508). C never dereferences void* directly, so a void*-typed
param always has some concrete cast (`(const unsigned char*)src`,
`(const int*)src`, ...) at the point of indexing — that concrete type was
being discarded.

First attempt: hardcode void* views to `u8`. Caught before landing (user
question, "is unsigned char the only cast that hits this?") — a void* cast
to a wider type (`(const int*)src)[i]`) would still compile-error before
the fix, but a blind u8 substitution would make it compile with silently
WRONG stride (byte-indexing where the C source intended int-indexing),
turning a compile error into a runtime correctness bug.

Actual fix: `matched_offset_temps_with_types` now also returns, per
matched offset temp, the pointee type of the intermediate cast feeding
`.add()/.offset()` (captured via a new `collect_let_types` walk over
`Stmt::Let { ty, .. }`). `apply_view` uses that concrete type for void*
params, only falling back to `u8` if no cast was found. Verified both
shapes: `unsigned char*` cast -> `[u8]` view (tests/fixtures/void_ptr_byte_view.c),
`int*` cast -> `[i32]` view (tests/fixtures/void_int_cast_view.c), both
differential-clean under lowering+rewrites. zstd (c-corpus): E0508 count
0 (was 1); no new errors introduced.
