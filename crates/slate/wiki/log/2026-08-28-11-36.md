# Finish raw_ptr_alias structural elision pass

_2026-08-28 11:36:51_

Continued src/backend/engine/rules/raw_ptr_alias.rs (structural raw-pointer
alias elision -- not a pointer_lattice consumer, kept purely structural per
this session's discussion; y0qs.4.2's actual lattice consumption still needs
a better-fitting pass, deferred).

Found and fixed two real bugs while making the debug eprintln!s (left over
from active debugging) reproduce cleanly:

1. source_var() peeled through Cast, but the elision replaced every use of
   the aliased name with a bare Expr::Var(source), silently dropping the
   cast. When source's real type differed from the declared type (e.g. a
   void*-to-struct-ptr cast), this produced ill-typed Rust
   ((*arg0).field on a *mut c_void). Fixed by cloning the full init expr
   (cast included) as the replacement instead of Expr::Var(source).

2. The rule rejected eliding `p` whenever a def-use neighbor was a
   transient CIR compiler temp (`let _v0 = p;`) that a later pass
   (EarlyInlineTemps) would inline away -- by the time p's node was
   visited, the temp hadn't been cleaned up yet, so elision was
   permanently missed. Tried a general engine-level fix first (a
   name->declaring-node index in Arena + dirty-requeue on read-set
   change), but it exposed a latent bug in some other existing rule --
   with raw_ptr_alias fully disabled, the same gcc-torture regressions
   still fired, proving the general requeue change had too broad a blast
   radius for this task. Reverted engine/mod.rs and arena.rs to
   session-start state. Fixed locally instead: raw_ptr_alias now
   recursively sees through pure-rename Let temps
   (all_uses_deref_transitively/pure_rename_target) when deciding
   eligibility, using the requeue the engine already provides (p's
   removal already requeues its precomputed def-use neighbors, which
   includes the temp).

Validated: cargo run -- translate on two scratch fixtures (plain
deref-only param, and a q-aliases-p case) -- both now elide down to using
arg0 directly. cargo nextest r --release --profile rewrites: 110/110
(gcc-torture regression from bug #1 is gone). --profile lowering: 10/10.
fmt/clippy --all-targets clean.

Left open: raw_ptr_alias is NOT the lattice's first consumer (per user
decision this session) -- y0qs.4.2 still needs a pass that actually reads
PointerFact/PointerBinding, e.g. one gated on the lattice's UNIQUE bit
instead of re-deriving it structurally.
