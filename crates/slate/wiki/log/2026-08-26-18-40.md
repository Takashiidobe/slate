# cir.cpuid unreachable with current toolchain (slate-3i0x.9)

_2026-08-26 18:40:27_

cir.cpuid only emits from the MSVC-style __cpuid(int*, int) builtin, which requires -fms-extensions plus a prototype declaration matching TargetLibBuiltin's signature exactly. glibc's cpuid.h uses inline asm (cir.asm), never cir.cpuid. clang's intrin.h only exposes the MSVC __cpuid declaration when the target triple is windows-msvc (#ifndef _MSC_VER guards it), and compiling for x86_64-pc-windows-msvc with our CIR-enabled clang fails separately (createCXXABI: C++ ABI kind NYI, plus missing MSVC-side headers). The only way to reach cir.cpuid is a hand-written extern prototype for __cpuid with -fms-extensions bolted on with no header backing it -- not a genuine C fixture, and SLATE_CLANG_ARGS would need to change project-wide (affecting every other fixture) for a single op with no real C source path to it. Recorded as unreachable with the current toolchain/target; todo fallback retained.
