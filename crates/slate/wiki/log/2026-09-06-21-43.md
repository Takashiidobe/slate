# add o/V memory constraint variants

_2026-09-06 21:43:27_

slate-3f8g.4.15.5: modeled GCC's o (offsettable) and V (non-offsettable)
memory constraint letters, previously unconditional errors.

Audited CIR: confirmed via clang dumps that =o/=V/+o/+V produce the exact
same *o/*V raw-constraint and maybe_memory address shape as m — no extra
info to distinguish offsettable-vs-not at the CIR level, and Slate always
materializes the address in a register regardless, so the distinction is
moot for correctness.

Fix: strip_memory_marker (asm.rs) now treats ConstraintAtom::Offsettable
and NonOffsettable as memory-like alongside Memory, so o/V (and +o/+V)
fold into the existing Constraint::Memory address-passthrough path used
for m — same code, no new branches needed in intrinsics.rs since the
maybe_memory output wiring from slate-3f8g.4.15.4 already dispatches on
Constraint::Memory generically.

Added tests/fixtures/asm_memory_variant_operand.c (o input, +V tied
output, =o output). Full rewrites profile (85 tests) passes.
