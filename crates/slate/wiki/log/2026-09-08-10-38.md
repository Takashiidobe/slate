# Triage musl libc-test src/regression and LTP for vendoring value

_2026-09-08 10:38:00_

slate-b66b.5.3: surveyed the local ~/libc-test checkout's src/regression bucket (69 cases, unvendored) against the already-vendored functional/api corpus, using the lens of 'does this exercise a C-ABI surface Slate's codegen could diverge on, not just a libc implementation bug identical on both sides.'

Recommend vendoring 5 cases: printf-fmt-n.c (%n varargs write-back), syscall-sign-extend.c (raw syscall arg encoding), sigaltstack.c (signal-frame ABI, synchronous/deterministic), fpclassify-invalid-ld80.c (x87 f80 bit-pattern edge cases against Slate's rustc_apfloat-backed LongDouble emulation), and tls_get_new-dtv.c+dso (TLS/DTV growth after dlopen from multiple threads, deterministic via pthread_barrier). Four need no harness changes (test.h/print.c only, same path filter-libc-test.sh already handles); tls_get_new-dtv.c needs the companion-.so naming convention extended beyond the _dlopen-suffixed heuristic since its dso isn't _dlopen-suffixed.

Explicitly excluded the remaining ~64 regression cases: OOM/rlimit-injection tests (environment-flaky), pure algorithmic/library-correctness cases (regex, memmem, iconv -- not a Slate-codegen-divergence surface), more pthread races/deadlocks by design (already have layout+basic-sync coverage via functional/pthread_*.c), and environment-dependent cases (getpwnam_r, statvfs).

LTP: no local checkout, so this is a structural conclusion not a file survey (called out explicitly). LTP's libc-facing tests are kernel/syscall conformance, orthogonal to C-ABI codegen divergence, plus an autoconf/make integration cost categorically larger than libc-test's flat .c layout. Conclusion: do not vendor LTP.

Wrote up as wiki/concepts/libc-test-regression-ltp-triage.md (durable decision doc, not a log-only note, since it's meant to be read when a future vendoring task opens).
