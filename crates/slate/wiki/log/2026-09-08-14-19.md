# Migrate FreeBSD oracle probe into unified ABI matrix (sfzn.17.2)

_2026-09-08 14:19:02_

Ported tests/fixtures.abi-probe/linux-libc-abi.c (the schema-versioned
kind\tname\tvalue probe shared with musl/glibc) to also compile for FreeBSD,
instead of writing a second probe format for tools/probes/freebsd-libc.c.
Gated ~10 Linux/glibc-only records (mntent, epoll_event, sys/user.h ptrace
regs, sysinfo, GNU glob/utmpx/utsname fields, ucontext_t) behind
GLIBC||MUSL, fixed two real libc-shim FreeBSD gaps found along the way
(dirent.h missing the d_ino->d_fileno compat alias real FreeBSD headers
have; ifaddrs OFFSET using glibc's ifa_ifu union member instead of the
ifa_dstaddr name both platforms actually expose).

Confirmed via real clang invocations against this host's already-bootstrapped
target/freebsd-oracle sysroots: the probe now compiles and links cleanly
against both the real FreeBSD headers and libc-shim, for x86_64 and aarch64.

Hit a genuine architectural wall: FreeBSD binaries cannot execute on this
Linux host -- linux-user QEMU only emulates Linux's syscall ABI, not
FreeBSD's, so the existing "compile+link+run, diff printf output" mechanism
(which works for musl/glibc via native exec or qemu-user) has no way to
produce runtime records for FreeBSD without real/virtualized FreeBSD.
Asked the user; decided to treat verified compile+link agreement as a
(weaker, explicitly labeled) PASS rather than skip FreeBSD entirely or build
a compile-time-only extraction subsystem. Implemented via a new
ProbeConfig::can_execute flag (false only for FreeBSD) and split
run_probe() into compile_and_link_probe()+execute step; the suite reports
"PASS ... (compile+link only; runtime values unverified on this host)" for
such targets instead of comparing sizeof/offsetof values.

Also fixed libc_abi_matrix_suite.rs to SKIP (not hard-FAIL) when resolve()
reports a missing prerequisite, matching the convention already used in the
sibling libc_runtime_matrix_suite.rs -- previously ANY resolve() error was
a hard test failure, which would have made FreeBSD (or any future platform)
permanently break the `libc` profile on hosts lacking its oracle. FreeBSD is
opt-in via SLATE_LIBC_ABI_LIBC=freebsd, not part of the default musl+glibc
set, so this change doesn't affect default CI runs.

Retired tools/probe-freebsd-libc.sh and tools/test-freebsd-oracle.sh (no
Rust test or CI workflow referenced them via Command::new(bash) --
contrary to the ticket's premise, header_compilation.rs's FreeBSD tests
exercise libc-shim directly, not the shell probe). Updated
wiki/concepts/freebsd-libc-oracle.md's "Probes" section to point at the
unified matrix instead.

Verified: default musl+glibc x4 arches still pass (4141 records), FreeBSD
x86_64/aarch64 now PASS via the matrix, FreeBSD i386/arm cleanly SKIP.
cargo fmt/clippy clean.
