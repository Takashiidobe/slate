# Elide switch labels; fix worklist requeue of moved nodes

_2026-09-02 13:24:39_

switch_break_inside_if kept `'__switch0: {` because structure_dispatch sets
needs_label for any non-tail `break 'L`. The break was redundant: it only skipped
the rest of an arm that does not fall through, so leaving the switch and ending
the arm are the same thing.

New `label_elide.rs`, three small rules over any LabeledBlock (not
switch-specific, and reusable by structure_goto):
- `break_to_else`: `[.. if c { A; break 'L }, rest]` -> `if c { A } else { rest }`
- `tail_break_drop`: deletes a `break 'L` already in tail position
- `drop_label`: LabeledBlock with no remaining `break 'L` becomes a Scope
`reaches_label_end` decides tail position by walking up through transparent
constructs (if/match/scope/labeled block, and tail-less unsafe/block); a loop
boundary stops it.

The rules did not fire at first, which exposed an engine bug: run_worklist seeds
from live_ids() once and afterwards requeues only the edited node, its parent,
and def-use neighbours. Nodes *created* by a rule (structure_dispatch builds its
replacement with insert_stmts) and nodes *re-parented* by a rule (ScopeFlatten
hoists children) were never revisited. Here the `if` was processed at index 28
before ScopeFlatten ran on index 31, so it never saw its post-flatten siblings.

Requeueing subtree+children+ancestors unconditionally cost ~2.5x wall time
(45s -> 2m), so it is opt-in via `NodeRule::requeues_moved_nodes`, set on
StructureDispatch, ScopeFlatten and BreakToElse. Back to 45.7s, 92 passed.

All 434 fixtures now emit zero switch labels; the only two labeled blocks left
are `'__continue0` from the continue-inside-switch-inside-loop lowering.
