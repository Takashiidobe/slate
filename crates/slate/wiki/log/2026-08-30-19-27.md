# gcc-torture: fix union default-init and anon-union bitfield naming (slate-os0h.3.1.12)

_2026-08-30 19:27:53_

Two related union bugs, both surfaced by pr19687/pr58726 (pr15296 was
already promoted earlier via the render_const_value_expr union-member fix).

1. default_value_expr's RecordKind::Union arm (src/frontend/lowerer.rs) only
   zeroed the FIRST member's own bytes (e.g. `Value { i: 0 }` for a union
   whose widest member is a 16-byte array). Rust doesn't extend that to the
   rest of the union's storage the way C's `= {}` does, so reading a wider
   member left garbage past the first member's width -- pr19687's
   `union U t = {}; t.j[i]` read uninitialized bytes and spuriously called
   abort(). Fixed by emitting `unsafe { std::mem::zeroed::<T>() }` for any
   non-empty union default, which zeroes the whole representation
   regardless of which member is narrower. This is the same shape as the
   existing CLibInitializer::Zeroed path, just applied to user unions.
   Ripple effect: 18 existing fixtures asserted the old `Name { field: 0 }`
   golden shape for uninitialized unions and needed
   tools/update_filecheck.py regeneration (3 of them -- anonymous_members.c,
   non_int_fields.c, unions.c -- have handwritten REWRITES-DAG blocks the
   script won't touch, but those didn't reference the default-init line so
   no manual edit was needed there).

2. record_analysis.rs's anonymous-record reconstruction (used when a union
   has no tag/typedef, e.g. `union { int f1; int f2 : 1; } b;`) renamed ANY
   bitfield member to `__bitfield_{i}` unconditionally, whether the parent
   was a struct or union. That renaming exists to merge multiple struct
   bitfields sharing one storage byte -- meaningless for a union, where
   every member already occupies its own independent slot at offset 0. The
   blanket rename meant CIR's `cir.get_member <name = "f2">` had no matching
   field once the struct definition renamed it away, so `b.f2` fell back to
   a raw (non-existent) field access and failed to compile. Fixed by keeping
   the union case as name-preserving, matching how a *named* union
   (`union U1 { unsigned f0; unsigned f1 : 15; }`, sourced from the Clang
   AST instead of this CIR-alias reconstruction path) already worked.

Promoted builtin-bitops-1.c (unrelated parity-cast fix, same session),
pr19687.c, and pr58726.c. Full lowering (10/10), rewrites (90/90), and libc
(19/19) profiles green.
