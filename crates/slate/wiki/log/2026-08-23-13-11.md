# sqlite3 CIR memory blowup: fixed in ClangIR ASM printer

_2026-08-23 13:11:32_

Patched mlir/lib/IR/AsmPrinter.cpp in ~/llvm-project-ref (2 small edits):
AliasState now marks a type's alias as "printed" at its FIRST encounter
anywhere in the print (top-level slot or nested reference), not only after
fully printing that type's own designated top-level slot. Previously any
reference reached before that slot's turn - e.g. a nested member reached
while printing a different type's body - fell through to a full structural
re-expansion. sqlite's Mem/sqlite3_value struct is reachable via dozens of
independent, non-cyclic pointer paths, so the printed CIR module
combinatorially re-expanded its body once per path, exhausting memory
during mlir::Operation::print (not CIRGen itself - confirmed via crash
backtrace, see prior entry).

Verified fixed, in order:
- /tmp/vdbe_449.i (4610-line reproducer): 52s bad_alloc -> 25ms success
- ~/sqlite/src/vdbe.c (9574 lines, previously independently pathological):
  0.2s, 35855 CIR lines, 373 cir.func defs
- ~/sqlite/bld/sqlite3.c (full 140456-line amalgamation, the ORIGINAL
  blocker for slate-wcf7): 2.05s under a 10GB ulimit -v cap. Previously:
  unbounded RSS past 16.8GB+, never finished.
