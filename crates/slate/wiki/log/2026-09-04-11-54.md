# __builtin_dynamic_object_size already covered by existing cir.objsize handling (slate-04q.47.4)

_2026-09-04 11:54:09_

__builtin_dynamic_object_size CIRGens through the exact same emitBuiltinObjectSize
path as __builtin_object_size (CIRGenBuiltin.cpp): both call
evaluateOrEmitBuiltinObjectSize first, which folds to a plain cir.const
whenever Expr::tryEvaluateObjectSize can determine the size at compile
time (local arrays, globals, pointer offsets into them, all of type 0/1/2,
plus type==3 unconditionally, which CIRGen never lowers to an op at all).
Only a genuinely unresolvable pointer reaches cir::ObjSizeOp::create, with
nullUnknown hardcoded true always and `dynamic` set only from which
builtin spelling was used -- min/max sentinel semantics are identical
either way.

slate's lower_objsize (src/frontend/lowerer/intrinsics.rs) already returns
the correct sentinel (0 for min, MAX/-1 for max) for any un-folded
cir.objsize regardless of the dynamic flag, so no lowering changes were
needed -- same shape as slate-04q.47.3.

Checked whether __builtin_dynamic_object_size's headline use case (staying
resolvable across a malloc(n) call, matching FORTIFY_SOURCE=3 semantics)
would produce a differential mismatch: it doesn't, because
tests/support.rs::compile_c_with_args always compiles the C reference at
-O0, and LLVM's allocsize-based resolution for llvm.objectsize(...,
dynamic) only fires under real optimization (confirmed: clang -O0 gives
SIZE_MAX, clang -O2 gives the correct 37 for malloc(37) -- so at -O0
the "dynamic" case is indistinguishable from `unknown` and slate's
sentinel fallback matches the reference exactly). Slate never runs LLVM's
own IR optimizer since it translates straight to Rust, so this resolution
path is out of scope; documented as an explicitly unsupported dynamic
case rather than implemented.

Added tests/fixtures/dynamic_object_size_ops.c covering local array,
pointer-offset, global, and unknown-pointer modes for
__builtin_dynamic_object_size plus the malloc(n)-through-a-callee case.
rewrites profile (93 tests) passes.
