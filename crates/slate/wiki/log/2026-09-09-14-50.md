# Parallelize --targets translation across threads

_2026-09-09 14:50:26_

translate_targets_with_args (directive_translate.rs) looped sequentially over --targets, mutating the process-global SLATE_TARGET env var each iteration (unsafe std::env::set_var). Every downstream target-dependent call site (c_ast.rs, function_setup.rs, backend/engine/prelude.rs, api.rs) reads target only through toolchain::active_target(), so that was the single choke point.

Fix: added a thread_local TARGET_OVERRIDE cell in toolchain.rs; active_target() checks it before falling back to the env var. Added with_target_override(target, f) to scope it per-thread. translate_targets_with_args now uses rayon's par_iter() over deduped_targets, calling with_target_override per task instead of mutating the env var, and removed the save/restore-env-var wrapper.

No other global mutable state was target-dependent: f80_cache (constants.rs) and the rust_ast ident_intern table are Mutex-guarded and keyed by value, not target; c_ast.rs TYPEDEFS/ENUM_TYPEDEFS/CALL_FACTS are already thread_local so each rayon worker gets its own map. rayon().map().collect() preserves input order, so TargetVariant order is unchanged and merge_target_variants is unaffected.

Perf-only change, no signature changes outside the two touched files. Verified with tests/directive_translate.rs (21/21 pass, including target_only_divergence and target_and_macro_divergence tests) plus cargo fmt/clippy clean.
