# MSVC fixture wiring: stddef.h bug, __STDC__ gate, FileCheck migration

_2026-09-04 19:03:48_

slate-wlpp.4/.5 session. Fixed a real, target-independent bug:
libc-shim/include/stddef.h was the one public header missing
#include <features.h> -- every other header includes it first, defining
the bare _SLATE_LIBC sentinel that bits/msvc/stddef.h's direct-include
guard requires. A C file whose first include is <stddef.h> (legitimate,
common) tripped "Never include <bits/msvc/stddef.h> directly" purely from
include order. Fixed by adding the missing include.

That unblocked stat_surface/time_surface/long_double_layout/
utime_timeb_surface enough to confirm they now fail on the real,
already-tracked wlpp.7 MSABI tag-decl gap instead -- correctly still
blocked, not further actionable here.

Found and fixed a real test-fixture bug (not a shim bug) in
stdio_surface.c: it asserted a UCRT non-underscore legacy alias family
(tempnam/fcloseall/fdopen/fgetchar/fileno/flushall/fputchar/getw/putw/
rmtmp/unlink/SYS_OPEN) that real UCRT gates behind `#if !__STDC__`.
Clang always defines __STDC__=1 in C mode (confirmed against the pinned
xwin sdk/include/ucrt/stdio.h), so this is permanently unreachable under
any Clang-based frontend including clang-cl -- not a shim gap, a fixture
error. Removed those assertions; the _-prefixed canonical names were
already covered. See wiki/concepts/msvc-ucrt-manifest-audit.md.

Migrated 3 fixtures (llp64, long_double_pointer, long_double_macro_constant)
off legacy hand-written REWRITES-MSVC directives (which permanently block
tools/update_filecheck.py's has_handwritten_block() auto-management) onto
fully tool-managed SLATE-FILECHECK-BEGIN/END blocks -- same mechanism
already used by wctype_surface/float_surface/scalar_layout. One of the
three (long_double_macro_constant) was actually stale: it hand-asserted
f64::from_bits(...) but current CIR now prints this constant's text in
plain decimal form (verified bit-exact against the old from_bits value),
so the manual check had silently drifted from reality. Auto-management
prevents this class of drift going forward. Same handwritten-directive
pattern also exists in several bionic/macos fixtures -- noted, not
touched (out of scope for wlpp.4/.5, currently passing).

Added 6 fixtures to msvc_translation_ready() with real translate+FileCheck
coverage (previously compile-only): wctype_surface, float_surface,
long_double_macro_constant, long_double_pointer, scalar_layout,
stdio_surface.

Verified: --profile lowering/rewrites --test differential and --profile
libc all green; fmt/clippy clean.
