# Expand libc ABI probe: statx, full msghdr/cmsghdr, sys/reg.h, sys/user.h

_2026-09-08 08:49:09_

Extended tools/probes/linux-libc-abi.c and libc-shim/include/sys/stat.h under
the slate-b66b.13 epic (slate-b66b.13.2/.3/.4/.5):

- struct statx/statx_timestamp: added to the shim under _GNU_SOURCE (matching
  real glibc/musl gating), probed size/align/all fields through
  stx_dio_offset_align. Dropped stx_subvol/stx_atomic_write_* from the
  automated probe: the local ARM cross-toolchain's UAPI headers predate
  kernel 6.13 and lack those named fields (struct size still matches via
  reserved padding) -- a toolchain-vintage gap, not a shim bug. User confirmed
  a 2025 ARM toolchain has since been installed with 6.13-era headers.
- msghdr/cmsghdr: added ALIGN plus full OFFSET coverage (msg_namelen,
  msg_iovlen, msg_controllen, msg_flags, cmsg_len, cmsg_level, cmsg_type).
  This is exactly the field set that hid the glibc/musl size_t-vs-int
  mismatch fixed in slate-b66b.13.1 -- the expanded probe would now catch it.
- sys/reg.h: register-index macros probed on x86_64/x86 only, matching that
  glibc only ships this header for x86/x86_64/m68k.
- sys/user.h: struct user_regs_struct/user_fpregs_struct/user_fpsimd_struct/
  struct_user probed per-arch (x86_64, x86, aarch64, arm). riscv32/riscv64
  get an explicit presence=0 record since neither real libc declares
  user_regs_struct there.

Moved `#define _GNU_SOURCE` to the top of the probe file (was previously
scoped only around the extensions include block), since sys/stat.h needed it
active on first include for the statx guard.

Verified: tools/libc-abi-matrix.py green across all 4 arches x both libcs,
cargo nextest --profile libc 37/37.
