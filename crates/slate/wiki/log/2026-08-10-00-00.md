# setjmp/longjmp translation and C-unwind propagation

_2026-08-10 00:00:00_

Built out `setjmp_recovery` (a query-driven fixup rule, `src/fixups/query/rules/setjmp_recovery.rs`) into whole-program `setjmp`/`longjmp` translation, growing from ~500 lines of edits across the day:

- **`05dae87b`**: extended the rule from a single-function pattern to a whole-`WholeProgram`-domain rule (`QueryRule<WholeProgram>`), pulling in `SalsaFacts` so it can see call relationships across the whole program instead of just the enclosing function.
- **`643e385a`**: the rule now also visits *indirect* calls (through function pointers) and labels their target ABI `"C-unwind"`, not just direct calls — `longjmp` can be reached through a function-pointer callback, and the unwind ABI needs to propagate through that indirection too. Added `indirect_call_unwind_abi_propagation.c` to cover it.
- **`0cb9fe81`**: emits `extern "C-unwind"` on the generated `extern` declarations for setjmp-related functions, not just on the Rust `fn` definitions — matters because slate models C `longjmp` as a Rust panic/unwind, and an `extern "C"` boundary (the default ABI) would abort instead of unwind through it.
- **`5536056d`**: the rewrite now also follows calls into other *rewritten* (renamed) files, not just the original file names — needed once cross-TU renaming could put a setjmp-calling function under a different generated module path. Added `enum_wrapper_unwind_abi_propagation.c`.
- **`5db8d819`**: fixups plus first pass of `book/src/features.md` documentation for the setjmp design (unwind-based `longjmp`, not signal/exception-based).

Design point worth keeping: unlike most cir.* lowering, this is a program-wide analysis pass (it needs to see every call site that can reach a `setjmp`-tagged function), which is why it lives as a `WholeProgram`-domain query rule rather than a per-function lowering handler.
