# default filecheck regen to both gnu targets

_2026-09-06 11:22:19_

`default_targets_for_path` returned no targets for anything outside the
bionic/macos/msvc/long_double special cases, so regenerating a
`tests/fixtures` fixture without `--target` ran in non-target mode and
flattened its `LOWERING-X86_64-GNU` / `LOWERING-AARCH64-GNU` lines into a
single host-specific plain check. On `add.c` that replaced the
`*mut i8` / `*mut u8` pair with a bare `*mut i8`, which would fail on an
aarch64 host.

The fallback is now x86_64-unknown-linux-gnu plus aarch64-unknown-linux-gnu,
and project regen picks the same default (`explicit_targets or
default_targets_for_path(proj)`) instead of only honoring explicit flags.
`add.c` regenerates byte-identical, confirming the corpus was authored this
way. Regen now costs two translations per profile.

Block assembly moved into `assemble_blocks`, shared by `update_path` and
`update_project`, so project fixtures fold like single-file ones: lines equal
across targets collapse onto the plain profile prefix and only divergent
lines stay target-tagged. On `gnu_symbol_pragmas/main.c` only the
`*mut i8` / `*mut u8` line stays split; two identical `rewrites` blocks
become one.

Not regenerated corpus-wide. About twenty `fixtures.multi` fixtures still
carry target blocks that are byte-identical to their plain block (e.g.
`cross_tu/math.c`, 28 redundant lines) and would fold on their next regen.
