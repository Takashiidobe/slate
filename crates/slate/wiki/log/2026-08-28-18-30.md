# length_lattice: internal slice view for companion-param buffer reads

_2026-08-28 18:30:46_

Implemented slate-y0qs.4.8's safe subset: interproc/length_lattice.rs.

For a pointer param whose pointer_lattice fact resolves Slice, paired with a
companion int param used solely as a for-loop upper bound matching the
pointer's offset index, materializes an internal
  let __<ptr>_view = unsafe { slice::from_raw_parts(ptr, len) };
and rewrites internal offset-deref reads to index into it. Function
signature is untouched -- never deletes a length param or its producing
expr, since that computation can carry side effects.

Deliberately deferred (separate mechanisms, out of scope here):
- usage-bound Const recovery (no companion param, full type lift)
- call-site length bridging / real signature-changing Buffer LiftKind lift
  (this issue's original scope, kept open)

Found and fixed a real soundness gap along the way: pointer_lattice's
place() never flips the write bit when a write target is a deref of an
offset-temp (*_v8 = val where _v8 = p.offset(i)), only when the deref
target is Var(name) directly. That let a genuinely-mutated buffer (gcc
torture pr110115) resolve as read-only Slice, which length_lattice trusted
and then generated code that assigned into an immutable slice --
compile-broken output, caught by the gcc_torture_suite regression test.
Fixed by having length_lattice independently scan for writes through its
matched offset temps (matched_offset_temps + is_written_through) and reject
the pairing if found, rather than trusting pointer_lattice's write bit.
pointer_lattice.rs's own place() gap is still there and could bite other
Buffer-kind work later.

Validated: tests/fixtures/length_lattice_view.c (new fixture) passes under
--profile rewrites; full rewrites profile suite 110/110 green including
gcc_torture_suite.
