# Tier-1 libc-call rewrite facade (data-driven table)

_2026-08-28 22:44:36_

Prototyped a Tier-1 facade over NodeRule so mechanical 'C libc call -> Rust path call' idioms are one table row instead of a ~70-line rule.

src/backend/engine/rules/libc_call.rs: one generic LibcCall NodeRule + ArgSpec (Passthrough | Custom(fn(&[Expr])->Option<Vec<Expr>>)) + a rules() table. Each row: (Known, rust_path, ArgSpec). The adapter centralizes the boilerplate every libc rule repeated by hand: peeling the singleton 'unsafe { .. }' wrapper the lowerer puts around extern calls, the get_mut/downcast/rebuild dance, and call_anchor wiring for O(1) dispatch.

Disambiguation is provenance-based, NOT name/unsafe-wrapper based: the matcher keys on binding.known() == Some(Known::X) (the FunctionIdentity resolved from stdlib.h provenance / macro-dump), so a user-defined function shadowing a libc name (e.g. function_provenance.c's own 'static void exit(int)') is left alone. An earlier name-based matcher wrongly rewrote that user exit -> std::process::exit and broke the differential (C exit 1 vs Rust 0); keying on Known fixed it.

Ported libc_exit -> table row (Known::Exit); deleted rules/libc_exit.rs. Added 'abort' as the second row: Known lacked an Abort variant, so added Known::Abort (enum + symbol()+header()+classifier table, stdlib.h). abort is differential-safe -- SIGABRT on both sides gives status.code()==None==None. ArgSpec::Custom kept as the arg-transform extension point (marked #[expect(dead_code)] until the first reordering/inserting idiom lands).

Validation: rewrites 110/110 (incl. function_provenance + assert_recovery abort), fmt/clippy clean. Net: a libc idiom goes from ~70 lines to one row, same engine behavior/cost.
