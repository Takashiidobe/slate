# cstr_literal covers mutable and i8/u8 pointer casts

_2026-09-02 13:49:01_

The `cstr_literal` rule (`src/backend/engine/rules/cstr_literal.rs`) only fired when
the byte-string cast target was exactly `*const core::ffi::c_char`, because it
rewrote by *dropping* the cast — sound only when `as_ptr()` already has the target
type. Everything else kept `b"...\0".as_ptr() as *mut i8`. In libexpat that was 325
sites vs 119 rewritten.

Changes:
- `is_byte_ptr` accepts any `Type::Ptr` whose inner is `CLib(CHAR)`, `Prim::I8`, or
  `Prim::U8`, regardless of mutability. The cast is now dropped only for
  `*const c_char` and re-wrapped otherwise: `c"x".as_ptr() as *mut i8`.
- `cstr_content` peels a chain of byte-pointer casts and accepts an already-rewritten
  `Expr::CStr` receiver. Without this the rule fired bottom-up on an inner
  `as *mut i8` and left a redundant outer `as *const c_char` on printf arguments
  that used to collapse away.
- `rewrite_of` returns `None` when the rewrite is a no-op, so `has_rewrite` cannot
  report a match the apply step will not make.

Fixture `tests/fixtures/cstr_literal_mut_ptr.c` covers `char *`, `const char *`,
`unsigned char *` returns plus a printf argument (the cast-dropping path).
77 fixture REWRITES snapshots regenerated; no LOWERING line changed. libexpat now
emits 444 `c""` literals and still compiles.
