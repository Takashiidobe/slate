# long double (f80) implementation

_2026-08-12/13/14 (dated 2026-08-13)_

Implemented C `long double` as a real x87-80-bit-extended type instead of widening it to `f64`, since the two are not observably equivalent (precision, and on x86_64 Linux the ABI passes/returns it as a 10-byte extended value with 16-byte alignment).

- **`4e5c7f90`**: chose `[u8; 10]` as the wire/storage representation (a `LongDouble` newtype), replacing an earlier scratch approach in `frontend/lowerer/runtime_support.rs` (shrunk 228 lines back down as the ad hoc version was replaced).
- **`5e5a672e`**: pulled in `rustc_apfloat` (the crate rustc itself uses for target-independent arbitrary-precision float arithmetic) to do correct arithmetic/rounding on the 80-bit format, since Rust has no native `f80`.
- **`e7ef0e1a`**: layout differs by target — added `uses_f64_long_double_abi()` (in `cir::emit`) so mac/msvc targets, where `long double` is ABI-identical to `double`, use `{size: 8, align: 8}` instead of the Linux x86_64 `{size: 16, align: 16}` (80-bit value padded to 16 bytes). Also set a per-lowerer `uses_long_double` flag when any record field's type needs it, to gate emitting the support code only when actually used.
- **`d0343ae3`** (`frontend/lowerer/memory.rs`): wired long-double casts to/from the `BitInt`/`UBitInt` (arbitrary-width integer) generic types by routing through i128/u128 as an intermediate width and calling into `f80_cast_from_name`/`f80_cast_to_name` shims, rather than trying to special-case every bit-width pairing directly.
- **`3deb5087`**: added the arithmetic trait surface (`Add`/`Sub`/`Mul`/`Div`, later `5747f1a3` filled in the `*Assign` variants) so generated Rust code can use ordinary operators on the `LongDouble` type.
- **`9dc993c9`** / **`7e48c84a`**: iterated on `frontend/c_ast.rs`/`frontend/lowerer.rs` (up to 172 lines) fixing lowering bugs surfaced by the growing long double test suite (`0d4df733` added the suite itself).
- **`b72c8e91`**: `strtold` no longer gets bespoke special-casing in `c_shim.rs` — folded into the general f80 shim table like any other f80-returning libc function.
- **`66e52899`**: fixed the printf-format rewrite (`sprintf_format`-adjacent path) that broke because it didn't recognize `__slate_f80` as a float-family type needing `%Lf`-style handling.
- **`4dbf586f`**: migrated C `_Complex` support onto the `num-complex` crate rather than a hand-rolled complex type, needed once complex-of-long-double had to compose with the new f80 arithmetic.
- **`d1d24861`** / **`fae5bd07`**: added variadic-function (`scanf`-style, `va_list`) and general edge-case coverage for long double, plus a 184-line `tests/fixtures.link/long_double/link.c` link-level test.
- **`0be654db`** / **`ff7d227d`** / **`0ae7ecc6`**: swept remaining rewrite-pass breakage caused by the new type, migrated more previously-failing gcc-torture cases from unsupported to supported now that long double worked, and closed the "raw lowering failure" epic that had been tracking this and related lowering gaps.
- **`943ed2e6`**: follow-up adjustments after bumping the ClangIR version, since the upstream CIR representation of `long double`/f80 operations shifted slightly between versions.
