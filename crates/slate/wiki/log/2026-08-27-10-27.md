# rewrite engine v2: slice 2 (zero_init ported, synthetic root wrapper)

_2026-08-27 10:27:45_

Ported ZeroInit (src/backend/query/rules/zero*init.rs, deleted in slice 1)
as a single unified NodeRule (src/backend/engine/rules/zero_init.rs),
priority 5 (runs before singleton_scopes). Collapses `let mut x: T = 0;
...; x = value;` into `let mut x: T = value;` when the first write to x
after its declaration is found, `x` isn't touched by anything between, and
either the write's value is pure/closed (no var reads, no calls) or every
intervening statement is itself a Let declaration -- mirrors the original
query engine's `direct`/`deferred` cases collapsed into one rule (cross*
effects always allowed), since deferred is a strict superset of direct.
Does not implement the original's "moved_decl" fallback (hoisting the
whole declaration down past effectful code) -- scoped out for now, real
gap tracked below.

Needed two supporting pieces:

- Expr::reads_var / a free stmt_reads_var in rust_ast.rs, mirroring
  substitute_var's traversal shape as a read-only presence check (used to
  decide whether an intervening statement or the hoisted value touches a
  name).
- expr_is_zero (recognizes literal 0/NullPtr/None, casts, negation, and
  all-zero struct/tuple-struct/array-repeat -- matches facts/values.rs's
  ConstValue::Zero cases but as a pure per-expression check, not a
  whole-function abstract interpreter: Var reads always come back "not
  zero" rather than tracing the referenced binding's own value set, since
  we don't have a fact cache yet).

Structural fix while wiring this up: FunctionArena now wraps a function's
body in a synthetic NodeKind::Block root (arena.rs) instead of returning a
bare `roots: Vec<NodeId>`. Every real statement now has a genuine parent
NodeId -- no rule has to special-case "top-level, no container" to find
its siblings. reify() unwraps the synthetic root transparently. Added
NodeKind::child_lists() (immutable twin of child_lists_mut) so rules can
scan a container's statement lists without needing mutable access.

Verified manually (cargo run -- translate) that the rule actually fires
end-to-end on a small case with only movable-declaration intervening
statements, and correctly declines to fire when a non-Let, impure
intervening assignment (e.g. an inlined `__retval = _v0;` bookkeeping
statement) is in the way -- which is expected: that specific fixture
(tests/fixtures/zero_init.c) needs EarlyInlineTemps to run first (as it
does in the old pipeline) before ZeroInit's preconditions hold; not a
regression since EarlyInlineTemps isn't ported yet either.

Investigated why tests/fixtures/zero_init.c's REWRITES-tagged FileCheck
assertions didn't fail despite the mismatched output: tests/support/
filecheck.rs's check_generated_rust_with_prefixes short-circuits to Ok(())
whenever the active profile is Rewrites (`if profile == Profile::Rewrites
{ return Ok(()); }`) -- REWRITES-prefixed structural checks only actually
run under the `lowering` nextest profile, which skips fixups entirely. So
these checks are not a live gate right now regardless of which fixups are
ported; pre-existing, not something this session changed.

Validated: build/clippy/fmt clean, all three nextest profiles green
(rewrites 110/110, lowering 10/10, libc 19/19; one `generated_directive_
filecheck` failure on a parallel run was a flaky/contention retry, passed
clean on rerun and in isolation -- unrelated to these changes).

future rules see through post-inlining shapes like the fixture above), or
work through passes.md in priority order. Consider whether ZeroInit's
"moved_decl" fallback is worth porting once a real regression surfaces.
