# predicate tokenizer opaque-collapse fix

_2026-08-23 09:52:29_

Fixed src/frontend/preprocess.rs predicate tokenizer: any unrecognized token (numeric literals, >=, ==, etc) previously made tokenize() return None, collapsing the ENTIRE #if predicate to one PredExpr::Opaque and losing the &&/|| tree — so eval() could never short-circuit even when a leading defined(X) was false. Now unrecognized runs fold into Opaque leaves within the And/Or tree (parse_opaque_atom), so 'defined(_MSC_VER) && _MSC_VER >= 1700 && defined(_M_ARM)' evaluates via short-circuit once defined(_MSC_VER)=false. Found via slate-wcf7 (translate sqlite3.c epic) at sqlite3.c:55623 (#pragma optimize guarded by this exact pattern). Fixture: tests/fixtures/pragma_guarded_by_opaque_version_predicate.c. Version-guard idioms like this are common in real C, so this is a general win, not sqlite-specific.
