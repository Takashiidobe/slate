# Wire libc ABI oracle matrix into nextest libc profile

_2026-09-08 10:12:28_

Added tests/libc_abi_matrix_suite.rs: a single #[test] that shells out to tools/libc-abi-matrix.py, captures stdout/stderr, and panics with the full output on nonzero exit. matrix.py already prints per-record FAIL name: oracle=... candidate=... lines, so a captured failure shows the first ABI mismatch directly rather than just a toolchain/compile error.

Wired binary_id(=slate::libc_abi_matrix_suite) into profile.libc's default-filter in .config/nextest.toml and excluded it from profile.rewrites, matching the other four libc suites.

Added env-var passthrough (SLATE_LIBC_ABI_LIBC, SLATE_LIBC_ABI_ARCH, SLATE_LIBC_ABI_FAMILY, comma-separated for repeated --arch/--family) for focused single target/libc/family runs during iteration, mapped onto the script's existing --libc/--arch/--family flags. Left the default nextest invocation unrestricted since the full 4-arch x 2-libc matrix completes in ~1.6s.

Verified: isolated focused run (musl/x86_64/pthread) passes under cargo nextest r --release --profile libc -E 'test(libc_abi_matrix)'; unrestricted full matrix passes in 1.6s under the same command; a forced bad --arch value correctly panics with the script's captured stderr. Documented the wiring and env vars in wiki/concepts/cross-target-toolchains.md.
