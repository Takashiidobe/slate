# x86 asm b/w/k/q register-width-override modifiers

_2026-09-07 08:10:47_

Fixed slate-3f8g.4.15.9: TemplateModifier::parse in src/frontend/lowerer/asm.rs
only recognized c/l/a (+ arm64 w/x), so GCC/LLVM x86 register-width-override
modifiers b/h/w/k/q (${0:b} etc.) were silently dropped and the template fell
back to the operand's natural-width modifier. `incb %b0` on an i32 operand
lowered to `incb {0:e}` -> rustc "invalid operand for instruction".

Fix: map x86 b/w/k/q to Rust's asm! register-modifier letters via
RegWidth::att_size_modifier (l/x/e/r), reusing the existing RegisterWidth
template-piece path. `h` (high-byte ah/bh/ch/dh view) has no Rust asm!
equivalent, so it's a new TemplateModifier::Unsupported variant that makes
render_operand_reference return None, bailing the whole template translation
out to the existing `unsupported!` diagnostic instead of silently emitting a
wrong-width instruction.

n (negate immediate) and P (bare/PLT symbol form) remain unimplemented per the
issue's stated priority (rarer in the audited corpus) — left for a follow-up
if a real fixture needs them.

New fixture: tests/fixtures/asm_x86_reg_width_override_modifiers.c, covers all
four supported overrides on both int and long operands, both lowering and
rewrites profiles.
