# glibc-versioned shim: crypt_data split, pow10 gated (slate-3f8g.5.11, .5.13)

_2026-09-04 08:40:59_

Closed both remaining slate-3f8g.5 companion-library gaps.

.5.11: split struct crypt_data per libc profile in libc-shim/include/crypt.h.
__SLATE_LIBC_GLIBC gets libxcrypt's exact 32768-byte layout (fields and sizes
copied straight from the host's /usr/include/crypt.h); every other profile
keeps the prior small musl-style struct. Verified byte-identical sizeof
against the real header. Proven with a new tests/fixtures.syslink/gnu_crypt_r
fixture (crypt_r round-trips, no more stack corruption from the 260-vs-32768
byte mismatch).

.5.13: pow10/pow10f/pow10l in math.h are now gated on !__SLATE_LIBC_GLIBC ||
__SLATE_GLIBC_MINOR__ < 27 (glibc 2.27 obsoleted them; other libcs unaffected).

New in support of both: __SLATE_GLIBC_MINOR__, detected per-invocation by
src/frontend/toolchain.rs::glibc_minor_version() via `getconf
GNU_LIBC_VERSION` (glibc's own canonical version query -- not portable to
musl or Darwin, so no shared cross-libc version abstraction was built; each
libc profile keeps its own bespoke detector, same as __SLATE_ANDROID_API__
and __SLATE_FREEBSD_VERSION__ already do). features.h requires the macro
whenever __SLATE_LIBC_GLIBC is set. The cross-arch header-compile smoke
suite (tests/support/libc_shim.rs) pins a fixed GLIBC_MINOR_VERSION=43
instead, since those checks never actually link/run -- same pattern as its
existing FREEBSD_VERSION_NUMBER constant.

Detecting from the live host (rather than hardcoding, unlike FreeBSD/Android)
matters here specifically because the differential harness always links the
generated Rust against whatever glibc is actually installed.
