# Asm-label rename audited clean; width-override modifiers confirmed broken

_2026-09-06 22:08:44_

Audited two unaudited GCC inline-asm features from the "other features" survey.

asm("name") symbol renaming on ordinary declarations (not register vars, not
weak/alias): clean, no bug. Clang's AsmLabelAttr bakes the renamed symbol
directly into CIR's @name; Slate joins AST facts by source location, not
name, so it transparently uses CIR's already-renamed symbol. Verified
end-to-end: C and translated Rust both print "5 51" for a fixture mixing a
renamed global, a renamed extern, and a renamed function. No bead needed.

Register-width-override template modifiers (%b/%h/%w/%k/%q, plus %n/%P):
confirmed broken. TemplateModifier::parse (src/frontend/lowerer/asm.rs:640)
only knows c/l/a; CIR's ${0:b}-style modifiers fall through to the operand's
natural-width modifier instead. Repro: __asm__("incb %b0" : "+r"(x)) on an
int lowers to asm!("incb {0:e}", ...) -- rustc hard-errors ("invalid operand
for instruction", incb %eax). Filed as slate-3f8g.4.15.9.
