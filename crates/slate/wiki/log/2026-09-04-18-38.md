# Bionic filesystem/dirent ABI (slate-sfzn.7.4)

_2026-09-04 18:38:20_

Implemented and oracle-verified the Bionic filesystem/dirent ABI for aarch64
and x86_64 Android (API 21), covering sys/types.h, sys/stat.h,
sys/statvfs.h, dirent.h, fcntl.h, utime.h.

Real Bionic keeps struct stat kernel-ABI-exact per architecture, diverging
from the shim's shared glibc-shaped bits/generic/stat.h and bits/x86_64/stat.h
in exactly two fields: st_blksize/st_blocks use raw int/long (not the
blksize_t/blkcnt_t typedefs) on aarch64, and st_nlink uses raw unsigned long
(not nlink_t) on x86_64. Added bits/bionic/stat.h with the correct per-arch
body, dispatched from bits/stat.h. The public blksize_t/blkcnt_t typedefs are
also unsigned long on Bionic (glibc/musl keep them signed) - added a Bionic
branch in bits/types.h before the shared __LP64__ case. struct statvfs also
diverges: no public f_type field, just a uint32_t __f_reserved[6] tail.

Bionic does not feature-test-macro-gate the *64 LFS family, mknod/mknodat,
S_IREAD/S_IWRITE/S_IEXEC, seekdir/telldir, or most fcntl.h AT_*/F_*/splice
declarations - confirmed by reading the real NDK r27d sysroot headers
(<linux/fcntl.h> is included unconditionally). Exposed the same set
unconditionally under __SLATE_LIBC_BIONIC. Conversely Bionic has no
getdents/posix_getdents/versionsort/name_to_handle_at/open_by_handle_at at
all - excluded those instead of leaking the Linux-libc surface.

API-level gating (lockf >=24, statx >=30, seekdir/telldir >=23) intentionally
left to slate-sfzn.7.9, matching 7.3's carve-out.

New: libc-shim/bionic-filesystem-headers.txt manifest,
tests/fixtures/bionic/filesystem_layout.c (one file, #if
__SLATE_ARCH_X86_64 for the two arch-divergent assertion blocks, compiled for
both architectures - not embedded as Rust format! strings, so it reads as a
real C test program). Two new tests in tests/header_compilation.rs.

Found and filed separately (out of scope, pre-existing): glibc/musl aarch64
struct stat is already wrong today (144 bytes instead of 128) because
__nlink_t widens to 8 bytes for any GLIBC+WORDSIZE_64 target with no
architecture check. Filed as slate-jxmx.

Validation: cargo fmt --check; cargo clippy --release (header_compilation
test); cargo nextest r --release --profile libc (36/36 pass, including
existing glibc/musl/freebsd/macos header sweeps - no regressions).
