# arm-lowering/arm-rewrites: fix cc-rs CC var, unmask + skip-list two pre-existing bugs

_2026-09-07 11:37:56_

The batch cargo build's build.rs (compiles a small C shim via cc-rs) never
set a CC_<target> env var, so cc-rs fell back to guessing
"arm-linux-gnueabihf-gcc" by target-triple convention. The installed cross
toolchain is ARM's official 15.2.rel1 release, whose gcc binary is named
"arm-none-linux-gnueabihf-gcc" - a different guess, so the build always
failed with ToolNotFound, regardless of SLATE_ARM_LINKER/SLATE_ARM_SYSROOT
(those only fed the cargo linker env, not cc-rs). Fixed by also setting
CC_<rust_triple_with_underscores> to cross.linker in
support::run_batch_cargo_build. Applies to both arm-lowering and
arm-rewrites (differential_arm.rs), not aarch64 (already worked via a
different code path).

Fixing this unmasked two real, pre-existing fixture failures that had
never actually run to completion before: c23_library (undefined reference
to memset_explicit - this toolchain's libc doesn't export it, filed as
slate-iow4) and long_double_complex (already tracked as
slate-3f8g.4.16.16, last-bit rounding differences in div/div_assign).
Added both to differential_arm.rs::skip_reason. Both profiles now pass
cleanly. No slate-3f8g.4.16.7-9 fixtures affected.
