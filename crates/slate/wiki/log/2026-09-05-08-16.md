# Add aarch64 cross-execution differential testing

_2026-09-05 08:16:39_

New opt-in nextest profiles (aarch64-lowering/aarch64-rewrites) cross-compile
tests/fixtures/*.c -- both the C reference and slate-generated Rust -- for
aarch64-unknown-linux-gnu and run both under qemu-aarch64-static, comparing
stdout/exit code, gated behind tests/differential_aarch64.rs so it never
runs as part of lowering/rewrites/libc. Toolchain: clang --target=aarch64-
linux-gnu --sysroot=/usr/aarch64-linux-gnu for C, cargo --target aarch64-
unknown-linux-gnu + aarch64-linux-gnu-gcc as linker for Rust, qemu-aarch64-
static -L <sysroot> to run both. SLATE_TARGET drives target-correct lowering
via the existing toolchain.rs mechanism (same one FixtureFlavor::Bionic uses).

tests/support/mod.rs's batching (compare_batch/build_batch/run_with_config)
grew an additive Option<CrossTarget> param; x86 call sites unaffected.

Found and fixed a real pre-existing bug: build_batch used --message-format=
json-render-diagnostics, which makes cargo print the *primary package's* own
diagnostics as plain stderr text instead of JSON compiler-message entries --
so any fixture with a genuine Rust compile error got the whole batch's
stderr dumped as its error, misattributed. Fixed via plain --message-
format=json. Affects both x86 and aarch64 suites, no behavior change for
passing builds.

Full run: 425/463 fixtures pass on both profiles, 38 skipped -- 14 x86-only
asm/intrinsics, 6 hit a CIR-frontend _BitInt>128/__float128 gap for this
target (slate-sdks.1), 14 hit a real bug: slate hardcodes char as signed i8
regardless of target signedness (slate-sdks.2 -- aarch64 defaults char to
unsigned), 3 hit an f128 division/type-consistency bug (slate-sdks.3), and
stat_struct likely shares slate-jxmx's aarch64 struct-stat root cause.
