# translate-project: declare macro-derived cfg(feature=...) in Cargo.toml

_2026-09-10 09:44:07_

translate-project had no #ifdef cfg-fork recovery: each LoadedVariant's Cfg
came only from target_cfg(target triple), so a non-target #ifdef was
resolved once by clang per compile-command entry -- no cfg(feature=...)
fork, nothing for Cargo.toml to declare. directive_translate's
plan_configs/merge_variants already does this for the single-file
`translate` command, which doesn't scaffold a crate.

Added: Cfg::feature_names + Program::cargo_features (walk Item::Cfg/
InlineMod for feature cfg atoms); crate_manifest/write_crate_manifest take
a BTreeSet<String> and emit [features] when non-empty, else identical
output. directive_translate::single_chain_macro_branches(source) exposes
plan_configs's per-branch (Cfg, extra clang args), restricted to files with
exactly one top-level #if/#else chain -- multiple independent chains stay
unforked for now, since folding their flat per-chain branch lists into the
project-wide `cfgs` axis (shared across files for target forking) risks
cross-file cfg pollution. lower_macro_forked_program (main.rs), called per
(stem, target-cfg) variant, recompiles once per branch when a single chain
is found, lowers with the existing cross-module ProjectInfo facts, and
folds via the existing merge_target_programs -- purely local to that file/
target slot.

New fixture tests/fixtures.multi/cfg_feature_macro +
cross_tu::project_declares_macro_derived_cfg_features_in_cargo_toml proves
the fork, the Cargo.toml [features] entry, and cargo check passing both
with and without --features my_feature. fmt/clippy clean; full cross_tu.rs
and full rewrites profile (95 tests) pass, no regressions.

Follow-up: multiple independent #ifdef chains in one file still don't
fork -- needs a per-file cross-product over each chain's branches, kept
local the same way this change is. Natural extension of slate-c16q.
