# macro-dump-plugin: support building against installed clang

_2026-09-10 11:16:28_

build.sh previously required SLATE_CLANG to point into a CMake source
build (read CMAKE_HOME_DIRECTORY from CMakeCache.txt for headers). Added
an installed-clang mode: when no CMakeCache.txt sits next to SLATE_CLANG,
build.sh now uses `llvm-config --includedir` to find matching clang/llvm
headers and skips linking against any clang/llvm libs (plugin resolves
symbols from the host process at load time, so headers alone suffice).

Verified against system Arch clang 22.1.8 (pacman clang/llvm packages,
no source checkout): plugin built clean, loaded into that same clang,
and emitted correct MACRO_EXPANSION output. Confirmed cross-version
plugin loading fails with an undefined-symbol error in both directions
(22-built .so into build-cir 24, and vice versa) -- plugins must still
be pinned to the exact clang major/build config they're loaded into.

This means a full source build of LLVM is only needed for CIR itself,
not for the macro-dump plugin. Once CIR ships stable-and-default
upstream, no source checkout will be required at all. Updated README.md
with per-platform (apt, pacman, dnf, Homebrew) install instructions;
Windows punts to WSL since native MSVC plugin builds are unverified.
