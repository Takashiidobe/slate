# decision: rewrite src/backend/query + salsa from scratch, handoff written

_2026-08-27 13:57_

`slate-y0qs.3` pivots from "retrofit the existing engine with a worklist"
to "replace it wholesale." Full reasoning and target architecture written
up in [rewrite-engine-v2.md](../concepts/rewrite-engine-v2.md) -- this
entry is just the decision trail for why, since it happened mid-session.

Tried the incremental retrofit first (function-level `TouchedItems`
scoping, see 2026-08-27-13-23 and 2026-08-27-13-38): real but small win
(67.4s -> ~65.6s on libexpat, ~3-4%). Investigated the next retrofit step
(share `query_items` walks across rules sharing a `QueryDomain`, e.g.
`SingletonScopes`+`DeadLocals` both `Statement`-domain) and found it
requires merging edit *application* across passes to keep facts
consistent, which requires making `PlanBuilder`'s overlap resolution
(`src/backend/query/plan.rs`) priority-aware instead of its current
symmetric drop-both-on-conflict behavior -- an invasive change to the
transactional-apply core every existing pass's correctness depends on.

Decided the retrofit cost is comparable to a rewrite, and a from-scratch
engine can dodge the batch-conflict problem structurally by applying one
edit at a time (pop worklist node -> dispatch -> first matching rule by
priority -> apply immediately -> requeue neighbors, no batch to
reconcile) instead of proposing many edits and resolving overlaps after
the fact.

Second decision, on facts: salsa's `set_program` is a batch snapshot-diff
model, wrong fit for one-edit-at-a-time application (every edit would pay
a snapshot-rebuild tax). Keep the fact *algorithms* (`src/backend/
facts/*.rs`), drop the salsa plumbing, replace with hand-rolled
node-ID-keyed fact caches with explicit local invalidation.

This is a full nuke of `src/backend/query/`, `src/backend/salsa.rs`, and
`apply_with_logger`'s 65-stage sequence in `src/backend/mod.rs` -- not
this session's job. Wrote [rewrite-engine-v2.md](../concepts/rewrite-engine-v2.md)
as the handoff spec for the agent that picks this up: target
architecture, what survives (fact algorithms, pass-catalog semantics,
per-rule precondition reasoning) vs what's replaced (all engine plumbing),
known risks (termination isn't automatic; interprocedural rules are a
separate SCC-ordered phase, `slate-y0qs.4`, not part of the local
worklist), validation contract, and a suggested first slice (arena +
worklist + dispatch core, proven on `ZeroInit` + `SingletonScopes` before
porting the rest).

This session's uncommitted retrofit changes (`TouchedItems` etc. in
`src/backend/mod.rs`/`query/item.rs`/`query/mod.rs`) are superseded and
noted as safe to discard in the handoff doc -- nothing from this session
was committed.
