# builtin setjmp/longjmp: wire cir.eh.longjmp, promote built-in-setjmp

_2026-08-23 09:10:17_

slate-os0h.3.1.51: cir.eh.longjmp had no handler (fell through to
todo!()). Added lower_eh_longjmp alongside the existing setjmp stub,
both now raw-lower to plain setjmp(env)/longjmp(env,1) calls so the
existing (wiki: setjmp-longjmp-lowering.md) catch_unwind-based
SetjmpRecovery fixup can recognize them like ordinary library
setjmp/longjmp.

Found src/backend/mod.rs::apply_with_logger has been a no-op (all
~80 fixup passes commented out) since 5c96833f "comment out backend"
(2026-08-14) -- standing repo-wide state, not scoped to this bug.
Selectively re-enabled just Pass::SetjmpRecovery (not the rest) so
this fix has something to feed into.

Two matcher gaps in setjmp_recovery.rs fixed to match __builtin_setjmp's
raw-lowered shape (differs from plain library setjmp callsites):
- setjmp_guard_shape only allowed exactly [let, if] in the guard scope;
  relaxed to allow an arbitrary prefix (buf[0]/buf[2] frame/stack stores)
  and a 3-stmt variant where the bool cast of the setjmp result gets its
  own temp instead of being inlined into the if-condition.
- buffer identity was matched by local temp var name, which differs
  per function; added resolve_buffer_root to chase addr-of chains back
  through let-bindings to the underlying global name so setjmp in one
  function and longjmp in another (e.g. sub2) resolve to the same buffer.

built-in-setjmp promoted to tests/fixtures.gcc-torture/. pr64242 and
pr84521 (same bead) still fail: their jump buffers are stack-locals
passed through an opaque void* function parameter, not globals -- no
identity to resolve to, and they specifically test raw stack-pointer
corruption semantics the catch_unwind model can't represent. Left
open, not a quick fix.

5 stale insta snapshots (frozen while backend was a no-op) updated to
reflect SetjmpRecovery actually running again: enum_wrapper_unwind_abi_
propagation, indirect_call_unwind_abi_propagation, setjmp_recovery_
extern_c_callback, setjmp_recovery_guard, setjmp_recovery_loop_continue.
