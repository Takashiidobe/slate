# Gate glob_t/fnmatch flags by libc; fix wordexp.h size_t bug

_2026-09-08 09:38:05_

(slate-b66b.13.15) Probed glob_t/wordexp_t layout plus GLOB_*/FNM_*/WRDE_*
flag values in tools/probes/linux-libc-abi.c, ran libc-abi-matrix across
all 4 arches x 2 libcs.

wordexp_t and all WRDE_* values already matched both libcs exactly --
no layout bug, but found an unrelated real bug along the way:
libc-shim/include/wordexp.h hardcoded `typedef unsigned long size_t;`
instead of using the standard __NEED_size_t + <bits/types.h> pattern.
unsigned long is wrong on every 32-bit arch (size_t is unsigned int
there) -- this was a silent ODR/type-mismatch bug waiting for any other
TU to also define size_t correctly. Fixed by switching to the standard
include pattern used by every other shim header.

glob_t's core fields (gl_pathc/gl_pathv/gl_offs) and the base GLOB_*
bits (ERR/MARK/NOSORT/DOOFFS/NOCHECK/APPEND/NOESCAPE/PERIOD, bits 0-7)
already matched both libcs bit-for-bit. Two real gaps: shim defined
GLOB_ALTDIRFUNC/BRACE/NOMAGIC/ONLYDIR unconditionally, but musl doesn't
define them at all (glob_t's function-pointer slots there are genuinely
unusable since musl's glob() doesn't support GLOB_ALTDIRFUNC); and shim
never defined GLOB_MAGCHAR (glibc-only, gl_flags feedback bit) at all.
Fixed both by gating the glibc-only extension macros behind
__SLATE_LIBC_GLIBC, matching real header behavior instead of exposing
glibc-only flags unconditionally.

Same pattern for fnmatch.h's FNM_EXTMATCH (glibc-only, musl doesn't
define it) -- gated behind __SLATE_LIBC_GLIBC.

Verified: tools/libc-abi-matrix.py green for glob_t/wordexp_t/GLOB_*/
FNM_*/WRDE_* on all 4 arches x 2 libcs (3213/3213 records), cargo
nextest --profile libc 37/37.
