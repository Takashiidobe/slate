# Implement FreeBSD filesystem and directory ABI

_2026-08-31 07:57:27_

Implemented slate-sfzn.10.4. Real FreeBSD 15.1-RELEASE struct stat is
modern (non-freebsd11), 224 bytes: st_dev,st_ino,st_nlink,st_mode(uint16),
st_bsdflags(int16),st_uid,st_gid,st_padding1,st_rdev,st_atim/mtim/ctim/
birthtim (timespec),st_size,st_blocks,st_blksize(int32),st_flags(uint32),
st_gen,st_filerev,st_spare[9] (uint64 x9). Field order and every offset
verified via offsetof-based _Static_assert against the oracle sysroot
(clang --target=<triple> --sysroot=<oracle>), not -fdump-record-layouts
(that flag silently fell back to host glibc headers when combined with
-isysroot instead of --sysroot -- caught this by noticing the dump showed
glibc's struct stat with __glibc_reserved padding).

struct dirent is 280 bytes: d_fileno,d_off,d_reclen,d_type,d_pad0,
d_namlen,d_pad1,d_name[256]. FreeBSD's field is already named d_fileno (not
d_ino), so suppressed the shared "#define d_fileno d_ino" compat macro for
FreeBSD. getdents(2) has a FreeBSD-specific signature (ssize_t(int,char*,
size_t) vs Linux's int(int,struct dirent*,size_t)) so it got its own
declaration.

fcntl.h O_*/F_*/AT_* are BSD-style bit values, genuinely distinct from
Darwin's BSD-style values too, not just from glibc's octal ones:
AT_FDCWD=-100 (Darwin -2), O_CLOEXEC=0x00100000 (Darwin 0x01000000),
F_DUPFD_CLOEXEC=17 (Darwin 67), F_GETLK/SETLK/SETLKW=11/12/13 (Darwin
7/8/9). Added bits/freebsd/fcntl.h and gated every existing glibc-style
octal O_*/F_*/AT_* block in the shared fcntl.h to also exclude
__SLATE_LIBC_FREEBSD (previously only excluded Darwin).

struct statvfs field order is FreeBSD-specific: f_bavail,f_bfree,f_blocks,
f_favail,f_ffree,f_files,f_bsize,f_flag,f_frsize,f_fsid,f_namemax -- not
the bsize/frsize-first order both the generic branch and Darwin use.
ST_RDONLY/ST_NOSUID values matched Darwin's, reused that branch.

unistd.h filesystem calls needed no changes (already libc-agnostic
prototypes). Left _PC_* pathconf constants alone -- they're glibc-numbered
with no per-libc gating for any libc including Darwin, a pre-existing gap
out of scope here, deferred to slate-sfzn.10.10 (feature-selection/
symbol-versioning).

New libc-shim/freebsd-filesystem-headers.txt manifest and
freebsd_filesystem_header_manifest_compiles_for_x86_64_and_aarch64 test in
tests/header_compilation.rs, with offsetof-based _Static_assert checks for
struct stat/dirent field positions and O_*/F_*/AT_* values on both
architectures.

Verified end-to-end: slate translate on a fixture exercising open/fstat/
opendir/readdir/statvfs for both x86_64/aarch64-unknown-freebsd produces
Rust structs matching the verified oracle layout field-for-field; cargo
check --target {x86_64,aarch64}-unknown-freebsd against the generated Rust
(with the libc crate) succeeds on both, clean except pre-existing benign
improper_ctypes warnings on the opaque DIR type (same as other libc
profiles). cargo fmt/clippy clean; nextest --profile libc 26/26, --profile
lowering 10/10, no regressions.

Ran concurrently with another agent doing cleanup work in libc-shim/bits/;
no file collisions this time (10.4 touched dirent.h/fcntl.h/sys/stat.h/
sys/statvfs.h/bits/freebsd/*, none of which overlapped their working set).
