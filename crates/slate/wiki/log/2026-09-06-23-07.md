# AArch64 'r' constraint: arch-dispatch register-width modifiers

_2026-09-06 23:07:17_

slate-3f8g.4.16.5: plain 'r' already worked (Generic -> AsmReg::Class("reg") is arch-agnostic). The real gap was register-width modifier selection, hardcoded to x86's l/x/e/r letters via RegWidth::att_size_modifier regardless of target. Added TargetArch dispatch in rust_asm_register_modifier: AArch64 uses only w (<=32-bit, Wn) / x (64-bit, Xn, default); ARM and RISC-V get no modifier (single-width GPRs). Added TemplateModifier::RegisterWidth for GCC's explicit %w/%x template overrides, gated to Arm64 only since x86 has an unrelated %w letter owned by the still-open slate-3f8g.4.15.9. Threaded a new Lowerer::target_arch field through translate_asm_template/render_operand_reference/register_modifier_suffix/parse_asm_template.

Also fixed a blocker hit while verifying on real aarch64 codegen: cir_asm_dialect (X86Att/X86Intel only) was unconditionally returning Some(Att) even for non-x86 asm ops, so every generated asm! carried options(att_syntax) -- an x86-only option rustc rejects elsewhere. Gated dialect resolution on TargetArch::is_x86() at the one call site in intrinsics.rs.

New fixture tests/fixtures/asm_aarch64_reg_width_modifiers.c (dg-do restricted to aarch64*-*-*, AARCH64-GNU-only FileCheck prefixes so it's excluded from the default x86_64 differential run). Verified via SLATE_TARGET=aarch64-unknown-linux-gnu translate output, and runtime-differentially tested under qemu-aarch64-static (aarch64-lowering and aarch64-rewrites profiles, SLATE_DIFF_FIXTURE-scoped) plus the full x86_64 lowering profile for regression coverage. Wiki updated with a new AArch64 section in wiki/concepts/inline-asm-support.md.
