# TranslationUnit holds the Dialect; sema reads it (iwsx step 2)

_2026-09-28 14:20:01_

TranslationUnit now carries dialect: Dialect in place of standard/flavor/target/options, and every sema entry point reads it instead of rebuilding configuration.

- Context::for_dialect replaces Context::new(...).with_options(...).with_features(...).with_contraction(default_contraction(...)), which sema/mod.rs and sema/module.rs each assembled by hand. default_contraction is now called only there.
- TypeResolver::with_tags(unit) drops its target parameter; every caller passed the unit's effective target anyway (assertion.rs and types.rs re-applied effective_target, Context::with_options applied it a third time; all idempotent).
- validate.rs, names.rs, module.rs, assertion.rs, reachability.rs read flavor/standard/features/target/options from unit.dialect. validate.rs previously used the raw target for literal checks.
- Inline semantics moved to Dialect::inline_semantics (options override, else features.inline_semantics); CompilerOptions::effective_inline_semantics is gone and StandardFeatures::new is private, so flavor-blind features can only come from StandardFeatures::default.

Left: TypeResolver::constant_value (types.rs ~400) builds a partial Context (target + features only; default overflow, floating and contraction), diverging from the module context. StandardFeatures::default is still the fallback in Lexer, const_expr without a parser, numeric::Context::new and TypeResolver::new.

Validation: cargo nextest run --release --no-fail-fast, 7264 passed, no FileCheck changes. Wiki: ast-spec, ast-grammar, ast-enum-touchpoints, ir-spec, compiler-flags updated for TranslationUnit.dialect.
