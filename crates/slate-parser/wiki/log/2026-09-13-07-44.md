# Migrate first 250 gcc-torture fixtures to FileCheck

_2026-09-13 07:44:28_

Attempted the first 250 alphabetical fixtures from tests/upstream/fixtures.gcc-torture.
239 migrated into tests/fixtures/gcc-torture with generated FileCheck expectations
(SLATE-FILECHECK-DEFINES DEFAULT, plus SLATE-FILECHECK-ISYSTEM for 27 files that
#include system headers, pointing at ~/Projects/slate/libc-shim/include).

11 failed to parse; filed as slate-parser-wf8.3.1 through .10 (one bead covers two
files sharing the GNU statement-expression root cause). Root causes: non-UTF-8 raw
byte in a string literal, ull-suffixed #if constants, tag/member namespace
collision, compound literal after return, nested tag+pointer field declarator,
wide/narrow string literal concatenation+indexing, typedef of tag+pointer
declarator, GNU statement expressions, register on function parameters, and
GNU __real/__imag operators. Their source files were left out of tests/fixtures
entirely (matching the gcc-dg convention) rather than partially migrated.

Found and fixed a real bug in tools/update_filecheck.py: CHECK_RE matched any
"// Word:"-shaped comment anywhere in a fixture, not just generated FileCheck
lines, so replace_blocks() silently deleted legitimate source comments shaped
like "// Origin: ...". Restricted the strip to the fixture's actual declared
prefixes (from SLATE-FILECHECK-DEFINES/-ERROR). Also fixed the script to read/
write fixtures with errors="surrogateescape" so it doesn't crash outright on a
non-UTF-8 fixture (the cargo parser still correctly rejects the invalid content).
