# Microsoft record layout for windows-msvc targets

_2026-09-28 09:15:03_

slate-parser-7y5: every *-windows-msvc triple (x86_64, i686, aarch64, thumbv7a) now uses layout_microsoft_record (sema/types.rs). It is a port of clang's MicrosoftRecordLayoutBuilder for C records, chosen by target environment under both the clang and msvc flavors. ms_struct/gcc_struct make no difference, as in clang.

- Bit-fields share a unit only if their declared types are the same size
  and the next one fits. Union bit-fields don't raise alignment.
- A zero-width bit-field counts only right after a non-zero-width
  bit-field.
- packed on the record = pack(1). A pack wider than a pointer is ignored.
- Required alignment (field aligned/_Alignas, aligned typedef, nested
  record's required_align) isn't capped by pack. On bit-fields it raises
  that field's alignment instead.
- Records with no storage are 4 bytes, or their alignment when required
  alignment is >= 4. The 64-bit targets always do the final rounding.
- Shared with Itanium: member_storage, checked_bit_width, bit_field_units
  (discrete declared-type units for MS and ms_struct).
- Verified: 95 probe records match clang -fdump-record-layouts on all four
  triples. tools/cl.exe (x64/x86/arm64) accepts sizeof/_Alignof asserts
  from clang's values on the 70-record cl-compatible subset.
- 13 clang-test suite fixtures regenerated; every record check_record_layout
  could compare matches clang (empty-layout, ms_bitfield_layout,
  anonymous-union-init, format-strings-bitfield-promotion,
  ms-anachronism).
- Found: i686 Win32 returns an empty record as coerce<i32> (was sret);
  clang ignores it -> slate-parser-ohze. The empty-record argument (clang
  byval align 4, slate coerce<>) is another instance of slate-parser-hy3i.
  x86_32-fpcc-struct-return.c records the current wrong answer.
- Fixtures: {clang,msvc}/windows/*/ms_record_layout.c. ir-spec.md has a new
  'Microsoft record layout' section, replacing the 'not a Microsoft ABI
  oracle' caveat.
