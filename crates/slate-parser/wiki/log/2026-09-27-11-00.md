# Target registry: one TargetSpec per triple

_2026-09-27 11:00:25_

slate-parser-78x3.1. New src/target_registry.rs holds one TargetSpec per
supported triple: a TargetInfo layout constructor plus a TargetProfile
(per-flavor Predefines, SysrootLayout, ClangHeaders, VaListKind,
AbiConvention). TargetInfo carries the profile; for_triple looks the triple
up and fills triple/profile, so constructors no longer take or set it
(arm32 and windows-msvc split into per-environment/per-family fns).

Routed through it, deleting their private matches and suffix checks:
seed_builtin_macros, sysroot::include_paths_at (msvc flavor still forces the
Windows kits layout), compiler_headers::include_paths (apple-darwin check ->
ClangHeaders::AppleFirst), abi_convention (only the Aapcs32 hard-float
promotion remains), va_list_kind, and the x86_64 stack-boundary rule.

An unsupported triple x flavor is now rejected at argument parsing
(for_triple_and_flavor, "the Gcc flavor is not supported on ..."); only
unsupported_gcc.c changed. No other expectation was regenerated.

Harness: new per-prefix directive SLATE-FILECHECK-PREFIX-ARGS <PREFIX> args
(tests/filecheck.rs and tools/update_filecheck.py). New fixture
sema/target_registry.c runs a predefines/sizeof/va_list/record-ABI probe
under all 28 registered triple x flavor combinations.

Linux entries give every flavor clang's predefines (pre-existing); filed
78x3.2. corpus_sweep.py's sysroot list is documented as a mirror. Wiki:
compiler-arg-rules.md updated, new concepts/adding-a-target.md.
