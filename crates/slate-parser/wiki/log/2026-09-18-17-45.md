# Stringification uses a per-token leading-space flag

_2026-09-18 17:45:50_

slate-parser-fsf redone. The first attempt inferred spacing from source-offset adjacency and failed across macro boundaries (T(P(1)+2) gave '1 +2') and for __VA_ARGS__ commas. Now like clang: Span<T> carries leading_space, set by the lexer for whitespace, newlines and comments; a macro expansion's first token takes the flag of the macro name it replaces, and a substituted argument's first token takes the flag of its parameter in the replacement list; ## keeps the left operand's flag. invocation_arguments now returns the dropped commas so __VA_ARGS__ restores them with their original flags. stringized_source emits a space only where a token (after the first) has the flag. Fixture stringify_spacing.c is compared against clang -E for 14 cases. Not covered: __VA_OPT__ contents still drop their inner commas (pre-existing).
