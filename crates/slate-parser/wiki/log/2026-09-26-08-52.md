# Fold floating arithmetic in integer constant contexts

_2026-09-26 08:52:30_

slate-parser-wxs.5 survey. The notes' three accept-where-clang-errors items are settled.
Duplicate case values and non-constant global initializers are rejected by clang, gcc
and cl, so slate accepting them is permissive (no valid program reaches them).
'int x = 1/0' was already an error for clang/gcc, and msvc folds it to 0 as cl does.
A sweep of valid-but-awkward constant expressions found two too-strict bugs. The
pointer->_Bool conversion is slate-parser-dyd.68. The other is this change.

fold.rs float_to_integer only accepted an immediate (optionally negated) floating
constant, which is C's literal ICE rule, so enum { E = (int)(2.5 * 2) }, array
bounds, bit-field widths and _Static_assert on such expressions failed. clang, gcc
and cl all fold them. The folder now evaluates floating constants, neg, add/sub/mul/div,
int->float, float widen/narrow/convert and conditionals (fold::floating), plus float
comparisons in the integer evaluator. Values travel as rustc_apfloat Quad, which
holds every binary format exactly, and each operation narrows to its own format and
rounds nearest-even. That reproduces clang -emit-llvm on 0.1f+0.2f==0.3f (1),
0.1+0.2==0.3 (0), (float)16777217, and long double chains. Decimal formats never fold.

An out-of-range float->int conversion (UB) folds per flavor, all measured:
- clang saturates, NaN -> 0.
- cl wraps the integer part below 2^64 and folds larger values, inf and NaN to 0.
  cl's one inconsistency, (unsigned char)300.5 -> 300, is not modelled.
- gcc rejects, and so do we.
ir_control_float_case_overflow.c had recorded case (int)1e100 as an error. clang
accepts it as INT_MAX, and that is now the expectation.

A block-scope char buf[(int)(2.5*2)] is now a constant array, as clang folds it.
Filed: gcc-flavor folding of static const objects (sizeof(char[k])).
Fixtures: sema/ir_float_constant_folding{,_msvc,_gcc}.c. ir-spec.md updated.
