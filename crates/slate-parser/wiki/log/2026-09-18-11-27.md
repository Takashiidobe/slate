# Parse _Decimal32/64/128 type specifiers

_2026-09-18 11:27:05_

slate-parser-ixa.36: `_Decimal64 d;` failed with 'unknown type name'.

- Lexer: `_Decimal32`, `_Decimal64`, `_Decimal128` lex as new keywords, gated on
  `StandardFeatures::decimal_floating_point`.
- AST: `FloatingType::{Decimal32, Decimal64, Decimal128}`; parsed in
  `parse_base_type` and recognized by `starts_type_name`. The DF/DD/DL literal
  suffixes already parsed into `FloatSuffix::DecimalF*`.
- `StandardFeatures::decimal_floating_point` is `Standard` from C23 (Annex H) and
  `Extension` before, never `Rejected`.

Decision: availability is not gated on compiler flavor or target. Clang rejects
these types, and gcc only enables them on x86/x86_64/aarch64/ppc/s390 Linux. That is
the implementation's choice, not the language's. Input is assumed to already compile
with the real compiler, and sema is a debugging aid, so whether the type is usable
is Slate's decision. A first attempt added `TargetInfo::supports_decimal_float(flavor)`
and sema errors mirroring clang/gcc wording; it was dropped for this reason.

Sema/IR type resolution still returns Unsupported("floating type") for them;
decimal arithmetic in the IR is out of scope.

Fixture: tests/fixtures/decimal_float.c (C89 and C23 runs). Also regenerated four
<math.h> fixtures (gnu_libm, long_double, gcc-torture 980709-1, 990826-0) for an
unrelated libc-shim math.h change.
