# MS sized integer keywords

_2026-09-27 09:42:08_

Closed slate-parser-v74.1.1.

- __int8, __int16 and __int32 (and the single-underscore _intN forms) now lex as the char, short and int keywords, as clang aliases them.
- __int64 is a new Keyword::Int64. It acts as a long long width, so clang-cl's __int64 unsigned int and long __int64 parse too; cl.exe rejects both.
- They are keywords only under --flavor=msvc, or --flavor=clang with a *-windows-msvc target. This mirrors clang turning on -fms-extensions for those targets, and is decided by microsoft_keywords_enabled when the preprocessor is configured, via StandardFeatures::microsoft_keywords. Everywhere else they stay identifiers (int __int64; still works under gcc).

Checked against clang --target=x86_64-pc-windows-msvc, cl.exe, gcc and Linux clang, using _Generic type identity for every form. Fixtures: ms-sized-int-keywords-{msvc,clang-cl,off}.c. vadefs.h no longer fails, so the next blocker for every CRT header is __pragma at vcruntime.h:96 (v74.1.2).

Existing bugs found and filed:
- kck: specifiers only parse in fixed orders.
- vp7: macros named like keywords are ignored.
- 9piq: keyword aliases lose their spelling when stringized.
