# Fold layout constants through sema, not the token-level const folder

_2026-09-20 20:31:17_

Bit-field widths, array designators and `aligned`/`_Alignas` operands were
folded by `const_expr::Parser::evaluate_ast`, the token-level evaluator the
preprocessor uses. It has no types, no target and no scope, so `sizeof(int)`,
an enumerator or a `constexpr` object in any of those positions failed with
`sizeof is not supported here` / `unsupported identifier`. Array *bounds*
already used `TypeResolver::constant_integer`; these three did not.

Routed all of them through `constant_integer`. `array_index` became a
`TypeResolver` method (`Lowerer::resolve` had to take `&mut self`).

Attribute operands were never name-resolved: `Resolver::declarator` dropped
`Declarator::Attributed`'s attributes, and nothing walked
`InitDeclaratorKind::attributes` or `DeclarationSpecifiers::attributes`. So
`__attribute__((aligned(sizeof(x))))` could not see `x` even once folding was
target-aware. Added the three `walk_attributes` calls.

Enumerators now enter the ordinary scope as `int` constants inside the first
resolution loop, which deleted `substitute_enumerators` — textual replacement
never descended into `sizeof`, and a substituted literal loses the
enumerator's type. Sweep results were byte-identical without it.

Also: `constexpr` objects declare an `Ordinary::Constant` (both in
`module.rs` for lowering and `assertion.rs` for the static-assert walk, the
same split enumerators already use); `sizeof (1, foo)` types the comma
through `lvalue_conversion`; `__real__`/`__imag__` accept real operands.

Corpus IR sweep: 2574/2688 -> 2582/2688. Filed dyd.36 (GNU variable-size
struct members) and dyd.37 (Attribute::Invalid should warn, not fail).
