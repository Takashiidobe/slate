# Lower numeric unary minus and bitwise not to IR

_2026-09-14 20:22:37_

sema::numeric now lowers unary `-`, `~`, and `+`; `!` and `++`/`--` are deferred.

- ir gains `UnaryArithOp { Neg, Not }` and `ValueKind::Unary { op, operand, semantics }`. The printer shares `format_semantics` between binary and unary nodes.
- `ArithSema::Bitwise` renamed to `ArithSema::Exact`: it now also covers floating `neg`, which has no overflow/rounding/exception behavior.
- Clang 22: signed `-x` is `sub nsw 0, x`, plain `sub` under -fwrapv, `ssub.with.overflow` under -ftrapv, so signed `neg` uses the context overflow policy; unsigned wraps. `~x` is `xor x, -1` under every flag. `fneg` is unchanged by -frounding-math, so `neg<f64>(..)` has no metadata.
- `~` on a floating operand -> new `InvalidOperand { operator, operand }` error (clang: invalid argument type to unary expression).
- Unary `+` is pruned like parens: it only promotes, and literals need no promotion yet. Once identifiers of sub-int types exist, `+`, `-`, and `~` must insert promotions.
- `!` -> unsupported "logical not (requires bool lowering)"; prefix and postfix `++`/`--` -> unsupported "increment and decrement (requires place lowering)".
- Fixtures: unary cases in sema/numeric_seed.c (incl. `-2147483648` as neg<i64>), flags_wrap.c/flags_trap.c, and FLOAT_BITNOT/LOGICAL_NOT/PRE_INCREMENT/POST_DECREMENT in unsupported.c.
- wiki: ir-spec.md numeric seed and compiler-flags.md updated. lh7.2.3 stays open (comparisons, conversions).
