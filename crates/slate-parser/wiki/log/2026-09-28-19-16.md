# Checker and lowering share one TypeResolver

_2026-09-28 19:16:33_

slate-parser-cc94.6. Sema builds one TypeResolver; analyze runs the static-assertion checker over it and lower takes it over (entities reset), so lowering reads the checker's tags, aliases, constants and memoized expression types.

- Memo by AST node so the second walk finds definitions: define_tag also memoizes failures by TagId (tag_failures; ResolveError, names::ResolveError and LayoutError derive Clone); define_alias memoizes by declarator NodeId and returns the alias TypeId, which lowering annotates at module assembly (Lowerer.alias_annotations).
- Type definition spans: TypeResolver.owner is set around declarator/parameter/function resolution in both walks and push records owners[TypeId]; Lowerer.type_spans and the definitions[start..] diffing are gone. Spans now derive the final definition, fixing tags printed 'incomplete' when first used before their completion (e.g. glibc _IO_FILE via FILE; ~70 fixtures).
- Checker now walks do-while body before condition, resolves empty declarations like lowering, and resolves type names inside expressions, keeping TypeIds in source order.
- Checker resolver warnings are stored per item (item_diagnostics) and replayed when lowering reaches the item, so warning order is unchanged.
- Fixed-type enum reference no longer overwrites an enum its own fixed type defined (c23-enum-6: enum e4 : typeof((enum e4 : long {...})0, 0L)).
- __asm member lookup is bounded by a watermark names.rs records per member (NameResolution.ms_asm_members), since the checker already defined later tags.
- Removed dead TypeResolver.assertion_scope.
- Accepted: a VLA typedef is numbered when lowering reaches it (variable_length_array_typedefs.c reorders two aliases).
