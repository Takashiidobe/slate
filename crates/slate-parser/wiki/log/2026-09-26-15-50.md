# Condition scope for if/while/do/switch in IR lowering

_2026-09-26 15:50:30_

slate-parser-dyd.40. parser_control_bodies.c failed IR lowering under C99 with
'unknown typedef': `if (sizeof(enum { T = 1 })) ...; return sizeof(T);` with a
file-scope `typedef int T`.

The parser and names.rs already gave C99+ selection/iteration statements their
own block (C11 6.8.4p3, 6.8.5p5) via control_statement_scopes. The lowerer in
sema/module.rs did not: it scoped each body, and `for` as a whole, but lowered
the if/while/do/switch controlling expression in the enclosing TypeResolver
scope. The enumerator T declared there then hid the typedef T for the rest of
the function, so the later `sizeof(T)` found no typedef.

Added Lowerer::control_scoped, which wraps the whole statement in scoped() when
control_statement_scopes is set and runs it directly under C89/GNU89, where the
enumerator really does leak. If, While, DoWhile and Switch use it.

Fixtures: parser_control_bodies.c drops its C99 IR-ERROR. sema/
control_body_scopes.c gains typedef_* cases with `typedef double T` so the
two readings differ: C89 returns 4 (enumerator), C99 returns 8 (typedef),
matching clang and gcc at runtime. Existing enumerator-vs-enumerator cases
there never caught this because ordinary identifiers resolve through names.rs;
only typedef lookups go through the lowerer's TypeResolver scopes.

ir-spec.md: the block-scope typedef section already claimed selection/iteration
statements were scoped; it now notes the C89 gating.
