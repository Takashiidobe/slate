# Tag references declare incomplete tags instead of failing

_2026-09-20 19:53:02_

slate-parser-dyd.5. The corpus sweep showed 51 fixtures rejected with
`unresolved tag name` (`_IO_FILE` x28, `_foo`, `bar`, `PgHdr`, `E`,
`Opaque`, ...). All of them were legal C that clang accepts.

Three rules were missing.

1. `names.rs::declaration` only treated a declarator-less tag declaration as
   declaring the tag when it had no fixed underlying type, so C23
   `enum E : unsigned char;` went down the reference path and failed.
2. `names.rs::reference_tag` errored on a lookup miss. Per C11 6.7.2.3p8 a
   tag specifier whose identifier is not visible *declares* an incomplete tag
   in the current scope, which is what makes `typedef struct _IO_FILE FILE;`
   and `struct Holder { struct Member *m; };` legal with no prior
   declaration.
3. Both `define_tag`s minted a fresh entry for a tag already declared in the
   innermost scope, so a forward declaration and its definition were two
   bindings (`bar`, `bar#1`) and a reference before the definition pointed at
   the incomplete one.

`types.rs` also fell back to searching the whole translation unit's tags by
name when its scoped `tag_names` lookup missed. That bound a block-scope
`struct T *p;` to an unrelated file-scope `struct T` defined later in the
file. Removed: a miss now pushes an incomplete tag into the current scope and
the later definition completes it only if it is in that same scope.

Corpus sweep: 2504/2687 -> 2554/2687 accepted, no regressions. Only two
fixtures needed regenerated expectations (binding-id renumbering from the
collapsed duplicates); `sema/ir_tag_scopes.c` gained implicit-declaration and
block-scope-hiding cases.
