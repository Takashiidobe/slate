# K&R definitions rewritten with promoted parameter types

_2026-09-14 12:01:17_

parse_kr_parameter_declarations (src/parser/stmt.rs) already rewrote K&R
old-style function definitions into a Vec<Parameter> at parse time (there
was never a separate IdentifierList/kr_declarations AST lane in the actual
code, only in ast-spec.md's aspirational description), but it used the
literal declared type for each parameter. Callers of an unprototyped
function apply default argument promotions, so the real ABI parameter type
differs: 'int knr(a, b) int a; char b; {...}' must be called as if b were
int, and any float parameter as if it were double.

Added Parameter.declared_ty: Option<CType> (None when unpromoted) and a
default_argument_promotion() helper (char/_Bool/short -> int, float ->
double) used only by the K&R rewrite; implicit-int parameters (no
declaration at all) are already int so declared_ty stays None for them.
Every other Parameter constructor sets declared_ty: None since prototype
parameters are never promoted.

Also fixed a regression slate-parser-ixa.1's split_top_level_items() fix
introduced: a K&R definition entirely on one physical source line (e.g.
'int knr(a, b) int a; char b; { return a+b; }') got chopped into three
bogus top-level items at the K&R declarations' semicolons, since nothing
recognized 'name(a, b)' followed by old-style parameter declarations as
one function. Fixed by detecting a top-level '(a, b)' bare-identifier-list
preceded by a name (the unambiguous K&R marker) and staying armed through
the following declarations' semicolons until the body's matching '{...}',
the same way the existing function_body heuristic treats an ordinary
'name(...) { ... }'.

Updated wiki/concepts/ast-spec.md to drop ParameterList::IdentifierList and
FunctionDefinition.kr_declarations (the decided design has no K&R side
lane) and describe ParameterDeclaration.declared_specifiers as the
promoted-type analog for the future TypeSpecifier/Declarator model
(lh7.3.5, not yet implemented).

Regenerated two gcc-torture fixtures whose K&R char parameter now shows
declared_ty, and added tests/fixtures/knr_promoted_parameters.c
(char/short/float/implicit-int) per slate-parser-ixa.3's acceptance
criteria.
