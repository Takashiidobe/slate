# Diagnose non-foldable calls in static assertions

_2026-09-19 14:49:25_

slate-parser-ifc. The bead proposed diagnosing calls, string literals, compound literals, and the comma operator at the top level of a static assertion. Tested against clang 22.1.8: in C, clang folds strings, compound literals, commas, and `"abc"[0]` as a GNU extension (`-Wgnu-folding-constant` under -pedantic). Only calls are rejected, so only calls are diagnosed. gcc rejects all of them, but input is assumed to compile with clang.

clang CheckICE sends a call to CheckEvalInICE only when getBuiltinCallee() is set. Whether it folds depends on ExprConstant handling that builtin. `strlen("ab")` folds, `abs(-2)` does not.

- `src/sema/builtins.rs`: `FOLDABLE_BUILTINS`, a hand-owned sorted table seeded from every `case Builtin::BI*` / `X86::BI*` label in clang/lib/AST/ExprConstant.cpp (llvm 58dd40228595), plus `__builtin_choose_expr` (a ChooseExpr in clang, a Call in our AST). Add GCC-only foldable builtins here.
- `ice_shape` now returns `Shape::{Constant, Skip, NotConstant(call)}`. A call whose callee (with parens stripped) is not in the table is `NotConstant`. A foldable builtin is `Skip` (we cannot evaluate it yet). The RHS of a short-circuited `&&`/`||` and an untaken `?:` arm are unevaluated, so their calls downgrade to `Skip`; if the deciding operand cannot be folded, both sides count as unevaluated. Comma and non-ICE unary operators propagate `NotConstant` and otherwise skip.
- Enumerator values still use only `Constant`.
- Fixture sema/static_assert_validation.c: CALL, CALL_POINTER, CALL_COMMA, CALL_LIBRARY, plus valid short-circuit, sizeof, _Generic, clz, strlen, and choose_expr cases. All were cross-checked with clang.
