# Expand macro arguments lazily and stop cloning definitions per invocation

_2026-09-28 07:33:07_

slate-parser-xgj9 (partial). windows.h fixture 805ms -> 663ms (1.21x).

Measured copy amplification first: 275k output tokens cost ~3M
Span<Token> clones in expansion (785k from cloning the whole MacroDef per
function-like invocation to restamp expansion/macro_origin, 600k from
eagerly expanding every argument, the rest from substitution and nested
results). Every Token string clone is a malloc+free; libc malloc/free/
memcpy is ~50% of the whole run.

Changes:
- Stamp: definition tokens get expansion/macro_origin as they are
  substituted; no MacroDef or parameter-list clone per invocation.
- Arguments are pre-expanded only if some use is not an operand of # or
  ## (any __VA_OPT__ in the body keeps every argument prescanned), and
  only if they contain an identifier that could expand. This matches
  clang/gcc: an unused, stringized or pasted __COUNTER__ argument no
  longer bumps the counter (old: 7, clang/gcc: 4 in gnu_counter.c,
  which now covers it).
- __VA_OPT__ detection no longer allocates a String per token.
- foldhash for the macro table and disabled sets (~2%).
- Dropped PPNodeKind::Code.text, never read but rebuilt per line (~1.5%).

Tried and dropped: moving the non-expanding prefix of a replacement
through rescan instead of re-cloning it (no measurable gain).

Experiment: mimalloc as the global allocator takes ~23% off the run,
which confirms allocation count is the main remaining cost; Token's
String payloads (Span<Token> is 144 bytes) are the next target.
