# Reject the - asm constraint modifier inside functions

_2026-09-26 22:39:22_

gcc and clang both reject `-` on an asm operand inside a function (clang: invalid input constraint '-r'; gcc: '-' modifier used inside of a function), and we accepted it. Now a parse error with clang's wording under every flavor.

Kept it at file scope: gcc 16 accepts `asm("# %0" : : "-i"(42));` and emits `# $42` (the gcc 15 toplevel-asm symbol/constant modifier). clang has no file-scope operand form at all and we already gate that to the gcc flavor, so dropping `-` there would make gcc too strict. The user asked to disallow `-` outright; I pushed back on the file-scope half with that evidence.

Fixtures: asm-statement.c and sema/ir_asm.c input "%-rm,r" -> "%rm,r"; new error/asm-pic-modifier-in-function.c; asm-file-scope-operands-gcc.c gained a "-i" case.
