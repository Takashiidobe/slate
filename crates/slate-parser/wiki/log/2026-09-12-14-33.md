# Macro-expand #if/#elif expressions

_2026-09-12 14:33:37_

evaluate_condition now expands object- and function-like macros in #if/#elif
tokens before handing them to const_expr, instead of evaluating unknown
identifiers as 0 (e.g. '#define VERSION 3 / #if VERSION >= 2' was false).

Operands of 'defined X', 'defined(X)', and '__has_*(...)' are left
unexpanded (expand.rs unexpanded_operands), matching clang.

When a macro in the expression has divergent definitions across
configurations (divergent_macro_conditions, same check expand_line uses),
the expression is evaluated once per definition condition and combined as
Or(cond_i AND Constant(value_i)), then simplified, so '#if WIDTH == 64'
after '#ifdef WIDE / #define WIDTH 64 / #else / #define WIDTH 32' yields
Defined(WIDE) / Not(Defined(WIDE)) branches.

Expression errors inside an expansion are reported at the use site
(token.expansion loc) rather than the macro definition.

New fixtures: pp-if-macro-expansion.c (DEFAULT, WIDE),
if-expression-macro-invalid.c.
