# Merge switch/case and goto labels into nesting Stmt variants

_2026-09-14 09:09:54_

slate-parser-lh7.3.9 asked for Box<Stmt> bodies everywhere plus a unified Labeled container (per wiki/concepts/ast-spec.md's target Statements section). Discussed scope with the user first: then_branch/body on If/While/DoWhile/For/Switch are already Vec<SpannedStmt>, so 'captures the body as a Vec<Stmt>' was already true -- the real gap was that a braced compound-statement body gets flattened into that Vec exactly like a brace-less single statement, losing brace-presence info. User said not to bother distinguishing braces for now; the part that mattered was 'case chains nest' -- case 1: case 2: x; was parsing as three flat sequential Stmt list items (Case(1), Case(2), Expr(x)) instead of nesting.

Replaced Stmt::Case(Expr)/CaseRange{start,end}/Default/Labeled(String) with two variants: Stmt::Labeled { label: String, body: Box<Stmt> } for goto targets, and Stmt::SwitchLabel { label: SwitchLabel, body: Box<Stmt> } for case/case-range/default, where SwitchLabel = Case(Expr) | CaseRange{start,end} | Default. Deliberately NOT one shared Label enum with a Named variant mixed into the switch-label set -- a goto label and a switch case are different things that happen to share the same syntax spelling, and folding them into one enum would mean every case/default match site has to rule out a Named arm that can never apply there. This was a direct user correction after an initial proposal to use a single Label enum.

parser/stmt.rs: parse_one_stmt's named-label/case/case-range/default branches now call a new parse_labeled_body helper that recursively parses the next statement as body instead of returning a bare marker Stmt. This naturally produces the nesting (case 1: case 2: x; becomes SwitchLabel(Case 1, body SwitchLabel(Case 2, body Expr x))) without any special-casing at the block/body level. parse_body's old loop-while-is_label flattening logic is gone -- it now just parses one statement and wraps it in a single-element Vec, since a chain of labels is already one nested Stmt. parse_labeled_body falls back to an empty Stmt::Block(Vec::new()) as body when a label has nothing parseable after it (end of a block, or immediately before the closing brace), verified against a scratch fixture (label at end of an if-body) -- did not add this as a permanent fixture since it is a narrow edge case already covered by existing dead-code paths.

Updated sema.rs (walk_stmt's exhaustive match, and check_function_asm's label-scope tracker), reachability.rs (Reachability::mark_stmt), and tests/filecheck.rs's summarize_evaluated_decl to match the new variants -- all now recurse into body the same way they already recursed into Block's statement list.

Regenerated all ~2400 FileCheck fixtures. wiki/concepts/ast-spec.md's Statements section and Migration table updated to reflect the actual implemented shape (Labeled/SwitchLabel split, not a single Label enum; if/loop bodies still Vec<Stmt> with braces not preserved). wiki/concepts/ast-enum-touchpoints.md's Adding-a-Stmt-variant section got a note about the two new variants needing recursion into body in every exhaustive match.

Brace-preservation (the other half of the original ticket) stays unimplemented -- explicit user descope, not filed as a follow-up bead.
