# Rust asm options derived during lowering

_2026-09-27 08:29:42_

slate-parser-25m.16. Statement asm now carries InlineAsm::options: Some(AsmOptions)
{memory: AsmMemory::{None,ReadOnly,Any}, pure, nostack, preserves_flags, may_unwind},
computed in sema/asm.rs options() via Lowerer::asm_statement. File-scope asm keeps None
(global_asm! takes no options). Printed as [options=...] after [dialect=...].

Oracle findings that shaped the rules:
- clang attaches memory(none)/memory(read) only to non-side-effecting asm (not volatile,
  has outputs, not goto); volatile asm is a full memory barrier in LLVM.
- gcc -O2 removes a dead store across asm volatile("nop" :: "r"(x)) (so volatile extended
  asm is nomem under gcc), but not across basic asm: gcc expands basic asm with
  (clobber (mem:BLK (scratch))).
- So memory is flavor-dependent: clang forces Any for side-effecting asm, gcc does not.
- x86 always clobbers flags/dirflag/fpsr (both compilers), so preserves_flags is never
  set there. gcc aarch64 adds (clobber (reg:CC cc)) only for "cc"; clang adds nothing.
- clang never emits alignstack on GNU asm, so nostack is always set. MSVC __asm
  (25m.6) should not be: clang gives MS asm alignstack.
- pure requires nomem or readonly in Rust, so memory clobber or memory output drops it.

A memory-class In (spilled rvalue) counts as a read, matching clang's readonly.
Selection uses AsmOperand::selected, so "rm" that picked reg stays nomem (more precise
than clang, which says readonly for any memory-allowing input).
