# slate-parser-119.3: computed goto, nested functions, VLA parsing

_2026-09-12 07:58:30_

Added parse-only AST support for three GNU/C99 extensions (slate-parser-119.3):

- Computed goto: `goto *expr;` -> new Stmt::ComputedGoto(Expr); label-as-value
  `&&label` -> new ConstExpr::LabelAddr(String), parsed in const_expr::Parser::parse_unary.
- GNU nested function definitions: a function def inside a function body ->
  new Stmt::NestedFunction(Box<FunctionDecl>), detected via new
  Parser::try_parse_nested_function (mirrors parse_function's signature parsing
  but token-based, bails to normal declaration parsing if it doesn't look like
  a nested function).
- VLAs: array declarator bounds no longer require constant-folding. parse_declarator
  now falls back to ArraySize::Expression(Expr::Const(..)) for non-constant bounds
  instead of panicking, and added ArraySize::Star for `[*]` unspecified-VLA params.

All new AST variants threaded through eval.rs (Concrete lowering), sema.rs, and
tests/filecheck.rs (which has exhaustive matches on Stmt/ArraySize).

Fixtures: tests/fixtures/computed-goto-vla.c and
tests/fixtures/nested-function-definition.c, each with #ifdef branches to
exercise conditional-preserving coverage per the bead's acceptance criteria.
Nested functions are kept in their own fixture since clang rejects them
(GCC-only extension) -- SLATE_CLANG_ORACLE mode would fail on that fixture,
so it's isolated from the clang-comparable computed-goto/VLA one.

Also fixed a pre-existing bug blocking compilation on main (introduced by
b3fb255 "allow records on a single line"): an orphaned extra `}` in
parse_tag_definition's same-line-brace fast path, left over from converting
two nested `if let` into a let-chain. Verified via git stash that main did
not compile before this fix.
