# slate-parser-6gk.3: full expression grammar

_2026-09-11 17:44:01_

Implemented full C expression grammar in src/const_expr.rs, replacing
the old opaque-string Expr::Call/Cast (removed from ast.rs): all
compound-assignment ops, ternary ?:, comma operator, real
Vec<ConstExpr> call args, real cast target types (CType/Declarator via
reused pub(crate) DeclaratorParser), arbitrarily-composed postfix
chains (member/arrow/subscript/call/inc-dec), prefix ++/--/&/*, and
_Alignof. Cast/call/grouped-paren disambiguation uses typedef-aware
backtracking (starts_type_name + try_parse_type_name).

Updated lexer.rs (new tokens), sema.rs's
is_integer_constant_expression, and tests/filecheck.rs's match sites
for the removed Expr variants.

Fixed root cause of FORCE_COLOR-induced false FileCheck failures:
update_filecheck.py and filecheck.rs's subprocess calls now strip
FORCE_COLOR/CLICOLOR_FORCE and set NO_COLOR=1, so `env -u FORCE_COLOR`
is no longer needed.

Regenerated stale fixtures for the new Cast/Call shapes. Verified
ported-slate-alias-global.c's ERROR case is unrelated (attribute-alias
parsing) and still correctly errors. Added
tests/fixtures/expression-grammar.c covering every new construct.
Confirmed SLATE_CLANG_ORACLE=1's "clang return was not an integer"
panic pre-exists (reproduces on control-flow-statements.c already),
not introduced here.

Filed slate-parser-6gk.5 (compound literals, deferred) as a follow-up.
Closed slate-parser-6gk.3.
