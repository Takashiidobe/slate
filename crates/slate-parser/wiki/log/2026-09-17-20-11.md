# Fold _Generic selections in integer constant expressions

_2026-09-17 20:11:10_

slate-parser-byw. sema/assertion.rs's ice_shape gate rejected ExprKind::Generic, so every _Generic static assertion was silently skipped. Corpus-wide instrumentation of the gate's fallthrough arm found exactly three skips, all in tests/fixtures/gcc/gcc-dg/stdckdint-1.c: _Generic(ckd_add(&a,1,1), bool: 1, default: 0) and its sub/mul siblings. The other forms named in the issue (calls, string/compound literals, comma) appear only nested inside those controlling expressions.

New TypeResolver::generic_selection resolves the controlling type (type-name operand via resolve, expression operand via assertion_operand_type), compares it structurally against each association type, and returns the selected value expression. constant_value, assertion_operand_type, and ice_shape all route through it, so folding and the syntax gate cannot disagree about which branch is live.

Two deliberate bail-outs, both returning Unsupported so the assertion skips rather than rejecting valid C: an unresolvable association type, and two associations whose resolved Type compares equal. The second matters because ir::Type collapses distinct C types with the same width and signedness (char vs signed char), so equality alone could pick the wrong branch.

_Generic's controlling expression is unevaluated, which is why typing ckd_add required assertion_operand_type to answer for a call. builtin_result_type maps __builtin_{add,sub,mul}_overflow to bool; every other callee stays Unsupported. A real builtin signature table is slate-parser-r3v; diagnosing the genuinely non-ICE forms is slate-parser-ifc.

Sema runs only through the binary, not the in-process filecheck path, so coverage lives in tests/fixtures/sema/static_assert_generic_selection.c.
