# Reject sizeof/alignof on bit-fields; keep _Generic unpromoted

_2026-09-17 20:45:30_

slate-parser-ybq, plus a regression from slate-parser-lh7.2.7.

A bit-field is not an object with its own address or layout. `&f->low` was
already rejected; `sizeof(f->low)` and `_Alignof(f->low)` silently reported the
declared storage type's size, because `unevaluated_type` resolved the place and
returned `place.ty` without looking at the slice. Both now reject.

Added `ResolveError::Invalid(&'static str)` for these. `Unsupported` means
"lowering doesn't handle this yet"; an address-of or sizeof on a bit-field is
invalid C and will never be lowered, so it should not read as a gap. Only the
three bit-field rejections use it; existing messages are untouched.

Regression fix: lh7.2.7 made a bit-field rvalue promote by declared width
inside `read`, which also reached `_Generic`'s controlling operand.
`_Generic(f->low, unsigned: 1, int: 2)` selected `int` where clang selects
`unsigned` — lvalue conversion applies there, integer promotion does not.
`unevaluated` now takes the place type directly when the operand is a
bit-field place, and otherwise falls back to lowering the expression as before,
so nothing else changes. Verified both selections against clang -O1 output
(returns 1 and 10).

`offsetof` on a bit-field was already rejected and matches clang.

Fixtures: tests/fixtures/sema/ir_bitfield_invalid.c (three error cases),
plus a bit_types function in ir_records.c covering _Generic selection on
bit-fields and sizeof/_Alignof on an ordinary member.
