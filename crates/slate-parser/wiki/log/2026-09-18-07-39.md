# Model diagnostic severity for extension and compat warnings

_2026-09-18 07:39:20_

Extension acceptances were silent: SemaError was the only diagnostic type and
compiler_args parsed no -W flags. Added a named-warning layer.

- `src/diagnostics.rs`: `Warning` (long-long, c99-compat,
  implicitly-unsigned-literal) plus `DiagnosticOptions`, the resolved severity
  map. Lives on `CompilerOptions`, so it reaches sema via `unit.options`.
- `compiler_args`: parses -W<name>, -Wno-<name>, -Werror[=<name>],
  -Wno-error=<name>, -Wpedantic/-pedantic, -pedantic-errors. Unknown -W names
  are accepted and ignored, as clang does, so -Wall -Wextra parse.
- `SemaError` carries `severity` and an optional `warning`; miette renders the
  name as the diagnostic code. `analyze` now returns `Result<Vec<SemaError>,
SemaErrors>` — Ok holds the warnings, which main prints to stderr.
- `select_integer_candidate` is now the single selection point, shared by
  validation and IR lowering; the literal warnings are derived from the
  candidate it picked, so they cannot drift from the typing rules.

The bead's original design was wrong and is corrected on the issue and in
wiki/concepts/diagnostic-severity.md: -pedantic-errors does NOT change the
candidate list. clang -m32 -std=c89 -pedantic-errors still types 4294967296 as
long long and errors on the extension's _use_. So severity never feeds type
selection and StandardFeatures does not read DiagnosticOptions.

Also from the clang oracle: c99-compat is not a pedantic diagnostic, so
-pedantic-errors leaves it a warning; long-long is pedantic-only.

Harness: a successful run prints warnings to stderr, which the harness did not
read. Added `// SLATE-FILECHECK-WARNING <prefix>`, which FileChecks stderr for
a config still expected to succeed, in both the test harness and
tools/update_filecheck.py. The generator's line filter now also keeps the
`-W<name>` code line and miette's wrapped continuation lines.

All 22 (literal, standard) warning pairs and 11 flag-severity combinations
verified against clang 22. Grouped from_values' four operation scalars into
OperationValues to stay under clippy's argument limit.
