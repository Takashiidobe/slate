# Reject or warn on conflicting redeclarations by compiler consensus

_2026-09-19 15:09:11_

slate-parser-wxs.3 (partial). Redeclaration conflicts are settled by one rule, checked against clang 22, gcc, and MSVC (cl.exe via Wine): where all three reject, reject; where any only warns, accept with a warning.

Probe results (c17, x86_64 Linux unless noted):
- All reject: return type of another kind or size (int/double, float/double, int/short, int/long long, int/void, int/_Bool), different pointer depth (int vs char *), `int *` vs `double *`, different tags. A struct/union/enum redefined in the same scope, even identically (C17). C23: clang and gcc accept identical redefinitions; MSVC has no C23 mode, so we follow the standard.
- MSVC only warns: same-size integers (C4142 "benign redefinition": int/unsigned, int/long on Windows, int* vs long*), and any prototyped parameter list difference (C4028 types, C4030/C4031 counts and `...`), even int vs double.

Implementation:
- `TypeResolver::define_tag` errors when a tag already complete in the same scope is defined again. In C23 (`StandardFeatures::compatible_tag_redefinitions`) it reuses the first definition when fields (name, type, access, bit width) or enumerators (name, value) match. Compared on IR definitions because AST `Span` equality includes ids and locations.
- `Lowerer::declare_function` now returns Result. `function_redeclaration_conflict` errors on incompatible return types and warns (new `Warning::ConflictingTypes`, `-Wconflicting-types`, default on, not pedantic) on same-layout sign-only return differences or differing prototyped parameter lists.
- `declare_global` warns instead of erroring on a sign-only difference, keeping the first type.

Gaps: int/long on Windows lower to the same IR type, so no warning (slate-parser-y47). `struct S; struct S *p;` fails with unresolved tag name on main (slate-parser-9wx). Block-scope tag definitions are still unsupported (slate-parser-rsm).

Fixtures sema/ir_redeclaration_conflicts.c (errors and warnings) and sema/ir_redeclaration_compatible.c (IR checked). In a mixed error/warning fixture, configurations with neither directive are never run, which is why the passing cases have their own fixture.
