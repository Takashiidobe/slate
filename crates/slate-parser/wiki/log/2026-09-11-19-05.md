# anonymous struct/union bodies, conditional fields, and string literals in const_expr

_2026-09-11 19:05:25_

Fixed slate-parser-wf8.1.12 and closed out wf8.1 (add.c now ports cleanly).

Root cause chain, found by repeatedly running add.c through the parser with -isystem pointed at libc-shim + clang builtins:

1. DeclaratorParser::parse_base_type's struct/union/enum arms only accepted a bare tag name (struct Foo) and hard-panicked ('expected union tag name') on any inline body -- so a nested/anonymous struct or union used as a member's type (e.g. signal.h's struct sigevent with an anonymous union field) couldn't parse at all. Added CType::Tagged.body: Option<TagBody> (TagBody::Fields/Enumerators) and parse_record_type/parse_enum_type/parse_field_list/parse_enumerator_list to parse inline bodies directly from the token stream.

2. Once that worked, a second bug surfaced: parse_tag_definition's field-splitting assumed one field per physical-line PPNode, so a nested body spanning multiple lines (e.g. bits/types.h's union { int **wch; char **wchb[4]; } \_\_value;) got truncated mid-body. Rewrote it (now parse_field_items) to join PPNodes by brace depth until a top-level ';'. Its own outer close-brace search had the same bug one level up -- it picked the FIRST node whose text started with '}', which could be a nested body's closing line, ending the outer struct too early. Fixed by tracking brace depth from the outer '{' instead.

3. Third: some struct fields are themselves guarded by #ifdef/#else inside the struct body (a Conditional PPNode among the field nodes), which FieldDecl had no way to represent. Added FieldItem::Conditional(Conditional<Vec<FieldItem>>) alongside FieldItem::Field, changed RecordDecl.fields to Vec<FieldItem>, and added RecordDecl::eval in eval.rs to flatten conditional fields against the active Env during the polyvariant-to-concrete pass -- mirroring the existing Initializer::Conditional/eval pattern exactly.

4. Fourth, unrelated: ConstExpr (the general expression backend per the const-expr-is-general-expr-backend memory) had no StringLit variant, so printf("%d\n", ...) in add.c's own main() failed with UnexpectedToken. Added ConstExpr::StringLit.

Regenerated FileCheck output for every fixture touched by the FieldItem::Field wrapping (compound-literals, expression-grammar, initializers, layout-attributes, packed, ported-gcc-torture-packed-2, records, target-type-attributes) via tools/update_filecheck.py -- never by hand.

Added tests/fixtures/nested-record-members.c (sizeof-in-array-bound + anonymous nested union + #ifdef field, in one struct) and tests/fixtures/add.c (the actual ported fixture; printf declared inline instead of #include <stdio.h> since the FileCheck harness has no -isystem wiring).

bd: closed wf8.1.12 and wf8.1 itself (all of wf8.1.1-.12 now closed).
