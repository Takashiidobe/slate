# wf8.2.5: C23 dialect gaps fixed

_2026-09-12 20:22:54_

Fixed all three parts of slate-parser-wf8.2.5:

(b) digit separators: lexer's numeric_end() consumed any apostrophe
unconditionally (assuming it was always a digit separator), so
`0'À'` (number immediately followed by a char literal starting
with `'`) got mis-lexed as one malformed number token plus a
truncated remainder. Fixed by requiring the char after `'` to be
alphanumeric before treating it as a separator.

(c) parse*top_level_item misclassification: signature_node_span
bailed out early (`return index.max(1)`) the moment it saw a Comment
PPNode, instead of skipping over it like declaration_node_span
already did. A declaration like `\_Complex float a =\n 1.if; /*c*/`has its comment attached to the SAME line as the terminating`;`,
but GroupParser::group always emits a line's comments before its
Item::Text, so the Comment PPNode lands \_between* the two Code
nodes. That made the span computation stop at 1 node, missing the
`;`, and the item fell through to parse*function instead of being
treated as a declaration. Fixed by having signature_node_span skip
non-Code nodes. Also fixed nodes_tokens(), which re-lexed a Comment
node's raw text (e.g. "/* ... \_/") as if it were code whenever a
multi-node span included one -- filtered to Code nodes only.

(a) **STDC_VERSION**: previously unset entirely, so C23-gated shim
header branches (stdbool.h's true/false, stddef.h's unreachable())
never activated. Per user decision (project has no per-file -std
dialect modeling and targets a single default configuration),
defined **STDC_VERSION** as 202311L in slate_target_defaults.h.
This has a large blast radius (~53 fixtures render differently now
that headers take the C23 branch instead of C17), all regenerated
via update_filecheck.py; verified via a temporary catch-unwind
instrumentation of the filecheck test harness that no new failures
(vs. the pre-existing 8 tracked in slate-parser-wf8.2.6) were
introduced.

Also fixed two bugs blocking that STDC_VERSION change:

- src/const_expr.rs: #if evaluated every bare identifier (including
  `true`) to 0; C23 requires `true`/`false` to evaluate specially in
  #if regardless of macro-definedness. Added a `true` -> 1 special
  case (matches C23 6.10.1p1).
- src/sema.rs: the "object cannot have type void" check fired for
  ANY declarator whose base type was void and which had a name,
  including `void *p` -- not checking whether the declarator
  indirects through a Pointer/Function first. Added
  declarator_indirects_void() and used it to gate the check.

Verified via full fixture regression scan (binary run over all 702
.c fixtures comparing error output before/after) and cargo nextest.
