# x86_win32 empty record results are void under clang

_2026-09-28 12:09:27_

slate-parser-ohze. clang's X86_32ABIInfo ignores an empty record result (isEmptyRecord with AllowArrays) before its small-struct-in-register rule, so on i686-pc-windows-msvc a struct with no fields, only zero-length arrays, unnamed bit-fields or empty-record members returns void even though MS layout makes it 4+ bytes. rustc returns the same-sized stand-in in EAX (or sret), and real cl.exe returns struct { int z[0]; } in EAX, so the explicit void is clang-flavor only; the argument stays byval and native_c on both.

- src/sema/abi.rs: record_abi gains an X86Win32 clang-flavor empty-result arm -> AbiPass::Void; is_empty_record treats zero-length arrays as empty (clang's isEmptyField); new is_empty_field shared with win32_returns_in_register.
- Linux i386 cdecl already gives sret for size-0 records (clang and gcc agree), no gap there.
- Fixtures: clang/windows/i686/abi_rust_divergence.c gains empty, zero_only, empty_members; new msvc/windows/i686/abi_zero_length_result.c pins native_c under cl; suites x86_32-fpcc-struct-return.c returnZero now void.
- ir-spec.md divergence table and x86_win32 paragraph updated.
