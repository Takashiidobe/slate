# Identifier expressions resolve by BindingId in assertion checking and lowering

_2026-09-28 17:25:13_

slate-parser-cc94.2; fixes slate-parser-evdx.

- TypeResolver::with_names(unit, names) replaces with_tags and is used by all
  four resolvers (lowering, assertion checker, --dump-ir-types via
  Sema::type_module, --dump-ir-expressions via Sema::expression_roots). It
  carries references (expr id -> BindingId) and declarations (declaring node
  id -> BindingId) from the Sema's one NameResolution.
- One constants: HashMap<BindingId, Operand> replaces Ordinary::Constant and
  the NodeId-keyed enumerators map. Enum resolution, the checker's own
  enumerator evaluation, and constexpr objects (checker and lowering) record
  into it; constant_value, assertion_operand_type and lowering's enumerator
  arm read it. Lowering's enumerator test is an O(1) binding-kind lookup
  instead of two linear scans over references and bindings.
- Ordinary::Object is gone: the checker declares objects, parameters and
  function definitions (previously never declared -> evdx) into entities by
  BindingId, composing with an earlier declaration's type like
  merge_redeclaration, so a stdcall prototype's convention survives a plain
  definition. Alignment requests go through ObjectRequest merging.
- Ordinary keeps Declared/Alias only; typedefs and tags stay in string scopes
  until cc94.3.
- Prerequisite commit d4cd6370 binds prototype parameters in names.
