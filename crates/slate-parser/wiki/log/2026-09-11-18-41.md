# add.c porting: -isystem, preprocessor and parser fixes

_2026-09-11 18:41:23_

Working slate-parser-wf8.1 (port tests/upstream/fixtures/add.c). Added -isystem
CLI flag (compiler_args.rs, main.rs) wired to the existing but previously-dead
SearchPaths.system field, pointed at ~/Projects/slate/libc-shim/include (glibc
headers) plus /usr/lib/clang/22/include (freestanding C11 headers like
stdnoreturn.h a real compiler ships alongside libc headers).

Fixed a chain of real preprocessor/parser gaps surfaced while getting stdio.h
to preprocess and parse cleanly (each filed+closed as its own bd issue under
slate-parser-wf8.1.1-.10):
- defined()/defined(X) in #if/#elif (const_expr.rs)
- backslash-newline line continuation splicing (pp.rs, had a bug: only merged
  the first continuation line of a 3+-line chain, fixed with an advancing index)
- #error treated as a no-op directive instead of a hard panic
- unresolved identifiers in #if/#elif evaluate to 0 per C 6.10.1p4
- __has_include/__has_include_next parsing (evaluates to a conservative false)
- statically-false #if/#elif/#else branches are now skipped (skip_block) rather
  than fully parsed -- this is what let __include_next and friends in dead
  vendor-guarded branches stop tripping the parser, and is a real behavior
  change: dead branches no longer appear in the polyvariant Conditional<T> node
- comment stripping (// and /* */) added to the pipeline for the first time
- const/volatile/restrict/_Atomic qualifiers on function parameters
- Parser::error_at was silently mis-rendering errors at offset 0 of the
  top-level file whenever the failing token came from an #include'd header
  (self.source.find(code) failed silently); now falls back to searching each
  included file's own content
- typedef/variable declarations combining an inline struct/union/enum body
  with a trailing declarator (`typedef struct TAG { ... } TAG;`) -- extended
  parse_tag_definition to detect the trailing name and emit an extra Typedef
  or Declaration decl referencing the tag

Regenerated FileCheck expectations for constant-expressions.c and
nested-conditionals.c (dead conditional branches now render as `[]` instead of
their old fully-parsed bodies) and flipped
tests/fixtures/ported-gcc-torture-packed-2.c from a SLATE-FILECHECK-ERROR
fixture to a normal passing one, since it was specifically pinning the
typedef+struct-body bug that's now fixed.

Stopped mid-way through add.c: next blocker is sizeof(<type-name>) (e.g.
sizeof(unsigned long)) not being supported in const_expr's sizeof parsing --
filed as slate-parser-wf8.1.11, left open/unclaimed for next session.
