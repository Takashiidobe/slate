# IR nodes own their ids; metadata keyed by IR node

_2026-09-19 15:38:32_

Epic slate-parser-xf9; closes lh7.2.34 and lh7.2.36.
Cause: IR spans reused AST NodeIds and Module.metadata was keyed by them, so every IR node built from one AST node (conversion wrappers, hoisted temporaries and their reads, atomic inner old/arith nodes, initializers anchored at a declarator, VLA extent temporaries, type definitions created by a declarator) printed that node's metadata.
Fix:
- Span::derive (src/ast.rs) copies the location with a fresh NodeId; IR construction in src/sema uses it for new nodes.
- Rewrites of the same node keep the id with with_value: the effects pass (Hoister::value/statements) must, or it drops metadata.
- IR enumerators keep their AST id: expression.rs finds an enumerator's value by the binding's AST node id.
- Module::annotate attaches metadata to the owning IR node after creation. Declarator C types go on the declared entity (let/global/function/parameter/typedef alias), not on type definitions it creates. Atomic builtin metadata goes on the operation, skipping the void Sequence wrapper from discarded().
Fixtures: ir_atomic_stdatomic.c and ir_typeof.c regenerated (duplicates removed); new sema/ir_metadata_single_owner.c.
Wiki: ir-spec, ast-spec, ir-shape updated.
