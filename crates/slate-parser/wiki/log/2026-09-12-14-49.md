# Split lines on conditionally defined macros used inside macro bodies

_2026-09-12 14:49:56_

Follow-up to the reachability change: requiring every case of a macro to
agree before expanding it regressed nested use. With INNER redefined under
'#ifdef A' and '#define OUTER INNER', 'int nested[OUTER];' left INNER
unexpanded in every configuration (it previously expanded to the always-true
definition, which was right only by default).

divergent_macro_conditions now goes through refine_cases, which refines the
cases for each macro on the line and then recurses into the replacement list of
each case's definition (skipping its parameter names, with an expanding set to
stop recursive macros). A line therefore splits when a macro it uses
transitively has configuration-dependent definitions. definition_cases returns
(condition, definition) pairs for this.

Test suite runtime is unchanged (~1.1s); no existing fixture output changed.

Fixture: pp-nested-conditional-macro.c (object-like OUTER -> INNER and
function-like WRAP(value) using INNER; DEFAULT and A), matches clang -E.

Filed slate-parser-2u9: #ifdef/defined() still evaluate a macro defined
conditionally inside the file against the -D/predefined names only.
