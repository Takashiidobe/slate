# Directive warnings were never fatal; the sweep mislabelled them

_2026-09-21 07:56:52_

slate-parser-dyd.13 reported that a Clang-accepted corpus configuration containing #warning reached the IR sweep as a failure. The parser was already correct: main.rs::report_directives prints every Severity::Warning to stderr and collects only errors into the command failure, and it runs before the parse result is unwrapped, so a #warning followed by an unrelated error reports both.

The defect was in tools/corpus_sweep.py. root_diagnostic matched a single regex over both the error marker and the warning marker and took the first hit, so tests/fixtures/c23_language.c was grouped under its leading '#warning C23 warning directive probe' instead of the real failure under it. DIAGNOSTIC_TIERS now ranks candidates: an indented detailed diagnostic, then miette's 'Error:   x' wrapper, then a warning marker only when the run produced no error marker at all. The middle tier also normalises every existing group label, which used to keep a stray leading marker.

Unmasked slate-parser-dyd.41: alignof is a C23 keyword spelling of _Alignof and src/lexer.rs lexes only _Alignof/__alignof/__alignof__, so it reached name resolution unbound.

Two fixtures pin the acceptance criterion, one per stream, because a fixture carrying a WARNING or ERROR prefix generates only those blocks: sema/warning_directive_nonfatal.c for the stderr warning and sema/ir_warning_directive.c for the IR that still comes out. wiki/concepts/diagnostic-severity.md gained a section on directive severity and the tiering.

No Rust changed. Gate passes; sweep 2622/2696 -> 2624/2698 with the two new fixtures accepted and no regressions.
