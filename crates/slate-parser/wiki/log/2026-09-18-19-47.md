# Lower imaginary types into IR

_2026-09-18 19:47:32_

Implemented slate-parser-lh7.2.17.2 following C23 Annex G rather than clang: clang rejects _Imaginary ('imaginary types are not supported') and gcc does not parse it, so there is no oracle; the user chose standard semantics over clang convergence.

- Type::Imaginary(FloatType) prints imaginary<fN>; storage, alignment and ABI pass (scalar) are the component's (G.2). Decimal and integer components are rejected (the parser already refuses int _Imaginary).
- New conversion kinds (G.4): real_to_imaginary / imaginary_to_real (positive zero, operand discarded, not pre-converted so no spurious exceptions), imaginary_to_complex, complex_to_imaginary, imaginary_convert. Integer-complex to imaginary goes through complex_convert to the float component first.
- Binary operators (G.5) apply only the common real type; each operand keeps its domain so operand types plus result type select the Annex G formula. R*I->I, I*I->R, I+I->I, R+I->C, any complex->C; == and != allowed; relational, %, bitwise, ~ are Invalid.
- usual_arithmetic (used by ?:) yields imaginary for I/I and complex for mixed domains.
- Imaginary literals (2.0i) are GNU-only and GNU types them complex, so they lower to aggregate<complex<fN>>(+0, v), same shape as braced complex initializers. 3i lexes as FloatLit today; rejected as 'integer imaginary literals', follow-up slate-parser-lh7.2.17.5.
- Imaginary float constants now print their value, not bits.

Fixtures: tests/fixtures/sema/ir_imaginary.c, ir_imaginary_invalid.c. Updated ir-spec.md, ir-grammar.md, ir-shape.md. clippy, fmt, cargo nextest run --release pass.
