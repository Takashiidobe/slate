# Function-name builtins already bound; add IR coverage

_2026-09-21 07:37:41_

slate-parser-dyd.11 asked for __func__, __FUNCTION__, __PRETTY_FUNCTION__ and
__builtin_FUNCTION to resolve in function scope. Investigating first: all four
already lower, implemented under dyd.21/dyd.22 (see 2026-09-20-09-28). The
bead was filed from a sweep run that predates those commits.

Verified rather than assumed. A full IR sweep at 11ac4b44 has no failure group
mentioning any of the four spellings, and all 8 corpus configurations whose
fixtures use them are accepted except gnu_misc_extension_survey.c, which fails
on `__attribute__((unused));` as an attributed null statement -- dyd.26, not
this bead.

The real gap was coverage: every fixture touching these names only checked the
AST, so nothing pinned the lowering. Added two generated IR fixtures.
ir_function_name_builtins.c covers all four spellings plus sizeof, indexing
and a static initializer under the Clang personality;
ir_function_name_builtins_gcc.c pins the GCC one, where __PRETTY_FUNCTION__ is
the bare name rather than the whole declaration. Both are clang -fsyntax-only
clean, so the sweep counts them on both sides.

Two divergences left deliberately, both outside the bead. Each occurrence
emits its own .strN where Clang reuses one global per function -- harmless for
the Rust backend, which consumes the global either way. And a use outside a
function is rejected, where Clang warns and recovers; no corpus case hits it.

No source changes, so the gate is fixtures only: 1 test run, 1 passed.
