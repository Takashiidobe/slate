# Lower vector lane subscripts

_2026-09-20 09:53:07_

dyd.24 (and the subscript half of lh7.2.17.7). `v[i]` on a vector did not
lower: subscripting only knew pointer arithmetic, so it failed with
"expected pointer" on 16 corpus configurations.

A vector lane is neither a pointer offset nor a record field, so it needs
its own projection. Two forms, because C allows both:

- `PlaceKind::Lane { base: Place, index: Value }`, printed
  `lane(place, value)`, for a vector *lvalue*. Keeping it a place is what
  makes `v[i] = x` a write and `v[i] += x` an update; `stable_place`
  hoists both the base and the index so the compound form evaluates each
  once. Like a bit-field, a lane is readable and writable but not
  addressable, so `&v[i]` is rejected.
- `ValueKind::Lane { vector, index }`, printed `lane<T>(value, value)`,
  for a base with no storage: `f()[0]`, `(a + b)[i]`,
  `((V8)(V64){..})[1]`. Three gcc-torture fixtures need it. This is
  deliberately *not* the general "project out of an rvalue aggregate"
  problem (`f().a` is still unsupported): a lane comes out of a register,
  a struct member does not.

`Lowerer::subscript` now lowers the base once and returns either a place
or a value; `place()` rejects the value form and `expr()` passes it
through. That also removed the old path where an array base was lowered
by `expr()` after `place()` had already built it.

`PlaceKind::Index { base: Value, .. }` was left alone: it takes a value
base, is still unconstructed, and the grammar keeps its note saying so.

Corpus sweep: slate-ir 2363/2674 -> 2378/2674, no regressions. The one
vector fixture still failing is `vector_extension_ops.c`, on
`__builtin_shufflevector` (dyd.25). ext_vector swizzles (`v.xy`, `.lo`)
remain unlowered under lh7.2.17.7; nothing in the corpus uses them.
