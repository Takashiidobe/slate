# Add AlignOfExpr and fix out-of-bounds parse-error spans

_2026-09-14 12:19:27_

const_expr.rs's _Alignof handling always required a parenthesized type name (self.expect(Token::LParen) then try_parse_type_name unconditionally), so '_Alignof x' failed with 'expected (, found x', and __alignof__(expr) on a non-typedef identifier silently misparsed the identifier as a bogus type name (same bug class as the earlier __real__/__imag__ Call-vs-Unary issue). Added ExprKind::AlignOfExpr(Expr) and rewrote parse_unary's Alignof handling to mirror sizeof's two-path structure: try the (type-name) form only when the next token starts_type_name, else parse an expression operand. Touched every exhaustive ExprKind match site per wiki/concepts/ast-enum-touchpoints.md (ast.rs Display, const_expr.rs evaluate_expr, sema.rs is_integer_constant_expression + walk_expr, reachability.rs mark_expr).

Regenerated 3 pre-existing gcc-torture/c-torture fixtures that had the old bogus AlignOf{ty: Named("func")} shape baked in from misparsing __alignof__(func) on a plain identifier.

Root-caused the reported OutOfBounds diagnostic: ParseError spans built by parser::Parser::error_at's final fallback (when the reconstructed, space-joined 'code' string used for Loc::whole() can't be found verbatim in any known source file — which happens whenever token-joined reconstruction doesn't match the original file's whitespace, e.g. unbalanced parens preventing top_level_semi from finding a statement's ';') used the caller-supplied offset/length as-is against self.source, with no relation between the two once the text search failed. Fixed centrally in ParseError::new (src/error.rs) by clamping offset/length to source.len() there, so every caller (present and future) gets an in-bounds span for free instead of each call site having to reason about it — per user request, favored this over a caller-local fix in error_at.

Created tests/fixtures/error/ and moved all 33 existing SLATE-FILECHECK-ERROR fixtures into it (git mv, then regenerated each with update_filecheck.py so the embedded diagnostic paths follow) per user request, to collect semantic/parse-error fixtures in one place instead of flat in tests/fixtures/. Added tests/fixtures/alignof_expr.c (all four _Alignof/__alignof__ forms) and tests/fixtures/error/alignof-malformed.c (malformed _Alignof( now produces an in-bounds, if imprecise, whole-file span instead of panicking).
