# Explicit atomic memory orderings in the IR (lh7.2.21)

_2026-09-18 19:36:30_

Resolved __c11_atomic_* and GCC __atomic_* builtins in sema (src/sema/atomic.rs, dispatched like the va_* builtins and skipped by name resolution). Clang's <stdatomic.h> now lowers.

IR: new MemoryOrder {Relaxed, Consume, Acquire, Release, AcqRel, SeqCst, Dynamic(value)}. Read, Store, Update and Statement::Write carry ordering: Option<MemoryOrder>, printed as atomic=<order>. New nodes: CompareExchange (bool result, success/failure orderings, weak) and Fence {ordering, scope: thread|signal}. Fence is a value that the hoister turns into a Statement::Fence, the same way Store becomes Write.

Decisions:
- Differs from the bead's design: Place.access keeps its atomic bit. It records that the object is _Atomic (type information, like the ptr pointee), and it is how a plain access gets its implicit seq_cst ordering (Place::implicit_ordering). Only printing moved from the place to the operation. Removing the bit would have meant threading atomicity alongside every place() call.
- Fetch arithmetic is in T with overflow=wrap (C11 7.17.7.5), not promoted. Pointer fetch_add uses ptr_offset with element=T (C11) or element=u8 (GCC bytes).
- nand = not(and), min/max = conditional(lt/gt(old, v), old, v): no new arith ops.
- Void-returning builtins lower to sequence(store, void) so the value's C type stays void.
- Constant orderings fold to the enum; anything else, including an out-of-range constant, becomes Dynamic.
- c_builtin metadata holds the builtin name; macro-provenance names are a follow-up bead.

Plain _Atomic output (ir_qualified_access.c) is byte-identical. New fixtures: sema/ir_atomic_builtins.c, sema/ir_atomic_stdatomic.c. Regenerated gnu_libc_stdio.c, whose output changed because the system headers changed.
