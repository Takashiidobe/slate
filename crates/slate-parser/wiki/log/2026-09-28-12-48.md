# Lex digit separators only from C23 on

_2026-09-28 12:48:31_

slate-parser-cxg.6 cluster F (c11-digit-separators-1.c, c23-digit-separators-1.c).

Two lexer bugs in Lexer::numeric_end. (1) Separators were accepted in every mode, on the premise (ast-spec) that input already compiled so accepting is free. gcc.dg shows it is not: with #define m(x) 0, m(1'2)+(3'4) is valid C11 where '2)+(3' is a character constant (value 0), and C23 where it is two numbers (value 34). gcc and clang both lex it as a char constant through gnu17. New StandardFeatures::digit_separators (C23) gates it. (2) The e/p sign rule looked at the previous char, so in 0x0'e-0xe the '-' joined the pp-number; per C23 6.4.8 the separator consumes its following char, so the sign rule only applies to an e/p the scan reaches directly. numeric_end now consumes e+/e- and 'x as pairs.

ast-spec.md feature table and paragraph updated.
