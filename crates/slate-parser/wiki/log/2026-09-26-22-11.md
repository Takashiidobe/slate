# MSVC flavor drops registry semantics for library builtins

_2026-09-26 22:11:32_

slate-parser-acp: under --flavor=msvc a bare `void exit(int);` lowered as [noreturn] and `toupper` as [memory=read], because clang_builtin treats Msvc like Clang and finish_functions / builtin_declaration copied the registry's NoReturn and Const/Pure.

Checked with tools/cl.exe /O2: code after `call exit` is kept (compatible and incompatible declarations); isdigit/toupper (Pure) and cbrt (Const) are called twice in f(x)+f(x); labs is inlined only as an /Oi intrinsic, which is not a declaration property. MSVC learns noreturn only from __declspec(noreturn); that already lowers to Attribute::NoReturn tracked per function, and cl agrees it reaches calls lowered before the declspec redeclaration (`call quit; int 3`).

ClangBuiltin::noreturn(flavor) and memory_effects(flavor) now return nothing for ClangBuiltinKind::Library under Msvc; both call sites (function.rs finish_functions, expression.rs builtin_declaration) use them. Dropping these is always the safe direction. c_builtin is kept as libc identity.

Not changed: the MSVC flavor still accepts clang compiler builtins (__builtin_trap keeps [noreturn]); cl.exe treats __builtin_trap as an unknown external function. Left out of the fixture so it doesn't claim cl behavior.
