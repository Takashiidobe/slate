# msvc flavor: implicit function declarations

_2026-09-28 12:16:41_

slate-parser-v74.2.2 (closes epic v74.2). cl.exe accepts a call to an undeclared identifier as an implicit extern int name() (C4013, level 3, silent at cl's default /W1, so even /WX accepts).

- names.rs: in a Call whose callee is an unresolved identifier that is not a builtin or predefined name, the msvc flavor creates a linked Function binding at file scope (reusing a linked block-scope extern if one exists) and records it in NameResolution::implicit_functions.
- module.rs: before lowering an item, each implicit binding it introduced becomes an unprototyped int() Function (external linkage, c_implicit metadata) via declare_function, so later declarations merge or report conflicting types like cl's C2371.
- diagnostics.rs: new Warning::ImplicitFunctionDeclaration (implicit-function-declaration), Ignored by default under msvc.
- Verified against cl.exe: reuse across functions, later compatible definition, later void/double redeclaration errors, pointer use after implicit declaration.
- Fixtures: msvc/windows/i686/implicit_function_declaration.c, two error fixtures (conflict, -Werror=), and suites clang-test/msvc/windows/{i686,x86_64}/CodeGen__inline-asm-intel.c written by hand from the sweep's helpers because --migrate needs clang-cl acceptance.
- ir-spec.md documents it. gcc C89 (cxg.14) can reuse by widening the flavor gate.
