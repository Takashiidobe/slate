# Incompatible external redeclarations of noreturn builtins keep noreturn under clang

_2026-09-26 22:03:17_

slate-parser-3vz: `int exit(long);` lowered without [noreturn]. clang merges every external declaration of a library builtin's name with its implicit builtin FunctionDecl. An incompatible type drops builtin status (no BuiltinAttr, no const/pure/nothrow: `long abs(long)` gets no memory(none)), but noreturn lives in the function type's ExtInfo and is inherited, so clang emits the declaration and its calls as noreturn. A static definition is not linked and stays plain.

finish_functions (src/sema/function.rs) now sets noreturn on an external-linkage function whose name is a NoReturn builtin even when declares_builtin fails; c_builtin and memory effects stay gated on compatibility.

Clang flavor only. Checked GCC -O2 on `void _Exit(long);`: code after the call is kept (builtin_prefixed_library_gcc.c expects no noreturn). cl.exe /O2 keeps code after exit even for a compatible `void exit(int)`, which means our MSVC flavor over-applies builtin noreturn in general; filed separately.

Fixture: tests/fixtures/sema/ir_redeclared_builtins.c gains int exit(long) (noreturn) and static _Exit (not). ir-spec.md updated.
