# Lower remaining object attributes

_2026-09-19 14:07:16_

slate-parser-lh7.2.22. Object declarations no longer fail on aligned, _Alignas, common, nocommon, weakref, or selectany.

- Global gains alignment: Option<u64> and common: bool, printed [align=N] and [common] after the symbol attributes. Both are resolved in Lowerer::resolve_object_requests after redeclarations merge, from per-binding ObjectRequest entries.
- Alignment: largest request across declarations. Verified against clang 22: clang honors the attribute as written even below natural (aligned(1) int -> align 1); gcc/MSVC flavors take max with natural. Printed only when it differs from natural.
- Common: verified clang rules. common on any declaration beats nocommon; otherwise nocommon opts out; otherwise the new -fcommon/-fno-common flag (default off, rejected by MSVC). Only external tentative definitions qualify: no initializer, not TLS, not alias/section/weak/selectany, and on MSVC targets not alignment-requested.
- weakref("t") is deliberately NOT weak+alias as the issue suggested: alias defines a symbol, weakref emits none and uses become extern_weak @t. Printed as extern with [weakref="t"]; internal linkage required. Also accepted on functions.
- selectany: [selectany]; external linkage required.

Follow-ups filed: alignof of an attributed object still folds natural alignment; aligned locals unsupported. Wiki: ir-spec.md, ir-grammar.md.
