# Attribute string arguments accept adjacent literals

_2026-09-28 09:03:56_

slate-parser-ex8x: parse_attribute_value's string_argument (was single_string, src/parser/attributes.rs) now takes a run of adjacent string literals and concatenates them via string_literal_content, like _Static_assert messages (slate-parser-v0ns).

- Affects every string-taking attribute: deprecated, nodiscard, section, visibility, alias, weakref, target, annotate, ifunc, tls_model, code_seg, pcs, scalar_storage_order.
- Encoding prefixes (u8"x", L"x", mixed "a" u8"b") are accepted too: clang and gcc both accept them in attribute arguments in C, while slate previously rejected even a single prefixed literal.
- Real-world trigger: UCRT's _CRT_INSECURE_DEPRECATE expands to __declspec(deprecated("..." #_Replacement "...")). sysroot_crt_headers.c never tripped it because it never uses a deprecated function; unused declarations are never validated because reachability filters them out. Calling strcpy failed with 'invalid arguments for attribute deprecated'.
- Fixtures: clang/linux/x86_64/attribute_string_concat.c (section/visibility values in IR), msvc/windows/x86_64/crt_insecure_deprecate.c (strcpy through UCRT string.h).
