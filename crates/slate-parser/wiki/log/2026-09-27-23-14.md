# Locate IR lowering errors at the failing expression

_2026-09-27 23:14:23_

slate-parser-vhnl. Lowering errors (numeric::ResolveError other than Names) had no location, so item_error fell back to the enclosing top-level declaration and an error in a long function underlined the whole function.

- New ResolveError::Located { loc, error } variant and ResolveError::at(loc), which wraps only when loc() is None, so the innermost location wins.
- Lowerer::expr and Lowerer::place are now thin wrappers around lower_expr/lower_place that call .at(e.expansion).
- Lowerer::statements' loop body moved verbatim into Lowerer::statement (continue -> return Ok(())); statements wraps each call with .at(statement.expansion).
- Nothing matching on specific variants goes through these boundaries (sizeof_error and the static-assert path call types methods directly); Err(_) fallbacks discard the error, so wrapping is safe.

Validation: sema_poisoned_declaration.c now points at 2:24 (s + 1), as the bead asked. 56 fixtures regenerated; zero error-message lines changed, only positions. Lines now match clang's on the checked fixtures (fp pragmas, nested/declarator function definitions, c23 auto). The column is the start of the statement/expression where clang points at an inner token (operator, pragma name); that would need per-raise-site locations and is not attempted. File-scope declarator errors (e.g. target builtin types) still use the declaration span. 4369 tests pass.
