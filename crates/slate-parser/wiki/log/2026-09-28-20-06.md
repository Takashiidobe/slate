# Checker owns declaration checks

_2026-09-28 20:06:24_

slate-parser-cc94.5.3. The checker (assertion.rs) now reports declaration rules in plain parse; lowering's copies are Internal.

- Shared rules called from both walks, lowering mapping through the new ResolveError::checked (Rejected -> Internal): module::linkage, symbol_attributes, function_symbol, attribute placement (new TypeResolver::attribute_error, the warning-free half of check_attributes, per Typedef/Function/Object/Parameter subject), and the auto/__auto_type rules, moved from Lowerer onto TypeResolver (deduced_initializer, check_inferred).
- Restated in Checker::object_rules/function_rules: void object, function initializer, thread-local function, block scope static function, thread-local automatic, block scope extern initializer, constexpr without initializer, VLA initializer, static VLA, weakref/selectany linkage, multiple global initializers, always_inline/noinline conflict, gcc single-declarator auto, auto deduced as different types.
- classify_conversion rejects conversions involving an incomplete enum (clang and gcc do; slate accepted in parse); expression.rs's enum-without-underlying is Internal.
- validate.rs's syntactic void-object check is narrowed to arrays of void (they never resolve); the checker covers the rest, including typedef'd void.

Errors now point at the declarator instead of the whole declaration. New fixture error/clang/declaration_rules.c (9 configs, each matching a clang error); constant_arithmetic_rejected ARRAY now says 'variable length array with static storage duration' (clang/gcc: VLA at file scope).

Filed: slate-parser-dvlq (function declarations with incomplete param/return types fail 'incomplete ABI type' — valid C), slate-parser-wtss (bogus visibility and inline conflicts are too strict).
