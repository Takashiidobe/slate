# Outermost header provenance

_2026-09-12 15:44:29_

Step 2 of epic slate-parser-crw (slate-parser-crw.2). Provenance gained header: Option<FileId>, the header the main file #included directly (None for main-file, command-line and predefine tokens). Preprocessor keeps outermost_header; resolve_and_parse_include sets it with get_or_insert when entering an include and restores the enclosing value afterwards, so bits/nested.h included from outer.h records outer.h. It is recorded per PPNode/decl, not per lexer token: every token on a logical line shares the line's provenance, and macro-expanded tokens take the provenance of the line they are expanded into, not of the macro definition. That is the right answer for deciding whether a declaration comes from libc. A file included under two different top-level headers gets a separate header on each inclusion, which is why this isn't stored per FileId in Files. All fixtures regenerated for the new field; new fixture header-provenance.c covers system nested, system outer and quoted local headers.
