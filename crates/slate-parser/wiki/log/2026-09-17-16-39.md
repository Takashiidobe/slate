# Mark bit-precise integers at the IR type level

_2026-09-17 16:39:25_

`NumericType::Integer` gained a `bit_precise` flag, so `_BitInt(N)` is a
distinct type from the standard integer of the same width. Constructors
`Type::integer`/`Type::bit_precise` (and the `NumericType` equivalents)
replace the struct literals at every construction site.

`TargetInfo::storage_of` now routes bit-precise integers straight to
`ScalarLayouts::bit_precise`, which no longer declines the tabulated
widths 8/16/32/64/128. On x86-64 `__int128` keeps size 16 align 16 while
`_BitInt(128)` gets size 16 align 8, matching clang; arm32 still rejects
`__int128` (its 128-bit entries are removed) but now accepts
`_BitInt(128)`.

The IR printer spells bit-precise types with a `b` suffix (`i128b`,
`u32b`) so the two no longer render identically.

Usual arithmetic conversions keep the wider operand's flag, and ties
prefer the standard type; C23's rule that bit-precise integers do not
promote is still unimplemented (slate-parser-3pt).

Fixture `tests/fixtures/sema/bitint_int128_layout.c` covers the layouts;
`ir_constant_folding.c` regenerated for the new spelling. Closes
slate-parser-8cs.
