# Generalize header-guard macro-visibility fix to arbitrary nesting (wf8.1.19)

_2026-09-11 19:56:29_

Follow-up to wf8.1.16's concretize_guard(), which only matched when a
macro's stored condition was structurally IDENTICAL to the guarding
branch's whole active condition -- so it stopped working the moment a
macro sat under any additional nesting inside the guard (e.g. a second,
independent #ifndef/#ifdef layer, or a divergent -D-driven macro nested
inside the guard).

Root fix in src/pp.rs: replaced the old whole-tree-equality rewrite with
a general subtree substitution. Added replace_subterm(condition, target,
replacement), which walks a Condition tree and replaces every exact
occurrence of `target` (e.g. `Not(Defined(GUARD))`) with `replacement`
(`Constant(1)`), preserving whatever Not/And/Or context it's nested
under -- critically different from substituting `Defined(GUARD)` itself,
which would flip polarity under the enclosing `Not` and give the wrong
answer (verified by hand-tracing a nested self-guard case where naive
substitution produced Constant(0) instead of Constant(1)).

concretize_guard() now: finds the guard name's own minimum macro_order
(when it was #define'd), bails out if that's before the branch even
opened (guards against a stale/pre-existing guard rather than one this
branch itself satisfied), then rewrites every macro's condition with
order > that point via replace_subterm + simplify_condition. Runs
bottom-up naturally (inner conditionals close and get rewritten before
their enclosing one does), so nested self-guards collapse correctly in
sequence.

Verified:
- Two-level self-nested guards (#ifndef OUTER { #define OUTER #ifndef
  INNER { #define INNER #define Y 1 } #endif } #endif) -- Y now resolves
  to plain `active`, both guard layers dropped.
- A genuinely -D-driven macro nested inside a self-fulfilling guard
  (#ifndef GUARD { #define GUARD #ifdef SOME_FEATURE ... #else ... #endif
  } #endif) -- the GUARD layer is dropped while the SOME_FEATURE
  divergence is correctly preserved and still resolves per -D at eval
  time (checked both with and without -DSOME_FEATURE).
- Real clang stdbool.h chain still resolves `bool` correctly
  (unsurprising in hindsight: #if defined(...) branches concretize to
  Constant() immediately at parse time via evaluate_with_defined, so
  only #ifdef/#ifndef contribute genuinely symbolic Defined() terms --
  the deep-nesting risk was real but narrower than first suspected).

Added tests/fixtures/header-guard.c (single-level guard + #if 1 case,
not previously covered by any fixture) and
tests/fixtures/nested-header-guard.c (two-level self-guard +
-D-divergent nested macro, DEFAULT and FEATURE configs). Full cargo test
and clippy pass (same pre-existing unrelated pp.rs warning as before).
