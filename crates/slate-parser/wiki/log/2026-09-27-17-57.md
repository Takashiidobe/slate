# Microsoft-ABI C inline definitions are never inline_only

_2026-09-27 17:57:10_

slate-parser-7n0i. finish_functions (src/sema/function.rs) decided [definition=emitted|inline_only] with the C99/gnu89 rules on every target. On windows-msvc clang (basicGVALinkageForFunction) only uses those rules for gnu_inline functions; every other C inline definition gets its own comdat: weak_odr when dllexport or any redeclaration is extern (isMSExternInline), otherwise linkonce_odr, emitted on first use. Either way the TU supplies the definition, so none is inline_only.

Fix: on a TargetEnvironment::Msvc target with no gnu_inline override, inline_only is false. gnu_inline extern inline stays inline_only (clang: available_externally).

Considered adding a third definition state (discardable, for linkonce_odr) and did not: emitted already means this TU supplies the definition, and a discardable state would also have to cover static inline, which prints emitted today.

Fixture: tests/fixtures/sema/x86_64-pc-windows-msvc/ir_inline.c (mirror of sema/ir_inline.c plus a dllexport inline, gnu89 and c99); checked against clang --target=x86_64-pc-windows-msvc -emit-llvm. Regenerated 7 fixtures; diff is only inline_only -> emitted (exported_inline, __forceinline functions in ms-winnt-keywords, UCRT snprintf/vsnprintf/__local_stdio_printf_options, all linkonce_odr in clang). ir-spec.md Function specifiers updated.
