# Lexer and numeric Context take the Dialect's features at construction

_2026-09-28 16:53:54_

Lexer::new/with_offset now take StandardFeatures as a constructor argument; with_features and the StandardFeatures::default initializer are gone (the preprocessor was the only caller and always set them).

numeric::Context::new and with_features are folded into Context::for_dialect, the only constructor, so a sema Context always carries the dialect's target, features, operation options and default contraction.

The only remaining StandardFeatures::default use is const_expr::Parser::new when its Option<&Parser> context is None (nested parses under a standalone #if/evaluate call). That Option<&Parser> threads through 19 signatures in const_expr, declarator and attributes, where None means 'standalone, accept everything' (e.g. gnu_registered accepts any attribute name); filed as a child of iwsx.
