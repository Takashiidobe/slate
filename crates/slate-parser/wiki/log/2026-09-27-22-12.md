# MSVC-only __asm member and TYPE operands

_2026-09-27 22:12:44_

In the MSVC flavor, __asm now accepts two forms that clang rejects (slate-parser-25m.6.7). First, .field on an untyped operand ([ebx].f) or on a pointer or scalar (g.f) looks the field up in every struct/union tag visible at that point: C2410 when ambiguous (even at the same offset; anonymous members count twice) and C2411 when missing. Second, TYPE <single C keyword>, with a lone signed/unsigned = 1, as cl.exe gives. cl.exe x86 /FAs disproved two premises of the bead: .f on a pointer/scalar ADDS the field offset rather than ignoring it, and two C symbols in one operand is C2424 in MSVC too, so it stays rejected. SIZE/LENGTH on a keyword and multi-word types are syntax errors. Also fixed: register-only references with a field-derived type now emit their ptr size (dword ptr [ebx + 8]) like object references, matching cl.exe. New AST variant MsAsmExpr::TypeKeyword. Fixtures ms_asm_msvc_members_{msvc,clang}.c; both diffed against cl.exe and clang. Clippy, fmt, and 4,356 release nextest tests pass.
