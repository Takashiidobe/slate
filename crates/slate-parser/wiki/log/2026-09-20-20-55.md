# Aggregate initializer rework: current object walk-out and range overwrites

_2026-09-20 20:55:52_

`slate-parser-dyd.9`. The initializer lowering in `src/sema/initializer.rs`
rejected overlapping GNU designated ranges outright and, worse, got the
position of the "current object" wrong after a designation.

Three defects, all confirmed against `clang -emit-llvm`:

- After `[1][0] = 1`, following items continued at the *top* level, so
  `int a[3][2] = {[1][0] = 1, 2, 3}` produced `a[1]={1,0}, a[2]={2,3}`
  instead of `a[1]={1,2}, a[2]={3,0}`. Silently wrong, no diagnostic.
- Any partially overlapping designated range was `Unsupported`
  (`gcc-dg/gnu99-init-1.c`).
- "aggregate initialized without braces" fired on
  `V v = 6 > m` for vector `V`: the whole-value check demanded exact type
  equality, so it bailed before `convert_expr`, which already handles the
  lax vector conversion (4 gcc-torture fixtures).

The rework: `fill` writes into an existing `Builder` rather than returning a
fresh one, so elision merges instead of replacing. `designate` resolves the
whole designator path up front, then `resume` walks the path's last index
back out, running `fill` at each level — that is the walk-out. `Builder`
keeps its members disjoint by splitting ranges on write (`split_out`,
`partitions`) rather than refusing to overlap, and a range designation
replays the remaining path over each part so every element merges with what
it already holds. Re-entering a subobject resets its position to 0, which is
what makes `{[0][1] = 9, [0 ... 2] = 2, 3}` restart at `[0][0]`.

`inferred_array_length` needed the same model — the inferred length depends
on the walk-out — so it now runs a type-only mirror (`Walk`) sharing
`designator_steps` with the real lowering.

Corpus sweep 2582/2688 -> 2588/2689. New fixture
`tests/fixtures/sema/designated_range_overwrites.c`, every global
cross-checked against clang.
