# Pick one asm constraint alternative during lowering

_2026-09-26 23:22:17_

slate-parser-25m.15. Rust takes one class per operand, so lowering now picks one GCC alternative for the whole asm: the first where every operand has a usable class.
Within an alternative: a constant input takes the immediate, else a register class its width fits, else an explicit register, else memory. Both compilers print $5 for "ri"(5). gcc picks the register for rm and clang the memory; the register is what Rust expresses without a pointer.
Unusable: unresolved letters, x87/MMX/AMX (clobber-only in Rust), a register too narrow or wide for the operand, an immediate whose value isn't an integer constant ("i"(&x), filed as .22 for sym operands), a match on an output.
IR: InlineAsm.alternative, InlineAsm.rejected (alternative, source operand, reason), AsmOperand.selected. Printed as [alternative=N|none], '-> class' when the chosen alternative offered several, and a rejected: line.
Lowering restructured: operands are lowered to candidates (output kind, value, or lvalue plus addressability) before selection. A selected Matching folds into its output (partial ties like "0,m" now fold), a selected mem gives InPlace, and anything else reads the value. That means rm/g inputs that pick a register are reads now, not places. With nothing selectable, the old behavior applies.
Found that the alternative-count check (sema/validate.rs) only runs for the clang flavor although gcc also rejects mismatched counts; filed slate-parser-cl7. Selection tolerates it via a 'missing' reason.
Emission notes (pinning, ({x}) wrapping, Rust modifier table) moved to the new emitter bead .21.
22 fixtures regenerated; new sema/ir_asm_alternatives.c.
