# slate-parser-6gk.5: compound literals

_2026-09-11 18:00:34_

Added ConstExpr::CompoundLiteral { ty, declarator, initializer: Vec<InitializerItem> }
in const_expr.rs, reusing ast::{Initializer, InitializerItem, Designator} rather
than inventing a parallel initializer-list type.

Parsing: parse_cast's existing (Type) lookahead now excludes the case where
`{` follows the `)`, so that pattern falls through to a new
try_parse_compound_literal check wired into parse_postfix's primary step
(compound literals are postfix-expressions, so `.field`/`->`/`[]`/++/-- all
compose over them for free via the existing postfix loop). Added a
const_expr::Parser::parse_initializer_list/parse_initializer_value pair
mirroring parser.rs's DeclaratorParser::parse_initializer (designators,
nested braces, string literals, general expressions via parse_assignment).

sema.rs's is_integer_constant_expression and const_expr.rs's evaluate_expr
both got a CompoundLiteral arm (not a constant expression).

Added tests/fixtures/compound-literals.c (struct-typed and typedef-typed
compound literals, designated fields, member access on a compound literal
argument). Verified accepted by real clang. cargo build/test/clippy/fmt all
clean. Closed slate-parser-6gk.5.
