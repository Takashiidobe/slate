# Static assertion messages accept adjacent string literals

_2026-09-28 06:57:33_

slate-parser-v0ns. `_Static_assert(c, "a" "b")` failed with 'expected static assertion message'.

Scope: static-assert only. General expressions already concatenate adjacent
literals in const_expr.rs; parse_static_assert hand-matched exactly one
Token::StringLit after the comma, so any sequence (including `#x " y"`
macro expansions) or prefixed literal (u8/L/u/U) was rejected.

Fix: parse_static_assert accepts one or more string-literal tokens of any
encoding and joins their raw contents. Matches clang and gcc, both of which
accept mixed prefixes here (clang only warns). Message text matches clang's
diagnostic, e.g. `"a" S(q) L"z"` -> 'aq yz'.

StaticAssert.message stays a raw-spelling String; no AST type change.

Test: CONCAT variant in tests/fixtures/sema/static_assert_validation.c
covering file/block scope, u8/L pieces, and a stringizing macro.
