# module header lists bf16 and the decimal formats

_2026-09-21 11:16:32_

The `storage` lines in the IR module's `target` block came from a hardcoded
list in `DisplayModule::fmt` that stopped at f128, so a module using `__bf16`
or `_Decimal32/64/128` printed a type whose size and alignment the header
never stated.

Decision: the header is exhaustive over the directly nameable scalar formats,
not a summary of common types. It now prints bool, every standard integer
width, and all nine floating formats in `FloatType` order (bf16, f16, f32,
f64, f80, f128, d32, d64, d128). A line is still omitted when the target does
not support the type (`storage_of` returning `Err`), which is how aarch64 and
arm32 drop f80 and arm32 drops i128. Bit-precise integers, pointers, `va_list`
and composites stay out: their layouts are derived and printed at the use
site.

bf16 and the decimals are defined for every target in `ScalarLayouts`, so all
193 fixtures with a module header gained four lines; regenerated with
`tools/update_filecheck.py --in-place`.

`wiki/concepts/ir-grammar.md` `storage_of` now enumerates the full list and
says it is exhaustive; `ir-spec.md` states the same next to the module-dump
paragraph.

Closes slate-parser-4a4.
