# Parser keeps enumerator, designator and _Generic expressions

_2026-09-13 20:20:14_

Closes slate-parser-lh7.3.8 and slate-parser-lh7.1.15.

- Enumerator values are parsed Expr (both decl.rs enum paths and
  DeclaratorParser::parse_enumerator_list); evaluate_enum_expression and
  record_enum_value are gone. "previous + 1" is left to sema.
- Designator::Array(Expr) / ArrayRange { start: Expr, end: Expr }; both
  initializer parsers parse the index as an expression (the const_expr
  one used to accept only a bare integer literal; the declarator one
  panicked on anything non-constant). IntegerValue removed.
- ExprKind::Generic holds GenericControl::{Expr, Type{ty, declarator}} and
  GenericAssociation::{Type{ty, declarator, value}, Default(value)}.
  The controlling operand only tries a type name when the token can start
  one, so _Generic(a, ...) keeps a instead of becoming a type.
- reachability marks designator indices and _Generic type names; sema's
  walker follows the new shapes.
- New fixture tests/fixtures/unevaluated-constants.c (clang accepts it);
  33 fixtures regenerated, no diagnostic lines changed.

Evaluation still in the parser: array bounds that fold become
ExprKind::Integer (filed as a follow-up bead), and __BIGGEST_ALIGNMENT__
is read from the target macro for bare aligned attributes.
