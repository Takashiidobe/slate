# Thread -std through preprocessor and lexer

_2026-09-14 12:48:28_

slate-parser-ixa.6: -std was parsed into CompilerArgs.standard but never
consumed, so __STDC_VERSION__ was always fixed at 202311L regardless of mode.

- Added LanguageStandard (c89/gnu89/c99/gnu99/c11/gnu11/c17/gnu17/c23/gnu23,
  default c23) to compiler_args.rs, with stdc_version()/is_c23_or_later()
  and a FromStr that rejects unknown spellings (e.g. "c93") with a useful
  error message.
- Threaded it through Parser::with_standard -> Preprocessor::new ->
  Lexer::with_standard.
- Preprocessor::seed_standard_predefines patches the existing
  __STDC_VERSION__ MacroEntry in place (no new interned file) so FileId
  numbering for every other fixture stays unaffected; removes the macro
  entirely pre-C99, matching clang.
- Lexer gates the bare "bool"/"thread_local"/"static_assert" keyword
  aliases behind is_c23_or_later(); pre-C23 they lex as plain identifiers
  (their underscore-prefixed spellings remain keywords in every mode).
- Extended tools/update_filecheck.py and tests/filecheck.rs with a new
  SLATE-FILECHECK-STD <prefix> <std> directive so a fixture can request a
  different -std per check prefix.
- New fixtures: std_mode_stdc_version.c (C89/C99/C11/C17/C23, matches the
  bug's repro exactly) and std_mode_bool_keyword.c (C17 parses `int bool;`
  as an identifier declaration; C23 parses `bool flag;` as a Bool-typed
  declaration) proving the keyword-set difference.
- cargo clippy --all-targets and cargo nextest run both clean.
