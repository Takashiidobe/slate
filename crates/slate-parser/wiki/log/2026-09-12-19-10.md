# Migrate gcc-dg fixtures, fix macro pasting bug and several parser gaps

_2026-09-12 19:10:15_

Migrated tests/upstream/fixtures.gcc-dg (176 files) into tests/fixtures/gcc-dg/,
extending tests/filecheck.rs and tools/update_filecheck.py to discover fixtures
recursively. gcc-torture (1430 files) is not yet migrated.

Found and fixed a real preprocessor bug: expand_macros inserted a macro's name
into the "disabled" (blue paint) set before expanding its own arguments, so a
macro calling itself indirectly through nested invocations (e.g. CONCAT3 ->
CONCAT -> CONCAT) failed to paste tokens, and self-referential-looking argument
expansion (STEP_2(value) -> STEP_1(STEP_1(value))) silently truncated expansion
depth by one level. Fixed by computing expanded arguments before inserting the
macro name into disabled, only guarding the replacement-body rescan. This
changed tests/fixtures/deep_ast.c's expected output (correctly, to full depth).

Parser fixes: array/range designator indices now accept full constant
expressions (not just IntLit) via a scan-to-boundary + const_expr::Parser::evaluate
helper; enum fixed-underlying-type syntax (C23 `enum foo : long { ... }`) with
backtracking to disambiguate from bitfield colons; `__extension__` skipped in
struct fields, declarations, and function signatures; `__attribute__` groups now
recognized inside the storage-class/qualifier loop for both declarations and
function signatures (e.g. `static inline __attribute__((always_inline)) int f()`);
`_Complex` accepts `_Float16`/`_Float64x`/`_Float128`/`__float128` operands;
top-level tag definitions (struct/union/enum) now skip a leading storage-class
prefix like `static` before dispatching into parse_tag_definition; `_Generic`'s
internal comma/colon splitting is now paren-depth-aware (top_level_token) instead
of finding the first raw comma, which broke controlling expressions containing
calls (e.g. `_Generic(ckd_add(&a,1,1), bool: 1, default: 0)`); a labeled
statement used as the un-braced body of an if/while (e.g. `if (x) L: for (...) ;`)
now correctly keeps parsing until it reaches the actual labeled statement instead
of returning after consuming just the label, which previously desynced any
following `else`. Added __CHAR8_TYPE__ to the clang predefines file.

gcc-dg fixtures went from 61 (bulk-migrated, unfixed) to 155/176 parsing cleanly
by the end of this session; full tests/fixtures tree is at 685/702. Filed
slate-parser-wf8.2.1 through .6 for the remaining known gaps (embedded _Generic,
typeof() with non-trivial expressions, #embed, __builtin_complex, C23 dialect/
__STDC_VERSION__ gating, and a handful of untriaged one-offs). gcc-torture
migration (wf8.3) not started.
