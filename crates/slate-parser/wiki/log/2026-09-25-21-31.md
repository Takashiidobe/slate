# Apply the mode attribute to resolved types

_2026-09-25 21:31:11_

slate-parser-dyd.31: __attribute__((mode(M))) used to be refused ("machine mode attribute"). Where it was accepted, it was ignored: enum fields with mode(byte) laid out as 4 bytes each.

- Parser: apply_vector_attributes is now apply_type_attributes. In attribute order it wraps the specifier in the new AST node TypeSpecifier::Mode(ModeType { base, mode }), alongside Vector, so a mode then vector_size gives a vector of the mode type.
- Sema: TypeResolver::machine_mode resolves the mode the way clang does:
  - Integer modes (QI/byte, HI, SI, DI, TI, word/pointer) pick the first standard integer of that width, so DI is long on LP64 and long long on LLP64 and 32-bit.
  - Signedness comes from the base: char follows the target, _Bool is unsigned, an enum uses its underlying type.
  - SF/DF are float/double; XF works only with x87 long double; TF is binary128 long double, or __float128 on non-MSVC x86.
  - A vector base keeps its byte size and changes lanes.
- Errors match clang: integer/float mismatch, pointer/array/function declarators, XF/TF where the target has no such type. Complex, vector, HF and other modes are Unsupported.
- The declaration attribute itself is now Ignored, since the type carries it.
- Verified typedef types against clang AST on x86_64 linux/msvc, i686, aarch64, armv7, and the 20050107/20050119 record layouts against -fdump-record-layouts.
- Fixtures: 20020108-1, cbrt, pr23135, simd-1, zerolen-2 and layout-attributes now lower. 20050107-1 and 20050119-1/2 now have the right layouts (size 4, not 16). ir_parameter_attribute_diagnostics uses code_seg for its unsupported case.
- Filed slate-parser-dyd.61: declarator-position type attributes apply to every declarator of a declaration (clang: only their own). Pre-existing for vector_size.
- ast-spec and ast-grammar updated.
