# MS __pragma operator

_2026-09-27 09:52:01_

slate-parser-v74.1.2.

vcruntime.h's _CRT_BEGIN_C_HEADER expands to __pragma(pack(push, _CRT_PACKING)),
so every MSVC CRT header failed once __int64 parsed.

expand_line's _Pragma detection is now Preprocessor::pragma_operator, which
recognizes both forms after macro expansion:
- _Pragma("..."): destringized and relexed, as before.
- __pragma(tokens): the balanced operand tokens are the pragma. They are
  already expanded, so pack(push, _CRT_PACKING) packs to 8.
Both go through record_pragma and become PPNodeKind::Pragma nodes, so pack,
warning and the other pragmas behave like the #pragma form.

__pragma is gated like the MS sized-int keywords: msvc flavor, or clang on a
*-windows-msvc target (clang's implied -fms-extensions). The StandardFeatures
field microsoft_keywords is renamed microsoft_extensions, since it now gates
more than keywords.

Fixtures ms-pragma-operator-{msvc,clang-cl}.c check pack(push,1)/pop via
struct sizes, plus warning(...) at file scope and in a function body. clang-cl
and cl.exe accept them; Linux clang rejects __pragma.

Header probe (--flavor=msvc): stdio.h, stdlib.h, string.h and math.h now
parse. windows.h stops at the winnt.h keywords (v74.1.3).
