# Parameter symbol and layout attributes follow clang

_2026-09-26 08:33:00_

slate-parser-dyd.48. sema::attributes used to refuse every symbol/layout attribute on a
parameter as Unsupported, failing the whole TU. Measured against clang 22 and gcc
(x86_64-linux, plus x86_64-windows-msvc for dll*/selectany/declspec(thread)):

- clang errors: section, alias, tls_model, __declspec(thread). These are now
  Use::Invalid with clang's wording.
- clang silent, gcc -Wattributes 'X attribute ignored': visibility, weak, weakref,
  selectany, dllimport, dllexport, common, nocommon. These are now
  Use::Inapplicable with no applies_to, so they warn -Wignored-attributes
  "'weak' attribute ignored" (gcc's wording) and are dropped. A parameter has no
  linkage or storage, so nothing is lost.
- used/retain were already Inapplicable (clang warns too).
- vector_size/ext_vector_type are type attributes the parser already folds into
  the parameter's TypeSpecifier::Vector, so they now pass as Use::Layout; before,
  every vector parameter spelled with a trailing attribute failed to lower.

Fixture: sema/ir_parameter_attribute_diagnostics.c (ERR_LAYOUT replaced by
WARN_SYMBOL, WARN_LAYOUT, VECTOR; ERR_SYMBOL now an invalid-context error).
