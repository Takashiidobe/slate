# AST and IR coverage review: standard-mode gating and lowering gaps

_2026-09-17 21:23:52_

Reviewed what `src/ast.rs` and `src/ir/` actually represent versus what the
parser accepts, probing the release binary rather than reading alone. Filed
17 beads; no code changed.

Two systemic findings.

**Standard mode reaches almost nothing.** `TranslationUnit.standard` feeds
only five decisions plus the C23 keyword set. Verified divergences from
clang: `integer_candidates` (validate.rs:720) hardcodes the C99+ candidate
list, so `-std=c89` rejects `18446744073709551615`, which clang accepts as
`unsigned long`; `restrict`/`inline`/`typeof`/`constexpr` lex as keywords in
every mode, so valid pre-C23 code using them as identifiers fails; K&R
definitions are accepted under `-std=c23`, which removed them; enumerator
range rules and fixed underlying types apply the C23 rules everywhere.
Epic `slate-parser-47s`, whose first child is a `StandardFeatures` struct
derived from standard + flavor — the existing ad-hoc predicates
(`has_control_scopes`, `allows_implicit_int`, …) don't scale to the dozen
more questions the rest of the epic needs, and `typeof` in particular
depends on the gnu-ness of the mode, not the version.

**The AST parses well past what sema lowers.** Qualifiers are metadata
strings only — `ir::Type::Pointer` carries just `is_const`, volatile and
atomic accesses are refused outright, and `restrict` is unrecoverable from
the IR. VLAs have no representation (`Array.length` is `Option<u64>`).
`CompoundLiteral`, `StatementExpression`, `VaArg`, `TypesCompatible`,
`BitCast`, and `typeof`-typed declarations all reach the catch-all
`Unsupported("advanced expression")`. `ir::Function` has no inline concept,
which is where gnu89 and C99 disagree most sharply — their emission rules
for `inline` and `extern inline` are exactly reversed, and one `Linkage`
enum can't express both. Children of `slate-parser-lh7.2`.

Corrected mid-review: K&R parameter promotion is deliberate and already
done (`slate-parser-ixa.3`, `declared_specifiers` recovers the declared
type). Only the C23 acceptance gate is missing there.
