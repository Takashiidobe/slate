# Top-level const on variables

_2026-09-19 14:35:59_

slate-parser-lh7.2.26. ir::Variable gains is_const (named like Parameter::is_const from lh7.2.15), set from resolved.c.qualifiers.is_const in declaration() and printed " [const]" between [restrict] and [constexpr] on let and global lines. Synthetic string-literal globals are false.

Before this, int *const q lowered to ptr<i32> with the const gone; Type::Pointer::is_const is the pointee, so nothing else carried it, and Slate needs it for let vs let mut.

Choices:
- resolved.c.qualifiers is the declarator outermost qualifier set, so const int a[2] (element const) gets [const]: the object is unmodifiable, which is what let vs let mut needs.
- constexpr objects carry [const] as well as [constexpr]; the qualifier set already has const for them (C23 makes them const).
- Qualifiers through a typedef count (typedef const int constant; constant t;).

Fixture churn: only " [const]" added, in ir_function_specifiers, ir_typeof, ir_typeof_qualifiers, string_array_initializer (checked by diffing with the marker stripped). New fixture sema/ir_const_variables.c. ir-grammar variable rule and ir-spec qualifier section updated.
