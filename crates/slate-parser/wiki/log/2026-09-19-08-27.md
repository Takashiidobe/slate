# Array parameter static and qualifiers survive pointer adjustment

_2026-09-19 08:27:50_

`ir::Parameter` now carries the facts that array-to-pointer adjustment used
to discard (slate-parser-lh7.2.15):

- `is_const` — the adjusted pointer's own const (`int a[const]`, and also
  plain `int *const p`, which was equally lost). Prints ` [const]`.
- `array: Option<ArrayParameter>` — the brackets the parameter was written
  with, as `{ extent, guaranteed }`. Prints `[array=3]`, `[array=%n]` for a
  captured VLA extent, `[array=*]` for `[*]`, with a leading `static` when
  C99 6.7.6.3p7 guarantees a minimum element count (`[array=static 3]`).
  Plain `int a[]` prints nothing: it is exactly the adjusted pointer, and
  printing it would churn every fixture for no information.

Also fixed alongside: element qualifiers were dropped from the adjusted
pointee, so `const int a[3]` lowered to `ptr<i32>` instead of
`ptr<const i32>`. clang canonicalizes it to `const int *`; the c_canon
metadata already said so, so the IR contradicted its own metadata (visible
in the ir_typeof_qualifiers `row` parameter).

`Declarator::array_qualifiers` became `array_parameter`, returning both the
qualifiers and `is_static` from the outermost array layer in one walk.

volatile/_Atomic needed nothing: they already reach the accesses through the
parameter's Access entry. Top-level const on a *variable* is still dropped —
filed as a follow-up bead.
