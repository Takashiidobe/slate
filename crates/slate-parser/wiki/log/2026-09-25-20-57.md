# Region-scoped floating-point pragmas

_2026-09-25 20:57:00_

slate-parser-dyd.28. STDC FENV_ACCESS/FP_CONTRACT/CX_LIMITED_RANGE and float_control now change the lowered floating semantics of the statements they enclose.

- Sema carries a FloatingRegion (rounding, exceptions, contraction, complex range, precise) in numeric::Context. Lowerer::compound saves it on entry to a function body, block or statement expression and restores it on exit; pragmas modify it from their position (sema/pragmas.rs FloatingPragmas).
- IR: ArithSema::Floating gains contract=off|on|fast, ComplexFloating gains range=basic|full. The user decided (2026-09-25) that permissions a consumer can use are recorded even though ignoring them is correct; compiler-flags.md's earlier 'no permission fields' rule is revised.
- Defaults: contract on for clang/msvc, fast for gcc gnu*, off for gcc ISO (verified with gcc 16.2.1 -mfma).
- Clang semantics verified against clang 22.1.8 -emit-llvm: FENV_ACCESS OFF/DEFAULT gives nearest-even even under -frounding-math, exceptions back to the command line; float_control(precise, on) sets contract on, (precise, off) contract fast.
- Clang errors: placement (file scope or compound start after only pragmas), push/pop only at file scope, FENV_ACCESS ON / except on while precise off, precise off while except on, malformed float_control. GCC ignores all four pragmas, so the gcc flavor neither errors nor applies them.
- AST: Stdc value is On/Off/Default (uppercase only, as clang); FloatControl(Set{..,push}|Push|Pop|Malformed) with the real parenthesized syntax. semantic_pragmas.c used the invalid 'float_control precise on' spelling and was fixed.
- Static/thread storage initializers always use nearest-even/ignore (C F.8.5; clang and gcc both fold them).
- Automatic FP constant expressions were already left unfolded, so FENV_ACCESS needs no fold change.
- Follow-ups: dyd.57 fast-math permissions, dyd.58 -ffp-contract/-fcx-limited-range args, dyd.59 hoisted pragma as if-body accepted.
