# gcc flavor: _FloatN/_FloatNx/__float80 types, strict-mode fixed-point identifiers

_2026-09-27 17:06:29_

slate-parser-cxg.9. Under --flavor=gcc (all modes) _Float32/_Float64/_Float32x/_Float64x/
_Float128 lex as keywords, __float80 too on x86 (StandardFeatures::with_gcc_keywords,
set in pp configure). clang keeps them identifiers: glibc typedefs them there.

Semantics, all checked with _Generic probes against gcc x86_64, -m32, aarch64 and
armv7 cross: _Float32/_Float64/_Float32x/_Float64x are new FloatKinds distinct from
float/double/long double; _Float128 is __float128 (same FloatKind); __float80 is
long double where x87. _Float64x format = TargetInfo::float64x_format (x87 f80,
binary128 ld f128, else f128 iff has_float128); _Float64x/_Float128 are errors on
armv7. float_rank now ranks by target format, ties per C23 6.3.1.8: _FloatN >
standard > _FloatNx (so f32x+double=double, f64x+ld=ld, f128+ld=_Float128).
Literals f32/f64/f32x/f64x get those kinds; f64x resolves per target like L (was
Unsupported); new W suffix = __float80. Trailing _Complex accepted after any
extended float keyword (was only float/double/long double).

gcc's -std=cNN implies -fno-asm, which unreserves _Fract/_Accum/_Sat: gcc flavor
lexes them as identifiers in strict modes (keywords-ignored-c99.c).

Harness fix: tests/filecheck.rs and tools/update_filecheck.py ignored
SLATE-FILECHECK-PREFIX-ARGS for ERROR configs, so per-target error configs ran on
the default clang/x86_64. Found via sema/gcc_floatn_types.c ARMV7.
