# wf8.3: finish last three fixtures (mixed string concat, __real/__imag, __complex prefix)

_2026-09-13 09:21:18_

Closed out the remaining wf8.3 children (slate-parser-wf8.3.{3,6,10}):

- wf8.3.3 (20000717-4.c, struct tag/member sharing an identifier) needed
  no new fix -- it was the same nested-tag-collection bug already fixed
  for wf8.3.5 (`struct slot { ... } slot[4];` is a nested tag definition
  inside another struct's field). Confirmed it parses clean and ported it.
- wf8.3.6 (20010325-1.c): adjacent string literal concatenation
  (`coalesce_string_literals` in parser.rs) only merged two `StringLit`
  tokens. `L"a" "b"` (wide + narrow) hit the catch-all `_ => push`, so the
  narrow literal was left as a separate token and the following `[1]`
  subscript expression failed to parse ("unexpected tokens after
  expression" -- generic diagnostic misattribution again). Generalized to
  `string_literal_content`/`concatenated_string_literal`: any pairing of
  StringLit/Utf8StringLit/Utf16StringLit/Utf32StringLit/WideStringLit now
  merges, with the prefixed variant winning per C11 6.4.5p5 (only one
  literal in the run is expected to carry a prefix; mixed-prefix runs
  keep whichever the merge saw first, same as before -- not spec-checked,
  just not worse than before).
- wf8.3.10 (20030910-1.c): `__real`/`__imag` unary complex-part operators.
  const_expr.rs's parse_unary already special-cased `__real__`/`__imag__`
  (double trailing underscore) as a `ConstExpr::Call{callee: Identifier,
  arguments}` hack -- just missing the bare `__real`/`__imag` spellings,
  added to the same match arm. Separately, `__complex double dc;` in the
  same fixture failed too: the lexer only recognized `_Complex` and
  `__complex__` as the Complex keyword, not bare `__complex`; added it
  next to the existing aliases in lexer.rs. (parser.rs's parse_base_type
  already had prefix-position `_Complex` handling -- `Keyword::Complex`
  as the leading token, recursing into the element type -- so no parser
  change was needed once the lexer recognized the spelling.)

All three ported to tests/fixtures/gcc-torture/ via update_filecheck.py.
This closes out slate-parser-wf8.3 entirely (all 10 children done);
slate-parser-wf8 (port the first 250 gcc-torture fixtures) can proceed
to the next batch.
