# Derive signatures for CustomTypeChecking builtins

_2026-09-20 09:42:19_

dyd.19. Builtins marked CustomTypeChecking get no signature from the
generated prototype table, because Clang computes their argument types in
Sema. `builtins::derived_signature` now maps a tblgen record to a
signature built from the *actual* argument types, and the call is then
lowered through the ordinary `Callee::Builtin` path, so the IR shape is
the same as any other builtin call.

Shapes:
- `Uniform { least, most, class }` — `T(T, ..)`, every operand and the
  result share the first operand's type. Covers the whole
  `__builtin_elementwise_*` family; `class` (integer/floating/arithmetic/
  any) is checked against the vector element type, not the vector. Clang
  applies no promotions here: `add_sat(short, short)` is `short`.
- `Scaled` — `T(T, int)` for `elementwise_ldexp`.
- `BitCount` — `int(T)` / `int(T, int)` for `__builtin_clzg`/`ctzg`.
- `Declared` — `__builtin_assume_aligned`, whose declared prototype
  `void*(void const*, size_t, ...)` was already accurate.

Three builtins cannot be expressed as a signature and became
`CustomBuiltin` arms instead: `__builtin_addressof` (the operand stays an
lvalue, so it lowers to `AddressOf(place)`), `__builtin_classify_type`
(unevaluated, folds to the GCC type-class code; the mapping was checked
against clang for every type class) and `__builtin_fpclassify` (a nested
conditional over `FloatClass` tests).

`typeof_operand` grew a sibling `speculative_type` returning
`(QualType, is_bit_field)`, so a derived signature and classify_type can
see through a bit-field while `typeof` still rejects it.

Drive-by: `v4si a = b;` was rejected as "aggregate initialized without
braces" because vectors have `Shape::Array`; a whole-vector initializer of
the same type is now accepted like a scalar one.

Corpus sweep: slate-ir 2354/2674 -> 2363/2674, no regressions. Vector
element subscript (`v[i]`) is still unlowered and is now dyd.24.
