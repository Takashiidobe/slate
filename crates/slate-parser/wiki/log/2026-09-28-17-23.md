# Bind prototype parameters in name resolution

_2026-09-28 17:23:42_

Part of slate-parser-cc94.2.

names.rs::declarator visited a non-definition function declarator's
parameter declarators only while collecting labels, and never bound the
parameter names. So an array bound in a prototype parameter
(int a[COUNT], int a[sizeof(T)], int a[n]) had no name references at all;
only TypeResolver's string scopes made those constant. cc94.2 moves identifier
lookup onto names.references, which needs these.

Now each prototype parameter declarator is visited and its name bound as a
parameter in the prototype scope (C11 6.2.1p4). Consequences:
- one new BindingId per named prototype parameter, so 945 IR/names fixtures
  renumber (%N, .strN). Verified with an id-normalized diff: the only
  non-id change is names_control_labels_expressions.c, where a prototype
  parameter 'values' is now bound and a later local shows as values#1.
- void d(int a, int a); now fails with duplicate ordinary name, as clang
  (redefinition of parameter) does.

Gate: 7268/7268.
