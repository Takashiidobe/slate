# Record asm dialect and fix template dialect alternation

_2026-09-26 22:28:40_

Closed slate-parser-25m.11. `ir::InlineAsm` now carries `dialect: Option<AsmDialect>` (`Att` on x86, `None` on AArch64/ARM), printed as `[dialect=att]` after the template string.

Diverged from the bead: the target arch is NOT copied onto each asm node. `Module::target.family` already holds it and asm cannot differ per statement, so a copy could only disagree. Dialect is per node because MSVC `__asm` (Intel) and GNU asm (AT&T) can share a TU under clang -fms-extensions.

Found and fixed a parser bug on the way. Verified with gcc 16.2.1 and clang 22.1.8 (-masm=att/intel, plus aarch64):
- The dialect alternation is the BARE `{att|intel}` in extended asm, x86 only. `%{` `%|` `%}` are escapes printing literal `{ | }` (clang rejects `%|`, gcc accepts). We had it inverted: `%{` became DialectStart and bare braces were text.
- Stray `|`/`}` outside an alternation are literal; missing alternative is empty; nested alternation is an error in both; unterminated `{` is accepted by clang (runs to end) and rejected by gcc, so we accept it.
- On aarch64 both compilers keep braces literal (ld1 {v0.16b} etc.), so the parser only recognizes alternation when target family is x86.

AST: `AsmTemplatePiece::{LBrace,Pipe,RBrace}` replaced by `DialectAlternatives(Vec<Vec<AsmTemplatePiece>>)`. IR: `AsmPiece::Dialect*` removed; lowering keeps only the selected side and merges adjacent text, so the backend never sees an alternation. Basic asm is untouched (verbatim, no alternation processing).

GNU asm is always Att until -masm lands: filed slate-parser-25m.19. Fixtures: sema/ir_asm.c dialects(), asm-statement.c, sema/aarch64-unknown-linux-gnu/ir_asm_braces.c, error/asm-nested-dialect-alternatives.c; ~70 IR fixtures gained [dialect=att].
