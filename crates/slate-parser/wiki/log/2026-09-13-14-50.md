# File-scope asm and flavor gating

_2026-09-13 14:50:42_

File-scope asm and flavor-gated asm forms (slate-parser-25m.5).

- New Decl::Asm { asm: GnuAsm, provenance }. Top-level Code nodes try
  parse_file_scope_asm right after _Static_assert; the node must be fully
  consumed. Added no-op arms in Decl::name/provenance, reachability,
  sema (both loops), and tests/filecheck.rs.
- At file scope the asm path is taken only when a string literal follows
  '(' so K&R 'asm(x);' still parses as a declaration.
- Behavior verified against gcc 16.2.1 and clang 22.1.8:
  - file-scope basic asm: both accept (clang fails later in MC only).
  - file-scope qualifiers: both reject; message 'meaningless volatile on
    asm outside function' in every flavor.
  - file-scope operands: clang rejects ('expected )' after template);
    gcc parses them (its error is semantic), so Gcc accepts.
  - hard register constraints {reg}: clang rejects with 'invalid
    input/output constraint ... in asm' at the constraint; gcc accepts.
  - asm goto("") without labels: gcc rejects 'expected :', clang accepts.
- Msvc flavor gets no gating (25m.6 owns MSVC asm).
- asm-statement.c no longer uses {rax} under clang; gcc coverage moved to
  asm-hard-register-gcc.c.
- Fixture gotcha: put SLATE-FILECHECK-* directives after the code. A
  FLAVOR line above the code shifts diagnostic line numbers between the
  updater and the harness (filed slate-parser-niv).
