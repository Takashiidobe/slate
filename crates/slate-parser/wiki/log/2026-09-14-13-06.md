# Span identifier-bearing AST fields (slate-parser-ixa.8)

_2026-09-14 13:06:45_

Member.field, Designator::Field, Stmt::Labeled.label, Stmt::Goto, ExprKind::LabelAddress, and Stmt::LocalLabelDecl now hold Span<String> instead of bare String, matching the existing GnuAsm.labels: Vec<Span<String>> pattern. Every parse site already had the token's Span available (const_expr::Parser::expect_field_name, parser/stmt.rs's inline Labeled/LocalLabelDecl/Goto matches, parser/declarator.rs's designator loop); the fix was to stop discarding it via Span::cover/span_tokens rather than any structural change. Span<T> already impls Display when T: Display, so downstream formatting (ExprKind::Member/LabelAddress Display) needed no changes. Kept Fragment::expect_ident's signature (String) unchanged since attributes.rs/asm.rs use it for unrelated identifiers outside this bead's scope; wrapped its result in span_tokens only at the Goto call site.
