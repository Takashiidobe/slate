# Validate static assertions during sema

_2026-09-17 15:32:23_

`sema::assertion` is a new pass that walks the AST before name resolution and
evaluates every file-scope and block-scope `_Static_assert`/`static_assert`
condition. It keeps its own `TypeResolver` with `assertion_scope` set, shadowing
names and tags per scope so a local object hides an enum constant of the same
name. The AST keeps the assertions verbatim; `sema::module` erases them during
IR lowering.

Policy on conditions we cannot evaluate: `ice_shape` whitelists the expression
forms the constant evaluator handles, and anything outside it is skipped
silently rather than diagnosed. Diagnosing them produced false positives on
valid C — `_Generic` selection (gcc-dg/stdckdint-1.c) and a macro call our
preprocessor fails to expand (gcc-dg/c23-digit-separators-1.c). Folding the rest
is slate-parser-byw; the preprocessor rescan bug is slate-parser-vxc.

Two layout gaps had to be closed first, both cross-checked against clang:

- `sizeof` of a non-plain string literal. `code_units` holds codepoints, not
  encoded units, so `encoded_length` re-encodes per encoding (UTF-8 1-4 bytes,
  UTF-16 surrogate pairs) and the element type follows u8/u/U/L.
- `_BitInt(N)` storage. `ScalarLayouts::bit_precise` takes the smallest standard
  integer layout that holds N, and for N above the widest standard type rounds
  up to that type's alignment. It deliberately declines the tabulated widths so
  targets that dropped `__int128` (arm32) keep rejecting it.

Also removed a duplicate `Conditional` arm in `TypeResolver::constant_value`;
the unreachable one skipped integer promotion before the usual arithmetic
conversions.
