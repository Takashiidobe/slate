# Model volatile, restrict, and \_Atomic in the IR

_2026-09-18 18:44:48_

slate-parser-lh7.2.10. volatile/\_Atomic were metadata-only (c_volatile/c_atomic) and lowering rejected any volatile or atomic access outright; restrict was unrecoverable from the IR.

Decision, per qualifier (mirrors CIR's cir.load volatile / atomic(seq_cst) flags on the memory op):

- ir::Access { volatile, atomic } lives on Place and prints on read/write/store/update (read<i32, volatile>, write<i32, atomic=seq_cst>).
- Type::Pointer gains pointee access next to is_const (ptr<volatile i32>): the only way to know \*p is volatile. Object types stay unqualified.
- Field carries its own access; a field place is base access | field access. Array decay and & fold place access back into the pointer type.
- Atomic compound assignment / ++ stays one update node (hoisted into a synthetic temporary) instead of read/compute/write, since C defines it as one RMW. Volatile updates still split; both halves keep volatile.
- restrict is a [restrict] flag on Parameter/Variable. Array-parameter bracket qualifiers (a[restrict 4]) become the adjusted pointer's own, via new Declarator::array_qualifiers.
- Typedef qualifiers and the \_Atomic(T) specifier now merge into resolved qualifiers (previously dropped; \_Atomic(T) was an unsupported type specifier).

Lowerer keeps a BindingId -> Access map; normalize() hands it to the Hoister so a hoisted Let initializer's write keeps volatile.
