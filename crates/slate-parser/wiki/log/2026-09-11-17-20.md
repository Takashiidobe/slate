# Parse control-flow statements

_2026-09-11 17:20:50_

Added if/else, while, do-while, for, switch/case/default (flat fallthrough
representation), labeled statements, goto, break, and continue as real Stmt
(and ConcreteStmt) variants for slate-parser-6gk.2.

Added If/Else/While/Do/For/Switch/Case/Default/Break/Continue/Goto keywords
to the lexer (Keyword::Default replaces the old "default" Ident special-case
used by _Generic).

Rewrote parser.rs's statement parsing: parse_stmts_from_tokens now loops a
new parse_one_stmt(tokens, &mut i) that dispatches on keyword, with a
parse_body helper for brace-or-single-statement control-flow bodies. Added
matching_paren and top_level_semi helpers alongside the existing
matching_brace.

Fixed a real bug this surfaced: parse_stmt_list previously parsed each
physical source line as an independent token stream, and parse_function's
multi-line closing-brace search just took the first line starting with `}`
-- both assumptions that broke as soon as a function body could contain
multi-line control-flow blocks. parse_stmt_list now concatenates consecutive
PPNode::Code lines into one token stream before parsing statements, and the
closing-brace search is now depth-aware across nodes.

eval.rs gained matching ConcreteStmt variants and eval arms (required for
exhaustive matches to compile, not full semantic handling -- reachability
and render still need real handling per slate-parser-6gk.1, which now
depends on this task plus 6gk.3/6gk.4).

New fixture tests/fixtures/control-flow-statements.c covers all new
constructs against the clang oracle. Regenerated
tests/fixtures/ported-slate-alias-global.c's expected error diagnostic --
the concatenated-line change shifted where its (already-known-wrong,
pre-assignment-support) error span points, not the underlying failure.
