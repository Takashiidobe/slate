# Clang-flavor asm sema

_2026-09-13 15:27:15_

Lax clang-only sema over structured asm (slate-parser-25m.7).

- TranslationUnit carries flavor: CompilerFlavor, set by the parser and kept
  by filter_translation_unit; analyze reads self.flavor. Checks run only for
  Clang. Messages mirror clang 22 (SemaStmtAsm.cpp, SemaDecl.cpp).
- Outputs: 'invalid lvalue in asm output'; casts get clang's asm-cast error.
  Syntactic only: const objects, functions, enumerators are not caught.
- Alternatives: the first operand (outputs then inputs) sets the count; the
  first mismatch reports 'N vs M' at that operand.
- asm goto: 'use of undeclared label'. Labels are Stmt::Labeled anywhere in
  the body plus any 'ident :' in raw ConstExpr statement-expression tokens
  (over-approximation, so no false errors).
- Register vars: file-scope unlabeled -> illegal storage class; unknown and
  empty register names; file scope accepts only rsp/rbp by raw spelling
  (x86-64 assumed); non-scalar -> unsupported type. Size mismatch skipped.
  clang accepts file-scope register initializers (gcc rejects them).
- Not done: asm goto jump-scope, duplicate label operands, input constraint
  validation. Spans are coarser than clang's.
- New exhaustive walk_stmt/walk_expr/walk_const_expr in sema.rs, recorded in
  wiki/concepts/ast-enum-touchpoints.md.
- Fixtures: asm-sema.c (SEMANTIC), asm-sema-gcc.c (accepted).
  asm-label-unknown-register.c is now FLAVOR gcc; asm-statement.c uses
  consistent alternative counts.
- Harness still fails on pre-existing issues: missing CHECKs (oxx.1.11) and
  void-object errors in 20010327-1.c / 20011114-1.c (new bug filed).
