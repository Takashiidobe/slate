# Gate restrict, inline, typeof and constexpr on standard mode

_2026-09-17 21:46:47_

slate-parser-47s.3. The lexer recognized `restrict`, `inline`, `typeof`,
`typeof_unqual` and `constexpr` as keywords in every standard mode, so
valid C that uses them as identifiers failed to parse.

Added five `Availability` fields to `StandardFeatures` and a
`LanguageStandard::is_gnu()` helper, since two of these depend on the
gnu-ness of the mode and not just the version. Verified each against
clang with `int <word>;` across c89..gnu23:

- restrict: keyword in c99+ (flavor-independent).
- inline: keyword in c99+, and an extension in gnu89.
- typeof: keyword in c23, and an extension in every gnu mode.
- constexpr, typeof_unqual: keyword in c23 only.

Correction to the bead's design note: `typeof_unqual` does _not_ follow
`typeof`. clang marks it `KEYC23` with no `KEYGNU`, so it is an
identifier in gnu89/gnu99/gnu17. It is gated with `constexpr`.

The `__`-prefixed spellings stay unconditional in all modes.

Also threaded features into the `_Pragma` lexer in `src/pp/mod.rs`. The
token-pasting lexer there still uses defaults (slate-parser-8c5), and
`__STRICT_ANSI__` is still not predefined (slate-parser-r37), which is
why the new fixtures pass a `-D` per configuration instead of branching
on gnu-ness from inside the source.

Four fixtures: `std_mode_{restrict,inline,typeof}_keyword.c` and
`std_mode_constexpr_typeof_unqual_keywords.c`.
