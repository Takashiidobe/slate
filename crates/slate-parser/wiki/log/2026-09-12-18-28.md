# fixed struct-return function misparsed as tag def, added __builtin_bit_cast/sizeof-no-parens/statement-expr-initializer/__label__ support

_2026-09-12 18:28:15_

- struct-returning function defs (e.g. `struct Byte f(void) { ... }`) were misclassified as struct tag definitions in parse_top_level_item because the heuristic only checked whether the first `{` came before the first `=`; fixed by also requiring the token before that `{` not be `)` (a function's param-list close), see src/parser.rs parse_top_level_item.
- added __builtin_bit_cast(type, expr) support as ConstExpr::BitCast (not const-foldable).
- sizeof without parens (`sizeof expr`) was unhandled in const_expr::Parser::parse_unary; added a fallback case.
- __attribute__((nonnull)) with no argument list (meaning all pointer args) was rejected; now parses to Attribute::NonNull(vec![]).
- statement-expressions `({ ... })` used directly as a declaration initializer (e.g. via glibc-style macros) weren't handled since DeclaratorParser::parse_initializer has no access to the full Parser needed for parse_stmts_from_tokens; special-cased in parse_declaration_tokens before calling parse_initializer.
- added GNU __label__ local-label declarations as Stmt::LocalLabelDecl (parsed, not semantically used).
- fixed tools/update_filecheck.py: generated CHECK lines containing literal {{, }}, or [[ (e.g. from a printf format string in the AST dump) broke FileCheck's regex-block parsing; added escape_filecheck_literal using bracket-class escapes (naive brace-adjacency in backslash-escaped forms causes premature block closure).
