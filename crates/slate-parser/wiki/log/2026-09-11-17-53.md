# slate-parser-6gk.4: local declarations and nested blocks

_2026-09-11 17:53_

Added Stmt::Decl(Declaration) and Stmt::Block(Vec<Stmt>) (+
ConcreteStmt equivalents), wired through eval.rs. parser.rs:
refactored parse_declaration into a shared parse_declaration_tokens so
declarations parse from an in-progress token stream, not just
top-level PPNode text. Added Keyword::is_storage_class_or_specifier()
and a starts_declaration() check to decide when a statement starts a
declaration vs an expression; parse_one_stmt now recognizes a bare '{'
as a nested Stmt::Block. for-loop init clauses now also accept a C99
declaration (closes a loose end from 6gk.2).

Fixed a bug this surfaced: parse_initializer only accepted a bare
int/string literal, breaking on locals like 'int total = a;'. Added
const_expr::Parser::parse_one (one assignment-expression from an
offset) and routed initializers through it, giving Expr::Const(...)
consistently with the rest of the codebase -- this changed existing
int-literal initializers from IntLit(n) to Const(Integer(n)), so
initializers.c/macros.c/macro-conditional-use.c were regenerated.

Converted ported-slate-alias-global.c from a SLATE-FILECHECK-ERROR
fixture to a passing one -- its only failure was the unsupported local
'int result;', now fixed.

Added tests/fixtures/local-declarations.c. Verified with real clang
that it and expression-grammar.c are valid C; confirmed
SLATE_CLANG_ORACLE=1's pre-existing return-value-summarizer panic is
unaffected. Closed slate-parser-6gk.3, then slate-parser-6gk.4.
