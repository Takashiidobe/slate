# Lower GNU and ext vector types into IR

_2026-09-19 08:05:42_

`ir::Type::Vector { element, lanes }` (`vector<i32, 4>`) now represents both
`vector_size(N)` and `ext_vector_type(N)`; `sema/types.rs` divides a byte size
by the element's storage size and rejects a size that is not a positive
multiple of it, and rejects `_Bool` and decimal elements.

Target storage is `next_power_of_two(lanes * element_size)` for size *and*
alignment — checked against clang, which reports `sizeof` 16 for a 3-lane
`int` vector and 8 for a 3-lane `short` vector. ABI passing is `AbiPass::NativeC`
on every target: register classification depends on the ISA extensions in use,
so it is left explicitly unclassified rather than guessed (bd
slate-parser-lh7.2.17.6).

Arithmetic is per-lane: the result type is a vector, the operation prints
`elementwise=true`, and the contract is the element's scalar contract except
that integer lanes wrap on overflow, since clang emits no `nsw` for vector
arithmetic. Comparisons produce a lane mask (signed integer vector of the
element's storage width) printed as `result=` rather than `bool`. Mixed
operands follow clang's lax vector conversions: the left operand fixes the
result type, a same-size vector is reinterpreted (`vector_bit_cast`), and a
scalar is converted to the element type then `vector_splat`. Clang rejects a
splat whose scalar type would truncate; we accept it and record the
conversion, since sema is a debugging aid for input that already compiles.

Braced initializers reuse the array shape with the lane count as length, so
the aggregate keeps the declared vector type. Lane subscripts and swizzles are
not lowered (bd slate-parser-lh7.2.17.7).

Pinned by `tests/fixtures/sema/ir_vector.c` and `ir_vector_invalid.c`; sizes,
alignments, and diagnostics were diffed against clang 22.
