# Stringification preserves original spacing

_2026-09-18 17:40:41_

slate-parser-fsf. # now goes through pp::stringized_source: a space is emitted only where the argument's tokens were not adjacent in source (same file, spelling end != next start), so S((-307)) is "(-307)" and S(a+b) is "a+b". String and char literal tokens get \ and " escaped as C11 6.10.3.2p4 requires. __VA_ARGS__ drops the original commas when splitting arguments, so expand.rs argument_separator infers a,b / a, b / a , b from the gap between the neighbouring tokens; other spacing around those commas collapses to the nearest of the three. Fixture stringify_spacing.c matches clang -E; several gcc-torture fixtures regenerated (strlen ( a [ v0 ] ) -> strlen(a[v0])).
