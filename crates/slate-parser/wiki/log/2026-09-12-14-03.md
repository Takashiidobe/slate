# Lexer splices and newline tokens

_2026-09-12 14:03:17_

Step 3 of epic slate-parser-11p. Lexer::with_offset now drops backslash-newline (and backslash-CRLF) pairs while building its char buffer, keeping each retained char's original byte offset, so tokens spanning a splice (even mid-identifier, per C translation phase 2) get correct source Locs. current_loc now ends a token at its last consumed char rather than at the next retained char, so a splice directly after a token is not counted in its length. New opt-in Lexer::with_newlines() emits Token::Newline for each logical newline (splices and newlines inside block comments are not logical newlines); default lexing, used by parser.rs, is unchanged. Nothing consumes newline mode yet: the preprocessor still pre-strips comments and splices line-by-line; switching it to whole-file token lexing and deleting strip_comments/splice_continuations is part of slate-parser-11p.4 (directive syntax tree + walker).
