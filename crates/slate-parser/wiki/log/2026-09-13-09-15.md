# wf8.3: register params, nested tags, typedef+pointer alias, statement expressions

_2026-09-13 09:15:50_

Fixed five gcc-torture parser/sema bugs (slate-parser-wf8.3.{4,5,7,8,9}):

- parse_parameters (parser.rs) now consumes a `register` storage-class
  keyword before/after qualifiers on function parameters; it was only
  handled for top-level/local declarations, not parameter-declaration
  context.
- Added ConstExpr::StatementExpression(Vec<Span<Token>>) to const_expr.rs
  so GNU `({ ... })` statement expressions can appear as a general
  subexpression (function args, binary operands), not just as a whole
  expression-statement. Const_expr's parse_primary detects `(` `{` and
  captures the raw token span (deferred, unparsed) via the newly
  pub(crate) parser::matching_brace. This is a raw-token leaf, not a
  parsed Vec<Stmt>, because const_expr::Parser has no access back to
  parser::Parser's statement grammar (self.error_at, typedef_names,
  recursive parse_stmts_from_tokens all need &Parser) -- threading that
  through would be a much bigger refactor than the fixtures needed.
  Touchpoints updated: Display, evaluate_expr (NotConstant), sema.rs's
  is_integer_constant_expression (false).
- build_tag_alias_decl (parser.rs) took (kind, name) and always produced
  a bare `Declarator::Name(alias)` -- so `typedef struct t { ... } *T;`
  silently dropped the `*`, and T was registered as `struct t` rather
  than `struct t *`, so any later use of T as a type failed sema with
  "unknown type name T". Both call sites (same-line and multi-line tag
  body closing-brace scanning) now run the trailing tokens through
  DeclaratorParser::parse_declarator and apply_abstract_declarator, so
  arbitrary declarator shapes (pointer, array, ...) on the alias work,
  not just bare names.
- sema.rs's `tags` set (used by check_type's "unknown tag" check) only
  collected names from top-level Decl::Record/Enum/Declaration/Typedef --
  never from tag definitions nested inside another record's field types
  (e.g. `struct type { struct field { ... } *fields; };`), and never
  registered a tag mentioned only via an incomplete pointer reference
  (`struct _obstack_chunk *chunk;` with no `struct _obstack_chunk`
  elsewhere) which is legal C (implicit forward declaration). Replaced
  the flat filter_map with collect_tag_names, a recursive CType walker
  that inserts every Tagged name it finds (body or no body) and recurses
  into TagBody::Fields, pointer/array/qualified/atomic/vector/typeof
  wrappers, and function return+parameter types.

Ported the underlying fixtures to tests/fixtures/gcc-torture/ via
tools/update_filecheck.py: 20020402-3.c, 20001203-2.c, 20011113-1.c,
20000917-1.c, 20020206-1.c, 20020320-1.c. The compound-literal-after-return
ticket (wf8.3.4, 20000917-1.c) turned out not to need its own fix -- it
was blocked by the same register/statement-expression issues, not a
separate compound-literal bug.
