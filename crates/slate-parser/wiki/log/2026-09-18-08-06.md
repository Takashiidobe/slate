# Raise -Wlong-long at long long declarations

_2026-09-18 08:06:58_

slate-parser-47s.9. -Wlong-long previously fired only at integer-literal
selection; clang also raises it for a written `long long` specifier with no
literal involved.

Design. Rather than add a `check_long_long` call at every site a type is
written (which costs one call per site for every future warning), two things
are now each stated once:

- `extension_warning(ty, features)` maps a single written specifier to the
  warning it earns. A new type-level extension warning is one match arm.
- `check_type` consults it for every specifier it already visits, so
  declarations, parameters, fields, and return types are covered with no new
  call sites. Block-scope locals cannot use `check_type` (its `typedefs` set
  is file-scope, so a function-local typedef would be misreported as an
  unknown type name), so `check_body_types` walks them with a new `walk_type`
  visitor and the same table.

`check_type`'s `typedefs`/`tags` pair collapsed into `TypeContext`, which also
carries the diagnostic knobs. Severity resolution moved to
`Warning::diagnose`, shared with the literal path so it is not written twice.

Fixed alongside: `-Werror=<name>` did not enable a default-off warning, so
`-Werror=long-long` was silently a no-op. 47s.8's fixture used
`-Werror=c99-compat`, which is default-on in c89, and masked it.

Deliberate divergence: `long long a, b, c;` reports once. Clang reports three
identical diagnostics at one span because it warns per declarator; that is an
implementation artifact, not semantics.

Verified against clang 22 over 54 (source, standard, flag) combinations: all
locations, counts, and exit codes match. Mutation-tested the new fixtures.
