# Token-based PP directive tree and walker

_2026-09-12 14:10:17_

Step 4 of epic slate-parser-11p. The preprocessor now lexes each file once (Lexer::with_newlines) and parses it in src/pp/syntax.rs into a macro-state-free tree: logical lines split on Token::Newline with comment tokens pulled out, then Item::{Comment, Text, Directive, Conditional(IfSection{branches, endif})}. Directive names are classified by token spelling (DirectiveName enum), so '#  if(1)' works and no string-prefix matching remains. Conditional structure is validated in every branch, including statically dead ones (dead '#else #else' now errors, matching clang), while non-conditional directive arguments are only interpreted when executed, per C's skipped-group rules. src/pp/mod.rs walks the tree in order with the same Condition folding (excluded accumulator), expression evaluation order, concretize_guard and statically-false skipping as before; define.rs builds MacroDefs from directive tokens (names from raw source spelling since the lexer canonicalizes keyword aliases like __inline); include.rs reads header names from StringLit or the source slice between < and >. Provenance lines come from a per-file line_starts index. Deleted: normalize_directive, skip_block, strip_comments, splice_continuations, collect_comments, line offset maps. Lexer char/string literals now stop at newline so prose apostrophes in #if 0 blocks don't swallow later lines. Null directive '#' is accepted. New fixtures: pp-token-directives.c, dead-branch-malformed-conditional.c. Existing fixtures unchanged.
