# Lex integer imaginary literals as integers

_2026-09-18 19:52:31_

Implemented slate-parser-lh7.2.17.5. GNU integer imaginary literals (3i, 3ui, 3iu, 0x10j, 3lI) used to lex as FloatLit because the i/j suffix made the digits non-integer, so they parsed as FloatLiteral and sema rejected them.

- Lexer::integer_digits strips i/j with the other integer suffix letters, so these now lex as IntLit. Lexer::is_imaginary_integer (contains i/I/j/J; no hex digit or other suffix uses those letters) gives the flag.
- IntegerLiteral gains imaginary: bool (Debug-skipped when false); ast-spec.md updated.
- Token::integer_value/_i128 return None for imaginary spellings, so attribute integer arguments do not silently accept 3i as 3.
- Constant evaluation (evaluate_expr, evaluate_wide) rejects them as NotConstant("imaginary literal"); #if 3i errors like gcc/clang.
- Sema lowers them to aggregate<complex<T>>(0, v), with T the literal's type without i/j; verified against clang: 3ui/3iu complex<u32>, 3lI and 5000000000i complex<i64>, 3ULLi complex<u64>. Shared imaginary_literal helper with float literals; removed is_integer_spelling (the error guard it served is gone).

AST fixtures containing Ni literals (complex_record_fields, gnu_integer_complex, gcc-torture 20041124-1/20041201-1/pr38151) now show IntegerLiteral instead of FloatLiteral. gnu_libc_stdio.c was regenerated as well; its declaration-order drift comes from the user's concurrent libc-shim edits, not from this change. clippy, fmt, cargo nextest run --release pass.
