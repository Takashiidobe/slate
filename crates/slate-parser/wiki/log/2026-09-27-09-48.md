# Preprocess keywords as identifiers

_2026-09-27 09:48:09_

slate-parser-vp7, slate-parser-9piq.

The lexer used to turn keywords into Token::Keyword before preprocessing, so
macro expansion (which only matches Token::Ident) ignored macros named like
keywords: #define const, #define __int128 long, #define inline __inline__.
Stringizing also printed the canonical keyword, so S(__const) gave "const".

Now the lexer, whose only user is the preprocessor, emits every word as
Token::Ident. The keyword table moved to lexer::keyword_token(word, features),
and Preprocessor::classify_keyword converts identifiers to keywords where
tokens leave the preprocessor: expanded code lines, #pragma and _Pragma
tokens. This matches clang, where keywords are plain identifiers until after
preprocessing. It also gives:
- #if treats keywords as identifiers (#if sizeof -> 0).
- ## pasting that forms a keyword (un##signed) is classified afterwards.
- stringizing keeps the source spelling (__signed__, _Alignof).

gcc.dg inline-17.c had CHECK lines baked in from the bug: its
#define inline __attribute__((gnu_inline)) inline was ignored. func2 is now
inline_only, matching the test's scan-assembler-not "func2".

New fixture: tests/fixtures/keyword_named_macros.c (clang and gcc accept it).
