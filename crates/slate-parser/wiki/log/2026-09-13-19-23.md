# Target AST spec

_2026-09-13 19:23:16_

Rewrote wiki/concepts/ast-spec.md as the target AST design (user decisions): C-grammar-shaped syntactic AST; Declaration = shared DeclarationSpecifiers + Vec<InitDeclarator> everywhere (file scope, blocks, for-init, typedef as storage class, FieldDeclaration); tag definitions stored in TranslationUnit.tags and referenced by TagId from the specifier that wrote them; TypeSpecifier split from Declarator (no pre-applied types); FunctionDefinition with ParameterList Void/Empty/Prototype/IdentifierList; one spanned Expr; literals keep suffix/encoding and decoded contents; parser never evaluates (enumerators, designators, _Generic); Box<Stmt> bodies and Labeled containers; CommentGroup for consecutive comments; no Unreachable. sema.rs validates and returns only valid nodes; src/ir/sema does types. Migration table maps current gaps. New probe findings: typedef struct {..} T, *PT drops PT; local static struct duplicates the tag body per declarator; enum values evaluated to IntLit; for (int i = 0, j = 1;;) fails to parse; sema rejects struct definitions in parameter lists.
