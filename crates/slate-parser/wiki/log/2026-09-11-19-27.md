# Fix #include_next, has_feature-style predicates, and directive whitespace in pp.rs

_2026-09-11 19:27:23_

Closed slate-parser-wf8.1.14 (support #include_next) and corrected the misdiagnosis on slate-parser-wf8.1.15 (__has_include_next already worked; real blocker for bool.c is a deeper macro-visibility bug, filed as wf8.1.16). Fixes: (1) parse_include_directive now recognizes '#include_next' before falling through to '#include' matching, and resolve_include's new Next arm searches self.search.system starting after the directory that resolved the *current* file. (2) parse_has_include's <header> token loop now accepts Token::Keyword (e.g. 'float' lexes as a keyword, not an Ident, breaking __has_include_next(<float.h>)). (3) evaluate_expr's Call arm now treats __has_feature/__has_extension/__has_builtin/__has_attribute/__has_cpp_attribute/__building_module the same as __has_include (evaluate to 0) instead of erroring as 'not a constant expression'. (4) Added normalize_directive() in pp.rs and applied it everywhere a line's directive shape is inspected, since clang's own headers indent nested directives ('#  undef', '#  endif') which previously either errored as unsupported or silently miscounted #if/#endif nesting ('expected #endif'). Added 3 new regression fixtures: tests/fixtures/include-next.c (with a 2-header tests/fixtures/include-next-headers/{outer,inner} pair), tests/fixtures/has-feature-predicates.c, tests/fixtures/directive-whitespace.c. Swept tests/upstream/fixtures/{aligned_struct,bool,atomic_widths,c11,atoi_atol_prelude_dynamic}.c again under the real -isystem chain and filed the remaining real gaps as wf8.1.16 (header-guard macro visibility -- the big one, affects most real headers), wf8.1.17 (extern "C" { } blocks unsupported), and wf8.1.18 (string.h/stdlib.h chain, not yet root-caused). cargo test and cargo clippy --tests both clean.
