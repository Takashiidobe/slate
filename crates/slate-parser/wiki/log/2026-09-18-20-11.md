slate-parser-lh7.2.12 (final slice). ValueKind::StatementExpression(Box<Evaluation>): Lowerer::expr lowers the leading statements via Lowerer::statements (now pub(super)) with the enclosing function's return type (new Lowerer.return_type, set next to in_function), and the trailing expression statement (skipping trailing comments) as the value, or void. Invalid outside a function. effects() treats it as effectful, so &&/||/?: route it through branch() and keep it conditional. Hoister::value always eliminates it: for a non-void result it declares a synthetic temporary, lowers the statements (Hoister::statements now pub(super)) into a Block that ends in a write to the temporary, and returns a read of it; a void or discarded result keeps only the Block. The printer arm (statement_expression<T, statements=N>(value)) exists only for exhaustiveness. Lowerer::expr's '_ => advanced expression' catch-all is gone because the match is now exhaustive; ast-enum-touchpoints lists it. Fixture sema/ir_statement_expressions.c (gcc accepts it): value use, nesting, discarded, no trailing expression, under &&, struct result, return inside, and in a while condition and compound assignment.
