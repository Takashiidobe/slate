# Bound parser recursion depth

_2026-09-17 16:20:10_

Deeply nested sources used to abort the process with `fatal runtime error:
stack overflow` instead of producing a diagnostic (slate-parser-87x).
Reproduced on `int x = ((((...1...))));` at ~4500 parens in release and at
~500 in debug, on `#if ((((1))))`, on nested blocks, and on nested brace
initializers.

Two changes, because a depth cap alone could not be set both high enough
for valid input and low enough for the debug profile's fatter frames:

- `parser::NESTING_LIMIT` (1024) caps recursive-descent frames, tracked in
  a `Cell<u32>` on `parser::Parser` so the statement parser and
  `const_expr::Parser` share one counter. A `#if` expression has no
  `parser::Parser`, so `const_expr::Parser` falls back to its own cell.
  Guarded at `parse_cast`, `parse_unary`, `parse_initializer_value` and
  `parse_one_stmt` — between them every unbounded recursion cycle passes
  through one of these. Save/restore of the previous depth keeps the
  counter balanced across error and backtracking paths.
- `main` now runs the pipeline on a 256 MB stack thread. The AST holds
  `Rc`, so `thread::scope` is not an option; a plain `spawn` + `join`
  works because `miette::Report` is `Send`.

The limit counts frames, not brackets: a paren level costs two, a block
level one. 1024 leaves `tests/fixtures/deep_ast.c` (~520 frames) working
and is far above C's guaranteed minimums of 63 nested parens / 127 blocks.

Fixture `tests/fixtures/error/nesting-limit.c` covers all three paths;
depth comes from macro expansion so the rendered diagnostic stays short.

Filed slate-parser-da9: long flat expressions (1600 `+` terms take 54s)
are superlinear, likely `Span::cover` re-scanning from the expression
start per binary node.
