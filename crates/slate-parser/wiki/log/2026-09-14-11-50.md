# Preserve static/qualifiers on array declarators

_2026-09-14 11:50:59_

DeclaratorParser::parse_declarator's '[' handling (src/parser/declarator.rs)
skipped over static/const/volatile/restrict tokens inside array brackets
without recording them, so 'int a[static 10]' lost the bounds-hint 'static'
and 'int b[const]' lost its qualifier entirely — both silently degraded to
a plain unspecified/expression array.

Added 'qualifiers: Qualifiers' and 'is_static: bool' fields to
Declarator::Array (matching wiki/concepts/ast-spec.md, which already
documented them). The parser now accepts 'static' before or after the
qualifier-list (C11 6.7.6.2 permits either order, but only once), reusing
DeclaratorParser::take_qualifiers for the qualifier list.

CType::Array is unaffected — the static/qualifier info only matters on the
parameter's Declarator (Parameter.declarator), not the resolved type, so
apply_abstract_declarator's CType::Array construction just ignores the new
fields via '..'. Updated the other exhaustive Declarator::Array matches
(const_expr.rs, reachability.rs, tests/filecheck.rs's oracle comparison)
the same way.

Regenerated tests/fixtures/nonnull_static_array_param.c and
tests/fixtures/c99.c (their existing 'int x[static N]'/'restrict' params
now render the new fields). Added
tests/fixtures/array_param_static_qualifiers.c covering
static/const/'static restrict'/'\*' per slate-parser-ixa.2's acceptance
criteria.
