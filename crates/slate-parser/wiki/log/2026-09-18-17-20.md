# Reject K&R identifier-list definitions in C23

_2026-09-18 17:20:05_

slate-parser-47s.4: StandardFeatures::identifier_list_definitions (Rejected in c23/gnu23, Standard before). parse_declaration errors 'identifier lists in function definitions were removed in C23' when the declarator parser returns IdentifierList::Parsed under C23; c89-c17 still rewrite to a promoted Prototype unchanged. Gating at the parser.identifier_list = Accepted assignment was wrong: that state also marks the outermost function declarator and captures definition_bindings, so gating it made parameters stop shadowing typedefs in bodies (parser_declaration_lifetimes.c regressed). The default standard is C23, so the 11 fixtures containing K&R definitions (knr_*, 9 gcc-torture) gained '// SLATE-FILECHECK-STD DEFAULT c17'; their CHECK lines are unchanged. New error/knr_definition_c23.c. clang -std=c23 reports 'unknown type name' instead; ours is a clearer message at the same declaration. ast-spec.md updated.
