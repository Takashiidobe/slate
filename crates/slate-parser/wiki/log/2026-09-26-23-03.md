# Model memory-capable asm inputs as places

_2026-09-26 23:03:53_

Inputs whose constraint allows memory in any alternative (m, o, g, rm, Arm Q) now lower to AsmOperandKind::InPlace(place) when the operand is addressable, printed as place<..>(..) instead of a pre-asm read<..>. Outputs already carried places.
AsmConstraint::allows_memory / memory_only read the resolved classes from .13. Address-of's checks moved into Lowerer::addressable and are shared.
Checked against clang and gcc:
- memory-only non-lvalue and bit-field: both reject -> error.
- memory-only register variable: gcc rejects, clang spills -> error under gcc only.
- clang rejects bit-fields/lanes under any memory-capable constraint; gcc takes the register (or spills a lane for m). We follow gcc: unaddressable operands fall back to a value, which an input can't tell from a copy.
- =m tied to 0 is accepted by both; the existing InOut{place, input} covers it.
17 existing fixtures regenerated; every changed line is a memory-capable in operand going read<..> -> place<..>.
Emission notes (in(reg) &raw const + wrapping the reference site) added to slate-parser-25m.15.
