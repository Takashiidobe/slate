# Support mode(__unwind_word__)

_2026-09-29 15:41:08_

slate-parser-cxg.33: `__attribute__((mode(__unwind_word__)))`, used by the `_Unwind_Word` typedef in both gcc's and clang's unwind.h, failed with 'machine mode'. It now resolves like `word`/`pointer` to an integer of the target's pointer width, keeping the base type's signedness (u64/i64 on x86_64, matching gcc and clang). gcc on x32 would use 64 bits against a 32-bit pointer, but slate has no x32 target, so pointer width is exact for every supported target. Using it on a floating base is rejected as a mode/type mismatch, like the other integer modes.

Fixtures: gcc and clang mode_unwind_word.c; gcc.dg cleanup-5.c and cleanup-8..13.c migrated to suites/gcc-dg for both flavors.

Known permissive gap, not filed: gcc parses a mode argument that names a typedef in scope as an expression and rejects it (e.g. a typedef named unwind_word before mode(unwind_word)); slate still accepts it.
