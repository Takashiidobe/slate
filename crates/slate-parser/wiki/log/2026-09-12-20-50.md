# Builtin macros __LINE__/__FILE__/__COUNTER__/#line

_2026-09-12 20:50:45_

Implemented in src/pp/expand.rs (expand_builtin_macro, intercepted before
regular macro lookup in expand_macros) and src/pp/mod.rs (presumed_location,
LineOverride table, record_line_directive/record_line_marker).

Key decisions:
- __LINE__/__FILE__ use the *expansion* Loc (token.expansion), which
  expand_macros already threads through to invocation site for nested macro
  bodies -- so __LINE__ inside a function-like macro correctly reports the
  call site's line, matching clang.
- __COUNTER__ needs mutable state from expand_macros's &self (called
  recursively/from multiple entry points), so it's a Cell<i64> rather than
  requiring &mut self everywhere.
- #line's digit-sequence argument must be parsed as *decimal* even with a
  leading zero (unlike a normal integer-literal, which would read leading-zero
  as octal) and must strip C23 digit separators first (`#line 0'123` == 123,
  not the octal value 83). See gcc-dg/c23-digit-separators-1.c.
- __FILE__'s default (no #line override) value uses display_path()
  (repo-relative), matching the codebase's existing diagnostic convention --
  NOT the raw canonical absolute path. This matters because `#embed __FILE__`
  re-resolves that string as an include path relative to the includer's
  directory; resolve_include's Quoted arm gained a fallback that also tries
  the name directly as a cwd-relative path, which is what makes the
  self-referential `#embed __FILE__` pattern round-trip correctly
  (gcc-dg/cpp__embed-13.c).
- __DATE__/__TIME__ deliberately not implemented (see slate-parser-xqm) --
  no time crate, and they're inherently non-reproducible/non-goal here.

Test-fixture gotcha: the FileCheck harness copies each fixture into a
per-run temp file (pid+slot in the name) before parsing, so any fixture
whose main-file __FILE__ value is checked verbatim would be flakes. Fixed
by pinning the presumed filename with `#line 1 "name.c"` at the top of the
fixture (assert_compile_time_true.c, assert_runtime_true.c,
assert_runtime_false.c, and the new builtin-line-macros.c use this trick).

Regenerated golden FileCheck blocks for fixtures that previously pinned the
pre-fix (unexpanded-identifier) behavior: assert_compile_time_true.c,
assert_runtime_true.c, assert_runtime_false.c, gnu_counter.c,
gcc-dg/cpp__embed-13.c, gcc-dg/c23-digit-separators-1.c.

Verified builtin-line-macros.c's values against `clang -E -P` directly;
they match exactly. Verified no regressions via a parse-exit-code diff
across all 703 fixtures between HEAD and this branch (git-stash-and-diff),
which is more reliable than cargo nextest here since the FileCheck test
harness aborts each worker thread on its first panic, hiding later
fixtures in the same chunk.
