# Fixed-point types lower to IR

_2026-09-20 19:15:53_

Preserved signedness in ast::FixedPointType and rewrote fixed-point specifier parsing as a single lookahead-driven loop, so _Sat/signed/unsigned/short/long may appear in any order before _Fract/_Accum. Added ir::Type::FixedPoint{width, scale, signed, saturating} printing as fixed<i32, 15> / sat_fixed<..>, with N1169 widths resolved in sema/ctype/layout.rs (fract 8 bits at rank short doubling per rank, accum twice the fract width, unsigned spends the sign bit on a fractional bit) and storage taken from the storage integer. Added ArithSema::FixedPoint (overflow=saturate|ub, rounding=toward_zero, by_zero, amount_out_of_range) plus the int_to_fixed/fixed_to_int/float_to_fixed/fixed_to_float/fixed_convert conversions; a fixed_convert that keeps every representable value stays Exact. The common type of two fixed operands takes the wider kind and rank, signed or saturating if either is; clang instead maxes integral and fractional bits, which is recorded as a deliberate divergence in ir-spec.md. Fixtures: tests/fixtures/sema/ir_fixed_point.c and ir_fixed_point_invalid.c; fixed-point-types.c regenerated with signedness. Literals (0.5k) remain unlexed, tracked by slate-parser-lh7.2.17.8. Verified with cargo clippy, cargo fmt, cargo nextest run --release.
