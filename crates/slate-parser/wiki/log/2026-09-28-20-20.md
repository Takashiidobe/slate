# Checker runs the initializer current-object walk

_2026-09-28 20:20:39_

slate-parser-cc94.5.4. The checker now checks braced initializers in plain parse by running lowering's current-object walk over types; lowering constructs no Rejected in initializer.rs.

- TypeResolver::check_initializer / check_braced (walk_fill, walk_place, walk_item) mirror lowering's braced/fill/init_into/item_entry/designate/resume, including the item an outer designator already claimed and union fullness. They replace the old Walk/consumed length-only walk; inferred_array_length runs the same walk with check=false.
- Each element's conversion is recorded with its target (TypeResolver::element_targets). Lowering's convert_element consumes it and fails Internal if its own target is not compatible with the checker's (compatibility, not identity: the checker resolves VM types with provisional extents).
- Checker reports: unknown field designator, array designator out of range / negative, empty designated range, designator/aggregate mismatch, designator for a scalar, initializer for incomplete record, incompatible string literal element — at the declarator, conversion errors at the element. Compound literals too.
- Too-strict fixes (clang+gcc accept): int x = {} (aggregate<i32, zero_fill=true>()), excess scalar elements dropped ({1, 2}, {{1, 2}} on a struct member), T a[] = {} is array<T, 0> (closes cxg.42; pr79286 fixtures now lower).
- Bug fixed: v4 a[] = {v, v} inferred length 1 (the old walk brace-elided into a whole vector); now 2 like clang.

Fixtures: error/clang/initializer_rules.c (12 configs, each a clang error), clang/initializer_brace_rules.c. v74.1.18 noted: no longer rejected, but matrix_type is still modeled as its element type.
