# Flatten preprocessed input for parser boundary

_2026-09-15 16:49:26_

Implemented ixa.32 parser boundary migration.
Added ParserInput to flatten expanded PPNode code tokens once and anchor comments/pragmas between token positions.
Parser now enters through a single expanded token buffer and delimiter cursor for top-level declarations, functions, linkage blocks, and nested statement declarations.
Removed chunk-specific function/tag signature scanners, top-level item splitting, and same-line/multi-node reparsing paths.
Shared expression parsing now borrows original token slices; adjacent string literals decode per piece and preserve source spans.
Record and enum body parsing consume the unified token stream while retaining comments.
Added parser_token_stream fixture covering compact, split-line, and macro-expanded equivalent programs.
Added parser_token_annotations fixture covering comments/pragmas in records, enums, blocks, and statement expressions.
Updated AST spec with ParserInput boundary and regenerated FileCheck expectations.
Validation: cargo clippy --allow-dirty --fix, cargo fmt, cargo nextest run --no-fail-fast (pass).
No scope-stack changes; those remain in ixa.33.
