# Run static assertion validation once per translation unit

_2026-09-17 17:00:46_

`assertion::validate` ran twice: `TranslationUnit::analyze` collected every
`SemaError` from it, and `resolve_module` then ran the whole pass again,
kept only the first error and wrapped it in `ResolveError::StaticAssertion`.
The same source therefore produced one diagnostic or many depending on the
entry point, and the second run re-walked every declaration and function
body for a result the CLI had already computed.

`resolve_module` no longer validates: `main.rs` calls `analyze` before any
lowering, so a failing assertion is reported there, with every error rather
than just the first. The `ir` and `parse` CLI paths now print identical
diagnostics. `ResolveError::StaticAssertion` is gone with its only
construction site; a rustdoc line on `resolve_module` records that it
lowers an already analyzed unit.

Closes slate-parser-okr. Error fixtures only exercise `parse`, so the
`ir` path's all-errors reporting has no FileCheck coverage; the harness
would need an ir-mode error configuration for that.
