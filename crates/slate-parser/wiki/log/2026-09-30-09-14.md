# pp: evaluate clang's __has_declspec_attribute, __has_warning, __is_identifier (dyd.67)

_2026-09-30 09:14:06_

Under --flavor=clang, #if now evaluates the three clang-only query operators and #ifdef reports them defined, as clang does in every C mode.

- __has_declspec_attribute(x): attribute_support::declspec_registered, but only
  with microsoft_extensions. clang answers 0 for every declspec on Linux (and
  mingw) unless -fms-extensions; the windows-msvc target implies it.
- __has_warning("-Wx"): clang's warning groups.
- __is_identifier(x): 0 when clang reserves x as a keyword in the current mode.
  The table sorts keywords by mode: Always, Microsoft, C99 (restrict), C23
  (bool, nullptr, ...), Gnu (asm), GnuOrC99 (inline), GnuOrC23 (typeof).
  __builtin_va_arg etc. are keywords to clang, __FILE__ is not.
- __is_identifier's operand is taken unexpanded in expand_condition (clang only).

The tables are generated: tools/generate_clang_pp_tables.py writes
src/pp/has_checks/clang.rs by probing the installed clang (diagtool tree
groups through __has_warning; every libclang-cpp identifier through
__is_identifier in 12 standards x -fms-extensions). A keyword whose mode
pattern fits no category stops the generator.

Verified against clang 22 over gnu89/c89/c17/gnu17/c23, -fms-extensions and
the windows-msvc target. Fixtures: clang-query-operators.c (linux GNU/ISO/C23,
windows); has-operators-defined.c now lists the three as defined.

Corpus: curl preprocesses identically to clang in 359/359 TUs (was 105
slate-errors on curl.h's __has_declspec_attribute).
