# sizeof of declared objects in array bounds

_2026-09-19 09:40:20_

slate-parser-lh7.2.27. The IR lowerer's TypeResolver kept no object table, so an array bound written as sizeof/_Alignof of a variable (int arr[sizeof(g)];) failed with 'unknown or unsupported sizeof operand type'. Only the assertion pre-pass declared objects into its own resolver scope. The lowerer's per-binding type and access maps (bindings, access) moved from Lowerer into TypeResolver, next to a references map (identifier NodeId -> BindingId) built once from name resolution. assertion_operand_type now resolves an identifier through that map first, so block scoping and shadowing come from names.rs (a local char K[5] shadows enum K) and the resolver needs no scope push/pop of its own. Lowerer::reference uses the same map instead of a linear scan of names.references. The assertion pre-pass is unchanged: its resolver's maps stay empty and it falls back to scope lookup. Fixture: sema/ir_sizeof_object_bound.c (clang and gcc accept it). _Atomic objects were left out of the fixture because gcc's unpromoted layout disagrees (slate-parser-lh7.2.30).
