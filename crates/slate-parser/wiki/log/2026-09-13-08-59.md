# Replace IntegerValue::Arbitrary(String) with WideInt

_2026-09-13 08:59:21_

Found a second stringly-typed oversized-integer fallback besides the one fixed in
wxs.5.1: ast.rs's IntegerValue::Arbitrary(String), used only by const_expr.rs's
local integer_value(token) helper for GNU designated-initializer array ranges
([huge_literal ... end] = value, Designator::ArrayRange{start,end}) when the
bound doesn't fit i128.

Replaced with IntegerValue::Wide(WideInt), reusing parse_wide_integer_literal
(already generalized in the IntegerLiteral removal commit to work on any
oversized IntLit spelling, not just wb-suffixed ones). WideInt needed an Eq
derive (BigInt/u32/bool all implement Eq) since IntegerValue already derived Eq.

No fixture exercises this path currently (grep for "Arbitrary(" across
tests/fixtures found nothing), same as the ConstExpr case before it.

Also answered a design question about WideInt's derived PartialEq/Eq: it's
intentionally structural (value+width+signed all compared), not C's `==`
value-only semantics -- e.g. \_BitInt(7)==1 and \_BitInt(2)==1 are numerically
equal in C but are different AST literal nodes here. Runtime value-equality for
constant folding already goes through WideInt::compare(), not derived Eq.
