# Fold const-object reads for asm immediates

_2026-09-27 18:22:11_

slate-parser-25m.23. Alternative selection judged constness with integer_constant, which cannot read objects, so "i"(k) for static const int k = 2 was rejected although clang and gcc print $2.

- Entities records the initializer of every const, non-volatile object (any storage duration). Under gcc a const tentative definition records a zero-filled aggregate, since gcc reads it as $0 and clang rejects it.
- fold.rs threads an Env (flavor + optional object map) through evaluate/floating. With objects, a Read without atomic ordering walks the stored initializer: bindings, fields (bit-fields wrapped to their width), array decay/index, pointer offset, AddressOf, derefs of const pointers, aggregate ranges, zero fill and string code units. Out-of-range indices fail.
- asm.rs computes constness for lvalue candidates too ("g"(k) was never considered constant), scales symbol indices with the same fold (&arr[k] -> sym offset 8), and replaces a selected imm operand's value with its folded const<ty>(n), because a Rust const operand cannot read a C object.

Oracle (clang 22, gcc 16): clang folds everything above at -O0. gcc -O0 folds only direct reads and selects a register for "g"(k)/"ri"(k), but from -O1 it matches clang, so slate follows clang for both flavors (permissive). Both reject volatile, non-const, extern and non-constant-initialized objects. An out-of-bounds read of a const array folds to $0 under gcc and is rejected by clang; slate rejects it (UB, not modeled).

Fixtures: sema/ir_asm_const_objects.c and _gcc.c. No existing fixture changed. ir-spec.md documents the folded immediate.
