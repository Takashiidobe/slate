# Close the silent-fallback holes in type lowering

_2026-09-20 19:32:53_

Made sema/types.rs base() exhaustive over TypeSpecifier (the catch-all only hid non-va_list TargetBuiltin) and ctype/layout.rs numeric() exhaustive over CTypeKind (its _ => int fallback silently typed an unknown kind as int). Both now fail the build on a new variant instead of guessing. Threaded Result through emit_arithmetic_conversion and added a postcondition: if the (from, to) match did not produce a value of the requested type it returns Unsupported("arithmetic conversion") instead of handing back the operand at its source type. That closed a real miscompile — with the int-to-fixed arm deleted, _Accum f(int n){return n;} previously lowered to 'return read<i32>' from a function typed fixed<i32, 15>, silently; it now errors. The cascade made arithmetic_conversion, promote_operand, promote, promote_truth, float_class_int and quiet_compare_int fallible, all in already-Result-returning callers. The is_* predicates were left as matches! defaulting to false on purpose. type-family-touchpoints.md updated: three sites moved from the silent list to the caught list.
