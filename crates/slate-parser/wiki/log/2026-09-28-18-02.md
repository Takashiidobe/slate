# Expression typer core cross-checked against lowering

_2026-09-28 18:02:48_

Added sema/typer.rs: TypeResolver::typed types an expression without lowering it and memoizes Typed { c, lvalue, bits } per NodeId in expression_types. Unimplemented means no answer.

Coverage: literals, identifiers (objects and constants), string and compound literals, casts, unary operators, inc/dec, assignment, comma, index, member (with bit-field width), binary operators including pointer arithmetic and comparisons, _Generic, and ?: over arithmetic or compatible non-pointer operands. Calls, builtins, statement expressions, pointer ?: and sizeof are not typed yet (cc94.4.2).

Lowerer::expr and Lowerer::place compare every typer answer with the lowered type and return Internal on disagreement. Rules shared with lowering were factored out rather than copied: binary_types (from binary_operand), arithmetic_type (from arithmetic_operands), literal_type (from literal).

speculative_type (typeof, __auto_type, classify builtins), unevaluated (_Generic controlling) and unevaluated_type (sizeof/alignof) ask the typer first. A sizeof operand it answers is no longer lowered unless its type is a VLA. Speculative lowering remains only as the fallback (deleted in cc94.4.3).

Bugs the cross-check found:
- inferred_array_length counted a braced string initializer ({"foo"}) as one element; the checker rejected _Static_assert(sizeof((char []){"foo"}) == 4). Now the string's length.
- A cast to a qualified type kept the qualifiers on the union-cast and void paths; the result is now unqualified.

Across the whole gate the typer and lowering agree on every answered expression; gcc-torture has ~165k answered vs ~13k unanswered nodes, mostly calls.

New fixture clang/linux/x86_64/expression_typer.c (clang and gcc accept it). Wiki: entity-model.md and ir-spec.md describe the typer-first path.
