# IR FileCheck expectations match @typeN and %N by named variables

_2026-09-29 09:02:48_

tools/update_filecheck.py gains loosen_ir_ids. IR type ids and bindings are numbered
over the whole module, system headers included, so one extra header declaration
restamped every later id (2c90f918 rewrote 14 lines of fputs_stderr_plain.c for a
single moved typedef).

Each @typeN / %N now becomes a FileCheck string variable named after the declared
name: TYPE__IO_FILE, VALUE_stderr. FileCheck names only allow [A-Za-z0-9_], so _ is
the separator even though it runs into leading underscores; the kind stays a prefix
to match FILE0/TAG0/NODE0. Repeated names count up (VALUE_x_2), unnamed entities are
ordinals (TYPE0, VALUE0), and a .strN global reuses its binding's variable. Quoted
strings and asm template: lines are untouched (their %N are operand indices).

Still strict: every type and binding has one definition line checked with -NEXT, so
a use must name the same entity; a corrupted _markers pointer or call callee fails.
String variables can be reused on their defining line, unlike numeric ones.

Regenerated all fixtures: every id-only change verified by normalizing both sides
(269653 lines, 0 mismatches). Ten error fixtures also had stale expectations
missing newer, partly redundant diagnostics; regenerated and filed as a bead.
Documented in wiki/concepts/fixture-layout.md.
