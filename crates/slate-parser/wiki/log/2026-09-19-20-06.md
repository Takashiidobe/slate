# C type layer acceptance sweep

_2026-09-19 20:06:02_

Closed epic slate-parser-9ve.

Audited every ir::Type comparison in src/sema and documented the survivors
in wiki/concepts/c-type-layer.md, with the grep command to re-run. Each one
asks a layout or representation question rather than a type-identity one,
except three residues: same_tag_content's structural pre-filter for C23 tag
redefinition (slate-parser-ntb), type_of.rs::with_length, and initializer.rs
brace elision, newly filed as slate-parser-pd7 because C23 6.7.11 makes it a
compatibility question that diverges for a tag defined twice in one TU.

Fixed a real bug the audit exposed: C23 compatible tag redefinition compared
IR field types, so struct S { char x; } against { signed char x; }, and long
against long long, were silently accepted where clang rejects. same_field_types
now answers through CTypes::compatible, over a copy of the old fields captured
before record_fields is overwritten.

Also replaced the conditional operator's last IR-type gate with
compatible_unqualified on C types (Unsupported -> Invalid) and deleted
compatible_c, a second 6.2.7 implementation, redirecting _Generic selection
and pointer subtraction to ctypes.compatible.

Regenerating all 2671 fixtures produced zero diff, so nothing outside the
deliberately regenerated fixtures of phases 3-5 changed.
