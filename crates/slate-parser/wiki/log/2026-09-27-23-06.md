# Report up to 20 sema errors per run

_2026-09-27 23:06:54_

Sema used to stop at the first IR-stage error. names::resolve and resolve_module now continue item by item over the top-level declarations and report up to 20 errors (clang's default -ferror-limit) plus 'too many errors emitted, stopping now'. Any error still means no IR. The limit is in with_sources, shared with analyze; only errors count. -ferror-limit is deliberately not a flag: it changes no code's meaning.

- names::ResolveError carries a Loc; names errors now point at the name, not nowhere. Lowering errors fall back to the whole top-level declaration.
- Unresolved references are recorded and visiting continues, so later declarators in the same declaration still bind (no cascade on b in int a = undeclared, b;). Other names errors end the item and reset to file scope.
- Poisoning: bindings declared by a failed item are poisoned; a later item's lowering error is dropped when it references one. Checked before the item's own bindings are poisoned so recursion still reports. Names errors are never dropped.
- resolve_module now returns SemaErrors; the per-declaration match moved to lower_item, post-passes to Lowerer::finish_module and run only on an error-free unit.
- 88 IR-error fixtures regenerated: first error unchanged in all 170 prefixes; 5 now report more errors, all checked against clang (va-opt.c also flags alpha/beta in args of the undeclared STRINGIFY call, which clang skips).

New fixtures: sema_reports_all_errors.c, sema_poisoned_declaration.c, sema_error_limit.c. Wiki: diagnostic-severity.md 'Reporting more than the first error'. Bead: slate-parser-zs34.
