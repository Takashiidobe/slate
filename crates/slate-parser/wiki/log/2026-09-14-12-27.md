# Represent _Alignas separately from __attribute__((aligned))

_2026-09-14 12:27:59_

attributes.rs parsed _Alignas/alignas into Attribute::Aligned(Expr), same node as GNU __attribute__((aligned(N))) — but _Alignas has different C11 rules (can't reduce alignment, disallowed on typedefs/bit-fields) and, per C11 6.7.5, takes either a type-name or a constant-expression, not just an expression. Parsing _Alignas(double) as an expression made 'semantic analysis failed: layout attribute requires an integer constant expression' fire on perfectly valid code.

Added ExprKind-adjacent AlignAsOperand { Type{ty, declarator} | Expr(Expr) } and Attribute::AlignAs(AlignAsOperand), keeping Attribute::Aligned for the GNU attribute form so the two stay distinguishable end to end (matters for [[architecture_single_configuration]]'s IR lowering goal, since _Alignas and aligned() get different Rust-side rules).

const_expr::Parser::try_parse_full_type_name (src/const_expr.rs) is a new pub(crate) associated fn: gates on starts_type_name(first_token) — same helper sizeof/_Alignof use to avoid the __real__/__alignof__(ident) misparse-as-bogus-type-name bug class — then runs the existing private try_parse_type_name and requires it consume every token, so partial parses fall through to the expression path instead of silently truncating. parse_attribute_groups (src/parser/attributes.rs) now takes typedef_names + statements so _Alignas's argument tokens can be tried against it before falling back to parse_attribute_expression; both call sites (Parser::parse_attribute_groups method, and the two DeclaratorParser call sites in declarator.rs) were threaded through.

sema.rs's check_attributes integer-constant-expression check now also covers Attribute::AlignAs(AlignAsOperand::Expr(_)) (not AlignAsOperand::Type, which has no expression to validate).

Regenerated 6 pre-existing fixtures that had _Alignas(N) baked in as the old Aligned(...) shape (builtin_assume_aligned.c, c23_language.c, c11.c, global_array_pointer_decay.c, over_aligned_local.c, gcc/gcc-torture/pr68532.c). Added tests/fixtures/alignas_vs_aligned.c with the exact bug repro (_Alignas(double), _Alignas(16), and __attribute__((aligned(16))) on sibling fields), confirming all three render as distinct nodes and no semantic error fires.
