# Fix over-broad block-scoped tag guard and lower enum values

_2026-09-17 20:32:07_

slate-parser-6id. src/sema/module.rs::declaration rejected every non-global declaration whose type specifier was TypeSpecifier::Tag(\_), so 'struct S s;', 'union U u;', 'enum E e;' and even 'struct S \*q;' all failed IR lowering with 'block scoped typedef or tag declaration' despite the tag being declared at file scope. The guard now matches only TagSpecifier::Definition, and the message says 'tag definition'.

Keeping that half of the guard is load-bearing, which I confirmed by removing it: two functions each defining 'struct Local' with different fields both resolve to @type0, so the type table emits one record and the second function's field accesses type against the first one's layout. Anonymous local tags are safe since they cannot collide by name. Filed as slate-parser-rsm; it needs the Lowerer's TypeResolver to scope tag identity per block.

The bead's own repro used an enum, which then failed for an unrelated reason: enum-typed values were unlowered everywhere, at file scope too. Only the switch discriminant called enum_integer. convert() gained both crossings (enum source unwraps via enum_to_int before the existing chain; enum target converts to the underlying and wraps in a new ConversionKind::IntToEnum), condition() unwraps an enum operand, and the Binary and Unary arms apply enum_integer to their operands. This matches the shape ir-spec.md already prescribed for switch rather than inventing a second model: enumerators stay typed as the underlying integer in the type table, the enum type appears only on storage, and the two conversions carry every crossing.

enum_underlying replaced the inline kind() match in enum_integer and follows Alias chains, so a typedef to an enum now lowers like the enum; switch on an alias-typed enum was previously missed too.
