# GCC compiler headers assembled from the 16.2.0 tarball

_2026-09-28 12:55:29_

slate-sysroots' gcc installer used to extract only gcc/ginclude from the 16.1.0 tarball, so --flavor=gcc failed on <limits.h> (glibc's limits.h does #include_next <limits.h> and GCC's generated limits.h was missing) and on <unwind.h>.

The tarball already contains everything; GCC's stmp-int-hdrs step (gcc/Makefile.in) only concatenates and renames. The installer now uses an explicit output table that mirrors it for a use_gcc_stdint=wrap target:
- limits.h = limitx.h + glimits.h + limity.h (LIMITS_H_TEST branch)
- syslimits.h = gsyslimits.h
- stdint.h = ginclude/stdint-wrap.h; stdint-gcc.h copied
- unwind.h = libgcc/unwind-generic.h
- the ginclude files listed in USER_H

Since GCC 15, limits.h/syslimits.h live in include/, not include-fixed/.

It no longer copies all of ginclude: tgmath.h (which shadowed glibc's), stdint-wrap.h and unwind-arm-common.h aren't installed on x86_64 Linux.

Pinned 16.2.0: the oracle is Arch's 16.2.1 20260810 snapshot, and there's no 16.2.1 tarball. All 17 installed headers are byte-identical to $(gcc -print-file-name=include). Target extra_headers (x86 intrinsics, arm_neon.h, ARM EABI unwind.h) need a per-triple layout: slate-parser-cxg.38.
