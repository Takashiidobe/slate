# g6b: seed clang's predefined macros, fix specifier order and macro visibility bugs

_2026-09-11 20:52:48_

Implemented slate-parser-g6b (seed compiler builtin type macros) by embedding a full snapshot of `clang -dM -E -x c /dev/null` (clang 22.1.8, x86_64-pc-linux-gnu) as src/predefines/clang_x86_64_linux_gnu.h, parsed via the normal #define machinery at Preprocessor::new time. Per user direction, seeded the whole predefine set now rather than a hand-picked subset, deferring per-target profiles to when cross-platform support matters.

Seeding the predefines file as file 0 broke an implicit assumption in parser.rs::parse_nodes that the main/root file is always FileId(0) (used for reachability filtering) -- fixed by tracking Preprocessor::main_file explicitly and threading it through instead of hardcoding FileId(0). All 55 existing fixtures needed FileId renumbering (0->1) after this, regenerated via update_filecheck.py; diffs are purely the id shift.

Getting the seeded macros to actually parse against real headers (libc-shim's stdlib.h under clang's resource headers) surfaced three more pre-existing bugs, found via bisection:

1. parser.rs parse_base_type: 'long unsigned int' (long before unsigned) wasn't handled -- only 'unsigned long' order worked. Clang's __SIZE_TYPE__/__UINTPTR_TYPE__ expand to exactly this ordering. Fixed by accepting an optional trailing unsigned/signed after long/short, matching what clang's predefines actually emit.

2. parser.rs parse_top_level_item: the declaration-vs-function-definition heuristic checked only 'contains LBrace' and 'contains Equal' anywhere in the line, so any single-line function body containing an assignment (e.g. 'void f(void) { x = 1; }') was misparsed as a brace-initializer declaration. Fixed by comparing the first LBrace's position against the first Equal's position instead of presence alone. This is a general, long-standing bug, not specific to the predefines work -- reproduces on plain user code with no macros involved.

3. pp.rs expand_macros: macro lookup required the macro's recorded Condition to be *exactly equal* to the current active condition, so a macro defined completely unconditionally (Condition::Constant(1), including every predefine) became invisible for expansion as soon as usage was nested inside any #ifndef/#if guard (active becomes e.g. Not(Defined(GUARD)), no longer literally Constant(1)). Since virtually all real headers wrap their content in an include guard, this made the predefines useless in practice. Fixed narrowly: a macro's condition also matches if it is statically true, without touching the exact-match path relied on for divergent macro definitions.

4. parser.rs parse_top_level_item / parse_function: plain (bodyless) declarations whose parameter list wraps across physical lines (e.g. 'int strfromd(char *s, ...,\n double fp);') were never joined across PPNodes -- only function *definitions* got that treatment from wf8.1.18. Generalized signature_node_span to also stop at a top-level Semi (not just LBrace), and added paren_depth-gated joining to the top-level declaration/function dispatch path so both cases share the same node-span logic.

With all four fixes, the full original wf8.1.18 repro (stdio.h + stdlib.h + string.h prelude, atoi_atol_prelude_dynamic.c) now parses end-to-end under the real libc-shim + clang resource-header include path.

Added fixtures: tests/fixtures/predefined-type-macros.c (builtin macro used at top level and inside a header guard), tests/fixtures/multiline-declaration.c (wrapped bodyless prototype). Full cargo test + clippy pass; all fixture FileId renumbering verified as the only diff from the file-0 shift.
