# ParseContext replaces Option<&Parser> in expression, declarator and attribute parsing

_2026-09-28 16:58:17_

slate-parser-iwsx.1. const_expr::Parser, DeclaratorParser, the attribute helpers, span_tokens and bare_identifier_names took context: Option<&Parser>. None meant a standalone parse (#if evaluation, __BIGGEST_ALIGNMENT__ evaluation, and type names nested under them) with no dialect at all: const_expr fell back to StandardFeatures::default, declarator feature gates (C23 auto inference, implicit int) read as off, and gnu/declspec/c23 attribute registration accepted every name.

New src/parser/context.rs: ParseContext<'a> is a Copy enum, Parser(&Parser) or Standalone(&Dialect). dialect()/features() are always available; parser() is the Option for what genuinely needs a parser (typedef lookup, tag definitions, scopes, statement expressions, token-slice span index, shared nesting counter). Parser::context() builds the Parser case.

const_expr::Parser drops its features field and reads context.features(). parse/evaluate take &Dialect; evaluate_with_defined builds Standalone(dialect). resolve_biggest_alignment takes &Dialect. Attribute registration always checks the dialect's flavor and target. asm_string (a free function that always passed None) uses Span::cover directly.

impl Default for StandardFeatures is removed: no parse runs without a Dialect now.

Validation: 7268/7268 tests, no fixture changes.
