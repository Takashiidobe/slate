# Thread macro-expansion origin through Span (slate-parser-lh7.1.9)

_2026-09-14 13:16:06_

Added Span<T>.macro_origin: Option<Rc<MacroOrigin>>, where MacroOrigin { name, definition: Provenance, parent: Option<Rc<MacroOrigin>> }. Provenance.header already carried the outermost-header FileId (from prior work), so the only missing piece was tagging expanded tokens with which macro produced them; pp/expand.rs::expand_macros now sets macro_origin on every replacement token in both the object-like and function-like branches, using the MacroEntry.provenance already stored per macro definition. Span::cover (used everywhere an AST node is built by covering its constituent tokens/sub-spans) propagates macro_origin only when every covered span agrees, so it reaches ExprKind/Stmt nodes for free without const_expr.rs or parser/\*.rs changes. Chain semantics: name/definition are the OUTERMOST macro invoked at the use site (e.g. INT_MAX), and parent walks through further nested macros its body expanded through (e.g. **INT_MAX**), via MacroOrigin::append which walks to the end of an existing chain and appends the next link -- this keeps the user-visible macro name primary, matching the Slate use case of pattern-matching macro name + header, with the internal expansion chain available for debugging. Verified end-to-end with a throwaway examples/ binary (not committed) parsing '#include <limits.h>; int m = INT_MAX; long n = LONG_MAX;' against the libc-shim headers: INT_MAX -> macro=INT_MAX (no parent, since the shim defines it as a literal); LONG_MAX -> macro=LONG_MAX, parent macro=**LONG_MAX** (the shim defines LONG_MAX via **LONG_MAX**). No renderer/dump mode or FileCheck fixture was added, matching the precedent set by slate-parser-ixa.8 (the user considers the print/test layer out of scope unless separately requested).
