# Lowering reads types and choices from the typer's facts; cross-check removed (slate-parser-ygrj.3)

_2026-09-30 12:20:41_

Step 3 of slate-parser-ygrj.

- Lowerer::expr/place take the node's C type from the facts (result, lvalue_result), and the typer/lowering cross-check is gone. TypeDisagreement and ExprKind::name went with it. A temporary FACTGAP probe first showed the typer covers every expression lowering visits in the suite.
- Arms that derived a result type read it instead: char/string/nullptr/label literals, &, __real/__imag (value and place), compound literals, identifiers, subscript and vector lanes, swizzles, __builtin_complex/addressof/classify_type/constant_p, types_compatible. binary() emits at computation_types, re-typing when the entry has unbound extents.
- Choices go in TypeResolver::choices: Operand (_Generic association, __builtin_choose_expr operand), Lanes (swizzle), Member (cast to union, from the checker's cast()). derived_signatures holds builtin signatures derived from an argument.
- Builtin argument conversions are recorded steps under Slot::Argument(i): the float builtins, __builtin_fpclassify arms, the atomic fetch operand, __atomic_is_lock_free size/pointer, and variadic/unprototyped call arguments (call_type; the checker's vararg conversion is removed). record_casts records a chain of casts and derives the context from the reason. Slot::Extent covers VLA sizes, and Slot::Parameter plus promoted_parameters cover K&R parameters. Lowerer::convert and conversion_context are removed.
- CastKind::EnumToInt(EnumTail) carries the underlying-to-target hop, so emit_cast doesn't classify again.
- Atomic internals (bool object as uchar, pointer bitwise via size_t, min/max signedness) name their CastKind directly.
- Function definitions merge with earlier declarations before the body. This fixes expat xmlparse.c:6302: the new fixture clang/linux/x86_64/function_definition_typedef_type.c has DeclRefExpr 'F':'int (int)' decaying to ptr<fn(i32) -> i32>, which matches clang.
- VM types: the typer types them again under lowering's bound extents; there is no separate slot structure.
- Kept in lowering on purpose: enum_operand before conditions, read's lvalue_conversion, and value decoding for literals and type queries. Follow-ups: ygrj.6 (declaration entity merge still runs in both passes), ygrj.7 (constant folder, comparison warnings).
- No fixture IR changed. Suite 7497/7497. The corpus was not re-run.
