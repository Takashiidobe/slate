# Emulate clang -fms-extensions / -fms-compatibility

_2026-09-29 20:58:09_

Part of slate-parser-v74.1.9 (prerequisite for predeclared size_t). clang flavor now takes -f[no-]ms-extensions and -f[no-]ms-compatibility; gcc and msvc reject them. Resolution (CompilerOptions::microsoft -> StandardFeatures::{microsoft_extensions, microsoft_compatibility}) mirrors clang's driver: both default on for *-windows-msvc, compatibility implies extensions, -fno-ms-extensions drops only default compatibility.
Predefines: snapshots hold the target default, so pp adds a <microsoft modes> delta (GNU-compat macros, __STDC__, __GCC_ATOMIC_* copied from __CLANG_ATOMIC_*, _MSC_EXTENSIONS/_M_IX86_FP by effective extensions, the _MSC_VER group by the requested extensions flag). Verified with clang -dM for 6 flag combinations on x86_64/i686 Windows and Linux.
MS __asm {} blocks now follow effective extensions (was: windows-msvc target), matching clang on Linux -fms-extensions and Windows -fno-ms-extensions. Inline visibility and object requests stay target-ABI based, as in clang.
Oracle facts: wiki/concepts/compiler-flags.md#ms-modes. Fixtures: clang/windows/x86_64/ms_modes.c, clang/linux/i686/ms_modes.c, clang/linux/x86_64/ms_asm_fms_extensions.c, error/gcc ms_extensions_flag.c, error/msvc ms_compatibility_flag.c.
