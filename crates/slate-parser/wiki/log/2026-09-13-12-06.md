# wf8.5.3/wf8.5.4: fix old-style field designators in compound literals + __volatile alias

_2026-09-13 12:06:54_

Fixed the last two triaged wf8.5 failures.

wf8.5.4 (__volatile): src/lexer.rs's keyword match only mapped the bare
"volatile" spelling to Keyword::Volatile; added "__volatile" and
"__volatile__" alongside it, matching the existing __const/__const__
pattern.

wf8.5.3 (old-style field designators in compound literals): const_expr.rs's
parse_initializer_list (used for compound-literal initializers) only
recognized [index]= and .field= designators, not the GNU old-style
`field: value` form that parser.rs's top-level parse_initializer already
supported. Ported the same ident-then-colon lookahead branch. Also had to
relax the post-designator `=` from a hard expect to an optional consume
(matching parser.rs's `self.matches`), since the colon-style designator has
no following `=`.

Ported compndlit-1.c and ffs-1.c to tests/fixtures/gcc-torture/, completing
the wf8.5 250-file batch (all 250 now pass FileCheck).
