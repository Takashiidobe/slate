# Lower numeric mul, div, and rem to IR

_2026-09-14 20:09:11_

sema::numeric now lowers same-concrete-type `*`, `/`, `%` alongside `+`/`-`.

- IR: replaced per-operator `ValueKind::Add`/`Sub` with one `ValueKind::Arith { op: ArithOp, .. }`; printed output unchanged (`add<..>`, `sub<..>`, `mul<..>`, `div<..>`, `rem<..>`).
- Signed div/rem are always `overflow=undefined`. Verified clang 22 emits plain sdiv/srem under both -fwrapv and -ftrapv (mul gets smul.with.overflow + ubsantrap under -ftrapv); GCC documents wrapv/trapv only for add/sub/mul. Division by zero is intrinsic UB, not printed.
- Float `%` is a new `ResolveError::InvalidOperands` (C requires integer operands).
- `ResolveError::Conversion` operator is now the `&'static str` from `BinaryOp`.
- Fixtures: mul/div/rem in sema/numeric_seed.c; flags_wrap.c and flags_trap.c show mul following the flag and div/rem staying undefined; unsupported.c gets FLOAT_REM and OPERATOR now uses `<`.
- wiki: ir-spec.md numeric seed and compiler-flags.md updated.
