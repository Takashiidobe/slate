# Replace macro-state include-cycle detection with a 200-deep include limit

_2026-09-28 07:17:49_

slate-parser-fmzz. Preprocessing windows.h took 3.1s vs clang -E 0.11s.

Cause: every #include called Preprocessor::macro_state(), which Debug-
formatted every macro definition (tokens and spans) into a String and
sorted them, so re-entering an open file with an identical macro table
could be reported as an include cycle. O(includes x macros): ~60% of the
whole run on windows.h.

Fix: dropped cycle detection (open_macro_states, macro_state,
include_guards, include_guard recognizer) for a nesting limit of 200,
which is what clang ('#include nested too deeply') and gcc ('nested depth
200 exceeds maximum') do. Guarded self-includes now re-enter and the
#ifndef skips the body; gcc-torture's recursive self-include idiom works
as before; a true cycle stops at depth 200 without stack overflow.
PPErrorKind::IncludeCycle -> IncludeTooDeep; error/include-cycle.c
regenerated.

Result: windows_h fixture 3.3s -> 0.8s (clang 0.15s). Full nextest
11.5s -> 6.2s. Remaining profile is flat: macro expansion ~29%, parse
~17%, lexing ~8.5%, SipHash ~7% (follow-up bead). rescan's wants_more
path never fires on windows.h, so its rest+tail clone is not a factor.
