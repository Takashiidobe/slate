# Binding-level qualifiers in IR declarations

_2026-09-19 20:54:48_

Phase 3 of slate-parser-8lv. Closes lh7.2.28.

ir::Variable and ir::Parameter gained an Access (volatile + atomic). It
prints as a prefix on the type, exactly as a record field's already did:

  global %1 counter: atomic i32 [storage=static] [linkage=external];
  let %9 flag: volatile i32 [storage=automatic];
  fn %7 @parameters(%13 a: atomic i32, %15 c: i32 [const]) -> void;

Before this, const and restrict were on the declaration but volatile and
_Atomic were not, so an object the translation unit never touched carried
neither fact. Slate needs it to choose the Rust type, which is a property of
the object rather than of one access.

All four bits now come from the one qualifiers value the site already
computes, and declare_global re-derives them from the merged composite so a
redeclaration cannot leave them stale.

One thing the regeneration caught: I first read the access from the resolved
type, which is wrong for an array parameter, because resolve_parameter does
not adjust and the bracket qualifiers of 'int a[restrict volatile 4]' belong
to the adjusted pointer. Deriving from qualifiers, as const and restrict
already did, makes it 'volatile ptr<i32> [restrict]'.

Fixture churn is confined to the new prefix: every added expectation line
carries one, none changed otherwise.
