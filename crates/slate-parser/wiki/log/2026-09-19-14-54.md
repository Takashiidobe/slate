# Accept pointer-sign mismatches in implicit conversions

_2026-09-19 14:54:15_

slate-parser-j4b. `Lowerer::convert` (sema/expression.rs) rejected implicit pointer conversions whose pointees were integers differing only in signedness, e.g. `const char *p = u8"a"` under C23 (u8 elements are unsigned char), `char *q = unsigned_buf`, `return int_ptr` from an `unsigned *` function. Clang 22 accepts all of these with -Wpointer-sign.

Decision: accept silently as `pointer_cast`. The IR already records the implicit cast and its reason, which is what Slate needs. Dropping pointee qualifiers was already accepted silently the same way. No -Wpointer-sign warning is emitted: warnings only come from the AST-level `analyze` pass, and `resolve_module` has no diagnostics channel. Filed that as slate-parser-x5r.

`differ_only_in_sign` compares only the immediate pointee (same width and bit_precise, different signed). `unsigned ** -> int **` and `unsigned * -> long *` stay errors; both are incompatible-pointer-types errors in clang 22. Passing arguments was already lenient.

Fixture sema/ir_pointer_sign.c; ir-spec pointer table updated.
