# Parse MSVC __asm into StmtKind::MsAsm

_2026-09-27 18:45:24_

slate-parser-25m.6.1. New src/parser/ms_asm.rs and StmtKind::MsAsm(MsAsm { instructions }).

- Gating: MSVC flavor x86 only (x64 errors like C4235); Clang flavor on x86 *-windows-msvc.
  __asm/_asm only; clang's asm { is not modeled.
- Parser::mark_ms_asm_lines rewrites the token stream in parse_input before brace matching:
  drops ; comments inside MS asm (a } in a comment no longer closes the function body) and
  inserts Token::Newline at line ends. ParserInput::replace_tokens remaps annotation positions.
- Merge rules verified with clang: same-line __asm continues; a next line continues only if it
  starts with __asm not followed by {; a braced block ends at its }; __asm then { on the next
  line is braced. Instruction counts match clang on todo/msvc-asm-example.c (119/119).
- Operands: MASM expression parser (ptr sizes, OFFSET/TYPE/LENGTH/SIZE/SHORT, segment
  overrides, [..], x[..] byte index, .field, st(n), + - * /). Numbers fold MASM h/b/y/o/q/d/t
  suffixes and C spellings; MSVC and clang both read 010 as octal 8 and accept 1u.
- Registers via x86::decode_register, case-insensitive, excluding gcc pseudo names
  (argp, flags, fpsr, dirflag, frame); segment registers are MsAsmSegment.
- Lowering returns ResolveError::Unsupported until 25m.6.3.

Fixtures (error only, per user): error/ms-asm-*.c, and
sema/i686-pc-windows-msvc/ms_asm_parse_{msvc,clang}.c, which reach the lowering error, so any
parse regression changes them. windows.h now parses on i686 in both flavors.
