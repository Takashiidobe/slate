# Lower ext_vector swizzles, shufflevector and convertvector

_2026-09-20 10:04:03_

lh7.2.17.7 and dyd.25, the rest of the vector extension surface.

**Swizzles.** `swizzle_lanes` maps a component name to lane indices:
`x/y/z/w`, `r/g/b/a`, `sN` in hex (either case), and
`lo`/`hi`/`even`/`odd`, where the half is the lane count rounded up to a
power of two — so a 3-lane `.hi` names one lane that does not exist.
Clang's own behaviour, checked against `-ast-dump`. What comes out
depends on the selection:

- one component in range -> the `lane(..)` place from dyd.24
- several distinct components in range -> `PlaceKind::Swizzle`, printed
  `swizzle<lanes=[2, 3]>(place)`, so `v.zw = w` stays a write
- repeated (`v.xx`) or out of range -> not assignable, so a one-operand
  `shuffle<..>` value

`Lowerer::member` now mirrors `subscript`: lower the base once, return a
place or a value, which also gets `(a + b).lo` and `f().even` for free.

Clang allows these only on `ext_vector_type`. `Type::Vector` does not
record which spelling declared it, so we accept them on `vector_size`
vectors too — consistent with [[feature-availability-not-target-gated]].

**shufflevector.** `ValueKind::Shuffle { left, right, mask }`. The
constant form indexes the concatenation of both operands, takes any
number of indices (so it narrows or widens), and prints `-1` as `undef`.
The two-argument form takes a runtime integer mask vector and prints
`mask=dynamic(..)`, reusing the spelling already used for atomic orders.

**convertvector.** Its second operand is a type, so it needed an AST
node: `ExprKind::ConvertVector { ty, value }`, parsed like
`__builtin_va_arg`. Same shape as `Cast`/`BitCast`/`VaArg`, so it joined
their or-patterns in `visit.rs`, `reachability.rs`, `sema/names.rs` and
`sema/assertion.rs` without a new arm anywhere;
[[ast-enum-touchpoints]] now records that shortcut.

Lowering deliberately does not restate the conversion policy:
`Context::elementwise_conversion` runs `emit_arithmetic_conversion` over
the *element* types and re-types the resulting chain onto the vector
operand. The scalar path is the only place that decides exactness,
rounding and `fits`, and an int->int conversion that needs a resize plus
a reinterpret keeps both steps.

Corpus sweep: 2378/2674 -> 2379/2674, no regressions. Only
`vector_extension_ops.c` needed any of this; the coverage is in
`tests/fixtures/sema/ir_vector.c`.
