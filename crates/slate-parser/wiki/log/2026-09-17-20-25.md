# Resolve _Generic selections during semantic lowering

_2026-09-17 20:25:35_

slate-parser-5i0.16. _Generic already folded in the constant-expression path (slate-parser-byw) but IR lowering rejected it as 'advanced expression'. Lowerer::expr and Lowerer::place gained Generic arms that select an association and lower only the selected expression, so the selection is gone before the IR exists and the unselected branches produce no IR at all. Covering place() as well as expr() is what makes _Generic(x, int: x, default: y) = 5 and &_Generic(...) work, since C makes the result an lvalue when the selected expression is one.

The association-matching half moved to TypeResolver::select_association, shared by the constant path and the Lowerer; each caller supplies the controlling type from whatever typer it has (assertion_operand_type vs. a real lowering).

Fixed a bug shipped with slate-parser-byw: the controlling operand must be lvalue-converted before matching, so arrays and functions decay to pointers and top-level qualifiers drop. Without it _Generic(arr, int *: 1, default: 0) wrongly took default. Verified against clang, which warns -Wunreachable-code-generic-assoc on an array-typed association precisely because the controlling type can never be one. The conversion now lives inside select_association so neither caller can skip it.

Typing the controlling operand in the Lowerer means lowering it, which allocates binding IDs and can push a .str global for a string literal. Since the operand is unevaluated, Lowerer::unevaluated snapshots next_id and globals.len() and restores both, so _Generic("abc", char *: 1, default: 0) emits no global and no ID is skipped.

Unrelated pre-existing bug found while testing enum controlling expressions and confirmed on HEAD: a local of a file-scope enum type fails IR lowering with 'block scoped typedef or tag declaration'. Filed as slate-parser-6id.
