# GCC flavor accepts __builtin_ prefix on library builtins

_2026-09-26 11:08:46_

Closes slate-parser-dyd.23. builtins::clang_builtin now takes the CompilerFlavor. When the name isn't registered as-is, --flavor=gcc strips a __builtin_ prefix and accepts the result if it is a ClangBuiltinKind::Library entry, so __builtin_exit names exit. Clang and MSVC keep only the prefixed aliases Builtins.td generates (AddBuiltinPrefixedAlias), so under the default flavor __builtin_exit is still "use of unknown builtin", matching clang 22. All three lookup sites (names.rs, expression.rs builtin_callee, function.rs finish_functions) pass the flavor through; Resolver in names.rs carries unit.flavor.

Binding: names.rs records a reference from the prefixed callee to the exit Function in scope, if there is one, so a compatible prior declaration is reused (one fn @exit). builtin_callee returns (builtin, None) for a prefixed spelling whose in-scope declaration is incompatible, so void exit(long) plus __builtin_exit(1) still calls the builtin exit(i32), as GCC does after warning -Wbuiltin-declaration-mismatch.

Not modeled: the prefixed spelling bypassing -fno-builtin. Library builtins that GCC has but Clang's registry lacks (puts) remain unresolved: slate-parser-dyd.72. The declared-after-call duplicate fn decl already existed for plain exit: slate-parser-l94.

Fixtures: gcc-torture/20000105-1.c is now SLATE-FILECHECK-FLAVOR gcc and lowers (it was an IR-ERROR). It's a deliberate slate-accepts/clang-rejects divergence in the sweep. The new tests/fixtures/builtin_prefixed_library_gcc.c covers the compatible-declaration and mismatched _Exit cases.

Gate: this machine has no Slate sysroots (~/.local/share/slate/sysroots, ../slate-sysroots), so 639 header-dependent fixtures fail with "header not found". The failing set is identical with and without this change, and both touched fixtures pass.
