# Wide \_BitInt constant evaluation via num-bigint

_2026-09-13 08:37:26_

Added ConstExpr::WideInteger(WideInt) (const_expr.rs), backed by num_bigint::BigInt,
so \_BitInt(N) literals with N > 64 (previously an inert IntegerLiteral(String)
that erred NotConstant when evaluated) now fold to a real value.

WideInt::wrap(value, width, signed) canonicalizes into two's-complement mod 2^width.
Binary ops apply the ticket's simplified usual-arithmetic-conversion: result width =
max(width_a, width_b), unsigned wins on any signedness mismatch.

evaluate_expr (returns i64, used by #if and array-size/designator contexts) keeps its
fast i64 path for plain Integer arithmetic. A new sibling evaluate_wide (returns
WideInt) is used instead whenever contains_wide() finds a WideInteger anywhere in the
Unary/Binary subtree; the final wide result is truncated to i64 for the shared
return type, matching the low-64-bits-is-correct behavior already established for
#if in wf8.3.1.

parse_primary constructs WideInteger only for wb/uwb-suffixed literals whose
magnitude exceeds u64::MAX (i.e. where integer_value() already returned None);
plain unsuffixed oversized literals still fall back to IntegerLiteral(String)
unchanged. Width is derived from the literal's own magnitude (bit length, +1 for
a signed sign bit) per C23's minimum-width literal-typing rule.

lexer::Lexer::integer_digits made pub(crate) so const_expr.rs can strip the wb/uwb
suffix to detect it and to isolate the digit/radix prefix for BigInt::parse_bytes.

Regenerated ~16 fixtures via update_filecheck.py: any AST dump containing a
wb-suffixed literal over u64::MAX now shows WideInteger { value, width, signed }
instead of the old IntegerLiteral("...wb") string.
