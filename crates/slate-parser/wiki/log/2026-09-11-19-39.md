# Fix macro visibility after conditional blocks (wf8.1.16)

_2026-09-11 19:39:18_

record_define() stored every #define under And(active, branch_condition) with no
simplification, so a macro defined inside any conditional (even a statically-true
#if 1) became invisible once active reverted after #endif (structural equality
lookup in expand_macros/divergent_macro_conditions never matched again). This broke
the universal #ifndef GUARD / #define GUARD / #endif header-guard idiom.

Fix in src/pp.rs:

1. Added simplify_condition() to fold Constant/And/Or/Not combinators, and route
   conjunction() through it. Fixes the plain "#if 1" case generically.
2. Added concretize_guard(), called after parsing each conditional branch: if the
   branch condition is Not(Defined(name)) and the body itself #define'd `name`
   (self.macros now contains it), retroactively rewrite any macro recorded with
   exactly that branch's condition to the outer active condition alone. This can
   only be resolved after the fact -- `Defined(name)` is unresolvable when the
   branch opens, since that's precisely the point where `name` is still undefined.

Verified: minimal `#if 1`/`#define FOO 42` repro, the classic ifndef-guard repro,
and the full clang stdbool.h chain (isystem /usr/lib/clang/22/include) now resolve
`bool` correctly. Regenerated tests/fixtures/macro-conditional-use.c FileCheck
output (And(Constant(1), Defined(...)) collapsed to bare Defined(...)). Full
`cargo test` suite passes. Did not attempt to generalize to macros defined under
multiple levels of nesting where the outer branch condition isn't a bare
Not(Defined(name)) guard of itself -- that still requires proper partial
evaluation of Defined() against self.macros, which is a bigger change.
