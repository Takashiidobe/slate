# Windows sysroot layout for clang on windows-msvc

_2026-09-27 09:57:19_

slate-parser-v74.1.4.

sysroot::include_paths_at chose the Windows CRT/SDK layout (crt/include,
sdk/include/{ucrt,shared,um,winrt,cppwinrt}) only for --flavor=msvc.
clang-cl mode (--flavor=clang -target=*-windows-msvc) fell through to the
Unix layout, so <stdio.h>, <windows.h> etc. were not found. The layout is
now chosen when the flavor is msvc or the triple ends in -windows-msvc. The
clang resource headers still come first (compiler_headers precedes sysroot
in CompilerArgs::search_paths), which matches clang-cl's order.

Header probe, clang-cl mode: stdio.h, stdlib.h, string.h, math.h, stddef.h
and stdint.h now parse. windows.h needs the winnt.h keywords (v74.1.3).
intrin.h hits '_Float16 _Complex' in clang's avx512fp16intrin.h (existing
cxg.5; noted there).

Found while writing the fixture: --dump-ir of any printf-family call fails
in clang-cl mode. Clang's resource vadefs.h maps __crt_va_start to
__builtin_va_start, and on *-windows-msvc __builtin_va_list is char*, which
slate models as a distinct VaList type. Filed slate-parser-v74.1.5 (P1).

Fixtures sema/x86_64-pc-windows-msvc/sysroot_crt_headers_{clang,msvc}.c
include sdkddkver/stdio/stdlib/string and call abs and strlen.
