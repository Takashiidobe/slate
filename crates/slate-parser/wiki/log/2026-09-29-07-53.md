# Function declarations with incomplete parameter or result types

_2026-09-29 07:53:48_

slate-parser-dvlq. 'struct S; void f(struct S); struct S g(void);' is valid C, but lowering computed every declaration's ABI immediately and failed with 'incomplete ABI type' (Internal since cc94.5.6).

- ir::Function::abi is Option<AbiSignature>. Lowerer::declaration_abi and AbiClassifier::declaration_parts (the type view) return None when the return type or a parameter is an incomplete record (AbiClassifier::is_incomplete, through aliases). finish_module's complete_declaration_abis recomputes each None from the binding's final type, so a record completed later gets its real ABI. One still incomplete prints [abi=incomplete]. The whole signature is unknown, not per pass, because x86 win32 vector-register assignment depends on the earlier arguments.
- Definitions, implicit declarations and synthesized builtins are always Some.
- Ill-formed uses move into the checker, as clang does: TypeResolver::is_incomplete_record; call_type rejects an incomplete argument or parameter ('argument type is incomplete') and an incomplete return ('calling function with incomplete return type'); Checker::function rejects an incomplete result or parameter on a definition. Plain parse accepted all four before.
- Fixtures: clang/linux/x86_64/ir_incomplete_function_declarations.c, clang/linux/x86_64/incomplete_function_uses.c (plain-parse error, matches clang's four errors).
- wiki: ir-grammar.md and ir-spec.md document [abi=incomplete].
- Filed slate-parser-v48q: incomplete objects (block-scope struct S s;, never-completed tentative definitions) are still accepted.
