# Checker owns statement-context checks

_2026-09-28 19:52:43_

slate-parser-cc94.5.2. The static-assertion checker (assertion.rs) now tracks a StatementContext (loops, breakables, switches, Returns) per function and reports, in plain parse: break/continue/case/default/[[fallthrough]] outside their construct, noninteger switch discriminant, nonconstant case label, nonpointer computed goto, non-scalar if/while/do/for condition, value return from void function, valueless return (per flavor), fallthrough attribute on a non-empty statement and nested function definitions (non-gcc). The module.rs copies are now Internal.

Too-strict fixes found on the way:
- return of a void expression in a void function is accepted (clang and gcc do); lowering emits the expression then return.
- constant_value folds a conditional whose condition is constant without requiring the unselected arm to be constant (gnu folding): case (1 ? 1 : i) and int [0 ? f() : 1] are constant, matching both oracles (c99-static-1 g5 now sizeof 4, vla-20 array=0).

Fixtures: ir_control_context.c -> control_context.c, plain parse, plus FALLTHROUGH/VOID_RETURN/VALUELESS/NONSCALAR; new clang/return_void_expression.c; names_control_labels.c moved to gcc/ (it uses a GNU nested function); nested-function clang torture fixtures now report 'function definition is not allowed here' first; ir_vector_invalid CONDITION points at the condition.
