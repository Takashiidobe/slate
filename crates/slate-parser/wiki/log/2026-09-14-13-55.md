# ParameterList and FunctionDefinition through the declarator parser

_2026-09-14 13:55:26_

Part of slate-parser-lh7.3.5 (step 1; the CType -> TypeSpecifier/TypeName swap remains).

- Declarator::Function and CType::Function carry ParameterList::{Prototype{parameters, variadic}, Void, Empty}, so f() and f(void) are distinguishable.
- FunctionDecl {ret_type, name, parameters, variadic, qualifiers, storage, ...} is replaced by FunctionDefinition {specifiers, declarator, attributes, body, provenance}. Top-level and nested definitions parse via parse_declaration_specifiers + parse_declarator; the return type is no longer pre-applied.
- This fixes definitions with non-trivial declarators ('int (*g(int))(char) {}') that failed with 'expected function name'.
- Declarator::function_parameters(_mut) finds the parameter list of the name's own type. Suffixes wrap prefix pointers in this tree, so the name-adjacent layer is not the outermost type; Grouped content wins, then the suffix nearest the name.
- K&R: DeclaratorParser.identifier_list accepts a bare identifier list on the first parameter list parsed; parse_function replaces it with the promoted K&R prototype. Implicit-int is a flag on parse_declaration_specifiers.
- Declarator::Pointer gained attributes ('struct S *__attribute__((noinline)) f()'), checked by sema.
- Specifier keywords are accepted after the base type too ('extern int inline f()').
- apply_abstract_declarator mis-derives Pointer over Grouped ('void *(*fp)(void)'); filed as a bead, not fixed.
- tools/update_filecheck.py gained --no-fail-fast.
- New fixtures: parameter_list_void_vs_empty.c, function_definition_declarators.c. All fixtures regenerated; parse_errors.c's message for 'int main( {' is now 'expected declaration type, found LBrace'.
