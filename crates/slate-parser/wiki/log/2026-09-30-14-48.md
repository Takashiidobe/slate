# Name resolution walks every layer of a function definition's declarator

_2026-09-30 14:48:00_

slate-parser-6x05.2. names.rs resolved a function definition's declarator only through function_parameters() (the definition's own parameter list, bound in the body scope). The remaining layers -- the returned function type's parameter list, pointer attributes, array-size expressions in the return type -- were never visited, so a typedef there had no reference and lowering failed with 'internal error: unknown typedef' (libpng contrib/libtests/pngstest.c get_pixel; signal()-style definitions).

Fix: declarator() became declarator_layers(declarator, definition: Option<&ParameterList>); the definition path walks all layers before pushing the body scope and skips only its own parameter list (pointer identity), which it still binds in the body scope. Walking the layers first keeps C's scoping: in void (*g(int T))(T x) the inner T is the typedef, because the prototype scope of (int T) has closed.

Fixture: clang/linux/x86_64/definition_returning_function_pointer_typedef_parameters.c (typedef shadowed by a parameter, nested function-pointer returns, sizeof(typedef) array bound in a return type). libpng sweep: 23/24, pngstest.c passes; the remaining pngsimd.c is the target-builtin-type bug (v74.1.13).
