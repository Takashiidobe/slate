# slate-f2zu.14.40.7 build.rs link args: -z nostart-stop-gc so __start_/__stop_ linker-set sections survive rust-lld gc-sections

_2026-11-16 12:13:27_

- bead: slate-f2zu.14.40.7
- kind: bug
- area: crates/slate/src/main.rs
- area: crates/slate/src/frontend/c_shim.rs
- area: crates/slate/tests/fixtures.release

Outcome: translated Linux bin and cdylib crates link with -z nostart-stop-gc like GNU ld, so sections reached only through __start_/__stop_ survive rust-lld's --gc-sections.

Symptom: C linker sets (a section iterated via __start_X/__stop_X) lost entries or failed to link after translation. rust-lld defaults to start-stop-gc; GNU ld (the C build) defaults to nostart-stop-gc.
- A global_asm! `.pushsection X,"a"` entry sharing X with a #[used] static was silently dropped (count 1 instead of 2).
- A plain `__attribute__((section("X")))` global with no `used` failed: `rust-lld: error: undefined symbol: __start_X`.

Reproducer:
```c
extern const int __start_slate_mixed_set[], __stop_slate_mixed_set[];
__attribute__((used, section("slate_mixed_set"))) static const int v = 7;
__asm__(".pushsection slate_mixed_set,\"a\"\n.balign 4\n.long 11\n.popsection");
/* main sums the entries: C prints "2 18", Rust printed "1 7" */
```

Cause: link args. No translator item was wrong; the generated crate never told the linker to keep __start_/__stop_-referenced sections.

Fix: `write_project_crate` (crates/slate/src/main.rs) now composes build.rs from parts:
- the long-double shim compile, if any (`c_shim::shim_build_statements`, formerly `shim_build_script`, now returns statements only);
- for bin crates `cargo:rustc-link-arg-bins=-Wl,-z,nostart-stop-gc`, for libraries with a cdylib crate type `cargo:rustc-link-arg-cdylib=...`, guarded by `CARGO_CFG_TARGET_OS == "linux"` at build time.
rlib/staticlib crates get no flag: their consumer owns the final link. build.rs is removed when no part applies.
Not gated on global_asm, since the plain-global case has no asm.

Regression tests: crates/slate/tests/fixtures.release/start_stop_mixed_asm_section.c, start_stop_plain_section.c. link_order_asm dropped its `"aR"` (SHF_GNU_RETAIN) workaround and still passes.
They are release fixtures because that suite builds slate's own generated crate and build.rs; the batch differential harness writes its own build.rs and would not see the flag.

Limits: batch differential harness (tests/support write_long_double_shim) does not pass the flag, so single-file fixtures in tests/fixtures/ still link with start-stop-gc.
