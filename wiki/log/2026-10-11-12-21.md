# Query the compile database's compiler for native headers

_2026-10-11 12:21:32_

translate-project now passes each compile_commands.json entry's argv[0] to slate-parser as --compiler=<path> (slate-wmx8).

- slate-parser: new Slate-only option --compiler (all flavors, Opt::Compiler), stored as CompilerArgs::compiler.
- native_headers::discover takes the compiler; the cache key includes it. Clang and GCC flavors query it in place of clang/gcc from PATH; MSVC ignores it.
- If the named compiler fails the flavor's query (e.g. cc that is really gcc under the clang flavor), discovery falls back to PATH clang/gcc, then the installed sysroot.
- Relative compiler paths with a directory component resolve against the entry's directory.
- Still host-only: a cross target never uses native headers, even from a named cross compiler, because clang --target=<cross> without a cross sysroot reports host /usr/include.
- New unix e2e test translate_project_uses_compile_database_compiler_headers: a wrapper script adds -isystem for a marker header; plain clang cannot find it.
- Docs: sysroots README native-headers order, compiler-arg-rules.
