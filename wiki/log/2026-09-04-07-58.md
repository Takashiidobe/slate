# GNU libm and companion-library audit (slate-3f8g.5.8)

_2026-09-04 07:58:24_

Inventoried the deterministic GNU libm and companion-library surface on the configured host (glibc 2.43, libxcrypt).

New fixture tests/fixtures/gnu_libm.c covers sincos/sincosf/sincosl, exp10 family, lgamma_r, significand(f), drem(f), scalb(f), Bessel j0/j1/jn/y0/y1/yn + j0f/y0f, the GNU fenv trap controls, and the long-double M_*l constants. Differentially matches C (`6 11 8 4 4`); lowering and rewrites both pass. Full lowering, rewrites, and libc profiles are green.

Two shim gaps found and fixed to land the fixture:
- libc-shim/include/fenv.h had no feenableexcept/fedisableexcept/fegetexcept. Added under _GNU_SOURCE, matching glibc's __USE_GNU gating.
- libc-shim/include/math.h had the double M_* constants but none of the long-double M_*l set. Added all thirteen with glibc's values.
Everything else the audit probed (sincos, exp10, lgamma_r, significand, drem, scalb, Bessel) was already declared.

Link requirements, resolved empirically rather than assumed:
- libm IS still a separate DSO here; glibc 2.34 merged libdl/libpthread/librt/libutil into libc but not libm. -lm is required.
- No plumbing was needed. The C side already hard-codes -lm (tests/support/mod.rs:192, :259), and rustc's own link line for x86_64-unknown-linux-gnu passes "-lgcc_s -lutil -lrt -lpthread -lm -ldl -lc", so the merged-in libraries come free too.
- libcrypt (libxcrypt) is the one companion library that needs an explicit -l and has no mechanism. Filed as slate-3f8g.5.12.

A scratch crate is not a valid way to test long-double output: Slate emits C thunks like __slate_sincosl__rv_f80_pf80_pf80 that only the harness's build.rs compiles, so an ad-hoc cargo project fails to link. Use the differential fixture.

Gaps filed: slate-3f8g.5.11 (shim struct crypt_data is 260 bytes vs libxcrypt's 32768 -- crypt_r would smash the stack), slate-3f8g.5.12 (no per-fixture link-library mechanism), slate-3f8g.5.13 (shim declares pow10, which glibc's header dropped and whose compat symbol will not link).

Out of scope per the epic and left uninventoried: libnsl/NIS, libresolv and network resolution, and anything host- or privilege-dependent.
