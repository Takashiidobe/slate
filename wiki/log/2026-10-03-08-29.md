# Export f80 project functions through native-ABI C wrappers (slate-dghn.23)

_2026-10-03 08:29:50_

Redis INCRBYFLOAT/HINCRBYFLOAT returned garbage: a translated definition such as
string2ld takes LongDouble as an INTEGER-class [u8;10] struct, but the C bridge a
caller in another translated unit calls assumes the native x87 ABI (memory).

Fix, reviving the CIR lowerer's __slate_ld_<name> trampoline with symbols swapped:
- lowerer.rs: an exported non-variadic definition whose signature holds f80 gets
  #[unsafe(export_name = "__slate_ld__<name>__r<ret>_<tags>")] instead of no_mangle.
  Names containing __, cf80 signatures, and variadic f80 exports are barriers.
- c_shim.rs: render_trampoline parses __slate_ld__ names and emits the real <name>
  as a native-ABI C wrapper (f80_store args, f80_load result) calling the Rust symbol.
  collect_program_shim_names also gathers these export names.
- The double underscore keeps exports distinct from bridges of callees named ld_*.
- differential.rs: release fixtures may be directories (multi-unit projects); the
  C oracle compiles all sources together.
- New fixture tests/fixtures.release/long_double_cross_unit (string2ld/ld2string/
  ld_add/ld_scale across two TUs) failed before, passes now.

Validation: slate profile 13/13 green. Redis e2e: barriers 0, build ok, bench geomean
1.001, INCRBYFLOAT 10.5 -> 12, HINCRBYFLOAT 4.5; runtest 683 -> 3876 ok.
