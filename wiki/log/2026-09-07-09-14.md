# ARM32 differential harness scaffolded

_2026-09-07 09:14:34_

Closes the scaffolding half of slate-3f8g.4.16.10: added tests/differential_arm.rs
(mirrors differential_aarch64.rs) plus arm-lowering/arm-rewrites nextest profiles,
excluded from rewrites/lowering. Installed ARM's official 15.2.rel1
arm-none-linux-gnueabihf toolchain tarball to ~/toolchains (AUR gcc packages
wanted to build from source); rustup target armv7-unknown-linux-gnueabihf added.

Key wiring: C oracle uses clang (not the cross gcc) so Clang-only builtins
(__builtin_bit_cast, __builtin_bitreverse32, _BitInt(128)) still work; clang
needs -B/-L pointed at the cross gcc's own libgcc dir (queried via
`<gcc> -print-libgcc-file-name`) plus -fuse-ld pointed at the cross ld, since
clang doesn't auto-discover this toolchain's "arm-none-linux-gnueabihf" layout
the way it does distro-packaged aarch64-linux-gnu-gcc.

Full fixture suite now passes under --profile arm-rewrites (444 fixtures,
minus skips). Surfaced 4 new bugs while getting there, all filed under
slate-3f8g.4.16 and skip-listed with reasons in differential_arm.rs:
- .16.11: long_double_bits() wrongly gives 32-bit arm the same 128-bit quad
  long double as aarch64; armhf long double is actually just double (8 bytes,
  confirmed on-device).
- .16.12: slate lowers C long/unsigned long/size_t as 64-bit unconditionally;
  armv7 is ILP32 (32-bit long).
- .16.13: double _Complex arithmetic crashes under qemu-arm-static on armv7
  hard-float ABI, root cause not yet identified.
- .16.14: ClangIR frontend rejects __int128/__float128 outright on armv7, and
  requires cir.alloca's size operand to be 64-bit even on this 32-bit target.

The existing ARM asm constraint fixtures (target of .16.1-.16.4, not yet
implemented) are also skip-listed here as expected/blocked, not new bugs.
