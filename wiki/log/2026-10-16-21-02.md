# Fold literal casts in a late pass

_2026-10-16 21:02:29_

slate-5vj0.5.6. New rule literal_casts, run in a second worklist pass (rules::late_registry) after the main registry converges. Worklist priority only orders rules within one node; nodes are visited in index order, so a cast stripped early could be moved by a later rule into an untyped spot. for_range joined stripped 'i = 0' and 'i < 64' into 'for i in 0..64' (gcc-torture pr37573/pr65401, ambiguous {integer}). The late pass is a single linear walk (one rule, nothing it enables); the user accepted it over moving the logic into codegen.

The rule:
- folds literal cast chains when the value fits every step: ((3 as i32) as i64) as u64 -> 3 as u64;
- drops the cast where Rust fixes the type: typed let init, assign value, non-shift compound-assign value, return, the function's tail expr, struct fields, array elems in a typed context, the operand of an arithmetic or comparison op whose other side is a non-literal, ranges likewise, and wrapping_add/sub/mul args.
Shifts, call args (variadic/generic), method receivers, untyped lets, and floats keep their casts. isize/usize use 32-bit bounds.

cstr_literal now takes the target's c_char (TargetInfo::char_signed) and drops 'as *const i8' after c"..".as_ptr() when it matches.

Fixture literal_cast_fold.c; 94 baselines regenerated. gcc-dg split-5 failed once under suite load and passed 3/3 alone (flaky, unrelated). slate profile otherwise green.
