Outcome: wiki/concepts/pointer-lift-shims.md records the C-ABI shim design for lifting exported and address-taken functions (lifted Rust fn + extern "C-unwind" wrapper that keeps the symbol and every function-pointer use); linked from pointer-capability-lattice.md.

Covers the wrapper shape and attribute placement, per-kind conversions (as_ref/as_mut, Option<&CStr> via null check + CStr::from_ptr, slices only with a body-proven count, lifted returns back to raw), outside-caller rules (all lifted params Option, aliasing with compatible params and mutable globals, caller-side rules kept for internal callers), routing (internal direct calls -> lifted fn, address-of -> wrapper), and the v1 shimmable set.

New decision (2026-11-28): shimmability is a deny-list checked on the function's own attributes, not on Program::export_pin, because open mode collapses every export to ExportPin::Exported. Closed-mode section/used/retain/dll_storage/selectany/constructor/destructor/weak_odr/discardable are shimmable (attribute moves to the wrapper); fallback and declared_other_prototype join the epic's exclusions. The slate-8ge7.26.6 open-mode counts therefore include abi_pass/target_feature/alias exports that v1 will not shim.

Limits: the slice wrapper claims n elements valid where C only needs the touched ones; v1 takes n as the caller's contract.
