# Thread target pointer-bitness through inline-asm lowering; add q/Q for non-byte operands

_2026-09-06 22:36:56_

Closes slate-3f8g.4.15.8. Added Lowerer::target_pointer_bits, computed once
from module.triple via TargetArch::pointer_bits (defaults to 64 if the
triple is missing/unrecognized). Threaded it through asm_operand_bits (fixing
the hardcoded Type::Ptr/FnPtr => 64 bug), asm_reg_for_constraint, and the
register-modifier-suffix machinery (wants_register_modifier now takes ty +
pointer_bits since reg_byte, unlike reg_abcd/reg, rejects template modifiers
outright).

Implemented Q/q for non-byte operands: Q always resolves to reg_abcd; q
resolves to reg_abcd under a 32-bit target, or Generic (plain reg, since
GCC's q means "any GPR" there) under 64-bit. Byte-sized operands under Q, or
under q on a 32-bit target, still error -- reg_abcd has no i8 arm and Rust
rejects ah/bh/ch/dh as explicit register operands. q on a 64-bit target with
a byte operand works directly via reg_byte (which does support i8), no
special-casing needed.

Verified the pointer-bits fix directly: a "D"(ptr) fixed-register input
lowers to in("rdi") at x86_64 but in("edi") under SLATE_TARGET=i686-unknown-
linux-gnu -- previously always "rdi" regardless of target. No automated
32-bit differential exists in this repo (would need real cross-toolchain
infra, out of scope), so this was checked via manual translate-only probes,
documented here rather than as a fixture.

Filed slate-3f8g.4.15.10 as follow-up: byte-sized Q/q-in-32-bit has a real,
verified workaround (widen to reg_abcd, use Rust's {N:l}/{N:h} template
modifiers -- confirmed both compile and execute correctly, including the
high-byte case disassembling to a bare `inc %ah`), but it needs new
TemplateModifier::HighByte plus EbxFixup-shaped widen/narrow glue, out of
scope for this bead.

Fixture: tests/fixtures/asm_byte_addressable_reg_constraint.c (Q on a wide
int, q on a byte at the default x86_64 target). Full lowering profile
(12/12) passes.
