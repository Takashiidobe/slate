# translate-project emits library crates when no unit defines main

_2026-10-03 16:48:14_

slate-dghn.2: translate-project used to fail with 'slate frontend does not yet support library projects' when no TU defined main.

Now (crates/slate/src/main.rs): with no root unit, every unit becomes '#[path] mod __slate_unit_<stem>;' in a generated src/lib.rs that also carries the merged #![feature] attrs. The manifest gets '[lib] path = "src/lib.rs"' plus crate-type from the new '--crate-type rlib|staticlib|cdylib[,..]' flag (default rlib) and autobins = false, so a unit named main is just a module. --crate-type with a main-defining project is an error. init_crate deletes the stale root (main.rs or lib.rs) when a crate directory switches modes. The autobins manifest parameter is now derived from lib_crate_types.

Exported functions were already #[unsafe(no_mangle)] (export_symbols), so a staticlib/cdylib exposes the C ABI with no extra work.

Test: new library_differential (tests/differential.rs) revives the dormant tests/fixtures.library projects: translate src/*.c as a staticlib, link each tests/*.c driver against the .a (support::link_c_with_archive, uncached because the archive is not a cache input) and compare it with an all-native build. simple and c23_strfrom have drivers; anon_union_member and hidden_visibility_callback are build-only. All four pass. README, slate-architecture and crates/slate/CLAUDE.md document the flag and the suite.

Redis: a TU subset can now be cargo-checked as an rlib with no stub main.c.
