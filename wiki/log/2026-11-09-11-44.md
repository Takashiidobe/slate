# Share MSVC comdat inline definitions across project units

_2026-11-09 11:44:12_

slate-j3by.1: an MSVC inline with explicit extern or dllexport (clang weak_odr) was exported from every unit that defined it, so a multi-unit Windows project failed with 'symbol is already defined'; a static local in a linkonce_odr (discardable) inline was one object per unit in slate and one in clang/cl.exe. slate-parser now prints [definition=weak_odr] (FunctionSemantics.weak_odr: MSVC inline semantics, declared inline, external body, not discardable); matches clang -emit-llvm on CodeGen/inline.c and dllexport.c. merge::translate_units runs shared_comdats before lowering: for a weak_odr or discardable function defined in several units it keeps one body (a weak_odr unit when there is one) and lowers the others from a module copy without that body, so they get an ordinary extern decl. When every definition is discardable, the kept one exports __slate_odr_<name> and the decls link_name it (LowerOptions.odr_symbols), so a library never exports a UCRT inline under its real name. Static locals are now shared. Not covered: --merge lowers units one at a time (slate-j3by.21); the stripped unit still emits its unused copy of the static local. Fixture: fixtures.dylink/inline_odr (Linux legs define the functions plainly, since C99 leaves inline-vs-external choice unspecified); pre-fix Windows failed to compile. 5 parser fixtures regenerated (emitted -> weak_odr).
