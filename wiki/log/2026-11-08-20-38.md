# gcc flavor: ignore mode with a non-identifier argument

_2026-11-08 20:38:30_

slate-78pa.7: gcc warns "'mode' attribute ignored" and accepts __attribute__((mode(X))) when the single argument is not an identifier (mode(1), mode("DI"), mode(vector_size(8))); slate rejected it as an invalid attribute. The parser (parser/attributes.rs) now builds Attribute::IgnoredMode { arguments } for gcc flavor when there is exactly one top-level argument that is not an identifier. Sema treats it as Inapplicable on every subject, so it emits -Wignored-attributes "'mode' attribute ignored" and the type is unchanged. clang/msvc and wrong argument counts still give Invalid. Migrated gcc.dg parm-impl-decl-1.c and parm-impl-decl-3.c (gcc flavor). New fixture gcc/linux/x86_64/mode_non_identifier_ignored.c covers typedef, specifier, declarator, field and parameter positions. Wiki: ast-spec, ast-grammar, attributes. Follow-up slate-78pa.8: gcc still checks the ignored argument as an expression (undeclared identifiers error); slate does not.
