# slate-f2zu.14.34.28 bare-metal panics: -Cpanic=immediate-abort inlines bounds-check panics as ud2; core dispatch default arm is unreachable_unchecked

_2026-11-15 18:20:07_

- bead: slate-f2zu.14.34.28
- kind: bug
- area: crates/slate/src/project/build_target.rs
- area: crates/slate/src/frontend/lowerer/control_flow.rs
- area: crates/slate/src/backend/engine/rules/structure_goto

Outcome: bare-metal (kernel) crates build with `-Zunstable-options -Cpanic=immediate-abort`, so checked `[i]` indexing and `unreachable!()` compile to an inline `ud2` with no call, and core-only crates lower the goto-dispatch default arm to `core::hint::unreachable_unchecked()` instead of `unreachable!()`.

Symptom: objtool on the relinked vmlinux.o flagged `get_cpu_entry_area` -> `core::panicking::panic_bounds_check` ("call leaves .noinstr.text") and calls with UACCESS enabled; the goto/asm-goto dispatch `_ => unreachable!()` arm (get_futex_key, arch_static_branch) is another panic call.

Reproducer:
```c
/* -ffreestanding */
static int jump_probe(int x) {
  static void *targets[] = {&&zero, &&one};
  goto *targets[x];
zero: return 10;
one:  return 20;
}
```
Before: `_ => { unreachable!(); }` in both the computed-goto match and the `__slate_state` match; `targets.0[x as usize]` compiles to `cmp; jae -> call panic_bounds_check` even under panic=abort (core's panic fns are `#[inline(never)]`).
After: `_ => { core::hint::unreachable_unchecked(); }`; with immediate-abort the bounds check is `cmp; ja -> ud2` in place (checked on a x86_64-unknown-none build-std staticlib).

Cause: panic=abort still calls core's out-of-line panic functions; objtool flags the call instruction itself, taken or not.

Fix:
- `FunctionLowerer::dispatch_unreachable` (crates/slate/src/frontend/lowerer/control_flow.rs): `unreachable!()` when `tables.runtime.has_std()`, else `core::hint::unreachable_unchecked()`. Hosted output keeps the panic, since a bad state there is a slate bug that should be loud.
- `structure_goto/reducible.rs` `is_exit_path` treats `core::hint::unreachable_unchecked` as diverging, like `unreachable!`.
- `shared_flags` (crates/slate/src/project/build_target.rs) adds `-Zunstable-options -Cpanic=immediate-abort` for x86_64-unknown-none and the i386 spec. Array indexing stays checked everywhere.
- rustc does not require a `#[panic_handler]` under immediate-abort; slate still emits it (host-triple core crates need it).
- Spec: wiki/concepts/ir-to-rust-lowering.md, wiki/concepts/ir/calls-abi.md.

Regression test:
- crates/slate/tests/fixtures/freestanding_dispatch_unreachable.c (computed goto + backward goto, -ffreestanding).
- differential.rs `freestanding_projects_build_for_bare_metal_targets` expects the new rustflags and builds both crates.

Limits: a failed kernel bounds check is a bare `ud2` (invalid-opcode oops, no BUG-table entry or message). Not confirmed by a relink yet; the other .28 calls (always_inline callees, instrumentation_begin/end) and .27 UACCESS ordering are separate.
