# Fix top-level items sharing a line being dropped

_2026-09-14 11:46:56_

parse_top_level_item (src/parser/decl.rs) only split a PP line's tokens into
multiple top-level items when the line had macro-expanded tokens, so any
source line with plain multiple items (e.g. 'void f(void){} void g(void){}',
'struct s {...}; int x;', 'int a; int b;') silently dropped everything after
the first item, or errored with 'unexpected tokens after declaration'.

Removed the macro-expansion gate so split_top_level_items() always splits
whenever it finds more than one top-level item, regardless of macro
expansion.

That exposed a second, latent bug: split_top_level_items()'s function-body
heuristic (an LBrace at depth 0 preceded by RParen) also matches compound
literals like '&(int){0}', so 'int \*i0a = &(int){0};' was being mis-split
into a bogus function-shaped item plus a stray ';'. Fixed by tracking
whether a top-level '=' has been seen since the current item started, and
suppressing the function-body heuristic when it has (declarations always
introduce compound literals via '=' initializer; real function definitions
never contain a top-level '=' before their body).

Added tests/fixtures/same_line_top_level_items.c covering functions, tag
definitions, plain declarations, and typedefs sharing a source line, per
slate-parser-ixa.1's acceptance criteria.
