Outcome: ir::Type is #[slate::sensitive] and cargo dylint reports zero hits across slate-parser and slate; every catch-all over it is gone or an expect whose reason states the assumption.

Triage of 97 hits (58 slate-parser, 39 slate), by resolution:

- New exhaustive views on ir::Type (ir/numeric.rs): `integer_bits() -> Option<(width, signed)>`
  (_Bool as 1-bit unsigned), `numeric_domain() -> Option<(NumericType, NumericDomain)>`
  (Real / Complex / Imaginary, NumericDomain is also sensitive), `is_void_or_function()`.
  Moved onto them: fold `integer_type`, `integer_fits`, `is_folded`, asm `nop_conversion`,
  asm_constants `known_value`, SEH filter check, MS asm return gate, `support_constant`,
  integer unary lowering, assertion float format, `imaginary_binary` component/domain,
  `reject_mixed_decimal`, imaginary decimal check, atomic non-object checks (atomic.rs, typer.rs).
- Listed exhaustively (per-kind ABI or layout decisions): `vectorcall_register_type`,
  `win32_returns_in_register`, `sysv_leaves` (sema/abi.rs); `asm_bridgeable`,
  `has_padding_bytes`, `is_sync` (crates/slate lowerer).
- Rejecting arms made explicit: unary plus, vector splat and `vector_rule` scalar checks,
  register-global read; `condition()` pointer arm is now `Pointer | BlockPointer` instead of a guard.
- Restructured: `parameter_shape` computes the array extent once; auto-var zero init in
  statements.rs matches on the type only after `init` is None; support-function result cast
  moved to `support_result_needs_cast`.
- Expects with reasons: structural recursions (abi `contains_vector`, `is_empty_record`,
  float-element and HFA walks, `has_runtime_size`, `variably_modified`, `required_alignment`,
  `same_layout`), delegations to an exhaustive callee (`qualified_storage` and slate
  `storage_of` to TargetInfo::storage_of, `object_bytes`, `require_pointer_element`,
  `unary_rule` to numeric_type), printing (`FloatBits` display), and classifier defaults whose
  false/None is the conservative path (fastcall/vectorcall scalars, atomics, libc catalog).

Bugs found and fixed:
- `win32_returns_in_register` returned false for `BlockPointer` and `VaList` fields, so a
  pointer-sized struct holding one was returned through sret on i686-windows; clang returns
  it in eax like any pointer.
- `sysv_leaves` gave up on `BlockPointer` (fell back to native_c); it is now an INTEGER leaf
  like `Pointer`.
- transparent_union `mark_transparent` ignored the attribute only for a real float or vector
  first member; a `_Complex` float first member is floating in clang and gcc too.

Found, filed, not fixed:
- slate-yar4.57: AAPCS `homogeneous_type` does not count `_Complex` members of an HFA.
- slate-yar4.58: padding `mark_data` treats x87 and _BitInt tail padding as data.

Limits: no fixture isolates the three fixes (parser and slate profiles pass). VaList-in-struct
on win32 and blocks on i686-windows are rare. Remaining enums for the lint: ValueKind,
VaListKind, CompilerFlavor.
