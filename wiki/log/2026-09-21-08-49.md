# share the parameter projection between both lowering paths

_2026-09-21 08:49:14_

`src/sema/types.rs::resolve_parameters` (the `--dump-ir-types` path) carried a
second copy of parameter lowering and had drifted from
`module.rs::parameters`. Two divergences:

- it used the **written** type as the parameter's `ir::Type`, skipping
  `adjusted_parameter`, so an array or function parameter never decayed to a
  pointer. The ABI classifier then rejected it: every header declaring
  `void f(int a[10])`, `void f(arr_t a)`, `void f(int cb(int))` or a VLA
  parameter failed `--dump-ir-types` with "unadjusted ABI parameter type".
- it picked array qualifiers on `declared_array.is_some()` rather than on the
  resolved type, so a typedef'd array parameter took the typedef's qualifiers
  instead of the (empty) declarator ones.

Factored the shared half — `QualType` + `ArrayDeclarator` -> written type,
qualifiers, `ArrayParameter` and adjusted `QualType` — into
`TypeResolver::parameter_shape`, keeping `module.rs`'s (clang-validated)
behaviour, and pointed both call sites at it. What is still split is id
allocation and the entity declaration, which needs a `Lowerer` the type-view
path does not have.

Fixture `tests/fixtures/sema/ir_types_parameter_adjustment.c` covers the eight
parameter shapes; each one's projection is now byte-identical to what
`--dump-ir` emits for the same declaration. Gate green, no existing fixture
output changed.
