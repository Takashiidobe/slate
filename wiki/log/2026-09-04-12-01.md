# scalar math builtins (fma/hypot/fdim/cbrt/ldexp/scalbn/logb/ilogb) already covered (slate-04q.47.6)

_2026-09-04 12:01:14_

Dumped CIR for all eight requested __builtin_* spellings
(llvm-project build): __builtin_fma is the only one CIR models as a
dedicated op (cir.fma, already handled by slate's Op::Fma). Every other
one -- __builtin_hypot, __builtin_fdim, __builtin_cbrt, __builtin_ldexp,
__builtin_scalbn, __builtin_logb, __builtin_ilogb -- CIRGens to a plain
`cir.call @hypot/@fdim/@cbrt/@ldexp/@scalbn/@logb/@ilogb`, byte-identical
CIR to calling the same-named libc function directly with no `__builtin_`
prefix. slate has no special-case table for these names at all (grepped
src/ for each name, zero hits outside the intrinsics_table.rs SIMD
tables) -- they already fall through to the generic "declare unsafe
extern C, call it" path used for any unrecognized libc call, which is
correct and byte-identical to C since Rust would link the exact same
libm implementation. No lowering changes needed.

Long-double variants (hypotl/fdiml/cbrtl/ldexpl/scalbnl/scalblnl/ilogbl/
logbl) are already fixture-covered in tests/fixtures/long_double.c via
the __slate_f80_* shim family (src/frontend/shims/long_double.c) -- same
CIR-identity argument applies to their __builtin_*l spellings, so no new
long-double fixture was needed.

Added tests/fixtures/builtin_math_scalar_ops.c using the actual
__builtin_* spellings (not the plain libc names) for all eight requested
functions at double precision, confirming the differential passes and
locking in the extern-C-call shape via FileCheck. rewrites profile
(93 tests) passes. Deliberately did not recover f64::hypot/f64::cbrt
Rust-idiom methods despite them existing in std -- the epic's own
"transliterate first, idiomatize later, in a separate verified fixup"
convention argues against bundling that speculative, unverified-parity
change into a fixture-only bead.
