# slate-parser-v48q sema: block-scope object of never-completed struct accepted

_2026-11-18 09:46:38_

- bead: slate-parser-v48q
- kind: bug
- area: crates/slate-parser/src/sema/assertion.rs

Outcome: a block-scope object definition of a never-completed struct/union is now rejected with "variable has incomplete type" in both flavors, as clang and gcc do.

Symptom: `struct S; void h(void) { struct S s; }` was accepted by slate-parser parse and --dump-ir.

Reproducer:
```c
struct S;
void h(void) { struct S s; }
```

Cause: the checker's `declaration` in crates/slate-parser/src/sema/assertion.rs never asked `is_incomplete_record` about the completed object type; only function results and OpenMP privatization did.

Fix: reject non-global, non-extern declarators whose completed type `is_incomplete_record`, beside `declare_object`.

Regression test: crates/slate-parser/tests/fixtures/error/{clang,gcc}/linux/x86_64/incomplete-local-object.c. The slate profile also promoted gcc-dg torture__pr116057.c (made to pass by the earlier slate-parser-cxg.39 vector_size fix).

Limits: file-scope tentative definitions that are never completed (`struct S s;` at file scope) are still accepted; clang rejects them at the end of the unit, gcc behavior not measured yet.
