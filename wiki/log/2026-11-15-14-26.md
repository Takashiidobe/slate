# slate-f2zu.14.34.23 asm_names: EXPORT_SYMBOL asm bound sym to local item for runtime symbols (strlen, memcmp) and data aliases (crypto_aes_sbox); modpost local symbol was exported

_2026-11-15 14:26:48_

- bead: slate-f2zu.14.34.23
- kind: bug
- area: crates/slate/src/frontend/lowerer.rs
- corpus: linux

Outcome: file-scope asm that names an exported runtime symbol (strlen, memcmp, bcmp) or an exported data alias (crypto_aes_sbox) keeps the literal symbol name in the template instead of a `sym` operand bound to a local Rust item, so kernel EXPORT_SYMBOL entries reference the global symbol.

Symptom: vmlinux relink reached modpost and failed with `ERROR: modpost: vmlinux: local symbol 'X' was exported` for strlen, memcmp, bcmp (lib/string.c) and crypto_aes_sbox, crypto_aes_inv_sbox (lib/crypto/aes.c). The .export_symbol relocation pointed at a local symbol (`.text.slate_distinct.string.strlen` section symbol, the local static aes_sbox).

Reproducer:
```c
static const unsigned char table[4] = {1, 2, 3, 4};
extern const unsigned char table_alias[4] __attribute__((alias("table")));
size_t strlen(const char *s) { const char *p = s; while (*p) p++; return p - s; }
asm(".section .export_list,\"a\"\n.quad strlen\n.quad table_alias\n.previous");
```
Before (translate-project): `global_asm!(".section .export_list...\n.quad {0}\n.quad {1}\n.previous", sym strlen, sym table)`.
After: `global_asm!(".section .export_list...\n.quad strlen\n.quad table_alias\n.previous")`.

Cause:
- `asm_names` (frontend/lowerer.rs) maps each same-unit defined function or global name to its binding; `lower_asm_block` turns a matching template word into `{N}` + `sym <rust item>` via `asm_symbol`.
- In export mode a runtime-symbol definition stays a private Rust fn; the C name sits on the `__slate_export_<name>` wrapper (`functions::runtime_export`, slate-f2zu.14.29). `sym strlen` named the private body.
- An exported ELF data alias has no Rust item: `push_alias` emits `.globl alias / .set alias, {sym target}`, and `asm_symbol` resolved the alias binding to the target static.

Fix: `asm_names` leaves out names whose global symbol is carried by something other than the item `sym` would name: exported functions whose link name is a `runtime_symbol`, and exported ELF aliases with a static target (same conditions as `lower_global_alias`). Those words stay literal and resolve at link time. `elf_aliases` now shares `elf_alias_target(&TargetInfo)`.

Regression tests:
- crates/slate/tests/fixtures.library/runtime_symbol_definitions: asm `.quad strlen` / `.quad memcmp` refs compared with `&strlen`/`&memcmp` from the C test (memcmp_ref differed before: 1 0 vs 1 1).
- crates/slate/tests/fixtures.release/data_alias_units: asm `.quad crypto_sbox`/`.quad table_alias`, FileCheck shows the literal template.

Limits: explicit asm symbol operands ("i"/"s" constraints, `AsmOperandKind::Symbol`) still bind through `asm_symbol` to the local item; filed slate-yar4.47.

See: slate-f2zu.14.34.16 (data alias export), slate-f2zu.14.29 (runtime symbol wrappers), slate-f2zu.14.34.9 (template word to sym), slate-f2zu.14.34.6.
