# slate-tsiw pp seed_standard_predefines: gcc defines __STDC_UTF_16__ and __STDC_UTF_32__ before C11

_2026-11-18 17:48:34_

- bead: slate-tsiw
- kind: bug
- area: crates/slate-parser/src/pp/mod.rs
- flavor: gcc

Outcome: the gcc flavor no longer defines `__STDC_UTF_16__`/`__STDC_UTF_32__` before C11, except under `-std=gnu99`, matching gcc 16.

Symptom: `slate-parser pp --flavor=gcc -std=c99` saw both macros defined; gcc prints nothing for c89, gnu89 and c99, and defines them for gnu99, c11 and later. clang defines them in every mode, so clang is untouched.

Reproducer:
```c
#ifdef __STDC_UTF_16__
yes
#endif
```

Cause: the gcc predefine header lists the macros unconditionally; `seed_standard_predefines` (pp/mod.rs) removes standard-dependent macros but did not cover these.

Fix: in `seed_standard_predefines`, for the gcc flavor with `!at_least_c11()` and standard other than `Gnu99`, remove both macros (same removal pattern as `__STRICT_ANSI__` and `__BOOL_DEFINED`). gcc's rule was derived by probing c89/gnu89/c99/gnu99/c11/gnu11/c23 and iso9899:199409.

Fixtures: `gcc/linux/x86_64/utf_macros_before_c11.c` (`-std=c99`) and `utf_macros_gnu99.c`.
