# Generate CLIB_RECORD_TYPES from header/libc layout probes

_2026-11-02 16:26:39_

slate-yar4.11: new crate slate-libc-gen. C side: slate-parser ir -include <header> per target/header gives record size/align/offsets (incomplete records and typedef-to-record included, record_name kept for aliases like macOS _opaque_pthread_attr_t). Rust side: per-target probe crate over crates/slate/vendor/libc reads size_of/align_of/offset_of! from the emitted object. A name enters the table only if every target where C defines it has a matching libc type; reserved (_-prefixed) fields are ignored unless aggregate and unmirrored; no common public field => opaque. FILE aliases are suppressed (macros reach _IO_FILE members). Output: backend/clib_records_table.rs (124 names, 12 targets: linux gnu x4, musl x2, apple x2, freebsd x2, android x2), included from rust_ast.rs; CLibType::FILE replaces CLIB_RECORD_TYPES[0] in printf_format.rs. Fixtures regenerated: c23_library, gnu_libc_platform, pointer_compare_address (tm -> slate_support::tm). slate profile green before regen. Not run: corpus sweeps.
