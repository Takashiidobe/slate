# classify_conversion decides every conversion on C types

_2026-09-19 19:13:28_

slate-parser-9ve.3. Conversion legality moved off ir::Type and onto the C type
layer. New src/sema/ctype/compat.rs (compatible/composite per 6.2.7) and
src/sema/ctype/convert.rs (classify_conversion -> CastKind + optional warning).
Lowerer::convert now classifies then emits; emit_cast only emits the kind it is
handed, so nothing is accepted merely because no rule rejected it. Deleted
pointer_conversion_warning, differ_only_in_sign, differ_only_in_nested_qualifiers,
compatible_ignoring_qualifiers, Lowerer::is_record and the old emit_convert pair.

Oracle (clang 22.1.8 / gcc 16.2.1 / cl.exe 14.51) settled the severities: MSVC
only warns on every incompatible-pointer and int/pointer case that clang and gcc
reject, so by the consensus rule all of them are accept-with-warning. That
reverses the ir-spec claim that unsigned* -> long* and unsigned** -> int** "stay
errors, as in clang 22", and reverses slate-parser-hdt: dropping _Atomic from a
pointee warns rather than errors. New warnings: int-conversion,
incompatible-pointer-types, pointer-integer-compare, compare-distinct-pointer-types.

Where all three compilers agree, we reject: 6.3.2.1p1 modifiable lvalues are now
enforced on =, compound assignment and ++/-- (const lvalue, array, or a struct
with a recursively const member).

Conditional operator now builds a real composite type. 6.5.15p6's null-pointer-
constant rule beats the void* rule, so c?(int*)0:(void*)0 is int*, not void* --
checked against clang and gcc with _Generic, which caught the first attempt.

Comparing on C types while emitting on layout has one trap worth remembering:
CastKind::Identity must still emit an arithmetic conversion when the two layouts
differ, because truth() makes a bool-typed value whose C type is int.

Regenerating every fixture changed none of them; the five new fixtures are the
only additions. Closed 4o9 and hdt. Filed zm8 (& on a register variable, needs
storage-class tracking). types::compatible over ir::Type survives for
function redeclaration until 9ve.4.
