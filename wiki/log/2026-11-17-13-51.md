# slate-yar4.43 deref_nullptr: indexing a null constant (PlaceKind::Index) lowers through add/offset, which rustc does not lint

_2026-11-17 13:51:23_

- bead: slate-yar4.43
- kind: bug
- area: crates/slate/tests/fixtures

Outcome: slate-yar4.43 does not reproduce. rustc's deref_nullptr lint fires only on a direct `*null_mut()` (or a deref of a null cast). Indexing a null constant always lowers through `.add(n)`/`.offset(i)`, which the lint does not inspect, so no `#![allow(deref_nullptr)]` is needed for PlaceKind::Index. The fixture now guards this case.

Symptom claimed by the bead: `if (p) p[i] = v` in a macro called with `(int *)NULL` would be rejected under deny(deref_nullptr).

Reproducer (now in crates/slate/tests/fixtures/null_deref_macro_args.c):

```c
#define STORE(p, i, v) do { if (p) (p)[i] = (v); } while (0)
static void store_null(int i) { STORE((int *)NULL, i, 4); STORE((int *)NULL, 0, 4); }
```

Lowered body: `unsafe { *$p .offset(($i) as isize) = $v; }`, invoked with `core::ptr::null_mut::< i32 > ()`. rustc 2024 compiles it without the allow.

Also checked with the allow stripped from the output (all compile):
- `((int *)0)[0] = 3` gives `*core::ptr::null_mut::<i32>().add(0) = 3`
- `((row *)0)[i][1]`, `((struct s *)0)[0].x`, `((struct s *)NULL)[i].y[0]`

The only rejected form among the probes was `(p)->y[i]`, which is a PlaceKind::Deref of the null base and is already flagged by places::is_null_constant (slate-f2zu.14.30).

Limits: if a rewrite ever folds `.add(0)` into a plain `*p`, the STORE(…, 0, …) case would fail to compile and show it.

See: slate-f2zu.14.30.
