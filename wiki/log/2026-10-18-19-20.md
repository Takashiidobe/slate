# Project-wide interproc solve in app mode (slate-o3gw.14)

_2026-10-18 19:20:19_

translate-project now lowers units in parallel, runs interproc once over all units (backend::apply_interprocedural), then runs the per-function engine per unit in parallel (backend::apply_local). Single-file translate is unchanged (engine::apply = interproc over one program + apply_local).

Symbols::resolve links a unit's extern fn decl to the unique #[no_mangle] definition in another unit (decls with link_name are not linked).

Exports::Liftable (executable projects) makes non-root exported definitions pointer_lattice candidates. A root keeps its C signature: main, address-taken symbols (frontend taken_functions mapped to External symbols via distinct_functions::address_taken_symbols), libc-named symbols (Known::from_symbol), symbols with duplicate exported definitions, unsafe or non-C-unwind defs, any attr besides NoMangle/Inline/Cold/MustUse/Deprecated/Allow (export_name/weak/link_section/shim targets), names in global_asm templates, link_name decl targets, and defs some decl declares variadic, with another arity, or with a non-pointer where the def has a pointer.

Exports::Fixed (libraries, single-file) keeps today's statics-only behavior. Only &T/&mut T/Box lifts cross units: length_lattice gets facts without the exported bindings, so fat lifts stay static-only. apply_plans retypes callers' extern decl params with each unit's own pointee type.

release_build_differential now checks an optional per-unit SLATE-FILECHECK block against that unit's generated file and writes a runtime-ok marker; update_filecheck.py accepts fixtures.release paths. New fixture: fixtures.release/cross_unit_pointer_lift.

Verification: snapshot of 2752 single files byte-identical; 10 projects changed (fixtures.multi pointer readers, sqlite: shell's sqlite3_qrf_decode_utf8 and sqlite3_memory_alarm). slate profile 20/20; sqlite benchmark passes, Rust/Clang 1.02/1.03/0.98.
