# Probe getopt.h/sys/timeb.h/sys/param.h/sys/random.h odds-and-ends; fix glibc optreset leak

_2026-09-08 09:16:50_

(slate-b66b.13.11) Added struct option (getopt.h) and struct timeb
(sys/timeb.h) size/align/offset probes, plus MACRO checks for sys/param.h
constants (NBBY/MAXPATHLEN/MAXHOSTNAMELEN/MAXSYMLINKS/NOFILE/DEV_BSIZE/
NOGROUP) and sys/random.h's GRND_* flags, to
tools/probes/linux-libc-abi.c's new emit_odds_and_ends().

Found a real bug while comparing getopt.h against real headers:
libc-shim/include/getopt.h and unistd.h both unconditionally declared
`extern int optreset;`. optreset is a BSD-heritage symbol (FreeBSD, Darwin,
musl all have it) that glibc genuinely does not declare -- confirmed
against /usr/include/bits/getopt_core.h, which has optarg/optind/opterr/
optopt but no optreset. Code checking for symbol non-visibility on the
glibc profile (the negative-compile harness slate-khfh.1 is meant to
verify this kind of thing) would have silently passed against the shim.
Gated both declarations behind `!defined(__SLATE_LIBC_GLIBC)` rather than
`defined(__SLATE_LIBC_MUSL)`, since unistd.h/getopt.h are shared across the
FreeBSD/Darwin profiles too and those genuinely have optreset.

struct option, struct timeb, and all probed sys/param.h/sys/random.h
values already matched both real glibc and musl exactly -- glibc's
sys/param.h derives MAXPATHLEN etc. from limits.h (PATH_MAX etc.) but the
resulting values coincide with musl's hardcoded literals on Linux, which
the shim already used unconditionally.

Verified: tools/libc-abi-matrix.py green across all 4 arches x 2 libcs,
cargo nextest --profile libc 37/37 (including unaffected FreeBSD/Darwin/
MSVC header-manifest tests, since unistd.h/getopt.h are shared).
