_2026-10-31 14:57:01_

slate-nfq8.8: profiled --merge on zlib, 16 targets. Wall time by phase was prepare 33s, compile 35s, everything after 3s, so the merge itself was never the cost: merge_unit, minimize and prime_implicants are under 0.3% of CPU. Changes: Mode::Relevant in project_plan.rs skips select's parse and sema and the element keys, since merge only reads relevant and error. Targets prepare in parallel. PreprocessTrace closure re-walked the graph per conditional in every run, 11% of CPU; RootFeatures in pp/trace.rs memoizes per context, branch and event, relying on reads only referring to earlier events. It matched closure on every query across all 16 targets before closure's conditional path was removed. pp/lexed.rs reuses lexed tokens per source text, features and charset, 18% of CPU. It is per thread because Token is not Send, and opt-in through reuse_lexed_sources so single-file translation and corpus sweeps hold nothing. Span::rehomed sets the file and a fresh NodeId when a token is read. signatures::check now runs before place_sections, which moves program items instead of cloning. Results, 3 interleaved hyperfine rounds: 16 targets 75.1s to 43.5s wall, 359s to 220s CPU, 6.67 to 4.27 GiB; 1 target 3.8s to 2.4s. Phases after: prepare 10s, compile 29s. Scaling: near-linear in targets and units.
