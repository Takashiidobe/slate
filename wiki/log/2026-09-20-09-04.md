# Lower the floating classification builtins

_2026-09-20 09:04:09_

First tranche of slate-parser-dyd.19, the CustomTypeChecking builtins that
get no signature from the typed prototype model.

Added `ValueKind::FloatClass { test, operand }` with `FloatClassTest`
(nan, infinite, finite, normal, subnormal, zero, signaling, sign_bit),
printed `float_class<bool, test=nan>(x)`. It results in bool, so the
int-returning builtins wrap it in the existing `from_bool<int>` promotion.

Dispatch is registry-driven: `builtins::custom_builtin` maps a tblgen record
to a typed `CustomBuiltin`, so the lowering site matches an enum instead of
builtin spellings. The pre-existing add/sub/mul overflow special case moved
onto the same dispatch.

Covered: isnan, isinf, isfinite, isnormal, issubnormal, iszero, issignaling,
signbit(f/l), isinf_sign, isunordered, isgreater, isgreaterequal, isless,
islessequal, islessgreater, __builtin_complex.

Two semantics worth recording:
- `isunordered` and `islessgreater` combine two tests with a bitwise
  `or<int>`, not `logical_or`. `logical_or` short-circuits and gets hoisted
  into an `if` when an operand has effects, but both operands of these
  builtins are always evaluated.
- `islessgreater` is `lt | gt`, not `ne`. IEEE `ne` is true for NaN, and
  `islessgreater(NaN, x)` must be false.
- `__builtin_complex(re, im)` needs no new IR: it is the same
  `aggregate<complex<T>>` a complex value gets anywhere else.

Corpus IR sweep 2324/2674 -> 2345/2674, 0 regressions. Remaining
CustomTypeChecking builtins are the elementwise family (4 configurations),
assume_aligned, nondeterministic_value, classify_type, addressof, clzg.
