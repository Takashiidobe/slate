# Corpus: per-flavor compile databases and a committed sweep tool (6x05.11, 6x05.1)

_2026-09-30 14:40:45_

- tools/c_corpus_setup.py: a recipe per ~/c-corpus project writes
  build-{gcc,msvc,clang}/compile_commands.json and runs the full build so
  generated sources exist. CMake out of tree (Ninja), autoconf out of tree
  and Makefile-only in tree under bear; msvc through msvc-wine (CMake with
  CMAKE_SYSTEM_NAME=Windows, sqlite via nmake with the database parsed from
  its log). msvc only where upstream ships a Windows build.
- Why: every old database came from cc (gcc), and mbedtls's 161 clang-rejects
  were unbuilt generated sources (its generators need jsonschema/jinja2, now
  in ~/c-corpus/.venv). clang-rejects is now 0 in every project.
- tools/c_corpus_sweep.py: reads build-clang, clang -fsyntax-only oracle,
  statuses ok/internal/unimplemented/rejected/timeout/missing-dependency/
  clang-rejects, target/c-corpus-sweep.{md,json}, --trophies. Full run 5m07s.
- Missing third-party headers (crypt.h, systemd, bzlib, readline) are
  missing-dependency, not slate failures; the corpus zlib is appended as
  -idirafter and libpng builds against it.
- Gotchas: clang demotes a dir given as both -I and -idirafter to a system
  dir (broke zlib's own TUs); don't export CC=cl (mbedtls runs host probes
  with $CC); CMAKE_CXX_COMPILER breaks zstd's flag checks; nmake needs /I
  and a relative TOP under Wine.
- pp_diff.kept_args also keeps -idirafter and -imacros.
- Trophy case regenerated: adds Mbed TLS (367/367); PCRE2 drops out
  (pcre2grep/pcre2test need bzlib.h/readline, missing-dependency).
- New beads: 6x05.12 (offsetof through anonymous members), 6x05.13
  (transparent_union parameters in function type compatibility).
- Wiki: new concepts/c-corpus.md, linked from architecture.md, index, CLAUDE.md.
