# slate-f2zu.14.23 VaCopy lowering: va_copy through raw pointer deref outside unsafe in kept template (E0133)

_2026-11-14 18:57:38_

- bead: slate-f2zu.14.23
- kind: bug
- flavor: clang
- area: crates/slate/src/frontend/lowerer/statements.rs

Outcome: `va_copy` from a source that needs unsafe (for example `*vaf->va`)
wraps the raw-pointer clone in `unsafe { }`, so kept `va_copy` templates
compile.

Symptom: linux vsprintf.rs:3347, xhci_trace.rs:2823
`$d = (*std::ptr::addr_of_mut!($s)).clone();` dereference of raw pointer is
unsafe (E0133).

Reproducer:

```c
#define va_copy(d, s) __builtin_va_copy(d, s)
struct va_format { const char *fmt; va_list *va; };
static void emit(struct va_format *vaf) {
  va_list va; va_copy(va, *vaf->va); vprintf(vaf->fmt, va); va_end(va);
}
```

Cause: `ValueKind::VaCopy` in lowerer/statements.rs built
`clone_va_list(through_raw_pointer(source))` for an unsafe source with no unsafe
block. A kept macro template gets no surrounding unsafe, and the call-site
argument `*unsafe { (*vaf).va }` also needs to sit inside one.

Fix: wrap that expression in `Expr::Unsafe`. Macro unsafety is unhygienic, so
the block also covers the `$s` fragment.

Regression test: crates/slate/tests/fixtures/va_copy_macro_through_pointer.c
