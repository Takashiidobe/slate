# Gate Owned pointer bridging on heap provenance (y0qs.4.9)

_2026-08-28 20:07:20_

Fixed the soundness gap filed as slate-y0qs.4.9: pointer_lattice's
arg_is_provably_bridgeable() accepted any bare-Var call argument as
bridgeable into Box<T> for an Owned-kind param, regardless of the
argument's provenance in the caller. A shared helper whose param gets
promoted to Owned (unique+free from merge_evidence_from's whole-program
merge) could then unsoundly wrap a stack address in Box::from_raw if a
caller passed it as a plain variable (not &expr) -- e.g. `int *p =
&local; h(p);`.

Fix: added collect_heap_locals(), a walk over each function body that
records local variable names directly assigned from a Known::Malloc /
Calloc / Realloc call (via let or plain assignment). validate_plans()
now builds one heap-locals set per function up front and threads it
into arg_is_provably_bridgeable(): for Owned-kind params, a bare-Var
argument only counts as bridgeable when the caller's own lift plan
covers it (unchanged) OR the var is a heap-local in that specific
caller. Any other bare Var (stack address stored in a local, unknown
provenance) now fails validation and the plan is dropped for that
param, falling back to the raw-pointer representation.

Added tests/fixtures/ptr_lattice_shared_helper_mixed_provenance.c: one
helper called once with a stack address and once with a malloc'd
pointer. Confirmed pre-fix this would have unsoundly lifted; post-fix
the helper stays a raw pointer and free() is preserved. Full rewrites
profile (110/110) green on rerun (one flaky test-cache-related failure
on first run, unrelated -- passed clean on --no-fail-fast rerun),
fmt/clippy clean.
