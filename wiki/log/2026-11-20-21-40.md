# slate-8ge7.15 slate-analysis pointer: inline asm is an opaque call over its operands; &x call-site proofs reject leaked automatic objects and mutable static arrays

_2026-11-20 21:40:16_

- bead: slate-8ge7.15
- kind: bug
- area: crates/slate-analysis/src/pointer.rs
- area: crates/slate/tests/fixtures
- area: wiki/concepts/slate-analysis.md

Outcome: inline asm is an opaque call over its operands, so params used by asm only through their pointee lift again; and the call-site proof for `&x` now rejects objects whose address leaks elsewhere in the caller, which closes an existing unsoundness.

Symptom (soundness, found first): `f(&x)` lifted `f`'s parameter to `&T`/`&mut T` even when the caller also leaked `x`'s address: `g = &x; bump(&x);` gave `bump(p: &i32)` while `poke()` wrote `x` through `g`. The same happened with `stash(&x)` storing into a global, `q = id(&y); two(&y, q)` (a returned param) and `r = &w; two(&w, r)` (a local alias).

Reproducer:
```c
static int *g;
static void poke(void) { *g += 100; }
static int bump(int *p) { int b = *p; poke(); return *p - b; }
int main(void) { int x = 1; g = &x; return bump(&x); }
```

Cause: `Walker::proven` accepted `AddressOf(Binding)` of any automatic object; `CallSite.objects` only fed the two-arguments-alias check.

Fix (crates/slate-analysis/src/pointer.rs):
- `Walker.leaked` collects automatic objects whose address goes anywhere except straight into a call argument: `assign` into a pointer node, `mark(.., ESCAPE)` (stores, unknown calls, aggregates, conversions, intrinsics), asm operand places, OpenMP/nested functions.
- In `analyze`, an object passed to a callee parameter whose class escapes or reaches a Return node (`returned`, propagated over the backward edges) also leaks; this uses the callee's summary even when the callee is not a candidate. Every candidate parameter that receives a leaked automatic object is `pinned` (unproven), whatever the length proof says.
- `Walker::shape` accepts an array decay as a length proof only for automatic arrays and `const` statics (`constants`). A mutable static is reachable by name during the call, so `sum(counts, 4)` stays raw; the finer rule is slate-8ge7.16.
- `Statement::Asm` no longer runs `escape_all`. `Walker::asm` walks operands: a tracked pointer value input escapes (WRITE|ESCAPE) unless the template is empty; `InPlace`/`Out`/`InOut`/`Memory` places are reads/writes; a pointer-typed place escapes when read and is raw when written.

After (x86_64): incl(p: &mut i32), narrow_output(out: &mut u32), sincos(s, c: &mut f64), swap_through_rbx(out_rcx: &mut u64), asm_folded_size_dispatch zero_*/load_*/pick(p: &T), load_g__const5(p: &u32), add_rm(p: &i32), asm_barriers input_barrier(&[u8]) / no_unroll(&[f32]) with the barrier keeping `p.as_ptr()`; aarch64 atomic_increment(counter: &mut i32) (`"+Q"(*counter)`). load(dtr) and try_store stay raw (`"r"(dtr)`, `"D"(lock)`, `"d"(pop)` are pointer values in a real template).

Losses from the leak rule (correct under it, flow-insensitive): bump in asm_memory_operand_write (main also passes &value to store's escaping `"r"(p)`), returned-param helpers (get, pair_lo/hi, pick, inner_of, choose_value, once, next_slot), callers that alias or stash the object (field_address_places, cross_unit_pointer_lift via counter_apply's indirect call, cross_unit_shared_types via registry_add, x86_header_expanded_builtins ia through intrinsics, libc_* fixtures, struct_field_2d_array, update_results, ptr_*).

Regression tests: crates/slate/tests/fixtures/pointer_lift_leaked_object.c, crates/slate/tests/fixtures/pointer_lift_static_array.c; the asm fixtures above.

Limits: leaks are flow-insensitive and ignore that a shared borrow is only harmed by writes through the alias during the call, so read-only callees lose lifts they could keep. Pre-existing `mut p` on params used in asm is unchanged.
