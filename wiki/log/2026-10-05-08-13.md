# Machine modes on enum definitions

_2026-10-05 08:13:06_

slate-parser-6x05.40: __attribute__((mode(M))) on an enum definition was ignored, so mode(byte) enums stayed 4 bytes.

Fix (sema/types.rs, TagBody::Enum): after the underlying type is chosen, a Mode attribute on the tag replaces it through machine_mode, so it wins over packed.
- clang flavor: mode applies to int, or the fixed type, so the result is signed unless the fixed type is unsigned. Values may overflow. When enumerators take the enum type (some value does not fit int), their values wrap to the enum width with WideInt::wrap, matching clang's extOrTrunc ({ 300, 0x80000000u } mode(QI) gives 44 and 0). Before this, the IR printed const<enum i8>(300).
- gcc and msvc flavors: mode applies to the value-derived type (unsigned unless some value is negative). Values that do not fit are rejected ('specified mode too small for enumerated values'). A fixed type ignores mode, as gcc does with a warning.
- A float mode (SF) is rejected by machine_mode in both flavors, like the oracles.

Fixtures (all failed before): clang/linux/x86_64/ir_enum_machine_mode.c, gcc/linux/x86_64/ir_enum_machine_mode.c, error/gcc/linux/x86_64/enum-mode-too-small.c. Regenerated both gcc-dg enum-incomplete-2.c copies (e7/e8, e11/e12 and the packed+mode e9/e10).
