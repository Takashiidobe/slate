# Dedupe Arena-subtree helpers across rewrite-engine rules

_2026-09-04 12:44:17_

Follow-up to the walk.rs expr-fold dedup. Found 3 more exact/near-exact duplicated tree-walkers in src/backend/engine/rules/: function_root (byte-identical in raw_ptr_alias.rs and inline_temps.rs), the node_substitute_var recursion skeleton (identical get_mut+recurse-into-children shape in both files -- only each file's own kind_own_substitute_var per-kind body differed, e.g. inline_temps.rs substitutes inside InlineAsm operands, raw_ptr_alias.rs conservatively bails with false), and remove_from_parent (identical in param_spills.rs and raw_ptr_alias.rs, differing only in bool vs unit return).

Added function_root, remove_from_parent, and substitute_var_in_subtree (parameterized over a caller-supplied kind_own_substitute_var closure, so each rule keeps its own per-kind substitution policy verbatim) to walk.rs; all three call sites now share one implementation instead of three.

Also deduped array_iter.rs's array_index_target/replace_index_use: both hand-rolled the same narrow Expr traversal (Binary/Unary-like/Call/MethodCall/Field/Index only -- deliberately narrower than walk.rs's child_exprs, so NOT swapped for the shared walker since that would broaden what the rule matches). Extracted index_search_children/_mut locally to array_iter.rs so the traversal order is defined once.

Verified no behavior change: cargo build/clippy clean, cargo nextest r --release --profile rewrites 93/93 passed both before and after. Explicitly left raw_ptr_alias.rs's kind_only_deref_uses alone despite looking like it should fold onto walk::visit_kind_exprs -- it hardcodes NodeKind::InlineAsm => false and Loop/Scope/LabeledBlock/Break/Continue => true, which are load-bearing conservative-when-uncertain gates, not generic traversal; genericizing them would risk silently loosening the rewrite's safety precondition.
