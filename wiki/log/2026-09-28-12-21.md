# Keep __vectorcall on x86-64

_2026-09-28 12:21:18_

slate-parser-1yuw. clang and cl.exe honour __vectorcall on x86-64 (x86_vectorcallcc on both -linux-gnu and -windows-msvc, vc@@N decoration on windows) while ignoring stdcall/fastcall/thiscall there; slate dropped all four outside 32-bit x86, so _Generic/__builtin_types_compatible_p and pointer conversions treated a vectorcall function as plain.

- src/sema/types.rs calling_convention: on X86_64 keep Vectorcall (and Cdecl = C), ignore the other three; AArch64/Arm32 ignore all.
- The ABI still prints platform shapes (sysv64/win64) with the vectorcall calling tag. Verified clang vs rustc: clang linux vectorcall uses SysV, clang windows puts HVAs in XMM, rustc extern "vectorcall" uses win64 without HVAs on both, so shapes diverge -> slate-parser-x74n (also notes clang's variadic-vectorcall error, which slate drops permissively).
- Fixtures: clang/{linux,windows}/x86_64/calling_convention_vectorcall.c, error/clang/linux/x86_64/calling_convention_vectorcall_pointer_mismatch.c; regenerated c23-vendor-attributes, calling_conventions_gnu, msvc/linux calling_conventions, and both calling-conv-ignored suite fixtures (upstream X64 CHECK expects x86_vectorcallcc).
- Docs: ir-spec x86 calling conventions paragraph, c-type-layer, ast-spec.
