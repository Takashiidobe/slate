# Arm ISA flags drive predefines and the arm32 float ABI

_2026-09-19 09:30:45_

slate-parser-d2e. TargetInfo.x86_isa became TargetInfo.isa: TargetIsa (src/target/isa.rs) with X86/AArch64/Arm variants. It resolves once, in CompilerArgParser::parse (a target rule calls the same resolve to report errors), instead of going through LayoutOptions/effective_target. -march is parsed family-neutrally (March::{X86, Arm}); resolve rejects a value for the wrong family.

AArch64 (src/target/aarch64_isa.rs): armv8-a..armv9.6-a plus curated +ext/+noext (simd fp fp16 crc crypto aes sha2 lse dotprod sve sve2 bf16 i8mm) and -msve-vector-bits. Clang behavior I found by probing (clang 22), which isn't obvious:
- QRDMX/COMPLEX/JCVT/FRINT follow the version, not a feature. armv9.x = armv8.(x+5) + fp16/sve/sve2, and 9.4+ adds sve2p1.
- Enable and disable closures differ: dotprod/bf16/i8mm/aes/sha2/crypto re-enable simd; nosimd drops them.
- Explicitly enabling fp16 also enables fp16fml, but only on armv8.4-8.9 (not v9); that is also how +sve re-enables NEON after +nosimd there.
- __ARM_FEATURE_SVE and the SVE_BF16/SVE_MATMUL variants need sve && simd, so +nosimd hides SVE but keeps SVE2.
- +aes+sha2 forms an implicit pair (CRYPTO macro, no SHA3). Disabling either half of a pair, or +nocrypto, drops both; an unpaired +aes survives +nosha2. +crypto adds SHA3/SHA512/SM3/SM4 on v8.4+. Modeled with a hidden CryptoPair bit.
The aapcs64 ABI of GNU vectors, floats, and HFAs doesn't change under any of these flags (checked against IR), so AArch64 is predefines only.

Arm32 (src/target/arm_isa.rs): -march armv7-a/armv8-a (no modifiers), -mfpu (10 values), -mfloat-abi, -mthumb/-marm. The default FPU is neon on v7 and crypto-neon-fp-armv8 on v8; the default float ABI comes from the triple. abi.rs now picks aapcs32_hard_float from the resolved float ABI rather than TargetEnvironment::GnuEabiHf. __SOFTFP__ = soft || (fpu none && abi != hard).

Headers: removed __ARM_ARCH/__ARM_FP/__ARM_NEON/__ARM_NEON_FP from the clang aarch64 linux+windows headers, and the FPU/arch/PCS macros from both armv7 headers.
Checked against clang -dM on 1333 Arm combinations (352 arm32 exhaustive, 621 aarch64 version x single/pair modifiers, 300 random 3-modifier chains, 60 windows): 0 mismatches. x86 still 34/34.
