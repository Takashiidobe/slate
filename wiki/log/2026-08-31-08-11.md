# Implement FreeBSD time and signal ABI

_2026-08-31 08:11:58_

Implemented slate-sfzn.10.5. CLOCKS_PER_SEC=128 on FreeBSD (not 1000000
like glibc/Darwin) -- caught from the oracle header, would have guessed
wrong. Modeled the full real clock-ID set in bits/freebsd/time.h including
FreeBSD-only IDs the ticket named (CLOCK_UPTIME=5, CLOCK_UPTIME_PRECISE=7,
CLOCK_UPTIME_FAST=8, CLOCK_SECOND=13) plus Linux-compat aliases
(CLOCK_BOOTTIME etc). time.h/sys/time.h are self-contained overlays like
Darwin's, not gated branches, since the surface diverges too much from
glibc for readable per-line gating.

sigset_t (bits/types.h) is FreeBSD's real struct{unsigned int __bits[4]}
-- 16 bytes/128 signal numbers, distinct from both glibc's 128-byte mask
and Darwin's plain 4-byte mask. This was the actual gap: FreeBSD
previously fell through to the generic glibc-shaped __sigset_t branch.

Signal numbers 1-33 match Darwin exactly, plus FreeBSD-only SIGTHR=32/
SIGLIBRT=33 and realtime range SIGRTMIN=65/SIGRTMAX=126 that Darwin lacks.
struct sigaction is 32 bytes with sa_flags at offset 8 and sigset_t
sa_mask at offset 12 -- field order is sa_flags-before-sa_mask, the
reverse of Darwin's sa_mask-before-sa_flags. siginfo_t is 80 bytes:
si_signo/si_errno/si_code/si_pid/si_uid/si_status/si_addr/si_value at
0/4/8/12/16/20/24/32, then a 40-byte _reason union modeled as
long+int[7] rather than every signal-specific sub-union (out of scope).
All offsets verified via offsetof _Static_assert against the oracle
sysroot for both x86_64 and aarch64 -- identical on both since this is
straight LP64 layout.

ILL_* code numbering genuinely diverges from Darwin's own permutation of
the same names (FreeBSD: ILL_ILLOPC=1,ILL_ILLOPN=2,ILL_ILLADR=3,
ILL_ILLTRP=4; Darwin swaps ILL_ILLTRP/ILL_PRVOPC earlier) -- caught by
diffing the oracle, would have been wrong if copied from Darwin's block
uncritically (I actually wrote it wrong on the first pass, copying
Darwin's order, and caught it comparing against the oracle grep before
running any tests). FPE_*/SEGV_*/BUS_*/TRAP_*/CLD_*/POLL_*/SI_* all
matched Darwin's values exactly. MINSIGSTKSZ is architecture-dependent
(2048 on x86_64, 4096 on aarch64, read from the real per-arch
machine/_limits.h), unlike Darwin's single fixed 32768.

New libc-shim/freebsd-time-signal-headers.txt manifest and
freebsd_time_signal_header_manifest_compiles_for_x86_64_and_aarch64 test
in tests/header_compilation.rs with offsetof/sizeof static asserts for
sigset_t/siginfo_t/sigaction and every clock-ID/signal-number/ILL_* value
checked.

Verified end-to-end: slate translate on a fixture exercising
clock_gettime/gettimeofday/sigaction+sigemptyset+raise with an SA_SIGINFO
handler, both x86_64/aarch64-unknown-freebsd -- generated struct layouts
match oracle-verified offsets exactly; cargo check --target
{x86_64,aarch64}-unknown-freebsd clean with zero warnings (not even the
usual improper_ctypes noise, since no opaque-struct FFI here). cargo
fmt/clippy clean; nextest --profile libc 27/27, --profile lowering 10/10,
no regressions.
