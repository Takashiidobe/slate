# slate-gbgp.8 libc_call is_reassigned: strcmp folded a char* local to its literal init although &local escaped to an out-param call

_2026-11-13 23:30:59_

- bead: slate-gbgp.8
- kind: bug
- area: crates/slate/src/backend/engine/rules/libc_call.rs
- area: crates/slate/src/backend/engine/rules/slot_promote.rs

Outcome: libc-call rewrites (`strcmp`/`strlen`/... -> `str` ops) no longer fold a `char *` local to its string-literal initializer once the local's address is taken anywhere in the function.

Symptom: NumPy `test_multiarray.py::TestDevice::test_to_device` (the only failure, 14871/14872) raised `Unsupported device: cpu. Only 'cpu' is accepted.` `array_to_device` (numpy/_core/src/multiarray/array_api_standard.c) does `char *device = ""; PyArg_ParseTupleAndKeywords(..., &device, ...); strcmp(device, "cpu")`, which was emitted as `"".cmp("cpu")`.

Reproducer:

```c
extern int fill(char **out);
int check(void) {
    char *device = "";
    if (!fill(&device)) return -1;
    return strcmp(device, "cpu") != 0;
}
```

Before: `if (unsafe { "".cmp("cpu") as i32 }) != 0`. After: a real `strcmp(device, c"cpu")` call.

Cause: `CallCtx::is_reassigned` (backend/engine/rules/libc_call.rs) only counted `Assign`/`CompoundAssign` to the local. `addr_of_mut!(device)`, `&mut device` (after the interproc pointer lift) and `addr_of!(device)` handed out a pointer the callee writes through, so `resolve_const_str`, `resolve_lifted` and `resolve_local_array` all followed the stale `Let` init.

Fix: `is_reassigned` also returns true for any def-use neighbor where `kind_takes_address` (now `pub(super)` in slot_promote.rs) finds `AddrOf`/`Ref` of the local or inline asm. Immutable `&`/`addr_of!` count too, since C casts away const.

Regression test: `crates/slate/tests/fixtures/strcmp_literal_local_address_escapes.c` (strcmp through `char **` out-param, `const char **` retarget, strlen after an out-param write).

See: slate-gbgp.8, slate-dghn.58.4.
