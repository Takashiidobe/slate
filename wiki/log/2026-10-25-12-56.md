# Emulate cl.exe /Gd /Gr /Gz /Gv default calling convention

_2026-10-25 12:56:41_

slate-3amj.5.8: /Gd /Gr /Gz /Gv set TargetAbi::default_convention (target_info.rs) from compiler_args.rs; two different ones are rejected ('/Gr: incompatible with /Gz', cl D8016). On x64 only /Gv applies. New function types without an explicit convention take the default (TypeResolver::default_convention, sema/types.rs), including K&R, unprototyped, typedef'd and implicit declarations (CTypes::implicit_function now takes the convention); variadics and main/wmain stay cdecl. An explicit __stdcall/__fastcall/__thiscall on x64 now resolves to cdecl so it overrides /Gv, as cl does. All probe cases checked against cl.exe 19.51. Parser fixtures: msvc/windows/i686/default_convention_{stdcall,fastcall}.c, msvc/windows/x86_64/default_convention_{vectorcall,x86_only}.c, error/msvc/windows/i686/default_convention_conflict.c. Promoted slate fixtures msvc/{i686,x86_64}/flag_msvc_*_default.c. Follow-up: WinMain/wWinMain/DllMain implicit stdcall on x86 filed under slate-3amj.5.
