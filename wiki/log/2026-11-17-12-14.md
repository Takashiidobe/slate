# slate-5q63.16 test speed: translate-project rewrote unchanged files and tests wiped cargo target dirs, so every slate run recompiled libc and build-std core

_2026-11-17 12:14:39_

- bead: slate-5q63.16
- kind: bug
- area: crates/slate/src/main.rs
- area: crates/slate/src/backend/format.rs
- area: crates/slate/tests

Outcome: the slate nextest profile runs in about 58s on a no-change run (was 179s), with no test over 43s.

Symptom: merge_filecheck 98-124s, freestanding_* tests ~90s each,
build_filecheck 136s, release_build/dylink/library differentials 75-98s on
runs where nothing changed.

Cause (verified by tracing execve and cargo fingerprint logs):
- translate-project rewrote every file, including the 443-file vendored libc,
  so cargo saw new mtimes and recompiled libc and friends for every project
  crate on every run (release 38/44, dylink 21/34, library 16/23 crates).
- The generated link-arg build.rs (`-z nostart-stop-gc`) printed no
  rerun-if-changed, so any newer file in the package (the Cargo.lock cargo
  regenerates after a wiped crate) reran it and relinked the bin. In
  merge_filecheck that was every feature-set `cargo run` (~280 rustc runs).
- Arch-mode tests removed the work dir that held CARGO_TARGET_DIR, so build-std
  rebuilt core/compiler_builtins for each of 5 bare-metal crates every run.
- merge_filecheck used 4 per-worker target dirs with dynamic fixture
  assignment; matrix tests built in crate_dir/target, which was wiped.

Fix:
- `backend::write_if_changed` (format.rs); `write_file` in main.rs,
  `build_target::write`, `write_rust`/`write_pretty_rust`, Cargo.toml, bitint,
  num-complex and shim writes all skip unchanged content. Re-translating a real
  project is now incremental for cargo too.
- Link-arg build.rs prints `cargo:rerun-if-changed=build.rs`.
- tests/support/fresh_tree.rs: `set_aside` moves the old crate to
  `<dir>.previous`, `keep_unchanged_mtimes` copies mtimes onto byte-identical
  regenerated files. Used by merge, arch-mode, matrix and build_filecheck,
  which still regenerate from scratch so stale files cannot leak into checks.
- Arch-mode target dirs live in test-cache/arch-mode-<work>; matrix in
  test-cache/matrix-<work>; merge per fixture in merge/cargo-targets/<stem>.

Limits: merge_filecheck still ~42s in the profile (31s alone): 82 merges (half
are the SLATE_JOBS=1 determinism pass), ~240 no-op cargo runs and ~270 clang
reference builds. See slate-5q63.11.8 for the trimming ideas.
See: slate-5q63.11, slate-5q63.11.2
