# Match a _Generic type-name controlling operand without lvalue conversion

_2026-09-28 12:33:27_

slate-parser-cxg.6, cluster A (c23-generic-1..4.c). C2y N3260 lets _Generic take a type name as its controlling operand, and gcc and clang accept it in earlier modes. The type is matched as written: _Generic(const int, int: 1, const int: 2) is 2, and void, function and array types (and associations of those types) can be selected.

sema used to lvalue-convert every controlling type inside select_association, and required both the controlling type and association types to have a layout (object_type), so void and int() failed. The lvalue conversion now happens only for an expression operand, at the two call sites (Types::generic_selection for static assertions, generic_selected for IR lowering); the layout checks are gone.

ast-spec.md _Generic paragraph updated. Fixture: c23-generic-4.c under gcc-dg gcc and clang (generic-1/2 expect -pedantic-errors diagnostics and generic-3 needs -Wno-c23-c2y-compat, so -4 is the clean one).
