# slate-8ge7.24.17.2 labeled-blocks sink: shadow check by BindingId, unrelated same-name globals/params/locals no longer block

Outcome: labeled-blocks `sink` refuses to move a goto tail into a block only when the tail references a different binding whose C name the block declares; unrelated globals, parameters and sibling locals with the same name no longer keep the labeled block.

Gap and why it mattered: `Pass::shadows` refused whenever a block-local name matched any global/function name, any parameter, or another local of the same name anywhere in the function, even if the moved tail never touched it. Those functions kept `'block: { ... break 'block; }` in the Rust output.

Before (global_name in the fixture; `int g;` is global, tail writes `other`):
    block %48 { { let g = c; while g > 0 { if g == 5 break %48; g--; } return g; } }
    other = 1; return -1;
After:
    { let g = c; while g > 0 { if g == 5 { other = 1; return -1; } g--; } return g; }

Implementation:
- `PassContext::visible` is now `HashMap<BindingId, String>`: globals and functions, plus enclosing locals and parameters for nested functions. Function ids are needed because `module.functions` is taken out while passes run.
- `labeled_blocks::transform` builds `Pass::bindings` from that map plus this function's parameters and named `Let`s.
- `sink` still refuses on cleanup/VLA/SEH (`names(inner).1`). It calls `shadows(declared, tail)` after `movable`. The `References` visitor collects the bindings the tail reads: places, captures and `Callee::Direct` callees (calls do not go through `binding()`). It then drops the tail's own declarations and refuses when any remaining binding's name is among the block's declared names.
- `Pass::outer`, `parameters` and `locals` are gone.

Fixture: crates/slate/tests/fixtures.transforms/structure-goto,labeled-blocks/shadow_names.c. global_name, param_name and sibling_local now sink. outer_read (reads outer `v`), global_write (writes global `g`) and outer_call (calls `helper()` under `int helper`) still refuse.

Limits: a goto tail sinks only when `else_arm` cannot move it first, which is the loop-nested break case. Straight-line `if (c) goto tail;` was never gated by this check.
