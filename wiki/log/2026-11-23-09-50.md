Outcome: The PlaceKind audit isolated wrong object sizes for complex components, and a guarded-heap probe confirmed its independent use-count check rejects untracked nested reads.

- `sema::object_size::place_designation` handles `Field` but drops `ComplexPart`. For `double _Complex z`, Clang -O2 reports 8 for `__builtin_object_size(&__imag__ z, 3)`; Slate's Clang flavor emits 0. GCC's modes 1 and 3 require 8 for the real component, while optimized Slate Rust reports 16. The native C checks exit 0 in both flavors; generated release Rust exits 40 with the Clang checks and 10 with the GCC checks. See slate-yar4.62.
- `guarded_heap::Cursor::read` counts direct reads. A single direct element read lifts the tested allocation to `Option<Vec<i32>>`. Arithmetic and conditional expressions containing element reads leave `malloc` and `free` intact because `analyze` rejects a mismatch against independent def-use counts.
