# bool-ternary fold rewrite rule

_2026-09-07 15:43:53_

Added src/backend/engine/rules/bool_ternary.rs (BoolTernaryFold, priority 41,
registered in rules/mod.rs). clang CIR lowers `||`/`&&` uniformly through
cir.ternary (never cir.select), even when both operands are pure, so
lower_ternary always emits `let __vN: bool = if cond { true } else { rhs };`
(or the && mirror). Nothing previously folded that back, so short-circuit
chains stayed as nested if/let scaffolding instead of `cond || rhs`.

The rule matches LetIf nodes whose then/else regions are either empty or a
single trivial `let __vM = init; <tail __vM>` binding (safe to inline
unconditionally - single use, no reordering), then classifies the resolved
then/else values: true/false -> cond, false/true -> !cond, true/_ -> cond ||
rhs, _/false -> cond && lhs. Rewrites the LetIf into a plain Let so
LateInlineTemps can keep cascading (multi-way || chains collapse to one
expression).

Also fixed a real bug in tools/update_filecheck.py hit while regenerating
fixtures: it always falls back to default_targets_for_path with no --target,
so target_mode is always true, and remove_target_mode_blocks unconditionally
stripped both LOWERING and REWRITES base blocks before regenerating only the
profile(s) passed via --profile - regen-filecheck.sh rewrites silently deleted
LOWERING blocks on dual-target fixtures. remove_target_mode_blocks now takes
the set of base profiles actually being regenerated and only strips those,
leaving the other profile's block in place. Verified byte-identical output
between --profile rewrites and --profile both post-fix; reran rewrites (85/85)
and lowering (12/12) nextest profiles clean.
