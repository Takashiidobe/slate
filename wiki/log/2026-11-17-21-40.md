# slate-parser-6x05.6 corpus tools: drop CLANG_DEFAULT_STANDARD -std=gnu17 pin, rely on per-flavor default standard

_2026-11-17 21:40:43_

- bead: slate-parser-6x05.6
- kind: bookkeeping
- area: crates/slate-parser/tools
- area: tools/corpus

Outcome: the corpus tools no longer pin -std=gnu17; slate and each oracle now use the flavor's own default standard.

The parser half of this bead (per-flavor `LanguageStandard::default_for`: clang
gnu17, gcc gnu23, msvc c17, plus regenerating 861 fixtures) landed on
2026-10-11 as slate-parser-v74.1.11 (wiki/log/2026-10-11-17-18.md). That
change already absorbed the FileCheck churn, so this change touches no fixtures.

Removed:
- `CLANG_DEFAULT_STANDARD` and its append in `pp_diff.run`
  (crates/slate-parser/tools/pp_diff.py).
- Both appends in crates/slate-parser/tools/c_corpus_sweep.py. The job-arg
  append also passed -std=gnu17 to the gcc oracle under --flavor=gcc, so gcc
  sweeps compared slate at gnu17 against gcc at gnu17 instead of gcc's gnu23
  default.
- The append in `translation_unit` in tools/corpus/e2e.py. It did the same
  thing for gcc-flavor projects.
- The "Pins -std=gnu17" note in wiki/concepts/c-corpus.md.

Check: pp_diff.py --file on a stddef.h + __STDC_VERSION__ probe gives "same"
without the pin.

Limits: the bead's "rerun the trophy sweep" step was not run here.
