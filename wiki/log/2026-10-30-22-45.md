# Splice merged variants at statement level

_2026-10-30 22:45:57_

slate-nfq8.3: --merge now keeps one function or record when variants share code (new src/project_splice.rs, Stmt::Cfg, Attr::CfgAttr, RecordField.cfg). Variant bodies are folded into one tree by LCS alignment that compares generated names up to renaming, since __v/__join/__slate_slot counters shift with unrelated code; a per-variant bijection demotes pairs that cannot be renamed consistently. Gates are minimized relative to the parent statement. Differing parameter and return types become gated type aliases, sections held by some variants become cfg_attr. Departures from the bead: no C-origin alignment, because origin would have to pass through every rewrite and alignment affects only size; no trace conditions or planner cover, because the full truth table is cheap (76s for 16 targets) and always correct. Results on zlib: linux-x86_64 106k to 33k lines (one configuration is 27k), inflate 57k to 4.9k. 16 targets 786k to 92.7k; 160 spliced, 22 hoisted, 11 duplicated functions. Verified: 512/512 on linux-x86_64 and 160 sampled across 16 targets with 0 mismatches, 736 shared symbols 0 mismatches. cargo check on 13 targets with 4 feature sets each, 52/52; x86_64-apple-darwin, aarch64-pc-windows-msvc and thumbv7a-pc-windows-msvc have no core here. Inverting all statement gates gave 108 mismatches on the fixture. cargo check caught a bug the projection check cannot see: a union of link_section attrs put sections on Darwin, which has none; the check allows added sections, so sections are now gated exactly. Fixture: fixtures.merge/splice_statements.c. Not done: runtime validation of merged zlib (slate-mbr2.1.9); match arm and if condition splicing, and shorter cfg lists (new beads).
