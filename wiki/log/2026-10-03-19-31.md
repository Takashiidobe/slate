# Lower global register variable reads (slate-3f8g.4.17.18)

_2026-10-03 19:31:21_

Global register variables (register T x asm("rsp") at file scope) used to lower to a zeroed static mut, so reads returned 0 with no barrier.

- lowerer.rs: register globals go to Tables::register_globals and are never added to statics, so no static is emitted.
- globals.rs: register_global maps x86_64 rsp/rbp and i686 esp/ebp (the only registers clang accepts, at matching size); any other register is a global barrier. lower_register_read emits unsafe { let t: usize; asm!("mov {}, rsp", lateout(reg) t); t as T } for integer and pointer types.
- values.rs: a Read of a register global takes that path before the volatile/plain read arms.
- places.rs: lower_place refuses register globals, so writes and every other place use become barriers (clang allows writes; Rust can't write rsp/rbp soundly).
- Fixture: tests/fixtures/x86_64/gnu_global_register_variable.c (integer and pointer reads of rsp checked against a local's address).
- The gcc-torture ratchet also promoted fprintf-1, fprintf-chk-1, printf-1, printf-chk-1; none use asm, so an earlier change fixed them.

Wiki: new wiki/concepts/inline-asm-parsing.md covering gcc/clang/msvc recognition, parser and sema flavor splits, and the x86_64 clang audit (beads slate-parser-asmcc/asmlet/asmrv/asmlax/asmblk/asmmsv).
