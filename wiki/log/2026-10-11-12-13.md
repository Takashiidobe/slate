# Use native toolchain headers for host targets

_2026-10-11 12:13:28_

slate-parser now discovers system headers from the native toolchain when the target is the host (slate-yzgh).

- New slate_parser::native_headers: clang (default flavor) via `clang --target=<host> -E -v` + `-print-resource-dir`, gcc via `gcc -E -v` + `-print-file-name=include`, MSVC via INCLUDE or find-msvc-tools. Cached per (triple, flavor).
- Precedence in CompilerArgs::search_paths (now returns Result): explicit -nostdinc/-isystem/--sysroot/-isysroot; SLATE_SYSROOTS set or non-host target -> installed only; host -> native; native failure -> installed sysroot if present, else CompilerArgError::SystemHeaders. No clang means an error, by design, since clang is the best-supported path.
- slate-parser binary defaults to its build target (new build.rs) instead of hardcoded x86_64-unknown-linux-gnu; falls back to that when the host is not in the registry (wasm).
- slate sysroot path|doctor native [clang|gcc|msvc].
- Test harnesses (filecheck, differential, support) set SLATE_SYSROOTS so fixtures stay pinned to installed sysroots.
- New e2e test translation_uses_native_headers_without_sysroot with all data dirs pointed at an empty folder.
- Follow-up slate-wmx8: query the compile database's compiler instead of PATH clang.
