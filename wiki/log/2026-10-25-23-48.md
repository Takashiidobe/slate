# Warn C4566 for characters the msvc execution charset lacks

_2026-10-25 23:48:15_

slate-3amj.5.20: cl.exe writes '?' for a plain string or char literal character the execution code page lacks and warns C4566 'character represented by universal-character-name '\u4E00' cannot be represented in the current code page (1252)'. slate-parser encoded the '?' silently.
New Warning::UnrepresentableCharacter ('unrepresentable-character', on). Emitted in sema/validate.rs push_literal_diagnostics (the literal pass, so it fires once per literal regardless of how many sema sites call execution_units). Uses const_expr unrepresentable_characters (CharLiteral, and per piece of StringLiteral) and Charset::represents.
cl.exe facts (probed): one warning per distinct character per string token, in first-use order, at that token's line (concatenated pieces each warn; a macro warns at each use); \uXXXX for BMP and \UXXXXXXXX otherwise, uppercase, also for raw source characters; L and u8 literals never; sizeof and unused static functions do; #if does not; /utf-8 and /execution-charset:utf-8 silence it since everything is representable.
/W0 and /w now set ignore_warnings, and /W1..4 and /Wall clear it, last one wins (cl: '/Wall /w' and '/Wall /W0' are silent, '/w /W1' warns). Other levels still do not filter.
Fixture: msvc/windows/x86_64/unrepresentable_character.c (DEFAULT, W0, REENABLED, UTF8), checked against cl. Wiki: diagnostic-severity warnings table, compiler-flags /W and charset bullets.
