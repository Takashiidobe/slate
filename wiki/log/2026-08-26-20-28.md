# features.md C23 audit

_2026-08-26 20:28:48_

Cross-checked docs/src/features.md's C23 library section against libc-shim headers and clang's own resource-dir headers.

Fixed docs (doc rot): 8 __STDC_VERSION_*_H__ macros were implemented (ASSERT_H, SETJMP_H, COMPLEX_H, STDIO_H, STDDEF_H, WCHAR_H, STRING_H, UCHAR_H) but never listed. Same for C23 fenv.h additions (fesetexcept/fesetexceptflag/fetestexceptflag/fegetmode/fesetmode), strfromd/strfromf/strfroml, and canonicalize/canonicalizef/canonicalizel (previously miscategorized under an 'unimplemented' umbrella bullet).

Fixed libc-shim: added __STDC_VERSION_{CTYPE,ERRNO,INTTYPES,LOCALE,SIGNAL,WCTYPE}_H__ to the corresponding libc-shim headers, gated on __STDC_VERSION__ >= 202311L, matching the existing pattern in stdlib.h etc. Verified via -dM -E across all libc nextest targets.

Confirmed NOT a bug: ATOMIC_VAR_INIT is correctly present pre-C23 and removed at C23 — it comes from clang's own builtin <stdatomic.h> (not libc-shim), which already gates it correctly on __STDC_VERSION__. Same clang-builtin-header story explains why STDATOMIC_H/STDBOOL_H/STDALIGN_H/STDNORETURN_H version macros can't be added from libc-shim — marked [~] in the doc as an upstream clang gap.

Filed slate-4srf.1 and slate-4srf.2 under the features.md audit epic for two C23 language features (_Generic type-name operand, single-arg va_start) that are likely already correct by construction (clang resolves both before CIR sees them) but lack a differential fixture.
