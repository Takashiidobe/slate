# slate-3amj.44 lowerer vla_buffer: -ftrivial-auto-var-init=pattern fills variable-length arrays

_2026-11-18 17:41:47_

- bead: slate-3amj.44
- kind: feature
- area: crates/slate/src/frontend/lowerer/vla.rs
- area: crates/slate/src/frontend/lowerer/auto_init.rs

Outcome: `-ftrivial-auto-var-init=pattern` now initializes variable-length arrays with the pattern byte instead of being a lowering barrier.

Gap: `vla_buffer` in `lowerer/vla.rs` returned `unsupported_type` for any VLA with `AutoInit::Pattern`. Zero mode already worked because the Vec buffer is zero-filled.

Reproducer:
```c
static void show(int n) { int ints[n]; float floats[n]; /* read bytes */ }
```

Before: barrier. After: `write_bytes(0xaa, count)` for int and `0xff` for float under clang; gcc fills `0xfe` everywhere (`ValueBits`). Output matches both compilers: clang `aa aa ff ff`, gcc `fe fe fe fe`.

Implementation: `uniform_pattern_byte` in `lowerer/auto_init.rs` peels the VLA to its base element type, paints it with the existing `Painter`, and returns the byte when one write covers the whole element (or the background when none). `vla_buffer` passes it to `write_bytes`.

Fixtures: `fixtures/flag_trivial_auto_var_init_pattern_vla.c` (clang), `fixtures/gcc/flag_trivial_auto_var_init_pattern_vla_gcc.c`.

Limits: elements whose pattern is not one uniform byte run (structs with mixed int/float fields, padding) and flexible-record VLAs (`variable_record`) stay barriers.
