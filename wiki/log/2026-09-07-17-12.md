# printf to print! first cut

_2026-09-07 17:12:55_

Added a whole-program backend pass (src/backend/engine/printf_format.rs,
wired after prelude::inject in engine/mod.rs) that converts `printf` calls
with a literal, decimal-only format string (`%d` + plain text, arg count
must match) into `println!`/`print!`, choosing println! when the format
ends in `\n`.

Design decision: this is a whole-Program pass, not a NodeRule, because it
needs a correctness gate the per-function engine can't express: convert
ALL-or-NOTHING. If the program has any other stdout-writing libc call
(puts/fputs/fwrite/fprintf/vprintf/fflush/putchar) anywhere, or any printf
call that doesn't cleanly convert (dynamic format, unsupported specifier,
arg-count mismatch, captured return value), the whole program is left
unconverted. This avoids ever mixing libc's FILE* stdout buffer with
Rust's Stdout buffer in one process, which would otherwise reorder output
relative to the C binary and break differential stdout-equality.

Every converted call gets an explicit `std::io::Write::flush(&mut
std::io::stdout())` right after it. This isn't about the mixing problem
(the gate already rules that out) — it's because generated `main` bodies
always end in `std::process::exit(...)`, which skips Rust destructors and
silently drops anything still sitting in Rust's stdout buffer. Belt and
suspenders, cheap, and matches the project's "transliterate correct-but-
ugly first" philosophy; a later fixup can elide the flush when it's
provably redundant.

Also found: NodeRules have no hook to add new top-level extern
declarations (prelude::inject only injects hand-written Rust support
functions). This ruled out an earlier design that would have called libc's
own `fflush(NULL)` to serialize interleaving instead of gating — that
route is closed unless/until the engine grows an extern-injection hook.

~160 existing fixtures had their REWRITES FileCheck blocks mechanically
regenerated (tools/update_filecheck.py / tools/regen-filecheck.sh) since
they use plain-%d printf calls that now legitimately convert. Two fixtures
(ctype_locale multi-fixture and ctype_libc_setlocale_non_c) had a bare
(non-SLATE-block) `// REWRITES-DAG: unsafe { tolower(` check that the
regen tooling doesn't touch; hand-loosened to `unsafe {` + `tolower(` as
separate DAG lines since rustfmt now wraps that call onto its own line
(collateral from the surrounding println! reflow, not a correctness bug).
