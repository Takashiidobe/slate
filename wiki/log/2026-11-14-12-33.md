# slate-f2zu.14.6 lower_type: enum never defined in the TU (enum incomplete) was a type barrier, now i32; drm_mode_status kernel cluster

_2026-11-14 12:33:15_

- bead: slate-f2zu.14.6
- kind: bug
- area: crates/slate/src/frontend/lowerer/types.rs
- corpus: linux

Outcome: an enum declared but never defined in a TU (GNU forward enum, `enum incomplete` in the IR) now lowers to `i32` instead of a `type @typeN(enum E)` barrier; the 7 kernel enum clusters (drm_mode_status and 6 others, 214 TUs) have no barrier rows left.

Symptom: `type @type735(enum drm_mode_status)` at include/drm/drm_mode_config.h:109 blocked every function touching `struct drm_mode_config_funcs` in 185 drm TUs (9467 rows). drm_colorop.c includes drm_mode_config.h, which only forward-declares the enum; drm_modes.h (the definition) is never included. Same for dax_access_mode, intel_cpu_type, vlv_iosf_sb_unit, irqchip_irq_state, vc_intensity, nf_nat_manip_type.

Reproducer:

```c
enum never_defined;
struct ops { enum never_defined (*check)(int); int x; };
```

Cause: the IR is right (`type @type0 never_defined = enum incomplete;`, `TypeDefinitionKind::Enum { underlying: None, .. }`). `Lowerer::lower_type` (crates/slate/src/frontend/lowerer/types.rs) only handled enums with `underlying: Some`, so the incomplete one fell into `Some(_) => Err(unsupported_type(ty))`. An enum completed later in the TU was already fine.

Fix: `Enum { underlying: None, .. }` lowers to `Prim::I32` for every flavor. C cannot call through a function returning an incomplete enum, read one, or take its sizeof, so no value exists in the TU and only the size has to be right. The `Some(_)` catch-all became unreachable and was removed.

Cross-unit: a unit that defines the enum with non-negative values lowers it as `u32`, so the defining and non-defining units disagree on the Rust type of the same struct field (`fn(i32) -> u32` vs `-> i32`, `*mut u32` vs `*mut i32`). translate-project keeps a per-unit struct in each file and links through extern pointers, and --merge reports 0 signature mismatches, so both build and match clang at runtime.

Regression tests:
- crates/slate/tests/fixtures/incomplete_enum_never_defined.c (fn-pointer return, pointer, struct field)
- crates/slate/tests/fixtures.release/incomplete_enum_cross_unit/ (one enum defined with negative values, one non-negative)
- crates/slate/tests/fixtures.merge/incomplete_enum_cross_unit.c (+ units/incomplete_enum_modes.{c,h})

Promoted: c-testsuite case_00209 (`enum E *e;` with E never defined).

Kernel check: lowering-barriers over the 214 TUs with these clusters: 0 enum barrier rows (was ~10k).

Limits: since the field types differ, a struct with an incomplete-enum field is not shared in __slate_types.rs between the defining and non-defining units.
