# slate-8ge7.24.19.10 heap buffers: fallible realloc and terminal release control flow

Outcome: Slate lifts fallible two-binding byte-buffer realloc, null resets
after free, and mutually exclusive final frees. Folded owned-buffer null
checks keep only the selected arm.

## Before and after

```c
unsigned char *q = realloc(p, n);
if (!q) {
  int saved = p[0];
  free(p);
  return saved;
}
p = q;
```

With a proven positive size and an eligible allocation, the old output kept
raw pointers. The new output keeps `p` as a vector.

```rust
let q = p.try_resize(n, 0).is_none();
if q {
    return p[0] as i32;
}
```

## Implementation

- `Walker::plan_heap_statement` requires an adjacent failure guard and
  commit, with no additional uses of the result binding. Publish the
  actions only after the owner survives the existing escape and alias proof.
- Use `Vec::try_filled` when the original allocation has an adjacent
  early-return null guard. Preserve the old vector on resize failure.
- Treat exclusive terminal frees in both arms as one final use for
  ownership. Remove an adjacent null reset when its only observable effect
  is an immediately following null test.
- Keep the selected branch when lowering an owned-buffer null test known
  to be constant.

Fixture: `heap_byte_buffers.c` tests successful growth, failed growth that
reads the old buffer, failed initial allocation, null resets, and both arms
of an exclusive release.

Limits: zero-capable sizes, escaped result pointers, mixed direct and checked
resize, and observable allocator diagnostics stay raw. Broader fallible
resize proofs are tracked in slate-8ge7.24.19.13.
