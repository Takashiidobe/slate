# Microsoft integer literal suffixes (msvc-sqlite.3)

_2026-10-16 18:21:17_

slate-parser-msvc-sqlite.3: i8/i16/i32/i64 (optionally u, any case) lex as integer literals instead of invalid floats. New IntegerSizeSuffix::Microsoft(MicrosoftIntegerSuffix) and StandardFeatures::microsoft_integer_literals (Rejected | Wrapping | Checked { int128 }).

The literal's type is exactly the suffix type: the first rank of that width, i8 is plain char, ui8 is unsigned char (validate::microsoft_literal, used by literal_type, resolve_literal and literal diagnostics).

MSVC (Wrapping), checked against cl.exe: any value wraps to the width (300i8 == 44, 4294967296i32 is int 0). In #if the wrapped value then promotes, so ui8/ui16 are signed (-1ui8 > 0 is false, 0xFFi8 < 0 is true). i128 is rejected.

Clang with Microsoft extensions (Checked), checked against clang --target=x86_64-pc-windows-msvc: values >= 2^width are errors, in-range bits reinterpret (200i8 == -56), #if ignores the suffix width. i128/ui128 are accepted only on 64-bit Windows targets (\_\_int128). gcc, and clang without Microsoft extensions, still reject.
