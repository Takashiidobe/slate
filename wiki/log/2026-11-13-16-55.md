# slate-dghn.51.1 pointer lattice: main malloc locals never heap_locals, free leaked into callee, Box param lost mut

_2026-11-13 16:55:13_

- bead: slate-dghn.51.1
- kind: bug
- area: crates/slate/src/backend/interproc/pointer_lattice.rs
- area: crates/slate/src/backend/engine/rules/remove_mut.rs

Outcome: a `malloc` local in `main` now counts as a heap local, so Box lifting fires from programs with a `main`, a pointer passed to a lifted callee is no longer treated as freed by it, and a `Box` param borrowed with `&mut *x` keeps its `mut`.

Symptom: zstd's `programs/zstd` crate failed `cargo build` with E0596 on `fn AIO_ReadPool_consumeAndRefill(ctx: Box<_>)` calling `consume(&mut (*ctx) as *mut _)`. Fixing that showed the Box lift was almost never firing in programs with a `main`.

Cause (verified with `SLATE_PTR_LATTICE_DEBUG=1` and a debug print in `validate_plans`):
1. `remove_mut::Binding::expr_mutates` did not treat `&mut *x` as a mutation of `x`, so `demote_params` stripped `mut` from a Box param.
2. `pointer_lattice::is_heap_alloc_call` used `peel_cast`, but a lowered `malloc` init is `Unsafe(Block { tail: Cast(Call) })`. `heap_locals` was empty for every caller, so `validate_plans` removed every Box plan whose caller was not itself lifted.
3. Once Box lifting fired, `ptr_lattice_escape_then_free` failed E0382: the caller-to-callee merge in `solve` copied `free` into `touch::y`, which never frees, so `touch` took `Box<i32>` and consumed it before the caller's later read.

Fix:
- `Binding::derefs_owner` in remove_mut.rs: `&mut *x` mutates `x` unless `x` is a `Ptr` or `Ref`.
- `is_heap_alloc_call` uses `peel_cast_and_unsafe`.
- the inbound merge in `solve` clears `free` on the caller fact.
- the call rewrite bridges a lifted local passed to a `Scalar` callee param with `&mut *raw`, since the callee is now `&mut i32` and the caller `Box<i32>`.

Before/After (`destroy(Ctx*)` that calls a pinned raw `consume(ctx, ..)` then `free(ctx)`, called from `main` with a `calloc` local):
`fn destroy(ctx: *mut Ctx)` stayed raw; the no-`main` path produced `fn destroy(ctx: Box<Ctx>)` without `mut`. Now `fn destroy(mut ctx: Box<Ctx>)` and the caller passes `Box::from_raw(ctx)`.

Regression tests: fixtures/heap_box_param_raw_borrow.c (new). Regenerated pointer_lattice.c, ptr_lattice_escape_then_free.c (now `touch(y: &mut i32)`, `use_and_free(mut y: Box<i32>)`) and ptr_lattice_free_cast_bridge.c (`just_free(p: Box<i32>)`, free deleted). `slate` profile with --no-fail-fast: only those three differed, none had a build or runtime error.

Limits: the bridged call is verbose (`&mut (*(&mut (*y) as *mut i32))`); a cleanup rule could fold it.
See: slate-dghn.51 (zstd), wiki/concepts/pointer-capability-lattice.md
