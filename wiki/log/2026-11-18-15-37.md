# slate-yar4.56 asm lowering: register operand wider than 64 bits (i686 =A on __int128) panicked with unreachable

_2026-11-18 15:37:28_

- bead: slate-yar4.56
- kind: bug
- area: crates/slate/src/frontend/lowerer/asm.rs
- target: i686

Outcome: an asm register operand wider than 64 bits (i686 "=A"/"+A" on unsigned __int128) now stops at an unsupported_asm barrier instead of panicking in the lowerer.

Symptom: `slate translate -std=c23 --target=i686-linux-gnu crates/slate/tests/fixtures/x86_64/asm_pair_and_any_operands.c` panicked with "internal error: entered unreachable code" at lowerer/asm.rs.

Reproducer:
    unsigned __int128 r;
    __asm__("" : "=A"(r));

Cause: slate-parser accepts __int128 on i686 by policy (slate-5exy.9, won't fix: more permissive than clang). The register scratch-type width closure in lowerer/asm.rs matched only U8..U64 from `asm_bits_type`, which returns `core::arch::x86_64::__m128i` for a 16-byte value, so the `_` arm reached `unreachable!()`.

Fix: the `_` arm returns `unsupported_asm("register operand wider than a general-purpose register")`. The error is now "unsupported slate-parser IR in pair_out / statement asm: register operand wider than a general-purpose register".

Regression test: none. The fixture is x86_64-only and the clang oracle rejects __int128 on i686, so no differential fixture can run this path; found by a cross-target translation sweep.

See: slate-5exy.9, slate-5q63.22.1.
