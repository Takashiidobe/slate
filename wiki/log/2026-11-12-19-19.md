# slate-dghn.41.3 corpus e2e: libuv test executables no longer re-translate libuv.so objects

_2026-11-12 19:19:21_

- bead: slate-dghn.41.3
- kind: bookkeeping
- area: tools/corpus

Outcome: corpus harness treats a recipe's shared-library variants as the project library when assembling a translated test executable, so libuv's uv_run_tests and uv_run_tests_a translate and build.

Cause: executable_units (tools/corpus/e2e.py) replaced only recipe.library with the prebuilt translated library; uv_run_tests links libuv.so, whose objects (including idna.c) were translated into the test crate next to test-idna.c, which #includes ../src/idna.c. Two #[no_mangle] uv__idna_toascii definitions in one crate failed rustc. Natively that is legal: the exe's definition interposes the shared library's, the same way cJSON's tests include ../cJSON.c.

Fix: executable_units matches recipe.library and recipe.variants; libuv recipe sets variants=["libuv.so"]. No translator change.

Limits: native uv_run_tests exits 40 and uv_run_tests_a 16 in this environment (network/tty tests), so the ctest comparison needs a per-test exclusion list; tracked on slate-dghn.41.
