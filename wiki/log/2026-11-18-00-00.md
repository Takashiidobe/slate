# slate-3amj.16 gcc -fms-extensions: accept flag, enable microsoft_anonymous_records only

_2026-11-18 00:00:22_

- bead: slate-3amj.16
- kind: feature
- area: crates/slate-parser/src/compiler_args.rs
- area: crates/slate-parser/src/standard_features.rs
- flavor: gcc

Outcome: gcc flavor accepts -fms-extensions and enables only anonymous struct/union members declared by tag or typedef (microsoft_anonymous_records); -fms-compatibility is still rejected.

Gap and why it mattered: gcc's -fms-extensions is narrower than clang's: in C it only makes a declarator-less `struct point;` or `point_t;` member an anonymous member. slate rejected the flag outright for gcc ("`ms-extensions` is not emulated for GCC").

Before:
```c
struct point { int x, y; };
typedef struct point point_t;
struct labeled { struct point; int label; };
struct typedef_member { point_t; int z; };
```
`slate translate --flavor=gcc -fms-extensions` -> `GCC MS modes: ms-extensions is not emulated for GCC`.

After: translates and prints `1 2 3 4 5 6 12` like gcc on x86_64, i686, aarch64.

Implementation:
- `compiler_args.rs` "GCC MS modes" validate rule now rejects only `Opt::MsCompatibility`.
- `standard_features.rs`: `microsoft_anonymous_records` for Gcc = `microsoft.anonymous_structs.unwrap_or(false)` (set by -fms-extensions, same path as clang). `microsoft_extensions` stays false for gcc, so no other MS behavior (integer literal suffixes, etc.) turns on.

Fixture: crates/slate/tests/fixtures/gcc/flag_gcc_ms_extensions.c (promoted from fixtures.unsupported/gcc).
The parser error fixture moved to error/gcc/linux/x86_64/ms_compatibility_flag.c and now covers -fms-compatibility rejection.

Limits: only anonymous records are modeled for gcc -fms-extensions; -fms-compatibility remains rejected.
See: slate-parser-cxg.24
