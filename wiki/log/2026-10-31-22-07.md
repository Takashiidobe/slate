# Add the remaining named typedefs to slate-support

_2026-10-31 22:07:18_

slate-f2zu.9.5.8.3: added intmax_t, uintmax_t, wint_t, off64_t, time_t, clock_t, pid_t, uid_t, gid_t, mode_t, dev_t, ino_t, nlink_t and socklen_t to vendor/slate-support and slate_support_definition in lowerer/types.rs, so none of NAMED_TYPEDEFS falls back to a local alias on a supported target unless flags change it. Values came from translating a probe C file on each of the 16 zlib matrix targets before the change. Afterward every type imported on every target, and a per-target cargo check appended type-equality assertions against those values: 15 of 16 passed; thumbv7a-pc-windows-msvc has no rustup target, so only the matcher was checked there. Used the probe instead of a corpus project because it covers every type on every target. 32-bit Android values are untested since those triples are unsupported. Fixture: fixtures.merge/named_types_support.c. zlib output line count unchanged at 40702.
