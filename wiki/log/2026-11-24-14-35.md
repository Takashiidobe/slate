# slate-e36k.24 CallConv: diagnose Clang regcall at native call boundaries

Outcome: Slate preserves x86 regcall in IR and diagnoses it during Rust lowering.

## Symptom

A translated host called a native regcall function through dlsym and passed a
translated regcall callback to the native library. The native host printed
regcall call=1 and regcall callback=1. The translated host printed 0 for both.

## Cause

The parser recognized regcall as an attribute spelling but did not build a
CallingConvention node. TypeResolver therefore left the definition and the
function pointer at the default C convention.

## Fix

Parse __regcall and GNU regcall into CallingConvention::Regcall. Preserve
CallConv::X86Regcall in x86 function types and call signatures. Slate reports
a lowering barrier for a definition, extern declaration, or function pointer
requiring the convention.

Fixture: crates/slate/tests/fixtures.dylink.unsupported/regcall_boundary
Parser fixture: crates/slate-parser/tests/fixtures/clang/linux/x86_64/calling_convention_regcall.c

Limits: Rust has no regcall ABI. The shared-library fixture stays unsupported
until native calls and callbacks can match Clang.
