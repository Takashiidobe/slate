# Fix raw-byte string literals and #if wide-integer overflow

_2026-09-13 08:08:23_

Closed slate-parser-wf8.3.1 and .2, migrating 20000227-1.c and 20000402-1.c.

wf8.3.1 (non-UTF-8 byte in a string literal): the whole pipeline read source
via std::fs::read_to_string, requiring valid UTF-8, but C allows arbitrary
raw bytes inside string/char literals. Instead of switching the lexer from
Vec<char> to bytes (a large refactor), added decode_source_bytes() and
raw_byte_for_char() in src/files.rs: decode opportunistically as UTF-8,
escaping any byte that isn't part of a valid sequence into a private-use
codepoint (U+10FF00 + byte, topping out at U+10FFFF for 0xFF). This round-
trips losslessly through the existing char-based lexer/parser with no
architecture change. lexer.rs's decode_char_escape unescapes it back to the
raw byte value for CharLit decoding. All 5 read_to_string call sites (parser.rs
x3, sema.rs, pp/include.rs, plus tests/filecheck.rs's fixture loader) now go
through std::fs::read + decode_source_bytes.

wf8.3.2 (#if rejects ull-suffixed integers): ULONG_LONG_MAX's libc-shim
definition '(**LONG_LONG_MAX** \* 2ULL + 1ULL)' overflowed i64 in
const_expr.rs's checked_mul before it could be compared. Root cause was two
bugs stacked: lexer.rs's Token::integer_value() clamped u64 literals to
i64::MAX instead of bit-reinterpreting them (so ULLONG_MAX-sized literals
were already wrong), and evaluate_expr's Add/Sub/Mul used checked i64 ops
that errored on overflow instead of wrapping like real 64-bit arithmetic.
Fixed integer_value() to reinterpret via `as i64` (two's-complement
wraparound, matching hardware), and widened Add/Sub/Mul to compute in i128
before truncating back to i64.

Also fixed a real bug in tools/update_filecheck.py found along the way:
render_error() parsed the fixture's own file path directly (not a stripped
temp file like render() does), so regenerating an ERROR-configured fixture's
CHECK block would capture the SLATE-FILECHECK-ERROR marker line itself as
part of the diagnostic snippet. Now uses the same stripped-source temp-file
approach as render(), with paths in the diagnostic output remapped back to
the real fixture path.
