# offsetof with runtime array indices

_2026-10-05 09:22:43_

slate-parser-6x05.38.18. __builtin_offsetof(T, a[i]) with a non-constant index (kernel container_of(..., pid_links[type]) in do_each_pid_task, 14 TUs) failed with 'nonconstant or unknown identifier' because TypeResolver::offsetof_member folded every index as an integer constant.

- offsetof_member now returns OffsetOfPath { ty, offset, runtime_indices }: constant indices fold into offset, others are kept as (index expr, element size).
- Lowering emits clang's codegen shape: offset_of leaf, then add(offset, mul(size_t(index), size)) per runtime index, all wrapping u64; index converted with reason=explicit (sign-extends signed indices).
- Typer rejects a non-integer index ('offsetof index is not an integer'); the ICE evaluator rejects offsetof with runtime indices.
- Fixtures: clang/linux/x86_64/offsetof_runtime_index.c, error/.../ir_layout_constants.c FLOAT_INDEX. Values checked against clang-compiled binaries.
- Found a pre-existing gap: static initializers accept non-constant arithmetic over globals (x * 8UL); filed slate-parser-6x05.47. A runtime-index offsetof in a static initializer falls into that gap now.
- Wiki: ir/pipeline.md constant-evaluation section.
