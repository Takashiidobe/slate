# slate-parser-6x05.38.8 X86Isa predefines: clang -march=i386/i486 keep __GCC_HAVE_SYNC_COMPARE_AND_SWAP_8 and LLONG_LOCK_FREE 2

_2026-11-18 08:39:11_

- bead: slate-parser-6x05.38.8
- kind: bug
- area: crates/slate-parser/src/target/x86_isa.rs
- flavor: clang
- target: i686

Outcome: with clang flavor, `-march=i386` and `-march=i486` now predefine the same atomics macros as native clang: no `__GCC_HAVE_SYNC_COMPARE_AND_SWAP_8`, `LLONG_LOCK_FREE` 1, and for i386 no `SYNC_1/2/4` either.

Symptom: slate kept the i686 snapshot values (`SYNC_1/2/4/8` defined, `__GCC/__CLANG_ATOMIC_LLONG_LOCK_FREE` 2) for CPUs without cmpxchg/cmpxchg8b. Repro: `crates/slate-parser/tools/gcc_macro_diff.py 'clang --target=i686-linux-gnu -march=i386' '--flavor=clang --target=i686-unknown-linux-gnu -march=i386'`.

Fix: `X86Isa::has_cmpxchg8b` (crates/slate-parser/src/target/x86_isa.rs) is false only for the CPU names i386 and i486. `X86Isa::disabled_macros` removes `SYNC_8`, plus `SYNC_1/2/4` on i386, and `X86Isa::predefines` sets both `LLONG_LOCK_FREE` macros to 1. This applies to clang flavor only; gcc rejects `-march=i386`. Native clang 23.1.4 still treats winchip-c6, winchip2 and c3 as having cx8, so they are not in the list, even though LLVM's backend CPU table says otherwise.

Decision (user): only the macros change. `TargetInfo::max_atomic_inline_bytes` and the IR's `__atomic_always_lock_free(8,0)` keep the i586+ assumption, because Rust has no x86 target below i586, so translated code cannot run on a CPU without cmpxchg8b. A hand-written CPU list replaced the generator options (an X86Cpu cx8 field, or an internal X86Feature::Cx8), which would have needed a regen of x86_isa_tables.rs.

Not urgent: the kernel's 26 `-march=i386` C units (arch/x86/boot, arch/x86/realmode/rm) use no atomics and none of these macros.

Regression test: crates/slate-parser/tests/fixtures/clang/linux/i686/march_atomic_macros.c (I386/I486/I586).

Limits: under -march=i386/i486, `__atomic_always_lock_free(8,0)` still folds to true, while native clang returns 0.
