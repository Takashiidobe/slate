# Implement macOS process, user, terminal ABI (slate-sfzn.6.10)

_2026-08-31 12:30:34_

slate-sfzn.6.10: unistd.h/spawn.h/sys/wait.h/poll.h/sys/select.h/termios.h/
pwd.h/dlfcn.h/regex.h/glob.h/fnmatch.h Darwin overlays were already wired to
bits/darwin/*.h before this session; grp.h needed no overlay (struct group
is byte-identical to the shared shim, like FreeBSD). The missing piece was
unistd.h's _SC_*/_PC_* sysconf block: Darwin fell through to glibc numbering.

Added a Darwin-specific block mirroring the base POSIX.1 numbering shared
with FreeBSD (1-27 identical) but diverging where XNU's bsd/sys/unistd.h
differs, e.g. _SC_PAGESIZE=29/_SC_MAPPED_FILES=47 (FreeBSD has these
swapped: 47/29). No macOS SDK was available on this machine to verify
against, so these constants are transcribed from memory and flagged
unverified in a header comment pending oracle confirmation - a follow-up
should diff against a real SDK sysconf list when one is reachable.

Added libc-shim/macos-process-headers.txt manifest and
macos_process_header_manifest_compiles_for_aarch64 (header_compilation.rs),
mirroring the freebsd_process_header_manifest test with Darwin-specific
_Static_assert values (termios size 72, c_cc@32, c_ispeed@56; passwd size
72, pw_change@24, pw_gecos@40; posix_spawnattr_t=8B; P_ALL=0/P_PID=1 (FreeBSD:
0/7); RTLD_DEFAULT=-2, RTLD_NOLOAD=0x10; regex_t=32B; fd_set=128B) - struct
layouts derived via clang -Xclang -fdump-record-layouts against the shim
itself, not guessed.

Added tests/fixtures/macos/process.c (posix_spawn/waitpid/tcgetattr/sysconf/
getpwuid), generated via update_filecheck.py --target MACOS=aarch64-apple-darwin.
libc profile (32/32), lowering (10/10), and rewrites (90/90) all pass;
fmt/clippy clean.
