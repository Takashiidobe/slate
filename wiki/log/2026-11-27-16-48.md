# slate-8ge7.2.8 inline-temps: sema synthetic temporaries inlined inside kept macro bodies (MOD63 a %= BASE template)

_2026-11-27 16:48:48_

- bead: slate-8ge7.2.8
- kind: rewrite
- area: crates/slate-analysis/src/transform/inline_temporaries.rs
- area: wiki/concepts/macro-provenance-transforms.md

Outcome: inline-temps now inlines sema's synthetic temporaries inside a kept macro body, so `--merge` templates read like the C (`$a %= 65521`, `$cursor = $cursor.add(1)`, `total += $a`) instead of keeping sema's read/compute/write temps.

Before (`#define MOD63(a) a %= BASE`, zlib adler32, `off_t len`):

    macro_rules! MOD63 { ($a:expr) => {
        let __v: off_t = $a;
        let __v2: off_t = __v % 65521;
        $a = __v2;
    }; }

After:

    macro_rules! MOD63 { ($a:expr) => { $a %= 65521; }; }

Rule: `Context::statements` now enters `Statement::MacroExpansion` bodies (`expansion_body`), and a `TemplateBlocks` visitor runs `list` on the statements and tail of every `StatementExpression` that `Module::macro_values` wraps (folded value expansions from slate-8ge7.2.7, block holes). The existing checks still apply: single read, same type, not captured, producer effects commute with what lies between, and `nested_depth` rejects a temp read inside a nested region or a hole. So a temp moves only within one body, and a hole in an initializer moves whole. `children` is unchanged, so structure-goto, do-while-zero and labeled-blocks still never enter a region.

wiki/concepts/macro-provenance-transforms.md: the rule now allows a rewrite whose nodes all stay in one kept body (holes moved whole, never changed); audit row for inline-temps updated.

Rule outside macros is unchanged: TemplateBlocks only fires on wrapped nodes and MacroExpansion statements exist only under `--merge`.

Fixture: crates/slate/tests/fixtures.merge/macro_compound_assign.c (MOD/MOD28/MOD63 on unsigned long, off_t and int; SCALE; ADD_TO as value and statement). Regenerated: macro_arg_casts, macro_boundaries, macro_caller_locals, macro_control_flow, macro_dispatch_locals, macro_families, macro_fold, macro_nesting, macro_places, macro_templates, macro_values (temps removed; some `__N` template suffixes swapped because content hashes changed).

Limits: a temp read twice stays (`NEXT()` keeps `let __v = cursor; cursor = __v.add(1); *__v`, the one temp post-increment needs; value `ADD_TO` keeps `{ let __v = $a + $v; $a = __v; __v }`). `MOD(int)` renders `$a = (($a as u32) % 65521) as i32` because the unsigned BASE converts. Per-site templates still split when types differ (MOD vs MOD__2).
