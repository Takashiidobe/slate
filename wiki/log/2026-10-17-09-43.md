# Lower __float128 va_arg on i686 and binary128 long double va_arg on aarch64

_2026-10-17 09:43:40_

slate-kih1.9. Scalar va_arg of f128 was a barrier off x86_64.

i686: f128 reads through __slate_i386_va::arg, which now rounds the char* cursor up to 16 for 16-aligned types before reading. gcc aligns a variadic __float128 to 16 on both the caller and va_arg side (LLVM's caller does too); clang's i386 va_arg reads it at 4-byte alignment and returns garbage (clang -m32 prints 0 for a round-tripped 1.5Q). So the new fixtures/i686/float128_va_arg.c (ints interleaved with __float128 to force padding) compares against float128_va_arg.expected recorded from gcc -m32. Rust's i686 u64/f64 alignment is 4, so only 16-aligned types change.

aarch64: binary128 long double va_arg lowers to __slate_aapcs_va::hfa::<_, f128>(list, 1, 16): one vector-register slot, stack fallback aligned to 16 (clang EmitAAPCSVAArg). long_double_va_arg and long_double_variadic_libc_name removed from fixtures.unsupported/aarch64-unknown-linux-gnu.txt.
