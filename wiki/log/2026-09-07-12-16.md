# Fix ARM32 ILP32 long/pointer width bugs (slate-3f8g.4.16.12)

_2026-09-07 12:16:54_

Root cause was three bugs, not one: (1) c_ast.rs's AST-string int_bits()
hardcoded 'long' -> 64 bits regardless of target; (2) lowerer.rs's c_layout()
hardcoded pointer size/align at 8 bytes universally, which desynced the
sizeof-const-fold queue (next_layout_query_expr pops a LayoutQuery even when
it can't render a replacement, so a wrong 'expected' value silently matched
the wrong query) causing local_record_same_tag's array-length divisor bug;
(3) atol/atoll runtime shims (prelude.rs, libc_call.rs) hardcoded Prim::I64.

Fixes:
- toolchain.rs: new long_bits()/active_long_bits(), mirroring
  long_double_bits(). ILP32 (pointer_width==32) or LLP64 (windows+msvc) -> 32,
  else 64.
- c_ast.rs: int_bits() uses active_long_bits() for plain 'long' (kept
  'long long' fixed at 64).
- lowerer.rs: c_layout/record_layout/record_natural_align/record_field_offset
  and effective_type_alignment now take pointer_bytes (from
  self.target_pointer_bits) instead of hardcoding 8.
- prelude.rs/libc_call.rs: atol width now target-aware; atoll got its own
  distinct ATOLL/__slate_atoll helper (previously silently shared atol's
  name/width, a latent bug once atol became target-dependent).
- libc-shim/include/setjmp.h: __slate_jmp_buf_tag's fields were 'long'/
  'unsigned long' meant as an x86-64-sized opaque ABI buffer, not real C
  'long' semantics -- switched to 'long long'/'unsigned long long' so it
  stays 64-bit-sized on ILP32 (the long_bits fix exposed this: narrowing to
  32-bit shrank the buffer below what real glibc setjmp/longjmp write).
- ato_int_prelude: parse now saturates via i128 + clamp(MIN,MAX) instead of
  unwrap_or(0) on overflow, matching glibc atoi/atol/atoll's real behavior
  (exposed once atol was correctly narrowed to i32 on ARM32, making a real
  overflow case in atoi_atol_prelude_dynamic reachable for the first time).
- builtin_ctzll_shift.c fixture was independently exercising UB
  (__builtin_ctzll(0) + oversized shift); fixed to use a fixed nonzero input,
  unrelated to the width bug but uncovered by the same investigation.

All 4 originally-skip-listed fixtures (compound_literal_address,
numeric_parse_fixup, local_record_same_tag, builtin_ctzll_shift) now pass;
skip-list entries removed from tests/differential_arm.rs. Full
lowering/rewrites/aarch64-lowering/aarch64-rewrites/arm-lowering/arm-rewrites
profiles pass.
