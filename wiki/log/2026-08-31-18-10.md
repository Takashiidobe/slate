# inline numeric-const temps into call args

_2026-08-31 18:10:57_

Added InlineConstArgTemps rule (src/backend/engine/rules/inline_temps.rs, priority 43) to the worklist engine. It inlines single-use, non-type-anchored numeric-constant let temps (_vN = 2, -10, 42L, floats) into their consuming call/macro argument, deleting the let.

Type preservation via ArgPos:
- Fixed function param (direct arg, callee canonical_type non-variadic at that index): inline bare; the param type pins the literal. -> add(2, 3).
- Variadic tail arg / macro arg / unknown callee: inline as 'init as ty' to pin the C-promoted type. -> printf(..., 7 as i32).
- Occurrence under an explicit cast: bare only if cast target == temp ty (avoids redundant double-cast, e.g. exit(0 as i32)); otherwise 'init as ty' to keep the temp's own type. This was the pr23941 fix: __FLT_MIN__ is an f32 literal used as '_v as f64'; bare-inlining made it parse as full-precision f64 and diverge, so we emit (lit as f32) as f64.

Variadic vs fixed is read from CallBinding::Direct canonical_type via canonical_fixed_arity (depth-aware C-signature param parse). Constants are pure/sinkable so no intervening-effect check is needed. Runtime differential (rewrites profile) green across corpus; pre-existing enforces_rewrite_checks meta-test still fails (REWRITES filecheck disabled). Fixtures: add.c (fixed path), inline_variadic_const_args.c (variadic path).
