# Make libc writer flushes match on every --merge target

_2026-10-31 19:17:48_

slate-f2zu.9.4: merged zlib flushed around fprintf on Linux, macOS and FreeBSD but not Android or Windows. Android: libc identity used only the outermost system header, and bionic's stdlib.h includes stdio.h, so fprintf after stdlib.h became Unknown. classify_function now takes the outermost header and the declaring file. This also fixes glibc nesting: gnu_libc_algorithms and gnu_libc_allocation now get println! and copy_nonoverlapping. Windows: ucrt defines printf and fprintf inline, so they had no identity. Added FunctionIdentity::HeaderInline, which printf_format treats as a writer by name. It is deliberately not Known, since print! would skip Windows text-mode newline translation. fputc is now a writer: fputc(c, stdout) was left unflushed before println!. Rejected: skipping flushes for writes to stderr. Matching stderr, __stderrp, __sF[2] or __acrt_iob_func(2) only names the startup object; stderr = stdout, freopen and setvbuf break the assumption, and fflush(NULL) needs none. zlib keeps its flushes, and .9.5.3 folding should move them into macro definitions. Fixture: fixtures.merge/flush_streams.c; 19 other FileCheck blocks regenerated. Validation: slate profile 33/33; zlib 47084 to 47021 lines; validate_merge 6/6 default and 6/6 all. Android, macOS and FreeBSD rust targets are not installed, so their output was not compiled.
