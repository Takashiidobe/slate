# gcc x86 -m feature implications

_2026-09-27 17:26:51_

slate-parser-78x3.5. X86IsaRequest folded -m flags into masks at parse time with clang's implication graph, before the flavor was known.
It now records (feature, enabled) in command-line order; X86Isa::resolve folds them with Rules::Clang or Rules::Gcc (TargetIsa::resolve already had the flavor since 78x3.4; IsaRequest lost Copy).
gcc graph: avx512f implies only avx2 (so -mno-fma / -mno-f16c keep avx512f), avx implies xsave as a real edge (-mno-xsave drops avx, -mno-avx keeps xsave). gcc also defines __FP_FAST_FMA* for avx512f without fma.
Both flavors: -mfoo is dropped when a later -mno-foo follows (driver cancellation); -mavx -mno-avx previously left SSE4.2 on under clang, which clang does not.
Verified with tools/gcc_macro_diff.py over 22 flag sets on x86_64 and i686: zero gcc differences (ignoring the host gcc -m32's k8 default vs the pentium4 snapshot); the clang sweep is byte-identical before/after; extra cancellation probes match both compilers.
