# slate-j3by.28 MSVC multiply: lower signed and unsigned high halves on x64

_2026-11-25 18:38:13_

- bead: slate-j3by.28
- kind: bug
- area: crates/slate/src/libc_catalog.rs
- area: crates/slate/vendor/slate-support/src/lib.rs
- flavor: msvc
- target: x86_64

Outcome: Slate lowers the three MSVC x64 widening multiply intrinsics
through existing slate_support call bindings.

Symptom: Each call hit the `builtin without a lowering` barrier, although
cl.exe compiled the x64 C probe successfully.

Reproducer:
```c
#include <intrin.h>
__int64 split(__int64 a, __int64 b, __int64 *high) {
  return _mul128(a, b, high);
}
```

Cause: The parser supplied the correct intrinsic signature and metadata.
`MSVC_INTRINSICS` had a binding for _umul128 and none for the signed split
or either high-half multiply.

Fix: The new support helpers widen each operand before multiplying.
__mulh and __umulh shift their signed or unsigned product right by 64.
_mul128 writes the signed high half through the output pointer and returns
the low bits as i64. The reproducer now calls slate_support::_mul128.

Regression test: crates/slate/tests/fixtures/msvc/x86_64/msvc_wide_multiply_intrinsics.c
covers signed negative and positive products, a low half with its sign bit
set, unsigned high halves, and the output write with a discarded result.

Limits: These bindings cover x64. Both high-half calls compiled on the
ARM64 oracle and remain listed in the generated coverage report.
