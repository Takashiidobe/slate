# Clang C function overloading (overloadable)

_2026-10-05 08:35:06_

slate-parser-6x05.38.15: with CONFIG_WARN_CONTEXT_ANALYSIS the kernel's context_lock_struct(name) defines eight static __always_inline __attribute__((overloadable)) helpers per lock type (__acquire_ctx_lock(const struct spinlock *), ...(const struct mutex *), ...), called through __acquire/__release/lockdep_assert_held. Slate had one binding per name, so the second definition was a conflicting redeclaration (57 kernel TUs).

- names.rs bind_function: each overloadable function declaration gets its own binding; NameResolution::overload_sets maps it to the overloads visible at its declaration. A plain function already in scope joins the set and keeps its C name.
- typer resolve_overload (from call_signature, so checker and lowering agree): per-argument ranks exact (incl. adding pointee qualifiers) < promotion < conversion < incompatible pointer < dropped qualifiers < ellipsis; the candidate at least as good everywhere and better once wins, written into references[callee]. Ambiguous and no-viable calls are Rejected, matching clang.
- Unimplemented (honest, not rejections): a non-call use of a multi-overload name; a same-type redeclaration of an overload (follow-up slate-parser-6x05.42); calling or defining an extern overload, which needs Itanium mangling (slate-parser-6x05.41, P4, user's choice A). Unused extern prototypes are lowered.
- IR: FunctionSemantics::overloadable prints [overloadable]; the C name is kept and consumers name by binding (user chose IR flag + Slate renames: slate-p58o.17).
- Side fix: clang-semantic-attributes.c used to merge overloaded(int)/overloaded(double) into one binding and drop the second declaration.

Every call target in ir_overloadable.c matches clang's emitted _ZL... callee. block/bdev.c now lowers. clang <tgmath.h> smoke test lowers; noted on cxg.34.
