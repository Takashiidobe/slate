Outcome: decided that without a ValueKind::MacroExpansion node, normalization hoists across expansion boundaries in every mode and template recovery rebuilds value regions from provenance afterwards; an expansion a hoist splits stays inline. Measured cost: 13/110 kept value expansions on the merge fixtures, 15/238 on zlib_projection_sample.

Question (slate-8ge7.2.2): today `Hoister::value` (sema/effects.rs) stops at `ValueKind::MacroExpansion`, keeping e.g. `r += NEXT()`'s `*cursor++` temporaries in `evaluation.statements` so the expansion lifts as one template. Once the node goes (slate-8ge7.2.3), either:
1. normalization ignores macros; template recovery rebuilds the region from provenance after normalization, and expansions whose parts separate stay inline; or
2. normalization never hoists across an expansion boundary, in every mode.

Decision: option 1. It matches the epic decision that macro_keep runs after slate-analysis and rejects expansions whose region a fact changed. Option 2 makes evaluation-order code read macro provenance and changes plain (non-merge) IR to depend on macro boundaries, against the strip-equals-plain invariant (slate-8ge7.2.1).

Measurement: a temporary counter in `frontend::lower_parsed` walked the final module and counted kept `ValueKind::MacroExpansion` values whose normalized `evaluation.statements` is non-empty (the ones a hoist would split under option 1; an upper bound on the loss). Option 2 loses none by construction. Unique (unit, result) lines across targets:

| Sample | kept value expansions | with hoisted statements |
| --- | --- | --- |
| merge fixtures (merge profile) | 110 | 13: macro_values.c 11 (NEXT_FROM x3, MIN, NEXT, BUMP_AND, ASSIGN_TO, STMT_EXPR, BOTH, EITHER, PICK), macro_control_flow.c TAKE, macro_dispatch_locals.c UPDATE_CHECK |
| zlib_projection_sample | 238 | 15: deflate.c UPDATE_HASH x10, gz{lib,read,write}.c GT_OFF x3, inflate.c UPDATE_CHECK x2 |

All split cases are value macros whose body has an assignment, increment, call under `&&`/`||`/`?:`, or a statement expression: `GT_OFF(x)` is `sizeof(int) == sizeof(z_off64_t) && (x) > gz_intmax()`, and the call on the right makes `&&` a branch with temporaries.

Limits: the counter is an upper bound. Hoisting is sequential, so a region's hoisted statements stay contiguous; a recovery that folds the run back into a block value (`{ let t = cursor; cursor = t.add(1); *t }`) could win most of these back. That is left to slate-8ge7.2.3. No code change landed; the counter was reverted.
