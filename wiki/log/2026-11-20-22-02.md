# slate-8ge7.7 c_string: char* params fed C-string literals lower to &CStr from slate-analysis; dead unsound string_params &str lift deleted

_2026-11-20 22:02:34_

- bead: slate-8ge7.7
- kind: feature
- area: crates/slate-analysis/src/pointer.rs
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/src/backend/interproc

Outcome: char* params used only as C strings and fed NUL-terminated literals lower to `&core::ffi::CStr` from a slate-analysis fact; the dead and unsound Rust-side `string_params.rs` is deleted.

Gap and why it mattered: `string_params` (char* -> `&str`) fired on no fixture: with it skipped, 5409 single-file fixtures translated identically and the slate and merge profiles stayed green. Its `c_string_payload` expected `Expr::CStr` bytes to end in NUL, but `cstr_literal` stores the content without it, so no call site was ever proven. Had it fired, it was unsound: callers passed Rust `"abc"` (no NUL) and the callee kept `strlen(s.as_ptr())`.

Before:

```rust
fn is_keyword(word: *const i8) -> i32 { /* strcmp(word as *const c_char, ..) */ }
keyword_length(c"if".as_ptr())
```

After:

```rust
fn is_keyword(word: &core::ffi::CStr) -> i32 {
    /* strcmp((word.as_ptr() as *const i8) as *const c_char, c"if".as_ptr() ..) */
}
keyword_length(c"if")
```

Implementation:
- `slate-analysis/src/pointer.rs`: `PointerFact::c_string`. `c_string_literal` finds `.str` globals (8-bit `code_units`, last unit 0, no interior 0); `Walker::literal` records per argument in `CallSite::literals`. `c_string_parameters` seeds candidate byte params whose class has STRING and none of WRITE/FREE/ESCAPE/NULLABLE/MACRO, not raw, returned, pinned or written, with at least one caller, then shrinks until every unpinned site passes a literal or an unwritten caller param still in the set.
- Lowering: `Tables::c_string_parameters`/`parameter_c_string`, `FunctionLowerer::c_string_of`. The param type (definition and extern declaration) is `&core::ffi::CStr`; `borrowed_read` lowers a read to `s.as_ptr() as <raw>`, so `p[i]`, `*p`, `memcpy` and `str*` calls stay inside the CStr's provenance; `lower_c_string_argument` emits `c"..."` or forwards the caller's `&CStr`. Calls do not add these to `borrowed`, so no argument temps are hoisted.
- `interproc/mod.rs`: the cross-unit assert also rejects an extern declaration left with `&CStr`.
- length_lattice audit: it only runs from `pointer_lattice::apply` (SLATE_IR_POINTERS=0), so its gate-on losses are the slate-8ge7.12 list.

Fixture: crates/slate/tests/fixtures/pointer_lift_c_string_params.c (lifted: literal callers, forwarded param, `p[0]` read; raw: a stack-buffer caller, a written param, a literal with an interior NUL). Regenerated: packed_sds_headers (sdsnew), msvc/i686/pragma_merge, pragma_section. A two-unit executable project lifts `pub fn keyword(w: &CStr)` and binds `keyword(c"if")` across units.

Limits: automatic arrays initialized from a literal (`const char x[] = "abc"`) and casts between char and unsigned char pointers still stay raw (slate-8ge7.13). Reads emit `(s.as_ptr() as *const i8) as *const c_char` double casts.

See: slate-8ge7.12, slate-8ge7.13, wiki/concepts/slate-analysis.md#pointer-capabilities.
