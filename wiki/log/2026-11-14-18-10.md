# slate-f2zu.14.22 lower_asm: register variable passed as +r and r emitted two in("r11") inputs; rbx merge of =b u32 with b u64 mismatched inout types

_2026-11-14 18:10:12_

- bead: slate-f2zu.14.22
- kind: bug
- area: crates/slate/src/frontend/lowerer/asm.rs
- target: x86_64

Outcome: x86_64 inline asm no longer emits a duplicate in("r11") for a register variable passed as both "+r" and "r", and the rbx save/swap merge of a "=b"/"b" pair with different widths uses one scratch width.

Symptom (linux check stage): `register r11 conflicts with register r11` (irq_stack.h call_on_stack: 14 errors across irq, irq_work, kvm, smp, softirq, mce_amd, threshold) and `incompatible types for asm inout argument: u64, u32` (vmware.h vmware_hypercall3).

Reproducer:
    register long t __asm__("r11") = x;
    __asm__("addq %[t], %0" : "+r"(t) : [t] "r"(t));
    unsigned long a; unsigned out;
    __asm__("..." : "=a"(a), "=b"(out) : "b"(in));   /* in is unsigned long */

Cause: in `lower_asm` (frontend/lowerer/asm.rs), every pinned operand went into `explicit`, so the register variable produced `inlateout("r11") t => __t0` plus `in("r11") t`: two inputs on one register. Separately, the `merged_rbx` branch joined the saved "=b" Out (u32 temp) with the "b" In (u64 input) into `inout(reg) in as u64 => __t1` without reconciling types.

Fix:
- Pinned `In` operand whose register already carries an input in `explicit` is dropped when the input expression is identical (template slot stays `Slot::Register`); different values are a barrier "two different inputs in register r11".
- `saved_rbx_scratch` records the saved rbx operand's scratch type. On merge the wider type wins: a narrower input is cast up; a narrower output temp has its `let` retyped to the wide type (the writeback's `asm_decode` cast truncates it).

Regression tests: crates/slate/tests/fixtures/x86_64/asm_register_variable_tied_twice.c, crates/slate/tests/fixtures/x86_64/asm_rbx_mixed_width.c

Limits: the 4 boot-code `cannot use register bx` errors are a harness target mismatch (-m16 TUs checked as x86_64), moved to slate-f2zu.14.25. Kernel recheck deferred until the slate-f2zu.14 epic is empty.
