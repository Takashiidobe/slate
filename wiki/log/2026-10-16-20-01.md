# for_range recovers counted while loops (slate-5vj0.5.4)

_2026-10-16 20:01:59_

for_range::recover used to match Loop with a negated-< break guard, but on slate-parser output loop_to_while turns that into a labeled While first, so it never fired.

- label_elide::drop_loop_label (new, priority 8) drops a Loop/While label when every break/continue to it is direct (no nested loop or labeled block in between) and no expression in the loop holds statements; the jumps become unlabeled.
- for_range now matches While { label: None, cond: i < end, last stmt i += 1 | i = i + 1 | i = i.wrapping_add(1) }. The start is the counter's let (any earlier sibling, init effect-free and unchanged in between) or a preceding i = start with the let elsewhere.
- remove_mut gained invariant_within(name, region): inside the region nothing writes or mutably borrows the binding, outside it nothing mutably borrows it. for_range uses it for the end bound (Value/Var/Cast/arith only) and for the counter over the body, which rejects addr_of_mut!(i) in the body (gcc-torture pr59358, pr68841).
- A continue that targets the loop, or any expression holding statements in the body, blocks the rewrite.
- inline_temps::late lets a Prim temp initialized from a plain Var be inlined as a method receiver, so unsigned loops fold to i = i.wrapping_add(1).

New fixture tests/fixtures/for_range_recover.c covers recovered loops and the cases that must stay while (mutated bound, bound written through a pointer, counter used after the loop, counter bumped in the body, global bound). 17 fixture baselines regenerated.

Follow-up: slate-5vj0.5.10 (counter names reused across sibling loops defeat name-keyed def/use).
