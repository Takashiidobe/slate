# Link libgcc statically for f128 so soft-float honors fenv

_2026-10-17 08:54:43_

slate-kih1.5.

- Rust's compiler_builtins f128 soft-float (**trunctfdf2, **addtf3, \_\_floattitf, ...) ignores the dynamic rounding mode and never raises fenv flags; libgcc's soft-fp honors both. clang/gcc on linux-gnu and musl both use libgcc, so that is the oracle's behavior.
- A plain extern to a C shim does not help: the linker binds the shim's \_\_trunctfdf2 reference to compiler_builtins too (rlib precedes libgcc_s).
- Fix: when a program uses f128 on a Gnu/GnuEabi/GnuEabiHf environment (musl triples use the Gnu env), emit support module \_\_slate_libgcc with #[link(name = "gcc", kind = "static")]. The local crate's native libs link before compiler_builtins, so libgcc's routines win. Static (not gcc_s) because Rust musl targets link statically and have no libgcc_s.
- MSVC has no \_\_float128; other environments keep compiler_builtins.
- Promoted gcc-dg torture\_\_float128-truncdf-underflow, -truncsf-underflow, fp-int-convert-float128-timode-3.
- aarch64 list: 9 long double fixtures now pass (aarch64 long double is f128 since slate-kih1.1); float128.c added (clang rejects \_\_float128 on aarch64, slate-9qnu).
- i686 list: float16 (slate-kih1.7) and pre-existing gnu_library_builtins (slate-c0b3) added.
