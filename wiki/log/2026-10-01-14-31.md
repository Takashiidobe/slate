# Host library headers through explicit include dirs

_2026-10-01 14:31:52_

slate-parser-6x05.15: policy is that the slate sysroot gets no more headers; a project needing a host library (redis -> systemd/sd-daemon.h) is given its include dir explicitly.

- slate translate-project accepts -I, -isystem, -iquote, -idirafter (separate or joined). Dirs are absolutized against the cwd and appended to every unit's args. translate_project_command now reads compile commands once and passes them to both frontends.
- compile_commands::path_option recognizes every path option in separate and joined form (-isystem<dir>, -idirafter<dir>, -iquote<dir>, -include<file>, -imacros<file>, -isysroot<dir>, --sysroot=<dir>, -I<dir>); joined forms were previously passed through relative, so they broke when slate ran from another directory. Values starting with '-' are not paths (-include-pch).
- Test: cross_tu project_translation_takes_include_dirs_from_cli_and_joined_options (fixtures.host-include): fails without the CLI flag, fails without joined absolutization, and diffs C vs Rust output.
- c_corpus_sweep.py HOST_INCLUDE_DIRS (redis: /usr/include as -idirafter, so the sysroot still wins for libc). redis: 75 missing-dependency -> ok; now 291 ok, 4 rejected (2x offsetof 6x05.12, 2x __builtin_reduce_add 6x05.14).
