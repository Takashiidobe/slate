# Diagnose file-scope typedef redefinition with a different type

_2026-10-12 08:19:55_

slate-parser-v74.1.21. typedef unsigned int T; typedef unsigned long long T; was accepted on every flavor (two aliases in the IR); clang, gcc and cl.exe (C2371) reject it.

- TypeResolver::define_alias (sema/types.rs) compares the previous alias's underlying type with the new one via typedef_redefinition_allowed: CTypes::compatible, plus same_layout for the msvc flavor (cl.exe only warns C4142 for unsigned int vs int; the warning is not emitted).
- Same-type redefinition (typedef int U; typedef int U;) stays accepted. Block-scope typedef redefinition is untouched (still 'duplicate ordinary name', slate-parser-q1z8).
- Also surfaces the i686 windows case from slate-parser-v74.1.9 where a header redeclares the predeclared size_t with another width; clang agrees it is an error.
- Fixtures: error/{clang/linux,gcc/linux,msvc/windows}/x86_64/typedef_redefinition_different_type.c, error/clang/linux/x86_64/typedef_redefinition_signedness.c, msvc/windows/x86_64/typedef_redefinition_same_layout.c. Parser 8252/8252, no existing fixture changed.
- Docs: ir/declarations.
