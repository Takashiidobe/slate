# slate-f2zu.14.34.13 __builtin_constant_p: non-ICE scalar lowers to llvm.is.constant at -O1+, so kernel min() drops __compiletime_assert_N after inlining

_2026-11-15 11:39:03_

- bead: slate-f2zu.14.34.13
- kind: parser
- area: crates/slate-parser/src/sema/expression.rs
- area: crates/slate-parser/src/sema/fold.rs
- corpus: linux

Outcome: at -O1 and above, `__builtin_constant_p` of a non-folding scalar lowers to `intrinsic<bool, llvm.is.constant>(x)` as clang emits it, so the answer comes after inlining and kernel `min()`/`__types_ok` no longer keeps calls to the undefined `__compiletime_assert_N`.

Diagnostic or IR fact that was wrong: `statically_true(x) = __builtin_constant_p(x) && (x)`. In `min(max_segments, 2)` the macro binds `y` to a local, and clang -O2 lowers `__builtin_constant_p(local)` to `llvm.is.constant`, which folds to 1 after mem2reg/inlining, so the assert call is dead. slate folded it to 0 in the parser, so the Rust kept `unsafe { __compiletime_assert_667() }` and the vmlinux link failed with an undefined reference (6 sites in the block shard: blk_settings, bio, blk_mq, blk_iocost).

```c
int local_min(void) { int y = 2; return __builtin_constant_p(y) && y >= 0; }
```

Before (-O2):
```
return from_bool<i32, reason=return>(logical_and<bool>(ne<i32>(const<i32>(0), const<i32>(0)), ge<i32>(...)));
```

After (-O2; -O0 unchanged):
```
return from_bool<i32, reason=return>(logical_and<bool>(intrinsic<bool, llvm.is.constant>(read<i32>(%y)), ge<i32>(...)));
```

Fix:
- `Lowerer::expr` for `__builtin_constant_p` (crates/slate-parser/src/sema/expression.rs): when the operand does not fold, `statically_known_query` decides whether to emit the intrinsic. That needs optimization on, an integer, `_Bool`, f32 or f64 operand, and no side effects. This mirrors clang CGBuiltin, which also gives 0 for pointers and for operands with side effects.
- `fold::evaluate` gives the intrinsic 1 when its argument folds and 0 otherwise. So asm dead-arm pruning and specialization (sema/asm_constants.rs) still see the 0 they relied on, and a clone with known arguments sees 1.
- slate needed no change: the generic `llvm-intrinsic` extern path emits `#[link_name = "llvm.is.constant.i32"]`. That is the same LLVM call `core::intrinsics::is_val_statically_known` lowers to, which was the plan in the bead.
- Spec: wiki/concepts/ir/builtins.md (compile-time queries).

Fixtures:
- crates/slate-parser/tests/fixtures/clang/linux/x86_64/ir_constant_p_after_inlining.c (O0 and O2)
- crates/slate/tests/fixtures.release/constant_p_after_inlining.c. This is a release fixture because the debug differential build still emits the standalone always_inline body, where the query is false and the undefined assert call stays.

Limits: pointer operands still fold to 0, as in clang. gcc can answer 1 for pointers after inlining.
