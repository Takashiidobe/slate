# _Countof operator (C2y)

_2026-10-03 18:20:14_

slate-parser-cxg.20.2: _Countof is a keyword token for gcc and clang in every mode (StandardFeatures::keyword_countof); msvc keeps it an identifier, matching cl.exe.
New AST variants ExprKind::CountOfType { ty } and CountOfExpr(expr), parsed like sizeof (a parenthesized type name not followed by '{', else a unary operand).
TypeResolver::count_extent is the one rule: the operand must be an array type; incomplete arrays and non-arrays (including adjusted array parameters) are Rejected. Result type is size_t.
Constness follows the outermost extent only: int [7][n] is the constant 7 (constant folding resolves the type name with provisional extents, as the typer does), int [n][3] is not.
Lowering: fixed outer extent folds to a count_of-annotated constant and evaluates nothing; a variable outer extent reads the captured extent binding, capturing a type name's bounds or sequencing the operand's effects first (shared after_operand helper with sizeof; extent_length factored out of runtime_size).
<stdcountof.h> works unchanged from the installed compiler headers.
gcc.dg: countof, -compat, -no-compat, -pedantic, -pedantic-errors, -stdcountof, -vla, -zero, -zero-compile now pass for both flavors and are suite fixtures. countof-vmt.c needs VLA struct members (cxg.47). countof-compile.c's fix_* calls need parameter-referencing constant bounds in prototypes (slate-parser-cxg.57), a pre-existing sizeof gap too.
Error fixtures: error/clang countof_invalid_operand.c, error/msvc countof_not_keyword.c.
