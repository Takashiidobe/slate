# slate-f2zu.14.34.9 AsmNames: asm template words after rep/lock prefixes and %%-escaped registers (rep insb, %%ds) were rewritten to mangled sym operands

_2026-11-15 09:12:57_

- bead: slate-f2zu.14.34.9
- kind: bug
- area: crates/slate/src/frontend/lowerer/asm.rs
- target: x86_64

Outcome: x86 asm template words after an instruction prefix (`rep insb`,
`lock incl`) and registers written `%%ds` are no longer rewritten into `sym`
operands when a C item of the same name exists in the unit.

Symptom: kernel shard builds failed in LLVM's asm parser with
`invalid instruction mnemonic` on
`rep _RNv..._11slate_crate18___slate_unit_iomap4insb` (lib/iomap.c defines
`insb`/`insw`/`insl`) and `invalid register name` on
`movw %_RNv..._17___slate_unit_regs2ds,%ax` (arch/x86/boot regs.c has a C `ds`).

Reproducer:

```c
void insb(unsigned long port, void *buf, unsigned long n) {
  asm volatile("rep insb" : "+D"(buf), "+c"(n) : "d"(port));
}
int ds;
unsigned short getds(void) { unsigned short v; asm("movw %%ds,%0" : "=r"(v)); return v; }
```

Before: `"rep {0}", sym insb` and `"movw %{1},{0:x}", ..., sym ds`. After:
`"rep insb"` and `"movw %ds,{0:x}"`.

Cause: `AsmNames::text` (crates/slate/src/frontend/lowerer/asm.rs) rewrites
template words naming unit-local items to `sym`, skipping the statement's first
word and `%`-prefixed words.

- `rep` was taken as the mnemonic, so `insb` became an operand candidate.
- The parser IR keeps `%%` as its own `AsmPiece::Percent` (`"movw " %% "ds,"`),
  and `text()` reset its `previous` char per text piece, so `ds` did not look
  `%`-prefixed.

Fix: `previous` moved into `AsmNames` and carried across pieces (a `Percent`
piece sets it to `%`, an operand or label piece clears it). On x86
(`AsmNames::x86`, set in `asm_template`), a statement-start word matching
`x86_prefix` (rep/repe/repz/repne/repnz, lock, xacquire, xrelease, notrack, bnd,
data16/32, addr16/32, rex\*) keeps `statement_start` so the next word is still
the mnemonic.

Regression test: crates/slate/tests/fixtures/x86_64/asm_template_symbol_words.c
(`rep movsb` with a C `movsb`, `lock incl` with a C `incl`, `%%ds` with a C
`ds`, and `incl counter(%rip)` still lowered to `sym counter`; failed first).

Shards: lib, arch_x86_kernel, \_packed_m16, arch_x86_boot_m16 retranslated and
clean-built. lib and arch_x86_kernel now build. Both m16 shards now compile and
fail only at link (undefined rust_eh_personality, plus .S/linker-script symbols
intcall, HEAP, video_cards), filed as slate-f2zu.14.34.11.

Limits: Intel-syntax registers have no `%`, so `mov ax, ds` with a C `ds` is
still rewritten (slate-yar4.46).

See: slate-f2zu.14.34.8, wiki/concepts/ir/asm.md.
