Outcome: no code change; folding a break-at-head loop into `while !c` is deferred to slate-8ge7.24.23 (scope pass), because every such loop reaches lowering with its head `if` wrapped in a scope and matching through it is the see-through pattern this epic removes.

Probe: `do { if (a > 2) break; .. } while (0)` in a macro, a goto-made loop (`again: if (i >= MIN(limit, 4)) { goto done; } .. goto again; done:`), `for (;;) { if (a > 9) break; a++; }`, `while (1) { if (a > 20) break; a += 2; }`. All four lower to `loop { if c { break; } .. }`.

Wiring `structure::header_test` into the While(true), For with no head, and DoWhile arms (a `loop_or_while(label, body)`) changed none of them, because the head is never the first statement of the loop body:
- the lowered For is `Scope{[Loop{[Scope{[If{c, [Scope{[break 'blk]}]}, ..]}]}]}`: For's init scope (empty init), the no-increment body scope, and the C braces around `goto done;`;
- the goto structuring transform breaks to `block %B`, whose only statement is the loop, not to the loop;
- DoWhile's `continue_block` wraps the body in a Scope even when no continue uses it.

A prototype that peeled leading scopes (`take_scoped_head_break`, `bare_break`) and moved a block label onto its only loop (`loop_taking_block_label`) worked but was rejected as seeing through wrappers. The wrappers should be gone before the fold runs: lowering emits a scope only when the C block declares something, and/or an IR transform inlines declaration-free blocks and retargets `break block` to the loop.
