# slate-o3gw.27 unsafe placement: tail macros lost their return value

_2026-11-24 10:05:34_

- bead: slate-o3gw.27
- kind: bug
- area: crates/slate/src/backend/engine/unsafe_placement.rs
- area: crates/slate/tests/fixtures/macro_unsafe_tail.c

Outcome: Unsafe placement preserves value-returning tail macros, and the regenerated modular SQLite crate builds in release mode.

## Symptom

The 102-unit SQLite core and shell translated, but rustc reported E0308 in
`sqlite3HeapNearlyFull`, `sqlite3JournalSize`, and `openDirectory`.

## Reproducer

```c
#define MAX(a, b) ((a) > (b) ? (a) : (b))
int maximum(const int *value, int floor) { return MAX(*value, floor); }
```

Before, the function ended with `unsafe { MAX!(*value, floor); }`, yielding
`()`. After, it ends with `unsafe { MAX!(*value, floor) }`, yielding `i32`.

## Cause and fix

`FinalReturnTail` expresses an implicit function result as the last `Stmt::Expr`
of a function with a return type. `place_stmt` wrapped a macro with an unsafe
argument as `Stmt::Unsafe`, whose body discarded the macro result. Unsafe
placement now routes that function position through `place_slot`, matching
codegen's tail rule and retaining statement placement at other macro sites.

## Regression fixture

`crates/slate/tests/fixtures/macro_unsafe_tail.c` checks plain `translate` output
and compares both branches of the macro with the C reference. SQLite's core
and shell were regenerated with their existing compile databases. Only the
three failing macro calls changed, and `cargo build --release --locked` passed.
