# slate-dghn.56.9 pointer lattice: lifted &mut param passed directly while a later argument reads it (E0499 double mutable borrow)

_2026-11-14 09:19:18_

- bead: slate-dghn.56.9
- kind: bug
- area: crates/slate/src/backend/interproc/pointer_lattice.rs

Outcome: a call that passes a lifted `&mut` parameter straight to a `&mut` callee parameter and reads the same parameter in a later argument now evaluates that later argument into a temporary first, so it no longer fails E0499.

Symptom: cargo check of translated cpython: src/modsupport.rs do_mkvalue, 3x E0499 "cannot borrow `*p_format` as mutable more than once": `do_mktuple(p_format, p_va, 41i8, countformat(unsafe { *(p_format as *mut *const i8) }, 41i8))`. Rewrite, not lowering: the pointer lattice lifted `const char **p_format` to `&mut *const i8` in both functions.

Reproducer:

    static int value(const char **p_format) {
        const char c = *(*p_format)++;
        if (c == '(')
            return group(p_format, ')', count(*p_format, ')'));
        return c;
    }

Before: `group(p_format, 41i8, count(unsafe { *(p_format as *mut *const i8) }, 41i8))`. The implicit reborrow for argument 0 is live while argument 2 uses `p_format` again.
After:

    return {
        let __arg2 = count(unsafe { *(p_format as *mut *const i8) }, 41i8);
        group(p_format, 41i8, __arg2)
    };

Cause: rewrite_expr's Call arm (backend/interproc/pointer_lattice.rs) passes a lifted var unchanged when callee_accepts_directly, which reborrows it mutably for the whole call. Rust evaluates arguments left to right, so any later argument mentioning the var conflicts.

Fix: the Call arm records directly-passed args whose plan is mutable. hoist_args_after_reborrow moves every later argument that reads_var the same name into `let __argN = ..;` and the call becomes the tail of a block. C leaves argument evaluation order unspecified, so evaluating those arguments first is valid; the reborrowed argument is a plain variable read.

Regression test: crates/slate/tests/fixtures/ptr_lattice_reborrow_sibling_arg.c. slate profile 39/39, no other fixture output changed.

Limits: only directly-passed lifted vars are handled; a raw pointer bridged with `&mut *p` next to a read of `*p` compiles and is not changed.
See: slate-dghn.56.7 (same cpython check run).
