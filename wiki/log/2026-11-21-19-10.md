# slate-8ge7.24.8 decl-init: fuse uninitialized locals and preserve written initializers

Outcome: Slate fuses only uninitialized declarations with a first assignment. Source-written and compiler-supplied initialization is retained.

Before: Rust lowering gave int x; a zero placeholder. zero_init::fold matched that placeholder and int x = 0 alike, and could pull a later RHS ahead of intervening work. branch_init also recognized explicit pure initializers as removable.

After: decl-init sinks the source declaration to the first direct ordinary write in the same straight-line IR list. The binding ID and typed RHS survive, and all computations keep their order. int x = 0; x = f(); retains the initial zero and the separate assignment.

Rule: only ordinary automatic scalar declarations with neither initializer nor auto_init qualify. DefUse checks that the assignment is the only reference in the straight-line range. Scans are bounded to 32 siblings and stop at scope, label, macro, comment and lifetime barriers. Rust lets carry local origin. branch_init still emits let x = if ... for proved two-arm initialization of an uninitialized binding.

Fixtures: fixtures/zero_init.c pairs an explicit zero with an uninitialized local. fixtures/branch_init_let_if.c covers the corresponding branch patterns. fixtures.transforms/decl-init/first_write.c checks load-before-call order and the cleanup, address and label barriers. The existing zero_init_cleanup_guard_order.c and zero_init_load_before_call_order.c exercise the kernel regressions.

Limits: Uses outside the bounded straight-line region still use existing lowering. General Rust definite initialization is separate.

Validation: Clippy and formatting passed. Release nextest slate (44) and merge (1) passed after regenerating 36 Slate checks and 4 merge checks with update_filecheck.py.
