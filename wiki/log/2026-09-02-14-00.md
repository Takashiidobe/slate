# Fold consecutive case values into inclusive range patterns

_2026-09-02 14:00:28_

Switch arms with many case values printed as `48 | 49 | 50 | ... | 57`. No type
threading was needed: `Pattern::InclusiveRange { start: i128, end: i128 }` already
existed in `src/backend/rust_ast.rs` and codegen already prints `{start}..={end}`.
It was only reachable from `case_range_pattern` in `src/frontend/lowerer/cir_ops.rs`,
i.e. GNU `case a ... b` ranges; individually listed case values never produced one.

New backend rule `src/backend/engine/rules/pattern_range.rs` (`pattern_range::fold`,
priority 47, `NodeKindTag::Match`): for a `Pattern::Or` whose alternatives are *all*
integer literals, sort, dedupe, and collapse each run of consecutive values of length
>= 3 into an `InclusiveRange`. Shorter runs keep their original pattern variant, so
`100 | 200` is untouched and `-3 | -2 | -1 | 7` becomes `-3..=-1 | 7`.

Sorting is safe because `Pattern::Or` is only built by `structure_dispatch::pattern_of`
from an integer switch arm value list — no bindings, no guards, no side effects, and
alternatives in one arm are order-independent. `U128` values above `i128::MAX` bail
out rather than wrap.

Fixture `tests/fixtures/switch_case_range_fold.c`. libexpat `xmltok.rs` now emits 13
range arms, including the hex-digit classifier (`48..=57`, `65..=70`, `97..=102`) and
a multi-run arm `0..=3 | 8..=10`; the crate still compiles.
