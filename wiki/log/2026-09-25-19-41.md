# Static-assertion checker honours block-scope forward tag declarations

_2026-09-25 19:41:35_

slate-parser-rdj: a block-scope 'struct T;' already declared a new incomplete tag during lowering (module.rs via TypeResolver::declare_incomplete_tag), but the static-assertion checker in assertion.rs ran its own declaration walk and skipped the form, so a static_assert after 'struct T;' still resolved the outer tag. Lowering was verified correct first: clang and slate both report incompatible pointer types for 'struct T; struct T *p = gt;'. Fix: replaced declare_incomplete_tag with TypeResolver::declare_forward_tag(&DeclarationSpecifiers) -> bool, which recognises the declarator-less 'struct-or-union identifier;' form and declares the tag in the current scope; module.rs and assertion.rs both call it, so the two passes cannot drift. New fixture tests/fixtures/sema/block_forward_tag_hides_outer.c (fails before, passes after, clang 22 accepts). Filed slate-parser-cs2: const_expr.rs parses the identifier 'defined' as the preprocessor operator in every expression, found while writing the fixture. Updated wiki/concepts/entity-model.md. Verified with cargo clippy --allow-dirty --fix, cargo fmt, cargo nextest run --release (pass).
