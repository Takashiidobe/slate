Outcome: translate-project builds all-freestanding, SSE-free x86 crates for x86_64-unknown-none or a generated i386-unknown-none.json spec, with rustflags derived from recorded codegen facts, and rejects crates whose units disagree.

## Gap and why it mattered

Kernel units (`-mcmodel=kernel -fno-PIE -mno-red-zone -mno-sse -mno-80387 -fcf-protection=branch -mretpoline-external-thunk -mindirect-branch-cs-prefix`) were translated into crates targeting the host `x86_64-unknown-linux-gnu`. `-mcmodel`, `-mred-zone`, `-mindirect-branch-cs-prefix` and `-mretpoline` were parsed and dropped, so nothing downstream could choose the right Rust target or flags. `-m16` boot code used the hosted i686 triple.

## Before

`machine` facts absent from the IR; `.cargo/config.toml` only set a triple (plus `+16bit-mode` for `-m16`).

## After

```
machine [code_model=kernel, pic=none, red_zone=off, cf_protection=branch, indirect_branch_cs_prefix];
```

```toml
[build]
target = "x86_64-unknown-none"
rustflags = ["-Crelocation-model=static", "-Zcf-protection=branch", "-Zretpoline-external-thunk", "-Zindirect-branch-cs-prefix", "-Ctarget-feature=-x87"]

[unstable]
build-std = ["core", "compiler_builtins"]
```

`-m16 -march=i386 -ffreestanding -mno-sse` writes `i386-unknown-none.json` (cpu from `-march`, `+16bit-mode,-32bit-mode`, soft-float) and `json-target-spec = true`.

## Implementation

- Parser: `CodegenOptions` gains `code_model` (`CodeModel`), `red_zone`, `indirect_branch_cs_prefix`, `retpoline` (clang only); they moved out of `CODEGEN_ONLY_FLAGS`. `Module.machine: MachineCodegen` carries them plus pic and cf-protection; printed after `nostdinc;`. gcc's `-fcf-protection=check` prints `check`.
- Slate: `project::build_target::BuildTarget::for_module` derives triple, spec, rustflags and build-std per unit. Hosted, SSE-on, and non-x86 units keep the old host behavior. `project_build_target` errors with "units A and B build for different targets (...)". Rustflags only spell differences from the Rust target's defaults (kernel code model and no red zone on x86_64-unknown-none).
- `tools/corpus/e2e.py shard_units` splits each shard by a codegen key (mode, march, cmodel, pic, red zone, cf-protection, retpoline family, sse, x87, core runtime). On linux this adds `arch_x86__packed_cg1` (vdso64), `arch_x86_boot_cg1` (boot/startup) and `drivers__packed_cg1` (EFI libstub).

## Fixture

- `crates/slate/tests/differential.rs::freestanding_projects_build_for_bare_metal_targets`: kernel flags and freestanding `-m16` crates cargo-build; kernel plus vdso-style units error.
- `crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/codegen_flag_macros.c` prefix `MACHINE`.

Limits: unmapped: `-fstack-protector-strong` (kernel's %gs canary; Rust-for-Linux leaves it off too) and `-mskip-rax-setup` (no rustc flag). An SSE-enabled freestanding unit keeps the hosted triple because x86_64-unknown-none uses the soft-float ABI. Each staticlib still has its own panic handler and core (slate-f2zu.14.34.6). A missing `-fpic`-family flag leaves the Rust target's relocation default.
