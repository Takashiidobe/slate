# Bridge extern calls passing or returning _Complex long double

_2026-11-07 09:08:21_

slate-p58o.4.13: long_double_complex.c failed on x86_64 for every libc call returning _Complex long double (conjl, csqrtl, cexpl, ...). Those externs were declared directly with num_complex::Complex<LongDouble>; x86_64 C returns complex long double in st0/st1 (COMPLEX_X87) while Rust expected a hidden return pointer, so results were garbage. i686 passed only because there it is returned through a hidden pointer. The extern direct-call guard (values.rs) and the extern declaration skip (lowerer.rs) used holds_long_double, which does not match Complex(F80). New Tables::bridges_long_double / extern_bridges_long_double (lowerer/f80.rs) also accept complex f80, so these calls go through the existing cf80 name-tagged C bridge (__slate_conjl__rcf80_cf80). passes_long_double is unchanged so Rust-defined functions taking complex long double do not become export barriers. Removed long_double_complex from fixtures.unsupported/x86_64-unknown-linux-gnu.txt. slate and slate-i686 profiles green.
