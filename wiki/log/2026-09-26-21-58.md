# Implicit builtin calls redeclare the same-named function

_2026-09-26 21:58:36_

slate-parser-l94: `exit(1)` called with no visible declaration, followed by `void exit(int);`, lowered to two `fn @exit` (one from Lowerer::builtin_declaration, one from the user declaration). Clang treats the implicit builtin FunctionDecl and every later (or earlier block-scope extern) declaration as one redeclaration chain, even an incompatible one: clang -std=c89 on `exit(1); int exit(long);` emits a single @exit.

Fix is in name resolution, not lowering, because entity types are only known once a declaration has been lowered, so the call in an earlier function body cannot see the later declaration's type:
- names.rs: an implicit builtin call (plain or GCC `__builtin_`-prefixed) references the linked (`Resolver::linked`) function entry of the builtin's name if one exists; otherwise it is parked in `implicit_builtin_calls` and gets its reference when `bind_ordinary` first links a function of that name.
- expression.rs builtin_callee: a function binding with no entity type yet (declared later) is taken as the builtin's declaration, and the call keeps the builtin's signature.

Unresolved implicit calls push no binding, so names dumps and binding numbering in existing fixtures are unchanged.
