# slate-3amj.36.2 TargetAbi: gcc -mabi=ms makes win64 the default convention (variadics, main, va_list char*); dylink compiler/translate_args keys

_2026-11-19 14:58:43_

- bead: slate-3amj.36.2
- kind: feature
- area: crates/slate-parser/src/compiler_args.rs
- area: crates/slate-parser/src/sema/types.rs
- area: crates/slate/tests/dylink.rs
- flavor: gcc
- target: x86_64

Outcome: gcc `-mabi=ms|sysv` is parsed instead of "unsupported compiler flag ignored"; on x86_64 `-mabi=ms` makes win64 the default convention (variadics and `main` included) and `va_list` a `char *`, and translated code links and runs against native ms_abi code in a new dylink fixture.

Gap and why it mattered: `-mabi=ms` (EFI and other freestanding x86_64 code) was dropped, so slate lowered every function as sysv64 while the native code it links with used the Microsoft x64 convention.

Before (`--flavor=gcc -mabi=ms`):

```
⚠ unsupported compiler flag `-mabi=ms` ignored
fn @take(b: @big, d: f64) -> i64 [abi=sysv64(native_c, scalar) -> scalar]
```

After:

```
fn @take(b: @big, d: f64) -> i64 [abi=win64 ms_abi(native_c, scalar) -> scalar]
fn @logf_(format: ptr<const i8>, ...) -> i32 [abi=win64 ms_abi(scalar) -> scalar];
fn @main(argc: i32, argv: ptr<ptr<i8>>) -> i32 [abi=win64 ms_abi(scalar, scalar) -> scalar]
global va_list_size = size_of<u64, ptr<i8>>(8)
```

Implementation:
- compiler_args.rs: `Opt::X86Abi` intercepts only `-mabi=ms` and `-mabi=sysv` (other `-mabi=` values keep the old path). gcc x86_64 `ms`: `default_convention = Win64`, `main_takes_default_convention = true` (gcc reads `argv` from `%rdx`), `profile.va_list = CharPointer` (gcc's `sizeof(va_list)` is 8). gcc i686 ignores both; clang accepts only `sysv` on x86; everything else is `not supported for target`.
- sema/types.rs: a function declarator's default convention now also applies to variadics when the convention `admits_variadic` (C, win64, sysv64); stdcall/vectorcall defaults still leave variadics as C.
- `sysv_abi` under `-mabi=ms` stays `CallConv::C`, which is the target's own sysv64 and Rust's `extern "C"`. `cdecl` on x86_64 under `-mabi=ms` is win64 (sema/types.rs `calling_convention`), since gcc ignores `cdecl` there and reads the arguments from `%rcx`/`%rdx`.
- tests/dylink.rs: `dylink.json` gains `compiler` (argv[0] of the translated host's compile command, so the flavor) and `translate_args` (translation only). The native side stays clang and spells ms_abi with attributes under `__clang__`.

Fixtures:
- crates/slate/tests/fixtures.dylink/abi_mabi_ms (linux): ms_abi exports, a 1000x host callback, an ms variadic, 8-byte struct return, 24-byte struct by reference, float/double/int mix, win64 `main`. Libc reached through `sysv_abi` pointers. It crashes when `-mabi=ms` is removed from `translate_args`.
- crates/slate-parser/tests/fixtures/gcc/linux/x86_64/abi_mabi_ms.c (MS and last-wins SYSV), error/clang/linux/x86_64/abi-flag-mabi-ms.c, error/gcc/linux/aarch64/abi-flag-mabi-ms.c.

Limits:
- Variadic definitions under `-mabi=ms` hit slate's existing "variadic ms_abi definition" barrier.
- printf and friends lower to slate_support, so translated code works where a native gcc `-mabi=ms` binary calling glibc printf would crash.
