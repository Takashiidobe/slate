# Assignment results: evaluate the stored value once, cut bit-field results to width, promote them like the bit-field

_2026-09-30 15:10:08_

slate-parser-dfrt. The hoister (src/sema/effects.rs) returned the stored value itself as an assignment's result, so the RHS was re-evaluated: b = f(); emitted write(b, call f) plus a bare call f (discard re-emitted it), a = b = f() called f three times, while ((c = getc(f)) != EOF) called getc twice per iteration, and b = (i = i + 1) recomputed i + 1 after the write (stored i+2). Fixture expectations had captured the duplicates since the effects pass landed.

Fix: Hoister::store. discard() of a Store (also through promotion conversions, promoted_store) emits only the Write. In value context a non-constant stored value is bound to a [synthetic] temporary first and the result reads it; constants (through conversions) chain directly.

Found while there and fixed with it:
- A store to a bit-field yielded the untruncated value (a = s.bf = 300 gave 300; clang 44). assigned_value() now yields widen<T>(truncate<iNb>(v)) for =, compound assignment and prefix ++/--.
- clang's getSourceBitField: =, compound assignment and prefix ++/-- on a bit-field promote like the bit-field ((s.bf = x) > -1 compares as i32). New Typed::source_bits, set by the typer; rvalue_type promotes from it; lowering's expr() applies the matching Promotion conversion. gcc also promotes postfix ++/-- (clang: s.bf++ > -1 is 0, gcc 1), so postfix sets source_bits under gcc only.

Fixtures: clang/.../assignment_result_evaluated_once.c, gcc/.../bitfield_assignment_result_promotion.c; ~690 fixture expectations regenerated (IR only, no diagnostic changes). Wiki: ir/control-flow.md hoisting, ir/places-pointers.md bit-field promotion.
