# slate-3amj.60 resolve_coverage: -fsanitize-coverage= value sets, legacy levels, fuzzer seeding and clang coverage_sanitizer feature

_2026-11-17 13:40:29_

Outcome: gcc and clang flavors now validate -fsanitize-coverage=/-fno-sanitize-coverage= and clang answers __has_feature(coverage_sanitizer) from the resolved coverage set, instead of warning "unsupported compiler flag ignored".

Gap: slate-3amj.58 left the coverage lists unhandled. clang sets coverage_sanitizer only for some values, and slate tied it to -fsanitize=fuzzer alone, so `-fsanitize=fuzzer-no-link -fsanitize-coverage=0` answered 1 where clang answers 0.

Before (`slate emit-slate-ir -fsanitize-coverage=trace-pc s.c`, s.c: `int c = __has_feature(coverage_sanitizer);`):

    ⚠ unsupported compiler flag `-fsanitize-coverage=trace-pc` ignored
    global c: i32 = const<i32>(0)

After:

    global c: i32 = const<i32>(1)

Implementation (src/sanitizers.rs `resolve_coverage`, called from `Sanitizers::resolve`; `Opt::SanitizeCoverage` in compiler_args.rs):
- gcc: names `trace-pc`, `trace-cmp` only; empty list is "missing argument"; no macro or feature.
- clang: lists replay in argv order. An integer value (`parse_clang_integer`: `0`, `0x3`, legacy levels) clears every feature; `0`/`all` inside a list are errors, as is `-fno-sanitize-coverage=all`. `func`/`bb`/`edge` exclude each other.
- fuzzer/fuzzer-no-link (final set) seed inline-8bit-counters, indirect-calls, trace-cmp, pc-table, plus stack-depth on Linux/Android.
- A positive list resets to empty while scudo or realtime is enabled and never removed by any -fno-sanitize= (clang's SupportsCoverage check).
- Without func/bb/edge, trace-pc[-guard]/inline-*/control-flow imply edge and stack-depth implies func. The feature is func|bb|edge|indirect-calls|trace-cmp|trace-loads|trace-stores|control-flow.
- `Sanitizers` is now `{ checks, coverage }`; the `coverage_sanitizer` row left `CLANG_FEATURES`.

Fixtures: clang/linux/x86_64/sanitize_coverage.c (19 prefixes), gcc/linux/x86_64/sanitize_coverage.c (3), error/clang/linux/x86_64/sanitize-coverage-{unknown,level-in-list,func-bb,no-all}.c, error/gcc/linux/x86_64/sanitize-coverage-{clang-only,empty,level}.c. Every value was checked against clang 23 / gcc 16.

Limits: clang's -Wdeprecated warnings for func/bb/edge without a trace type, trace-bb, 8bit-counters and nonzero levels are not reported. -fsanitize-coverage-allowlist=/ignorelist= stay unsupported flags.
