# regen-filecheck now covers cross-TU fixtures

_2026-09-06 10:58:37_

`tools/regen-filecheck.sh` extracted the fixture name from
`filecheck/<name>/checks-N.txt`, which for a cross-TU failure names the
generated _module_ (`symbols`), not the fixture directory
(`gnu_symbol_pragmas`). It resolved by scanning `tests/` for `<name>.c`,
which breaks whenever the module name is not unique (`main.c` is in most
`fixtures.multi` fixtures).

Now the two check-file shapes are distinguished by work root: paths under
`target/cross-tu/` are project runs, so the fixture is the directory holding
`filecheck/`; everything else keeps the old `filecheck/<fixture>/` rule.
Project names resolve directly against `tests/fixtures.multi` and
`tests/fixtures.library`, and unresolved fixtures are listed at the end.

`update_filecheck.py` silently ignored project sources with no
`@lowering`/`@rewrite` markers, so a fixture whose only failing checks are
handwritten regenerated as a no-op with no output. It now warns per file.

This does not fix `gnu_symbol_pragmas`: its `LOWERING-DAG` lines are
handwritten and nothing can regenerate them. Its failure is a real behavior
change from the in-flight `strong_symbols` work, not a stale snapshot.
