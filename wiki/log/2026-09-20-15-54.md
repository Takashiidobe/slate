# Apply declaration-scoped pragmas to layout and symbols

_2026-09-20 15:54:58_

Pragmas were parsed and then dropped everywhere, so `#pragma pack(1)` gave an
unpacked layout. New `src/sema/pragmas.rs` resolves them.

- One ordered walk over `unit.decls`, descending into function bodies so a
  `StmtKind::Pragma` changes the same state. It produces a *lookup*, not a
  running state, because sema lays out tags on demand rather than in source
  order: packs key on `TagId`, symbol pragmas on the name. `apply` only fills
  `SymbolAttributes` fields the declaration left open, so an explicit attribute
  wins.
- `#pragma pack(N)` is a cap, not a pack-to-1: field align becomes
  `min(max(natural_or_packed, aligned_attr), N)`. It caps an `aligned` on a
  field but not on the record, and while a pack is in effect bit-fields stop
  padding to avoid straddling a unit. Verified against
  `clang -Xclang -fdump-record-layouts`.
- Parser fixes found on the way: `pack(push, lbl, 1)` parsed the label as the
  alignment expression (`PragmaKind::Pack` gains `label`), and `ms_struct`
  was modelled as a push/pop stack when it is really `on|off|reset`.
- `ms_struct on` is `Unsupported("ms_struct record layout")` rather than an
  Itanium layout wearing an MS label. `__attribute__((ms_struct))` has the same
  gap and stays silent for now, since erroring would regress three fixtures
  (slate-parser-dyd.29).
- Region-scoped FP pragmas split out as slate-parser-dyd.28: they need IR
  surface that does not exist (`FloatingSemantics` has no contraction or
  complex-range field).

Corpus-wide layout diff: exactly 10 records changed out of 4055, all in
pack-using fixtures, all now matching clang -- including gcc-torture
20131127-1, pr58570 and pr79737-1. Sweep unchanged at 2487/2681, 0 regressed.
