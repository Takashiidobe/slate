# add Type::String variant

_2026-09-02 15:25:18_

BufferKind::StringOwned rendered as Type::Custom("String".to_string()) in
length_lattice.rs. Added a proper Type::String variant to rust_ast::Type,
sibling to Custom/Str, and pointed that one call site at it.

Mechanical: fixed the 3 exhaustive matches the compiler flagged -
codegen.rs's ty() renderer (writes "String", same output ident_path would
have produced for Custom("String")) and two type_mentions_* predicates in
lowerer/types.rs (folded into the existing false-catchall arm alongside
Custom(_)).

Left is_string/is_str_or_slice/is_byte_str_or_slice in
engine/rules/libc_call.rs untouched - they only recognize
Type::Generic{name:"String",..}, not Custom or the new String variant, so
behavior for the StringOwned call site is unchanged (still falls to their
wildcard false arm either way, same as before).

Verified: cargo check/clippy clean, `rewrites` profile 92/92 (length_lattice
is backend/interproc, not frontend/lowering).
