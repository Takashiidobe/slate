# Lower record, union, and bit-field access

_2026-09-17 20:42:21_

slate-parser-lh7.2.7. Member access stays a projection path, resolving the
ir-spec open question against a `field_ptr` value: `PlaceKind::Field` now
carries `bits: Option<BitFieldAccess>` alongside `base` and `index`.

- Anonymous struct/union members expand during lowering into the chain of
  field indices through them, so `o->left` becomes
  `field0(field1(field2(deref(..))))`. Unions need no new machinery; a member
  is the same projection onto overlapping storage.
- Bit-field places print their resolved slice:
  `bitfield1<unit=0, bytes=0..2, bits=3..8>(..)`. The unit/byte extent comes
  from the record layout's `bit_units`/`field_units`; the bit range is
  relative to the unit, LSB-first, matching the existing absolute
  `bit_offsets`. Place type stays the declared field type (its signedness is
  what the read extends by).
- A bit-field rvalue promotes by declared width, not storage type, so
  `unsigned low : 3` reads through `reinterpret<i32, reason=promotion>`.
  `update` promotes `OldValue` the same way, so `f->high += 1` adds at i32 and
  converts back on store, matching clang.
- `&f->low` is now rejected. `sizeof(f->low)` is still accepted wrongly
  (slate-parser-ybq).
- Fixed adjacent layout bug: a tagged record body with no declarator inside a
  record (`struct Outer { struct Tagged { int z; }; ... }`) was being treated
  as an anonymous member, inflating the record. Only untagged struct/union
  bodies are anonymous members now. Verified `sizeof` against clang.

Layout for the new fixture was diffed against
`clang -cc1 -fdump-record-layouts`. Fixture: tests/fixtures/sema/ir_records.c.
