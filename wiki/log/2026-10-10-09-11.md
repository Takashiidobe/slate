# Whole-storage asm bridges for padded, bit-field, union, and bool aggregates

_2026-10-10 09:11:47_

slate-3f8g.4.17.20: aggregate register operands no longer need fully occupied storage.

Finding: the field-wise marshaling the bead proposed is unnecessary. Slate records already
spell padding as __slate_pad_N byte fields, bit-field units are integer-backed bitfields
wrappers, and locals start zeroed (union member writes keep other bytes), so every byte of
a record value is initialized and a whole-storage transmute is sound. Memory C leaves
uninitialized (malloc) is uninitialized for every typed copy in Slate, asm or not.

Change (lowerer/asm.rs):
- asm_full_storage -> asm_bridgeable: records with layout accept bit-fields, padding,
  partial union members, and _Bool fields; the 'field-wise bridge' barrier is gone.
- asm_decode normalizes restricted values: asm_bool_offsets collects _Bool byte offsets
  through structs and arrays (unions and bit-field getters need none); the scratch integer
  becomes (x & keep) | ((x >> s) as u8 != 0) as uN << s per bool byte before the transmute.
- A _Bool field inside a 16/32/64-byte vector-register aggregate is a barrier.

Fixture x86_64/asm_aggregate_field_bridge.c (extended, promoted): padded +r/add, sete into a
_Bool-led struct, bit-field xor, partial union in/out, nested struct with _Bool array, and an
8-byte padded struct copied through a register. slate profile 14/14.
