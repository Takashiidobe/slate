# slate-8ge7.24.11.1 lower_pointer_offset: .add/.sub from the IR amount type; delete ptr_offset rule

_2026-11-21 22:46:29_

- bead: slate-8ge7.24.11.1
- kind: rewrite
- area: crates/slate/src/frontend/lowerer/pointers.rs
- area: crates/slate/src/backend/engine/rules

Outcome: PointerOffset lowers to .add/.sub from the IR amount's C type, and the ptr_offset Rust rule (and its only helper module, rules/representable.rs) is deleted.

Before: lowering always emitted `p.offset(i as isize)` / `p.offset(-(i as isize))`; ptr_offset (2922 fires / 452 fixtures, 2 bug logs) guessed signedness from Rust spellings (casts, local var types) and rewrote to .add/.sub. It missed amounts whose type it could not see: struct fields, `if` expressions.

After (FunctionLowerer::lower_pointer_offset, crates/slate/src/frontend/lowerer/pointers.rs):
- amount with an unsigned C integer type (tables.resolve_type(..).integer_bits() unsigned) -> `p.add(i as usize)` / `p.sub(i as usize)`.
- amount lowered to a literal (lower_number's `Expr::Cast { Value }`, also sizeof layout queries) that is non-negative and <= isize::MAX -> `p.add(3)` / `p.sub(3)`.
- everything else keeps `.offset(i as isize)`. Wrapping, byte (VLA) and function-pointer offsets are unchanged.

C: `memcpy(c->bytes + c->length, buf, n)` with `size_t length`
Before: `(*cookie).bytes.as_mut_ptr().offset((*cookie).length as isize)`
After:  `(*cookie).bytes.as_mut_ptr().add((*cookie).length as usize)`

Fixtures: gnu_cookie_stdio, gnu_libc_stdio, packed_sds_headers regenerated (all three newly use add/sub); every other fixture, including ptr_offset_unsigned.c, keeps its output.

Limits: `p[c]` with `unsigned char c` stays `.offset((c as i32) as isize)`: C promotes c to int, so the IR amount is signed. Same as the rule.
