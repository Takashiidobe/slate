# Pointer to _Bool is a null comparison, not int-conversion

_2026-09-26 08:47:10_

slate-parser-dyd.68, found while surveying slate-parser-wxs.5.
classify_conversion treated every pointer->arithmetic conversion across an
assignment, argument, return or initializer as -Wint-conversion. That is
DefaultError under the clang flavor, so '_Bool b = p;', 'b = p;', passing p to a
_Bool parameter, 'return p;' from a _Bool function and 'static _Bool z = &n;' all
failed to lower. clang 22, gcc and cl accept every one of them silently. glibc's
assert(ptr) converts its operand to _Bool, so any assert on a pointer failed too;
gcc-torture/pr58831.c had recorded that failure as its expected output and now
lowers.

C 6.3.1.2: converting a scalar to _Bool compares it against 0. New
CastKind::PtrToBool (convert.rs) is returned before the int-conversion check, and
expression.rs lowers it through condition(), i.e. ne(p, null), for both implicit
conversions and explicit casts. The explicit cast (_Bool)p used to emit
ptr_to_int<bool>(p), which reads as a truncation. That was inconsistent with
int/float->bool (ne(x, 0)) and with pointer conditions.
Static initializers fold to clang's values (&n -> 1, (int *)0 -> 0).
