# Storage for statically initialized flexible array members

_2026-10-18 09:03:08_

slate-9ox1.3.17, .3.7, .3.8: a static like struct {int a; int x[];} d1 = {0, 0} or union U {char a[]; int i;} u = {"12345"} lowered the FAM as [T; 0] while the initializer supplied N elements, so rustc rejected it with E0308.

- Tables::flexible_member finds a defined static whose aggregate initializer gives an incomplete-array field a sized array<T, N>. Tables::flexible_globals maps those bindings to their declared record's Rust name.
- lower_static builds __SlateStorage_<name>: build_record runs on a copy of the record definition with that field's type set to array<T, N> and the layout size grown to cover it, rounded to the record's alignment. Prefix offsets and alignment match the declared record, including a FAM inside tail padding and packed records.
- The initializer goes through lower_aggregate_into with the storage type forced, which always takes the zeroed-temp-plus-assignments path, so storage padding fields never need a struct literal.
- lower_binding returns *(addr_of_mut!(name) as *mut Record) for these globals, so every access, address, and whole-record copy sees the C type and sizeof stays the C value. This also works in other statics' initializers (char *p = tail.name).
- Over-aligned or bit-field records are a barrier; filed as a P3 follow-up.
- New fixture tests/fixtures/flexible_array_static_initializer.c. Promoted gcc-dg pr25805 and pr119001-1, gcc-torture 20010924-1 and pr33382, and fixtures/gnu_init_designator_survey.c.
- ir-to-rust-lowering.md has a row for the storage type.
