# cxx-stdlib-shim-lowering concept doc

_2026-08-25 12:44:21_

Added wiki/concepts/cxx-stdlib-shim-lowering.md, proposing the raw-lowering target for std::string/vector/map/iostream/arbitrary C++ types: opaque byte buffer (sized via cir.record_layouts) plus a generated extern C wrapper function per call site, compiled into a companion .cpp by the existing C++ toolchain, so every construct/method/move/destruct call crosses through real C++ code rather than being reimplemented. Chose this over both direct reimplementation (rejected per the earlier cxx-translation-pain-points.md finding: std::string alone expands to 86 inlined cir.funcs including a self-referential SSO pointer needing move fixup) and the cxx crate (hand-authored static bridge, doesn't cover arbitrary user types) and raw mangled-symbol linking (rejected: Itanium ABI passes non-trivial-by-value params via hidden reference, differs from C ABI classification for the same repr(C) struct -- silent corruption, not a lint). Documents why this closes the SSO-move and virtual-dispatch gaps for free (real C++ code does the move/vtable resolution every time, Rust never touches the bytes), reuses the setjmp/longjmp and exceptions ABI-flip precedent for exceptions crossing the shim boundary, and records concrete limits: no-linkage/lambda closure types can't be named in a separate companion file, shim compilation must match the original TU's preprocessor flags exactly (_GLIBCXX_USE_CXX11_ABI, _GLIBCXX_DEBUG) or layout silently diverges, and the later idiomization pass must cut along whole-type-graph lines (can't idiomize one member type while its container/base shims still expect original layout). Cross-linked from cxx-translation-pain-points.md's stdlib section. No code changed.
