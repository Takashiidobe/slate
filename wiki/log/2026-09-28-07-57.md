# clang/test MS-mode three-way sweep

_2026-09-28 07:57:28_

slate-parser-v74.4: built tools/llvm_lit_sweep.py (sibling of gcc_dg_sweep.py) and ran it over the 317 MS-mode .c files in clang/test.

Scope: Windows-triple / %clang_cl RUN lines that compile %s. Skipped Driver, PCH, CIR, ClangScanDeps, OffloadTools and utils; -E/-P runs; -verify runs whose prefixes expect errors (30 files). That leaves 161 configurations.
Oracles: clang --target=<triple> -fsyntax-only with the slate MSVC sysroot as -isystem, and tools/cl.exe /Zs /TC /std:. Test feature flags (-fblocks, -fenable-matrix, -fdefer-ts...) go to clang only; -W flags go to both clang and slate.

Result: 80 all-accept, 50 clang-only-accepts, 15 clang-cl-only gaps, 13 shared gaps, 2 msvc-only gaps, 1 all-reject.

Finding: slate defaults every flavor to gnu23, clang 22 to gnu17. Under gnu23, K&R definitions and () = (void) broke 3 files, so the sweep now pins gnu17 for the clang flavor and files the default as one bead (v74.1.11).

Filed v74.1.7-.18 (SEH, MS intrinsic lowering, size_t under ms-compat, declspec align vs pragma pack, default std, __builtin_ms_va_list, __m128 typedef name, __is_target_*, MS asm {k1}, and three non-MS P4s: blocks, CFString, matrix) and v74.2.2 (msvc implicit function declarations). Each has a Migrate-on-fix list.

Migrated 200 fixtures to tests/fixtures/msvc/clang-test (125 clang, 75 msvc copies where cl.exe also accepts). The target goes in SLATE-FILECHECK-ARGS, not the directory, because update_filecheck.py reads the directory triple only under sema/.
Validation: cargo nextest run --release --no-fail-fast, 4580/4580 pass.
