# Type neon_vector_type and neon_polyvector_type as lane-count vectors

_2026-11-07 13:58:46_

slate-e36k.12: neon_vector_type(N)/neon_polyvector_type(N) were unmodeled clang attributes, so NEON typedefs lowered to the scalar element (int32x4_t = i32) and arm_neon.h failed at the first __builtin_bit_cast (vbfdotq_f32).
- ast::Attribute::NeonVectorType(Expr) (both spellings; poly only changes C++ mangling/overloads), a type attribute wrapped as VectorSize::Lanes like ext_vector_type, so it lowers to vector<T, N>. Threaded through visit, reachability, sema attribute uses and attribute folding. attribute_support: clang_only on every target (clang 23 accepts it on x86_64 too).
- generate_clang_builtins.py: NEON LLL (128-bit) now decodes to __int128_t/__uint128_t; vmull_p64's poly128_t return was an unresolved Opaque.
- Full arm_neon.h --all-declarations now parses for aarch64-unknown-linux-gnu, aarch64-pc-windows-msvc and armv7-unknown-linux-gnueabihf; aarch64-msvc -include wchar.h --all-declarations succeeds again (slate-libc-gen's generic fallback left as is).
- Layout matches clang: 128-bit vectors align 16 on aarch64, 8 on armv7.
