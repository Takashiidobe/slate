# libexpat bring-up: pointer, struct, and record fixes

_2026-08-10 06:00:00_

Drove libexpat to 100% compilation through a long batch of individually small `lower.rs` fixes, each fixture-locked:

- **`480a6b1d`**: `while`/`switch` interaction bug — a `continue` inside a `switch` nested in a `while` loop was being lowered as if it continued the switch's own (nonexistent) loop construct instead of the enclosing `while`. Fixed switch lowering to track the correct loop-continue target; `while_switch_continue.c`.
- **`dc593c1b`**: `c_ast.rs` wasn't following typedefs far enough to resolve function-pointer-typed return types — `typedef T (*fp)(...)`-shaped return types now resolve through the alias chain; `pointer_to_function_pointer_field.c`.
- **`3246a5f5`**: generated `impl From<Enum> for <repr>` instead of relying on an implicit enum→integer conversion, since Rust doesn't allow that implicitly the way C does; affects both `codegen.rs` and `directive_translate.rs` output.
- **`2b3e122a`**: struct-literal fields whose C initializer is `0`/absent for a pointer member now emit `None`/`null_mut()` correctly rather than a bare zero cast.
- **`6ccf34cf`** / **`b627af0b`** / **`c0d6aaef`**: three related function-pointer-through-void-pointer cases — casting a function pointer to `void*`, transmuting it back, and selecting between two function pointers in a `cir.select` (ternary) — all needed explicit `Type::FnPtr` handling since Rust's `*mut c_void` doesn't implicitly coerce from/to `fn` types the way C's `void*` does. Fixtures: `void_ptr_function_pointer_cast.c`, `ternary_function_pointer_select.c`.
- **`ca26742f`**: two structurally-identical-but-differently-named records emitted by different translation units are now reconciled to agree on a single shared shape before being promoted to a shared type, instead of racing on which name wins — `src/main.rs`, +cross_tu.rs coverage.
- **`a0a633b5`**: nested-aggregate depth counting was treating `->` (function return arrows appearing in mangled type strings) as a nesting-depth increment alongside `<`/`>`; switched to counting only `<`/`>` strictly. Fixed `nested_aggregate_const_record_field_alignment.c`.
- **`05fb9d33`**: deref of function-pointer callbacks stored in structs wasn't resolving correctly across translation units; fixed in both `lower.rs` and the cross-TU driver in `main.rs`.
- **`8811d95a`**: array literals with only some elements initialized (C's implicit-zero tail) now emit properly typed default values per element type instead of a blanket zero.
- **`a64d5755`**: multi-dimensional array handling in `c_ast.rs`, plus a fix to `inline_temps.rs` where the temp-inlining fixup was too aggressive and inlined expressions into `println!`-style macro call sites where a temp was actually load-bearing (needed to preserve evaluation order/side effects).
- **`1806edc5`**: pointer arithmetic against a "one past the end" pointer (valid in C, UB to dereference but valid to compute) now lowers without tripping bounds fixups meant for real out-of-bounds cases.
- **`a0b73e16`**: local (function-scoped) struct definitions that collide by name with another local or global record now get a `local_record_extras` set threaded through the `Lowerer` so both can coexist instead of one silently shadowing the other.
- **`f916a634`**: `-fvisibility=hidden` now affects generated `pub`/private visibility instead of being ignored, in both `lower.rs` and the cross-TU driver.
- **`b7a457d7`** / **`25fef099`**: final sweeps closing out the remaining libexpat-specific fixture failures (array-indexed struct fields typed against a named enum, among others) — `25fef099` is the commit where libexpat compiles clean end to end.
