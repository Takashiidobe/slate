# Resolve names and fold operands in MSVC __asm

_2026-09-27 18:57:59_

slate-parser-25m.6.2.

- names.rs: an MsAsmExpr::Name resolves in the ordinary namespace first,
  then as an asm label defined anywhere in the function (any __asm, case
  insensitive). Otherwise it is 'unresolved label name'. Asm labels stay
  apart from C labels, as in clang.
- reachability.rs: marks MS asm names, so header declarations used only
  from __asm survive pruning.
- sema/ms_asm.rs (new): folds each operand MASM style into one symbol +
  displacement + base/index(scale) + size/segment/OFFSET/SHORT, classified
  as register, immediate or MsAsmReference. Objects go through place();
  enumerators, TYPE/LENGTH/SIZE and field offsets become constants.
  module.rs runs it, then still returns the unsupported error until 25m.6.3
  (types carry #[expect(dead_code)] until then).
- parser: [eax]T.field parses as [eax] + T.field.
- Oracles: TYPE/LENGTH/SIZE count only the first array level (clang and
  MSVC agree). Where they disagree we follow clang; the MSVC-only forms
  went to slate-parser-25m.6.7.
- Fixtures: ms_asm_names_{msvc,clang}.c (every name kind plus a header
  that pruning would drop) and seven resolution-error fixtures.
- Wiki: msvc-asm.md (sema section), ast-grammar.md, ast-enum-touchpoints.md.
