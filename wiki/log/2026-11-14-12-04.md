# slate-f2zu.14.3 asm_template: x86_64 AT&T %a modifier on symbol/immediate operand (per-cpu %%gs:%a[var], get_current)

_2026-11-14 12:04:47_

- bead: slate-f2zu.14.3
- kind: feature
- area: crates/slate/src/frontend/lowerer/asm.rs
- target: x86_64

Outcome: x86_64 AT&T inline asm `%a` on a symbol or immediate operand now lowers
(symbol -> `{N}+off(%rip)`, immediate -> bare constant), unblocking the kernel
per-cpu read `%%gs:%a[var]`.

## Gap and why it mattered

`__raw_cpu_read_stable` (arch/x86/include/asm/percpu.h:182), reached by
`get_current` and `current_top_of_stack` in every TU that includes asm/current.h
(2437 kernel TUs), is:

    asm("movq %%gs:%a[var], %[val]" : [val] "=r"(v) : [var] "i"(&current_task));

The template lowering accepted only None/`c`/`P`/`p` on symbol and immediate
operands.

## Before

`statement asm: symbol modifier Some('a')` (and `immediate modifier Some('a')`
for `"i"(8)`).

## After

clang and gcc (-O2, also -mcmodel=kernel) print `%gs:current_task(%rip)`,
`arr+16(%rip)`, and `16` for an immediate. Slate now emits the same:

    "movq %gs:{1}(%rip), {0:r}", lateout(reg) __t0, sym word
    "movq {1}+16(%rip), {0:r}", lateout(reg) __t0, sym arr
    "leaq {1}, {0:r}", lateout(reg) __t0, const 8 as i32

`%a` on a register already lowered to `({N:r})`. The asm keeps
`options(pure, nomem)` because the C asm has no memory clobber; this is what
`this_cpu_read_stable` intends (repeated reads may merge).

## Implementation

`asm_template` (crates/slate/src/frontend/lowerer/asm.rs) gets `x86_64_att`. The
symbol branch allows `a` there and appends `(%rip)` after the offset; the
immediate branch prints `{N}` with no `$`.

## Fixture

crates/slate/tests/fixtures/x86_64/asm_address_modifier.c: `%%gs:%a` reads
(user-space gs base is 0, so it runs natively), `%a` with an offset, `leaq %a`,
an immediate and a register. Output is "41 4 / 3 2 / 8 1" under clang and gcc.

Kernel example TUs: kernel/sched/rq-offsets.c now has no barriers. init/main.c
went from 8 to 7 blocked; what remains is slate-f2zu.14.4 (initializers) and
slate-f2zu.14.5 (register variables).

Limits: i686 (absolute form, PIC-dependent), Intel dialect and arm `%a` remain
barriers.
