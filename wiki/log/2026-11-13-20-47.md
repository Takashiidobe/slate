# slate-f2zu.11.4 translate-project: migrate zlib/tinycc to manifests, delete --matrix and the matrix format

_2026-11-13 20:47:50_

- bead: slate-f2zu.11.4
- kind: feature
- area: crates/slate/src/project
- area: crates/slate/tests
- area: tools/corpus

Outcome: the hand-written translate-project matrix format, `--matrix` and `--matrix-target` are gone; zlib and tinycc are described by manifests built with `slate project` from their real compile_commands.json, and `--manifest-target` selects targets.

Gap and why it mattered: two input formats meant two readers and a hand-maintained flag list per target that drifted from the real build (zlib's matrix never defined -D_LARGEFILE64_SOURCE=1, which the CMake build does).

Before:
  slate translate-project --matrix tools/corpus/matrices/zlib.json --merge --matrix-target linux-x86_64 ~/c-corpus/zlib out
After:
  slate translate-project --manifest tools/corpus/manifests/zlib.json --merge --manifest-target linux-x86_64 ~/c-corpus/zlib out

Corpus manifests (paths relative to ~/c-corpus/<project>):
- tools/corpus/manifests/zlib.json: 16 targets (12 clang from build-clang, 4 msvc from build-msvc), build_target zlibstatic, the 9 features (pkzip-bug and inflate-allow-invalid via --name). Made only with `slate project` commands.
- tools/corpus/manifests/tinycc.json: linux-x86_64 gcc from build-gcc (the real ONE_SOURCE=0 multi-file build, 11 units). The old matrix's windows-x86_64 and darwin-aarch64 targets (one-source tcc.c with TCC_TARGET_PE / TCC_TARGET_ARM64) have no real build database, so they are dropped.
- zlib --merge, all 16 targets, before vs after: with targets/features/sources in the same order the remaining differences come from the CMake flags (_LARGEFILE64_SOURCE=1 adds off64_t and glibc LFS64 variants, e.g. adler32_combine_ gains a target_env = "gnu" variant). Accepted as the new baseline; not attributed further.

Implementation:
- matrix.rs: `MatrixFile`, `MatrixTarget`, `Matrix::read` and serde on `Feature` deleted; `Matrix::single_source(source, args, flavor, triples)` replaces the in-memory MatrixFile that api.rs used for single-file `translate --target a --target b`. User-facing errors say "manifest" ("unknown manifest target", "manifest features a, b cannot be combined", ...). Rust type names (Matrix, MatrixError) are unchanged.
- main.rs: only `--manifest`; `--manifest-target`; messages "--plan requires --manifest", "--manifest requires --manifest-target", "pass one --manifest".
- Ordering: manifests are BTreeMaps, so targets and features are processed alphabetically; merge reports and some cfg term orders changed. libc_spellings' `classify` now splices from the android/musl variant instead of the gnu one (projection all: 0 mismatches).

Tests:
- tests/support/manifest.rs `write_manifest(spec, sources, project, path)` turns a test spec (manifest shape, `targets` map with test-only per-target `args`) into per-target compile_commands.json files plus a manifest. fixtures.merge/targets.json, fixtures.plan/targets.json and fixtures.plan/wide.json are specs; matrix.json files deleted. plan and merge harnesses, target_outside_manifest_hits_guard, exhaustive_projection_is_bounded, target_properties_match_rustc and zlib_projection_sample use manifests.
- build_filecheck.rs and lowered_names.rs write manifests with write_manifest; fixtures.lowered-names/targets.json replaces matrix.json.
- differential.rs: matrix_* tests removed; their error cases moved into manifest_rejects_invalid_input; manifest-plain added to manifest_selection_and_merge_match_c_with_same_configuration.
- FileCheck regenerated: fixtures.merge {cover_refine, flush_streams, flush_value_writers, hoist_syscall, large_arrays, libc_spellings, libc_symbol_paths, macro_boundaries, named_types_support, stdio_bindings, target_properties, unseen_signature}, fixtures.plan {exclusive, usage_no_manifest (renamed from usage_no_matrix), usage_unknown_target, wide}.

Tools: tools/corpus/project_manifest.py loads a manifest plus its databases into per-target -D/-I/-U flags, sources and features; validate_merge.py and trace_attribution.py use it (args come from the first unit of each target).

Docs: README multi-target section, crates/slate/docs/src/translate-directives.md, wiki/concepts/cross-target-toolchains.md.

Limits: tinycc lost its windows and darwin targets. validate_merge.py was only import-checked; trace_attribution.py ran on linux-x86_64.
