# Dialect: one invocation config for pp and parser (iwsx step 1)

_2026-09-28 14:16:43_

Added src/dialect.rs: an immutable Dialect { flavor, standard, features, target, options } built once by the driver after argument parsing. Dialect::new applies options.effective_target and StandardFeatures::for_compiler exactly once, so holders of a Dialect only ever see the effective target and flavor-aware features.

Preprocessor::new(search, &Dialect) now returns Result and seeds builtin macros itself; the separate configure(target, options, flavor) call is gone, so an unconfigured preprocessor can no longer exist. Its standard/flavor/features/target fields collapsed into the dialect reference.

Parser::new(search, Dialect) replaces the with_target/with_flavor/with_options/with_standard builders and effective_options(). Before this, with_standard set flavor-blind StandardFeatures::new, so parser-side reads of implicit_int, identifier_list_definitions and auto_type_inference would never see a per-flavor value (needed by cxg.14 and cxg.16). Attribute registration and asm now read the effective target (only family/environment are consulted, so no behavior change).

Parser clones the Dialect when building a Preprocessor because prepare_preprocessor borrows the parser mutably, the same reason search is cloned.

Not done yet: TranslationUnit still stores standard/flavor/target/options separately, and sema still rebuilds StandardFeatures (validate, types, module, sema/mod), default_contraction and effective_target itself. Lexer keeps taking StandardFeatures via with_features since that is all it reads.

Validation: cargo nextest run --release --no-fail-fast, 7264 passed, no FileCheck changes.
