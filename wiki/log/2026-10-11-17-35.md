# ms_abi and sysv_abi calling conventions

_2026-10-11 17:35:41_

slate-parser-fmz4. sema dropped ms_abi/sysv_abi, so the function type and AbiSignature stayed on the target default.

slate-parser:

- CallConv gains Win64 (printed ms_abi) and SysV64 (sysv_abi).
- Mapping follows clang SemaDeclAttr: ms_abi is cdecl on Windows and Win64 elsewhere on x86_64/aarch64; sysv_abi is cdecl off Windows and SysV64 on x86_64 Windows. Ignored on other targets (i686-linux ms_abi, aarch64-windows sysv_abi).
- AbiClassifier picks the AbiConvention from the calling convention: win64, win_arm64 on AArch64 (so the Windows ARM64 variadic rules apply), sysv64.
- Unlike the x86 conventions they survive on variadic functions (CallConv::admits_variadic), matching clang's win64cc (i32, ...).
- Distinct-type checks reuse the existing machinery: redeclaration and pointer mismatches are diagnosed.

slate:

- rust::Abi gains Win64Unwind/SysV64Unwind. Definitions and function pointers use win64-unwind/sysv64-unwind; extern declarations go in separate unsafe extern "win64"/"sysv64" blocks.
- Rejected as barriers: variadic definitions (rustc allows C variadics only under C/C-unwind), long double (the f80 shims assume the C ABI), Win64 on AArch64 (no rustc ABI), and the x86 conventions (stdcall etc.), which were previously lowered silently as C.
- New library fixture ms_abi_calls: a native C driver calls ms_abi definitions in the translated staticlib and vice versa, including a callback, stack arguments, aggregates, and a native ms_abi variadic. With Win64 forced to C the translated binary crashes.

Fixtures: clang/linux/{x86_64,aarch64}/ms_abi_convention.c, clang/windows/x86_64/sysv_abi_convention.c, clang/linux/i686/ms_abi_ignored.c, error ms_abi_redeclaration/ms_abi_pointer_mismatch; 4 regenerated.
Filed slate-parser-3bbf (target("avx") ignored by SysV64 vector classification) and slate-parser-74a3 (conflicting conventions on one declaration not diagnosed).
