Outcome: translate-project manifests are written with `slate project target|feature ...` instead of by hand; target add infers triple, flavor and build target from the compile_commands.json, and feature add derives Cargo feature names from macro names (FASTEST -> fastest, NO_GZIP -> no-gzip).

Gap and why it mattered: slate-f2zu.11.1 added the --manifest reader, but manifests had to be hand-written, with the triple, flavor and CMake build target worked out by the user and feature names typed twice.

After:
  slate project target add <manifest> linux-x86_64 build/compile_commands.json [--project DIR] [--triple T] [--flavor F] [--sysroot S] [--build-target B] [--replace]
  slate project target remove <manifest> <name>...
  slate project feature add <manifest> FASTEST NO_GZIP [--project DIR]
  slate project feature add <manifest> --name level-two LEVEL=2 --define HAS_LEVEL
  slate project feature remove <manifest> fastest NO_GZIP
  slate project feature conflict <manifest> fastest no-gzip

Implementation (crates/slate/src/project/manifest.rs, new):
- `Manifest`/`ManifestTarget` moved here from matrix.rs, now Serialize; optional fields and empty features/invalid_features are omitted. Writes go to `<manifest>.tmp` then rename; BTreeMap keeps keys sorted. The first add creates the file.
- target add: flavor = --flavor, else the single flavor `compiler_flavor` gives every unit (error lists them when they differ). Triple = --triple, else the last --target per unit (compiler-name prefix or the command's own --target), canonicalized through target_registry (error when none or several). build_target = select_target's pick (only when one file has conflicting commands, as before); the report prints the pick and the other build targets. The finished target is validated by `read_manifest_target`, so foreign --target commands and feature macros already in the base commands are rejected before writing. compile_commands is stored relative to --project (default: cwd) when inside it.
- feature add: each define becomes its own feature unless --name groups them (positional and --define are the same list). Errors: invalid derived name (suggests --name), existing feature, two defines with the same derived name, a define given twice, a macro another feature already defines, and a macro any target's base commands -D/-U (names every such target).
- feature remove takes a name or a define and drops invalid_features groups that mention it. conflict takes names or defines, needs two distinct features, and is a no-op for an existing group.
- compile_commands.rs: `compiler_flavor` maps clang-cl to msvc; `read_units` also returns the `SelectedTarget`.
- main.rs: clap subcommands `project target add|remove`, `project feature add|remove|conflict`.

Fixture tests (crates/slate/tests/differential.rs):
- project_commands_build_the_fixture_manifest: builds tests/fixtures.matrix/generated/manifest.json from CLI commands and compares it to the checked-in file, then checks each error message, that errors leave the file unchanged, and --replace and remove.
- project_target_add_infers_triple_flavor_and_build_target: x86_64-linux-gnu-gcc infers triple and gcc, clang-cl infers msvc, shared/static/app outputs pick `static`, --build-target app, and the mixed-triple, mixed-flavor, foreign --target and unknown build target errors.

Limits: some shared errors still say "matrix" (e.g. `matrix feature "x" is not a valid Cargo feature name`); renamed in slate-f2zu.11.4.
