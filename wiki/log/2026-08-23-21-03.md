# slate-sfzn.7.3: Bionic type-layer ABI fixes + drop libc-crate dependency for mbstate_t

_2026-08-23 21:03:47_

Oracle-verified (NDK r27d sysroot) and fixed real Bionic ABI divergences the shim previously got wrong for all 64-bit Android targets: fpos_t is a plain off_t scalar (not glibc's 16-byte union) in stdio.h; __mbstate_t is {__seq:[u8;4], __reserved:[u8;4]} align-1 (not glibc's {int __count; union} align-4) in bits/types.h; wctype_t is signed long and wctrans_t is const void* (not glibc's unsigned long / const int*); locale.h/wchar.h/wctype.h gate the newlocale/uselocale/_l family and LC_PAPER..LC_IDENTIFICATION unconditionally for Bionic since real bionic headers don't feature-test-macro-gate them; langinfo.h's nl_item constants were glibc's packed encoding (CODESET=14) instead of bionic's plain 1..55 ordinals (CODESET=1) -- a real bug since these values cross the FFI boundary to the real libc.so. Along the way found the Rust libc crate (0.2.189) has no mbstate_t binding at all for Android, so lowering mbstate_t through CLIB_RECORD_TYPES to libc::mbstate_t doesn't even compile for android targets. Fix: removed mbstate_t from CLIB_RECORD_TYPES (src/backend/rust_ast.rs) entirely -- the existing generic record-lowering path already emits a correct #[repr(C)] struct from the shim's own (now oracle-accurate) definition, for every libc, so there was no need to special-case libc at all for this type. Verified via NDK-sysroot clang -fsyntax-only for both aarch64/x86_64-linux-android21, cargo check against real aarch64/x86_64-linux-android rustc targets, and updated 3 insta snapshots (c11, c23_library, uchar_conversions) that now show real struct literals instead of std::mem::zeroed::<libc::mbstate_t>(). New fixture tests/fixtures/bionic/stdio_locale_conversion.c exercises FILE/fpos_t/mbstate_t/locale_t/wctype_t/nl_langinfo together (translate-only -- tests/differential.rs is fully disabled repo-wide right now, pre-existing and unrelated). Also confirmed a pre-existing test-isolation flake: gcc_torture_suite and snapshot tests race on shared target/ scratch dirs when run together under the lowering nextest profile (reproduces identically on clean HEAD, nothing to do with this change).
