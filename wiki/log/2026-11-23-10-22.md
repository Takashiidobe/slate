# slate-yar4.61 PlaceKind::Swizzle: lower vector place reads and writes

_2026-11-23 10:22:23_

- bead: slate-yar4.61
- kind: bug
- area: crates/slate/src/frontend/lowerer/vectors.rs

Outcome: Slate lowers plain swizzle place reads and writes for aligned and packed vectors, including nested swizzles and dynamic lane selection.

## Symptom and reproducer

```c
typedef int v4 __attribute__((ext_vector_type(4)));
typedef int v2 __attribute__((ext_vector_type(2)));
v2 flip(v4 *p) {
  p->yx = p->xy;
  return p->xy;
}
```

Before: `translate` failed with “cannot lower place to Rust”.
After: the returned pair contains the swapped lanes and the other lanes retain their values.

## Cause and fix

The parser emitted `PlaceKind::Swizzle`, but the Rust read and assignment paths fell into `lower_place`, which expects a single addressable location.

`swizzle_access` composes nested lane maps and obtains the raw pointer to the base vector. Reads construct a vector from the selected scalar loads. Writes capture the RHS and base once, then store only the selected lanes without loading neighboring lanes. The scalar operations use unaligned access for both packed and aligned bases.

## Regression fixture

`crates/slate/tests/fixtures/vector_swizzle_place.c` compares Clang and translated Rust for overlapping swaps, three-lane compound assignment, packed partial initialization and reads, nested projections, and single evaluation of effectful operands.

Limits: volatile swizzles require whole-vector access granularity. See slate-yar4.64.
