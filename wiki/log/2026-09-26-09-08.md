# Builtins look like functions; NoReturn becomes fn noreturn

_2026-09-26 09:08:49_

Closes slate-parser-dyd.20. Builtin calls no longer use a separate Callee::Builtin(name); the variant is removed. Like clang's LazilyCreateBuiltin, an undeclared function-like builtin gets one implicit fn per spelling (unnamed params, registry prototype, linkage=external, c_builtin metadata), and calls are Callee::Direct to it. A source declaration that keeps builtin status (external, compatible type) is the callee instead, and finish_functions gives it c_builtin plus [noreturn] when the builtin is NoReturn, matching clang's noreturn on e.g. a plain `void abort(void);`.

Decision: only NoReturn reaches the IR. Const/Pure/NoThrow only license optimizations and are not C-observable, so they are not lowered (rule from the dyd rescoping: lower a rule only when it decides acceptance or changes lowering). An earlier draft marked noreturn on the call's builtin callee; rejected because noreturn is a function property and direct callees already carry it on fn.

Gotcha: implicit declarations created while lowering an unevaluated operand (sizeof, _Generic) must be discarded with the rewound ids; unevaluated/unevaluated_type now share discard_after, which also truncates module.functions and prunes builtin_declarations. This also covers the libatomic __atomic_is_lock_free declaration, which previously could leak with a reused id.

Fixture churn (~1880 files) was verified mechanically: after normalizing %N/.strN and callee spellings the only diffs are callee rewrites, new/noreturn fn declarations, and c_builtin moving from call to fn in ir_implicit_builtins.c. New fixture: tests/fixtures/sema/ir_builtin_noreturn.c. Full suite 3019/3019.
