# Fold const-object array bounds at static and file scope (clang)

_2026-10-16 17:18:40_

Closed slate-parser-6x05.44. clang accepts 'const int n = 3; int a[n];' at file scope and 'static int b[n];' in a function (-Wgnu-folding-constant), also a block-scope 'const int m' used by a static array; slate rejected them as static-storage VLAs. Oracle check: gcc 16 rejects both file scope ('variably modified at file scope') and block-scope static, so the bead's 'gcc accepts file scope' was stale and only the clang flavor folds; automatic 'int d[m]' stays a VLA in clang and in slate. The checker runs before lowering and entities only record const initializers during lowering, so the checker now records them itself: TypeResolver::declare_folded_object stores a const, non-volatile integer object whose initializer is an ICE, wrapped to the object's type (const unsigned char n = 300 gives 44 as clang). TypeResolver::constant reads that map only while fold_object_bounds is set; assertion.rs sets it around declarator_type and module.rs around capture_extents and the unbound-extent re-resolve for file-scope, static and extern declarators (folds_object_bounds).
