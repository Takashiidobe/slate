# UTF-8 and UCN identifiers, gnu99 u/U/u8 literals

_2026-10-11 16:18:32_

slate-parser-cxg.23. gcc enables u/U/u8 string and char prefixes in gnu99 (libcpp uliterals), clang only from c11: unicode_literal_prefixes is Extension for gcc gnu99. The lexer now takes non-ASCII UTF-8 in identifiers and pp-numbers (identifier_utf8: all modes except gcc before c99, never a raw invalid byte) and complete UCNs from c99 (identifier_ucns: \u+4 hex, \U+8, \u{...}, \N{...}). UCNs other than \N are decoded into the Ident, so \u00C1, \u00c1 and Á are one name for macros, #ifndef, and the IR; an incomplete UCN (\U0000000z) or any UCN in c89 stays a separate \ token, which ucnid-6/ucnid-7 rely on. Existing fixtures c99.c, c23_language.c, pp_stringify_backslash.c (both flavors), cpp__ucnid-3.c (both flavors) now print the decoded name. Migrated 32 gcc.dg files to suites/gcc-dg/gcc (ucnid-11-utf8 and ucnid-12-utf8 need other files). Split off cxg.58 (\N{NAME} needs a name table; named-universal-char-escape-1/-2 decode wrong) and cxg.59 (utf-inc-init.c designator into an initialized member). Parser profile 8177/8177.
