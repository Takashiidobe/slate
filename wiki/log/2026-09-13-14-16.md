# Hand-maintained x86 register table (slate-parser-25m.2)

_2026-09-13 14:16:59_

Added the x86-64 register table for structured inline asm, clang flavor only.

- AST: Register { X86(X86Register), Other(String) }; X86Register { spelling as written, number (GCC hard-register number), canonical GCC name, width: Option<X86RegisterWidth> }; X86RegisterWidth { Low8, High8, Bits16, Bits32, Bits64 }.
- src/target/x86.rs: GCC_REGISTER_NAMES and ADDITIONAL_REGISTER_NAMES, a hand-maintained mirror of GCCRegNames / AddlRegNames in ~/llvm-project clang/lib/Basic/Targets/X86.cpp (x86 has no GCCRegAliases). decode_register mirrors TargetInfo::isValidGCCRegisterName: strip one leading % or #, leading digit parses with LLVM getAsInteger(0) auto radix (0x, 0b, 0o, leading 0 octal) as an index, then canonical names, then additional names; unknown -> Register::Other.
- Width is the one thing clang discards (al/ah/eax/rax all normalize to 'ax'); we keep it per spelling. Numeric spellings have no width; canonical ax..sp are 16-bit, r8..r15 and r16..r31 are 64-bit; st/xmm/ymm/zmm/k/cr/dr/bnd/tmm have none.

Decision: hand-maintain instead of generating from TableGen. clang's accepted names are hand-written C++ arrays, not TableGen; X86RegisterInfo.td has a different register set (HAX, EIP, no argp/frame), so it cannot be the source of truth.
Verification: no consumer yet (arrives in slate-parser-25m.3/.4), so a one-off script diffed the Rust arrays against X86.cpp at llvm 58dd40228595: 181 canonical names identical in order, 96 additional (name, index) pairs identical, widths consistent with spelling. clippy clean; nextest fails only the 2 pre-existing fixtures.
