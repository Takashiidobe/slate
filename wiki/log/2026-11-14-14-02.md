# slate-f2zu.14.13 ConstantBuiltin: \_\_builtin_abs/expect/strlen/strcmp/memcmp/fabs/copysign/fmax/fmin fold to const in static initializers and \_Static_assert

_2026-11-14 14:02:16_

- bead: slate-f2zu.14.13
- kind: parser
- area: crates/slate-parser/src/sema/types.rs
- area: crates/slate-parser/src/sema/builtins.rs
- area: crates/slate-parser/src/sema/fold.rs

Outcome: in static and thread-storage initializers, and in asm immediates, these
builtins now fold to `const` when their arguments are constant:
`__builtin_abs/labs/llabs`, `__builtin_expect(_with_probability)`,
`__builtin_strlen/strcmp/memcmp` on string literals, and
`__builtin_fabs/copysign/fmax/fmin` (plain, `f` and `l` forms). `_Static_assert`
evaluates them as well, where before it skipped them silently.

Diagnostic or IR fact that was wrong:

- These calls stayed `call<..>` in static initializers, and slate rejects a call
  there with `global v: non-constant initializer call<...>`. Both gcc and clang
  accept the code.
- `_Static_assert(__builtin_abs(-3) == 4, "")` passed in slate, because
  `call_shape` marked foldable builtins `Skip`. clang reports
  `static assertion failed`.

Before (`static int v = __builtin_abs(-3);`):

```
global %1 v: i32 [storage=static] = call<i32, signature=fn(i32) -> i32>(%22, neg<i32, overflow=ub>(const<i32>(3)))
```

After:

```
global %1 v: i32 [storage=static] = const<i32>(3) [linkage=internal]
```

Fix:

- `ConstantBuiltin::of_call` (sema/builtins.rs) recognizes the prefixed names
  and checks their arity.
- `TypeResolver::constant_builtin` (sema/types.rs) evaluates them:
  - String builtins read `execution_units` of Plain/UTF-8 literals and return
    -1/0/1. `memcmp` stops at the first difference and rejects a read past the
    end before any difference, which matches clang.
  - `abs` rejects the most negative value.
  - Float builtins go through `fold::float_builtin`, which uses rustc_apfloat
    `abs`, `copy_sign`, `max` and `min` (IEEE maxNum/minNum).
- `lower_expr`'s static-initializer fold (sema/expression.rs) and `call_shape`
  (sema/assertion.rs) accept `ConstantBuiltin` alongside `BitBuiltin`.
- Spec: wiki/concepts/ir/builtins.md.

Fixtures:

- crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/builtin_constant_fold_static_init.c
  (an automatic local and a runtime argument keep the call)
- crates/slate/tests/fixtures/static_init_constant_builtins.c

Limits:

- Unprefixed `abs`/`fabs`/`strlen` stay calls. The flavors disagree: clang folds
  `strlen("ab")` but not `abs(-3)`, while gcc folds both.
- gcc-only folds are still missing: `__builtin_sqrt(4.0)`, and
  `__builtin_add_overflow_p`, which is unsupported everywhere.
- `memchr`, and literals reached through casts, are not folded.
- gcc's `clz(0) = 32` was already folded before this change.
