# Bridge calls through variadic long double function pointers

_2026-11-07 08:32:11_

slate-yar4.22: an indirect call through a variadic function pointer passed long
double variadic arguments as Rust LongDouble (INTEGER class), so printf through
int (_)(const char _, ...) printed garbage; a variadic pointer whose signature
holds f80 was a barrier. Now the call becomes
**slate_icall**r<ret>\_<fixed>**<variadic tags> (lowerer/f80.rs
lower_long_double_indirect_call, Tables::is_variadic_function_pointer, predicate
in values.rs) when the signature or any argument holds f80.
c_shim::render_indirect_trampoline splits at the second **, casts to <ret>
(_)(<fixed>, ...), and loads every f80 argument. Variadic args are always
native, which Rust-defined variadic callees expect (their va_arg reads x87).
Taking the address of a Rust-defined variadic function whose signature holds f80
stays a barrier. Fixtures: x86_64/long_double_variadic_function_pointer.c
(printf and a Rust-defined variadic through pointers),
fixtures.dylink/long_double_abi ld_vsum (native long double (_)(long double,
int, ...)), FileCheck regenerated. Full slate profile green.
