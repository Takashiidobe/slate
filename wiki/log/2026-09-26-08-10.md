# gate attribute spellings per flavor and target

_2026-09-26 08:10:05_

slate-parser-dyd.46. Every modeled attribute was accepted under every flavor and target, so
`dllimport` set a dll_storage marker on ELF, clang-only spellings (`overloadable`,
`annotate`) applied under gcc, and unknown spellings were silently dropped.

Added `src/attribute_support.rs`, the one hand-maintained table of which
`__attribute__` names clang, gcc and msvc register, each as a target gate
(`Always`, `Never`, `Windows`, `X86`, `NotAArch64`, ...), plus which
`[[scope::]]` namespaces each flavor accepts. It replaces the parser's
`is_attribute_name` list. The parser turns an unregistered GNU or scoped C23
spelling into `Attribute::Unknown`; sema reports it as the new
`Warning::UnknownAttributes` ("unknown attribute 'X' ignored").

Measured with clang 22.1.8 on 13 triples, gcc 16.2.1 on x86_64/aarch64 and
cl 19.51 (`tools/cl.exe`); table summary in
wiki/concepts/diagnostic-severity.md. cl has no `__attribute__` syntax, so the
msvc column is all `Never`.

`__declspec` is not gated: clang reports unsupported declspecs under
-Wignored-attributes and cl errors (C2485). Filed slate-parser-dyd.65.

Fixtures: `sema/unknown_attributes_{clang_linux,clang_windows,gcc_aarch64}.c`,
each matching its oracle's warning set. `ir_threaded_type_attributes.c` now
shows `scalar_storage_order` as Unknown under clang;
`ir_parameter_attribute_diagnostics.c` ERR_UNSUPPORTED moved to the
`__declspec(code_seg)` spelling, since clang does not register
`__attribute__((code_seg))`. Noted in AGENTS.md where the oracle compilers live.
