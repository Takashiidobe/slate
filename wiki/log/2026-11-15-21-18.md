# slate-f2zu.14.34.33 asm memory operand: "m" on a global lowered in(reg) so pv_ops calls were call \*(%rcx), now sym+N(%rip)

_2026-11-15 21:18:49_

- bead: slate-f2zu.14.34.33
- kind: bug
- area: crates/slate/src/frontend/lowerer/asm.rs
- area: crates/slate-parser/src/sema/asm.rs
- area: crates/slate-parser/src/ir/asm.rs
- target: x86_64

Outcome: on x86_64, an asm "m" operand on a global at a constant offset lowers
to a `sym` operand printed `{N}+off(%rip)`, as clang emits, so kernel pv_ops
calls are `call *pv_ops+N(%rip)` with the relocation on the call instruction.

Symptom: objtool on the relinked vmlinux.o reported "call to {dynamic}() leaves
.noinstr.text section" in default_idle and acpi_safe_halt (PVOP_ALT_VCALL with
"m"(pv_ops.irq.safe_halt)).

Reproducer
(crates/slate/tests/fixtures/x86_64/asm_memory_operand_global_symbol.c, -fPIE):
struct ops { long pad; long val; long arr[4]; } ops; **asm** volatile("movq %1,
%0" : "=r"(v) : "m"(ops.val));

Cause: lower_asm passed every memory operand as `in(reg) addr_of!(place)` and
memory_reference printed `({N:r})`. The machine code was
`mov $pv_ops,%rcx; call *(%rcx)`. objtool recognises pv_ops calls, and checks
their noinstr targets, only through the relocation on the call instruction. The
IR had no (binding, offset) fact for a memory operand's place; sema's
symbol_place computed one only for "i"/"s" symbol operands.

Fix:

- slate-parser: ir::AsmOperand gains `address: Option<AsmSymbol>`. sema/asm.rs
  memory_address sets it for a memory-selected InPlace, Out or InOut (no tied
  input) place whose symbol_place root has static storage, both at first
  selection and in reselect. Printed as `at<offset=N>(%b)`.
- slate: the Memory branch of lower_asm emits `Slot::MemorySymbol` plus
  `sym <static>` when asm_memory_symbol allows it. Conditions: x86_64; a plain
  static (not indirect, weak-address, flexible, register or libc-support); not
  weak; and non-preemptible, meaning internal linkage, hidden or protected
  visibility, or machine.pic level 0 or executable. A function-local static has
  no global entry and is allowed. The template prints `{N}+off(%rip)`, or
  `<size> ptr [rip + {N}+off]` for Intel; `%H` adds 8.

After (fixture): core::arch::asm!("movq {1}+8(%rip), {0:r}", lateout(reg)
\_\_t0, sym ops, ...); core::arch::asm!("addq $1, {0}+8(%rip)", sym local_ops,
...); A pointer deref ("m"(\*p)) keeps the `({N:r})` form.

Verification: arch_x86_kernel and drivers_acpi shards retranslated and built.

- Every pv_ops call site is now `call *0x0(%rip)` with R_X86_64_PC32 pv_ops+N:
  default_idle, acpi_safe_halt, acpi_idle_play_dead, and 3 reboot/crash paths.
- default_idle's relocation (pv_ops-0x4) is identical to clang's native
  process.o built with -fno-PIE.
- Before: `mov $0x0,%rcx` (R_X86_64_32S pv_ops); call \*(%rcx).
- Per-object objtool does not run the noinstr check on either build, so the
  warning itself clears only at the vmlinux.o relink.
- Parser profile: 7 IR FileCheck blocks regenerated to show the new `at<>` fact.
  Slate profile passes.

Limits: i686 keeps the register form; under -fPIC clang uses GOTOFF there.
Confirmed only at the next relink.

See: slate-f2zu.14.34.33, slate-f2zu.14.34.28, wiki/concepts/ir/asm.md (Memory
operands, Slate lowering).
