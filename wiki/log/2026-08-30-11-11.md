# fix pointer-to-array local init decaying to element pointer

_2026-08-30 11:11:11_

slate-n4e4: `arr_t *p = &src;` (src an array-typed local) generated
`p = src.as_mut_ptr()` (`*mut i32`) but `p` is `*mut [i32;5]`, so the crate
failed E0308. CIR stores the array alloca `%1` (`!cir.ptr<!cir.array>`)
directly into `p` with no array_to_ptrdecay cast, so it's a whole-array
pointer, not a decayed element pointer.

Fix: extracted the existing `points_to_whole_aggregate` logic from
`call_arg_expr` into `whole_aggregate_pointer_expr(operand, ty)` in
values.rs, which yields `addr_of_mut!(*slot)` when an array slot is stored
into a pointer-to-array/vector. Used it in both `call_arg_expr` and
`lower_store` (storage.rs). Fixture: tests/fixtures/ptr_to_array_local.c.
Closes the features.md audit epic (slate-4srf) bar the blocked CIR NYI
slate-b4jj.

Fixture carries both `@lowering` + `@rewrite` FileCheck regions asserting
`p = std::ptr::addr_of_mut!(*src);`. Made the both-regions rule explicit in
CLAUDE.md conventions and differential-fixtures.md (was previously phrased as
a soft "prefer"), and noted that a fixture can/should carry multiple disjoint
region pairs for each interesting statement, and that markers can't wrap a
function signature (asm sentinels only work in a body).
