# Bridge f80 aggregates by value with size tags

_2026-11-07 08:16:50_

slate-p58o.4.12: on x86_64 SysV, a direct, indirect or variadic bridge call passing or returning a struct holding long double by value was a 'call to X passing T' barrier, a regression from the CIR removal (slate-7wcq.9 reprinted record defs from the Program). Tables::long_double_aggregate_tag (lowerer/f80.rs) now tags such aggregates by class: size > 16 with align 16 is MEMORY in both C and Rust -> m<size>, and c_shim declares struct __slate_m<size> { long double v[size/16]; } and passes it unchanged; a 16-byte single-long-double aggregate is X87 in C but INTEGER in Rust -> s80, rendered exactly like f80 (split_tags) but a distinct name so it never collides with the scalar bridge. f80 function pointer arguments tag fp (void *), since they already point at native-ABI code. Other aggregates stay barriers; variadic f80 function pointers remain a barrier. Promoted c-testsuite case_00204. Fixture: fixtures.dylink/long_double_abi.
