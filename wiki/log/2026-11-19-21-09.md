# slate-yar4.58 padding mark_data: x87 long double tail and _BitInt padding bits were kept as data under __builtin_clear_padding

_2026-11-19 21:09:15_

- bead: slate-yar4.58
- kind: bug
- area: crates/slate/src/frontend/lowerer/padding.rs
- area: crates/slate-parser/src/sema/abi.rs
- flavor: gcc
- target: x86_64

Outcome: `__builtin_clear_padding` and `-fzero-init-padding-bits` now zero the 6 tail bytes of an x87 long double and the padding bits of a `_BitInt(N)`, matching gcc; slate-yar4.57 is closed as not a bug.

Reproducer (gcc, x86_64):

```c
struct x87 { long double x; };
struct bitint { _BitInt(17) b; char c; };
struct x87 a;  memset(&a, 0xAB, sizeof a);  memcpy(&a, &v, 10);  __builtin_clear_padding(&a);
struct bitint b; memset(&b, 0xEF, sizeof b); ((unsigned char *)&b)[0] = 5; __builtin_clear_padding(&b);
```

Before: `x87: ... ab ab ab ab ab ab`, `bitint: 05 ef ef ef 06 ...` (padding kept).
After: `x87: ... 00 00 00 00 00 00`, `bitint: 05 ef 01 00 06 ...` (bits 17+ cleared, bit 16 kept), same as gcc.

Cause: `Tables::mark_data` (frontend/lowerer/padding.rs) fell into a catch-all that marked
every byte of `storage_of(ty)` as data. A typed `LongDouble` store rewrites the tail with
zeros, so only writes that touch the 10 data bytes (memcpy, byte stores) exposed it.

Fix: explicit arms for `F80` and `Imaginary(F80)` (80 data bits), `Complex(F80)` (two 80-bit
parts at the F80 stride), and bit-precise integers (low `width` bits). `mark_bits` sets
per-bit keep masks, which `clear_padding_at` already turns into masked `&=` stores.

Regression test: tests/fixtures/gcc/x86_64/clear_padding_x87_bitint.c (x87, x87 mixed with
char/short neighbours, `_BitInt(17)`, `_Complex long double`).

slate-yar4.57 (AAPCS HFA ignoring `_Complex` members): not a bug. Both the C and Rust views
omit it and fall back to native_c, which rustc's repr(C) `Complex<f64>` already matches. A
dylink linux-aarch64 fixture with C-defined and Rust-defined callers of struct{_Complex}
passed without a fix, so it was dropped. The `#[expect]` reason in sema/abi.rs
`homogeneous_type` now says this. wiki/concepts/differential-fixtures.md also lost its stale
`slate-` nextest profile prefixes.

Also covered on i686 (12-byte long double, 2 tail bytes) by gcc/i686/clear_padding_x87_bitint.c;
with padding.rs reverted it failed with the same kept garbage, so no i686-specific code was needed.

Limits: x86_64 and i686 only (aarch64 long double is IEEE quad, no x87 padding).

See: slate-yar4.58, slate-yar4.57, slate-5q63.25.2.
