# slate-j3by.27 shift64_op: lower MSVC __ll_lshift, __ll_rshift, and __ull_rshift with target count masks

_2026-11-25 18:59:25_

- bead: slate-j3by.27
- kind: bug
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/tests/fixtures/msvc
- flavor: msvc

Outcome: Slate emits native Rust operations for the three MSVC 64-bit shift intrinsics on x64 and x86.

Symptom: The original fixture reached lld-link with undefined shift symbols.
The current baseline diagnoses `__ll_lshift: builtin without a lowering`
after the MSVC catalog began marking all three declarations as builtins.

Reproducer:

```c
#include <intrin.h>
#pragma intrinsic(__ll_lshift, __ll_rshift, __ull_rshift)
static int check(int n) {
  return __ll_lshift(1, n) != 2 || __ll_rshift(-16, n) != -8 ||
         __ull_rshift(0x8000000000000000ULL, n) != 0x4000000000000000ULL;
}
int main(void) { return check(65); }
```

Cause: The parser supplied the correct signed and unsigned operand types.
`lower_value_node` had no matching builtin branch, so the generic
`lower_call` guard rejected the calls.

Fix: `shift64_op` selects the Rust shift and registers each intrinsic with
`open_coded_builtin`. The direct-call arm masks the count with 63 on x64
or 31 on x86, which matches cl.exe for counts 32, 64, 65, and -1.
The `i64` operand in `__ll_rshift` sign-extends, while the `u64` operand
in `__ull_rshift` zero-fills. The reproducer now translates and exits 0.

Regression test: `crates/slate/tests/fixtures/msvc/msvc_64bit_shift_intrinsics.c`
compares the C and Rust executables on x64 and x86. It checks wrapping and
negative counts, both right-shift fill modes, and left-shift truncation.
