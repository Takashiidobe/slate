# slate-f2zu.14.11 Lowerer::in_constant_initializer: bit builtins (\_\_builtin_bswap32, ffsll, ctz) with constant arguments fold to const in static initializers

_2026-11-14 13:14:22_

- bead: slate-f2zu.14.11
- kind: parser
- area: crates/slate-parser/src/sema/expression.rs
- area: crates/slate-parser/src/sema/module.rs
- corpus: linux

Outcome: inside the initializer of a static or thread-storage object, a bit
builtin (`__builtin_bswap32`, `ffsll`, `ctz`, `clz`, `popcount`, ...) called
with constant arguments lowers to `const<T>(N)` in the IR; the call is kept
everywhere else. Kernel static-initializer rows in the targeted 30 TUs drop from
97 to 17.

Diagnostic or IR fact that was wrong: gcc and clang constant-evaluate these
builtins in static initializers (`htonl(INADDR_NONE)` via `__cpu_to_be32` ->
`__builtin_bswap32`, `REG_FIELD_PREP` -> `__bf_shf` -> `__builtin_ffsll`), and
the parser's ICE evaluator already folded them
(`_Static_assert(__builtin_bswap32(1u) == 0x01000000u)` passed), but the IR kept
a `call`, which slate's `is_constant_initializer` rejects, and Rust cannot run
`llvm.bswap` in a `static`.

Before (`static unsigned be = __builtin_bswap32(0x01020304u);`):

```
global %1 be: u32 [storage=static] = call<u32, signature=fn(u32) -> u32>(%10, const<u32>(16909060))
```

After:

```
global %1 be: u32 [storage=static] = const<u32>(67305985)
```

Fix:

- `Lowerer::in_constant_initializer` (sema/expression.rs), set in sema/module.rs
  around `initializer_value` when the object's storage is not automatic (the
  same switch that already resets floating semantics and x87 excess), and
  restored after.
- `Lowerer::lower_expr`: before `function_like_builtin`, a `BitBuiltin::of_call`
  call whose `TypeResolver::constant_value` succeeds becomes a `Constant`
  annotated `c_builtin = <name>`, like `__builtin_constant_p`. Folded builtins
  are no longer declared when nothing else calls them.
- A rejected result (`__builtin_clz(0)`) stays a call and still blocks, as
  before.
- Design: the parser folds, not slate, so the `_Static_assert` and initializer
  paths share one evaluator and flavor rules. An earlier lowerer-side fold was
  reverted.
- Spec: wiki/concepts/ir/builtins.md (bit operations).

Fixtures:

- crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/builtin_bit_fold_static_init.c
  (globals, nested compound literal, block-scope static fold; automatic local

- crates/slate/tests/fixtures/static_init_bit_builtins.c (cpu_to_be32/16,

Limits: block-scope C23 `static` compound literals outside a static initializer
are not covered. gcc's `clz(0) = 32` fold and the rest of clang's Constexpr list
are slate-f2zu.14.13. The 17 rows left (constant conditionals with a
non-constant unselected arm, other builtin calls in hcd.c, `&weak_extern.field`
in efi.c) are slate-f2zu.14.12.

See: slate-mxxa (`__builtin_nan` fold precedent), slate-f2zu.14.4.
