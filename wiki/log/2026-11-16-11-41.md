# slate-f2zu.14.40.4 translate-project global_asm!: initcalls and linker-set entries from different units emitted in CGU order, not link order (genl_init before netlink_proto_init)

_2026-11-16 11:41:18_

- bead: slate-f2zu.14.40.4
- kind: bug
- area: crates/slate/src/project/link_order.rs
- area: crates/slate/src/main.rs
- area: crates/slate/src/compile_commands.rs
- area: tools/corpus/e2e.py
- corpus: linux

Outcome: translate-project keeps compile_commands order as link order and emits every unit's file-scope assembly as one crate-root `global_asm!` in that order, so section entries from different units (kernel initcalls, linker sets) no longer come out in rustc codegen-unit order.

Symptom: translated kernel boot hit BUG_ON(!nl_table) in netlink (af_netlink.c:2035) from genl_init -> genl_pernet_init. netlink_proto_init and genl_init are both core_initcalls in the net__packed shard; native .initcall1.init has af_netlink's entry first, the translated one had genetlink's first.

Reproducer (crates/slate/tests/fixtures.release/link_order_asm): 9 units, each with
```c
__attribute__((used)) static int registered_u1(void) { return 1; }
__asm__(".pushsection slate_order_set,\"aR\"\n.balign 4\n.long registered_u1 - .\n.popsection");
```
plus enough code that rustc gives each module its own CGU; main walks __start_/__stop_slate_order_set. C prints `0 1 2 3 4 40 5 6 7 8`, Rust printed `0 6 7 8 2 5 1 4 3`.

Cause (verified):
- `global_asm!` and `#[link_section]` statics go into the CGU of their module; rustc orders CGU objects arbitrarily (40-module test crate at 16 CGUs: both shuffled; one CGU: source order).
- `parse_slate_units` (main.rs) keyed units by stem in a BTreeMap and `compile_commands::read_entries` sorted by path, so lib.rs listed modules alphabetically regardless of the database.

Fix:
- `read_entries` restores first-occurrence order after its path-sorted dedup; `parse_slate_units` keeps that order.
- `project::link_order::hoist_global_asm` (called from `write_project_crate`): when two or more ungated units carry a `GlobalAsm` whose `sym` operands all name a Fn/Static defined in the unit, those items move into the crate root, concatenated per run of equal options with placeholders renumbered, `sym crate::__slate_unit_<stem>::<name>`. Named items and the unit's Record/Struct/Enum defs become `pub` (rustc's type-privacy check at the sym path needs every ADT in the signature visible). Extern-symbol asm (`.weak` weak-address alias, slate-f2zu.14.12) stays beside its strong reference.
- tools/corpus/e2e.py `shard_units` sorts each shard's units by vmlinux.a member position.

Kernel check: net__packed retranslated in link order builds; `.initcall1.init` is sock_init, netlink_proto_init, genl_init (native order). Not relinked or booted: cross-shard order is still wrong (slate-f2zu.14.40.5).

Limits: `#[link_section]` statics (.init_array constructors, `__attribute__((section))` data) are still per CGU: slate-f2zu.14.40.6. rust-lld start-stop-gc drops __start_-only sections: slate-f2zu.14.40.7 (fixture uses "aR").
