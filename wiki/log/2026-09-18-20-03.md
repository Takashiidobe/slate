# VLA parameters and [*]

_2026-09-18 20:03:45_

slate-parser-lh7.2.11. Type::VariableArray's extent is now VariableExtent::{Captured(BindingId), Unspecified}; Unspecified prints vla<T, *>. TypeResolver::resolve_parameter sets a prototype_scope flag under which [*] and any non-constant, uncaptured bound derive Unspecified instead of failing constant evaluation; derive()'s Function arm, resolve_parameters (type view) and Lowerer::parameters all go through it, and all three now adjust VariableArray parameters to pointers like fixed arrays. Function definitions pass a prologue to Lowerer::parameters, which runs capture_extents per parameter (outermost bound included, per C11 6.9.1p10 entry evaluation) before resolving its type; the prologue is prepended to the body. names.rs now walks definition parameter declarators so bounds like a[n] resolve to earlier parameters. Pointer offset/difference use TypeResolver::require_complete (recurses through VLA elements) instead of storage(), so ptr_offset<..., element=vla<i32, %m>> expresses the runtime stride. types::compatible treats VLA vs VLA/array as compatible by element (C11 6.7.6.2p6), used by pointer conversion and pointer subtraction. Fixture sema/variable_length_array_parameters.c; ir-spec (incl. the sizeof-of-VLA exception to required constant evaluation) and ir-grammar updated. Follow-ups: lh7.2.24 (sizeof(int[n]), casts), lh7.2.25 (VLA typedef, {} initializer).
