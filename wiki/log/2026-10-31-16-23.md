# Count temp uses from the arena read index in inline_temps

_2026-10-31 16:23:09_

slate-5q63.10: the inline_temps rules rescanned the whole function per temp through node_ident_count, then scanned each following sibling in locate_consumer.
Added Arena::read_count, which sums the existing per-node reads over def_use_neighbors (deduplicated, since touch can list a node twice when it reads a name twice). locate_sole_consumer now walks up from the only reader instead of scanning siblings, and is only called after read_count is 1. Removed node_ident_count and kind_own_ident_count.
The index and the old scan differ on paper in three rare cases inside nested expression blocks: closure params shadowing the name, For patterns shadowing it, and match guards, which only the index counts. A temporary check compared count and consumer against the old code on 93866 calls across the slate, clang, gcc and msvc profiles plus zlib: 0 mismatches.
zlib, 16 targets, 4 interleaved hyperfine rounds: 1145 to 1045 G instructions (-8.8%), 223 to 206 s CPU, 39.6 to 36.5 s wall on a noisier machine than earlier logs. Memory unchanged at 2.35 GiB. apply_local fell from 20% to 14.8% of samples and e_ident_count left the profile.
Validation: zlib output byte-identical at 1 and 16 targets. slate 33/33 on the final code. clang 4809/4809, gcc 3678/3678, msvc 474/474 ran with the temporary check in place.
