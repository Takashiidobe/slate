# slate-8ge7.24.17.4 unsafe_placement: unsafe blocks placed from operation markers, fewer and larger blocks

_2026-11-22 13:12:16_

- bead: slate-8ge7.24.17.4
- kind: rewrite
- area: crates/slate/src/backend/engine
- area: crates/slate/src/frontend/lowerer

Outcome: unsafe blocks are placed from the .3 operation markers by a final engine pass (engine/unsafe_placement.rs) instead of being kept from the lowerer's wrappers; output has fewer, larger unsafe blocks and every fixture still compiles.

Before (lowerer wrappers kept as emitted):
    let a = unsafe { *p.offset(1) } + unsafe { G };
    unsafe { f(x) };
    unsafe { g(y) };
After:
    let a = unsafe { *p.offset(1) + G };
    unsafe {
        f(x);
        g(y);
    }

Rule: unsafe_placement::place runs at the end of engine::apply_local, after finish_place_arguments. It strips every Expr::Unsafe/Stmt::Unsafe and re-places from needs_unsafe:
- Contexts Value/Place/RawPlace/Write follow rustc: addr_of!/&raw of a static mut and of a direct union field are safe; union writes through Field/TupleField are safe, through Index are not.
- An expression is pending when its op needs unsafe, when two or more children are pending, when a pending child sits in a non-Value context, or when it is a Cast over a pending child. The highest pending Value expression is wrapped.
- Blocks, closures and format macros are self-contained; each format arg is its own slot (static_mut_refs denies a borrow of a static through println!).
- Statement form for inline asm, assignments with a pending target, and pending statement macros (let in a macro expansion cannot sit in expression position). Adjacent let-free statement blocks merge. An old Stmt::Unsafe with lets becomes a plain block, spliced when it is last.
- Static/const initializers are placed too.
Lowerer: unreachable_unchecked, the setjmp support call and weak-address reads now carry marks; codegen no longer wraps Transmute/CopyNonoverlapping itself.

Merge fix found on the way: check_macro_template compared the filled template `value = value + 1` against the separately lowered `value += 1`; the filled side now runs statements::fold_compound_assignments. macro_places.c had captured the mismatch error as its expected output; it now translates and its macro bodies drop inner unsafe while call sites take one block.

Fixture: ~520 FileCheck blocks regenerated (tests/fixtures, release, build, dylink, merge); torture__pr71984.c promoted out of gcc-only.unsupported. slate and merge profiles pass.

Limits: the lowerer still wraps; nested_unsafe, peel_unsafe, NodeKind::Unsafe and the SLATE_UNSAFE_MARK_CHECK checker go in the cleanup commit. msvc ms_asm_entry_labels.c is stale (slate-j3by.23).
