Outcome: ~/slate-translated/slate-python is a standalone tree: ./run.sh builds the translated interpreter if needed and drops into python, and cargo run --release in python/ does the same.

- e2e.py writes <crate>/.cargo/config.toml for every crate it builds (build.target = host triple, target-dir, -A warnings and the native link args as rustflags) instead of passing RUSTFLAGS/CARGO_TARGET_DIR, so a plain cargo build/run reproduces the harness build. build.target keeps the rustflags off dependency build scripts, which link from their own directories; binaries move to cargo-target/<triple>/<profile>/.
- Recipe.standalone ("cpython") symlinks the corpus checkout into the output dir, rewrites link args under it to relative paths, writes a minimal rust-toolchain.toml with the pinned channel, and copies tools/corpus/standalone/cpython.sh as run.sh (also the cargo runner): it sets PYTHONHOME and PYTHONPATH=cpython/Lib:<pybuilddir> so the interpreter finds the stdlib and extension modules outside the build tree.
- crate_manifest emits [lints.cargo] unused_dependencies = "allow" and the vendored num-complex template drops package.homepage, the two cargo-level warnings that -A warnings cannot silence.
