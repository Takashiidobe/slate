# slate-3amj.54 target_feature: unit ISA flags (-mavx2, -march) put #[target_feature] on every function; macro intrinsics no longer crash LLVM isel

_2026-11-13 23:19:20_

- bead: slate-3amj.54
- kind: feature
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/src/backend/interproc
- area: crates/slate-parser/src/target/x86_isa.rs
- target: x86_64

Outcome: a unit compiled with x86 ISA flags (`-mavx2`, `-mfma`, `-mavx512f`, `-march=x86-64-v3`) now puts those features in `#[target_feature]` on every function it defines, so header intrinsic macros that expand in user functions (`_mm256_i32gather_epi32`) no longer crash rustc-LLVM isel.

Gap and why it mattered: only `__attribute__((target(...)))` functions got `#[target_feature]`. Macro intrinsics expand to `__builtin_ia32_*` inside the user's function, so `@llvm.x86.avx2.gather.d.d.256` landed in a function with only `target-cpu=x86-64`. NumPy's `FLOAT_fmax_X86_V3` / `DOUBLE_fmax_X86_V4` (loops_minmax.dispatch) hit `LLVM ERROR: Do not know how to split the result of this operator!` in the release build.

Before (`-mavx2 -mfma`):

```c
static int gather_sum(const int *table, __m256i index) {
    __m256i v = _mm256_i32gather_epi32(table, index, 4);
    ...
}
```

`gather_sum` had no attribute; the fixture failed at rustc.

After: every defined function (including nested functions) gets

```rust
#[target_feature(enable = "avx,avx2,fma,popcnt,sse3,sse4.1,sse4.2,ssse3,xsave")]
unsafe fn gather_sum(...)
```

plus any features from its own `target(...)` attribute.

Implementation:
- `X86Isa::enabled_beyond(baseline)` (slate-parser target/x86_isa.rs): clang spellings of features enabled in the unit but not in `X86Isa::baseline(family)`.
- `unit_target_features` (lowerer/target_features.rs) maps them through `X86_FEATURES` to rustc names. Features rustc has no name for (`crc32`, `mmx`, `cx8`, ...) are skipped, not barriers.
- `Tables::unit_features` seeds `enabled_target_features`, so `target_feature_attr`, the asm register-class checks and `self.target_features` all see the unit ISA.
- `FunctionName::is_unsafe` is set for every function (and nested function) of a unit with unit features, so callers wrap calls in `unsafe`.

- `interproc::has_unsafe_signature` (backend/interproc/mod.rs): a fn that is `unsafe` only because of `#[target_feature]` (Rust ABI, not variadic) is still a candidate for the pointer, length and string-param lifts. Without this, every function in an ISA-flag unit lost its slice lifts (`print_lanes(name, lanes: &[f32])` regressed to `*const f32, count`). Explicit `target(...)` functions now get lifted too (`target_feature_dispatch.c`: `popcount_hw(words: &[u64])`).

This reverses the slate-dghn.58 note that unit-level flags should not add `target_feature`. It also lets header intrinsics inline into callers (perf parity).

FileCheck regenerated: alloca_layout_gcc_avx, flag_fp_contract_gcc, flag_gcc_isa_features, flag_msvc_arch_avx2, extern_vector_abi, flag_fp_contract_off, target_feature_dispatch, x86_header_expanded_builtins_3.

Limits: x86 only; lifting header intrinsics with `target` attrs leaves casts like `*(__A as *const u32)` and `&(*addr_of_mut!(c))` (x86_header_expanded_builtins_3.c). `/arch:AVX2` gives no `fma` (parser ISA fact, unchanged). AArch64 `-march=armv8.x-a+...` units are unchanged. Clang block invoke functions (`lower_block_function`) do not get the attribute.
