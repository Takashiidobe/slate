# slate-f2zu.14.34.21 **builtin_constant_p: enum operand folded to 0, so **rht_ptr/IS_PLATFORM BUILD_BUG_ON kept \_\_compiletime_assert_N

_2026-11-15 15:23:26_

- bead: slate-f2zu.14.34.21
- kind: parser
- area: crates/slate-parser/src/sema/expression.rs
- corpus: linux

Outcome: `__builtin_constant_p` of a non-folding enum operand now lowers to
`llvm.is.constant` (on its underlying integer) at -O1+, so kernel
`BUILD_BUG_ON(!__builtin_constant_p(enum_param))` in always_inline helpers no
longer keeps calls to undefined `__compiletime_assert_N`.

Diagnostic or IR fact that was wrong: .13 emitted the intrinsic only for
integer, `_Bool`, f32 and f64 IR types. An enum value has IR type
`Defined(enum)`, so `statically_known_query` rejected it and the query folded
to 0. The kernel uses this in `__rht_ptr` (include/linux/rhashtable.h,
`enum rht_lookup_freq freq`) and i915's `IS_PLATFORM`/`IS_SUBPLATFORM`
(`enum intel_platform p`). Those account for most of the remaining
**compiletime_assert_N link errors (xdp_unreg_mem_model, **netlink_lookup,
page_pool_create_percpu, i915_driver_probe, i9xx_fsb_freq, ...). Translated Rust
had `if true { unsafe { __compiletime_assert_845() }; }`.

```c
enum freq { NORMAL, LIKELY };
int enum_operand(const enum freq fr) { return __builtin_constant_p(fr); }
```

Before (-O2):

```
if not<bool>(ne<i32>(const<i32>(0), const<i32>(0))) [folded=true]
```

After (-O2; -O0 unchanged):

```
if not<bool>(intrinsic<bool, llvm.is.constant>(enum_to_int<u32, reason=promotion>(read<@type0>(%5)))) [folded=true]
```

Fix: `Lowerer::expr`'s `__builtin_constant_p` arm
(crates/slate-parser/src/sema/expression.rs) passes the lowered operand through
`enum_integer` after the fold check, so an enum reaches `statically_known_query`
as its underlying integer type. Spec: wiki/concepts/ir/builtins.md.

Verified on the example TUs (net/core/xdp.c,
drivers/gpu/drm/i915/i915_driver.c): `__rht_ptr` and `IS_PLATFORM` asserts are
now guarded by the intrinsic. The remaining `if true` asserts there are
`BUILD_BUG()` in `get_current`'s dead `IS_ENABLED` arm, which rustc folds; the
old link did not report them.

`**types_ok`, `\_\_native_word`) were not re-examined individually.
