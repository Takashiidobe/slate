# Old-style declaration gaps in the gcc flavor

_2026-11-08 21:22:07_

slate-parser-cxg.18.2: (1) Empty declarations in a K&R parameter declaration list (f (a, b) int; register; {}) are skipped (parse_kr_parameter_declarations, parser/stmt.rs), and its specifiers now allow implicit int. (2) In the gcc flavor before C23 a non-definition with an identifier list (extern int f (i);) is an unprototyped declaration instead of a K&R definition missing its body (parse_external_item, parser/decl.rs); clang rejects it. (3) gcc accepts return expr in a void function under C89/gnu89 (warning); dialect.rs sets value_return_in_void for gcc before C99 (it was only set by -fpermissive). Fixture: gcc_statement_flavor_rules.c RETURN; migrated gcc.dg declspec-15/16/17 and Wdeprecated-non-prototype-3. permerror-gnu89(-pedantic).c still fail on __builtin_abs used as a value: slate-parser-cxg.18.10.
