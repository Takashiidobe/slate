# Slate frontend function pointers use the C-unwind ABI

_2026-10-01 09:28:04_

slate-p58o.3.43: function pointers to extern (libc) functions were a FunctionDecay barrier, because function pointers lowered as Option<unsafe fn> with the Rust ABI, which an extern "C" item cannot coerce to.

Decision (ported from the old CIR lowerer): C-ABI function pointers throughout.
- lower_type emits FnPtr with Abi::CUnwind: Option<unsafe extern "C-unwind" fn(..)>. C-unwind rather than C because forced unwinds (pthread_cancel) must cross generated frames; see wiki/concepts/pthread-cancel-forced-unwind-needs-c-unwind-abi.md.
- Decay of a defined function records its Rust name in Dependencies.address_taken; assemble() gives those FnDefs extern "C-unwind" ABI (still safe fns, so direct calls are unchanged). No IR walk is needed. A decay recorded in a function that later barriers only costs an extra ABI annotation.
- Decay of an extern function is transmute::<*const (), FnPtr>(name as *const ()), which is also valid in static initializers.

qsort_bsearch_fixup.c previously handed Rust-ABI comparators to libc and only passed because the ABIs coincide on x86_64 for pointer args. It is now correct by construction.

Fixtures promoted: fn_ptr_cmp_libc.c, libc_address_taken_safe_callback.c, gcc-torture pr54937.c.
Validation: full slate profile green apart from the pr54937 promotion.
