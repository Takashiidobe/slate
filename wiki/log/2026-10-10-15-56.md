# Gate #elifdef and #elifndef on flavor and standard

_2026-10-10 15:56:20_

slate-parser-cxg.7.19: slate applied #elifdef in every mode, so gcc.dg cpp/c11-elifdef-1.c (#if 0 / #elifdef A / #error) failed under -std=c11.

Oracle behaviour (gcc -E, clang -E, cl /EP):
- clang: a directive in every standard (an extension before C23).
- gcc: a directive in gnu modes and C23; in strict ISO modes before C23 it is an unknown directive, ignored in a skipped group and 'invalid preprocessing directive' in a taken one.
- cl: same as gcc's strict modes by default and with /std:c11 or /std:c17 (C7730 '#elifdef requires /std:clatest' when taken); a directive under /std:clatest. cl /EP crashes (C1001) on '#if 0 / #elifdef A / #else'.

StandardFeatures::elifdef_directives holds the rule; TokenSource gets it and names the two directives Unknown when it is off, so both the active path and skip_group see the same name.

Fixtures: pp_elifdef_by_standard.c (gcc gnu11+c23, clang c11+c23, msvc c23), pp_elifdef_skipped_before_c23.c (gcc c11, msvc c17), error elifdef-c11.c (gcc) and elifdef-c17.c (msvc). Migrated gcc.dg cpp/c11-elifdef-1.c, c23-elifdef-1.c, gnu11-elifdef-3.c. Parser profile 8054/8054.
