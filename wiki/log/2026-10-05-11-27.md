# String literals lower as places, so &"..." works

_2026-10-05 11:27:48_

slate-parser-6x05.38.23. lower_place had no StringLiteral arm, so taking the address of a string literal (&"abc", &L"ab") hit 'internal error: expression is not a supported place'. Kernel 8250_pci.c REPORT_CONFIG(option) expands to (IS_ENABLED(...) ? 0 : (kernel_ulong_t)&#option) in a designated initializer. The internal .str global emission is now code_unit_global, shared by string_global (__func__ and friends) and a new string_literal helper; lower_place uses string_literal for StringLiteral, and the value path reads through it, so value IR is unchanged. Fixture: clang/linux/x86_64/address_of_string_literal.c. drivers/tty/serial/8250/8250_pci.c now parses under --flavor=clang.
