# anon_local_records shared across --lib types.rs

_2026-08-25 14:47:33_

translate-project --lib on giflib failed to compile because struct operation (giftool.c) was hoisted into shared src/types.rs (--lib crates always share every named record) while its anonymous union member (auto-named anon_0) stayed private to giftool.rs - types.rs referenced an inaccessible type. Root cause: main.rs's four translate-project code paths each collect shared_records from unit.records and shim_records_for_module, but never called frontend::anon_local_records for the --lib paths (the plain translate-project path already did this correctly via its occurrence-counted record_occurrences map). Fixed by adding an anon_local_records merge loop, using the same shape-conflict-tracked merge as named records, to both translate_project_lib_crate_with_manifest and translate_project_lib_crate_with_compile_commands. Per user request, extracted the shared enum+record+anon-record+shim-record merge block (previously duplicated near-verbatim at both --lib call sites) into a new merge_shared_types_for_module helper (plus merge_record_into_shared) in src/main.rs, rather than pasting the anon-record loop a third time. Added tests/fixtures.library/anon_union_member (single-TU struct with an anonymous union member) and a matching cross_tu.rs test asserting cargo check succeeds; verified it reproduces the original E0425 with the fix reverted. Fixes slate-2ppd.2; closes the slate-2ppd 'translate giflib' epic - the full giflib source tree now translates and cargo builds cleanly via translate-project --lib.
