# Make batch crates fresh on no-change test runs

_2026-10-31 23:20:00_

slate-5q63.11.2: every generated batch crate rebuilt all of its bins on every run, so the slate profile recompiled thousands of fixtures with no source change. Cargo reported two always-missing rerun-if-changed paths (CARGO_LOG=debug, 'stale: missing'): vendor/bitfields/build.rs named ../README.md and ../bitfields_impl/src/lib.rs, and tests/support's support_crate_path pointed num-traits, num-complex and libc at a build script in crates/slate/vendor while their package root was the per-project stub, so rerun-if-changed=build.rs resolved to nothing. Since every bin depends on these crates, all were rebuilt. Removed both rerun lines from bitfields (this also fixes translate-project's generated crates, which use the same path dep) and support_crate_path now copies build.rs next to the stub manifest. Results: no-change cargo time across 12 batch crates 45.5s -> 2.5s, gcc_torture_supported 16.5s -> 5.1s, full slate profile 128-136s -> 55.7s no-change (33/33 pass; 80.8s on the first run, which rebuilds everything once). The bead's premise was wrong: failing bins are not the cost, those four ratchet crates take 0.6s in total, so no failure cache was added.
