# slate-5q63.15 translate-project: emitted crates hard-coded absolute bitfields path and link-order.json source paths

_2026-11-17 10:43:32_

- bead: slate-5q63.15
- kind: bug
- area: crates/slate/src/main.rs
- area: crates/slate/build.rs
- area: crates/slate/src/compile_commands.rs
- area: tools/corpus/kernel_link.py

Outcome: translate-project crates no longer hold absolute paths: bitfields is vendored into the crate and link-order.json names sources relative to the compile command directory.

Symptom: every emitted Cargo.toml had `bitfields = { path = "<slate checkout>/crates/slate/vendor/bitfields" }`
and link-order.json listed absolute C source paths, so translated crates (slate-linux) did not build or
link on another machine.

Cause: `crate_manifest` in crates/slate/src/main.rs formatted `CARGO_MANIFEST_DIR/vendor/bitfields` into
the manifest, and `write_link_order_map` serialized `SlateUnit.path` (absolute, canonicalized).

Fix:
- crates/slate/build.rs `write_vendored_crate` takes the entries to embed; bitfields embeds
  `Cargo.toml`, `build.rs`, `src`; bitfields-impl embeds `Cargo.toml`, `src` (cargo ignores the missing
  examples/tests targets of a path dependency; the build script must exist).
- main.rs `write_vendored_crate(crate_dir, name, files)` replaces `write_vendored_libc` and writes libc,
  mach2, bitfields, bitfields-impl; manifest uses `bitfields = { path = "bitfields" }`.
- `CompileCommand` gains `directory`; `translate_slate_project` writes each unit's `file` as
  `compile_commands::relative_path(directory, file)` (e.g. `../block/bdev.c` for the kernel's
  build-clang directory).
- tools/corpus/kernel_link.py `link_units` resolves `native_dir / file` (normpath) before choosing the
  native or project base; absolute entries from older crates still work.

Verified: a bitfield project translated, moved to another directory, `cargo run` exits 0; a
freestanding staticlib writes `"file": "../src/k.c"` and `link_units` maps it to `src/k.o`.

Limits: the test harness manifest (crates/slate/tests/support/mod.rs `bitfields_path`) still uses the
absolute checkout path; it is local-only. ~/slate-translated/slate-linux was not regenerated; its
hand-fixed link.py resolves against the kernel root, the in-repo kernel_link.py against the build dir.
