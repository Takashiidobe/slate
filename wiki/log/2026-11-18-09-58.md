# slate-3amj.27 clang flags: -fforce-enable-int128 defines __SIZEOF_INT128__ on i686

_2026-11-18 09:58:06_

- bead: slate-3amj.27
- kind: feature
- area: crates/slate-parser/src/compiler_args.rs
- flavor: clang
- target: i686

Outcome: clang-flavor `-fforce-enable-int128` is now a recognized flag that defines `__SIZEOF_INT128__=16`, as clang does on targets without __int128 (i686).

Gap and why it mattered: the flag printed "unsupported compiler flag ignored" and the macro stayed undefined, so code guarded by `#ifdef __SIZEOF_INT128__` took its no-int128 path under the flag. The `__int128` type itself already lowered on i686 without the flag (permissive), and the differential fixture crates/slate/tests/fixtures/i686/flag_force_enable_int128.c was already promoted (slate-xw0x.10).

Before (clang -target i686, -fforce-enable-int128):
```c
#ifdef __SIZEOF_INT128__
int sizeof_int128 = __SIZEOF_INT128__;
#else
int sizeof_int128 = 0;
#endif
```
sizeof_int128 = 0 plus the unsupported-flag warning. After: 16, no warning; without the flag still 0.

Implementation: `Opt::ForceEnableInt128` (clang only) in crates/slate-parser/src/compiler_args.rs, parsed like `-pthread`, and a `MacroOption::Define("__SIZEOF_INT128__=16")` inserted next to the `_REENTRANT`/`__EXCEPTIONS` insertions, skipped under -undef.

Fixture: crates/slate-parser/tests/fixtures/clang/linux/i686/force_enable_int128.c (DEFAULT and FORCED prefixes).

Limits: i686 without the flag still accepts `__int128` where clang rejects it; the flag does not gate the type.
