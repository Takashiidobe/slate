# slate-dghn.58.9 rust_binding_name/codegen keywords: C identifier gen emitted bare, reserved in Rust 2024

_2026-11-13 22:24:38_

- bead: slate-dghn.58.9
- kind: bug
- area: crates/slate/src/frontend/lowerer/names.rs
- area: crates/slate/src/backend/codegen.rs

Outcome: a C identifier named `gen` (variable, parameter, function, struct tag, field) is emitted as `r#gen`, so Rust 2024 parses it; this was the only failure in the NumPy clang-aarch64 translate stage (84 rustc errors in Cython output).

Symptom: `error: expected expression, found reserved keyword gen` at `__Pyx_Coroutine_SendEx(gen, ...)`.

Reproducer:
```c
struct gen { int gen; };
static int gen(int gen) { return gen * 2; }
```
Before: `struct gen { gen: i32 }`, `fn gen(gen: i32)`. After: `struct r#gen { r#gen: i32 }`, `fn r#gen(r#gen: i32)`.

Cause: `gen` is reserved in Rust 2024 but was missing from both keyword lists: `rust_binding_name` (crates/slate/src/frontend/lowerer/names.rs) and the keyword match in crates/slate/src/backend/codegen.rs (which already had `try`).

Fix: add `gen` to both lists. The symbol name is unchanged (`r#gen` links as `gen`).

Regression test: crates/slate/tests/fixtures/rust_keyword_gen_identifier.c (struct tag, field, function, parameter, function pointer, block-scope local, macro argument).

See: slate-dghn.58, slate-dghn.58.7
