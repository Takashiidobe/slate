# slate-parser-6gk.1: control-flow reachability

_2026-09-11 18:06:16_

Audited eval.rs and render.rs first: both were already complete for every new
Stmt/Expr kind -- eval.rs's Stmt::eval match is compiler-enforced exhaustive
(would fail to build otherwise), and render.rs renders via generic
Debug-derived dumping, so it needed no per-variant changes. The real gap was
reachability.rs, which only ever did decl-level dead-code elimination
(pruning decls unreachable from the root file), never touching statements.

Added ConcreteStmt::Unreachable(Box<ConcreteStmt>) and a structured pass
(reachability::mark_unreachable) that walks a function body sequentially,
wrapping statements after a terminator (return/break/continue/goto, or an
if/else whose both branches terminate) in Unreachable. Labeled/Case/Default
statements reset the terminated flag, since they're jump targets reachable
from elsewhere (goto/switch dispatch) even after dead code. Wired into
eval.rs when building each ConcreteFunctionDecl's body. Deliberately
conservative: loops and switch statements themselves are never treated as
guaranteed-terminating (no constant-condition or switch-exhaustiveness
analysis), so only genuinely unambiguous dead code is flagged.

Added tests/fixtures/reachability.c (dead code after return/break/goto, a
label re-enabling reachability, and an if/else where both branches return).
Verified with real clang. Fixed tests/filecheck.rs's clang-oracle summarizer
match for the new variant. cargo build/test/clippy/fmt all clean. Closed
slate-parser-6gk.1.
