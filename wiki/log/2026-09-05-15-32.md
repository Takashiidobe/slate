# clear_cache intrinsic mangling: rustc LLVM version skew, not a generator bug

_2026-09-05 15:32:43_

target_stack_builtin_ops's Rust batch build failed with "unknown LLVM
intrinsic `llvm.clear_cache.p0`". Traced it to a genuine LLVM version skew,
not a bug in slate-intrinsic-gen's classification logic:

- slate-intrinsic-gen extracts src/frontend/lowerer/intrinsics_table.rs from
  ~/llvm-project/build-cir, which must track LLVM tip-of-tree for CIR support
  (currently 24.0.0git). There, int_clear_cache uses llvm_anyptr_ty
  (Intrinsics.td), so LLVM's own Intrinsic::isOverloaded() correctly reports
  it as overloaded, needing the `.p0` mangled suffix. Verified with
  `opt -passes=verify` on a hand-written .ll: llvm.clear_cache.p0 is a real,
  verifier-accepted intrinsic on that tree.
- rustc (`rustc --version --verbose`) bundles LLVM 22.1.8, which predates
  that anyptr conversion and doesn't recognize the mangled name at all —
  hence "unknown LLVM intrinsic".

So the generator was right about the LLVM it was pointed at; it's just the
wrong LLVM version for matching what rustc's codegen backend accepts. Per
user direction: don't hand-edit the generated table (it'll be clobbered on
regen) and don't re-point the generator at a matching LLVM 22 build (too
heavy for one entry). Instead added a small manual override table
(TOOLCHAIN_SIGNATURE_OVERRIDES in src/frontend/lowerer/intrinsics.rs) that
find_intrinsic_signature() checks before falling back to the generated
tables, overriding just `llvm.clear_cache` to overloaded:false (fixed name,
no mangling) — matching what rustc's LLVM 22 actually accepts.

Also regenerated the fixture's stale FileCheck snapshot (it had never
actually compiled before, so its expectations were guesses) — first attempt
via a plain `update_filecheck.py --in-place` accidentally collapsed the
fixture's X86_64-GNU/AARCH64-GNU dual-target lines down to the host arch
only; reverted and redid it with the required
`--target X86_64-GNU=... --target AARCH64-GNU=...` form per
wiki/concepts/differential-fixtures.md, which correctly touched only the two
`link_name` lines.

Fixes slate-ks17.
