# C23 cross-scope tag compatibility and C-typed brace elision

_2026-09-25 19:37:46_

Implemented C23 (N3037) same-TU tag compatibility (slate-parser-rhg): when a named struct/union/enum is completed under C23, TypeResolver::join_compatible_tag joins it to an earlier same-named definition whose content matches (same_tag_shape plus same_field_types via CTypes::compatible) and records a tag class in CTypes; compatible_unqualified compares Record/Enum by tag class. The class is joined before the member check so self-referential members compare coinductively. classify_conversion treats compatible distinct records as RecordCopy. Attributes are ignored (gcc behaviour; clang 22 treats aligned() as incompatible). Then closed slate-parser-pd7: brace elision in item_entry and the length-inference walk (consumed/Walk) now ask initializes_whole over C types via compatible_unqualified; subobject_type moved to TypeResolver and inferred_array_length takes the element QualType. Why rhg first: pd7's proposed fix alone was unobservable, since compatible_unqualified treated distinct record ids as incompatible and even 'struct S a = g;' across scopes was rejected. Verified against clang 22 -std=c23 with a probe of compatible/incompatible cases (names, bit widths, enumerator values, quals, struct vs union, nested, anonymous). New fixture tests/fixtures/sema/c23_cross_scope_tag_compatibility.c. gcc-dg c23-tag-alias-4, c23-tag-alias-7 now lower successfully and c23-tag-composite-10 now stops at __builtin_clear_padding; regenerated. Filed slate-parser-rdj (block-scope 'struct T;' reuses outer tag, pre-existing). Updated wiki c-type-layer.md and ir-spec.md. Verified with cargo clippy --allow-dirty --fix, cargo fmt, cargo nextest run --release (pass).
