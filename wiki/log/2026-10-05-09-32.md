# noreturn on function-pointer declarators

_2026-10-05 09:32:59_

slate-parser-6x05.38.19. efistub.h declares 'efi_status_t __noreturn (__efiapi *exit)(...)' in a struct; slate-parser warned 'noreturn attribute ignored; it applies only to function types' (fatal under the kernel's -Werror, 13 TUs) because sema/attributes.rs::inapplicable rejected noreturn on every non-Function Subject.

- noreturn left the Subject table. TypeResolver::check_function_type_attributes runs after type resolution in the declaration loop, for parameters, and for fields (named and anonymous).
- clang rule (from distributeFunctionTypeAttr/FunctionTypeUnwrapper, measured): accepted if peeling pointers and arrays reaches a function type, including typedefs of function pointers and function typedefs; warns on int.
- gcc rule (measured): accepted on a function declaration or a declarator whose type is a pointer to a function; (**p), arrays, typedef'd-pointer arrays and a function-type typedef warn.
- Warnings match both oracles line for line on the new fixtures {clang,gcc}/linux/x86_64/noreturn_function_pointer.c.
- Not covered: attributes on a pointer declarator chunk (FP *__attribute__((noreturn)) p) are never checked; gcc warns there. Calls through such pointers are not marked noreturn in the IR (direct calls are not either).
- .38.12 (format/nonnull on function-pointer typedefs) is the same family; check_function_type_attributes is the place to extend.
- Wiki: attributes.md applicability.
