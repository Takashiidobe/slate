# slate-xw0x.15 generated_differential: compare typed IR mutants against C fixture oracles

_2026-11-24 09:19:55_

- bead: slate-xw0x.15
- kind: feature
- area: crates/slate-mutate
- area: crates/slate/tests

Outcome: The existing differential runner can compare Slate IR mutants with Clang, GCC, and MSVC using the fixture's compiler flags.

Before
`SLATE_DIFF_FIXTURE=peel_casts` runs the original fixture once per target.

After
`SLATE_MUTATE=1 SLATE_DIFF_FIXTURE=peel_casts` runs mutations of that fixture. A mismatch preserves the mutated C, the generated Rust when available, and the compiler arguments.

Implementation
- `slate-mutate::candidates` reads parser types, source spans, and `slate-analysis` facts. An eligible local has one initializer, one read at an observed output, and zero later writes.
- The C oracle compiles a source edit for the same literal changed by `Mutation::apply`. Slate runs its IR transforms and lowers that changed module directly.
- Integer rules use operation semantics to bound shifts and divisors and filter signed arithmetic candidates. A change to a constant refreshes integer conversion fit metadata on its ancestor values.
- Mutation mode is an option on `generated_differential`. It uses the existing fixture corpus and its flavor and flags, with optional extra flags for both compilers.

Fixture
Existing `peel_casts`, `div`, `local_vla`, `gcc/flag_unsigned_bitfields`, and `msvc/flag_msvc_define` fixtures ran through the Clang, GCC, and MSVC oracle paths.

Limits: The initial rules target integer values in top-level returns and decimal printf calls in main. Source materialization needs an editable literal in the main file.
See: slate-xw0x.16 for additional context and type rules and flag coverage.
