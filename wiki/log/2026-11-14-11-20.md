# slate-f2zu.14.1 pp paste: empty macro argument before ## pasted the previous token, 'pasting formed )foo'

_2026-11-14 11:20:00_

- bead: slate-f2zu.14.1
- kind: parser
- area: crates/slate-parser/src/pp/expand.rs
- corpus: linux

Outcome: an empty macro argument on the left of `##` acts as a placemarker, so the paste yields the right operand instead of pasting the token before the argument.

Diagnostic: `pasting formed ')foo', an invalid preprocessing token` (clang flavor; gcc flavor gave the gcc wording). 11 kernel TUs failed to parse: include/net/ipv6.h:214 `mod##SNMP_INC_STATS64` (net/core/filter.c, net/ipv6/*), net/mac80211/trace.h:41 `n##control_freq`, i915 intel_gt_sysfs_pm.c:415 `&p##attr_##s`.

Reproducer:
```c
#define F(m, x) do { if (x) m##foo = 1; } while (0)
int foo;
int main(void) { F(, 1); return foo - 1; }
```

Before: parse error above. After: `do { if (1) foo = 1; } while (0)`, same as clang -E and gcc -E.

Cause: `Preprocessor::substitute_function_macro` (src/pp/expand.rs) emits nothing for an empty parameter operand of `##`; the `##` branch then popped the previous output token (`)`, `&`, `,`) as its left operand. `CAT(, x)` worked only because the output was empty there.

Fix: track a placemarker (the empty operand's leading space) after an empty `##` left operand. The next `##` appends the right operand's tokens, gives the first one the placemarker's leading space (so `if (1) foo` keeps its space), and keeps the placemarker when the right operand is empty too (`a##b##c` with a and b empty yields c).

Fixture: crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/paste-empty-left-operand.c (after `)`, `&`, `,`, `[`, chained empties, all empty, and a non-empty control). Parser profile passes.
