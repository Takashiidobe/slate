# slate-f2zu.14.23 bridge_arg_into_ref: &mut reborrow through `as *const T` cast for a const param lifted to &mut (E0596)

_2026-11-14 18:53:19_

- bead: slate-f2zu.14.23
- kind: bug
- flavor: clang
- area: crates/slate/src/backend/interproc/pointer_lattice.rs

Outcome: a call to a callee whose C `const T *` parameter was lifted to `&mut T` now reborrows through `*mut T` instead of failing E0596.

Symptom: linux gdt_idt.rs, cacheinfo.rs, ldt.rs, tcp_input.rs: `native_load_idt(unsafe { &mut (*(addr_of_mut!(desc) as *const desc_ptr)) })` cannot borrow data in a `*const` pointer as mutable (10 errors).

Reproducer:
```c
static inline void load(const struct desc_ptr *dtr) {
  __asm__ __volatile__("movq 2(%1), %0" : "=r"(got) : "r"(dtr), "m"(*dtr));
}
load(&desc);
```
The asm memory operand lowers as `dtr as *mut desc_ptr`, so the pointer lattice lifts `dtr` to `&mut desc_ptr`, while the call argument keeps the C const conversion `as *const desc_ptr`.

Cause: `bridge_arg_into_ref` (interproc/pointer_lattice.rs) wrapped the argument as `&mut *(arg)` without looking at its cast.

Fix: when the bridge is mutable and the argument is `Expr::Cast` to `Type::Ptr`, set that pointer cast to mutable. Output: `&mut (*(addr_of_mut!(desc) as *mut desc_ptr))`.

Regression test: crates/slate/tests/fixtures/x86_64/asm_memory_input_const_param_lifted_ref.c
