# Gate struct sysinfo trailing padding by libc/wordsize

_2026-09-08 09:08:00_

(slate-b66b.13.7) Probed struct sysinfo (sys/sysinfo.h) in
tools/probes/linux-libc-abi.c: size/align plus offsets of all fields up to
mem_unit (trailing padding size falls out implicitly from size minus
mem_unit's offset, avoiding the fact that glibc names the padding field
`_f` and musl names it `__reserved`).

glibc's struct sysinfo comes straight from the kernel UAPI header
(linux/sysinfo.h), which sizes the trailing pad as
`20 - 2*sizeof(kernel_ulong_t) - sizeof(u32)` (libc5-compat padding from the
original syscall ABI) -- 0 bytes on 64-bit (struct still rounds up to 112
for 8-byte alignment), 8 bytes on 32-bit (64-byte struct). musl instead
hand-declares a fixed 256-byte `__reserved` regardless of word size. Both
are safe: sysinfo() is a raw syscall that only writes fields the kernel
knows about, so the extra musl bytes are simply never touched. sizeof()
genuinely differs between the two libcs though.

libc-shim/include/sys/sysinfo.h previously had one fixed __reserved[256]
shape (musl-only correct). Fixed by computing the glibc-shaped padding with
the same formula, using the shim's own sizeof(unsigned long)/sizeof(unsigned)
so it comes out right per word size automatically, gated on
__SLATE_LIBC_GLIBC; musl (and everything else) keeps the fixed 256-byte
buffer.

Verified: tools/libc-abi-matrix.py green for struct_sysinfo on all 4 arches
x 2 libcs, cargo nextest --profile libc 37/37.
