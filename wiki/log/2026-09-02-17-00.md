# adjacent-temp-forward: extend LateInlineTemps top-level use to if/match

_2026-09-02 17:00:23_

slate-y0qs.9: extend LateInlineTemps' top-level-use type-anchor check
(inline_temps.rs::is_top_level_use) to NodeKind::If (cond) and
NodeKind::Match (expr), not just Let/Assign/Return.

## Gap
A single-use adjacent bool temp feeding an `if` was blocked: `let _v: bool =
value < 0; if _v { ... }` never inlined to `if value < 0 { ... }` because
expr_is_type_anchored(value < 0) is false (int-literal RHS isn't type
anchored) and consumer_pins_type only checks compound conditions like
`_v > 0`, not a bare `if _v`. Comparison/match producers are unambiguous
(comparisons always yield bool; match scrutinee type was already fixed by
the removed Let), so bare top-level use is safe the same way Return already
was.

## Fix
Two match arms added to is_top_level_use: If{cond} and Match{expr} check
expr_ident(..) == Some(name), same shape as the existing Return arm.

## Verified
tests/fixtures/return_cleanup.c (`if (value < 0) return -1; return value+2;`)
now lowers to `if value < 0 { return -1; } value + 2` under rewrites,
regenerated via update_filecheck.py. Full `cargo nextest r --release
--profile rewrites` (92 tests) green, cargo fmt/clippy clean.

## Scope not done
slate-y0qs.9's broader acceptance criteria (effectful initializers across
control flow, peeling pure boolean chains through call->negation->if,
giflib temp-count reduction) still open -- this is the if/match top-level-use
slice only.
