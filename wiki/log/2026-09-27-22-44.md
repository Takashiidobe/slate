# Declaration specifiers parse in any order

_2026-09-27 22:44:23_

Fixes slate-parser-kck; also clears three items of slate-parser-cxg.18.

parse_base_type took one type-specifier token and branched on the next
few, so only fixed orders parsed: int long, char signed, long int
unsigned, long const long, _BitInt(42) unsigned, int __int64, storage
classes or attributes between type keywords were all rejected. It is
replaced by an accumulator in src/parser/declarator.rs, modelled on
clang's DeclSpec: parse_type_specifiers alternates take_type_specifier
with parse_specifier_keywords (qualifiers, storage class, attributes,
inline) and builds the TypeSpecifier at the end.

SpecifierShape holds base / sign / width / _Complex / _Imaginary / _Sat,
and each keyword is checked as it is added, so an incompatible one is
reported at its own token as 'cannot combine `x` with previous
declaration specifiers'. Rules checked against clang and gcc: long twice
at most, short excludes long, signed/unsigned conflict (a repeat is
accepted, as clang does), one base, long only with double among floats,
typedef/tag/typeof/_Atomic()/_Bool/void take nothing else, an identifier
is a type name only when no type keyword precedes it. MS __int64 is a
long long width (clang-cl: int __int64, long __int64 and __int64 __int64
pass; __int64 long and short __int64 fail). Fixed-point folds into the
same set, so fixed_point_ahead and parse_fixed_point are gone.

Fixtures: new sema/declaration_specifier_order.c (_Generic checks
verified by clang, five rejected variants); ms-sized-int-keywords-
clang-cl.c gains the __int64 orders; ir_imaginary_invalid.c and
ir_fixed_point_invalid.c changed wording only.
