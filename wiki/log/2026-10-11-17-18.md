# Default language standard per flavor: clang gnu17, gcc gnu23, msvc c17

_2026-10-11 17:18:21_

slate-parser-v74.1.11. LanguageStandard::default*for(flavor) replaces the Gnu23-for-everyone Default (2026-09-17 decision did not consider flavors). clang 22: gnu17 (**STDC_VERSION** 201710L on every target). gcc 16: gnu23. cl.exe without /std: behaves like /std:c17 for parsing (K&R definitions, void f(); f(1,2), bool as an identifier all accepted; #elifdef off) and still gets no **STDC_VERSION** (existing explicit_standard gate), so msvc defaults to C17. CompilerArgs no longer derives Default (unused).
Fixtures: 861 clang-flavor fixtures without SLATE-FILECHECK-STD regenerated (818 gcc-torture, rest clang/linux). Almost all is 'int main()' becoming unprototyped; the rest is gnu17 semantics (true is int 1, sizeof(true) 4) and glibc headers taking pre-C23 paths (assert without \_\_assert_single_arg, threads.h). 12 fixtures that test C23 features and that clang -std=gnu17 also rejects are pinned to gnu23 (c23*\*.c, flags_exceptions, flags_rounding, long_double, misc_language_survey, spans, gcc-torture pr117432); their output is unchanged.
Migrated CodeGen/microsoft-call-conv-x64.c; variadic-null-win64.c and call-graph-section-noprototype.c were already migrated with explicit gnu17/c17 and now also pass on the default (sweep slate_clang_default_std = 0 for all three).
