# slate-f2zu.9.17 do-while-zero: do { } while (0) becomes a block or labeled block on the IR instead of loop { if true { break } }

_2026-11-21 20:15:00_

- bead: slate-f2zu.9.17
- kind: rewrite
- area: crates/slate-analysis/src/transform

Outcome: `do { … } while (0)` outside kept macros is replaced on the IR by its body (a block), or by a labeled block when the body breaks or continues out of it, so it no longer lowers as `loop { …; if true { break; } }`.

Before (do_while.c):

    loop {
        total += 7;
        if true {
            break;
        }
    }

After:

    total += 7;

Rule (crates/slate-analysis/src/transform/do_while_zero.rs, pass `do-while-zero`, slot AfterMacroStrip, after const-fold):
- Match `DoWhile { id, body, condition }` whose condition has no statements and whose value is `const<bool>(false)` or a constant integer comparison that is false (`const_fold::constant_comparison`, so `ne(0, 0)` qualifies without const-fold having run).
- No `Break(id)`/`Continue(id)` in the body: `Block(body)`.
- Otherwise `LabeledBlock { id, body }` with `Continue(id)` retargeted to `Break(id)` (continue in a do-while(0) evaluates the false condition and leaves).
- Statement NodeId is kept; the condition's value NodeIds are retired from c_types/metadata.
- Post-order, so nested do-while(0) collapses inside out.
- Blocked by: kept macro expansions (`children` does not enter `MacroExpansion`; the macro_rules template must stay matched), a non-constant or effectful condition.

Combined with structure-goto, zlib-shaped `NEED(n)` macros holding a goto lower to plain `if !(have < 2) { … }`.

Fixture: crates/slate/tests/fixtures.transforms/do-while-zero/macros.c (swapped/clamp kept macros untouched; need, skip with continue, nested, repeat with a real condition). 13 tests/fixtures blocks regenerated: 71 `if true`/`if false` lines gone, none added (do_while, goto_structured_bug_on, atomic_rmw_redis, x86 header builtins, vector builtins, …).
