# Recurse through nested statements in walk::stmt_exprs

_2026-10-18 18:08:22_

Prep for slate-o3gw.4. walk::stmt_exprs and stmt_exprs_mut (reached only through
child_exprs for Expr::Block/Expr::Unsafe statement-expression blocks) used to
stop at Let/Expr/Return/Assign/CompoundAssign/Unsafe, so expressions inside a
nested If, LetIf, While, For, Loop, Match, Scope, Block, LabeledBlock or
InlineAsm operand were invisible to child_exprs. The callers expect a complete
walk (slot_promote occurrence/address-taken counts, remove_mut mutation checks,
libc_call site numbering), so this was a latent soundness hole: a &x or x = ..
inside such a nested statement was missed. Both walkers now recurse in the same
order, so the ordinals libc_call computes with child_exprs still line up with
the ones it rewrites through child_exprs_mut. The full slate profile is green with
no FileCheck changes.
