# Shape-keyed rule dispatch table (slate-gfyj.1)

_2026-08-27 22:14:55_

Implemented slate-gfyj.1 from the rewrite-engine throughput epic
(slate-gfyj), depended on slate-gfyj.2 (Ident interning) landing first.

Added NodeKindTag (arena.rs) -- one fieldless variant per NodeKind shape
(18 total) -- and NodeKind::tag() to map a node to its tag in O(1).
NodeRule gained a required `fn kinds(&self) -> &'static [NodeKindTag]`
declaring every shape a rule could ever match. engine/mod.rs's RuleRegistry
now bucket-sorts rules into a `[Vec<u32>; NodeKindTag::COUNT]` array at
construction (sorted by priority first, so bucket order still matches
priority order); run_worklist looks up arena.get(id).tag() once per popped
node and only tries registry.candidates(tag) instead of scanning every
registered rule with registry.iter().filter(matches).

This is the MLIR PatternApplicator / LLVM InstCombine-opcode-switch idea
discussed earlier: dispatch by declared root shape instead of linear scan,
so registering more idiom rules later doesn't slow down every other node's
match cost. Mirrors what mixing interning (gfyj.2) needed to be worth doing
first, since dispatch buckets keyed by identifier (e.g. call-target name for
future memchr/strlen-style rules) would otherwise hash/compare Strings.

Did not add a synthetic rule-count microbenchmark as a unit test -- project
convention is fixture-driven differential e2e tests only, no #[cfg(test)].
Correctness/dispatch-shape verified by code construction (array indexed by
tag) rather than a timed test.

rewrites profile: 110/110 pass, unchanged behavior.
