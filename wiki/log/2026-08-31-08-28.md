# Implement FreeBSD sockets and network libc ABI

_2026-08-31 08:28:43_

slate-sfzn.10.7: implemented the FreeBSD networking surface (sys/socket.h,
netinet/in.h, sys/un.h, netdb.h, arpa/inet.h, ifaddrs.h) via a new
full self-contained overlay pattern (bits/freebsd/{socket,in,un,netdb,ifaddrs}.h),
gated with #if defined(__SLATE_LIBC_FREEBSD) ahead of the existing
Linux-shaped generic implementation, which previously had zero libc
branching at all for this subsystem.

Key oracle-verified findings:
- Every sockaddr variant has a leading `unsigned char sa_len` byte before
  sa_family_t: sockaddr=16B, sockaddr_in=16B (sin_family@1), sockaddr_in6=28B
  (sin6_addr@8), sockaddr_un=106B with SUNPATHLEN=104 (not glibc's 108),
  sun_path@2. sockaddr_storage keeps the 128B _SS_PAD1/2 algebra but starts
  with ss_len/ss_family.
- AF_INET6 is a 3-way divergence: FreeBSD=28, Linux=10, Darwin=30.
- SOL_SOCKET=0xffff on FreeBSD, not 1. SO_* option values split into low
  bitmask flags vs non-contiguous 0x1001+ values.
- struct addrinfo has a DIFFERENT FIELD ORDER than the shared shim:
  ai_canonname comes before ai_addr, not after (verified via offsetof:
  canonname@24, addr@32, size 48B) - a silent Linux-order copy would have
  been ABI-wrong despite identical member types.
- EAI_* codes are positive on FreeBSD (EAI_FAMILY=5), not negative.
- struct ifaddrs has a separate ifa_dstaddr field, not a union with
  ifa_broadaddr (which is a #define alias instead).
- hostent/servent/protoent/netent layouts are identical to the shared
  shim; only their constants (NI_MAXHOST=1025, EAI_*) diverge.
- arpa/inet.h needed no overlay - signatures are identical and types
  already dispatch correctly.

All sizes/offsets verified with the _Static_assert sentinel-value trick
against both oracle sysroots (x86_64 and aarch64 produced identical
values - confirmed via diff of the relevant oracle headers). Added
libc-shim/freebsd-net-headers.txt manifest + a new
freebsd_net_header_manifest_compiles_for_x86_64_and_aarch64 test with
_Static_asserts covering every struct offset/size and the AF_INET6/
SOL_SOCKET divergences. Kept the option-constant surface narrow per the
ticket's design note (excluded routing-socket internals/kernel networking).

Verified end-to-end: slate translate + cargo check --target
{x86_64,aarch64}-unknown-freebsd for a fixture doing socket/bind/listen/
getsockname/sockaddr_un/addrinfo/getifaddrs - both architectures clean,
zero warnings. Full libc (29/29) and lowering (10/10) nextest profiles
pass; cargo fmt/clippy clean.
