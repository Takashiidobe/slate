# Classify C comments as leading, trailing, or detached in the parser

_2026-10-05 19:03:19_

slate-6cgg.1 (design: wiki/concepts/comment-placement.md).

Preprocessor: PPNodeKind::Comment carries a CommentLayout scanned from source text: placement (own line, after code, directive line), column, and follower (same-line comment, next-line comment, code, or separated by a blank line / directive / } / EOF). Conditional directives are looked through, so a comment above #ifndef X still leads the declaration inside. Comments after code on a line are now emitted after the line's code instead of before it. Comments on conditional-directive lines (#endif /* X */) are dropped.

Parser: ParserInput groups split at blank lines; a trailing group only absorbs own-line continuations at its column. CommentGroup gained attach (Leading/Trailing/Detached) and doc (/** /*! /// //!, not /**/ /*** ////). Chosen with the user: comments stay tagged siblings rather than owner fields on every node; owner is the next sibling (Leading) or previous (Trailing). Comments inside an item's tokens become Trailing siblings after it. ParameterDeclaration.comments holds parameter comments (inside its tokens, or Trailing after its comma). Enum bodies now keep a trailing comment on the last enumerator without a comma.

IR: ir::Comment { text, attach, doc } replaces Vec<String>; --show-comments prints 'comment <attach> [doc] "text"'. Parameter comments are forwarded to Module.comments until slate-6cgg.2 attaches them. Slate lowering updated for the type change only.

Fixture ir_comment_attachment.c; ir_comments.c and parser_token_annotations.c regenerated. comments_preserved_differential fails identically before this change (filed slate-m553).
