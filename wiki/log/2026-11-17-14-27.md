# slate-3amj.55 target_feature: AArch64 -march=armv8.x-a+feature units put #[target_feature] on every function

_2026-11-17 14:27:15_

- bead: slate-3amj.55
- kind: feature
- area: crates/slate/src/frontend/lowerer
- area: crates/slate-parser/src/target/aarch64_isa.rs
- target: aarch64

Outcome: an AArch64 unit built with -march=armv8.x-a+feature now puts the unit's features beyond the target baseline in #[target_feature] on every function it defines, as slate-3amj.54 did for x86. Inline asm and intrinsics that need dotprod, crc, rdm, ... now build.

Gap and why it mattered: AArch64 units kept only the target baseline (neon). NumPy's ASIMDDP/ASIMDHP dispatch units and kernel code built with -march=armv8.2-a+... put instructions in plain functions, and rustc's assembler rejects them.

Before (`-march=armv8.2-a+dotprod`):

```c
static int32x4_t dot(int32x4_t acc, int8x16_t a, int8x16_t b) {
  __asm__("sdot %0.4s, %1.16b, %2.16b" : "+w"(acc) : "w"(a), "w"(b));
  return acc;
}
```

rustc: `error: instruction requires: dotprod` (and `requires: crc` for crc32b).

After:

```rust
#[target_feature(enable = "rdm,crc,lse,dotprod")]
unsafe fn dot(...)
```

Implementation:
- slate-parser `AArch64Isa::enabled_beyond(baseline)` (target/aarch64_isa.rs) returns clang spellings of features beyond `AArch64Isa::baseline()`:
  - `v8.1a` for the version (QRDMX).
  - `fullfp16`, `fp16fml`, `complxnum`, `jsconv`, `fptoint`, and so on.
  - `crypto` expands to aes and sha2, plus sha3 and sm4 from v8.4.
- slate `unit_target_features` (lowerer/target_features.rs) maps them through `AARCH64_FEATURES`, which now maps one clang name to several rustc names:
  - `v8.1a` to rdm, `v8.3a` to fcma and jsconv, `v8.5a` to frintts. rustc's own v8.Na features are unstable.
  - `fullfp16` to fp16, `fp16fml` to fhm, `complxnum` to fcma, `fptoint` to frintts, plus rand, rcpc, bti, ...
  These also cover the arm_neon.h/arm_acle.h per-function `target(...)` names that used to be barriers.
- `rustc_features(family, name)` replaces `Tables::rustc_feature`.
- `AARCH64_UNSTABLE_FEATURES` (cssc, faminmax, fp8*, lut, mops, sme, sme2, sve2p1) drive the `aarch64_unstable_target_feature` crate attr. Stability was checked with the pinned rustc.

Fixture: crates/slate/tests/fixtures/aarch64/unit_isa_target_feature.c (sdot and crc32b asm, plus a function pointer to a featured function).

Limits:
- Feature-gated NEON/ACLE builtins (`vdotq_*`, `vqrdmlahq_*`, `vsha256hq_u32`, `vaeseq_u8`, `vcmlaq_f32`, `vrnd32xq_f32`, `__crc32b`) still have no lowering ("builtin without a lowering").
- float16x8_t vectors are rejected ("return type vector<f16, 8>").
- `+sha3` is not an accepted -march modifier.
- Pauth (paca/pacg) is not mapped.
- The baseline is the generic v8.0 one, so on darwin the functions repeat features the target already has (harmless).

See: slate-3amj.54 (x86), slate-dghn.58.
