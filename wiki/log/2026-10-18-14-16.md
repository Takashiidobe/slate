# slate-oreg.9: GNU aliases, function alignment, clrsb/parity, integer abs

_2026-10-18 14:16:27_

Promoted gcc-torture alias-2, alias-3, alias-4, align-3, builtin-bitops-1, 20021127-1, and fixtures.unsupported/alias_global.c.

- Aliases: a global with **attribute**((alias("t"))) whose target is a same-typed, non-alias definition in the TU now takes the target's Rust name (names.rs alias_target / global_names) and is skipped in declare(), so every access goes to the target static.
- main(int argc): main_wrapper now accepts arity 1 (alias-4).
- align-3 (slate-parser): **alignof** of a function designator returns the function's aligned() request, or 4 by default on clang (1 on gcc). record_function merges the requested alignment into the entity; types.rs function_alignment serves both the constant path and the sema path. typer.rs no longer measures storage for function operands of alignof.
- **builtin_clrsb/l/ll and **builtin_parity/l/ll go through the existing clrsbg/parityg lowering.
- abs/labs/llabs and their \__builtin_ spellings are lowered inline as wrapping_abs(). This matches clang, which always emits llvm.abs for these calls (even at -O0), so a function the TU defines with one of those names is never called. The extern declarations for them are dropped.

New fixture: fixtures/gnu_alias_alignment_builtins.c. FileCheck blocks changed: extern_decl, gnu_library_builtins (abs -> wrapping_abs), and parser gcc-torture align-3 for clang and gcc (expected error -> IR with const 256).
