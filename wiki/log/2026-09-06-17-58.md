# asm.rs enum refactor: target arch, register width, template modifiers

_2026-09-06 17:58:18_

Replaced string-literal matches in src/frontend/lowerer/asm.rs with typed enums per review feedback.

- rust_target_arch(&str) -> Option<&'static str> became a TargetArch enum with
  TryFrom<&str>, rustc_name(), is_x86(). Narrowed to the four arch families
  slate actually supports (x86/x86_64, arm/arm64, riscv32/64) instead of the
  full LLVM triple arch list.
- New RegWidth enum (Byte/Word/Dword/Qword) replaces raw u32 bit-count matches
  in X86Reg::sized_name, x86_flag_output_suffix, and rust_asm_register_modifier.
  sized_name is now total over RegWidth; fallibility (unsupported widths like
  i128) lives at the RegWidth::from_bits boundary instead of inside every
  register-name lookup.
- New TemplateModifier enum replaces matches!(modifier, Some("c" | "l")) in
  translate_asm_template.
- constraint_is_explicit_register now reuses parse_constraint_atoms /
  Constraint::FixedReg instead of duplicating the a|b|c|d|S|D letter set.

Deliberately left asm_operand_bits hardcoding pointers to 64 bits (wrong on
32-bit targets) -- filed as slate-3f8g.4.15.8 rather than bundled here, since
fixing it needs threading target pointer width into FunctionLowerer, which has
no triple/target field today.

All 9 pre-existing asm fixtures still pass unchanged (lowering profile).
