# add SSE (x) register class; scope y/q/Q/A

_2026-09-06 21:57:57_

slate-3f8g.4.15.6: implemented GCC's x constraint (SSE register), scoped
out y/q/Q/A after auditing real-world frequency via GitHub code search
(exact-case, x86 context, filtering 6502/ARM false positives from letter
reuse) rather than guessing.

x: real modern usage (cosmopolitan libc tinymath, toaruos libc). Cheap and
sound to add: AsmReg::Class(String) in the backend already accepts an
arbitrary class name, so "xmm_reg" needed zero codegen changes -- only a
new AsmRegConstraint::Sse case in asm.rs (parse_reg_constraint,
asm_reg_for_constraint, resolved_asm_reg_to_backend, reg_constraint_family).
wants_register_modifier already excludes it by default (no GPR-width
:e/:l/:r suffix applied to xmm placeholders).

y (MMX): real but rare/legacy hits (msieve, kvm-unit-tests, pm123 3DNow).
Blocked regardless of demand -- confirmed via rustc that mmx_reg can only
be a clobber, never bound as input/output.

q/Q (byte subset): actually the most-used of the four in real code, but Q
is always a/b/c/d while q is a/b/c/d in 32-bit mode and any GPR in 64-bit
mode -- needs target-bitness plumbing that doesn't exist in
FunctionLowerer today. Deferred to slate-3f8g.4.15.8 (bitness work already
planned there for the asm_operand_bits pointer-width bug).

A (edx:eax pair): rare (~4 hits, all the legacy rdtsc idiom); a genuinely
different lattice shape (one constraint, two tied registers), not a
letter-to-class mapping. Lowest priority.

Added tests/fixtures/asm_sse_register_operand.c. Full rewrites profile
(85 tests) passes.
