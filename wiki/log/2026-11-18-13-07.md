# slate-3amj.36.1 -freg-struct-return/-mregparm: MachineCodegen reg_struct_return/regparm reach rustc as -Zreg-struct-return/-Zregparm; --merge per-target rustflags via Cargo profiles

Outcome: i686 `-freg-struct-return` and `-mregparm=N` reach rustc as `-Zreg-struct-return`/`-Zregparm=N`, and `--merge` crates now carry per-target codegen rustflags through Cargo profiles.

Gap and why it mattered:
- `-freg-struct-return` was parsed and ignored. Rust code returned small structs through sret while C callers expected eax:edx, so a cdylib called from C crashed (dylink `abi_reg_struct_return`: "exit code differs: C=Some(0) Rust=None"). The kernel's i686 boot code builds with `-freg-struct-return -mregparm=3`.
- `--merge` built `Program` facts with `..Default`, so stack protector, sanitizer, and ABI flags of every target were dropped.

Before (i686, `-freg-struct-return`):
  struct pair { int a, b; }; struct pair make_pair(int, int);
  sema printed `-> sret<align=4>`, no rustflags, wrong ABI at runtime.
After:
  `machine [reg_struct_return];`, result `native_c`, Cargo.toml package rustflags
  `["-Zreg-struct-return", "-Cunsafe-allow-abi-mismatch=reg-struct-return"]`.

Implementation:
- slate-parser `MachineCodegen` gains `reg_struct_return` and `regparm` (from `target.abi.struct_return`/`default_regparm`), printed `reg_struct_return`, `regparm=N`.
- `sema/abi.rs` `forced_struct_return` (Registers, X86Cdecl) classifies the C result (`win32_returns_in_register`, gcc empty record -> sret, clang -> void) and rustc's (`rust_single_float_element`, every 1/2/4/8 byte -> register); `native_c` when equal, else the C shape.
- `lowerer/functions.rs` `function_abi` rejects a defined-record result that is still `sret`/`coerce` under reg_struct_return.
- `main.rs` `crate_call_abi_rustflags` adds `-Zreg-struct-return`, `-Zregparm=N`, `-Cunsafe-allow-abi-mismatch=...` (needed: target modifiers mismatch prebuilt std). Units that disagree are an error.
- `--merge`: `merge.rs` `codegen_facts` builds per-target `Program` facts into `Merged.target_codegen`. `ProfilePlan` gives the host (or first) target the dev/release package rustflags and every other target with different flags `[profile.<triple>] inherits = "release"` plus package rustflags. Each profile adds `--cfg slate_profile_<name>`; a `compile_error!` per target cfg fails builds with the wrong profile.
- rustc refuses to compile a build script for an x86_64 host with these flags (`-Zregparm=N is only supported on x86`), and package rustflags beat `build-override`, so such crates have no `build.rs`: the Linux `nostart-stop-gc` link arg becomes `-Clink-arg`, long double C shims are an error.
- `update_filecheck.py` regenerates merge fixtures with the merge profile (it ran `slate`, which filters out `merge_filecheck`).

Fixtures:
- `crates/slate-parser/tests/fixtures/{clang,gcc}/linux/i686/abi_convention_flags.c` (REG, REGPARM prefixes)
- `crates/slate/tests/fixtures.dylink/abi_reg_struct_return/`
- `crates/slate/tests/fixtures.merge/target_rustflags.c` (`// merge-target-args:`)
- `crates/slate/tests/fixtures.unsupported/i686/reg_struct_return_divergent.c`

Limits: `-Zregparm` is passed unchecked; rustc diverges for `long long` and small record args and the inreg sret pointer (slate-3amj.36.3). Indirect calls through function pointers to divergent-result functions are not rejected. `--merge` still does not carry the `runtime` (no_std) fact.

See: rust-lang/rust#145694, #161027, #131749, #116973; slate-3amj.36.3, slate-3amj.59.
