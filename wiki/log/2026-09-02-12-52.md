# Recover out += 1 from lowered accumulate statements

_2026-09-02 12:52:01_

Two corpus-wide rules, both prerequisites for the ideal switch-arm shape.

slate-25or -- constant temps in binary-operand position. LateInlineTemps
refused `let _v1: i32 = 1; out = out + _v1;` because
`expr_is_type_anchored(Value(I64(1)))` is false and `is_top_level_use` demands
the consumer's value be a bare Var, which a Binary is not. InlineConstArgTemps
covers the same constants but only in call-argument position. The anchor was
already on the Let (`ty: Some(Prim(I32))`) and simply never consulted. Added
`consumer_pins_type`/`binary_operand_pinned`: an un-anchored constant may be
inlined when its use is a binary operand whose sibling operand is type-anchored,
since inference pins it from the sibling. Shl/Shr are excluded -- a shift's
operand types are independent, so the sibling pins nothing.

slate-v4go -- `compound_assign::recover`. Nothing in rules/ constructed a
CompoundAssign; every reference was a pattern-match on ones the lowerer emitted.
New rule folds `Assign { target, Binary { op, lhs, rhs } }` with `lhs == target`
into `CompoundAssign`. Restricted to arithmetic/bitwise ops and to targets that
are simple places (var, field, deref, index with pure subscript) so the place is
not re-evaluated with side effects. Only lhs is matched: `x = y - x` is not
`x -= y`.

Together: `let _v2: i32 = 10; let _v3 = out; out = _v3 + _v2;` becomes
`out += 10`. rewrites profile: 92 passed, 7 skipped, no runtime diffs.
Only switch_default_middle_fallthrough was regenerated; other fixtures' REWRITES
blocks are now stale but are still silent no-ops, so nothing fails yet.
