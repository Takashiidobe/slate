# slate-8ge7.2.7 macro_fold: split value expansion's hoisted run folds back into a StatementExpression block template (NEXT, NEXT_FROM, BOTH, PICK, STMT_EXPR lift; hoist_split_region 40 -> 18)

Outcome: a value macro (or argument hole) whose effects sema hoisted into statements now lifts as a block template instead of staying inline as `hoist_split_region`; macro_values.c recovers 22 of 40 split sites and macro_dispatch_locals UPDATE_CHECK lifts.

Gap: since slate-8ge7.2.3 the hoister ignores macro boundaries, so `r += NEXT()` (`#define NEXT() (*cursor++)`) emitted its temporaries before the statement and the expansion was rejected (13/110 merge, 15/238 zlib in slate-8ge7.2.2).

Before:

    let __v0: *mut i32 = unsafe { cursor };
    unsafe { cursor = __v0.add(1); }
    r += unsafe { *__v0 };

After:

    macro_rules! NEXT { () => { {
        let __v: *mut i32 = unsafe { cursor };
        let __v2: *mut i32 = unsafe { __v.add(1) };
        unsafe { cursor = __v2; }
        unsafe { *__v }
    } }; }
    r += NEXT!();

Implementation:
- slate-parser `Hoister::value` records `Module::macro_hoisted_runs[root] = HoistedRun { statements, value }` when it splits a root or hole (the ids of `out[before..]` and of the hoisted value).
- `frontend::macro_fold::fold_hoisted_runs` (before the BeforeMacroKeep passes, outer runs first): finds the run's statement list, requires the run to be contiguous and free of control flow and static declarations, the only statements between it and the consumer to be declarations, the value to sit outside any Conditional/Logical in the consumer's operand, every run declaration to be referenced only in the run and the value, and the consumer's other operands plus the gap to commute with the run (no effects, no reads of bindings the run writes, and no memory or non-local reads when the run writes memory or calls). Then it replaces the value with `StatementExpression { run, value }`, moves the root's `macro_values` wraps onto it, copies the C type, and drops `hoist_split_region` when every split of the expansion folded. An empty run (root replaced) only moves the wraps.
- `unfold_rejected` after `kept_expansions` splices the run back (before the first gap statement) for expansions macro_keep still rejects, so inline output stays as before.
- decl-init: `first_write` checks `DefUse::only_writes(variable, 1)` instead of `straight_line_write`, whose statement count rejected a block value's inner statements (`let mut sum = 0; sum = NEXT_FROM!(local);`). `straight_line_write` removed.

Fixtures: fixtures.merge/macro_values.c (ASSIGN_TO, BOTH, BUMP_AND, EITHER, MIN, NEXT, NEXT_FROM, PICK, STMT_EXPR now lift), macro_dispatch_locals.c (UPDATE_CHECK).

Limits: template bodies keep sema's temporaries (`let __v2 = __v.add(1); $p = __v2`) until slate-8ge7.2.8. A hole that folds passes a block argument (`BOTH!(zero != 0, ({ let v = hit; hit = v + 1; v }) != 0)`). Still inline: discarded expansions (`NOTHING(x)`, statement-level splits through `Hoister::discard`), nested conditional splits (`MIN(MAX(k++, 1), 5)`), and consumers with calls in other operands. `ASSIGN_TO(&t, 42)` renders `{ *$p = $v; $v }` because sema reuses the constant for the result.

See: slate-8ge7.2.2, slate-8ge7.2.3, slate-8ge7.2.8, slate-5exy.15 (pre-existing hoister order bug found while probing).
