# slate-5q63.22.1 backend::asm: asm!/global_asm! templates built as typed AsmTemplate (x86/aarch64/arm instructions, directives, operand modifiers) instead of format! strings

_2026-11-18 15:30:33_

- bead: slate-5q63.22.1
- kind: feature
- area: crates/slate/src/backend/asm
- area: crates/slate/src/frontend/lowerer/asm.rs
- area: crates/slate/src/frontend/lowerer

Outcome: every asm! / global_asm! template slate emits is now a typed `backend::asm::AsmTemplate` (instructions, directives, operand references with per-arch modifier enums) instead of a format!-built String; user C asm stays passthrough text with typed operand references.

Gap and why it mattered:
`rust_ast::InlineAsm.template` was a String. lowerer/asm.rs, lowerer.rs (ifunc/alias/.weak/.drectve), globals.rs (register reads) and selectany.rs built it with `format!("{{{slot}:{modifier}}}")`, escaped C braces by hand, and several sites used implicit positional `{}` that silently depended on operand order. Modifiers were bare chars, so a wrong letter for the target compiled fine and only failed in rustc.

Before (synthesized lines, ifunc):
    template: format!(".globl {symbol}{hidden}\n.type {symbol}, @gnu_indirect_function\n.set {symbol}, {{}}")
    template = format!("mov {{{slot}:r}}, rbx\n{template}\n...")

After:
    AsmTemplate::new().with(Directive::Globl(symbol.into())).with(Directive::Set { symbol, value: Operand::new(0).into() })
    template.wrap([syntax.line(x86::Inst::mov(scratch, rbx))], [syntax.line(x86::Inst::mov(rbx, scratch))])

Implementation (crates/slate/src/backend/asm/):
- mod.rs: `AsmTemplate` (lines joined by "\n"; push/with/prepend/append/wrap), `AsmLine` {Passthrough, X86{syntax, inst}, AArch64, Arm, Directive, Mention{arch, operand}}, `Operand {slot, modifier}`, `Modifier` {X86, AArch64, Arm}, `Passthrough` (Text/Operand fragments, braces escaped only at print), `Condition`.
- x86.rs: `Syntax` {Intel, Att}; `Inst` {Mov, Xchg, Movd, Movq, Set, Fld, Fstp, FstpSt} take Intel-order dst/src and the printer reverses and adds `%` for AT&T; `Reg` {Gpr(Gpr, Width), St, Mm}; `Mem {size, base}`; `Modifier` {Byte, HighByte, Word, Dword, Qword, Xmm, Ymm, Zmm}.
- aarch64.rs: `Inst` {Mov, Cset, MsrNzcv}, `Reg` {X(n), Sp}, `Modifier` {W, X, B, H, S, D, Q, V}.
- arm.rs: `Inst::Mov {condition, dst, src}`, `Reg` r0-r15, `Arg::Imm`, `Modifier` {LowHalf e, HighHalf f}.
- directive.rs: `Directive` {Globl, Weak, Hidden, Protected, Type, Set, Section(Drectve | Comdat), Text, Ascii, P2Align, Zero, Data, Label}.
- lowerer/asm.rs: helpers return `Operand`/`Passthrough`/`AsmLine`; `AsmNames::text` writes fragments; spills, msr nzcv, rbx save/swap, reserved-register moves and flag-output setcc/cset/mov are typed instructions. `register_global` returns `RegisterGlobal` (typed register) instead of "rsp".
- interproc `mentions_symbol` and merge's global-asm key use the rendered template.

Output changes (checked by translating 296 asm/alias/ifunc/selectany fixtures for x86_64, i686, aarch64, armv7 and x86_64-msvc before and after; only these differ):
- positional `{}` is now explicit `{0}`, `{1}`, ... (ifunc `.set`, aliases, `.weak`, selectany `.long {N}`, register reads `mov {0}, rsp`).
- AT&T rbx swap prints `xchg %rbx, {N:r}` instead of `xchg {N:r}, %rbx` (same instruction; operands now follow the one AT&T reversal rule).
FileCheck blocks for those fixtures were regenerated.

Limits: user-written C asm is not parsed into instructions (by design); `gpr_name`/`explicit_reference` still spell passthrough register names as text. Condition codes are a `&'static str` newtype from the parser's `=@cc` table, not per-arch enums.
