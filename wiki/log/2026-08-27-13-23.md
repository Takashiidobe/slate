# worklist engine: item-scoped rescan pilot on zero_init

_2026-08-27 13:23_

Started `slate-y0qs.3` per [rewrite-worklist-engine.md](../concepts/rewrite-worklist-engine.md).
Scoped this pass to core infra + one pilot rule rather than migrating all 65
passes: full migration needs the SCC/unification phase for cross-function
rules first, and touches every pass's fixpoint semantics at once.

Added `TouchedItems` (`src/backend/query/item.rs`): `Plan::apply` now reports
which item indices its accepted edits actually touched (`None`/`All`/`Items`),
derived from each `AnchoredEdit`'s existing `Anchor` (already carries
`item_index` for Binding/Definition/Expression/Function/Statements; `Program`/
`InsertItems` anchors have no stable item index, so they conservatively mark
`All`). `ItemPlanBuilder::add_rule_scoped` filters `query_items`'s candidate
list to that scope before running any matcher/case, so scoped rounds skip
rule-matching work entirely for unaffected items instead of re-deriving facts
for the whole program. `add_rule` is now `add_rule_scoped(.., None)`.

`to_fixpoint_program_with_facts_scoped` (`src/backend/mod.rs`) threads the
previous round's `touched` set into the next round's scope; round 1 is
unscoped (need a full walk to seed). This targets the ~90% "rule-matching
cost" bucket from `slate-y0qs.1`'s profiling, not the 9.5% `set_program`-diff
bucket `slate-y0qs.2` already declined to chase.

Wired `ZeroInit` (`direct`/`deferred`) and `EarlyInlineTemps`/`LateInlineTemps`
(both call sites) through it -- all four are `Binding`-domain rules, always
function-scoped, so per-function touched-scoping is sound.
`SLATE_DIFF_FIXTURE=zero_init` differential test passes unchanged.

Found unrelated pre-existing baseline breakage while running the full
`rewrites` profile: 9/118 test binaries fail, confirmed present at 4281c7e2
(before this work) via a throwaway worktree, e.g.
`gcc_torture_supported_tests_match_c` (E0609 on `__slate_anon_N`/
`__bitfield_0` -- stale field names after `anonymous_structs` retypes a
spilled-parameter struct to a tuple struct). Filed `slate-mmiy`, left unfixed
per explicit instruction -- not in scope for y0qs.3.

Verified no regression: ran the full `rewrites` profile (`--no-fail-fast`) on
this branch and against the 4281c7e2 worktree side by side -- both fail the
same 9 test binaries (one extra failure on one run,
`ctype_libc_fixup_stays_off_when_a_sibling_tu_changes_locale`, reproduced as
flaky under parallel `--no-fail-fast` execution and passes in isolation and
on rerun; not a regression). `generated_differential`'s failure is a macOS
cross-target-check missing `libc`, unrelated to this change.

Next: extend `add_rule_scoped` to more fixpoint-shaped, function-scoped
passes (`stdio`, `heap_ownership`, `buffer_cursor`, `option_box_locals`) --
the other slow candidates `slate-y0qs.1` flagged. Anything that reasons across
function boundaries (`string_params`, `ptr_len`) must wait for the
SCC/unification phase in the design doc; per-function touched-scoping isn't
sound for those.
