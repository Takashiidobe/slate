# GCC optimize pragma: Ofast and non-cumulative restarts

_2026-10-24 10:11:53_

slate-nip8: #pragma GCC optimize "Ofast" now applies fast-math plus the speed level. Probed against gcc: a later non-Ofast level in the same list restores the math flags from before Ofast; explicit fast-math survives a later level; no-fast-math after Ofast clears it. Probing also showed each optimize pragma restarts from the requested command-line options (math flags and level), not from the previous pragma, so 'fast-math' then 'no-math-errno' leaves only errno, and a level is lost when a later pragma names none. The earlier cumulative behavior (slate-1vcv and the original math tracking) was wrong; fixed. The restart state keeps -fassociative-math un-gated by trapping math (MathOptions::requested_associative_math) while reset_options returns to the resolved command line. pp/math.rs: PragmaMath::{restart,apply_option,apply_level}, before_ofast. Optimization::from_level no longer accepts 'fast'. Fixture: gcc/linux/x86_64/pragma_optimize_ofast.c (-O0, -O2, -fassociative-math, and -fno-trapping-math runs, name sets identical to gcc -E). Parser gate 8369/8369, no existing fixture changed. Docs: preprocessor.md.
