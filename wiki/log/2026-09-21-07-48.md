# Prototype scope and Object/Function redeclaration merging

_2026-09-21 07:48:45_

slate-parser-dyd.12. The bead grouped two fixtures under one diagnostic,
`duplicate ordinary name`, but they had unrelated causes.

parser_declaration_lifetimes.c was prototype scope leaking. C11 6.2.1p4 ends a
parameter list's names at the `)`, and three passes push that scope
independently -- names.rs, types.rs and module.rs -- all three of which
leaked. A file-scope `typedef double T` was destroyed by a later, unrelated
`int f(enum { T = 2 } v);`.

The part that cost the most time: module.rs resolves parameters a *second*
time, to build Parameters, and types.rs::define_tag is memoized on AST TagId,
so the second resolution declared no names at all. Scoping the first
resolution therefore lost the enumerators outright for a definition, whose
parameter scope has to reach into the body. define_tag now re-declares the tag
name and enumerators on the memoized path: the body is resolved once, but its
names belong to whichever scope the specifier is written in. module.rs wraps a
prototype's parameters in `scoped`, and a definition's in one scope shared
with the body.

20031112-1.c was the Object/Function split in bind_ordinary. `extern __inline
int __finite(double)` binds Function; `extern __typeof(__finite) __finite
__asm__(...)` has no parameters in its declarator, so it binds Object, and the
kinds had to match to merge. That distinction is syntactic -- names.rs runs
before any type exists -- so redeclares() now treats the two as one kind and
leaves type agreement to merge_redeclaration, which still rejects `int x; void
x(void);` and `int f(void); double f(void);` with better messages than the
duplicate-name one it replaces.

Added TypeResolver::with_scope to match the lowerer's scoped().
