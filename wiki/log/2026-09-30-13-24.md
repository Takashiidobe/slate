# Checker owns redeclaration merging; lowering reads declared_types

_2026-09-30 13:24:51_

slate-parser-ygrj.6.

- Checker declare_object records the merged type after each declaration in TypeResolver::declared_types (keyed by declarator or definition NodeId), and it now emits the conflicting-types warning. The warning is stashed in item_diagnostics, so -Werror=conflicting-types now fails the checker (parse too), as other checker warnings do.
- Lowering no longer calls merge_redeclaration. The function-definition, declare_global and declare_function paths call Lowerer::redeclared, which declares the recorded type. The previous-type plumbing is gone. The point-in-time type is kept because the fact is recorded per declaration node.
- A temporary cross-check (old lowering merge vs recorded) over the full suite found one disagreement: int parameters(int T, int a[sizeof(T)]) {..} was recorded as int(int, int[*]), because the checker resolved a definition's function type before declaring its parameters. Lowering got int[4] only via a memoized typer fact. Fix: Checker::function declares parameters first. Their tag() also runs under provisional_extents, which keeps gcc-torture 20020210-1.c (VLA struct parameter, a GNU extension) Unimplemented rather than rejected.
