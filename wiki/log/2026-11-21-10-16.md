# slate-8ge7.8 slate-analysis def_use: counted_loops moved from sema onto per-function DefUse; IR drops For.counted

_2026-11-21 10:16:08_

- bead: slate-8ge7.8
- bead: slate-8ge7.5
- kind: feature
- area: crates/slate-analysis
- area: crates/slate-parser/src/sema
- area: crates/slate-parser/src/ir
- area: crates/slate/src/frontend/lowerer

Outcome: counted-loop recognition moved out of slate-parser sema into slate-analysis, built on a new per-function def-use (def_use::DefUse); the IR no longer carries `For.counted`, and lowering reads `UnitFacts::counted_loop(for_id)`.

Gap and why it mattered: counted_loops was a lowering-only fact computed in sema and printed into every IR dump (slate-8ge7.8). Its private `Uses` walker (writes/escapes per binding) was the def-use that slate-8ge7.5 asked to generalize, and the next consumers (inline_temps, dead_store for slate-8ge7.9) need the same facts plus positions.

Before: `sema/counted_loops.rs::annotate` set `Statement::For { counted: Some(CountedLoop) }`; IR printed `counted: %i in 0..read<i32>(%n)`; `lower_counted_for` read the field.

After: `slate_analysis::CountedLoop` keyed by the `for` statement's BindingId per unit; `Statement::For` has no `counted` field; printer, visitor, grammar line removed. Rust output unchanged.

Implementation:
- `crates/slate-analysis/src/def_use.rs`: `DefUse::of(body)` numbers statements in pre-order (a subtree is a contiguous range); records each use as (position, Read | Write | Escape) per binding; loop and switch body ranges; labels, asm/SEH/OpenMP positions, case->switch positions; `ordered = false` on goto, computed goto, label, label address. Queries: `escapes`, `touched_in(binding, range)`, `body(loop_id)`, `structured(range)`.
- `crates/slate-analysis/src/counted_loops.rs`: same rules as before; the body checks are range queries on the function's single DefUse instead of a fresh `Uses` walk per `for`.
- `slate_parser::sema::fold_integer` exposes `fold::integer` for the `<=` bound check.
- pointer.rs no longer walks `counted.start`/`end` (they were clones of IR values, walked twice).

Verification: for all 186 parser fixtures that printed `counted:` at HEAD, a temporary stderr dump of the new facts gave the same count of counted and inclusive loops per file (openmp.c files match per DEFINES config; 8 non-linux va_list_layout copies skipped, their linux copy matched). Parser fixtures regenerated: only `counted:` lines removed. parser profile 9329/9329.

Fixture: `crates/slate/tests/fixtures/for_range_rejected.c` (ported from the deleted parser fixture ir_counted_loops_rejected.c as a runtime differential); accepted shapes stay in `for_range_counted.c`.

Limits: "case of a switch outside the body" has no runtime fixture: jumping into a for body skips the index initializer, which is UB in C. Unordered functions (goto/labels) are slate-8ge7.22.

See: slate-8ge7.5, slate-8ge7.8, slate-8ge7.22, wiki/concepts/slate-analysis.md#def-use, wiki/concepts/ir/control-flow.md#counted-loops.
