# Implement FreeBSD pthread (libthr) and synchronization ABI

_2026-08-31 08:19:27_

Implemented slate-sfzn.10.6. Headline finding: unlike glibc/NPTL (fixed
byte-array opaque types) and Darwin (fixed opaque structs with a __sig
signature field), every FreeBSD libthr pthread type except
pthread_once_t/pthread_key_t is a plain pointer to an incomplete struct
(typedef struct pthread_mutex *pthread_mutex_t; etc, for
pthread_t/attr_t/mutex_t/mutexattr_t/cond_t/condattr_t/rwlock_t/
rwlockattr_t/barrier_t/barrierattr_t/spinlock_t -- all 8 bytes, verified
sizeof against the oracle for both architectures). The kernel allocates
and owns the pointee, so the "opaque storage size/alignment" concern the
ticket raised is basically moot for FreeBSD -- it's just a pointer.
pthread_key_t is plain int. pthread_once_t is the one real aggregate:
struct{int state; pthread_mutex_t mutex;}, 16 bytes, sizeof-verified.

Because every lock is a pointer, static initializers are trivial:
PTHREAD_MUTEX_INITIALIZER/COND_INITIALIZER/RWLOCK_INITIALIZER are all
NULL (kernel lazily allocates on first use), PTHREAD_ONCE_INIT is
{0, NULL}. PTHREAD_ADAPTIVE_MUTEX_INITIALIZER_NP is the sentinel
(pthread_mutex_t)1.

Mutex-type enum starts at 1 not 0: ERRORCHECK=1, RECURSIVE=2, NORMAL=3,
ADAPTIVE_NP=4, with PTHREAD_MUTEX_DEFAULT aliasing ERRORCHECK (not NORMAL
like Darwin). PTHREAD_STACK_MIN reuses the same per-arch
machine/_limits.h __MINSIGSTKSZ derivation as MINSIGSTKSZ from 10.5:
2048 on x86_64, 4096 on aarch64.

sem_t (bits/freebsd/semaphore.h) is a real 16-byte value type (not a
pointer, and not glibc's 32-byte struct or Darwin's 4-byte int):
struct{uint32_t _magic; struct{volatile uint32_t _count; uint32_t
_flags;} _kern; uint32_t _padding;}, sizeof-verified. SEM_VALUE_MAX is
INT_MAX, not Darwin's 32767.

sched.h: FreeBSD's real sched.h is nearly empty, pulls SCHED_*/
sched_param from sys/sched.h. Numbering starts at 1 (SCHED_FIFO=1,
SCHED_OTHER=2, SCHED_RR=3), distinct from both Linux's 0-based numbering
and Darwin's own values. struct sched_param is just {int
sched_priority;}, no reserved padding.

New libc-shim/freebsd-pthread-headers.txt manifest and
freebsd_pthread_header_manifest_compiles_for_x86_64_and_aarch64 test with
sizeof static asserts for every pthread/sem_t/sched_param type and every
constant value checked.

Verified end-to-end: slate translate + cargo check --target
{x86_64,aarch64}-unknown-freebsd against generated Rust with real libc
crate, fixture exercising pthread_create/join, mutex lock/unlock on a
PTHREAD_MUTEX_INITIALIZER mutex, pthread_once, and sem_init/wait/post/
destroy, both architectures -- compiles clean modulo the same benign
opaque-struct improper_ctypes warnings already present for Darwin's
__dirstream. cargo fmt/clippy clean; nextest --profile libc 28/28,
--profile lowering 10/10, no regressions.
