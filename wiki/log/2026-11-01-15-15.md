# Lift macros containing return

_2026-11-01 15:15:01_

slate-f2zu.9.5.12.10: return crosses macro_rules, so macro_keep no longer rejects it, and a body with one lifts. zlib: 49 to 51 of 58 macros lifted (ERR_RETURN 1024, FLUSH_BLOCK 2688 expansions per distinct compile).
Item::MacroRules gains value and returns. value replaces the old convention that a trailing Stmt::Return meant a value template, which would have printed a real return as an expression. returns is set while lowering a Return for every open site, so it covers nesting and excludes returns inside a hole. Codegen wraps a returning template in a block so a tail call in a non-void fn parses: without it rustc reports macro expansion ignores keyword return. The template key gets a tag only for a statement template ending in return, so no existing name changes.
A function ending in a macro that returns gets no fallback return, and ends_in_jump sees through MacroExpansion so such a switch arm does not fall through.
Decided: a break or continue leaving the macro stays inline, as the bead says, now reported as break_out_of_macro rather than control_transfer. A break inside the macro's own loop already lifted. zlib has 0 such uses. Passing the label as $l:lifetime compiles in rustc but label-removal and loop-conversion rules cannot see it; filed as a P3 under the epic.
Decided: a function calling a returning template keeps its C signature, because return_alias_for and return_buffer_candidates assume they see every return. This is defensive: with the pin disabled I could not produce a miscompile or build failure, since the Box lift did not fire even on plain code (the size lowers to wrapping_mul) and the alias probe stayed raw. Its visible cost is parameter lifts, e.g. hidden_null_return keeps p: *mut i32 instead of &mut i32.
zlib all 16 targets with SLATE_CHECK_MACRO_TEMPLATES=1: no mismatch; projection 2048 checked, 0 mismatches; signatures 676/0. cargo check passes on x86_64 linux, i686 linux, aarch64 linux and x86_64 windows, default features.
