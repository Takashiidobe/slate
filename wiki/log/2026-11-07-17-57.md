# Accept K&R definitions in gcc C23 modes

_2026-11-07 17:57:03_

slate-parser-cxg.16: GCC 16 still accepts old-style (identifier-list) definitions in -std=c23/gnu23/c2y (warning -Wold-style-definition), so StandardFeatures::for_compiler (standard_features.rs) now upgrades identifier_list_definitions from Rejected to Extension for the gcc flavor. clang flavor still rejects in C23 (slate-parser-47s.4). Calls stay unprototyped, same IR as gnu17.
Also: K&R parameter declarations now accept trailing attributes ('int x __attribute__((unused));'), mirroring prototype parameters, in parse_kr_parameter_declarations (parser/stmt.rs); this fixed the 'expected ; in K&R parameter declaration' cases (builtins-30, attr-invalid, complete-port).
Migrated 10 gcc.dg fixtures to suites/gcc-dg/gcc/linux/x86_64: sms-2, builtins-30, ifelse-1, uninit-A, unused-1, sibcall-6, uninit-10, uninit-A-O0, wtr-label-1, attr-invalid.
Remaining reproducers are unrelated to the C23 gate (they fail under gnu17 too) and are filed: slate-78pa.2 (calls checked against K&R definition param types: warn-1, pr111922, pr60647-1, torture/pr104825, winline-10), slate-78pa.3 (Warray-parameter-2 parse).
