# Splice backslash, horizontal whitespace, newline under gcc and clang

_2026-10-10 15:32:29_

slate-parser-cxg.7.14.

gcc and clang treat a backslash followed by spaces, tabs, form feeds or vertical tabs and then \n or \r\n as a line splice (with a 'backslash and newline separated by space' warning). This holds anywhere in phase 2: macro bodies, string literals, // comments. Lexer::with_offset now computes the splice length through splice_len, which skips that whitespace when StandardFeatures::whitespace_line_splice is set. It also applies after a trigraph ??/.

MSVC does not splice there: cl /EP keeps the backslash and cl /Zs reports C2017 (unknown escape sequence), so the feature is off for the msvc flavor.

Fixtures: {gcc,clang}/linux/x86_64/pp_line_splice_whitespace.c (space, tab, \f, \v, space before \r\n, in a macro, a string and a // comment; matched against gcc/clang object symbols), error/msvc/windows/x86_64/line-splice-whitespace.c. Fixtures with trailing whitespace were written from a script because the Write formatter hook may strip it. Migrated gcc.dg cpp/backslash.c (c89) and cpp/Wtrigraphs-2.c (c99).
