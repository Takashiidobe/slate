# VLA type names in expressions

_2026-09-19 14:24:20_

slate-parser-lh7.2.24. A type name inside a function body now captures its non-constant array bounds where the expression is evaluated. New ValueKind::Capture { id, extent, value } (printed capture<%id>(extent, value)) binds a size_t extent before its body; Hoister::value lowers it to a synthetic Statement::Temporary at that point, and effects() treats it as effectful so ?: and && arms branch and evaluate the bound only in their arm. It never survives normalization, so like statement_expression it is left out of ir-grammar.

Lowerer::capture_extents is split: extents(declarator) -> Vec<(BindingId, Value)> does the walk, and capture_extents maps those to Temporary statements for declarations/parameters. Expression side: type_name_extents (only when in_function, so file-scope bounds still fail constant evaluation) and with_extents wrap the result, outermost bound first.

- sizeof(type): captures kept only when the named type is itself a VLA (C11 6.5.3.4p2). sizeof(int (*)[n]) folds to 8 and does not evaluate n; its size_of metadata string still names the dropped extent id.
- Casts: every bound captured, before the operand, matching clang EmitVariablyModifiedType ordering. (void)(int (*)[next()])p leaves only the call.
- _Alignof of a VLA type or object used to fail in qualified_storage; fixed_element() peels VariableArray to the innermost fixed element.

Compound literals (title of the bead) are a Place, not a Value, so Capture does not reach them: split to lh7.2.35.
