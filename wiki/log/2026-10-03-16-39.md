# Pointer lattice keeps reassigned, stored, and null-compared params raw

_2026-10-03 16:39:04_

slate-dghn.20: interproc pointer_lattice lifted raw pointer params to &T/&mut T even when the lifting was invalid, and the use rewrite produced casts in place position (E0070 'node as *const Node = ...') or mutability mismatches (E0308).

Three classification gaps in ClassifyCtx, all in pointer_lattice.rs:
- A param reassigned in the body (node = node->next) was never recorded. New PointerFact bit 'reassigned' (local only, not merged across call sites) forces a raw representation, so the param keeps its pointer type.
- A tracked pointer stored through a place (*ipp = i2p) was not an escape; the value side of a non-Var Assign now observes escape. This also avoids handing out &T for a pointer later written through.
- is_null_like missed the frontend's std::ptr::null::<T>() / null_mut::<T>() calls, so 'if (0 == n)' never marked n nullable and the comparison became null_mut() == (n as *const i32).
