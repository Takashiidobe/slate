# share host-target filecheck prefixes across runners

_2026-09-06 11:13:02_

`host_gnu_arch_suffix` and the host prefix table lived in `differential.rs`,
so only single-fixture runs honored `LOWERING-X86_64-GNU` /
`REWRITES-AARCH64-GNU` blocks. Every such block in `tests/fixtures.multi` and
`tests/fixtures.library` was inert: `support::filecheck::directive` only
matches `COMMON`, `COMMON-<PROFILE>` and the bare profile prefix plus a
directive suffix, and `check_project_modules` passed no extra prefixes.

Hoisted into `tests/support/filecheck.rs` as `host_gnu_arch_suffix`,
`host_prefixes(profile)`, plus `has_host_checks` and
`check_generated_rust_for_host` wrappers. `cross_tu.rs` (which every project
runner funnels through, including the library, host-only and raw-lower
tests), `gcc_dg_suite.rs`, and `differential.rs`'s Default flavor now share
one definition. The previously-dead project blocks pass as written.

`update_filecheck.py` can now generate them: `update_project` used
`profiles[0][2]` as the environment for every profile, so `--target` on a
project would have emitted one target's output under both prefixes. It now
translates once per distinct environment and picks the matching modules per
profile, so `--target PREFIX=TRIPLE` works for projects. Verified on a scratch
copy of `shared_long_double`: the x86_64 block asserts
`value: LongDouble([0; 10])` where the aarch64 block asserts `value: 0.0f128`.
