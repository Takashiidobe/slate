# slate-dghn.56.6 switch lowering: declaration in one case used by a later case was scoped to its match arm (E0425 not_taken)

_2026-11-14 09:04:30_

- bead: slate-dghn.56.6
- kind: bug
- area: crates/slate/src/frontend/lowerer/switch.rs
- area: crates/slate/src/frontend/lowerer/statements.rs

Outcome: a declaration under one switch case that a later case uses now lowers to one binding declared before the match, so cpython instrumentation.rs no longer fails with E0425 on not_taken.

Symptom: cargo check of translated cpython, src/instrumentation.rs: cannot find value `not_taken` in this scope (branchesiter_next). Not a rewrite: it comes from lowering.

Reproducer:

    switch (kind) {
    case 0:
        int taken = next + 1;
        return taken * 2;
    case 2:
        taken = next + 5;   /* same scope in C: the switch body is one block */
        return taken * 3;
    }

Before: `0 => { let mut taken: i32 = next + 1; ... } 2 => { taken = next + 5; ... }` (E0425).
After: `let mut taken: i32 = 0; match kind { 0 | 1 => { taken = next + 1; ... } 2 => { taken = next + 5; ... } }`.

Cause: lower_switch (frontend/lowerer/switch.rs) lowers each SwitchArm body on its own, so a top-level ir::Statement::Let in one arm became a `let` scoped to that match arm. The fallthrough case loop (lower_case_loop) had the same problem.

Fix: FunctionLowerer::shared_case_lets finds top-level Lets in an arm whose binding is mentioned (MacroStructureVisitor::binding over a clone of each arm) in another arm. Each one is lowered once before the switch as the same Let without its initializer (zero init), wrapped with the switch in a Stmt::Scope, and recorded in FunctionLowerer::switch_lets. lower_statement_node lowers a Let in switch_lets as lower_assignment of its initializer (or nothing). byref, auto_init and VLA declarations are not hoisted.

Regression test: crates/slate/tests/fixtures/switch_case_shared_declaration.c (match path and fallthrough path). Also promoted gcc-dg gcc-only asan__use-after-scope-switch-2.c.

Limits: a goto-dispatch function already hoists every local, so this path only runs for structured switches.
See: slate-dghn.56.5 (same cpython check run).
