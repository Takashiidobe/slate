# peel_casts ptr-chain widening + directive-filecheck race fix

_2026-09-01 23:04:49_

dx0m.4 (peel-casts follow-ups, needs type oracle).

Added a lightweight var-type oracle: Arena::var_type(name) resolves from
param_types, then the defining Let/LetIf declared ty, then a Let init cast ty.
peel_casts now threads a HashMap<Ident,Type> (built from arena.reads(id)) so the
pointer chain (v as A) as B collapses when v is a pointer/int-typed Var — the case
excluded in v1 because a bare Var could be a Rust reference. Proven by
peel_casts_ptr_chain.c: inline_temps folds a cast temp into write_bytes producing
(_v1 as *mut c_void) as *mut u8, now collapsed to _v1 as *mut u8.

Floats stay untouched: is_ptr_or_int_type/is_int_prim exclude F16..F128, and the
chain branch requires both layers be thin raw ptrs. (x as f32) as f64 and int
narrow-then-widen are never dropped.

Identity-cast removal (dx0m.4 half 1) is subsumed by inline_temps/mem2reg upstream —
no surviving `v as T` where v:T reaches final output (libc sinks/temp folding kill
it first), so no fixture to lock it; left out deliberately.

Also fixed a pre-existing flaky race: check_directive_output keyed its FileCheck
scratch dir only by fixture name, so generated_directive_filecheck and
directive_translated_fixtures_compile_for_current_host (parallel_map) both translating
arch_targets.c as separate nextest processes raced on checks-N.txt → "no check strings
found". Scratch dir now suffixed with pid + atomic seq.
