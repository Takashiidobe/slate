# Support __NSConstantString and __builtin___CFStringMakeConstantString

_2026-10-12 08:27:49_

slate-parser-v74.1.17. clang predeclares __NSConstantString and lowers __builtin___CFStringMakeConstantString on every target; slate had 'unknown type name __NSConstantString' and no typing rule for the call.

- pp/mod.rs predeclared_typedefs: for the clang flavor, injects struct __NSConstantString_tag {const int *isa; int flags; const char *str; long length;} and its __NSConstantString typedef from <built-in> (size_t logic split into size_type_declaration).
- names.rs registers __NSConstantString as a builtin typedef; the registry's Opaque constant_CFString maps to it, so the builtin returns const __NSConstantString *.
- CustomBuiltin::CfString: the typer requires a plain ASCII string literal (clang's 'CFString literal is not a string constant' error otherwise); Lowerer::cf_string emits an internal global {class ref, 1992, str, length} and returns its address. __CFConstantStringClassReference is an extern int[] global created on first use. Non-ASCII (UTF-16 CFString) and the swift runtime ABIs are not modelled.
- Predeclaring the tag shifts anonymous tag numbering in clang-flavor names dumps: control_body_scopes.c regenerated (180 line renumberings only).
- Fixtures: clang/linux/x86_64/cfstring_builtin.c, error/clang/linux/x86_64/cfstring_builtin_nonliteral.c, migrated suites/clang-test/clang/windows/x86_64/CodeGen__cf-runtime-abi.c (objc config only). Clang accepts all and gives the same non-literal error text. Parser 8255/8255.
- Docs: ir/builtins.
