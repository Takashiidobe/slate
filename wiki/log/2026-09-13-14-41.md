# Structured GNU asm statement AST

_2026-09-13 14:41:44_

Replaced Stmt::Asm(String) token dump with Stmt::Asm(GnuAsm) (slate-parser-25m.4).

- GnuAsm { qualifiers: Vec<Span<AsmQualifier>>, template: Span<String>
  (verbatim, concatenated), operands: Option<AsmOperands> }. None = basic
  asm; its template is never split (gcc/clang emit it verbatim).
- AsmOperands: pieces, outputs, inputs, clobbers, labels. Grammar mirrors
  clang ParseStmtAsm.cpp: ': outputs : inputs : clobbers' then ': labels'
  only allowed (and required) for asm goto.
- Template pieces mirror clang GCCAsmStmt::AnalyzeAsmString at llvm
  58dd40228595: %% %{ %} %= plus %| (gcc accepts it, clang does not).
  %N and %[name] index outputs++inputs++labels like both compilers;
  indices past the operands become Label(i - operand_count). Letter
  modifiers are kept (Operand{index, modifier}) because clang allows any
  letter and gcc gives %a0 meaning; %cc aliases to c like clang. %l on a
  non-label is an error (gcc rejects it).
- Deviation from the issue text: clobbers are Memory | Cc | Unwind |
  Register(Register), since clang's isValidClobber accepts cc and unwind.
- Constraints split on ','; modifiers = + & % - anywhere; {reg} ->
  HardRegister(decode_register), digits or [output name] -> Matching,
  otherwise Letters(rest).
- Reachability unchanged: asm goto already falls into the non-terminating
  default arm. Sema does not track label uses, so nothing to mark.
- Unknown % escapes, out-of-range numbers, unknown/empty/unterminated
  symbolic names are errors in every flavor for now; gcc gating is 25m.5.
- Shared asm_string helper now backs both declarator asm labels and
  statements.
