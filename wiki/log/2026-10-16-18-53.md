# FileCheck for every single-file suite, whole-program default, id variables

_2026-10-16 18:53:05_

slate-5vj0.2 follow-up.

- FileCheck runs inside support::translate_slate, so fixtures, i686, unsupported, gcc-torture, gcc-dg, and c-testsuite all enforce checks. Prefixes: CHECK plus the -target= triple (host when absent).
- update_filecheck.py: no @check-fn markers means whole-program checks (CHECK first line, CHECK-NEXT/EMPTY after), as the old render_checks did. Fixtures with handwritten CHECK lines and no markers are left alone. Default selection is every supported single-file fixture; a Suite table maps each bucket to its work dir, test, and selector env var.
- Unstable identifiers become FileCheck variables scoped per check group: old families (__v, arg, anon_*, _unnamed_at_, __slate_alloca_frame, __state, __dispatch*, __switch*) plus __t, _v, __join_, __slate_{break,continue,slot,storage,compound,anon}_N, __SlateRecordN, and <c_name>_<id> renames detected against the C source's identifiers. A name present in the C source stays literal.
- Ids are TU-wide (one extra struct + prototype moved __slate_break_16->22, __v18->24); the regenerated buffer_return_lift checks still pass with that prefix.
- Crate root in string literals (assert/__builtin_FILE) becomes {{.*}}.
- Bug found: slate-parser lowering copies every C comment into the Rust, so check blocks leaked into output (checks could match their own copies; output depended on the block). comment_text now drops @check-fn, SLATE-FILECHECK-*, and CHECK/<A-B-C triple> directive lines; the harness errors on generated Rust carrying an active directive.
- Non-UTF-8 fixtures (gcc-torture 20000227-1) are read lossily by the harness and round-tripped with surrogateescape by the tool.
