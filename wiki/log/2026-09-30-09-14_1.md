# reachability: keep the declaration that first names a tag inside a member

_2026-09-30 09:14:22_

Reachability pruning (slate-parser-6x05.7) split one tag into two when the declaration that first named it at file scope was unused.

curl's api.h: struct Curl_eapi_guard { struct Curl_easy *data; } is the first
mention of Curl_easy, and it has file scope (C gives a tag first named in a
member declaration the enclosing scope). A later prototype takes
struct Curl_easy *. The guard struct is never used, so pruning dropped it,
and the prototype's struct Curl_easy became prototype-scoped: a distinct
type. Every call then failed 'incompatible pointer types' (15 curl TUs).
The flattened preprocessed file passed because everything is in the main
file there, so nothing is pruned.

Reachability::new recorded only top-level struct X; / definitions (and a
top-level reference specifier) as introducing a tag name. FileScopeNames now
walks a declaration's specifier into record members and nested definitions,
collecting tag references and definitions and nested enumerators, for both
declarations and function definitions. The first decl that names a tag is
then kept whenever that tag name is reached.

Fixture: clang/linux/x86_64/member-tag-file-scope.c (+ .h), which fails with
two incompatible-pointer errors without the fix. Wiki: ir/pipeline.md
reachability section.

curl: 354/359 TUs clang accepts now reach IR (was 340 after dyd.67, 249 at
the 2026-09-29 baseline).
