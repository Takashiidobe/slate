# slate-f2zu.14 e2e.py linux: translate-project OOM on 3005 kernel TUs, shard per kbuild directory (69 crates), check-stage error clusters

_2026-11-14 17:08:13_

- bead: slate-f2zu.14
- kind: feature
- area: tools/corpus/e2e.py
- flavor: clang

Outcome: the linux corpus run reaches the translate and check stages by splitting the kernel into 69 per-directory crates; all 69 translate and 5 pass cargo check.

Gap: `translate-project` parses every unit to IR before translating any (parse_slate_units in crates/slate/src/main.rs) and keeps all modules for the project rewrites. Kernel TUs retain ~60 MB of IR each (60 kernel/ TUs: 3.7 GB before translation; kernel/sched/core.c alone peaks at 812 MB end to end), so 3005 TUs need ~180 GB. The single-crate run was OOM-killed on a 29 GB machine.

Before: `e2e.py linux --until translate` ran one translate-project over all units and died.

After: `TranslationOnly.shard_units` (linux: 120) makes e2e.py split units by source directory (shard_units): a directory over the limit splits by its next path component, and children under a quarter of the limit are packed into `<dir>__packed`. Each shard gets shards/<name>/compile_commands.json, its own translate-project crate, and its own cargo check (args.jobs // 4 in parallel, separate CARGO_TARGET_DIR). Reports: shards.json (units per shard), translate.md, check.md (rustc errors clustered with identifiers, numbers and alloc ids normalized).

Units compiled with `-S` (asm-offsets.c, bounds.c, rq-offsets.c generate headers and define main) get one bin crate each. A shard whose translate-project fails with "defines main" (arch/x86/boot, the real-mode setup image) is retried without --crate-type, so it becomes a bin crate.

Cross-unit analyses (signature lifting, shared types, comdat owners) now see one shard at a time; calls between shards stay extern "C", as the kernel linker resolves them.

Result 2026-11-14: translate 69/69 ok in 917 s. check 5/69 clean, 24682 errors. Clusters filed:
- .17 __ADDRESSABLE `(void *)(uintptr_t)&sym` round trip in static initializers: 22424 errors, 60 shards
- .18 overloadable `__acquire_ctx_lock` duplicates: 1728 E0428 + E0308 at call sites
- .19 const pointer arithmetic (LIST_POISON, &sysctl_vals[1]): 98
- .20 `__va_args` not in scope: 94
- .21 packed field references E0793: 49
- .22 inline asm register and type rejections: 16
- .23 remaining errors

Limits: rustc reports borrowck and const-eval errors only after earlier phases pass, so counts will move as clusters are fixed. A streaming translate-project (summaries first, then per-unit translation) would remove the memory limit but was not done.
