# Skip a leading UTF-8 byte order mark

_2026-10-10 15:41:29_

slate-parser-cxg.7.16.

A file starting with EF BB BF lexed the BOM into the first token (pr33415.c: 'cannot combine int with previous declaration specifiers'). gcc, clang and cl (/Zs under Wine) all accept a BOM at the start of the main file and of an included header, so there is no per-flavor gate.

Lexer::with_offset starts scanning after a leading U+FEFF. It is skipped there, not in decode_source_bytes, so byte offsets and spans still count the three bytes and match the file on disk.

Fixtures: {gcc,clang}/linux/x86_64 and msvc/windows/x86_64 pp_utf8_byte_order_mark.c (written from a script so the file starts with the BOM; a #define on the first line checks that a directive right after the BOM is still a directive). Migrated gcc.dg cpp/pr33415.c (c89). Wiki: preprocessor.md pipeline.
