# Carry asm operand width and register views

_2026-09-26 23:12:27_

slate-parser-25m.14. Each AsmOperand records width (storage bits of its type) and the IR printer shows it as 'width N'.
GCC width modifiers resolve to AsmRegisterView on the piece: x86 b/w/k/q/h/x/t/g, AArch64 b/h/s/d/q/w/x; printed as %k0(32), %h0(high8).
Verified with gcc and clang: an unmodified x86 reference prints at the operand width (%dil for char) while Rust {0} prints the full register, so x86 emission needs a Rust modifier. AArch64 prints the full x/v register in both compilers, which matches Rust.
A tied input folded into its output keeps its own width on x86: gcc prints "=r"(char) : "0"(int) as %dil / %edi, so that reference becomes %0(32). clang rejects size-mismatched ties.
x widens to ymm_reg or zmm_reg for 256- and 512-bit operands (new YmmReg class); both compilers print %ymm/%zmm.
The Rust modifier depends on the class an alternative picks, so its table is in ir-spec and on the .15 notes rather than computed here.
