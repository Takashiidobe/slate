# slate-parser-cxg.39 parser: vector_size on function definition return type ignored (finish_declaration skipped)

_2026-11-18 09:42:39_

- bead: slate-parser-cxg.39
- kind: parser
- area: crates/slate-parser/src/parser/decl.rs

Outcome: a leading `__attribute__((vector_size(N)))` on a function definition's return type now yields the vector type, as it already did on a declaration.

Symptom: both flavors rejected the definition with "conversion between vector types of different size"; clang and gcc accept it. Seen across gcc.dg pr110915-*.

Reproducer:
```c
typedef int vs __attribute__((vector_size(8)));
#define vector __attribute__((vector_size(8)))
vector signed g(vs r) { return r; }
```

Cause: the function-definition branch of the declaration parser (crates/slate-parser/src/parser/decl.rs) returns the FunctionDefinition before `finish_declaration`, which is the only place that folds `specifiers.attributes` into `specifiers.ty` via `TypeSpecifier::with_type_attributes`. The definition kept a plain `int` return type, while the earlier prototype got `vector<i32, 2>`.

Fix: apply `with_type_attributes` to `specifiers.ty` in the definition branch, the same two lines `finish_declaration` runs.

Regression test: crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/vector_size_function_definition.c.

Limits: the gcc.dg pr110915-* files were not migrated (gcc.dg sources are not on this machine).
