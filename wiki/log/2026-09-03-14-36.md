# compat.c fixture: clang parse-time rejection, dup of pcek.12

_2026-09-03 14:36:57_

slate-6v25.7 triage: tests/fixtures.chibicc/unsupported/compat/compat.c fails
before CIR lowering ever runs -- clang -emit-cir rejects it at parse time:

- compat.c:3 `int restrict x` -- bare implicit-int param with restrict:
  "restrict requires a pointer or reference"
- compat.c:9,24 `volatile x;` / similar -- "type specifier missing, defaults
  to int" under -Wimplicit-int, which is a hard error on ISO C99+ (this repo
  builds against a clang where it's not just a warning).

This is legacy K&R implicit-int syntax rejected by clang's own parser, not a
slate/CIR gap -- no AST or CIR is ever produced, so there's nothing for
slate to lower differently. Root cause is a duplicate of slate-pcek.12
(legacy/GNU C laxness rejected by modern clang defaults), which already
tracks the broader question of whether to add -Wno-error= flags to slate's
clang invocations. Marked slate-6v25.7 blocked rather than deleting the
fixture -- keeps the corpus entry and its provenance, promote via git mv if
pcek.12 ever decides to relax parsing.
