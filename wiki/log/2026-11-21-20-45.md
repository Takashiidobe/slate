# slate-8ge7.24.10.6 structure-goto: hoist Let declarations used after a forward block or backward-goto loop instead of bailing

_2026-11-21 20:45:06_

- bead: slate-8ge7.24.10.6
- kind: feature
- area: crates/slate-analysis/src/transform/structure_goto.rs

Outcome: structure-goto no longer bails when a declaration inside the range it wraps (forward labeled block or backward loop) is used after the range; it hoists the declaration in front of the wrapper instead.

Gap and why it mattered: `movable` refused any range whose `Let` was read after the label, so `if (a) goto skip; int b; b = a * 3; skip: b = a;` stayed a goto and went to lower_dispatch. The same applied to loop-local declarations read after a backward-goto loop.

Before (forward.c used_after, IR after --passes=all):

    if ne(a, 0) goto skip;
    let b: i32;
    write(b, mul(a, 3));
    label skip: write(b, a);

After:

    let b: i32;
    block %0 {
        if ne(a, 0) break %0;
        write(b, mul(a, 3));
    }
    write(b, a);

Implementation (crates/slate-analysis/src/transform/structure_goto.rs):
- `movable` returns the set of declarations used after the range (None when it must bail); `declarations` records whether each one is `hoistable`.
- `hoistable`: non-automatic storage moves whole; automatic needs not const/constexpr/byref, and an initializer only for scalar types (bool, numeric, pointer), which `extract` splits into an uninitialized `Let` (keeping its NodeId) plus a `Write` in place. Temporaries, cleanup and variably modified locals still bail.
- `hoist`/`extract` lift the `Let`s (also from inside `Label` bodies) in front of the range. Forward hoisting runs first; loop-hoisted declarations go between the labeled block and the loop, so the block does not end their scope.

Fixtures: fixtures.transforms/structure-goto/forward.c (used_after, initialized_after), backward.c (loop_local). goto_residual_region.c changed only its dispatch state number.

Limits: decl_init does not re-fuse the split `Let` with a `Write` that ends up inside the block; that needs a write that dominates every use.
