# slate-f2zu.14.23 inline_temps::const_arg: numeric temp inlined into addr_of! in typecheck template (E0745 address of temporary)

_2026-11-14 18:54:31_

- bead: slate-f2zu.14.23
- kind: rewrite
- flavor: clang
- area: crates/slate/src/backend/engine/rules/inline_temps.rs

Outcome: `inline_temps::const_arg` no longer inlines a numeric temp into an
`addr_of!` operand, so kept `typecheck` templates keep their dummy local.

Symptom: linux i915_gem\*.rs, xprt.rs, mcast.rs, route.rs:
`addr_of!(0u64 as $type)` cannot take address of a temporary (E0745, 9 errors).

Reproducer:

```c
#define typecheck(type,x) ({ type __dummy; typeof(x) __dummy2; \
  (void)(&__dummy == &__dummy2); 1; })
static unsigned long next(const struct request *req, unsigned long now) {
  unsigned long timeout = now + req->timeout;
  if (time_before(timeout, req->deadline)) return timeout;
  return req->deadline;
}
```

`typeof(req->deadline)` is `const unsigned long`, so `__dummy2` lowers to an
immutable `let __v3: u64 = 0` in the template.

Cause: `expr_arg_pos` looked through `Expr::AddrOf`, so the single-use immutable
temp counted as a cast argument and `addr_of!(__v3)` became
`addr_of!(0u64 as $type)`. Outside templates the local has a user name, so
`is_temp_name` kept the rule from firing.

Fix: `expr_arg_pos` returns None for `Expr::AddrOf`. `Ref` still looks through,
since `&0` is promoted.

Regression test:
crates/slate/tests/fixtures/macro_typecheck_const_typeof_local_address.c
