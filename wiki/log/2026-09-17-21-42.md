# Loosen tag ids and decl indices in FileCheck expectations

_2026-09-17 21:42:55_

`slate-parser-45s`. `tools/update_filecheck.py` gains `loosen_ids()`, a
post-pass beside `loosen_system_provenance()`. Follows the same rule that
`711caf5f` set for provenance line numbers: loosen what tracks something
outside the fixture, keep exact what a wrong value would make a real defect.

Tag ids and decl indices count declarations across the whole translation
unit, system headers included, so adding one declaration to a header
restamps every fixture that reads it. That is what broke
`gcc-dg/pr85388-4.c` and `gcc-dg/split-4.c`: both expected `tag[25]` against
a local header snapshot that now yields 24.

**A tag id is a cross-reference, not just a label**, which is why this isn't
a blanket `{{[0-9]+}}`. Each distinct `TagId` value binds a FileCheck numeric
variable on first sight (`[[#TAG0:]]`) and reuses it afterwards
(`[[#TAG0]]`), so a declaration still has to name the tag it named before —
only the absolute number stops mattering. `anon_local_struct.c` is the case
that shows why: two anonymous structs, two declarations, and the fixture
still pins which references which. Verified negatively by repointing one
reference at the other variable — the fixture fails.

The `tag[N]` and `decl[N]` labels do become plain `{{[0-9]+}}`. `render.rs`
formats `tag[{}]` from `tag.value.id.0`, the same field the `id: TagId(..)`
line below already checks, so their agreement was tautological. Decl indices
are referenced nowhere, and the `-NEXT` chain already pins order and
completeness.

Regenerated every fixture: 2377 files, 17913 insertions and 17913 deletions —
a 1:1 line rewrite in which every added line is one of the three expected
forms, so no content drifted in under cover of the reformat. Full suite
passes with nothing moved aside.
