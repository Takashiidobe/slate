# Add preprocessor trace for configuration planning

_2026-10-30 18:55:41_

slate-mbr2.1.4: slate-parser pp --trace and Parser::preprocess_file_traced record why each token exists. New pp/trace.rs: TokenTrace (enclosing conditional arms plus macro events) on Code and Pragma nodes, Conditional/Arm for every #if with state and macros read, MacroEvent for each #define/#undef, Expansion including empty ones (Assert without ZLIB_DEBUG), and PreprocessTrace::dependencies for the transitive closure with roots. Off by default: trace stays None and the vectors stay empty.

ZLIB_DEBUG tested first, then a soundness check: for each of 15 zlib TUs and 9 features, diff real preprocessor output with and without the feature and require every changed source line to be attributed to it. The first run missed 1 of 2903: inflate.c:526 'if (' exists only under NO_GZIP, because '#ifndef NO_GZIP / #define GUNZIP' was skipped so GUNZIP read as plainly undefined, and the other configuration has no such line. Fix: a #define or #undef in a skipped group is now an event, and later reads and uses of that name depend on it. This also links unrenamed tokens to Z_PREFIX-style renames. Arms that were never evaluated now contribute their names as reads.

Result: 0 unattributed of 56,192 changed lines across x86_64 linux single/all/pairs, x86_64 windows, armv7 and aarch64 musl (tools/corpus/trace_attribution.py). Over-flagging: lit-mem 2 of 47, zlib-debug about 10%. The check is per source line, not per token. Traced tokens matched plain pp on 300 runs (10 targets, 15 TUs, base and all features).

Not recorded: what a header in a skipped #include would define, #include targets computed from macros, __has_include results, inclusions dropped by guards. slate-mbr2.1.6 needs a new entry point that returns an AST and a trace together. The edit hook also removed two existing comments in expand.rs. Fixtures: preprocessor_trace_{nested,macros,undef,include,skipped}.c. Parser profile 8942 passed, slate profile 25 passed, 5 skipped.
