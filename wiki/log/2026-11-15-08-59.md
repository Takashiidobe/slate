# slate-f2zu.14.34.8 sema mark_folded_branches: dead sizeof switch/if arms instantiated asm for the wrong width (movl (%rax),%r14 in \_\_get_user_size)

_2026-11-15 08:59:48_

- bead: slate-f2zu.14.34.8
- kind: bug
- area: crates/slate-parser/src/sema/folded_branches.rs
- area: crates/slate-parser/src/ir/module.rs
- area: crates/slate/src/frontend/lowerer/control_flow.rs
- area: crates/slate/src/frontend/lowerer/switch.rs
- area: crates/slate/src/frontend/lowerer/types.rs
- target: x86_64

Outcome: a constant-condition `if`/`switch` carries `[folded=V]` in the IR, and
slate keeps every arm but lets rustc drop the dead ones like clang does, so
`__get_user_size`/`__put_user_size` no longer instantiate `movl (%rax),%r14` and
all 10 linux shards lose their `invalid operand for instruction` errors.

Symptom: `cargo build --release` of the kernel shards failed in LLVM's asm
parser on `movq %ebp,(%r12)`, `movl (%rax),%r14`, `cmpw $0,%al`. The bead blamed
operand-width modifiers; the widths were faithful to the C. The asm sits in the
dead arms of `switch (sizeof(*ptr))`: in `case 4: "movl %[umem],%[output]"` the
output is `"=r"(x)` with `x` a `u64`, so `%r14` is right for the operand and the
arm is only valid because clang (`EmitSwitchStmt`/`EmitIfStmt`) never emits it.
Dead arms that call undefined functions (`__get_user_bad()`) fail to link the
same way at `-O0`.

Reproducer:

```c
unsigned long load(unsigned long *p) {
  unsigned long r;
  if (sizeof(*p) == 4) asm("movl %1,%0" : "=r"(r) : "m"(*p));
  else asm("movq %1,%0" : "=r"(r) : "m"(*p));
  return r;
}
```

Plain `if`/`match` on `size_of::<u64>()`: rustc `-O0` instantiates the dead asm
and fails. `-O3` folds a plain `match`, but not inside the asm-goto
`__slate_state` loop, which is why the kernel failed even at `-O3`.

Cause: no IR fact said the condition was constant, so lowering emitted runtime
branches. `DeadArms` in `sema/asm_constants.rs` already pruned folded `if`s, but
only in functions with unresolved `"i"` operands, and never `switch`.

Fix:

- `ir::Statement::If { folded: Option<bool> }` and
  `Switch { folded: Option<Number> }`, set by `sema/folded_branches.rs`
  (`mark_folded_branches`, after `constant_asm_operands`) using `folded_integer`
  (`integer_with_objects`). Not set when the dead `if` arm holds a label or an
  outer switch's case, or when the switch body holds a label or another switch's
  case (`JumpTargets::of_switch`). Printed as `[folded=…]`.
- Structured lowering keeps all arms. `FunctionLowerer::const_layout` (set by
  `lower_folded`) makes `lower_layout_query` emit
  `const { core::mem::size_of::<T>() }`, which MIR folds at `-O0`. Only the leaf
  is wrapped because `Expr::ConstBlock` is opaque to rewrites, so
  `8 != (… as u64)` stays rewritable.
- The state machine (`control_flow.rs`) turns a folded `Branch`/`Switch` into
  `Node::Jump` to the live target (`switch::folded_case`), so states reached
  only from dead arms are unreachable and dropped.

Regression tests:
`crates/slate/tests/fixtures/x86_64/asm_folded_size_dispatch.c` (asm-goto
switch, `if` chain, plain switch, `__bad_size` in the dead arms; failed first),
`crates/slate-parser/tests/fixtures/clang/linux/x86_64/ir_folded_branches.c`
(folded and unfolded cases, label and Duff negatives).

Churn: 325 parser FileCheck fixtures gain only `[folded=…]`; 7 slate fixtures
change one `size_of` leaf to `const { … }`.

Shards: arch_x86_kernel, drivers_gpu_drm_i915(**packed), lib, fs, io_uring,
net**packed, mm, net_core, sound retranslated and clean-built: 0 invalid-operand
errors, 8/10 build; arch_x86_kernel and lib only have the slate-f2zu.14.34.9
symbol-substitution errors left.

Limits: a dead arm inside the fallthrough-switch case loop
(`lower_fallthrough_switch`) is still reachable through the case variable; only
the scrutinee gets the const leaf. A folded condition without a layout query
that rustc cannot fold itself (address compares) still emits both arms.

See: slate-f2zu.14.34.9, slate-dghn.54, wiki/concepts/ir/control-flow.md.
