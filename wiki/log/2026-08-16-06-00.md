# chibicc/torture fixture batch: static muts, copysign, bitint overflow

_2026-08-16 06:00:00_

- **`484120e7`**: static (file-scope) mutable globals whose type ends in a flexible array member (`struct { int n; int data[]; }`) weren't sized correctly — added `widen_flexible_array_members` to scan CIR global ops for a `sym_type` that implies a flexible tail and grow the emitted Rust array to match the actual initializer length.
- **`228d549d`**: indexing into a `static mut` array previously always went through `ArrayPtr`+`.add(index)` unconditionally; added `global_array_ptr_expr` to compute the correct raw pointer expression directly for statics instead of taking a reference into the `static mut` first (referencing into a `static mut` is more UB-prone than computing a raw pointer to it).
- **`158496e3`**: fixed a long-double fixture where a floating literal appearing as the operand of a binary operator wasn't recognized as long-double-typed by `collect_long_double_init_values` (`frontend/c_ast.rs`), causing it to default to double precision.
- **`f1ca78d8`**: added saturating-arithmetic lowering (C's saturating add/sub semantics on fixed-point/certain intrinsics) in `frontend/lowerer.rs`.
- **`16194bc5`**: added overflowing-arithmetic (checked-and-flag, not saturating) variants for `_BitInt(N)` operations — 144-line rework of `frontend/lowerer/arithmetic.rs`, alongside the checked-overflow work from the frontend-fixup batch a few days earlier (`7871b04f`).
- **`b61a23d1`**: fixed `copysign`/`copysignl` handling — `collect_long_double_init_values` previously only matched `ImplicitCastExpr` wrapping a `CallExpr`, missing bare `CallExpr` nodes, and didn't handle negated floating literals correctly (85-line `c_ast.rs` rework to track sign separately from magnitude).
- **`5a1ddde8`**: `frontend/lowerer/storage.rs`'s copy-non-overlapping detection (used to decide whether a struct/array copy can lower to `copy_from_slice`/similar vs. needs `copy` semantics) was firing too eagerly and misclassifying some overlapping cases as safe.
- **`b9c30924`**: handled anonymous structs containing arrays as a field.
- **`466b92fc`**: fixed identifier-name collisions with Rust reserved keywords (e.g. a C variable literally named `type` or `move`) in `frontend/lowerer.rs`.
- **`e496f5da`**: handled casting a function pointer to an integer type (`memory.rs`, 33 lines) — C allows `(intptr_t)some_function`, which needs explicit `as usize`-style lowering since Rust `fn` pointers don't implicitly cast to integers.
- **`32b8b8bf`**: handled non-UTF8 bytes when reading C source files (`api.rs`) — some corpus fixtures contain non-UTF8 string/char literal bytes that previously caused a hard parse failure instead of being carried through as raw bytes.
- **`05b58b68`**: ignored the IEEE `_Complex` division conformance cases (`ieee__cdivchkd.c` and siblings) since they link against libgcc/compiler-rt and produce host-toolchain-dependent results rather than a portable reference answer — not something slate's C-vs-Rust differential testing can meaningfully check.
- **`d18c10c3`**: continued the chibicc-specific fixture pass started the same day, working through cases unique to chibicc's own coding style rather than the general gcc-torture/c-testsuite corpora.
