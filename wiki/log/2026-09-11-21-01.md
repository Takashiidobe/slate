# Fix single-line struct/union/enum body parsing (slate-parser-qwy)

_2026-09-11 21:01:02_

parse_tag_definition() only scanned nodes[1..] for a tag body's closing '}', so struct/union/enum bodies written entirely on one physical line (e.g. 'struct Point { int x; int y; };') failed with 'expected }' or fell through to 'expected ;'.

Fixed the same way as the earlier single-line function-body bug: added a same-line fast path using matching_brace() on the token stream of nodes[0]. When the closing brace is found in the same node, split the body tokens on top-level ';' (struct/union fields) or ',' (enum enumerators) via a new split_top_level() helper, and parse each segment directly via parse_declaration_tokens/const_expr rather than going through the PPNode-per-line field/enumerator parsers.

Also extracted build_tag_alias_decl() to share the typedef-alias/trailing-name decl construction between the new same-line path and the existing multi-node path.

Added tests/fixtures/single-line-tag-body.c covering a plain single-line struct, an enum, and a typedef'd struct with trailing alias name, regenerated via tools/update_filecheck.py --in-place.

Verified: cargo build (no warnings), cargo test (fixtures_are_filechecked passes).
