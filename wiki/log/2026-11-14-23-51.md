# slate-f2zu.14.34.4 translate-project: freestanding crate root gets #![no_std], #[panic_handler] calling C panic(), panic=abort, slate-support without the hosted feature; no build.rs for LLVM-intrinsic externs

_2026-11-14 23:51:07_

- bead: slate-f2zu.14.34.4
- kind: feature
- area: crates/slate/src/main.rs
- area: crates/slate/src/frontend/c_shim.rs
- area: crates/slate/vendor/slate-support
- area: crates/slate/src/frontend/support

Outcome: translate-project emits a no_std crate when every unit is freestanding
(Runtime::Core): #![no_std] on the crate root, a #[panic_handler] that calls the
C panic() when a unit declares one (else loops), and panic = "abort" in both
profiles; and no crate gets a build.rs just for LLVM-intrinsic externs.

Gap and why it mattered: kernel shards are linked into vmlinux, which has no
Rust std, no unwinder, and no host C compiler output. Generated crates had a
hosted root, unwinding panics, and 53 of 72 slate-linux shards had a build.rs
compiling an empty slate_long_double.c (just `#define _GNU_SOURCE`) with the
host cc.

Before (library of -ffreestanding units declaring
`void panic(const char *fmt, ...)`):

```rust
#![allow(non_camel_case_types, non_snake_case, non_upper_case_globals, rustdoc::all)]
#[path = "ring.rs"]
mod __slate_unit_ring;
```

After:

```rust
#![no_std]
#![allow(...)]
#[path = "ring.rs"]
mod __slate_unit_ring;
mod __slate_panic {
    unsafe extern "C" { fn panic(fmt: *const core::ffi::c_char, ...); }
    #[panic_handler]
    fn __slate_panic_handler(_: &core::panic::PanicInfo) -> ! {
        unsafe { panic(c"rust panic\n".as_ptr()) };
        loop {}
    }
}
```

plus `panic = "abort"` under [profile.dev] and a new [profile.release].

Implementation:

- `rust_ast::CrateAttr::NoStd` (codegen prints `no_std`).
- `write_project_crate` (crates/slate/src/main.rs): `freestanding` = every
  program's `runtime` is Core (a mixed crate stays std, since Core output is
  valid under std). Adds NoStd to the lib.rs or main.rs root and a
  `__slate_panic` SupportModule from frontend/support/panic_c.rs or
  panic_loop.rs; `declares_c_panic` looks for a top-level `panic` Fn or extern
  decl whose first param is a pointer. `crate_manifest` takes `freestanding` for
  the abort profiles.
- `c_shim::collect_item_shim_names` skips `llvm-intrinsic` extern blocks:
  `__slate_intrinsic_*` link names render no C, yet made `has_shims` true.
  Hosted crates benefit too.
- slate-support gains a `hosted` cargo feature (default on) that owns the
  optional `libc` dependency; everything libc-typed (the `pub use libc::*`
  re-export, putc/getc/errno_location, stdin/stdout/stderr, off_t and the 32-bit
  glibc lseek family, time_t) moved to vendor/slate-support/src/hosted.rs behind
  it. Freestanding crates depend on slate-support with
  `default-features = false`, so they never build libc, which defines nothing
  for target_os = "none". A stray slate_support::printf in a freestanding crate
  now fails to compile instead of linking libc (slate-3amj.56 removes the
  remaining sources). Single-file fixtures keep the default.
- When no shims are needed, a stale build.rs / src/slate_long_double.c from an
  earlier translation into the same directory is removed.

Fixture: crates/slate/tests/fixtures.library/freestanding_crate_root (staticlib,
-ffreestanding, driver defines panic()).

Limits: each staticlib carries its own panic handler and core, so linking
several shard staticlibs into one image will duplicate rust_begin_unwind
(slate-f2zu.14.34.6 has to pick one handler or link rlibs into one staticlib).
The fixture crate builds for x86_64-unknown-none with -Zbuild-std=core, but
kernel code model, soft-float and relocation flags are still slate-f2zu.14.34.5.
A -ffreestanding project unit that includes host libc headers still emits
slate_support:: calls (slate-3amj.56) and will not compile. Units that do need C
shims (long double, variadic trampolines) still get a host-cc build.rs.

See: slate-f2zu.14.34.3, slate-f2zu.14.34.5, slate-f2zu.14.34.6.
