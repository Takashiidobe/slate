# Check symbol signatures across units in --merge

_2026-10-30 20:27:33_

slate-mbr2.1.7: translate-project --merge now fails if a symbol shared between units has incompatible signatures in any valid feature assignment of a target (backend/link/signatures.rs). Each compile's definitions and declarations are reduced to a signature that expands by-value types by layout and names pointees. Two variants conflict when an assignment agrees on their common features and is not an invalid combination. Accepted as compatible: unprototyped declarations, unsized extern arrays, pointers to opaque records, __SlateAlign wrappers on definitions, noreturn vs void. Fixtures: fixtures.merge/signature_mismatch.c (new // merge-expect-exit: directive), signature_compatible.c. zlib, 10 targets, 1860 compiles: 468 shared symbols, 0 mismatches, 60s. The first run reported 3 false positives from alignment wrappers on _dist_code, _length_code and z_errmsg. Limits: a third unit's #error can make a reported assignment impossible; same-name pointees are not compared by content.
