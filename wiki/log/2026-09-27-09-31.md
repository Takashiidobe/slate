# Plan clang/test MS-mode sweep, probe MSVC headers

_2026-09-27 09:31:48_

Filed epic slate-parser-v74: a three-way sweep of the MS-mode C tests in clang/test, comparing slate against clang-cl (clang --target=*-windows-msvc, the primary target) and cl.exe. Sub-epics: v74.1 for clang-cl gaps, v74.2 for MSVC-only gaps. v74.4 is the sweep tool task.

Header probe first: each of 33 standard and Windows headers was included from a one-line file, with the x86_64 sysroot. Every CRT header fails in both slate flavors; clang-cl and cl.exe accept them. The blockers, in the order they are reached:
- vadefs.h unsigned __int64 (v74.1.1)
- vcruntime.h __pragma (v74.1.2)
- winnt.h __ptr64 / __unaligned / __forceinline (v74.1.3)
With those replaced by -D macros, the CRT, intrin.h, windows.h and winsock2.h all parse.

Other findings:
- The clang flavor on an msvc target gets no CRT/SDK include dirs, because sysroot.rs keys the layout on the flavor (v74.1.4).
- The msvc flavor never defines __STDC_VERSION__ under -std (v74.2.1).
- ../slate-sysroots runs xwin unpinned. It installed CRT 14.44 with an older UCRT: no tgmath.h, and threads.h uses the undefined _UCRT_DISABLE_CLANG_WARNINGS. That is skewed from the msvc-wine oracle (14.51, 10.0.26100.0) (v74.3).

The sysroot directory layout itself is fine: clang finds every header given its four include directories.
