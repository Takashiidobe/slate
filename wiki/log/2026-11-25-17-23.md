# slate-j3by.24 lower_shift128: MSVC x64 double-width shifts mask counts modulo 64

_2026-11-25 17:23:53_

- bead: slate-j3by.24
- kind: bug
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/tests/fixtures/msvc/x86_64
- flavor: msvc
- target: x86_64

Outcome: Slate lowers both MSVC x64 double-width shifts with counts modulo 64.

Symptom: Slate's lowering-barriers command reported "builtin without a lowering"
for both wrappers in the MSVC x64 fixture.

Reproducer:
```c
#include <intrin.h>
unsigned __int64 f(unsigned __int64 lo, unsigned __int64 hi, unsigned char n) {
  return __shiftleft128(lo, hi, n) ^ __shiftright128(lo, hi, n);
}
```

Cause: The parser emitted direct builtin calls with the correct
`(u64, u64, u8) -> u64` signature. `lower_value_node` fell through to
`lower_call`, whose unsupported builtin guard rejected them.

Fix: `lower_shift128` builds a `u128` from the two halves, masks the count
with 63, and shifts before selecting the high half for the left shift or the
low half for the right shift. `open_coded_builtin` suppresses both extern
declarations. The same wrappers now lower to Rust integer operations.

Regression test: crates/slate/tests/fixtures/msvc/x86_64/msvc_shift128_intrinsics.c
uses two nonzero halves to check count 64 preserves the returned half and count
65 carries bits between halves in both directions.
