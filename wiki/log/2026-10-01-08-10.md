# Slate lowering barriers label return-type failures on the prototype

_2026-10-01 08:10:47_

slate-p58o.16: return-type lowering failures now point at the function prototype; no parser change.

- lower_return (functions.rs) lowers the return type before parameters and body, so a signature failure is reported before body failures it would cause.
- A failure with no site of its own becomes Construct::Return { returns, ty } at the function site. Construct::label() renders it as "cannot lower a function returning `<c_return>`", or "return type could not be lowered to Rust" when the function has no c_return metadata (extern declarations).
- A failure already sited elsewhere (a record definition) keeps its site and gets that label on the prototype as context.
- The driver clips Function and Return primary spans to their first line, as it already did for context labels, so a definition does not underline its whole body.
- into_public keeps only the first (innermost) context per site, so "in function" no longer stacks on the same span as a more specific label.
- Tables now holds module metadata for the c_return lookup.
