# Preserve complex types through record fields

_2026-08-30 21:10:51_

c_ast::CType had no complex variant, so parse_c_type() fell back to a plain
integer/float type for any `_Complex T` record/union field (e.g. `_Complex
unsigned short` -> `u16`), while CIR-driven expression lowering already
produced correct `num_complex::Complex<T>` values. That mismatch broke
struct/union field declarations for the 4 remaining gcc-torture cases mapped
to slate-os0h.3.1.16 (20020227-1, 20041124-1, 20041201-1, pr42248).

Added `CType::Complex(Box<CType>)` and wired it through parsing (strip a
`_Complex` token prefix), CIR->CType conversion, Rust type lowering, C layout
(size = 2x aligned element size, align = element align), the record-shape
normalizer, and the ABI signature hash. Clang's AST JSON already prefers
`desugaredQualType` for typedef'd complex fields, so no typedef-specific
handling was needed.

Promoting those 4 cases surfaced a second, unrelated codegen bug: Rust
forbids a bare struct literal anywhere inside an `if`/`while`/`match`/`for`
head (grammar ambiguity with the body block), and nothing in
src/backend/codegen.rs guarded for it. `inline_temps` had started inlining
freshly-lowered `num_complex::Complex { .. }` temporaries into `if`
conditions once record fields carried the right type. Fixed by wrapping the
whole condition in one paren pair whenever `expr_contains_bare_struct_lit`
finds a StructLit reachable without crossing a delimiter (call args, index
brackets, etc.) - simpler than mirroring rustc's per-site parenthesization,
and correct since parens fully reset the restriction. Wired into
Stmt::If/While/Match/For's conditions, the Expr::If ternary, and the
previously-missed Stmt::LetIf (a `let x = if ... else ...;` node distinct
from Expr::If).

lowering and rewrites nextest profiles pass; libc profile unaffected.
