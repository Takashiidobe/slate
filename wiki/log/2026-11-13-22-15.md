Outcome: clang `__builtin_neon_*` rounding (vrnd, vrndm/n/p/a/x/i), float-to-int rounding conversions (vcvt{n,m,p,a}[q]_{s,u}{32,64}_v), vmovl_v, vmovn_v and vmull_v expand in sema; this closes the NumPy aarch64 NEON sub-beads under slate-dghn.58.7.

Gap: these were the last NEON barrier groups in NumPy clang-aarch64 (vrnd{,m,n,p}q_v 6 each, vmull_v 14, vmovl_v 5, vmovn_v 2, vcvtnq_s32/s64_v 2 each).

Before:
```
help: function __builtin_neon_vrndnq_v: vector C ABI
```
After: `vrndnq_f32` declares `llvm.roundeven.v4f32`, `vcvtnq_s32_f32` declares `llvm.aarch64.neon.fcvtns.v4i32.v4f32`, `vmovl_s8` is a lane-wise `as i16` cast.

Implementation (sema/neon_builtins.rs):
- `neon_vector(code, NeonShape)` now decodes the operand shape from the result code: `Same`, `Float` (facgt, fcvt*: float of the same width), `Half` (vmovl, vmull: half-width ints, same signedness and lanes), `Double` (vmovn: double-width ints, 64-bit result). `NeonOp::shape` picks it.
- vrnd*: `NeonOp::Round(<llvm name>)` through `neon_lanewise`.
- vcvt{mode}: `llvm.aarch64.neon.fcvt{mode}{s,u}` by the result signedness (the hardware saturates and maps NaN to 0, unlike an `as` cast).
- vmovl/vmovn: `elementwise_conversion`. vmull: both operands widened, then `Arith Mul` with `Overflow::Wrap` (the product always fits). `llvm.aarch64.neon.smull/umull/pmull` have no signature in the intrinsic catalog, so they are not used; poly codes (`vmull_p8`) return `None` from `neon_vector` and keep the extern call.

Bug fixed on the way (crates/slate/src/frontend/c_shim.rs, `render_shim_c_source_for_names`): the x87 long-double C shims were added when any `__slate_*` name contained "f80". The hashed intrinsic wrapper `__slate_intrinsic_eda9f32bf802a624` matched, so the aarch64 batch compiled `__float128` C with aarch64-linux-gnu-gcc and failed ("unknown type name '__float128'"). `__slate_intrinsic_*` names are now skipped for that check. The same renderer serves project builds (main.rs), so a project whose intrinsic hash contained f80 would have hit it too.

Fixture: crates/slate/tests/fixtures/aarch64/neon_rounding_widen_narrow.c (slate-aarch64, qemu): ties, ±0, NaN/±Inf, out-of-range conversions, denormals, integer extremes for extend/truncate/long multiply.

Limits: vmull_p8 (poly) and vshll_n_v (used by vmovl_high_*) still go to the extern call. NumPy corpus not rerun.
