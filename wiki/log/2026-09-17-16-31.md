# Lay out AST dumps without nested pad adapters

_2026-09-17 16:31:41_

Dumping a deep AST was cubic: a flat `int x = 1 + 1 + ...` of 400/800/1600
terms took 0.86s/6.4s/59s (slate-parser-da9). `perf` put 99.55% of samples
in `core::fmt::builders::PadAdapter::write_str`.

The cost is inherent to `{:#?}`: each nesting level wraps the formatter in
another `PadAdapter`, so every byte written traverses the whole chain,
making a dump O(bytes x depth). The parser itself was never slow — the
`ir` path over the same 1600-term input ran in 0.155s and scales linearly,
so only `Renderer::render_debug` was affected. The original bead blamed
`Span::cover`; that was a guess and it was wrong.

`render_debug` now formats non-alternate (`{:?}`, one line, no adapters)
and `expand` re-lays it out: openers newline and indent, `, ` becomes a
newline at the current depth, closers get the trailing comma and dedent,
and empty groups stay inline. String and char literals are copied
verbatim so braces and commas inside them are untouched. Only one custom
Debug impl exists (`Span<T>`, which delegates), so the input grammar is
just derive plus std builders.

Verified by diffing old and new binaries over all 2524 `.c` fixtures:
byte-identical. Now 0.009s/0.021s/0.048s, and 5000 terms in 0.24s.
