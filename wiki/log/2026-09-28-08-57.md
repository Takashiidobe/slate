# gcc flavor asm operand validation

_2026-09-28 08:57:25_

slate-parser-cl7: check_function_asm (validate.rs) now runs for gcc as well as clang.

- gcc rejects mismatched constraint alternative counts, but only at expand
  time: -fsyntax-only passes, a full compile fails with 'operand constraints
  for asm differ in number of alternatives'. gcc also rejects duplicate asm
  operand names, undeclared asm goto labels and jumps into statement
  expressions, so the label and scope checks carry over unchanged.
- gcc's output-lvalue rule is looser than clang's: build_asm_expr runs
  c_fully_fold and STRIP_NOPS before lvalue_or_else. It accepts same-mode
  casts ((unsigned char)c, (long)p, (int *)l), commas ((y, x)), folded
  identities (x + 0, x * 1, x << 0, 0 ? x : x, 1 ? x : y) and ({ x; }).
  It rejects mode-changing casts ((int)c, (long)x), x ? x : y, x + 1,
  g().a, (x ? s : t).a and string literals (read-only).
- New is_gcc_output_lvalue can't see types, so it's permissive: it
  accepts every cast, every conditional whose arms are lvalues, every
  statement expression, and binary ops with an identity literal operand.
  Known looseness: (x ? s : t).a is accepted.
- Many gcc-accepted forms still fail later in lowering ('expression is not
  a supported place'); noted on slate-parser-cxg.15.
- File-scope register variable checks remain clang-only (gcc also rejects
  'register name not specified'); that gap is permissive and left as is.
- Fixtures: gcc/linux/x86_64/asm-hard-register.c now uses matching counts
  ("={ax},r" / "{rdi},r", which gcc accepts); asm-sema.c regenerated.
