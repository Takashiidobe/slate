# slate-5q63.26 codegen: Codegen::stmts rendered trailing-comment stmts twice, exponential in nesting; sqlite translate 2x faster

_2026-11-20 16:45:52_

- bead: slate-5q63.26
- kind: bug
- area: crates/slate/src/backend/codegen.rs

Outcome: `Codegen::stmts` renders a statement with a trailing comment once instead of twice, so codegen is linear in block nesting depth; sqlite translate-project went from 25-29 s to 13-15 s with byte-identical output.

Symptom: profiling sqlite translate-project for slate-8ge7.1 put 42% of CPU in `slate::backend::codegen` (12.6 of 30 cpu-s), far above interproc (2-3%).

Reproducer:

```c
int f(int x) {
  while (x > 0) {
    while (x > 1) {
      /* ... nested 22 deep ... */
        x--;
    } // close 1
  } // close 0
  return x;
}
```

Depth 16: 0.08 s, 20: 0.44 s, 22: 1.85 s (doubling per level).

Cause: in `Codegen::stmts`, a non-comment stmt followed by a `CommentAttach::Trailing` single-line comment was rendered into a fresh `Codegen` to test whether it fits on one line; when it did not (any block statement), it was rendered again with `self.stmt`. Each nested level repeats this, so a block at depth d is rendered 2^d times. The scratch `Codegen` also dropped the parent's `macro_params` and `no_unwind`.

Fix: the scratch render carries the parent's `macro_params` and `no_unwind`; if the text is one line, emit it with `// comment` and skip the comment stmt, otherwise write the already-rendered text and let the comment stmt print normally. Codegen does no indentation (rustfmt does), so the scratch text is exactly what `self.stmt` would write.

Validation: depth-22 probe 1.85 s -> 0.10 s, identical output; sqlite crate output identical before/after (diff -r, only the crate name from the output dir differs); slate profile 43/43.

After the fix, flat profile of sqlite translate-project: rustfmt 27.5% (`rustfmt_nightly::comment::CharClasses::next` alone 20%), parser 25%, unattributed closures/clones 16%, allocator 11%, engine rules 8.5%, other backend 4.7%, lowering 2.7%, interproc 2.3%, codegen 0.1%.

Limits: no regression fixture; an exponential slowdown needs a time-bounded test, not a differential fixture. Profile is flat (no call stacks): a debuginfo/frame-pointer rebuild crashed the machine twice.

See: slate-8ge7.1, wiki/log/2026-11-20-16-12.md.
