# Native-ABI entry for Rust-defined variadic long double functions

_2026-11-07 08:55:51_

slate-yar4.25: a Rust-defined variadic function whose fixed params or return hold f80 had no native-ABI entry, so taking its address was a barrier (C cannot forward ...). Now its ... binding lowers as a VaList parameter (functions.rs) and it is exported as __slate_ldv__<entry>__r<tags> (f80.rs long_double_entry_export_name; lowerer.rs for static defs, entry __slate_ldfp_<unit>_<name>). c_shim::render_variadic_export renders native <entry>(fixed, ...) that va_starts, stores f80 fixed args, passes the va_list, loads the result. Every call, direct or not, goes through the native entry via __slate_icall__ (values.rs arm; the libc-name check applies only to extern callees, long_double_variadic_libc_name.c defines a static exit). Also: single-file translation sets LowerOptions.unit to the file stem (api.rs), so static native entries stay unique when the test batch links all fixtures' shims; long double bridges declare fp (function pointer) params as *const () so bridges with equal names share a Rust type. Fixtures: x86_64/long_double_variadic_definition_address.c (direct, pointer, zero variadic args, va_start twice, mixed types), dylink ld_vcall (native C calls a translated variadic callback; guarded off Windows, slate-j3by.11 filed for clang-flavor Win64 va_arg). FileCheck regenerated: long_double_function_pointer, long_double_va_arg, long_double_variadic_libc_name, dylink host. Full slate profile green after the last fix (generated_differential rerun).
