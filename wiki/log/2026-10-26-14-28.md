# Emulate -malign-double; pad erased packed fields with aligned integer storage

_2026-10-26 14:28:25_

slate-3amj.25: -malign-double (gcc, clang; gcc also -mno-align-double, last wins; gcc rejects it off x86, clang and msvc reject -mno-/the spelling).
Parser: LayoutOptions::align_double/align_long_double, applied in CompilerOptions::effective_target via TargetInfo::with_align_double: i64/u64/f64 get alignment 8 (only i686 changes). clang also sets long double's alignment to 8 on every target (x86_64/aarch64 16 -> 8; i686 12 bytes, align 8). gcc leaves long double alone. No macro delta.
Backend: Tables::storage_of now reads scalar alignment from the triple's base TargetInfo (Tables::rust_layout), since that is what Rust's primitives have; the IR target's raised C alignment then shows up as explicit padding plus repr(align) instead of a silently wrong repr(C) layout.
Pre-existing bug fixed on the way: a packed record's erased field (MaybeUninit<[u8; N]>, used for LongDouble/raised records) had Rust alignment 1 but was placed assuming min(field_align, pack), so #pragma pack(8) struct { char; long double; } put the field at Rust offset 1 instead of 8. Erased storage is now [uN; _] with uN's Rust alignment equal to the packed field alignment (bytes and alignment 1 otherwise, so the layout checks barrier).
