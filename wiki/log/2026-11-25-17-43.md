# slate-j3by.26 rotate_method: MSVC scalar rotates wrap counts at each operand width

_2026-11-25 17:43:15_

- bead: slate-j3by.26
- kind: bug
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate-parser/src/sema/builtins.rs
- area: crates/slate/tests/fixtures/msvc
- flavor: msvc

Outcome: Slate lowers direct MSVC left and right rotates at all four
widths while preserving calls through CRT function pointers.

Symptom: The MSVC fixture reported `builtin without a lowering` for the
first rotate at each width on x86, x64, and ARM64.

Reproducer:
```c
#include <intrin.h>
unsigned char rotate8(unsigned char value, unsigned char count) {
  return _rotl8(value, count);
}
```

Cause: `rotate_method` recognized the Clang scalar rotate builtins only.
The MSVC names fell through to the unsupported builtin guard in `lower_call`.

Fix: Add all eight names to `rotate_method`. The reproducer now becomes
`value.rotate_left(count as u32)`. The existing scalar lowering preserves
operand width and Rust reduces the `u32` count modulo that width. The
extern declaration path remains available for addressed CRT functions.
Builtin lookup uses the catalog's `ALL_MS_LANGUAGES` marker for MSVC and
Clang with Microsoft extensions enabled. Plain Clang and GCC retain
ordinary calls to functions declared with the same names.

Regression test: crates/slate/tests/fixtures/msvc/msvc_rotate_intrinsics.c
checks both directions at zero, width, width minus one, width plus one, and
the count type's extremes. A separate case calls `_rotl` and `_rotr64`
through volatile function pointers.
crates/slate/tests/fixtures/ms_rotate_names_without_extensions.c checks
that ordinary functions with these names still run their C bodies.
