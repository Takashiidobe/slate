# Barrier codegen-only builtins by kind, not name prefix

_2026-10-02 20:58:43_

slate-dghn.16. The 'builtin without a lowering' barrier only matched extern calls named __builtin_*, so codegen-only builtins with other spellings (__rdtsc before its expansion, __debugbreak, _mm_pause, __readfsdword) reported ok in lowering-barriers and failed only at link time.

Parser: builtin function declarations (declared and implicit) now carry c_builtin_kind (clang's ClangBuiltinKind: library/builtin/atomic/language) and c_builtin_header when the registry names one, via ClangBuiltin::declaration_metadata.

Slate: FunctionName.codegen_builtin is set when the kind is not library or the header ends in intrin.h (MS and x86 intrinsics are LibBuiltins in clang but have no library symbol). The barrier fires for __builtin_* or codegen_builtin, unless builtin_library_name maps it (memcpy etc.). Intrinsic-catalog and expanded builtins never reach lower_call.

Fixtures: parser ir_builtin_kind_metadata.c (abs library/stdlib.h, _mm_pause library/emmintrin.h, __builtin_trap builtin); slate fixtures.unsupported/codegen_only_builtin_extern.c (_mm_pause/_mm_getcsr extern calls now a barrier instead of a link failure). Regenerated 5 parser expectations for the new metadata; ir_x86_target_builtins.c was also stale from the __rdtsc expansion in slate-dghn.1.

Validation: parser profile 5 expected metadata failures, regenerated; slate profile green. Wiki: ir/builtins.md, ir-to-rust-lowering.md.
