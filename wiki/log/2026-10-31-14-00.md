# Preprocess every --merge assignment and remove refinement

_2026-10-31 14:00:19_

slate-nfq8.9: the bead's signature and taken-symbol gaps were symptoms of a miscompile. Refinement seeded no features, each alone and all on, so code only present under #if A && B && !C was never compiled and was silently dropped: default --merge exited 0 and Rust printed 0 where C printed 7. --check-projection, off by default, was the only detector. A probe of 317 two-unit condition pairs on 5 features gave 70 projection mismatches. Per the user, --merge now has one mode: it preprocesses every valid assignment and compiles each new fingerprint (the rest reuse a result). Removed --merge-full-table, Coverage, refine, undecided_rows, ambiguous_rows, hitting_rows, untried_rows and the gates and claims tracking. This reverses the inference from slate-nfq8.6; fingerprint reuse from slate-nfq8.7 stays. Signatures and taken symbols now see every assignment with no new check code. Fixtures: unseen_row.c (code and link_section under an unseen assignment), unseen_signature.c (a widen mismatch only there, reported on linux, where long is i64, and not windows). Both failed first with projection mismatches and 0 signature mismatches. They set // merge-features because the shared matrix's invalid beta+gamma makes the all-on seed land on alpha,beta. Results, zlib 16 targets: 2544 compiles (was 1506), 85.7s (was 69.2s), 159 per linux-x86_64 target (was 94). Output byte-identical to the old full table: 60,234 lines, 2,877 cfgs. The old refined output differed only in condition order in deflate.rs and zutil.rs, so earlier codegen and layout validation still applies; it was not rerun. Probe rerun: 0 of 317 mismatch. Slate profile 33/33. Fingerprint reuse showed no clear wall-time gain: 85.7s vs 86.1s without it, single uninterleaved runs.
