# Operand conversions recorded by the checker, applied by lowering (slate-parser-ygrj.2)

_2026-09-30 11:53:12_

Step 2 of slate-parser-ygrj.

- New facts on TypeResolver: operand_conversions ((owner NodeId, Slot) -> Vec<Step { kind: Arithmetic | Cast(CastKind), to, reason }>) and computation_types. Keyed by the operator and slot, so GNU x ?: y and compound assignment don't collide.
- The typer records them: binary_type now returns the result plus BinaryFacts (arithmetic: promotion + usual arithmetic steps; pointer +/-: index promotion); record_pointer_comparison; record_update for op= and ++/--, including the bit-field promotion and the Result conversion back; ?: Then/Else; unary + - ~ and non-complex __real/__imag; Index. The checker records switch/case (record_switch, record_case).
- Lowering applies them with converted / converted_statement and no longer calls arithmetic_operands, binary_operand, unary_operand, conditional_pointers, compatible_unqualified or convert_expr. Lowerer::promote and convert_expr are removed. binary() only dispatches on pointer shape and emits arithmetic at the recorded computation type. runtime_size emits its size_t multiply directly.
- Fixes the enum ?: disagreement: conditional<u32> with enum_to_int arms, which matches clang's 'unsigned int' / IntegralCast. New fixture clang/linux/x86_64/conditional_enum_arms.c covers the plain enum, mbedtls cast-arm, zlib nested ?: through a function-pointer member, and zstd enum-member shapes; the pre-change binary fails all four ?: with TypeDisagreement. The corpus files themselves were not re-run.
- IR change: gcc-dg c90-const-expr-5.c 'fp == (const void *)0' now lowers as pointer_cast(null<ptr<const void>>) instead of null<ptr<fn>>, because null pointer constants now follow the typer's rule (qualified void is not an NPC). clang -ast-dump shows BitCast there too.
- VM exception: recorded targets with unbound extents make operand_steps drop the owner's memo and type it again under lowering's bound extents.
- Left for ygrj.3: vararg default promotion targets (call()), builtin/atomic argument convert, K&R parameters, VLA extents, result types. &&/|| and ! still use enum_operand + condition.
- The constant folder (constant_value_with_context) still uses binary_operand/unary_operand/arithmetic_operands.
