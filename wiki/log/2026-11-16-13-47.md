# slate-f2zu.14.41 e2e.py: --from translate|build and --shards resume a linux run with only the changed shards re-translated

_2026-11-16 13:47:55_

- bead: slate-f2zu.14.41
- kind: feature
- area: tools/corpus/e2e.py
- corpus: linux

Outcome: e2e.py can resume a sharded (linux) run at translate or build and
re-translate only named shards, instead of a full ~1h25m rerun.

- `--from translate` skips the barrier pass (28m on linux); `--from build` also
  skips translate. Default `native` runs everything as before.
- `--shards a,b,c` re-translates only those shards (unknown names abort). Build
  and link still loop over every shard: sync_tree only rewrites files whose
  content changed, so cargo treats untouched shards as fresh.
- Both flags error on non-sharded projects.
- Full linux run for reference: barriers 28m, translate 16m, build 39m, link
  <1m.

Example (after a slate fix that changes 51 shards):
`python3 tools/corpus/e2e.py linux --until link --jobs 2 --from translate --shards "$(cat shards.txt)"`
