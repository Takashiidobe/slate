# reject --target for project filecheck regen

_2026-09-06 11:03:19_

`update_filecheck.py` rejected `--target` only when project mode came from an
explicit `--project`/`--library-project` flag. Passing a `tests/fixtures.multi`
path infers project mode, so the flags slipped through and generated
target-prefixed blocks from a single translation: `update_project` reads
`environment = profiles[0][2]`, so every target's block came from the *first*
target's environment. The guard now fires on inferred project mode too.

Nothing consumes target-qualified prefixes in project fixtures anyway.
`check_project_modules` calls `check_generated_rust` with no extra prefixes,
and `support::filecheck::directive` only accepts `COMMON`, `COMMON-<PROFILE>`
and the bare profile prefix plus a directive suffix, so
`REWRITES-X86_64-GNU-DAG` never matches. Only `differential.rs` reads
`*-X86_64-GNU`, and only for `fixtures.link/long_double`.

Side effect worth knowing: those inert blocks in
`tests/fixtures.multi/gnu_symbol_pragmas/strong.c` make
`has_handwritten_block` treat the file as handwritten, so regen skips it.
