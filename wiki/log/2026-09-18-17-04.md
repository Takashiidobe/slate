# Clang flavor rejects wide plain character constants

_2026-09-18 17:04:42_

slate-parser-4zk: sema validation now takes the compiler flavor (LiteralContext.flavor). Under --flavor=clang a plain character constant whose source character expands to more than one execution-charset byte (e.g. 'Ω') is rejected with 'character too large for enclosing character literal type', matching clang. gcc/msvc keep packing the UTF-8 bytes into an int (0xCEA9). Escapes like '\xff' and multicharacter 'ab' are unaffected. Only the diagnostic path branches; sema::numeric::Context still carries no flavor because no value/type computation differs. Fixtures: error/clang_plain_character_constant.c, sema/gcc_plain_character_constant.c. Also regenerated sema/ir_generic_selection.c (stale coerce<i64> -> coerce<i32> for a 4-byte struct) and applied cargo fmt to ir/mod.rs, ir/module.rs, sema/types.rs.
