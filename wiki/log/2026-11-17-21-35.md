# slate-xw0x.12 build_filecheck: rebuilt every fixture/target each run; build-ok marker now holds an input key and cached runs only FileCheck

_2026-11-17 21:35:35_

- bead: slate-xw0x.12
- kind: bug
- area: crates/slate/tests/build_filecheck.rs
- area: crates/slate/tests/support

Outcome: build_filecheck takes 0.02s on a no-change run (was 4.3s alone, 19s in the slate profile); the slate profile is 15-16s with no test over 13s.

Symptom: after slate-xw0x.11, build_filecheck was the slowest slate-profile test (19s). Alone it took 4.3s: 13 fixture/target pairs from tests/fixtures.build, run serially, each doing clang -c, translate-project and a no-op cargo build, all of which waited for CPU under the profile's contention.

Cause: nothing was skipped when inputs were unchanged; the `.build-ok` marker was deleted and rewritten every run.

Fix (crates/slate/tests/build_filecheck.rs `build_fixture`):
- Key = `support::translation_key(fixture, [target, dg-options...])` (now pub): slate binary size+mtime, sysroot path, args, fixture bytes, and all non-.c files in the fixture directory (which covers the `<stem>.rs` assertion files appended to lib.rs).
- The `.build-ok` marker now holds the key. When it matches and `<name>.generated.rs` exists, only FileCheck runs on the saved output; otherwise the marker is removed and the full clang/translate/cargo path runs, writing the key at the end.
- update_filecheck.py only checks the marker exists, so it is unaffected. Editing a fixture's FileCheck block changes its key and rebuilds that fixture.

Measured: build_filecheck 3.7s -> 0.017s alone; slate profile 18-19s -> 15.3/15.9s, 43/43. Slowest now: manifest_selection_and_merge (12.8s), generated_differential (12.8s), dylink_* (10-11s), so the profile is contention-bound across many tests rather than one long pole.

Limits: same as slate-xw0x.11: host/sysroot header or Rust toolchain changes without a slate rebuild do not invalidate the key.
See: slate-xw0x.11, wiki/log/2026-11-17-21-31.md
