# Share token text through Rc instead of owning a String per token

_2026-09-28 07:41:13_

slate-parser-xgj9 (partial). windows.h fixture 653ms -> 602ms; libc
malloc/free/memcpy share of the run 50% -> 35%.

Token's string payloads (Ident, IntLit, FloatLit, string/char literals,
Comment) are now lexer::TokenText, a newtype over Rc<str>; char literal
code units are Rc<[u32]>. Cloning a token no longer allocates, which is
what macro expansion, argument collection and the parser's token copies
do constantly. Token shrinks 56 -> 40 bytes.

TokenText derefs to str and compares with &str/String, so existing
name == "..." and as_str() code is unchanged; only construction sites
needed .into(). The AST keeps String: the parser converts once when it
builds a node, the same cost as the clone it did before. The expansion
disabled set is HashSet<TokenText>. Debug output is identical, so no
fixture changed.

Next hot spot is the lexer: each file becomes a Vec<char> plus a
Vec<usize> byte-offset table (12 bytes written per source byte) and
every identifier is collected into a String and then copied into an Rc.
