# Generalize declaration-matrix reconciliation into a tool

_2026-09-09 09:29:22_

Built tools/reconcile_header.py to generalize the anchor-based merge used for
elf.h (slate-b66b.14.2.25) across the declaration-matrix workflow. For a
header it probes all 8 glibc/musl x {x86_64,i386,arm,aarch64} oracles via the
existing emit_oracle_header_macros ignored test (name+value+definition_file
per macro), adds the header to every manifest whose oracle actually exposes
it, runs the real matrix to get compiler-verified missing-macro sets per
descriptor, groups missing macros by (presence pattern, value), and derives
the narrowest __SLATE_LIBC_*/__SLATE_ARCH_*/__SLATE_WORDSIZE_* guard for each
group from a lattice (falling back to an OR-of-AND expression for any other
pattern). Insertion point is anchored after the nearest preceding macro
already in the shim, found via the oracle's own definition_file for true
source order (not the alphabetical order the generated fixture/JSON use).

Any macro whose value differs across descriptors that share a missing
pattern is a real conflict and is never auto-inserted. Two correctness gaps
were caught while running it on the real batch and both are now handled:
(1) a test failure that isn't a "macro is missing" #error (e.g. a header
visibility mismatch) was silently swallowed as "already reconciled" instead
of surfacing -- fixed by keying off the test's exit code and always
returning the raw diagnostic when it isn't fully accounted for by known
macro-missing lines; (2) glibc's "#define X X" self-referential
feature-marker idiom (paired with an enum of the same name, e.g. FTW_STOP)
was transliterated verbatim as a broken self-reference with no backing
value -- the tool doesn't parse enums, so this shape is now routed to the
conflict/manual-review bucket instead of auto-inserted.

Claimed and closed the next 5 alphabetical children of slate-b66b.14.2:
fts.h, ftw.h, gconv.h, getopt.h, glob.h. fts.h and ftw.h needed a manual
per-arch include-closure fix (older glibc cross sysroots for arm/aarch64
don't transitively pull sys/stat.h/dirent.h/sys/types.h the way the host
x86_64 oracle does) -- real divergence, not tool error. gconv.h had no
usable content at all (a stub #error) and needed a hand-written
transliteration of glibc's internal gconv step/step_data structures, which
is out of scope for a macro-only tool. getopt.h was already fully
reconciled. glob.h's one gap (GLOB_ABEND aliasing GLOB_ABORTED) was a
correct auto-insertion.

Full `libc` nextest profile: 48/48. No Rust files changed, so fmt/clippy
were skipped per user correction (see feedback_skip_fmt_clippy_no_rust_changes
memory).
