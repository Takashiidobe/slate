# slate-f2zu.11.1 translate-project --manifest: per-target compile_commands.json plus declared features, resolved Matrix model

_2026-11-13 20:11:03_

- bead: slate-f2zu.11.1
- kind: feature
- area: crates/slate/src/project/matrix.rs
- area: crates/slate/src/compile_commands.rs
- area: crates/slate/src/main.rs

Outcome: translate-project accepts `--manifest <file>`, a version-1 JSON that points each target at a compile_commands.json and declares Cargo features as extra defines; --plan, --merge and single-target runs work on it exactly as on --matrix.

Gap and why it mattered: the matrix (tools/corpus/matrices/*.json) is hand-written with one shared source list and per-target (not per-file) args. Real builds already describe each target in compile_commands.json, including per-file flags. Features cannot be inferred from those files (zlib's 9 feature defines appear in none of its build databases), so they are declared.

Format:
  {"version": 1,
   "targets": {"linux-x86_64": {"triple": "...", "flavor": "clang", "sysroot": "?",
               "compile_commands": "build-linux/compile_commands.json", "build_target": "?"}},
   "features": {"fast": ["FAST"]}, "invalid_features": [["fast", "small"]]}
compile_commands paths resolve against the project directory argument. One database may back several targets; the manifest triple overrides the host.

Implementation:
- `Matrix` (crates/slate/src/project/matrix.rs) is now a resolved model: per target a `BTreeMap<source, UnitCommand>` of unparsed args plus directory. `MatrixFile::resolve(project)` lowers the old format; `Matrix::read_manifest(path, project)` reads the new one. `command`/`commands` no longer take `project`, so plan.rs and merge.rs stopped threading it.
- compile_commands.rs: `UnitCommand` and `read_units` expose the per-unit args before `compiler_arguments`, so feature defines can be appended per configuration. `read` behaves as before.
- Manifest errors: version != 1; a command `--target=`/`-target` whose registry triple differs from the manifest triple (aarch64-linux-gnu vs x86_64-unknown-linux-gnu); a feature macro already -D/-U (or /D, /U) in a target's base commands; targets compiling different source sets (until slate-f2zu.11.3 cfg-gates units).
- main.rs: `--manifest` beside `--matrix` (only one allowed); `--matrix-target` selects targets for both.

Fixture: crates/slate/tests/fixtures.matrix/generated/{manifest.json,build-linux,build-windows}. value.c gets -DTARGET_EXTRA=7 only in the linux database (per-file arg). Tests in tests/differential.rs: manifest_targets_use_their_own_compile_commands, manifest_selection_and_merge_match_c_with_same_configuration (features and a linux+windows --merge run, compared with clang), manifest_rejects_invalid_input.

Limits: error text still says "matrix" for shared errors; --matrix-target keeps its name. Both change when the old format is deleted (slate-f2zu.11.4).
