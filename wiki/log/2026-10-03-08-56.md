# Native-ABI f80 function pointers: ldfp entries and icall trampolines (slate-dghn.24)

_2026-10-03 08:56:33_

Function pointers whose signature holds long double by value now always point at
native-ABI code, so they work when handed to C (redis RM\_\*LongDouble in the module
API table) and when filled from C (cbrtl, ldexpl).

- values.rs/f80.rs: taking the address of such a function yields an address-only
  extern **slate*ldfp*<unit>\_<name>. Extern functions and exported definitions
  get #[link_name = "<name>"] (the dghn.23 native wrapper or libc). Other
  definitions get export_name **slate*ld\_\_\_\_slate_ldfp*<unit>\_<name>\_\_r<tags>
  plus C-unwind ABI, and c_shim renders the native wrapper under the ldfp name.
- Indirect calls through such pointers call **slate_icall**r<ret>\_<tags>(fp, ...),
  a C trampoline that loads f80 args and calls the pointer natively.
- LowerOptions.unit carries the unit stem so statics sharing a name stay distinct.
  c_shim splits **slate_ld** names at the last \_\_ (tags never contain one).
- Variadic, unprototyped, and complex f80 function pointers are barriers.
