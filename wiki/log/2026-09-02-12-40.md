# Freshen temp names in duplicated switch arms

_2026-09-02 12:40:50_

Tail duplication in `structure_dispatch` cloned each fallthrough arm's
statements verbatim, so the copied `let _vN` declarations appeared twice in one
function. `inline_temps` bails on `node_ident_count(root, name) != 1`, so the
duplicated arm kept every lowered temp while the original arm got cleaned --
half of each recovered switch read far worse than the other half. Conservative
direction (no miscompile), but visibly bad output.

Copies now get fresh `_vN` names. `max_temp` walks the function root once for
the highest existing index; `rename_decls` renames declarations in the copy via
the new `Stmt::declared_name_mut`, and `freshen` rewrites uses with the existing
`Stmt::substitute_var`. Only `_vN`-shaped names are renamed, so nothing declared
outside the copy is touched and there is no shadowing to respect.

Added `Stmt::child_bodies_mut` (mirrors `NodeKind::child_lists_mut`) and
`Stmt::declared_name_mut` to rust_ast, both reusable by any later pass that
clones code -- `structure_goto` will need exactly this.

Every arm of switch_fallthrough / switch_default_first_fallthrough /
switch_default_middle_fallthrough now collapses to `out = out + _vN`
uniformly. rewrites profile: 92 passed, 7 skipped.
