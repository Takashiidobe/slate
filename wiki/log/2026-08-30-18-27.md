# bitint nested-struct static init emits raw literal (slate-m7x7)

_2026-08-30 18:27:43_

Two bugs in render_const_value_expr (src/frontend/lowerer.rs):

1. The scalar fallback (`_ => scalar_attr_expr(attr)`) never checked whether
   the target Rust type was a `bitint::BInt`/`BUint` generic, so a
   _BitInt(N) struct field's Attr::Int/CirInt initializer rendered as a bare
   integer literal instead of `BInt::<...>::from_i128(...)`. Fixed by adding
   dedicated match arms that route through `bitint_from_int_expr`, deriving
   signedness from the generic's name (`bitint::BInt` vs `bitint::BUint`).

2. The `RecordKind::Union` arm of `Attr::ConstRecord` always used
   `record.fields.first()` regardless of which union member the CIR
   `#cir.const_record` initializer actually held (CIR only lists the *active*
   member, not an index). Fixed by comparing the initializer element's CIR
   type (`attr_cir_type`) against the union's declared member-type list
   (`union_member_cir_types`, after resolving `CirType::Named` aliases via
   `self.expand_alias` on both sides) to find the matching field index.

Promoted test-fixtures/bitint_record_layout.c to tests/fixtures/ with
@lowering/@rewrite regions plus manual COMMON-DAG checks for the
`from_i128` construction (global static, outside any function body, can't
use body-scoped region markers). The union fix also unblocked
gcc-torture pr15296.c (a `union u0` initializer), promoted out of
fixtures.gcc-torture.unsupported/.
