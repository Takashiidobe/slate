# slate-3amj.5.22 msvc pragma: fenv_access(on|off) and fp_contract(on|off) map to STDC floating pragmas

_2026-11-18 17:45:02_

- bead: slate-3amj.5.22
- kind: parser
- area: crates/slate-parser/src/parser/decl.rs
- flavor: msvc

Outcome: under the msvc flavor, `#pragma fenv_access(on|off)` and `#pragma fp_contract(on|off)` now apply the same floating-region handling as the STDC pragmas.

Gap: parser/decl.rs only mapped `#pragma STDC FENV_ACCESS` and `FP_CONTRACT` (plus `float_control`), so cl.exe's own spellings stayed `PragmaKind::Opaque` and were ignored.

Before (`/fp:fast`):
```c
#pragma fenv_access(on)
double f(double a, double b, double c) { return a * b + c; }
```
Accepted silently. cl.exe gives C3198 "fenv_access pragma operates only in precise mode".

After: sema error `'#pragma STDC FENV_ACCESS ON' is illegal when precise is disabled`. Under `/fp:contract`, `fenv_access(on)` gives `rounding=environment, exceptions=observable` and `fp_contract(off)` gives `contract=off`.

Fix: new msvc-gated arm in parser/decl.rs that produces `PragmaKind::Stdc` via `parse_msvc_floating_value`; `FloatingPragmas::stdc` (sema/pragmas.rs) is unchanged.

Fixtures: `error/msvc/windows/x86_64/fp_option_fast_fenv_access.c`, `msvc/windows/x86_64/fp_pragma_msvc_spellings.c`.

Limits: the diagnostic text is the STDC wording, not cl's C3198 text. `fp_contract` has no `default` value in cl, so only on/off are accepted.

See: slate-3amj.9 (fp:fast clears precise)
