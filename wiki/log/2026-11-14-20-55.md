# slate-f2zu.14.31 named_asm_labels: inline asm defining global labels (vdso __futex_list64_try_unlock_cs_start) rejected by rustc; units now allow named_asm_labels

_2026-11-14 20:55:25_

- bead: slate-f2zu.14.31
- kind: bug
- area: crates/slate/src/frontend/lowerer/asm.rs
- area: crates/slate/src/frontend/lowerer.rs
- area: crates/slate/src/main.rs
- area: crates/slate/src/backend/rust_ast.rs
- flavor: clang

Outcome: a unit whose inline asm defines a named label (`name:` that is not a numeric local label) now gets `#![allow(named_asm_labels)]`, carried to the crate root in project mode, so asm that exports global labels by symbol passes rustc.

Symptom (linux check stage, arch_x86__packed: 6, arch_x86__packed_m32: 3 errors): `avoid using named labels in inline assembly` on arch/x86/entry/vdso vfutex.c, whose asm defines `__futex_list64_try_unlock_cs_{start,success,end}:` (and the list32 set). vdso2c exports those symbols from the vDSO ELF and the kernel compares an interrupted user IP against [start, end) to fix up a robust-futex unlock, so the labels must stay global and inside the function's own code.

Reproducer:
    extern const char slate_cs_start[], slate_cs_end[];
    __attribute__((noinline)) static int bump(int x) {
      __asm__ volatile("slate_cs_start:\n\tnop\nslate_cs_end:" ::: "memory");
      return x + 1;
    }

Cause: rustc's deny-by-default `named_asm_labels` rejects any named label definition in `asm!`, because LLVM may duplicate the block. Renumbering would break external references, and `global_asm!` cannot take the register operands the block binds. C carries the same duplication hazard and the program relies on a single emission, so the translation trusts it the same way: a duplicate would fail at link, as in C.

Fix:
- `rust::Lint::NamedAsmLabels` ("named_asm_labels").
- `asm::defines_named_label(template)` splits the final template on newline and `;` and looks for a leading `[A-Za-z_.$][A-Za-z0-9_.$]*:`; `lower_asm` and `lower_asm_block` (naked bodies) set `Dependencies::named_asm_labels`. `AsmKind::Global` is excluded: rustc does not lint `global_asm!`, and file-scope asm defining functions (`.globl f\nf:`) is common.
- `write_project_crate` carries NamedAsmLabels to the crate root with the other carried lints.

Regression test: crates/slate/tests/fixtures/asm_named_global_labels.c (labels in a noinline function, referenced from C as extern arrays).

Kernel: re-translated only arch_x86__packed and arch_x86__packed_m32 in ~/slate-translated/slate-linux; cargo check is clean for both. Also closes slate-f2zu.14.33 (the m32 list32 labels).

See: slate-f2zu.14.30, slate-f2zu.14.33
