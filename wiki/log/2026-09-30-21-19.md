# Lower null pointer values in the slate frontend

_2026-09-30 21:19:15_

slate-p58o.3.36, closing slate-p58o.3.32.

- ValueKind::Null for data pointers lowers to std::ptr::null::<T>() or null_mut::<T>() from the lowered pointer's mutability, with the pointee rendered via codegen::type_to_string. Function-pointer null stays None.
- Null is accepted in static initializers (both calls are const fn), so static T *p = NULL and pointer tables of NULL lower.
- 3.32 needed no array-aggregate code: array members, zero fill and nested arrays landed with 3.16. Its last named fixture, aggregate_array_literal_typed_elements.c, was blocked only on null.
- New fixture null_pointer_values.c: NULL-terminated list, NULL return, !p, p ? p : default, NULL struct fields and arrays, NULL global and static initializers, const and void pointers.
- Promoted: null_pointer_values, aggregate_array_literal_typed_elements, getenv_var_recover, 18 more local fixtures, 38 gcc-torture. c23_typeof_unqual.c stays unsupported on _BitInt(7).
- Fixed the 3.29 promotion of c23_embed.c, which left its #embed .bin files in fixtures.unsupported/ and broke generated_differential. The bins are copied to fixtures/ (c23_language.c, still unsupported, uses them too). Moved function_provenance/ headers with function_provenance.c.
