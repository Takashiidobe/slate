# slate-5q63.22.6 slate-intrinsic-gen: intrinsics_table.rs emitted via quote + prettyplease instead of format! rows

_2026-11-18 16:07:27_

- bead: slate-5q63.22.6
- kind: feature
- area: crates/slate-intrinsic-gen
- area: crates/slate/src/frontend/lowerer/intrinsics_table.rs

Outcome: slate-intrinsic-gen builds intrinsics_table.rs as a quote! token stream printed by prettyplease instead of format! row strings; the checked-in table is regenerated in that layout (values unchanged).

Gap and why it mattered:
generate_source pushed hand-spelled struct definitions and one `format!` per row (`IntrinsicSignature {{ name: {:?}, .. }}`), with `{{` escapes, `{:?}` for string literals, and `#[rustfmt::skip]` tables.

Before:
    out.push_str(&format!("    IntrinsicSignature {{ name: {:?}, builtins: &{:?}, overloaded: {}, ret: {}, params: {}, overloaded_positions: {} }},\n", ..));
After:
    quote! { IntrinsicSignature { name: #name, builtins: &[#(#builtins),*], overloaded: #overloaded, ret: #ret, params: #params, overloaded_positions: #overloaded_positions } }
    prettyplease::unparse(&syn::parse2(tokens)?)

Implementation (crates/slate-intrinsic-gen/src/main.rs):
- generate_source returns Result<String, syn::Error>; `intrinsic_row`, `stdarch_row`, and `optional` (Some/None) build rows; table names via format_ident!; u32 positions are unsuffixed literals.
- New generator-only deps: quote, proc-macro2 (added to workspace.dependencies), syn 3 (full, parsing, printing), prettyplease 0.3 — the versions slate already uses.
- `#[rustfmt::skip]` is gone; the README's `cargo fmt` step after a regen normalizes the file.

Verified: a scratch crate fed the current table's data (all five sections + X86_STDARCH_OVERRIDES, LLVM_COMMIT 58dd40228595) through HEAD's and the new generate_source; parsed with syn, rustfmt::skip stripped and trailing commas normalized, the token streams are equal. The new output was installed and cargo fmt'd: intrinsics_table.rs is now 100,463 lines / 2.8 MB (was 6,511 / 1.8 MB). slate-c2rust builds. No regen against LLVM: ~/llvm-project is at a different commit, which would also change content.
