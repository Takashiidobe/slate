# Add label support to Stmt::While for continue-bearing loops

_2026-09-04 09:22:30_

Added label: Option<Label> to rust_ast::Stmt::While and engine/arena's NodeKind::While (slate-04q.85.8), mirroring Stmt::Loop's existing label field. Touched every exhaustive match site across rust_ast.rs, arena.rs's two Stmt<->NodeKind::While conversions, codegen.rs (mirrors Loop's Some/None label-prefix branch), engine/prelude.rs and frontend/lowerer/runtime_support.rs's synthetic While constructors (label: None, both self-authored helper loops with no source label), and the read-only traversal matches in interproc/{length,pointer}_lattice.rs, interproc/string_params.rs, engine/rules/inline_temps.rs (all just added `..` or `, ..`, no logic change).

Payoff: LoopToWhile (slate-04q.85.2) no longer requires label: None on the Loop it's converting -- it now carries the Loop's label straight through to the While. This is sound because Rust's `continue` inside a `while` already re-checks the condition before restarting, which is exactly what a C `continue` inside a head-tested while/for loop needs -- unlike `for`, which needs the LabeledBlock-wrapping workaround to still run its step on continue, `while` never did. continue_while.c (labeled, real continue) now converts: `'__loop0: while i < n { i += 1; if ... }` instead of staying in raw `loop { if !cond { break } ... }` form. Regenerated its REWRITES FileCheck block.

Verified: full rewrites profile 93/93 (incl. generated_differential across gcc-torture/chibicc/c-testsuite), full lowering profile 10/10 (frontend file touched), cargo clippy clean, cargo fmt clean (only reflowed string_params.rs line wrapping, no logic change).
