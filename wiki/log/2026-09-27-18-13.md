# Accept symbolic immediates in asm alternative selection

_2026-09-27 18:13:06_

Fixed slate-parser-25m.22. Alternative selection only took an immediate whose value was an integer constant, so "i"(&g) and "i"(fn) rejected every alternative.

Oracle (clang 22, gcc 16, -fno-pie): these are accepted: &global, &static_local, functions, array decay, string literals, &arr[2] ($arr+8), &s.b[1] ($s+8), (char*)&g+3, &g-1, and pointer-width casts ((long)&g; (int)(long)&g on i686). These are rejected: &automatic, non-constant indices, narrowing casts, and "n"(&g). A thread-local is accepted by gcc and rejected by clang. Functions are rejected by both under the default PIE; slate does not model PIE, so it accepts them (permissive). AArch64 accepts symbols too.

Model: "i" (and so "g") now offers classes [imm | sym]; "n" and the target immediate letters offer only imm. Lowerer::symbol folds a value to AsmSymbol { binding, offset } through AddressOf, Array/FunctionDecay, Deref, Field (non-bitfield, via the new TypeResolver::field_offset), constant Index and PointerOffset, and pointer-width Convert. A binding qualifies with static storage (Thread only under gcc) or function type. String literal globals are not in entities, so the storage lookup falls back to module.globals. When the class is selected, the input becomes AsmOperandKind::Symbol and prints sym<offset=N>(%id). The class ranks with the immediate, so the gcc guality fixtures' "g"(&a) now selects sym instead of reg, matching both compilers' $a.

Filed slate-parser-25m.23: integer_constant does not fold reads of const statics ("i"(k)), which both compilers accept.

Fixtures: sema/ir_asm_symbols.c, ir_asm_symbols_gcc.c (TLS), ir_asm_symbols_i686.c. Updated ir-spec and ir-grammar.
