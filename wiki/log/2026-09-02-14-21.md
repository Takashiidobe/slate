# Switch case values above i128::MAX on native u128 selectors

_2026-09-02 14:21:15_

slate-c6jq.1. `unsigned _BitInt(128)` lowers its selector to a native Rust `u128`,
but `case_value_pattern` read case values through `Attr::as_int() -> Option<i128>`,
so any value above `i128::MAX` bailed the whole switch to
`todo!("cir.switch: unrepresentable case value")`.

`Attr::CirInt { value: String }` already carries the full-precision decimal, so no
new value representation was needed. Added `case_value_decimal` (CirInt only, kept
separate from `case_value_digits` so the still-dead bitint path stays dead until
slate-c6jq.2) and a u128 fallback in `case_value_pattern` / `case_range_pattern`.

`Pattern::InclusiveRangeU128 { start: u128, end: u128 }` is new: GNU `case a ... b`
above `i128::MAX` has no representation in the existing i128-keyed variant. Codegen
prints it identically. Only `codegen::pattern` matches `Pattern` exhaustively, so the
variant cost one arm.

`pattern_range::fold` now folds in u128 space when every alternative is
`Pattern::U128`, else in i128 space as before — otherwise making `U128` reachable
would have left huge consecutive runs unfolded while small ones folded. Run grouping
is shared through `fold_runs`, generic over the key type.

Fixture `tests/fixtures/switch_case_u128_values.c` (discrete values, a GNU range, and
a foldable run, all above `i128::MAX`).
