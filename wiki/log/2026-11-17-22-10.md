# slate-3amj.38 -fno-delete-null-pointer-checks: null checks after a deref were folded by LLVM; lower to slate_support::opaque_is_null

_2026-11-17 22:10:30_

- bead: slate-3amj.38
- kind: feature
- area: crates/slate-parser/src/ir
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/vendor/slate-support

Outcome: under -fno-delete-null-pointer-checks, translated null checks survive optimization after a dereference, as they do with clang and gcc.

Gap: the flag was recorded (`CodegenOptions::delete_null_pointer_checks`) and
ignored. The kernel builds with it. clang emits "null-pointer-is-valid" on
every function. rustc has no such knob, so LLVM treated `*p` as proof that
p != null and deleted a later `p.is_null()` (verified with rustc -O).

Rejected designs (measured with rustc -O --emit=llvm-ir):
- read_volatile / write_volatile through the pointer: LLVM still folds the
  later is_null() (`load volatile` then `ret`). The Rust docs allow volatile
  access at address 0, but that does not stop the fold.
- core::hint::black_box(p).is_null(): keeps the check but spills p to the
  stack and is documented as best effort.

Before (C `int x = *p; if (!p) return -1; return x;`):
    let value: i32 = unsafe { *p };
    if p.is_null() { return -1; }      // folded away by LLVM
After:
    let value: i32 = unsafe { *p };
    if !(!::slate_support::opaque_is_null(p)) { return -1; }

Implementation:
- Parser: `Module.null_pointer_is_valid` = !delete_null_pointer_checks, set in
  sema/module.rs and sema/types.rs, printed as `null_pointer_is_valid;` after
  `nostdinc;` (ir-grammar.md).
- slate_support: `opaque_is_null<T: ?Sized>(*const T) -> bool` casts to
  *const u8 and passes it through `asm!("/* {0} */", inout(reg) ..,
  options(pure, nomem, nostack, preserves_flags))`. `pure` stays: what keeps
  the check is the opaque output, and pure still lets LLVM CSE or hoist the asm.
  No cfg fallback: x86_64, i686, aarch64 and armv7 all keep the cmp.
- Lowering (lowerer/values.rs, `opaque_null_operand`): `eq`/`ne` of a data
  pointer against `null` becomes `opaque_is_null(p)` / `!opaque_is_null(p)`.
  Accesses stay plain loads and stores. Function pointers (Option<fn>) are
  untouched.

Fixtures: crates/slate/tests/fixtures/no_delete_null_pointer_checks.c (passes
on x86_64, i686, aarch64 and armv7). Parser driver_flag_effects.c (clang and
gcc) gained the IR line.

Limits: `!p` prints as `!(!opaque_is_null(p))` (the null_compare double-not fold
does not see the call). Ordered comparisons against null are not laundered.
See: ir::Visitor rename (wiki/log/2026-11-17-21-52.md).
