# Implement MS bit-field record layout for ms_struct

_2026-09-25 19:59:57_

Records marked `__attribute__((ms_struct))`, or defined under `#pragma ms_struct on`
without `gcc_struct`, now lay out with the MS bit-field algorithm instead of an
Itanium layout (attribute) or `Unsupported` (pragma). slate-parser-dyd.29.

Ported from clang's ItaniumRecordLayoutBuilder `IsMsStruct` path, not the
bead's summary, because the probes showed rules the summary missed:
- `MsUnit::place` tracks the open unit (its bit size and unfilled bits). A
  bit-field joins the unit only if the type sizes are equal and it fits;
  otherwise a new unit starts at the end of the old one, aligned to the unit
  size. The data size jumps to the end of the unit, so a following `char`
  lands after the whole `int`.
- A zero-width bit-field is ignored after a non-bit-field. After a bit-field
  it ends the unit and raises record alignment even when unnamed; the ARM
  `zero_width_bitfield_aligns_record` flag does not apply here.
- `packed` leaves ms bit-field alignment alone, but `#pragma pack` caps it
  (and is ignored for zero width). In a union, bit-fields have alignment 1 and
  occupy their full type size.
- Scalar non-bit-fields (not enum, complex, `_BitInt` or `_Atomic`; arrays
  stripped) are aligned to their size: i686 `long long` and `double` become
  8-aligned. A scalar with a non-power-of-two size (i686 `long double`) is
  `Invalid`, matching clang's default-error -Wincompatible-ms-struct.
- Bit units are whole declared-type units, one run per unit, as in clang's
  discrete bit-field codegen.
The width checks moved ahead of the branch so both algorithms share them.

Verified: 36 probe records on x86_64 and i686 matched clang 22 layouts
(check_record_layout.py; its -complete dump predates trailing attributes, so
S23 was confirmed with _Static_assert). bf-ms-attrib (12) and bf-ms-layout-5
(32) now match their own sizeof guards; bf-ms-layout-3 was unchanged.
Fixtures: sema/ir_ms_struct_layout.c and
sema/i686-unknown-linux-gnu/ms_struct_layout.c (NPOT error config).
Microsoft target layout (*-windows-msvc) remains separate and missing.
