# Slate frontend long double through the LongDouble shim

_2026-09-30 22:07:00_

slate-p58o.4.2: the slate frontend now lowers x86_64 long double (IR f80).

- Moved the f80 runtime (LongDouble prelude, \__slate_f80_\* shim decls, cast shim names, bridge type tags) from legacy frontend/lowerer/runtime_support.rs into slate_parser_frontend/long_double.rs. Legacy imports it from there.
- lower*type: f80 -> LongDouble. The prelude and the \_\_slate_f80*\* extern decls are emitted when any f80 type is lowered.
- Constants: Number::FloatBits -> LongDouble([10 LE bytes]). f80 truth tests compare against a zero literal.
- Arithmetic, negation, and comparisons use the prelude operator impls. Convert with an f80 side -> **slate*f80_from*<t>/**slate*f80_to*<t>. f80 conversions are not const initializers.
- Extern calls whose return or argument holds f80 by value (including inside structs) -> C bridge **slate\_<callee>**r<ret>\_<tags>. The harness renders and links it from the name, as the CIR path does. The direct extern decl is dropped.
- Barriers: variadic callees not in function_identity::Known, non-pointer aggregate bridge args, va_arg of long double.
- Fixtures: new x86*64/long_double_shim_basics.c; promoted gnu_libm, long_double*{comparisons,pointer*out,struct,variadic}, x86_64/long_double*{aggregate_increment,extern_sin,f80_arithmetic,literal_edge,literal_macro,literal_precision,strtold_f80}, 7 gcc-torture, and 2 gcc-dg (c23-float-1, c23-float-12).
- printf_specifier_survey now differs only on a %p stack address (slate-p58o.4.6).
- Follow-ups: slate-p58o.4.3 va_arg, .4.4 cf80, .4.5 bridge prototypes.
- Validation: cargo nextest r --release --profile slate is green (8/8).
