# Re-enable FileCheck on generated Rust with target prefixes

_2026-10-16 18:33:16_

Epic slate-5vj0 restores FileCheck on Slate's generated Rust, suspended since the clang-ir to slate-parser move (slate-p58o.7.2, c8ad97815).

slate-5vj0.1:
- tests/support/filecheck.rs restored from c8ad97815^ with the LOWERING/REWRITES Profile removed. Rewrites always run, so prefixes describe configuration: CHECK for every configuration, plus the uppercased target triple (X86_64-UNKNOWN-LINUX-GNU, I686-UNKNOWN-LINUX-GNU). CHECK-LABEL function-group semantics unchanged; SLATE_FILECHECK overrides the binary.
- run_cases_for_target runs FileCheck after translation, so generated_differential, i686_differential, and the unsupported ratchet enforce checks. Failures classify as 'filecheck' in triage.
- fputs_stderr_plain carries the first checks; both the CHECK and the triple-prefixed check were shown to fail on a wrong pattern. It pins the raw fputs call: no libc idiomization fires on slate-parser output yet.
- All LOWERING/REWRITES/COMMON blocks and @lowering/@slate-lowerer markers stripped from 62 fixtures (~16k lines) instead of migrated; @rewrite-fn markers kept for the regen tool. Pre-strip blocks in git are the reference for what rewrites used to produce (slate-5vj0.4).

Next: port update_filecheck.py with Rust-fn-name lookup (slate-5vj0.2). Later: flavor/ISA/stdlib prefixes and per-flavor dirs like tests/fixtures/msvc/.
