# slate-f2zu.14.9 asm: i686 ebx operands/clobbers, split =b/b rbx operands, %a on fixed registers, defined-builtin module asm symbols

_2026-11-14 13:41:31_

- bead: slate-f2zu.14.9
- kind: feature
- area: crates/slate/src/frontend/lowerer/asm.rs
- corpus: linux

Outcome: i686 asm binds ebx operands and clobbers directly, x86_64 asm accepts a
separate "=b" output and "b" input, `%a` works on fixed-register operands, and
module-level asm may name a libc builtin that the unit defines itself.

Symptom: 16 kernel functions hit asm barriers:

- `ebx operand` / `ebx clobber` (i386 only):
  arch/x86/boot/{cpuflags,cpucheck,pm,video}.c and the vdso32 `VDSO_SYSCALL2`
  fallbacks in asm/vdso/gettimeofday.h.
- `second rbx operand`: vmware_hypercall_slow / vmware_hypercall3, written as
  `"=b"(rbx)` plus `"b"(in1)`.
- `explicit register modifier Some('a')`: vdso common/vfutex.c:37 `%a[lock]`
  with `[lock] "D"(lock)`.
- `builtin symbol operand`: EXPORT_SYMBOL module asm (`.quad snprintf`) in
  lib/vsprintf.c, and `abort` in kernel/exit.c. The kernel defines both
  functions itself.

Reproducer:

```c
static unsigned long f(unsigned long in) { unsigned long b; __asm__("" : "=b"(b) : "b"(in)); return b; }
static unsigned g(unsigned *p) { unsigned v; __asm__("movl %a1, %0" : "=r"(v) : "D"(p)); return v; }
int abs(int x) { return x < 0 ? -x : x; }
__asm__(".quad abs");
```

Cause:

- The ebx barriers were left over from x86_64. rustc forbids rbx only on x86_64;
  on i686 it accepts `"ebx"` (it is esi that i686 reserves). This was checked
  with rustc for i686, both with and without PIC.
- The x86_64 rbx save/xchg slot (`saved_rbx`) allowed only one bx operand per
  asm.
- `explicit_reference` took only no modifier or `V`.
- `asm_symbol` rejected any function carrying `c_builtin` metadata, even one
  defined in the unit.

Fix (crates/slate/src/frontend/lowerer/asm.rs):

- On i686, an explicit bx operand is pinned as `"bx"`, and a bx clobber becomes
  `out("bx") _`.
- On x86*64, a second bx operand is merged into the existing xchg-wrapped `reg`
  slot: an Out plus an In become one InOut, and an In (InOut with output
  `*`) plus an Out become one InOut. Any other combination stays `second rbx
  operand`.
- `asm_template` writes `%a` on `Slot::Register` as `(%rdi)` (AT&T) or `[rdi]`
  (Intel), using a pointer-width name.
- `asm_symbol` now rejects only intrinsics and builtins that are `is_extern`.

Regression tests:
crates/slate/tests/fixtures/i686/asm_ebx_operands_and_clobber.c and
crates/slate/tests/fixtures/x86_64/asm_split_rbx_operands_and_address_modifier.c.
All 10 kernel TUs listed above now show no asm barriers.

Limits: two bx inputs, or two bx outputs, in the same x86_64 asm are still a
barrier.
