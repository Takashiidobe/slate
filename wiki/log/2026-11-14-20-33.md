# slate-f2zu.14.29 runtime_export: memcpy/memcmp/strlen/malloc definitions rejected by invalid_runtime_symbol_definitions as C-unwind; exported through extern C libc-typed wrappers

_2026-11-14 20:33:47_

- bead: slate-f2zu.14.29
- kind: bug
- area: crates/slate/src/frontend/lowerer/functions.rs
- area: crates/slate/src/frontend/lowerer.rs
- area: crates/slate/src/main.rs
- area: crates/slate/src/backend/rust_ast.rs

Outcome: an exported C definition of a rustc runtime symbol (memcpy, memmove,
memset, memcmp, bcmp, strlen everywhere; also malloc, realloc, free, exit, open,
read, write, close off Windows) compiles: the body stays a private Rust fn with
its translated types, and an `extern "C"` wrapper with the libc signature
exports the symbol; units that declare or define these names allow
`suspicious_runtime_symbol_definitions`.

Symptom (linux check stage, arch_x86_boot, arch_x86_boot_m16, lib: 13 errors):
`invalid definition of the runtime memcmp symbol used by the standard library`
for
`#[unsafe(no_mangle)] extern "C-unwind" fn memcmp(s1: *const (), s2: *const (), len: u32) -> i32`,
likewise strlen, bcmp, memset, memmove, memcpy, malloc(int), free.

Reproducer (library mode, which exports): void *memcpy(void *dest, const void
*src, unsigned long n) { ... } int memcmp(const void *s1, const void \*s2, int
len) { ... }

Cause: rustc's deny-by-default `invalid_runtime_symbol_definitions` rejects
every `C-unwind` definition of these names, even with exact libc types (probed
on x86_64, i686, aarch64, windows-msvc; full list found by probing all 864 libc
catalog functions plus bcmp). std and compiler-generated calls assume they never
unwind. Type mismatches (u64 vs usize, *mut () vs *mut c_void, malloc(i32)) are
only the warn-level `suspicious_runtime_symbol_definitions`. `lower_bodies` gave
every export `Abi::CUnwind`.

Fix:

- `rust::Abi::C` (spelled "C").
- `functions::runtime_symbol(name, os)` holds the libc signature per name
  (c_void/c_char pointers, usize, isize, core::ffi::c_int); the windows subset
  is the six mem/str names.
- `functions::runtime_export` builds
  `#[unsafe(export_name = "<symbol>")] unsafe extern "C" fn __slate_export_<name>(libc params) -> libc ret`,
  casting each argument to the body's type and the result back, like the main
  shim. The definition loses its export and keeps its name, so in-unit callers
  are unchanged. Arity/return mismatches and variadic definitions (open) fall
  back to `extern "C"` in place.
- `Dependencies::runtime_symbols` (set by such definitions and by extern
  declarations of these names) adds
  `#![allow(suspicious_runtime_symbol_definitions)]`; project mode carries it to
  lib.rs or the executable root.

Regression test: crates/slate/tests/fixtures.library/runtime_symbol_definitions
(memcpy/memset/memcmp(int len)/bcmp/strlen exported from a staticlib, called
from native C). FileCheck regenerated for asm_label_function.c and
msvc/conditional_global_initializers.c (new allow line only).

Kernel: re-translated only the three shards in ~/slate-translated/slate-linux;
cargo check is now clean for all three (8, 2, 3 errors to 0).

Limits: open/read/write/close are pthread cancellation points; a translated
program defining them aborts instead of unwinding on cancellation, since rustc
forbids C-unwind there. See: slate-3f8g.5.7, slate-f2zu.14.28
