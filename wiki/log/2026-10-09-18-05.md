# slate-dghn.35: lower alloca to a thread-local bump stack

_2026-10-09 18:05:09_

alloca, _alloca, __builtin_alloca and __builtin_alloca_uninitialized now lower
to __slate_alloca::alloca(size), backed by a thread-local bump stack emitted as
a support module (src/frontend/support/alloca.rs) when a unit uses alloca.

Runtime: a list of 1 MiB blocks (larger for oversized requests) with a
(block, offset) top. Every allocation is 16-aligned (clang's suitable alignment
for alloca on all our targets) and zero-filled. Blocks above the top are kept
for reuse and replaced only when too small for a request.

Lifetime: any function that lowers an alloca starts with
let __slate_alloca_mark = __slate_alloca::Mark::new(); whose Drop restores the
saved top on every return path. Loop allocas accumulate until return, as in C.
Chose this over a per-function Vec<Vec<_>> arena so quickjs's per-call alloca
in JS_CallInternal is a pointer bump, not a malloc/free pair.

dead_store::eliminate turned the unused guard let into a bare expression
statement (dropping it immediately), so it now exempts Mark::new initializers.

Known gaps: longjmp across a marked frame skips its Drop (Rust UB for frames
with destructors; the outer mark still reclaims the memory).
__builtin_alloca_with_align stays unsupported (no corpus users). chibicc
alloca.c stays unsupported: it asserts adjacent downward stack layout.

Fixture: tests/fixtures/builtin_alloca.c (const/dynamic/uninitialized, loop,
branch escape via struct, ternary, alloca(0), alignment, recursion, blocks
overflow + reuse). Promoted: gnu_libc_platform (strdupa/strndupa), gcc-torture
20021113-1, 20070824-1, alloca-1, frame-address, pr36321; gcc-dg pr85388-4,
split-4.
