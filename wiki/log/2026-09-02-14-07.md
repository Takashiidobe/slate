# BitInt switches cannot reach the range-fold rule

_2026-09-02 14:07:28_

Checked whether `pattern_range::fold` can corrupt wide `_BitInt` switches by
collapsing into `Pattern::InclusiveRange { start: i128, end: i128 }`. It cannot,
but not for the reason the rule itself suggests — the gate is upstream.

`Attr::as_int()` returns `Option<i128>`. `switch_case` in
`src/frontend/lowerer/cir_ops.rs` bails on any value that does not fit, and
`lower_switch` (`src/frontend/lowerer/control_flow.rs:145`) then emits
`todo!("cir.switch: unrepresentable case value")` for the whole switch. So a
pattern the fold can see has already round-tripped through i128 losslessly.

Measured, not inferred:
- `_BitInt(128)` lowers the selector to plain `i128`; the fold fires and is exact.
- `_BitInt(72)`, `_BitInt(200)`, `_BitInt(256)` lower the selector to
  `bitint::BInt<N,..>` and emit `todo!()` — no match, no patterns.
- `unsigned _BitInt(128)` with case values above `i128::MAX` also emits `todo!()`,
  so `Pattern::U128` is unreachable from a switch and the rule's `i128::try_from`
  bail is belt-and-braces.
- `unsigned long long` values above `i64::MAX` fold correctly
  (`18446744073709551610..=18446744073709551612` on a `u64` scrutinee).

`tests/fixtures/switch_case_range_fold_wide.c` pins the two widths that do lower.
The `todo!()` gap is filed as slate-c6jq.
