# slate-f2zu.14.40.10 zero_init::fold: impure first write moved above cleanup guard constructor let, ps2_sendbyte deadlocked on serio->lock at boot

_2026-11-16 14:59:00_

- bead: slate-f2zu.14.40.10
- kind: bug
- area: crates/slate/src/backend/engine/rules/zero_init.rs
- corpus: linux

Outcome: `zero_init::fold` no longer moves an impure first write (a call) above
an intervening `let` whose initializer has side effects, so cleanup-guard
constructors run before the guarded call again; the translated kernel boots to
busybox.

Symptom: translated kernel hung at ~1.07-1.5 s (point varied by run and CPU
count). QEMU monitor: CPU 0 at a fixed RIP in `queued_spin_lock_slowpath` with
IF clear. Stack: serio_handle_event -> psmouse_connect -> synaptics_detect ->
cypress_send_ext_cmd -> cypress_ps2_ext_cmd -> ps2_sendbyte.

C (drivers/input/serio/libps2.c):

```c
int ps2_sendbyte(struct ps2dev *ps2dev, u8 byte, unsigned int timeout) {
	int retval;
	guard(serio_pause_rx)(ps2dev->serio);
	retval = ps2_do_sendbyte(ps2dev, byte, timeout, 1);
	return retval;
}
```

Translated:

```rust
let retval: i32 = ps2_do_sendbyte(ps2dev, byte, timeout, 1u32);
let mut __UNIQUE_ID_guard_459 = class_serio_pause_rx_constructor(unsafe { (*ps2dev).serio });
```

ps2_do_sendbyte expects the lock held: it unlocks, waits, relocks and returns
holding it; the guard constructor then took `serio->lock` again.

Reproducer: crates/slate/tests/fixtures/zero_init_cleanup_guard_order.c
(DEFINE_GUARD-shaped class constructor plus `__attribute__((cleanup))`, call
after the guard reads the lock state).

Cause: emit-slate-ir order is correct (`let retval;`, guard `let` with call
init, `write retval = call`). `intervening_ok`
(crates/slate/src/backend/engine/rules/zero_init.rs) let an impure value cross
any `NodeKind::Let`, ignoring its init.

Fix: an impure value crosses a `Let` only when its init is absent, zero
(`expr_is_zero`), or `expr_is_pure_and_closed`.

Kernel check: retranslated `_packed_r7` only, relinked; boot reaches the busybox
shell.
