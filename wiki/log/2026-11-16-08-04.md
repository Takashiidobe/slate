# slate-f2zu.14.40.3 pp_diff kept_args: SEMANTIC_FLAGS allowlist dropped -fno-strict-overflow/-fwrapv, kernel vsnprintf end = buf + INT_MAX wrap check folded away

_2026-11-16 08:04:27_

- bead: slate-f2zu.14.40.3
- kind: bug
- area: crates/slate-parser/tools/pp_diff.py
- corpus: linux

Outcome: the corpus harness forwards every compile_commands flag to slate (only
the compiler, -c/-S/-E, -o, -M\* dependency flags, -Xclang pairs and the source
are dropped); the SEMANTIC_FLAGS allowlist is gone.

Symptom: the translated kernel page-faulted right after 'Booting the kernel' in
vsnprintf (end[-1] = 0 with end = 0x3003a37). sprintf passes size = INT_MAX,
`end = buf + size` wraps past the top of the address space, and the C
`if (end < buf)` clamp relies on -fno-strict-overflow. slate emitted
`buf.add(size as usize)` and LLVM folded the check away.

Cause: crates/slate-parser/tools/pp_diff.py kept_args only forwarded an
allowlist of "semantic" flags. -fno-strict-overflow (every kernel unit, 3580
corpus commands) and -fwrapv (1384 commands) were dropped, so the
wrapping_offset lowering (slate-3amj.37) never ran in the corpus.

Fix: kept_args keeps every argument except outputs and dependency files.
Deciding which flags affect codegen is slate-parser's job, not a harness
allowlist.

Limits: slate-parser still errors on unknown options, so a project with a flag
it does not model now fails translation instead of silently losing the flag.
slate-f2zu.14.40.3 tracks warning and ignoring them.

See: slate-f2zu.14.40.3, slate-3amj.37, slate-f2zu.14.40.
