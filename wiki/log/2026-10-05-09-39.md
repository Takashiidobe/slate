# format/nonnull/alloc_size/alloc_align on function-pointer declarators

_2026-10-05 09:39:07_

slate-parser-6x05.38.12. list_sort.h 'typedef int __attribute__((nonnull(2,3))) (*list_cmp_func_t)(...)' and dis-asm.h 'typedef int (*fprintf_ftype)(...) __attribute__((format(printf,2,3)))' warned -Wignored-attributes (fatal under the kernel's -Werror) because inapplicable() treated these as functions-only by Subject.

- attributes.rs::function_type_attribute lists the type-dependent attributes (noreturn, format, nonnull, alloc_size, alloc_align) with spelling and subject text. inapplicable() only warns for them on a struct/union definition; this also restores the noreturn-on-record warning dropped in .38.19.
- check_function_type_attributes now takes DeclaredAs { Function, Parameter, Other } and applies per-attribute rules, measured on both oracles:
  - format/nonnull/alloc_size/alloc_align: function or pointer to function (typedefs included); (**p) and arrays warn. Same in clang and gcc.
  - nonnull on a parameter: clang accepts any pointer and warns 'pointer arguments' otherwise (new warning); gcc uses the function-pointer rule.
  - noreturn rules unchanged from .38.19.
- Fixtures {clang,gcc}/linux/x86_64/function_pointer_prototype_attributes.c: warning lines match both oracles (clang also by column).
- Kernel: lib/list_sort.c and tools/objtool/disas.c parse.
- Follow-ups: slate-parser-6x05.48 (sentinel, returns_nonnull, const differ per flavor on function pointers), slate-parser-6x05.49 (pointer-chunk attributes never checked; gcc warns).
- Wiki: attributes.md applicability.
