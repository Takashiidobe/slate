# slate-f2zu.14.34.27 Guard::drop: cleanup clac out of line, objtool redundant UACCESS disable in kernel cleanup closures

_2026-11-16 20:45:52_

- bead: slate-f2zu.14.34.27
- kind: bug
- area: crates/slate/vendor/slate-support

Outcome: the translated kernel's objtool run has no UACCESS warnings left; `slate_support::Guard::drop` is `#[inline]`, so cleanup handlers such as `user_access_end()` (clac) inline back into the scope that ran `stac`.

Symptom: after slate-f2zu.14.40.13/.15 the relinked vmlinux.o had 58
`.altinstr_replacement: redundant UACCESS disable` and 1
`futex_wake_op: call to slate_support::Guard::drop with UACCESS enabled`.
Native vmlinux.o has 0 with the same objtool flags.

Cause: kernel scoped user-access guards put `user_access_end()` in a
`__attribute__((cleanup))` handler that clang inlines. slate lowers cleanup to
`Guard(&mut dyn FnMut())` (slate-f2zu.14.40.14), and `Guard::drop` lives in
slate-support, a separate crate. With `-Zcross-crate-inline-threshold=never`
for slate_crate and one CGU per unit, the non-generic `drop` was never
inlined, so every clac ran in an out-of-line function (closure or its
FnOnce::call_once shim), and objtool saw the clac outside the stac region.

Fix: `#[inline]` on `impl Drop for Guard<'_> { fn drop }` in
crates/slate/vendor/slate-support/src/lib.rs, which makes the body available
to the caller's CGU.

Verification: full `e2e.py linux --from translate` at eee56c433 plus this
change: link ok, check_groups passes, objtool 60 -> 30 with all 59 UACCESS and
native_machine_emergency_restart (slate-f2zu.14.34.34) gone. The 30 left are
new and tracked separately (slate-f2zu.14.34.35 panic handler loop,
slate-f2zu.14.34.36 BUG() split across goto states). Boot: busybox, loopback,
initcall/.init.setup tables identical to native, dmesg matches modulo noise.

Regression test: none at fixture level (objtool-only property); the kernel
objtool count is the check.

See: slate-f2zu.14.40.14 (Guard lowering), slate-f2zu.14.40.13.
