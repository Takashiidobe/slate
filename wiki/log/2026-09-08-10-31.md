# Port libc ABI oracle matrix from Python to Rust

_2026-09-08 10:31:37_

Ported tools/libc-abi-matrix.py and tools/libc-abi-probe.py into native Rust (slate-b66b.5.1 target/config resolution, slate-b66b.5.4 the compile-only test), retiring both Python scripts.

New tests/support/libc_probe.rs: reuses tests/support/libc_shim.rs's existing Architecture/LibcVariant enums and TestConfig::preprocessor_defines() (no need to re-derive Slate's define set) rather than inventing a parallel arch/libc model. Adds ProbeConfig::resolve() (a straight port of the Python matrix's config(): musl/glibc sysroot+linker resolution with the same env var names and local host defaults, musl aarch64's special crt1.o/crti.o/crtn.o static-link path, QEMU lookup with SLATE_LIBC_QEMU_<ARCH> override) plus run_probe() (compile probe.c -> link -> run, optionally under QEMU, parse tab-separated kind/name/value records) and compare_records().

Moved the shared probe source from tools/probes/linux-libc-abi.c to tests/fixtures.abi-probe/linux-libc-abi.c (its own fixture directory, room to split further later) via git mv; updated the (now-removed) Python script's path before deleting it.

tests/libc_abi_matrix_suite.rs rewritten in place from the interim Python-subprocess wrapper (added under slate-b66b.4) to call libc_probe directly -- no subprocess, no JSON serialization round-trip. Same SLATE_LIBC_ABI_LIBC/ARCH/FAMILY env-var selectors as before. Deleted tools/libc-abi-matrix.py and tools/libc-abi-probe.py; updated wiki/concepts/cross-target-toolchains.md to describe the Rust invocation instead of the python3 commands.

Verified: focused musl/x86_64/pthread run passes; full unrestricted matrix reproduces the exact prior Python baseline (8 targets, 4117 records, 0 failures) in ~1s; cargo clippy clean (fixed one type_complexity warning with a type alias); full cargo nextest --release --profile libc green, 38/38 in ~7s.
