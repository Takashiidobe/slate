# AArch64 asm: I/J/K/L/M/N/Y/Z immediate constraints, Q memory, Upl/Upa scoped

_2026-09-07 11:27:04_

slate-3f8g.4.16.7-9. I/J/K/L/M/N already routed to Constant via the
pre-existing (arch-unguarded) ConstantEligible atom set. Added Y/Z
(Arm64-gated). Z lowers fully; Y is parsed but known_arith_value is
int-only (no float sibling), so a real Y operand still errors - follow-up
needed. S is out of scope: CIR loses symbol identity through an S operand
(get_global + load, not an address). Fixing S surfaced a real bug:
a/b/c/d/S/D FixedReg letters matched unconditionally regardless of
target_arch, so AArch64's S silently resolved to x86's esi register name.
Gated all six behind target_arch.is_x86().

Q (exclusive/atomic memory, no offset) now maps to Constraint::Memory on
Arm64 (was colliding with x86's ByteAddressableAbcd letter). Slate's
existing address-materialize-in-register scheme already satisfies Q's
no-offset requirement. The multi-referenced-memory-slot restriction blocks
the canonical ldxr/stxr idiom (one +Q tied to both instructions); worked
around in the fixture with two independent +Q operands over the same C
lvalue instead of one slot referenced twice.

Ush rejected by SLATE_CLANG's CIR frontend before CIR generation, same
category as ARM32's k. Upl/Upa (SVE predicate regs): declined via audit -
no real-world usage found, Arm's own guidance says SVE predicate values
can't be ordinary asm outputs (clobber-only, like x86 y), and Slate has no
scalable-vector representation anyway.

Also: the installed reference clang (22.1.8, differential ground truth,
distinct from SLATE_CLANG) rejects the only legal Z value (0) and any Y
value as compiler bugs - gcc accepts both. Blocks differential coverage of
Z/Y independent of the known_arith_value gap.

Fixtures: asm_aarch64_immediate_constant_constraints.c (I/K/L),
asm_aarch64_exclusive_memory_constraint.c (Q). Wiki:
inline-asm-support.md AArch64 section updated.
