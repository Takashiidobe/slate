# slate-3amj.57 pointer_lattice: wrapping_offset (-fno-strict-overflow) not counted as pointer arithmetic, written params lifted to &T (kernel hid-samsung E0594)

_2026-11-16 09:03:36_

- bead: slate-3amj.57
- kind: bug
- area: crates/slate/src/backend/interproc/pointer_lattice.rs
- corpus: linux

Outcome: pointer_lattice treats wrapping_offset as pointer arithmetic, so under
-fno-strict-overflow/-fwrapv a parameter indexed or written through
wrapping_offset stays a raw pointer instead of being lifted to &T.

Symptom: once the corpus harness forwarded -fno-strict-overflow (b184900cf), the
kernel's drivers**packed and arch_x86**packed shards failed to build:
hid*samsung.rs `fn samsung_irda_report_fixup(..., rdesc: &u8, ...)` with E0594
`cannot assign to data in a *const pointer`on`*(rdesc as *const
u8).wrapping_offset(176) = 255`, E0070 on `rdesc as *const u8 =
samsung_irda_report_fixup(..)`, E0308 on `.report_fixup =
Some(samsung_report_fixup)`; pgtable.rs stored through `(pmds as *const _mut
_).wrapping_offset(i)`.

Reproducer (minimal C, -fno-strict-overflow):

```c
static u8 *inner(u8 *rdesc, unsigned *rsize) {
  if (*rsize == 6 && rdesc[4] == 0x40) { rdesc[1] = 0xff; }
  return rdesc;
}
```

Before: `fn inner(rdesc: &u8, ..)` and
`*(rdesc as *const u8).wrapping_offset(1) = 255` (E0594). After:
`fn inner(rdesc: *mut u8, ..)` and `*rdesc.wrapping_offset(1 as isize) = 255`.

Cause: slate-3amj.37 (11c7252d5) changed the lowering to emit wrapping_offset,
but crates/slate/src/backend/interproc/pointer_lattice.rs matched pointer steps
by name ("add" | "offset" | "wrapping_add" | "sub" | "wrapping_sub") at five
sites: try_offset_alias, the write-through-offset check, observe_offset,
pointer_root, and the rewrite_expr receiver rewrite. wrapping_offset was missing
from all of them. The standalone fixture from .37 never hit this because its
pointers were not liftable.

Fix: one is_pointer_step predicate (adds wrapping_offset) used at all five
sites.

Intentionally unchanged: length_lattice (offset/add matches),
rules/ptr_offset.rs (offset -> add) and rust_ast collect_offset_calls still skip
wrapping_offset. Recognizing it there would rewrite to slice indexing or .add
and reintroduce the no-wrap assumption the flag removes; the cost is fewer
idiomatic rewrites under -fno-strict-overflow.

Regression test: crates/slate/tests/fixtures/no_strict_overflow_pointer_writes.c
(fn pointer callback that reassigns its param from a writer, store through
slots[i], read-only sum).

See: slate-3amj.37, slate-f2zu.14.40.3, slate-f2zu.14.40.
