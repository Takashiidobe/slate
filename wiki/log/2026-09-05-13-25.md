# just regen-* recipes take default aarch64/x86_64-gnu targets

_2026-09-05 13:25:55_

Added filecheck_targets to the justfile: a plain overridable variable
(--target X86_64-GNU=x86_64-unknown-linux-gnu --target
AARCH64-GNU=aarch64-unknown-linux-gnu) that regen-lowering-match,
regen-rewrites-match, regen-filecheck-match, and the bulk regen-lowering/
regen-rewrites/regen-filecheck recipes now pass to tools/update_filecheck.py
by default, so cross-target checks regenerate without typing the --target
flags by hand each time.

First attempt threaded targets through as a leading recipe parameter
(regen-lowering-match targets=filecheck_targets *pattern), which silently
broke positional calls like `just regen-lowering-match add` - "add" bound
to targets instead of pattern, leaving pattern empty. Reverted to the
existing corpus-style convention: filecheck_targets stays a bare variable,
overridden via `just filecheck_targets='...' regen-filecheck` rather than
a recipe argument. Keeps every existing call signature unchanged.

bionic/macos/msvc fixtures keep update_filecheck.py's own
default_targets_for_path inference (android/darwin/msvc triples) - the
private _regen-filecheck leaf recipe branches on path with a bash `case`
so the generic linux-gnu default never overwrites those. Verified via
`just --dry-run` on plain/override/bulk/bionic paths, then a real
`just regen-filecheck tests/fixtures/add.c` run, confirmed by
SLATE_DIFF_FIXTURE=add differential passing on both lowering and rewrites
profiles.
