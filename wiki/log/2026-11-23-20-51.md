# slate-yar4.55 proves_pair accepts bounded array prefixes and interior ranges

_2026-11-23 20:51:38_

- bead: slate-yar4.55
- kind: bug
- area: crates/slate-analysis/src/pointer
- area: crates/slate/src/frontend/lowerer

Outcome: a local fixed-size array passed to a count-bounded callee can lift to an exact Rust slice at each call site.

Symptom: passing a shorter prefix or an interior pointer kept the separate length parameter and could keep the pointer raw.

Reproducer:
    static int sum(const int *p, int n) {
        int total = 0;
        for (int i = 0; i < n; ++i) total += p[i];
        return total;
    }
    int a[4] = {10, 20, 30, 40};
    return sum(a, 4) + sum((a + 3) - 2, 2);

Cause: proves_pair classified only direct array decay with an exact full-extent count. lower_sized_borrow passed the entire safe array when dropping the companion length.

Fix: resolve a constant element offset relative to a fixed array, checking each intermediate offset. A shorter slice requires that every pointer read be a dereference through a counted loop index guarded by the length parameter. Size the caller's slice to the proven start and count, keeping the whole-array form for full extents.

Regression test: crates/slate/tests/fixtures/length_lift_array_ranges.c uses the same sum for whole-array, forward, subtracting, address-of-element, prefix and empty ranges. It also verifies a separate read at offset -1 stays valid.

Limits: dynamic caller offsets and heap subranges require additional proofs. Access before the slice start keeps a raw pointer.

See: slate-yar4.66 for lifting accesses before an interior pointer.
