# Build name resolution once in a Sema shared by analyze and lowering

_2026-09-28 17:14:43_

slate-parser-cc94.1 (first step of the cc94 NodeId side-table epic).

- New sema::Sema { unit, names, items }: names::resolve_items runs once in
  Sema::new. main builds it after parsing and calls sema.analyze(files), then
  sema.lower(files) for --dump-ir; --dump-ir-names reads sema.names().
- TranslationUnit::analyze became Sema::analyze; resolve_module became the
  private body behind Sema::lower, taking the Sema's names/items instead of
  re-running name resolution. names::resolve (now unused) removed.
- validate dropped its file-scope typedef/tag HashSets and collect_tag_names.
  'unknown type name' now comes from the resolver's per-item Unresolved
  { namespace: "typedef" } errors, which are scope-accurate (block-scope
  typedefs included). The 'unknown tag' check was dead: a tag reference is
  always valid C and names declares an incomplete tag for it.
- Wiki: diagnostic-severity, ir-spec, c-type-layer, ast-enum-touchpoints
  updated for the new entry points.

cc94 decomposed into cc94.1-.5. Deviation from the epic design, recorded in
cc94.4: a type table filled by lowering can't serve typeof/sizeof operands
(never lowered), so step 2 is a type-only expression pass, not lowering
recording types.
