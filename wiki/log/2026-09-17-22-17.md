# Gate predefined macros on standard mode and default to gnu23

_2026-09-17 22:17:05_

slate-parser-r37. Diffing `clang -dM` across c89..gnu23 showed the
standard-dependent predefine delta is not just `__STRICT_ANSI__`:

- `__STRICT_ANSI__`: defined iff strict. Gated on `__GNUC__` being
  present, not on CompilerFlavor -- clang targeting MSVC defines neither,
  so the flavor check was wrong and the macro tracks `__GNUC__`.
- `linux`, `unix`, `i386`: defined iff gnu. Hoisted out of the seven
  captured profile headers into `slate_gnu_namespace_{,i386_}linux.h`,
  layered only in gnu modes. A future `-dM` recapture must strip
  `^#define [a-z]` again.
- `__GNUC_STDC_INLINE__` / `__GNUC_GNU_INLINE__`: flips at the c99
  boundary. Interacts with the `inline` keyword gating in 47s.3.
- c23 only: `__CHAR8_TYPE__`, `__{CLANG,GCC}_ATOMIC_CHAR8_T_LOCK_FREE`,
  `__BOOL_DEFINED` (MSVC only), and ~32 `__*_FMT{b,B}__`.

The c23 set is derived from what the profile already holds rather than
tabulated per target: `__X_FMTb__` from `__X_FMTx__` with the conversion
char swapped, char8_t lock-free from `..._CHAR_LOCK_FREE`. Verified that
derivation against clang on all 7 targets. Rules are symmetric
(define-or-remove) so they hold whatever standard a profile was captured
at -- the clang profiles are gnu17 dumps, the gcc ones gnu23.

Nothing is baked into the profile headers: they stay verbatim `-dM`
captures so they can be regenerated and diffed, which is the same reason
`__STDC_VERSION__` was already patched in code.

Verified with a generated probe (`#`-stringifying every affected macro
into one string literal) across 7 targets x 10 standards: 70/70 match
clang. Widening it to every predefine leaves only standard-invariant
differences, i.e. pre-existing ones -- see the stringification bug filed
separately.

Default standard moved C23 -> Gnu23. No real compiler defaults to a
strict mode, and the whole fixture corpus was written against
effectively-gnu predefines; strict c23 as the default also tripped a
libc-shim inconsistency (`struct __ucontext` behind \_GNU_SOURCE while
ucontext.h declares users of it unconditionally).

update_filecheck.py now loosens file ids and node ids the way it already
loosened tag ids, via FileCheck numeric variables, so provenance survives
a predefine layer being added. Repeats inside one directive fall back to
`{{[0-9]+}}`, which FileCheck requires. 565 fixtures regenerated;
everything but 5 files is id renumbering.
