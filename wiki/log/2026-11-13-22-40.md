# slate-dghn.58.5 lower_extern: extern C functions with vector params/returns (SVML __m512) lowered via #[target_feature] Rust-ABI shim

_2026-11-13 22:40:26_

- bead: slate-dghn.58.5
- kind: feature
- area: crates/slate/src/frontend/lowerer
- flavor: clang
- target: x86_64

Outcome: extern C functions taking or returning vectors (NumPy's SVML `__svml_expf16(__m512)`) now translate instead of hitting the `vector C ABI` barrier.

Gap and why it mattered: NumPy's X86_V4 dispatch units call SVML entry points implemented in numpy's `.s` files. `lower_extern` rejected any extern with a vector in its signature; those were the last three builtin-class barriers in the NumPy clang sweep (`__svml_expf16`, `__svml_exp8_ha`, `__svml_exp2f16`).

Before (`-mavx512f`):

```c
extern __m512 vdouble16(__m512 x);
static float first_lane(void) { return _mm512_cvtss_f32(vdouble16(_mm512_set1_ps(1.5f))); }
```

`help: function vdouble16: vector C ABI`. Dropping the barrier alone is not enough: rustc rejects the call because `first_lane` lacks `avx512f` ("the function has type `Simd<f32, 16>` in its signature, which is passed in SIMD vector registers under the "C" ABI"). Unit-level `-mavx512f` does not put `#[target_feature]` on the unit's own functions.

After:

```rust
unsafe extern "C" {
    #[link_name = "vdouble16"]
    fn __slate_vabi_vdouble16(arg0: std::simd::Simd<f32, 16>) -> std::simd::Simd<f32, 16>;
}
#[target_feature(enable = "avx512f")]
unsafe fn vdouble16(arg0: std::simd::Simd<f32, 16>) -> std::simd::Simd<f32, 16> {
    return unsafe { __slate_vabi_vdouble16(arg0) };
}
```

Callers reach the shim through the Rust ABI, which rustc does not feature-check, so the zmm C ABI only appears inside the shim and matches the native asm.

Implementation: `Tables::vector_abi_feature` (target_features.rs) requires every vector pass in the declaration's `AbiSignature` to be `Direct` and returns `avx` (32 bytes) or `avx512f` (64 bytes) on x86, else no shim (16-byte SSE/NEON vectors are baseline and stay plain externs). `lower_extern` renames the decl, adds `link_name`, sets identity `Unknown`, and returns the shim `FnDef`; `declare` pushes it into `items`.

Chosen over putting `#[target_feature]` on every caller: `FunctionName::is_unsafe` is fixed before lowering, so that needed a body pre-pass and would make callers `unsafe fn` transitively.

Fixture: `crates/slate/tests/fixtures/x86_64/extern_vector_abi.c` (`-mavx512f`, `__m128`/`__m256`/`__m512`/`__m512d` externs defined in global asm).

Limits: a vector the declaration passes `byval` stays a barrier, including an extern declared at baseline ISA but called from a `target("avx512f")` function (call-site ABI is direct, declaration ABI is byval). Weak externs, indirect calls through vector-ABI function pointers from featureless callers, non-x86/AArch64 targets, and exported definitions with vector ABI (`lower_bodies`) are unchanged.

See: slate-dghn.58.1, slate-dghn.58.4, wiki/concepts/intrinsic-lowering.md.
