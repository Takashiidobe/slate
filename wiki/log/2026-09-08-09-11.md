# Probe mcontext_t/ucontext_t register layout per-ISA

_2026-09-08 09:11:45_

(slate-b66b.13.8) Added emit_ucontext() to tools/probes/linux-libc-abi.c:
ucontext_t align/offsets (uc_flags/uc_link/uc_stack/uc_mcontext/uc_sigmask),
mcontext_t size/align, plus per-arch REG_* ucontext index macros
(x86_64/x86) and named mcontext_t field offsets (aarch64 regs/sp/pc/pstate,
arm trap_no/arm_r0../arm_cpsr/fault_address), following the sys/reg.h and
sys/user.h precedent from slate-b66b.13.4/.13.5.

Initially suspected glibc's ucontext_t needed an extra trailing __ssp[4]
field (shadow-stack pointer support) missing from the x86/x86_64 shim.
Wrong -- the existing shim already over-sizes __fpregs_mem (68 longs on
x86_64, 32 on x86) to cover struct _libc_fpstate's real size PLUS the
trailing __ssp bytes in one flat buffer (544 = 512 fpstate + 32 ssp on
x86_64; 128 = 112 + 16 on x86). Adding a separate __ssp field would have
double-counted those bytes. No shim changes were needed for .8; the
existing per-arch mcontext_t/ucontext_t layouts (including ARM's
libc-varying uc_regspace element type, which differs from musl but matches
in size/alignment) were already correct.

Verified: tools/libc-abi-matrix.py green (zero mismatches) across all 4
arches x 2 libcs, cargo nextest --profile libc 37/37.
