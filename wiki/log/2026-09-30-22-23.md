# Slate frontend va_arg of long double

_2026-09-30 22:23:17_

slate-p58o.4.3: va_arg of long double in Rust-defined variadic functions.

- Callee: ValueKind::VaArg of f80 lowers to __slate_f80_va_arg(addr_of_mut!(ap)). The C helper (shims/long_double.c, now includes <stdarg.h>) does va_arg(*ap, long double) and stores into __slate_f80. Works because x86_64 VaList is repr(transparent) over the C __va_list_tag layout, so C advances the Rust list in place.
- Caller: Rust passes LongDouble ([u8;10], align 16) as an INTEGER-class struct in GP registers, but C va_arg reads x87 long double from the overflow area. A direct call to a non-extern variadic function whose variadic args hold f80 now goes through __slate_va_<callee>__r<ret>_<fixed>__<variadic>. c_shim::render_variadic_trampoline emits '<ret> callee(<fixed>, ...);' with fixed f80 params/return as __slate_f80 (the Rust definition's ABI) and __slate_f80_load on variadic f80 args only.
- The callee gets #[unsafe(no_mangle)] (Context::exports) so the trampoline can call it. Static name collisions across TUs are a follow-up bead.
- Factored long_double_bridge_tags / call_long_double_bridge out of lower_long_double_bridge.
- Updated wiki/concepts/long-double-f80.md.

Fixtures: new long_double_va_arg.c (pure f80 varargs, mixed int/double/f80 past register exhaustion, va_copy); promoted gcc-torture va-arg-5.c and va-arg-6.c.
Validation: full slate profile; only failure was the torture ratchet asking for those two promotions.
