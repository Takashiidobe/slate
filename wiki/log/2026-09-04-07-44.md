# FileCheck fn-scope markers match by name, not position

_2026-09-04 07:44:52_

`@lowering-fn-begin` could not wrap a `static` function. The instrumenter
injected sentinel `void __slate_filecheck_begin_N(void) {}` definitions around
the target and captured everything emitted between them. Those sentinels are
external, so clang emits them eagerly; a `static` target is deferred and lands
after them, leaving an empty region and

    error: @lowering annotation 0 selected no checks

Rejected fix: strip `static` in the instrumenter. It is signature-preserving in
plain fixture mode, but under `--project`/`--library-project`
`external_def = emit_pub && typed_function_is_exported(function)`
(function_setup.rs:57) keys off linkage, so dropping `static` turns
`fn helper(..)` into `pub extern "C-unwind" fn helper(..)` — the tool would
emit a CHECK line the real run never produces, failing at test time rather
than generation time. `static inline` also needs both keywords stripped or the
definition disappears entirely.

Implemented instead: `instrument_annotations` reads the wrapped definition's
name from the C source (`c_function_definition_name`, after
`strip_attribute_groups` removes `__attribute__((...))` and `[[...]]`), and
`extract_generated_regions` pulls that named item out of the generated Rust
wherever it landed. No sentinels are injected for fn-scope markers at all, so
the instrumented translation is byte-identical to the real one. `module_with_marker`
locates project modules by target name when the marker is fn-scope.

24 of 25 fn-marker fixtures regenerate byte-identically, as do the project and
library modes. The exception is `enum_field_ptr_call_arg.c`: its checks had
captured `select_type`, an unmarked static clang had hoisted into the sentinel
window. The fixture only marks `run`, so those 40 lines were dropped.
