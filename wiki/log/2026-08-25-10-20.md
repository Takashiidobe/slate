# disjunctive dispatch with real overlap is genuinely unsupported

_2026-08-25 10:20:40_

Follow-up to the marker_trait_attr correction: #[marker] only solves
disjunctive gating (uniform body regardless of which predicate matched).
Tested the harder case — disjunctive dispatch where two independent,
open-ended predicates A/B can both hold for the same type and need
different bodies with A taking priority (the real shape of C++'s
if constexpr(A) {..} else if constexpr(B) {..} chains).

Tried and confirmed closed:

- Tag/autoref dispatch (impl<T: TraitA> BranchA for &&ChoiceTag<T>) hits
  E0207 (T unconstrained by the impl type) once un-parameterized, and once
  fixed by parameterizing the tag, hits the same generic-fn timing bug as
  the original autoref case (resolves once against abstract T pre-monomorphization,
  always prints the one universally-applicable branch).
- Ordinary overlapping impls + `default fn` under #![feature(specialization)]
  still hard-errors E0119 — default alone doesn't grant an override,
  specialization needs a _provable subset_ relationship, and two
  independent trait bounds have none.
- The natural C++ tie-break (enable_if<!is_a<T>::value && is_b<T>::value>)
  has no Rust equivalent: `T: TraitB + !TraitA` errors "negative bounds are
  not supported" — Rust has no negative bounds for user traits at any
  stability level.

Conclusion: this is a genuine unsupported/manual-port boundary, not a
fixup-pass gap. Full writeup: wiki/concepts/cxx-translation-pain-points.md.
