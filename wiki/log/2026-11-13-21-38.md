# slate-dghn.58.8 lowering: __builtin_bit_cast between vector types (vreinterpret in arm_neon.h) had no lowering

_2026-11-13 21:38:42_

- bead: slate-dghn.58.8
- kind: bug
- area: crates/slate/src/frontend/lowerer/values.rs

Outcome: `__builtin_bit_cast` to or from a vector type lowers to `std::mem::transmute` on every target; NumPy clang-aarch64 drops from 985 to 723 blocked functions (no Convert barriers left).

Symptom: clang 23 arm_neon.h writes every `vreinterpret*` and `_v` builtin wrapper with `__builtin_bit_cast`, so 584 NumPy aarch64 rows failed with "cannot lower Convert to Rust". x86 headers use `(__m128d)` casts (`ConversionKind::VectorBitCast`), which is why x86 NumPy never hit it.

Reproducer:
```c
typedef long long v2i __attribute__((vector_size(16)));
typedef double v2d __attribute__((vector_size(16)));
v2d f(v2i a) { return __builtin_bit_cast(v2d, a); }
```
Before: `help: value bit_cast<vector<f64, 2>, reason=explicit>(read<vector<i64, 2>>(%3))`

Cause: sema emits `ConversionKind::BitCast` for `__builtin_bit_cast` (sizes already checked equal). In `lower_value_node` (frontend/lowerer/values.rs) the generic vector arm sent it to `lower_vector_convert`, which only knows the vector conversion kinds.

Fix: an arm before it matches `BitCast` where either side resolves to `ir::Type::Vector` and emits `Expr::Transmute`, same as `VectorBitCast`. Covers vector<->vector, vector<->scalar and vector<->struct.

Regression test: crates/slate/tests/fixtures/vector_builtin_bit_cast.c (i64x2<->f64x2, f32x4->u8x16, i32x2->double, i64<->i16x4, i32x2<->struct, nested casts).

Limits: the remaining 723 NumPy aarch64 rows are NEON builtins (slate-dghn.58.7).
