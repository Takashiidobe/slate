# slate-f2zu.14.40.2 lower_dispatch: cleanup attribute dropped in goto functions, every scoped_guard leaked its lock; ternary stored into field not an escape

_2026-11-15 23:48:16_

- bead: slate-f2zu.14.40.2
- kind: bug
- area: crates/slate/src/frontend/lowerer/control_flow.rs
- area: crates/slate/src/frontend/lowerer/statements.rs
- area: crates/slate/src/backend/interproc/pointer_lattice.rs
- corpus: linux

Outcome: functions lowered through lower_dispatch (any goto, label, computed
goto or asm goto) now run **attribute**((cleanup)) handlers, so the kernel's
scoped_guard releases its lock; a pointer stored into a field through a ternary
now counts as escaping.

Symptom: the translated kernel deadlocked at boot in init_ISA_irqs ->
irq_set_chip_and_handler_name -> queued_spin_lock_slowpath. Every scoped_guard
expands to
`for (CLASS(...) scope; ...; ({ goto label; })) if (0) { label: break; } else body`,
so every scoped_guard function goes through dispatch, and dispatch never emitted
cleanups.

Reproducer (minimal C):

```c
for (struct guard scope __attribute__((cleanup(guard_release))) = guard_take(lock, ok);
     scope.lock || !1; ({ goto done; }))
  if (0) { done: break; } else { *slot = value; }
```

Before: core::ptr::write(slot_0, guard_take(..)); ...; return ret; with no
guard_release call, so lock stayed incremented. After:

```rust
let __slate_cleanup_armed_0 = core::cell::Cell::new(false);
let __slate_cleanup_0 = __slate_cleanup::Guard(|| { if __slate_cleanup_armed_0.get() { unsafe { guard_release(__slate_slot_0 as *mut _) }; } });
... core::ptr::write(__slate_slot_0, guard_take(lock, ok)); __slate_cleanup_armed_0.set(true);
... __slate_cleanup_armed_0.set(false); guard_release(__slate_slot_0 as *mut _); return ret;
```

Cause: cleanup_guard ran only from lower_statement_list (structured path);
lower_dispatch (crates/slate/src/frontend/lowerer/control_flow.rs) hoisted the
variable into a MaybeUninit slot and dropped variable.cleanup.

Fix:

- Graph builds a Node::Cleanup on every CFG edge that leaves a cleanup
  variable's scope: Graph::scoped (rest of the list after the Let), For init
  scoped over condition/increment/body (exit edge = condition false and break),
  break/continue unwind to the depth recorded with the loop, goto/computed
  goto/asm goto labels unwind to the label's scope (scope_labels pre-pass,
  common prefix).
- Returns: per cleanup variable an armed Cell plus a function-level
  \_\_slate_cleanup::Guard, declared in BindingId order so drops run innermost
  first after the return value is computed.
- Barriers instead of silent drops: CleanupInCondition (cleanup Let in a loop
  condition evaluation), CleanupSlot (byref or VLA cleanup variable).
- cleanup_call (statements.rs) shared by the structured guard and dispatch.
- pointer_lattice ClassifyCtx::stored_sources/escape_stored: a stored value's
  If/Match arms and Block/Unsafe tails are escape sources (was Var/Cast only),
  for struct/array literals, field stores and global stores.
  `struct guard g = {ok ? lock : 0}` lifted lock to &i32 and failed to compile.

Regression test: crates/slate/tests/fixtures/cleanup_scoped_guard_for_goto.c
(nested guards, return/goto/break out, continue and goto out of a loop, drop
order). Promoted fixtures.gcc-dg.gcc-only/torture\_\_pr122835.c (cleanup + asm
goto).

Limits: a cleanup Let that is the only body of a Label/Case/Default gets list
scope (cleanup at the end of that body, not the enclosing block).
~/slate-translated/slate-linux was not hand-patched (about 10 affected functions
in kernel/irq/chip.c alone); it needs re-translation.

See: slate-f2zu.14.40.1, slate-3amj.37.
