# Make WinMain, wWinMain and DllMain stdcall on x86 windows-msvc

_2026-10-25 23:27:13_

slate-3amj.5.18: TypeResolver::default_convention (sema/types.rs) gives functions named WinMain, wWinMain or DllMain without an explicit convention X86Stdcall on x86 and C elsewhere on windows-msvc targets, ignoring /Gd /Gr /Gz /Gv (x64 /Gv also left them vectorcall before). Probed cl.exe 19.51 x86/x64 and clang i686-pc-windows-msvc: applies at file and block scope and to definitions, not to parameters or pointers; variadic stays cdecl; explicit conventions win; '__cdecl WinMain' then plain 'WinMain' is C2373 (slate: redeclared with a different calling convention). Typedefs named WinMain get it in msvc only (clang skips them): new TypeResolver::typedef_scope set by resolve(). Definition parameters in assertion.rs now go through resolve_parameter so prototype_scope excludes them.
