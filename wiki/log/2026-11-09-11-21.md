# Lower va_arg on aarch64-apple-darwin char* va_lists

_2026-11-09 11:21:26_

slate-yar4.37: Apple arm64 va_list is char* with every variadic argument on the stack in 8-byte slots, so va_arg on a va_list parameter hit 'cannot lower VaArg to Rust'. New support module support/darwin_arm64_va.rs (__slate_darwin_arm64_va): arg aligns the cursor to max(8, align_of T), reads T and advances by size rounded up to 8 (clang EmitDarwinVAArg with AllowHigherAlign); indirect reads through a pointer slot. lowerer/values.rs routes every AArch64 VaArg whose list type is a pointer there, using indirect when the IR passing is VaPassing::Indirect (non-HFA aggregates > 16 bytes; HFAs of any size stay direct, matching clang). long double is f64 on darwin and goes through arg. Build fixture fixtures.build/apple/va_arg_darwin_arm64.c (aarch64-apple-darwin only: int, char, double, long double, pointer, __int128, small/big/hfa/quad/16-aligned structs). tools/corpus/matrices/tinycc.json gains darwin-aarch64 (-DTCC_TARGET_ARM64); tcc.c translates and cargo-checks for aarch64-apple-darwin (the build script's slate_long_double.c needs CC_aarch64_apple_darwin=clang with -isysroot <sysroot>/SDK on a linux host).
