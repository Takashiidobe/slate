# slate-3amj.33 compiler_args: gcc -msoft-float defines _SOFT_FLOAT on x86, clang accepts it unchanged

_2026-11-18 17:37:51_

- bead: slate-3amj.33
- kind: feature
- area: crates/slate-parser/src/compiler_args.rs
- flavor: gcc
- target: x86_64

Outcome: gcc `-msoft-float` on x86 now defines `_SOFT_FLOAT`, and clang accepts it with no predefine change.

Gap: `-msoft-float` had no `Opt` in `compiler_args.rs`, so `_SOFT_FLOAT` stayed undefined under gcc. gcc defines it when x87 is off and keeps `__SSE__`. clang defines nothing extra and keeps SSE on x86_64.

Reproducer:
```c
#ifdef _SOFT_FLOAT
int soft = 1;
#else
int soft = 0;
#endif
```

Before (gcc, `-msoft-float`): `soft = 0`. After: `soft = 1`, `sse = 1`. Output matches gcc: `1 1`. clang stays `0 1`.

Implementation: new `Opt::SoftFloat` beside `Opt::X87`. It is accepted by gcc and clang. Applying it sets `X86Feature::X87` to `!value`; the existing `x86_isa.rs` predefine logic then emits `_SOFT_FLOAT=1` for gcc only.

Fixture: `crates/slate/tests/fixtures/gcc/x86_64/flag_soft_float_macros.c`, promoted from `fixtures.unsupported`.

Limits: arm/aarch64 `-msoft-float` (`__SOFTFP__`, ABI) is not modeled. `-mgeneral-regs-only` was not touched.

See: slate-3amj
