# Emulate per-flavor alloca spacing and alignment

_2026-11-08 08:20:57_

slate-yar4.35: alloca's arena now grows downward and spaces/aligns allocations like the flavor's compiler. New ir::AllocaLayout {padding, alignment} on Module, set in sema by AllocaLayout::for_dialect: gcc x86_64 pads 8, gcc i686 pads 12, gcc x86 aligns to vector_register_bytes (__BIGGEST_ALIGNMENT__ 16/32/64), armv7 aligns 8, everything else 16 (clang ignores -mavx; cl.exe x64/x86 matches clang). Measured with gcc/clang/cl.exe probes across -O0/-O2, -mavx, -mavx512f, i686, aarch64, armv7. Lowering passes (size + padding, alignment); _with_align passes max(bits/8, alignment). Runtime (support/alloca.rs) tracks used bytes from block top and rounds down; no fixed 16 floor. Fixtures: alloca_layout.c, gcc/alloca_layout_gcc.c, gcc/x86_64/alloca_layout_gcc_avx.c (alignment only; gcc -mavx spacing depends on incoming sp), msvc/alloca_layout_msvc.c (abort-based, header-free on armv7). chibicc alloca moved ignored -> supported; builtin_alloca promoted on armv7. Wiki: ir/builtins.md#alloca documents the TLS Vec-of-heap-blocks emulation. slate, slate-targets, msvc, parser green.
