# Generated crates use #![no_main] and a C-ABI main with the real argv (slate-dghn.26)

_2026-10-03 09:03:08_

Redis 'Process title set as expected' failed: the Rust main wrapper built argv from
std::env::args, so redis setproctitle overwrote a copy and /proc/pid/cmdline never changed.

- functions.rs main_wrapper now emits #[unsafe(no_mangle)] unsafe extern "C-unwind"
  fn main(argc, argv, envp) -> i32 that returns __slate_main(argc, argv[, envp]).
  C's main receives exactly what the C runtime passes; 3-argument main is now supported.
- The lowerer adds CrateAttr::NoMain (new, prints #![no_main]) alongside the features.
- translate-project hoists all of the root unit's crate attributes into the single
  block ahead of the mod items (inner attributes must come first).
- Side effect: Rust's lang_start no longer runs, so SIGPIPE keeps C's default disposition.

Fixture tests/fixtures/main_process_argv.c (3-arg main, rewrites argv[0] in place,
reads /proc/self/cmdline, envp == environ) failed first and passes. Slate profile 13/13.
The redis e2e rerun was deferred to the slate-dghn.10 milestone check.
