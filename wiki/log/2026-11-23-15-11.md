# slate-e36k.13 Clang static initializer: fold discarded comma operands

_2026-11-23 15:11:36_

- bead: slate-e36k.13
- kind: parser
- area: crates/slate-parser/src/sema
- flavor: clang

Outcome: Clang static initializers can discard a constant comma operand, so
CodeMetal scope_of_macro_3 translates, builds, and exits 0.

**Reproducer**

```c
int u = (3, 4) + 2;
```

Clang accepts this in C11, including with `-pedantic-errors`. GCC rejects it
in C11 and GNU11. The discarded operand must be evaluable at compile time.
Both Clang and Slate reject replacing `3` with an ordinary function call.

**IR and fix**

Before, the IR had `add(sequence(3, 4), 2)`, which Rust lowering rejected as a
nonconstant initializer. The IR now contains `const<i32>(6)`. Clang
static-initializer lowering uses the existing typed evaluator to discard
constant sequence operands before folding an enclosing integer initializer.
The pass preserves evaluated calls and loads. GCC retains the sequence.

**Fixture**

`crates/slate-parser/tests/fixtures/clang/linux/x86_64/comma_static_initializer.c`
covers nested commas, short-circuiting, a static address, a block-scope static
aggregate, and a call that remains in IR when evaluated. The Slate CLI still
rejects the side-effecting initializer as nonconstant. Promoted the chibicc
`constexpr` fixture after its comma initializer passed end to end.

**Limits**

The pass uses Slate's existing constant evaluator. Other Clang extensions,
such as reading an ordinary non-constexpr const object, still need support.
See slate-parser-6x05.51 for Clang const-object folding and slate-e36k.14 for
discarded string literals and indexed static addresses.
