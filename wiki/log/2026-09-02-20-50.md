# Fix inline_temps treating var-anchored nested binaries as unanchored

_2026-09-02 20:50:39_

expr_is_type_anchored's Expr::Binary case required BOTH operands independently type-anchored (AND) before treating a nested binary as safe to sit beside an inlined literal. That's stricter than Rust's actual inference: for any same-typed-operand binop (+,-,*,/,%,comparisons,bitwise), one concretely-typed leaf (e.g. a Var) forces the whole subtree's type regardless of untyped literals elsewhere in it -- x % 2 is fully i32-anchored by x alone, 2 doesn't need to be independently anchored.

Symptom: let _v: i32 = 0; if x % 2 == _v { ... } never inlined -- consumer_pins_type -> binary_operand_pinned checked the sibling operand (x % 2) via expr_is_type_anchored, which recursed AND into x (anchored) and 2 (an untyped i64 literal, never anchored on its own) and returned false. Confirmed this is general, not switch-specific: reproduced standalone with no switch involved (mod_eq.c). The switch_torture.c fixture's duplicated if (x % 2 == 0) arms were where it first surfaced, once structure_dispatch (prior log entry) started recovering that shape at all.

Fix: changed the Binary case to OR (either operand anchored suffices), with Shl/Shr kept special-cased to only the LHS (shift RHS type is independent, matching the same exception already made in binary_operand_pinned's own sibling_pins check). src/backend/engine/rules/inline_temps.rs:1002-1010.

rewrites profile: 92/92, unchanged. libc profile: same single pre-existing pthread_cancel-points failure as the unmodified baseline (confirmed flaky, unrelated -- verified via git stash against the prior commit before touching this file).
