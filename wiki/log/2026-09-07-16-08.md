# forward pure temps into asm! read operands

_2026-09-07 16:08:44_

Closes slate-dx0m.6. LateInlineTemps' argument-use allowlist
(kind_call_or_macro_arg_use, is_top_level_use in inline_temps.rs) never
matched NodeKind::InlineAsm, so a movable-pure temp whose only use was an
asm! in(...)/const operand could never be forwarded, however trivial (a bare
integer literal like `let __v0: i32 = 7;` feeding `in("eax") __v0`).

Added asm_operand_read_expr(op) -> Option<&Expr>, matching the read-position
half of each AsmOperand (In/Const values, InOut's input; Out/InOut's output
and Label are write-only or unsupported, never a read). Wired it into
kind_call_or_macro_arg_use (via call_arg_uses_name, same as other call/macro
args) and is_top_level_use (bare-var match, same as other top-level
consumers).

Also had to extend is_movable_pure_temp to accept an uninitialized
`let x: T;` (init: None) as an inert intervening statement - asm output
bindings (`let __v2: u32;` before the asm! block binds it via lateout) were
failing the "all intervening siblings are movable-pure temps" check and
blocking the forward before the allowlist was even consulted.

Verified: cpuid_leaf7_feature's `in("eax") 7, in("ecx") 0` operands now fold
directly (no more __v0/__v1 temps). Regenerated 8 affected asm fixtures with
`update_filecheck.py --profile both` (tool-generated, no handwritten blocks
hit this time). Full rewrites profile: 85/85 pass. fmt/clippy clean.
