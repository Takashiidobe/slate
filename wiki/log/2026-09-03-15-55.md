# Make all generated extern functions C-unwind

_2026-09-03 15:55:34_

Root-caused the pthread_cancel-points SIGABRT (slate-cu47): NOT a rustc
codegen bug. glibc's forced-unwind for pthread_cancel is a foreign unwind
crossing plain extern "C" fn boundaries in generated Rust, which Rust
correctly aborts on per RFC 2945 (C fns assert no-unwind). Full writeup in
wiki/concepts/pthread-cancel-forced-unwind-needs-c-unwind-abi.md, including
a minimal stable-Rust repro.

Decided against a reachability-based override list (POSIX cancellation
points + call-graph walk): unsound for user code with function pointers,
and unwind-tolerance is a per-frame property so partial tagging is fragile.
Instead: make every slate-generated extern "C" fn/fn-ptr type unconditionally
extern "C-unwind".

Also collapsed Abi::C out of the Abi enum entirely (backend/rust_ast.rs) -
since nothing constructs plain C anymore, keeping the variant around would
just be dead surface. Updated all 7 construction sites:
function_setup.rs:74,215,500; lowerer.rs:1335,2186,2987; types.rs:404.
FFI extern-block declarations (calling into real libc) are a separate
Item::ExternBlock{abi: String} path, untouched.

cargo check is clean. Fixture snapshots (~1169 files reference `extern "C"`
in FileCheck blocks) need regenerating via tools/update_filecheck.py per
affected fixture - user is running that themselves.
