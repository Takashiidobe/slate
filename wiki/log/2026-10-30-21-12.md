# Hoist one differing value out of merged functions

_2026-10-30 21:12:29_

slate-nfq8.2: --merge now keeps one shared function body when all its variants differ in one value: a literal, or a primitive type at any number of positions. The value moves to one #[cfg]-gated module-level const __SLATE_HOIST_<fn> or type __SlateHoist_<fn> (new src/project_hoist.rs, Item::TypeAlias). The hoist cfg is the variant's existing truth-table cfg; the function's cfg comes from the union of variants' on-sets. Departures from the bead: a type difference may span several positions because it is still one declaration, and the dependency on nfq8.3 was removed because comparison is position by position and needs no source alignment. Const typing: a literal needs a type from its suffix or from return, typed let, direct cast, if branch or arithmetic, and all uses must agree and match the literal's kind, otherwise whole-item duplication. A difference in any node the walker does not enter also falls back, since it fails shell equality. --check-projection expands bindings before comparing; reversing the bindings on purpose produced 54 mismatches on hoist_operands. Survey (zlib, 16 targets, 786k lines): 108 of 153 multi-variant functions differ in shape, 175k of 179k duplicated lines. Result: 22 functions hoisted, 132 duplicated, 284 lines saved (0.04%). nfq8.3 is what reduces size. Verified: 160/160 sampled configurations, 736 shared symbols no mismatches, cargo check on 13 targets with default and lit-mem,no-gzip features (x86_64-apple-darwin, aarch64-pc-windows-msvc, thumbv7a-pc-windows-msvc not installed). Fixtures: fixtures.merge/hoist_syscall.c (real SYS_preadv, new // merge-second-target: directive), hoist_operands.c, hoist_fallback.c. Not done: tests/fixtures.cfg is not run by any test, and the translate --targets merge has no hoisting (new bead).
