# Keep flattened out-params mutable through alloca frames

_2026-08-29 13:39:24_

slate-ft0v.2. libexpat's rewrite build had 5 E0308 "types differ in mutability" errors where a genuine C out-parameter (e.g. checkPiTarget's int *tokPtr) was lifted by the pointer lattice to a shared `&i32`, then a `*mut i32` alloca-frame field assignment failed to type-check.

Root cause: the lattice's write-evidence collection only followed writes through plain-variable aliases. Out-param writes launder through the generated alloca frame: `frame.N = arg` (spill), `let v = frame.N` (reload), `*v = ...` (write). The frame-field place `frame.N` was never a tracked alias, so the write never reached `arg` and it looked read-only.

Fix in src/backend/interproc/pointer_lattice.rs: added `frame_field_key`/`place_key` and (1) record `frame.N = param` as an alias of the param, (2) generalized `try_alias` to accept a frame-field source so `let v = frame.N` aliases the param, (3) generalized the deref write-detection via `place_key`. Now the `*v = ...` write is attributed to the param, so it stays `&mut`.

Fixture: tests/fixtures/ptr_out_param_alloca_frame.c. rewrites profile: 110 pass. libexpat generated-crate errors 36 -> 31 (the remaining 31 are the lowering-side record-identity collisions, slate-ft0v.3, unaffected).
