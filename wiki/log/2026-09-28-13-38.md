# Alignment: alignof of variables in static asserts, members, and typedef redeclarations (cxg.37 E)

_2026-09-28 13:38:21_

slate-parser-cxg.37 cluster E (Wattributes-8.c, typedef-redecl2.c, typedef-redecl3.c).

- `_Static_assert` is evaluated by sema/assertion.rs with its own TypeResolver
  and no entities, so object_alignment (keyed by NodeId -> BindingId) never saw
  `int c __attribute__((aligned(2)))`: `_Alignof(c)` fell back to natural even
  for aligned(8). Ordinary::Object now carries the requested alignment; the
  checker computes it with requested_alignment and merges with a previous
  declaration in the same scope (lookup_local), matching ObjectRequest::merge.
- `_Alignof(s.m)` / `_Alignof(p->m)` now report the field alignment
  layout_record computed (both GNU and MSVC paths return a per-field Vec,
  stored in TypeResolver::field_alignments next to record_fields). gcc and
  clang: packed -> 1, packed+aligned(2) -> 2, aligned(16) -> 16. Previously
  natural in both lowering and assertions. Kept out of ir::RecordLayout.
- define_alias merges the alignment of a same-scope previous alias:
  typedef int T; ...aligned(64)...; ...aligned(128)...; typedef int T; gives
  128 in gcc and clang. The assertion checker used to insert its Declared
  placeholder before define_alias, hiding the previous alias; it now only
  inserts it for non-typedefs or failed resolution.
