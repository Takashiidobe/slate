# slate-f2zu.14.26 address_integer_write: packed pointer field in static image wrote aligned, E0080 alignment 1 vs 8 in idt_descr

_2026-11-14 18:51:49_

- bead: slate-f2zu.14.26
- kind: bug
- area: crates/slate/src/frontend/lowerer/globals.rs

Outcome: static MaybeUninit images store address-integer leaves with
write_unaligned, so a pointer-valued field inside a packed struct
const-evaluates.

Symptom: linux arch_x86_kernel/idt.rs, idt_descr: error[E0080] accessing memory
based on pointer with alignment 1, but alignment 8 is required.

Reproducer:

```c
struct desc_ptr { unsigned short size; unsigned long address; } __attribute__((packed));
static int table[16];
static struct desc_ptr d = { .size = sizeof(table) - 1, .address = (unsigned long)table };
```

Cause: `FunctionLowerer::address_integer_write` (frontend/lowerer/globals.rs),
used by `address_image` and `fill_aggregate` for integer fields holding
addresses, emitted
`(addr_of_mut!((*__t1).address) as *mut *const ()).write(..)`. `address` sits at
offset 2 in the packed record, and an aligned write of a `*const ()` there is UB
that const eval rejects.

Fix: emit `.write_unaligned(..)` unconditionally. It is correct at any alignment
and const-stable, and avoids tracking packed ancestors through nested
`fill_aggregate` calls.

Regression test:
crates/slate/tests/fixtures/static_packed_address_integer_image.c.
static_address_integer_initializers.c FileCheck regenerated (write ->
write_unaligned only).

See: slate-f2zu.14.23 (split from), slate-f2zu.14.21 (packed bit-field units).
