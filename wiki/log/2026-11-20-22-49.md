# slate-yar4.59 f80 record alignment: long double field borrows no longer hit packing barrier

_2026-11-20 22:49:53_

- bead: slate-yar4.59
- kind: bug
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/tests/fixtures/x86_64

Outcome: x87 long double storage in Rust now uses the target C size and
alignment, so a normally aligned f80 field needs no packed record and can be
borrowed safely.

Symptom: Under x86_64 clang -malign-double, C aligns long double to 8 bytes
while Slate’s Rust representation used alignment 16. The record was emitted as
repr(C, packed(8)), turning a proven borrow of its f80 field into a barrier.

Before:

```rust
#[repr(C, packed(8))]
struct extended { c: i8, x: LongDouble }
let x = unsafe { (core::ptr::addr_of_mut!(e.x) as *mut LongDouble).read_unaligned() };
```

After:

```rust
#[repr(C)]
struct extended { c: i8, x: LongDouble }
half(&mut e.x);
```

Cause: `Tables::storage_of` omitted F80 numeric, complex, and imaginary types,
so record layout reasoning could not compare them using the target’s C storage
layout. `record_pack` worked around the resulting Rust/C alignment difference by
treating any record containing x87 as packed.

Fix: `storage_of` now queries the target for the size and alignment of F80
forms. `record_pack` only packs when the IR marks a field underaligned; the
`holds_x87` fallback is removed. The aligned-field invariant error text now
describes the general Rust type/offset mismatch.

Regression test:
`crates/slate/tests/fixtures/x86_64/flag_align_double_long_double_borrow.c`
moves from unsupported to supported and checks a mutable borrow through
`half(&e.x)`.
`crates/slate/tests/fixtures/x86_64/flag_align_double_long_double.c` checks
ordinary record representation, field access, and target-reported long-double
alignment and size.

See: wiki/concepts/ir/types.md#records, slate-yar4.59.
