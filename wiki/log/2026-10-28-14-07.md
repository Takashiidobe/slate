# Lower AArch64 register-variable asm operands

_2026-10-28 14:07:58_

slate-3f8g.4.24: register variables bound to aarch64 asm operands (register long x8 asm("x8"), the syscall-wrapper pattern) barriered with 'register variable needs explicit register lowering'. Cause: slate-parser's holds() (sema/asm.rs) knew only x86 names, so the operand stayed Register(reg) instead of Explicit. holds() now accepts x0-x30 for reg and v0-v31/v0-v15/v0-v7 for vreg/vreg_low16/vreg_low8. Slate (lowerer/asm.rs) lowers an aarch64 Explicit operand to in("x8")/inout("v3"), printed by name at the view width (w1, d3); x19/x29 stay a barrier (reserved register operand). aarch64_register_modifier treats an explicit x register as general; asm_scratch_type gives an explicit v register the vector scratch type. Fixtures: slate tests/fixtures/aarch64/asm_aarch64_register_variables.c (write and getpid via svc, w1 and d3 variables), parser clang/linux/aarch64/ir_asm_register_variables.c. wiki ir/asm.md updated; also dropped the >128-bit vector barrier note (clang and gcc reject such operands). slate, parser and slate-aarch64 profiles green.
