# Compound literal _Alignas and subscript of pointer-to-incomplete

_2026-09-29 15:32:07_

cxg.54: the typer's Index case passed the element type to pointer_offset, which then took its pointee again and required it complete. For struct S **p, p[0] checked struct S instead of struct S *. It now passes the pointer, as the binary + path already did. Subscripting a struct S * still fails as it should.

cxg.53 (DR 444): gcc accepts _Alignas in a compound literal type name and aligns the object; clang rejects it. slate now accepts it in every flavor (permissive, not too strict).
- Parser: only try_parse_compound_literal lets a type name start with _Alignas/alignas. Casts, sizeof and _Alignof still fail to parse it, and gcc and clang both reject those too.
- names.rs type_name now visits the specifier attributes, so typedefs named in an _Alignas operand resolve. Before, that failed with 'unknown typedef'.
- IR: PlaceKind::CompoundLiteral gains alignment: Option<u64>, printed [align=N] after [storage=..]. It uses requested_alignment plus object_alignment_override, the same path as locals, and is set only when _Alignas is present so plain literals print unchanged.
- A request below the natural alignment is not rejected, which matches how declarations are handled.

Filed a follow-up: __attribute__((aligned)) in a type name is dropped. gcc applies it to the type; clang ignores it.

Migrated gcc.dg/c11-align-7.c and gcc.dg/Wmismatched-dealloc.c into suites/gcc-dg; new fixture gcc/linux/x86_64/compound_literal_alignas.c.
