# Lower rounding=environment float arithmetic and conversions to C fenv shims

_2026-10-26 09:16:09_

slate-3amj.47: rustc assumes round-to-nearest, so rounding=environment ops lowered to plain Rust were constant-folded (1.0/3.0 under FE_UPWARD) and could move across fesetround. The lowerer (lowerer/values.rs) now routes f32/f64 add/sub/mul/div (lower_environment_arith), f64->f32 float_narrow, and inexact int_to_float (lower_environment_int_to_float) through __slate_fenv_* bridges in frontend/shims/fenv.c (the CIR-era shim set, until now used only by flt_rounds). An extern call rustc cannot see into blocks both folding and code motion; black_box only blocks folding. Signed sources widen to i64, unsigned to u64. 128-bit sources keep the __slate_rounding reduce-with-sticky path, which now takes the i64 shim as a fn pointer instead of black_box (support/rounding.rs). The u64 shims halve with a sticky bit, since clang's magic-constant u64->double sequence is wrong under directed rounding. New calls.rs declare_c_bridge (split from call_c_bridge) declares a bridge without calling it.
No noinline attribute: the shim is a separate cc-built static library and the generated crates never use linker-plugin LTO, so rustc cannot inline it.
Mode-independent ops (compares, neg, exact conversions, fmod) stay native; f80 already runs in long_double.c. Not routed: f16 arithmetic (aarch64 _Float16 without excess precision).
Fixtures: promoted flag_fp_model_strict.c; new flag_rounding_math.c (constants and volatiles, all four modes, i64/u64/i32/__int128 sources, x86_64/i686/aarch64; clang oracle, since gcc -frounding-math still folds some constants). stdlib_fenv_access.c FileCheck regenerated. gcc-dg torture__fp-double-convert-float-1.c now passes and is promoted.
