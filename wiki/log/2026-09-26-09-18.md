# const/pure become fn [memory=none|read]; such calls are not side effects in hoisting

_2026-09-26 09:18:02_

Closes slate-parser-dyd.70. FunctionSemantics gains memory: Option<MemoryEffects> (None < Read, the stronger wins), printed [memory=none]/[memory=read]. Sources: GNU __attribute__((const))/((pure)) in record_function, and builtin Const/Pure from the tblgen registry (implicit builtin declarations and source declarations that keep builtin status). ConstIgnoringErrno*/ConstIgnoringExceptions do not count; NoThrow stays dropped (C without -fexceptions never unwinds).

Hoister::effects (now a method; place_effects/atomicity_effects too) treats a direct call to a function with any memory restriction as effect-free apart from its arguments. Before: 'return a && square(b);' with const square lowered to let %t: bool [synthetic] + if/else writes. After: logical_and inline. Plain calls and square(b++) keep the spill. Indirect calls are always effectful.

Why this is sound: effects() only decides whether evaluating a value changes state (which forces && / || / ?: into if-branches and statement emission). A pure call writes nothing, so skipping or inlining it changes nothing; its reads still see the same state because no sibling write is hoisted across it that wasn't already (see dyd.71: hoisting already moves later-operand writes ahead of any call, which is a separate pre-existing ordering issue).

Real-corpus effect: 150 fixtures lose spills, e.g. c23_library.c stdc_leading_zeros wrappers become one conditional<u32> return; c2y-complex-1.c's chained signbit || tests collapse into one logical_or. Fixture: tests/fixtures/sema/ir_const_pure_calls.c. 3020/3020.
