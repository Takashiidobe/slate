# slate-f2zu.14.34.30 asm DeadArms: if around min()/clamp() BUILD_BUG_ON deleted by unanswered \_\_builtin_constant_p=0 in functions reaching an unresolved "i" asm

_2026-11-15 20:07:52_

- bead: slate-f2zu.14.34.30
- kind: parser
- area: crates/slate-parser/src/sema/asm_constants.rs
- area: crates/slate-parser/src/sema/folded_branches.rs

Outcome: asm dead-arm pruning no longer deletes an `if` whose condition only
folds by answering an unanswered `__builtin_constant_p` as 0, unless an asm
operand needs that answer, so kernel `min()`/`clamp()` `__types_ok` asserts stay
guarded and LLVM folds them.

Symptom: after the .21/.28 relink, 5 undefined `__compiletime_assert_N` remained
in copy_string_kernel (fs/exec.c), tlb_flush_mmu (mm/mmu_gather.c),
**hrtimer_rearm_deferred (kernel/time/hrtimer.c) and ioc_timer_fn
(block/blk-iocost.c). The IR had no `if`: `do { call **compiletime_assert_1111()
} while 0`. A standalone copy of the function kept the guard.

Reproducer:

```c
static inline __attribute__((always_inline)) void mark(int n) { __asm__ volatile("# %0" ::"i"(n)); }
unsigned drain(int len) {
  while (len > 0) {
    if (!(__builtin_constant_p((long long)len >= 0) && (long long)len >= 0))
      __compiletime_assert_1();
    len -= 3;
    mark(1);
  }
}
```

Before (-O2): the `if` is gone and the assert is called unconditionally (link:
undefined symbol). Without the `mark(1)` call the guard stays. After:
`if !statically_true!((len as i64) >= 0) { __compiletime_assert_1() }`;
rustc/LLVM proves `len >= 0` in the loop and drops it, as clang does.

Cause: `constant_asm_operands` runs `DeadArms`
(crates/slate-parser/src/sema/asm_constants.rs) on every function that has, or
calls, an unresolved `"i"` operand. `DeadArms` used `folded_condition`
(fold::evaluate, unanswered `llvm.is.constant` = 0) for every `if`/`?:` in such
a function, not only the ones guarding asm. It was missed in .21, which fixed
only `folded_branches`. Only the full TU reproduces it because the callee with
the asm must be defined in the same TU.

Fix: `DeadArms::taken` prunes when `Lowerer::branch_integer` (deferred queries)
folds the condition. If it folds only with the 0 answer, it prunes only when the
condition or the dropped arm `needs_resolution` (a rejected asm operand, or a
call to an unresolved function): `nf_hook`'s
`__builtin_constant_p(pf) && !branch(&keys[pf][nr])` still prunes, because the
asm is in the condition. Spec: wiki/concepts/ir/asm.md,
wiki/concepts/ir/builtins.md.

Regression test:

- crates/slate/tests/fixtures.release/constant_p_after_inlining.c `drain`
  (failed to link before).
- crates/slate-parser/tests/fixtures/clang/linux/x86_64/ir_constant_p_after_inlining.c
  `assert_kept_beside_asm` (guard kept) and `asm_arm_pruned` (`"i"` arm still
  pruned).
- ir_asm_dead_arm_entry_value.c (asm in the condition) still passes.

Verified on single kernel TUs: all 4 asserts guarded. Limits: not relinked. See:
slate-f2zu.14.34.21, slate-f2zu.14.34.31.
