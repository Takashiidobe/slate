# Lower __builtin_unreachable, __builtin_assume, __builtin_assume_aligned

_2026-10-05 15:24:11_

slate-dghn.33.

- slate (values.rs): __builtin_unreachable -> unsafe { std::hint::unreachable_unchecked() }; __builtin_assume(c) and MSVC __assume(c) -> unsafe { std::hint::assert_unchecked(c) }; __builtin_assume_aligned(p, a[, off]) -> p cast to the result type (the IR has already hoisted any side effects of a/off).
- slate-parser (sema/expression.rs, function_like_builtin): clang never evaluates an assume operand and ignores the assumption when it has potential side effects (-Wassume). The parser used to lower the operand normally, so hoisting ran x++ / calls. Now a side-effecting operand (effects::has_effects) is replaced by const<bool>(true).
- Fixtures: new builtin_assume_unreachable.c (slate) and builtin_assume_side_effects.c (parser FileCheck); promoted builtin_assume_aligned, control_flow_builtin_ops, gcc-dg c23-unreachable-1, gcc-torture 20230509-1 and pr81281.
- Wiki: ir-to-rust-lowering builtin rows (also fixed the stale global visibility row), ir/builtins assume note.
- Corpus probe after the change: yyjson 0 barriers; pcre2 library 0 (pcre2grep/pcre2test need host zlib.h/readline.h).
