# slate-3amj.33 compiler_args: -msoft-float selects the soft float ABI on 32-bit Arm, gcc rejects it on AArch64

_2026-11-18 19:31:51_

- bead: slate-3amj.33
- kind: feature
- area: crates/slate-parser/src/compiler_args.rs
- area: crates/slate-parser/src/target/isa.rs
- target: armv7

Outcome: `-msoft-float` on 32-bit Arm now selects the soft float ABI (`__SOFTFP__`, no `__ARM_PCS_VFP`); gcc rejects it on AArch64 and clang ignores it there, as the real compilers do.

Gap: slate-3amj.33 only modeled x86 (`_SOFT_FLOAT`). On armv7 `-msoft-float` was accepted but changed nothing, so `__ARM_PCS_VFP` stayed defined and `__SOFTFP__` was absent.

Reproducer:
```c
#ifdef __SOFTFP__
int soft;
#endif
```

Before (armv7-unknown-linux-gnueabihf, `-msoft-float`): `__ARM_PCS_VFP` defined, `__SOFTFP__` undefined. After: `__SOFTFP__ 1`, `__ARM_PCS 1`, no `__ARM_PCS_VFP`, same as gcc and clang.

Implementation: `IsaRequest.soft_float` (target/isa.rs) replaces the parse-time x87 write. `TargetIsa::resolve` applies it per family: x86 clears/sets `X86Feature::X87`; Arm32 maps it to `ArmFloatAbi::Soft`/`Hard` unless `-mfloat-abi` was given later; AArch64 errors for gcc and ignores it for clang. `-mfloat-abi=` clears `soft_float` and `-msoft-float` clears `float_abi`, so the last option wins as in gcc and clang.

Fixtures (crates/slate-parser/tests/fixtures): gcc and clang `armv7-unknown-linux-gnueabihf/flag_soft_float.c`, gcc `flag_soft_float_then_hard_abi.c` and `flag_hard_abi_then_soft_float.c`, clang `aarch64/flag_soft_float_ignored.c`, `error/gcc/linux/aarch64/flag_soft_float.c`. No slate differential fixture: the armhf sysroot has no `gnu/stubs-soft.h`, so `<stdio.h>` cannot be included with the soft ABI.

Limits: x86 `-msoft-float` now beats `-m80387` regardless of order. Soft-float calling-convention lowering is untouched. `-mgeneral-regs-only` untouched.
