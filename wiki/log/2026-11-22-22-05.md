Outcome: Guarded allocation lifts track the initialized prefix and sparse
slots. Growing a buffer leaves its new elements uninitialized.

## Before and after

```c
int *p = NULL;
if (flag) p = malloc(4 * sizeof(int));
if (p) {
  for (int i = 0; i < 4; ++i) p[i] = i;
  printf("%d\n", p[3]);
  free(p);
}
```

Before: the fill loop kept a raw pointer. Other guarded malloc fixtures
that lifted allocated a fully zero-filled vector.

```rust
let mut p: Option<Vec<i32>> = None;
if flag != 0 {
    p = Vec::try_alloc(4);
}
if let Some(p) = p.as_mut() {

    println!("{}", p[3]);
}
```

## Implementation

- `guarded_heap::Cursor` tracks the logical extent and initialized prefix
  separately. Sparse stores select `Vec<MaybeUninit<T>>`, with unsafe loads
  only at proven initialized slots.
- Constant-extent `calloc` seeds the initialized prefix. Recognized zero
  `memset` initializes the whole buffer at its original program point.
- A checked increasing `realloc` reserves capacity or adds uninitialized
  slots. Failure leaves the previous extent and initialization intact.
- `VecExt` adds `try_alloc`, `try_uninit`, `try_reserve_len`, and
  `try_resize_with` without requiring `Clone`.

Fixtures: `guarded_heap_initialization.c` covers fills, calloc, and both
growth representations. The arithmetic fixture covers sparse malloc.
An injected allocation failure returned the old values on both emitted paths.

Limits: guarded integer allocations and fixed extents. Direct byte-buffer
owners are tracked in slate-8ge7.24.19.15.
