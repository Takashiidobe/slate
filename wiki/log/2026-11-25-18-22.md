# slate-j3by.29.1 clang_builtin: generate MSVC recognition from the alphabetical list

_2026-11-25 18:22:00_

- bead: slate-j3by.29.1
- kind: parser
- area: crates/slate-parser/src/sema/builtins.rs
- area: crates/slate-parser/tools
- flavor: msvc

Outcome: The Microsoft alphabetical inventory supplies typed MSVC intrinsics
for x86, x64, and ARM64. Calls with missing lowerings reach a translation barrier.

Symptom: Slate translated __nop, __rdtscp, and _cvt_ftoi_sat into extern calls.
The same x64 source compiled with cl.exe and left no external references to
those intrinsics.

Reproducer:
```c
#include <intrin.h>
unsigned __int64 counter(unsigned int *aux) {
  return __rdtscp(aux);
}
```

Cause: `clang_builtin` used the shared Clang builtin and target catalogs,
which had no entries for several MSVC spellings.

Fix: `generate_msvc_builtins.py` reads the alphabetical document and linked
family pages, captures per-target declarations from MSVC headers, and
checks availability with cl.exe. It produces a sorted catalog and a JSON
Lines inventory with documentation revisions, compiler version, declaration
and probe status. The generator also lists the header typedefs used by the
prototypes so the parser can resolve SIMD and record-pointer arguments.
In MSVC mode, `clang_builtin` consults the generated
target table after the existing lookup paths. The reproducer now reports
`builtin without a lowering` on x64.

Fixtures: tests/fixtures/msvc/windows/{x86_64,aarch64}/alphabetical_intrinsics.c
under crates/slate-parser check types, metadata, and architecture gating.
The generator's extraction test covers grouped spellings, family headings,
and the __mul128 to _mul128 spelling correction.

Limits: The installed oracle covers x86, x64, and ARM64. The report marks
ARM32 unverified. The other Microsoft inventory pages have their own beads.
