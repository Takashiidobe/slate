# Sysroot install and doctor detect outdated pins

_2026-10-24 08:06:24_

slate-w483: install_staged_at returned early whenever an install existed and validated, so pin bumps never reached existing sysroots, and doctor could not tell. install.rs gains install_pinned_at(output, expected_manifest, ...): an install whose SYSROOT-MANIFEST.txt differs from the expected text (or lacks one) is rebuilt in staging and swapped in; a failed rebuild restores the previous install. install_staged_at keeps its signature (no expected manifest) for compiler_headers. linux_gnu, linux_musl, android_bionic and freebsd now build their manifest from a manifest(target) fn used by both install and lib.rs pinned_manifest(); Paths::doctor adds a 'sysroot up to date with pinned versions' check (fails exit 1). Darwin (user SDK) and msvc (xwin-resolved versions) have no pinned manifest and are unchanged. Tests in slate-sysroots/src/tests.rs: outdated doctor, replace on stale manifest, keep on current, failed rebuild keeps previous. Checked slate sysroot doctor on the real install (passes) and a temp install with an old glibc in the manifest (fails). README updated. Not the cause of slate-6cqm: that is update_filecheck.py running without SLATE_SYSROOTS (native headers) while the harness sets it.
