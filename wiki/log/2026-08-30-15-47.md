# slate-3f8g.4.14.1: support explicit register variables in inline asm

_2026-08-30 15:47:23_

Root cause: clang bakes register-variable bindings (register int x asm("eax"))
directly into the extended-asm's own constraint string as explicit register
constraints ("={eax}" out, "{eax}" in) - there's no separate CIR node for the
declaration. slate already resolved these correctly for operand emission
(asm_reg_for_constraint / AsmReg::Explicit already handled fixed-letter and
{name} constraints), but translate_asm_template bailed with `return None`
the moment any template placeholder ($0 etc) referenced an explicit-register
slot, producing "could not translate inline asm template".

Fix attempt 1 (wrong): just stop bailing and emit {slot} like a normal
operand. Rust's asm! actually forbids referencing explicit-register operands
via {N} placeholders at all ("explicit register arguments cannot be used in
the asm template") - confirmed by actually compiling the generated Rust, not
just eyeballing it.

Real fix: src/frontend/lowerer/asm.rs translate_asm_template now resolves
the register name via parse_reg_constraint + asm_reg_for_constraint for
explicit-register slots and substitutes the literal register name text
(with a `%` prefix under AT&T dialect) directly into the template instead of
a {N} placeholder. Added a dialect parameter threaded from
cir_asm_dialect(op.asm_flavor) at the intrinsics.rs call site.

Also found and fixed two unrelated but adjacent tool bugs while building the
fixture: both tools/update_filecheck.py and tests/differential.rs hardcode
-std=c23 for fixture translation/reference-compile, which rejects this GNU-
only declaration syntax (register variables predate and are unrelated to
C23). Added a targeted per-fixture override in both places (FIXTURE_STD_OVERRIDES
in the python tool, fixture_clang_arg_overrides/fixture_c_ref_std_override in
differential.rs) rather than flipping the global default, to avoid unknown
blast radius across the rest of the corpus.

Fixture: tests/fixtures/gnu_asm_register_variable.c, tool-generated FileCheck
on both profiles. Full rewrites (90/90) and lowering (10/10) suites pass.

New wiki/concepts/inline-asm-support.md tracks the supported/unsupported GCC
inline-asm surface, found by probing gh-search-sourced real-world constraint
shapes against the lowerer. Epic slate-3f8g.4.14 filed under the existing
GNU-asm epic slate-3f8g.4; slate-3f8g.4.14.2 (invalid asm! emission for
=@ccX flag-output constraints) still open, not started this session.
