# slate-8ge7.24.11.3 lowering compound_assign: write(P, op(read(P), e)) lowers to P op= e; rule deleted

Outcome: lowering emits `place op= e` directly from IR writes of the form write(P, op(read(P), e)), and the Rust rule compound_assign::recover is deleted.

C has no compound-assignment node in the IR: `x += e`, `x++` and `++x` have value semantics, so sema expands them into read/op/write temporaries, and inline-temps leaves write(P, arith(read(P), e)). A user-written `x = x + e` is the same IR, and both lower to `x += e`, as before.

Before (`*p *= next();` with p lowered through a temp pointer):

    unsafe {
        *__v1 = *__v1 * __v0;
    }

After:

    unsafe {
        *__v1 *= __v0;
    }

Rule: lowerer/statements.rs `updates_in_place` (IR) picks Write statements whose value is Arith add..shr with left = read of the same place. `same_place` / `same_operand` compare Binding, Deref, Field (not bit-fields), Index, ArrayDecay, PointerOffset, constants and plain reads, and reject volatile. The value, left operand and place types must be equal, so promoted `char c += 1` keeps `c = ((c as i32) + 1) as i8`. `compound_assignment` then folds the lowered Stmt::Assign when the value lowered to a Rust binary operator (not wrapping_add) whose lhs, after peeling an expression `unsafe { }`, equals the target. It also looks inside a single-statement Stmt::Unsafe.

Also: inline-temps now runs on NestedFunction and block-literal (^{}) bodies (InnerFunctions visitor in inline_temporaries.rs). Their read/op/write temporaries were previously only collapsed by Rust rules.

Wins over the old rule: `static mut` and raw-pointer places (`counter += by`, `*counter_ptr += 1`). The old rule did not see through `unsafe { }`. Rust inline_temps now also inlines the single-use temp pointer.

Fixture: crates/slate/tests/fixtures/compound_assignment_places.c (pointer, index, field, promoted, `a[i++] += 10` evaluating its place once, volatile kept). About 90 fixtures regenerated, including 4 in fixtures.release.

Limits: peel_unsafe is local. The general fix is slate-8ge7.24.11.9 (unsafe as a per-operation marker), and peel_unsafe is deleted when that lands.
