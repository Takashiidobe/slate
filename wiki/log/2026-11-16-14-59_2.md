# slate-f2zu.14.40.12 hoist_global_asm: file-scope asm local labels (int3_selftest_asm, uprobe_trampoline_entry) hoisted away from extern users

_2026-11-16 14:59:00_

- bead: slate-f2zu.14.40.12
- kind: bug
- area: crates/slate/src/project/link_order.rs
- corpus: linux

Outcome: `hoist_global_asm` keeps a file-scope asm block in its unit when it defines a non-global label (not `.L`, not numeric, no `.globl`/`.weak` in the block) that the unit declares in an extern block, so the label stays in the object of its users.

Symptom: vmlinux link: undefined `int3_selftest_asm`, `int3_selftest_callee` (alternative.c, shard arch_x86_kernel_r0) and `uprobe_trampoline_entry` (uprobes.c, arch_x86_kernel_r2). nm: defined as `t`/`r` (local) in the crate-root CGU, `U` in the unit's CGU.

C (arch/x86/kernel/alternative.c):
```c
extern void int3_selftest_asm(unsigned int *ptr);
asm(".pushsection .init.text, \"ax\", @progbits\n"
    "int3_selftest_asm:\n" "int3; nop; nop; nop; nop\n" ASM_RET ".popsection\n");
```
Cause: `hoistable` (crates/slate/src/project/link_order.rs) accepted any asm whose sym operands are local items; operand-less blocks always passed and moved to the crate root, separating local labels from their extern users.

Fix: `defines_declared_local_label` collects labels via `local_labels` and rejects the block if one is declared in an `Item::ExternBlock`. Unreferenced local labels (PREL32 initcalls `__initcall__kmod_...:`) are still hoisted, so .40.4's initcall ordering holds.

Kernel check: vmlinux links with 0 errors.

Limits: incomplete. rustc can still inline a small user of the label into another CGU (`local_sum_u1` inlined into main -> `U local_table_u1` in main's CGU; links with -Zcross-crate-inline-threshold=never). Fixture link_order_asm_cgu dropped until slate-f2zu.14.40.13 replaces hoisting with one CGU per unit.
See: slate-f2zu.14.40.4, slate-f2zu.14.40.13
