# slate-parser-6x05.46 gcc alignof_object_storage: __alignof__ of an object with incomplete struct type rejected as incomplete field type

_2026-11-17 22:21:57_

- bead: slate-parser-6x05.46
- kind: parser
- area: crates/slate-parser/src/sema
- flavor: gcc

Outcome: under the gcc flavor, `__alignof__`/`_Alignof` of an object whose type is an incomplete struct folds to the declared alignment (or 1) instead of failing with "incomplete field type".

Symptom: gcc accepts alignof of an extern object with an incomplete type and returns its alignment from the declaration; slate rejected it under every flavor with `incomplete field type`.

Reproducer:
```c
struct rq;
typedef struct rq rq128 __attribute__((aligned(128)));
extern struct rq requested __attribute__((aligned(64)));
extern rq128 lowered __attribute__((aligned(8)));
extern struct rq plain;
unsigned long a(void) { return __alignof__(requested); } /* gcc: 64 */
unsigned long b(void) { return __alignof__(lowered); }   /* gcc: 8 */
unsigned long c(void) { return _Alignof(plain); }        /* gcc: 1 */
```

Cause: the three alignof-of-expression paths (`TypeResolver::operand_layout` in sema/typer.rs, the constant folder's `AlignOfExpr` arm in `constant_value_with_context` in sema/types.rs, and `Lowerer::lower_expr` in sema/expression.rs) all call `measured_storage`. For an incomplete record, that returns `Rejected("incomplete field type")`.

Fix: the new `TypeResolver::alignof_object_storage` maps that error to a 0-byte, 1-aligned layout under `CompilerFlavor::Gcc` only. The result still goes through `declared_storage` (typedef alignment) and `object_alignment` (the declaration's `aligned` request), as for complete types. The lowerer emits a plain `const` (never an `align_of` LayoutQuery) when the type was not measurable, so the backend never sees `align_of` of an opaque type. Clang and MSVC still reject the code, as clang does.

Regression tests:
- crates/slate-parser/tests/fixtures/gcc/linux/x86_64/alignof_incomplete_object.c (IR checks; values match gcc -O2: 64/8/128/1)
- crates/slate-parser/tests/fixtures/error/clang/linux/x86_64/alignof_incomplete_object.c (clang still rejects)

Limits: the clang error text is still the generic "incomplete field type", not clang's "invalid application of __alignof to an incomplete type".
