# Corpus e2e: utf8proc, libexpat, giflib, lmdb, c-ares, libevent

_2026-10-05 15:08:58_

Six more corpus projects pass translated (slate-dghn.36-.40, .42); no lowering changes were needed.

Harness (tools/corpus/e2e.py):
- MakeLibrary recipe for in-tree Make libraries (giflib, lmdb): TUs from ar t of the archives, tools from a make variable, each tool relinked from make -Bn's link line with the archives swapped for the translated one, then the test command runs in translated and native sandboxes.
- make_variables expands values via an --eval print goal; make -pn printed them unexpanded.
- CMakeLibrary: components (more libraries to translate, libevent), test_env (c-ares GTEST_PRINT_TIME=0), compare_stdout=False (libevent output is not reproducible natively).
- ctest cases run in parallel with their ENVIRONMENT property; bash/sh wrapper scripts (libexpat run.sh) resolve to argv[2].
- Differential {output}: a fresh directory per run whose files are compared (xmlwf -d).

Setup: utf8proc UTF8PROC_ENABLE_TESTING, c-ares CARES_BUILD_TESTS, libevent EVENT__LIBRARY_TYPE=STATIC.

Results: utf8proc 10/10 ctest; libexpat 1/1 ctest + 36/36 xmlwf; giflib 51/51; lmdb mtest suite + dump round trips; c-ares 3/3 (1219 gtest); libevent 84/84 by exit code. zlib, cJSON, libyaml, lua, redis (barriers) rechecked.

Gotcha: an sccache server hung on the c-ares crate's cargo check; RUSTC_WRAPPER= worked around it.
