# #if true follows the dialect's standard

_2026-09-28 16:52:17_

const_expr evaluated #if with default StandardFeatures (no parser context), and the directive evaluator additionally hard-coded the identifier true to 1. So -std=c99 (clang and gcc) took the #if true branch; both oracles evaluate it to 0 before C23.

Fix: const_expr::Parser carries a features field; Parser::parse/evaluate take StandardFeatures and evaluate_with_defined takes &Dialect (replacing its target and flavor parameters). The evaluator's name == "true" special case is gone: in C23 the parser already produces BoolLiteral(true), and before C23 true is an ordinary identifier that evaluates to 0.

Fixtures: tests/fixtures/{clang,gcc}/linux/x86_64/pp_if_true_by_standard.c, C99 and C23 runs, verified against clang -E and gcc -E.

Nested const_expr parses without a parser context still fall back to StandardFeatures::default (Parser::new); only standalone entry points take explicit features.
