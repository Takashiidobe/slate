# C23 enumerator typing, fixed-type enums, gcc ?: pointer qualifiers (cxg.37 G)

_2026-09-28 13:52:41_

slate-parser-cxg.37 cluster G (c23-enum-1.c, c23-enum-6.c).

- Enum bodies (TypeResolver::define_tag) now type each enumerator per C23
  6.7.2.2 while the enum is open: int if it fits, else the promoted type of
  its value expression; implicit previous+1 keeps the previous type and
  widens (same signedness) on overflow. Values are BigInt (was i64). With a
  fixed underlying type the definition is completed (underlying + layout)
  before the first enumerator, so sizeof(enum E) works inside it, and values
  must fit the fixed type. Underlying = first of int/long/long long (signed if
  any value negative) that holds all values.
- fold.rs folds through enum_to_int of an enum-typed constant (or
  int_to_enum); C23 enumerators have enum type, so static_assert(A == 1) on
  one was "nonconstant" before, including for fixed-type enums.
- Block-scope `enum E : T;` declares a new E when an outer E exists
  (declare_forward_tag); callers still resolve the specifier, because T can
  define E itself (enum e4 : typeof((enum e4 : long {...})0, 0L)). Resolving it
  inside declare_forward_tag bypassed Lowerer::resolve_type and lost the
  nested enumerators. The assertion checker now resolves bare tag references.
- assertion_operand_type: Cast arm (type-name, unqualified); ?: falls back to
  a pointer-typed result when constant evaluation cannot type it.
- That fallback exposed that c11-qual-1.c / c23-qual-7.c passed only because
  the checker skipped them; the IR already picked the wrong _Generic branch.
  merge_pointer now takes PointerMerge rules (StandardFeatures::
  conditional_pointers): gcc drops _Atomic and, before C23, qualifiers of an
  array pointee; clang keeps both (verified with both compilers).
- nullptr_t -> enum with bool underlying is allowed (gcc accepts; clang
  rejects, permissive).
- sema/assertion.rs still has its own simplified enumerator loop in tag();
  resolve() overrides it, left as is.
