# Codegen-only flag table and flag_probe tool

_2026-10-04 16:44:28_

Groundwork for 6x05.38.4: cut the context an agent needs to add a compiler flag.
- compiler_args: CODEGEN_ONLY_FLAGS is now one table of CodegenOnlyFlag rows (spelling, switch or value form, accepting flavors, negation flavors). It replaces the all-flavor CODEGEN_ONLY_FLAGS/CODEGEN_ONLY_VALUE_FLAGS lists in ignored_option and CLANG_CODEGEN_ONLY_M_FLAGS. Matches record Opt::CodegenOnly(spelling), so check_flavor applies. No behavior change: the old rows keep all three flavors (msvc still accepts them, as before); -moutline stays clang only. The parser profile passes (7724).
- tools/flag_probe.py FLAG... [-- extra]: for gcc and clang it reports oracle vs slate-parser acceptance of the flag, its -fno-/-mno- opposite and a bogus =value, plus the predefine delta. Both sides expand the same probe file (cc -E -P vs slate-parser pp), each against its own baseline. DIFF lines mark gaps; exit 1 on any DIFF.
- wiki compiler-arg-rules: documents the table, the first-match order of parse_arguments (the ISA and -W matchers are broad: -mretpoline-external-thunk parses as an ISA feature, -Wa,/-Wp, as unknown warnings), and an 'Adding an option' checklist listing every touchpoint.
