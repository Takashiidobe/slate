# Lay out union flexible array members

_2026-09-25 21:50:02_

slate-parser-dyd.53: record layout only treated an incomplete array as a zero-size member when it was the last field of a struct, so a union with an incomplete array member failed with 'incomplete field type'.

- clang and gcc accept incomplete array members in unions (a GNU extension; clang warns only under -pedantic) at any position, including several per union and a union with nothing else. Each has size 0 and its element's alignment, and the union's size comes from its other members (clang -fdump-record-layouts and gcc agree: sizeof 4/0/4/8, packed 1).
- layout_record now applies the zero-size rule to any union member, and still only to the last struct member.
- Initializers needed no change: the existing flexible-array initializer path produces a sized array<T, N> member, as for structs. The object's extent is max(record size, member size) for a union. ir-spec says so now.
- New fixture: tests/fixtures/union_flexible_array_member.c.
- gnu_init_designator_survey.c now gets past the union and stops at (union Castable)five, a GNU cast to union, filed as slate-parser-dyd.63.
