Outcome: a kept `--merge` statement macro written `do { .. } while (0)` templates as plain statements (an early `break` becomes an `if`), because do-while-zero, block-flatten and labeled-blocks now also run in `Slot::BeforeMacroKeep` and enter `Statement::MacroExpansion` bodies.

Before (fixtures.merge/macro_templates.c):

```c
#define ONCE(a) do { if ((a) > 2) break; printf("small %d\n", (int)(a)); } while (0)
```

```rust
macro_rules! ONCE {
    ($a:expr) => {
        loop {
            if ($a) > 2 {
                break;
            }
            println!("small {}", ($a) as i32);
            if true {
                break;
            }
        }
    };
}
```

After:

```rust
macro_rules! ONCE {
    ($a:expr) => {
        if ($a) <= 2 {
            println!("small {}", ($a) as i32);
        }
    };
}
```

Rule: `inline_temporaries::children_and_expansions` lists a `MacroExpansion` body as a child; do-while-zero (`list`, `exits`), block-flatten (`list`) and labeled-blocks (`descend`) descend with it. Rewrites stay inside one body. labeled-blocks' `nested_breaks`/`replace` still use `children()`, and the visitor-based `all_breaks` sees nested expansions, so a block whose break sits in a nested macro is neither sunk nor dissolved (the counts differ). The passes run in both slots, so a kept body is rewritten before `macro_keep::kept_expansions` decides and is unchanged by the second run.

Checked: merge profile runs with SLATE_CHECK_MACRO_STRUCTURE (no provenance loss reported); slate and parser profiles pass.

FileCheck changes: fixtures.transforms/do-while-zero/macros.c (kept SWAP/CLAMP bodies unwrap); fixtures.merge macro_arguments, macro_caller_locals, macro_conditions, macro_control_flow, macro_dispatch_locals, macro_families, macro_name_arguments, macro_nesting, macro_repetition, macro_templates (the `loop { ..; if true { break; } }` wrapper is gone; some template suffixes renumber); fixtures bitint_stdc_bits, builtin_unsigned_mul_overflow, function_designator_compared_with_null, null_deref_macro_args, x86_64 object_alignment/vector_reduce_builtins (same, plus variant reorder).

Limits: an unwrapped template with a top-level `let` now leaves the binding in the caller's block, as `{ int t = ..; }` block macros already did. macro_rules hygiene hides the name, but the value lives until the caller's block ends.
