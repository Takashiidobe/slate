# Parse 'defined' as an operator only in #if/#elif

_2026-09-25 19:44:56_

slate-parser-cs2: const_expr::Parser, which is also the general C expression backend, recognised the identifier 'defined' as the preprocessor defined-operator in every expression, so 'int defined; ... = defined;' failed with 'unexpected token Semi' and 'typeof(defined)' with 'expected integer expression'. Fix: a 'directive' flag on Parser, set only by evaluate_with_defined, gates parse_defined. Checked that this covers every directive: #if and #elif both reach evaluate_condition -> evaluate_with_defined (pp/mod.rs walk_conditional), which is the only const_expr call in src/pp; #ifdef/#ifndef/#elifdef/#elifndef take a bare macro name and never parse an expression; __has_include/__has_embed/__has_* are expanded before evaluation. The evaluator's 'defined' call arm already required is_defined, which only the directive path supplies. Fixture tests/fixtures/sema/identifier_named_defined.c exercises defined in #if and #elif plus 'defined' as an object in typeof, an initializer and a macro argument; clang 22 accepts it; fails before, passes after. Noted but not filed as a bug: slate accepts a non-constant file-scope initializer like 'int b = defined;' (permissive, accepted cost). Verified with cargo clippy --allow-dirty --fix, cargo fmt, cargo nextest run --release (pass).
