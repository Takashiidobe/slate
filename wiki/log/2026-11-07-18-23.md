# Records with a trailing VLA member (gcc flavor)

_2026-11-07 18:23:24_

slate-parser-cxg.47: gcc accepts block-scope records whose member is a VLA (struct { int h; char a[n]; } x;). Supported shape: a trailing array member of a struct, or the only member of a union (VLA or fixed array of one); other VM members, records containing such records, and records in prototypes are 'not implemented' (slate-78pa.5); clang flavor reports 'fields must have a constant size'.
Parser: define_tag resolves gcc block-scope record fields with provisional extents and records the type in variable_records; member_storage lays the tail out like a flexible array (size 0, element align), so offsets stay constant. The checker records the bound's Extent conversion (assertion.rs tag()); lowering captures the bounds where the record is defined (typeof_evaluations TagSpecifier::Definition, also for declarator-less declarations and type names) and rebind_variable_member swaps the field's vla<T,*> for the captured extent. sizeof is runtime ((offset + tail + align-1)/align*align, record_runtime_size; runtime_size also handles fixed arrays of VLAs) and never an ICE (typer + constant_value_with_context use has_runtime_size). Reads by value are 'not implemented' (slate-78pa.4: pr27301, 20010605-1, 20030224-1).
Backend: storage_of(vla) is (0, align) so the struct gets a [T; 0] tail; Tables::variable_record makes such locals variably modified, stored as Vec<uN> (N = record align) of (offset + tail + align-1)/align units; vla_address handles field places (&raw mut field as *mut T); pointer arithmetic on them is a barrier.
