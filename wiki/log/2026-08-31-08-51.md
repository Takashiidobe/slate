# aarch64 char* struct field signedness fix (slate-vd43)

_2026-08-31 08:51:56_

Bug: on aarch64 (AAPCS64, unsigned-by-ABI plain char), struct fields declared
'char *foo;' lowered to *mut i8 instead of *mut u8, while local 'char *'
variables correctly got *mut u8. Local vars read signedness straight off CIR;
struct fields went through c_ast::parse_c_type, a Clang-AST-QualType-string
parser that hardcodes bare "char" as signed regardless of target.

Fix: rather than teaching c_ast.rs about target ABI (would duplicate clang's
own char-signedness logic and risk drift), extended
reconcile_anonymous_member_types in src/frontend/lowerer/record_analysis.rs
to adopt CIR-derived int signedness for every named record's fields, not just
anonymous ones. Added adopt_cir_int_signedness(), which walks matching
Ptr/Array nesting down to the leaf CType::Int and copies `signed` from the
CIR-derived type (cir_type_to_ctype/resolved_integer_parts), which is always
ABI-correct since it comes from real clang codegen for the target.

Fixture: tests/fixtures/bionic/struct_char_ptr_field_signedness.c (aarch64
flavor), struct with a char* field assigned into a matching local; asserts
both are *mut u8 via LOWERING-BIONIC-AARCH64-DAG. Verified it fails
(*mut i8) with the fix reverted, passes with it applied. Full `lowering`
profile (10/10) green after the change.
