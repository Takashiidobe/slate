# Rewrite nested libc calls

_2026-10-16 21:09:15_

slate-5vj0.5.8: libc_call only rewrote calls sitting directly in a statement slot, so strcmp(a, "x") == 0 inside an if, a compound assign, or a cast stayed a libc call.

- engine/mod.rs: RuleRegistry::candidates takes every name the node reads and unions the anchored rules for each, so a libc rule anchored on strcmp is a candidate for any node that calls strcmp anywhere in its expressions. NodeKind::call_anchor and expr_call_anchor are removed.
- rules/libc_call.rs: kinds add If, While, Match. When the top-level slot is not a known call, matches/apply search the node's expressions pre-order for the first nested site whose args lift (known_call_args) and have no side effects (inline_temps::expr_effects), and replace it in place; a Cast parent supplies the result type.
- Fixture tests/fixtures/libc_call_nested.c: strcmp, strncmp, strlen, strspn, strcspn, atoi fire nested; strcmp(next_word(), ...) stays a libc call.

Follow-ups filed: literal args still scanned for NUL in c_string_len; dead pointer lets after the literal lifts; gcc-dg split-5 flaky under load.
