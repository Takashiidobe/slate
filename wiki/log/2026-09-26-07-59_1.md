# Builtin status follows signature compatibility, not bare absence of a declaration

_2026-09-26 07:59:14_

dyd.45 (rewritten). Before: any declaration of a builtin name in scope made its calls plain calls to the declared function, so '#include <string.h>' + strlen() lost builtin semantics that clang keeps.

Now (sema/expression.rs builtin_callee): a call is a builtin when the name is undeclared, or when its reference resolves to a Function binding with external linkage whose type is ctypes.compatible with the builtin signature. Oracle: clang -ast-dump shows BuiltinAttr (Inherited) on compatible redeclarations - unprototyped 'int abs();', 'const double' params, restrict, a missing noreturn, block-scope extern decls, even external definitions (clang folds abs(-1) over a user body). Incompatible (int malloc(int)) and static declarations lose it.

Header provenance deliberately plays no part: neither clang nor gcc use it for builtin semantics. Provenance + signature is the libc-identity question for the Rust handoff, split out as dyd.64.

Conflicting __builtin_* redeclarations are a clang error; we accept them as plain calls (permissive). -Wincompatible-library-redeclaration text not emitted (diagnostic-only, per the dyd.17 policy).

Fixture fallout: 1438 fixtures regenerated; every changed line verified to be only a callee swap %N -> builtin name (abort, printf, exit, strlen, ...). New fixture: tests/fixtures/sema/ir_redeclared_builtins.c (-std=c17 so 'int abs();' stays unprototyped).
