# Compiler personality moves onto TypeResolver

_2026-09-19 19:40:47_

slate-parser-9ve.5. TypeResolver now carries a CompilerFlavor, set once in
with_tags from unit.flavor. All four resolvers already went through that
constructor, so the "share construction" work the bead anticipated was a
one-line read -- including assertion.rs, which needs it so a gcc-measured
static_assert on an atomic aggregate passes under --flavor=gcc.

Two rules read it: promotes_atomic_layout (clang rounds an atomic object up to
the next lock-free width, gcc does not promote aggregates at all) and
effective_alignment (clang honors a below-natural alignment attribute, gcc and
MSVC raise it). src/sema/module.rs no longer mentions CompilerFlavor.

The alignment rule went onto TypeResolver rather than into layout() as the bead
worded it: an object's alignment attribute is not a property of its type, so
layout(QualType) -> ir::Type is the wrong home. Personality-in-one-place is the
part that mattered.

lh7.2.30 closed. Re-measuring turned up something its table missed: the
clang/gcc divergence reaches member offsets, not just top-level size and align.
struct { char head; _Atomic struct { char a[3]; } value; char tail; } is 12
bytes with value at offset 4 under clang and 5 bytes at offset 1 under gcc. The
new gcc fixture is a separate file, since SLATE-FILECHECK-FLAVOR is per-file
rather than per-prefix.

MSVC turns out to match neither personality: a non-lock-free _Atomic gets a
lock word, size = 4 + round_up(sizeof(T),4) at align 4, leaving sizes already
1/2/4/8 alone. That changes the object representation rather than its layout,
so it needs a hidden field, not a StorageLayout tweak. Filed as rol; msvc stays
on clang's rule, no more wrong than before.

lh7.2.29 left open. The flavor reaches AbiClassifier now, but the C type does
not -- from_parts takes ir::Type, and resolve_type_module rebuilds the ABI from
a finished Module with no C types at all, so it is not the local change the
bead hoped for. No speculative parameter added.
