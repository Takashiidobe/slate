# Static assertions as void expressions (gcc)

_2026-10-09 17:35:18_

slate-parser-cxg.20.12. gcc 16 accepts static_assert (cond[, msg]) as a void expression in every mode (pedwarn before C2y); clang 23 rejects it in every mode, including -std=c2y.

- AST: ExprKind::StaticAssert(Box<StaticAssert>), parsed in const_expr primary when StandardFeatures::static_assert_expressions is on (gcc flavor only).
- Sema: the typer types it as void; Checker::subexpressions evaluates it with the existing static_assertion_error, so failures report in comma operands, ?: arms, casts and typeof. Lowering emits a void value (Slate lowers it to {}).
- Statements and for-init clauses that start with the keyword stay the declaration form. for (static_assert(...);;) previously failed as an unresolved name in every flavor; it is now StmtKind::StaticAssert in all flavors (C11 allows it; gcc and clang accept it).
- Fixtures: gcc-dg c2y-static-assert-2/3, error/gcc static_assert_expression_failed.c (matches gcc's four failures), error/clang static_assert_expression_rejected.c, clang static_assert_for_init.c.
- c2y-static-assert-4 reports 20 of gcc's 30 failures only because sema stops at ERROR_LIMIT = 20.
- Wiki: ast-spec, ast-grammar, ast-enum-touchpoints (Checker::subexpressions catch-all).
