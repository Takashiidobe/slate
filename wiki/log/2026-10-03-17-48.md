# Transparent-union parameters in function type compatibility (slate-parser-6x05.13)

_2026-10-03 17:48:05_

- Prototyped function types now treat a transparent_union parameter as compatible with any type compatible with one of its members, matching clang's mergeTransparentUnionType and gcc. glibc's getsockname (__SOCKADDR_ARG) now converts to int (*)(int, struct sockaddr *, socklen_t *).
- CTypes gained transparent_members, filled by TypeResolver::mark_transparent so the ctype layer can see union members.
- The composite keeps the left (earlier) parameter rather than clang's merged member type. Merging to the member made a redeclared function's call signature fn(ptr<i32>) while its definition took the union; keeping the union leaves redeclaration IR unchanged and makes function-pointer conversions explicit pointer_casts.
- Fixtures: transparent_union_function_compat.c (clang and gcc: getsockname, redeclaration, both pointer directions, ?:), error/transparent_union_function_non_member.c (no matching member still rejected).
- libuv sweep: 244/244 ok. gcc's only extra is a -Wpedantic 'not truly compatible' note, not emulated.
- Wiki: c-type-layer.md compatibility section.
