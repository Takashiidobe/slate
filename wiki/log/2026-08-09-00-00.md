# compile-time optimization pass

_2026-08-09 00:00:00_

A dedicated day chasing rewrite/compile-time performance, all through the salsa-backed query layer (`src/fixups/salsa.rs`, `src/fixups/query/context.rs`). Pattern across the whole day: a fact lookup that scanned a `Vec<Fact>` linearly per call site got replaced with a salsa-memoized `BTreeMap` keyed by the thing callers actually look up by, so repeated queries during fixup application stop being O(n) each.

- **Polynomial time in binding uses** (`65ab6bf3`): `binding_uses` was calling `self.expression_sites().into_iter()` — materializing and cloning the whole expression-site list — inside a per-binding loop; switched to `self.expression_sites.iter()` and only cloned the single matched site. Also added `[fixup-timing]` instrumentation (per-200-item heartbeats, per-candidate elapsed) to `ItemPlanBuilder` so future slowdowns are visible without a profiler.
- **`places_by_path` / `control_flow_by_key`** (`498be7e3`): added salsa-tracked `BTreeMap<AstPath, _>` and `BTreeMap<(ControlFlowSubject, AstPath), _>` indexes over places/control-flow facts, replacing linear `.iter().find(...)` scans in `SalsaFacts` lookups. Required deriving `salsa::SalsaValue` on `ControlFlowSubject` so it can key a salsa-tracked map.
- **`all_binding_refs` cache** (`c196a0e3`): added a salsa-tracked, function-flattened `Vec<BindingRef>` combining `bindings_typed` and `binding_types_typed` per function, and changed the single-binding lookup path to search the cached slice by reference (`.iter().find(...).cloned()`) instead of rebuilding+consuming an owned `Vec` on every call.
- **`functions_by_item_index`** (`2aa63b22`): reworked `src/fixups/salsa.rs` and `facts/walk.rs` (~150 line diff) to index functions by item index rather than re-deriving the mapping on each query.
- **Skip salsa DB creation** (`5a0644b9`): `src/fixups/mod.rs`'s `apply_with_logger` pass loop now skips constructing a fresh salsa `FixupDb`/`ProgramInput` for passes that don't need query-layer facts at all — a 256-line restructuring of the per-pass dispatch.
- **Borrow-alias reasons indexed** (`531ea115`): same by-key-map treatment applied to borrow-alias fact lookups in `salsa.rs`.
- **mimalloc + `#[global_allocator]`** (`426d6f11`): swapped the process allocator to `mimalloc` in `src/main.rs`, reported as ~25% faster overall alongside the def-use indexing changes in the same commit.

No test-suite regressions from these — all are cache/indexing changes behind existing salsa query APIs. Filed follow-up tickets for remaining compile-time work rather than chasing every hotspot in one sitting.
