# opaque and empty structs lower to FFI-safe zero-sized records

_2026-09-04 08:12:32_

slate-3f8g.5.10. A struct with no fields lowered to `#[repr(C)] struct X {}`, which rustc's improper_ctypes rejects: C has no zero-sized types, so an empty struct has no single C meaning (GCC/Clang size 0, MSVC size 1).

Two C shapes reach this, and both are now handled:
- forward-declared only (`struct my_handle;` used behind a pointer). required_record_defs in src/frontend/lowerer/module_index.rs synthesizes a placeholder Record with no fields when a name is required but never defined; c_ast::collect_records only ever collects completeDefinition records, so incomplete types arrive this way.
- defined but empty (`struct S {};`, a GNU extension).

Fix: reused the idiom already present for empty unions rather than inventing a second mechanism. A Rust union with no fields is illegal, so lower_record synthesized a `__slate_empty: [u8; 0]` field for those. That synthesis moved down into lower_record_def, where it now covers structs and unions and every caller, including the lower_shared_types cross-TU path that previously bypassed it. The empty-union special cases in default_value_expr collapsed into one kind-independent branch.

Consolidating was safe because synthesized_storage only ever gated cir_field_types, and an empty cir slice makes trust_cir false anyway, so the field falls back to c_record_field_type identically.

Verified rather than assumed:
- `struct my_handle;` and `struct S {};` both emit `__slate_empty: [u8; 0]`.
- Construction still works. A program that builds empty structs by value, copies them, passes one to a function, and nests one in a larger struct produces `empty_def { __slate_empty: [] }` and matches C (`3 7 4`).
- Rebuilding the gnu_libc_* crates gives zero warnings, down from three on hcreate_r/hsearch_r/hdestroy_r.

Reverted the earlier libc-shim/include/search.h workaround (giving struct __tab an explicit `char __opaque[0]`). It is unnecessary now, and the shim goes back to matching glibc's genuinely-incomplete `struct _ENTRY`, which also drops the over-permissiveness that workaround introduced: `sizeof(struct __tab)` is an error again, as against real glibc.

Five FileCheck snapshots went stale and were regenerated (gnu_empty_struct, macos/filesystem, macos/stdio_locale, bionic/fundamental_types, bionic/stdio_locale_conversion). All were shape-only; no stdout or exit-code diffs. lowering, rewrites, and libc profiles all green; clippy clean.
