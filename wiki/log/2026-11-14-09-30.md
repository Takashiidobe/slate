# slate-dghn.56.8 macro templates: nested macro place argument read outside unsafe (E0133 on (*view).suboffsets in ADJUST_PTR!)

_2026-11-14 09:30:53_

- bead: slate-dghn.56.8
- kind: bug
- area: crates/slate/src/frontend/lowerer/macro_sites.rs

Outcome: a macro place argument forwarded into a nested macro now gets `unsafe { $p }` around every value read in the nested template when the underlying place is unsafe to read, so cpython memoryobject.rs no longer fails E0133 at `ADJUST_PTR__3!(ptr, (*view).suboffsets, dim)`.

Symptom: cargo check of translated cpython: src/memoryobject.rs:6940 and :8697, E0133 "dereference of raw pointer is unsafe" on the call-site argument `(*view).suboffsets`. Not a pointer-lattice rewrite: macro template construction in lowering. The nested template was

    macro_rules! HAVE_PTR {
        ($suboffsets:expr, $dim:expr) => {
            !$suboffsets.is_null() && (unsafe { *unsafe { $suboffsets }.offset(($dim) as isize) }) >= 0
        };
    }

so the first read of the place argument expanded outside unsafe.

Reproducer (translate-project, or translate, which also lifts macros):

    #define HAVE_PTR(suboffsets, dim) (suboffsets && suboffsets[dim] >= 0)
    #define ADJUST_PTR(ptr, suboffsets, dim) \
        (HAVE_PTR(suboffsets, dim) ? *((char**)ptr) + suboffsets[dim] : ptr)
    ptr = ADJUST_PTR(ptr, view->suboffsets, dim);   /* view: const struct view * */

After: `!unsafe { $suboffsets }.is_null() && ...`, the crate builds and prints the native output.

Cause: FunctionLowerer::finish_macro_site (frontend/lowerer/macro_sites.rs) passes read_is_unsafe to macro_templates::make_place_parameter, which wraps the template's value holes of a place parameter as `unsafe { *$*p }`. read_is_unsafe was `matches!(argument, Some(Expr::Unsafe(_)))`, the shape of the lowered value argument. For HAVE_PTR nested in ADJUST_PTR the value argument lowers to ADJUST_PTR's own hole, not an Unsafe block, so the value hole stayed bare. The place hole read beside it was wrapped because place lowering decides from the IR place.

Fix: MacroSite gains unsafe_places; lower_macro_place_hole ORs in FunctionLowerer::place_is_unsafe on the IR place (which already looks through macro holes via without_macro_holes). read_is_unsafe is the old check or that flag. A first attempt keyed on a Deref in the lowered place broke the template self-check in macro_places.c and macro_dispatch_locals.c (a `*&mut n` local place is safe); the IR check does not.

Regression test: crates/slate/tests/fixtures.merge/macro_nested_place_argument.c (null and non-null suboffsets). slate profile 39/39, no other fixture output changed.

See: slate-dghn.56.7, slate-dghn.56.9 (same cpython check run).
