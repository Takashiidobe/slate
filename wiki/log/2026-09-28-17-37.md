# Key typedef and tag references by BindingId

_2026-09-28 17:37:45_

cc94.3. TypeSpecifier::Named and TagSpecifier::Reference now hold their name as Span<String>, so each typedef-name and tag reference has its own NodeId (default AST printing is unchanged). names.rs records references under that id, records a standalone struct S; that opens a new tag in declarations, exports NameResolution.tags (TagId -> BindingId), and now visits an enum definition's fixed underlying type.

TypeResolver drops its string scope stacks (ordinary, tag_names, push_scope/pop_scope/with_scope, lookup/lookup_local/declare, Ordinary): typedef aliases are aliases[BindingId], tags tag_bindings[BindingId]. define_alias takes the declarator NodeId. The lowerer's scoped/control_scoped wrappers and the checker's scope pushes are gone, since names.rs is the only scope model; the statement arms were rewritten without closures. MS asm typedef lookup goes through the reference binding; ms_asm_field scans all tag bindings newest first (permissive).

Behavior: since names are not keyed by tag kind, struct S after union S (reference, forward declaration or definition) is one binding and is now rejected (same_tag_kind), matching clang and gcc; previously they were two types. 'unknown type name' now underlines the name instead of the declaration.

Plan change for cc94.4: the checker and lowering each build their own TypeResolver/CTypes, so no per-NodeId type table can pass between them. New cc94.6 (depends on cc94.3, blocks cc94.4) shares one resolver first. Filed the block-scope typedef redefinition over-strictness separately.
