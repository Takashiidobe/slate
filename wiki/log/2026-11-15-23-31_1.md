# slate-3amj.37 lower_pointer_offset: overflow=wrap (-fno-strict-overflow) lowers to wrapping_offset, keeping vsnprintf end < buf overflow check

_2026-11-15 23:31:10_

- bead: slate-3amj.37
- kind: bug
- area: crates/slate/src/frontend/lowerer/pointers.rs
- area: crates/slate/src/frontend/lowerer/values.rs
- corpus: linux

Outcome: ValueKind::PointerOffset with overflow=wrap (set by the parser under
-fno-strict-overflow / -fwrapv-pointer, and for builtins such as
\_\_builtin_align_up) now lowers to wrapping_offset / wrapping_byte_offset
instead of offset, so LLVM keeps `end < buf` overflow checks.

Symptom: the translated kernel's every early printk faulted: PANIC: early
exception 0x0e IP vsnprintf+0x4db cr2 0x3003a36. vsnprintf does
`end = buf + size; if (end < buf) {...}` with size = INT_MAX; the Rust used
buf.add(size), LLVM folded `end < buf` to false, and end[-1] = 0 wrote to the
wrapped address.

Reproducer (minimal C, -O2 -fno-strict-overflow):

```c
__attribute__((noinline)) static int end_wraps(char *buf, unsigned long size) {
  char *end = buf + size;
  return end < buf;
}
```

Before: `let end: *mut i8 = unsafe { buf.add(size as usize) };`, so
end_wraps(buf + 8, ULONG_MAX - 1) returned 0 at release (clang: 1). After:
`let end: *mut i8 = buf.wrapping_offset(size as isize);` returns 1.

Cause: the IR already carried the fact (ptr_offset<..., overflow=wrap>, sema
pointer_offset from CompilerOptions.pointer_wrap); lower_pointer_offset
(crates/slate/src/frontend/lowerer/pointers.rs) ignored it and only used
wrapping_offset in static initializers, label addresses and function pointers.

Fix: lower_pointer_offset takes `wrap`; with it, the VLA case uses
wrapping_byte_offset and the void and plain cases use wrapping_offset (no unsafe
block). Same lowering clang does under -fwrapv-pointer (no inbounds).

Regression test:
crates/slate/tests/fixtures.release/no_strict_overflow_pointer_wrap.c. FileCheck
regenerated where the parser already emitted wrap: fixtures/align_builtins.c,
atomic_fallbacks.c, msvc/interlocked_volatile.c.

Limits: PointerDifference has no overflow field and still lowers to offset_from
(UB across objects); vsnprintf's `size = end - buf` after clamping did not need
it. Array subscripts are unchanged.

See: slate-f2zu.14.40.1 (no_builtins, same session), slate-f2zu.14.40.2.
