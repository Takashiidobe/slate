# slate-yar4.67 lower_stdc_rotate: preserve unsigned counts through modulo reduction

_2026-11-24 19:46:22_

- bead: slate-yar4.67
- kind: bug
- area: crates/slate/src/frontend/lowerer/bitint.rs
- area: crates/slate/tests/fixtures

Outcome: Both C23 rotate builtins preserve high bits of unsigned counts until reducing them modulo the operand width.

## Symptom

Rotating the value 1 in an unsigned _BitInt(17) by UINT64_MAX
produced 65536 on the left and 2 on the right. Both should produce
1 since UINT64_MAX is a multiple of 17.

## Cause and fix

The typed IR supplies a u64 count. The primitive remainder branch in
FunctionLowerer::lower_stdc_rotate cast it to i64, changing UINT64_MAX
to -1 and reducing it to 16. It now uses unsigned remainder for
unsigned counts and Euclidean remainder for signed counts, in a
primitive type wide enough for the input. The reduced shift is then
cast to u32.

## Regression test

crates/slate/tests/fixtures/bitint_rotate_unsigned_count.c checks both
directions. The C and translated Rust now both exit 0 on x86_64, i686,
aarch64, and armv7 Linux. Before the fix, translated Rust exited 3.

See: slate-6uvv.11.
