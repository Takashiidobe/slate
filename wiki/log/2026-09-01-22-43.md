# Fix libc headers for name-based long-double shims

_2026-09-01 22:43:09_

Unifying c_shim generation regressed the name-based shim path used by
differential batches (render_shim_c_source_for_names). Its preamble only
emitted F80/FENV headers, so wrappers around stdio/stdlib libc functions
(printf, sscanf, strtold, strfroml) hit -Wno-implicit-function-declaration
and were silently declared as returning int -- strtold returned garbage
(long_double_strtold_f80 differential mismatch).

Fixes:
- c_shim: derive #include headers in render_shim_c_source_for_names by
  extracting each shim's callee from its mangled name and looking it up in
  the Known catalog (header_for_shim_name), same bits/ filtering as the
  typed path.
- function_identity: add nan/nanf/nanl and sscanf to the Known catalog so
  their bridge shims carry identity + math.h/stdio.h provenance (nanl was
  previously Unknown, emitting a conflicting `long double nanl(char *)`
  prototype against libc's const-qualified declaration).
- c_shim: restore the `|| !trusted_headers.is_empty()` guard suppressing
  redundant prototypes when a trusted header already declares the callee.

All three nextest profiles (lowering, rewrites, libc) pass.
