# Lower __block variables to runtime Block_byref with scoped release

_2026-11-02 11:54:15_

slate-3amj.42.5: __block variables were leaked Box cells, so they never moved on Block_copy (C: &x changes, writes through the old pointer are lost) and never freed. They are now Block_byref (__slate_blocks::Byref<T>: isa, forwarding, flags, size, value); every access is *value(x) through forwarding, and by_reference captures are byref_field entries in the block descriptor, so the shared copy/dispose helpers call _Block_object_assign/_Block_object_dispose with BLOCK_FIELD_IS_BYREF. C never needs byref keep/destroy helpers. Structured functions: storage MaybeUninit<Byref<T>> is declared just before the declaration, then let x = byref(..), then let x_scope = scope(x) whose Drop releases the declaring scope's reference; dead_store now keeps __slate_blocks::scope like other drop guards (it had turned the let into an expression statement, dropping it at once). Goto-dispatch functions (previously a rustc type error): ByrefSlot<T> at the function top, init() releases the previous incarnation when a backward goto re-declares it, Drop releases at exit. New FunctionLowerer::pending: lower_statement emits it before the statement (saving/restoring around nested statements), so block literal slots and byref storage now live in the enclosing C block instead of the function top; under dispatch they are still hoisted. Fixtures: block_byref.c (forwarding, shared/escaping/per-iteration __block, no heap growth), block_goto.c (backward goto re-declaring a copied __block, no heap growth). Full slate profile passes; block_byref and block_goto also pass on i686 and aarch64.
