# slate-f2zu.14.18 overloadable: duplicate Rust fns per overload set (__acquire_ctx_lock) and export_name ignoring asm_name

_2026-11-14 17:29:37_

- bead: slate-f2zu.14.18
- kind: bug
- area: crates/slate/src/frontend/lowerer/names.rs
- area: crates/slate/src/frontend/lowerer.rs

Outcome: each `__attribute__((overloadable))` function gets its own Rust name, and exported definitions use the parser's `asm_name` (Itanium-mangled symbol or `__asm__` label) as their export name.

## Symptom

Kernel context-analysis helpers (include/linux/compiler-context-analysis.h) declare static inline overloads `__acquire_ctx_lock(raw_spinlock *)`, `(spinlock *)`, `(mutex *)`, ...; slate emitted one `fn __acquire_ctx_lock` per overload: E0428 duplicate definitions plus E0308 at calls (1728 + ~170 errors, 6+ shards).

## Reproducer

    static void __attribute__((overloadable)) acquire(struct spinlock *l) {}
    static void __attribute__((overloadable)) acquire(struct mutex *l) {}

## Cause

The parser already resolves every call to the chosen overload's binding, but `function_rust_name` derived the Rust item name from the C name only, so all overloads in a set shared it. Separately, the exported-definition path in `Lowerer` ignored `function.symbol.asm_name`, so extern overloads (and asm-labelled functions) exported their plain C name.

## Fix

- `name_overload_sets` (frontend/lowerer/names.rs), called from `Lowerer::new` after `names` is built: for a C name with more than one overloadable binding, rename each to `{name}__{index}` (1-based, module order) through `unique_name`, avoiding other function and global names. A lone overloadable function, or an unmarked one sharing the name, keeps the plain name.
- Exported definitions take `#[export_name = asm_name]` when the parser set one (`_Z5scalei`, `renamed_entry`), before falling back to the C name.

Rust has no overloading, and `macro_rules!` cannot dispatch on types; renaming per binding is enough because sema already chose the overload.

## Regression test

- crates/slate/tests/fixtures/overloadable_functions.c (static and extern overload sets, collision with a global named `pick__1`).
- crates/slate/tests/fixtures.library/overloadable_exports (native C caller links `_Z5scalei`, `_Z5scalel`, and an asm-labelled definition).

Limits: taking an overload's address (non-call use) is still a parser Unimplemented (slate-parser-6x05.42). Names are index-based, not type-derived.
See: slate-p58o.17 (same bug, closed), wiki/concepts/itanium-mangling.md
