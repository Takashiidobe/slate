# slate-5q63.22.5 databake spike: rejected for generated tables; quote + prettyplease for intrinsic-gen and libc-gen

_2026-11-18 16:01:22_

- bead: slate-5q63.22.5
- kind: bookkeeping
- area: crates/slate-intrinsic-gen
- area: crates/slate-libc-gen
- area: crates/slate/build.rs

Outcome: databake is rejected for slate's generated Rust tables; quote + prettyplease is the chosen emitter (follow-ups slate-5q63.22.6 intrinsic-gen, slate-5q63.22.7 libc-gen); the crates/slate/build.rs vendored table stays as is.

Spike: scratch crate (databake 0.2.1 + derive, quote 1, syn 2, prettyplease 0.2) baked the real GENERAL+X86 sections of crates/slate/src/frontend/lowerer/intrinsics_table.rs (5.4k IntrinsicSignature rows) both ways.

Findings:
- &'static data bakes correctly: `&'static str` -> literal, `&'static [T]` -> `&[..]`, Option, unit enums (`catalog::Kind::Global`). Output is deterministic; 1.42 MB in ~65 ms (quote: 1.35 MB, ~54 ms).
- Owned generator data does not bake to consts: String -> `"x".to_owned()`, Vec -> `alloc::vec![..]`. `#[derive(Bake)]` on a struct with String/Vec fields fails to compile (needs BakeSize). Generators hold owned data, so databake needs a parallel &'static mirror type per table plus Box::leak, which is as much code as one quote! row.
- Every derived type is emitted under a fixed `#[databake(path = ..)]` prefix and integers get suffixes (`0u32`); the path must match the consumer module, but the consuming types (Symbol, CLibRecord, IntrinsicSignature) live in slate or in the generated file itself, not in a crate shared with the generator.
- No `include_str!` support: the build.rs vendored table needs a macro call, so it would need quote anyway.
- Dependency cost: databake, databake-derive, synstructure on top of quote/proc-macro2/syn, which the workspace already has (syn 3 + prettyplease 0.3 in slate).
- Both routes through prettyplease expand one-row-per-line `#[rustfmt::skip]` tables ~8.7x (6.5k -> 46.7k lines). This is a one-time reformat and is acceptable for checked-in files.

Recommendation:
- intrinsic-gen and libc-gen: build rows with quote! and print with prettyplease (slate-5q63.22.6, slate-5q63.22.7). The libc-gen probe items (static S{i}, size_of/offset_of asserts) are Rust items, not data, so quote also covers them where databake cannot.
- crates/slate/build.rs: keep the single writeln!. Adding quote/syn as build-deps of slate costs every clean build for one line of output.

See: slate-5q63.22, slate-5q63.22.2 (build.rs via rust_ast).
