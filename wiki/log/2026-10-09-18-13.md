# slate-dghn.32: barrier-only inline asm already lowers

_2026-10-09 18:13:10_

The 2026-10-05 barrier probe counted empty and barrier-only inline asm as
barriers in curl (4544 rows from typecheck-gcc.h), stb, libsodium, mbedtls,
xxHash, quickjs and libuv. The parser-IR asm lowering (1f397413a, 9dbcb4900,
f4236e123) already covers every form: each becomes a real core::arch::asm!
with the same template and operands, which is more faithful than the bead's
proposed compiler_fence / black_box / spin_loop substitutes (the memory clobber
is kept by omitting nomem, and +r operands round-trip through a register).

Re-probe with lowering-barriers over build-clang compile databases:
curl 364 TUs, 0 barrier rows (4 TU errors are generated test bundles absent
from the build tree); libuv 244 TUs, 0 barrier rows.

Fixture tests/fixtures/asm_barriers.c pins the corpus shapes: asm(""), curl's
CURLWARNING function, "" ::: "memory", +r value barriers (incl. libsodium's
volatile uint16_t and the non-volatile asm("" : "+r"(e) :)), stb's input-only
""::"r"(ptr), pause, pause with memory clobber, and rep; nop. No Rust
changes.
