# Add translate-project target and feature matrix

_2026-10-30 18:21:54_

slate-mbr2.1.1: translate-project --matrix <file> --matrix-target <name> [--features a,b] translates one target and feature set from a hand-written JSON matrix, with no compile database, so host configure results cannot leak between targets. New crates/slate/src/project_matrix.rs validates the file up front (registry triple and flavor support, duplicate names, Cargo feature names, invalid_features groups, unknown fields). Generated headers are -I entries in a target's args; sources and args resolve against the project directory. Argument order: target, project, features.

tools/corpus/matrices/zlib.json declares 16 targets and 9 features. Linux (gnu and musl) and all 4 Windows targets translate; every feature and the all-features set translate on x86_64 linux; the linux-x86_64 crate passes cargo check. darwin and freebsd stop on 'expected RParen in declarator' (slate-parser-2ka9), android on <asm/types.h> (slate-e36k.2).

Z_SOLO and NO_STRERROR fail under real clang as well (gz*.c needs gzFile, compress.c needs NULL, gzread.c needs errno), so they are not slate bugs and are not features. Removed the slate-mbr2.1.6 -> .2 dependency since the matrix lists sources itself. Not done: Cargo [features] output (slate-mbr2.1.6), merged multi-target output.

Tests: fixtures.matrix/generated, with three differential.rs tests: C parity per feature selection, per-target headers and args, and rejected input. Full slate profile passes.
