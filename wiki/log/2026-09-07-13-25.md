# ARM32 double _Complex ABI bug confirmed fixed by rustc update, unskip complex fixtures

_2026-09-07 13:25:53_

slate-3f8g.4.16.13 was closed as an environment limitation: rustc's extern "C" ABI lowering for a #[repr(C)] struct of two f64 didn't match armv7 hard-float AAPCS-VFP's calling convention for C's native _Complex double, confirmed with a minimal hand-written repro segfaulting the same way as slate's output.

Re-tested after a toolchain update to rustc 1.100.0-nightly (2026-09-06): both complex and stdlib_complex_cx_limited_range now pass under --profile arm-rewrites (SLATE_ARM_LINKER/SLATE_ARM_SYSROOT must be exported manually in a bash session -- they're only set via the fish-only .env). Removed both skip_reason entries in tests/differential_arm.rs.

Running the full arm-rewrites suite with the skips removed surfaced an unrelated new regression from the same rustc update: gnu_builtin_debugtrap and target_stack_builtin_ops fail because rustc removed the abi_unadjusted feature (rust-lang/rust#161398), which slate's lowerer emits ('unsafe extern "unadjusted"' blocks) for these ARM32 builtin fixtures. Filed as slate-3f8g.4.16.19, out of scope for this ticket.
