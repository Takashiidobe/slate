# Lower remaining statement kinds explicitly; no module-statement catch-all

_2026-09-25 20:06:49_

slate-parser-dyd.26. `Lowerer::statements` no longer has a catch-all `Unsupported("module
statement")`. The match is exhaustive, so a new StmtKind fails to compile
instead of reaching lowering. Probing the 12 affected fixtures showed they
split 8 nested functions, 2 valueless returns, 1 attributed statement and 1
attribute statement. The bead guessed LocalLabelDecl and Pragma, but both were
already handled.

Each kind is decided per compiler (clang 22.1.8 and gcc 16 probes):
- `return;` in a non-void function: clang errors in every mode. gcc accepts it
  silently in gnu89 and errors from C99. MSVC documents it as warning C4033
  (not measured). New `StandardFeatures::valueless_return_in_nonvoid` (C89).
  It lowers to `return` with no value, with the same meaning as
  `fallthrough=ub_if_used`. Otherwise it is `Invalid`.
- Attribute statement: `[[x]];` or a label's `__attribute__((unused));` with no
  fallthrough becomes a null statement. Both compilers only warn.
- `[[x]] stmt` lowers the statement in place (no extra block, so case labels
  and declarations keep their scope), and its attributes are dropped.
  `[[fallthrough]] x++;` is Invalid except under gcc, which warns and ignores
  it.
- Nested function: clang has no support, so Invalid("function definition is
  not allowed here") under clang/msvc. Under gcc it is the narrower
  Unsupported("GNU nested function"), which is too strict. Filed
  slate-parser-dyd.56, which needs capture/closure IR.

Fixtures: sema/statement_flavor_rules.c (clang) and
sema/gcc_statement_flavor_rules.c (gcc; the gnu89 return lowers and gnu99
errors); each configuration was checked against the matching compiler.
parser_attributed_statements.c and gnu_misc_extension_survey.c now lower. The
10 others fail with the narrower messages.
