# Model x86-64 __vectorcall pass shapes

_2026-10-24 15:10:37_

slate-parser-x74n. rustc extern "vectorcall" uses win64 rules without HVA registers on both x86-64 OSes (1/2/4/8-byte records as integers, else byref/sret, empty result dropped, i128/f128 byref); clang uses SysV on linux and win64 + HVA registers on windows. Verified with clang -emit-llvm and rustc --emit=llvm-ir (no_core).
- src/sema/abi.rs: from_parts maps transparent unions first, then routes x86-64 vectorcall to x64_vectorcall_parts. On vectorcall signatures native_c means the rustc win64 model (rust_win64_pass) agrees with the C compiler.
- Linux (sysv_vectorcall_pass): full SysV shape of records/complex (explicit abi_pass shape, else sysv_c_shape/sysv_pass; >16 bytes memory, empty arg void), __int128 coerce<i64, i64>, __float128 coerce<f128>.
- Windows: HVA detection mirrors clang isHomogeneousAggregate for vectorcall (hva_members/hva_base/vectorcall_register_type: 1-4 members of one kind and size, complex = 2, no bit-fields/zero arrays/padding, empty record fields skipped); result HVA coerce; args use clang's two-pass allocation of 6 XMM registers, exhausted HVAs byref.
- sysv_record refactored onto sysv_c_shape + sysv_pass (no output change).
- ir: AbiChunk::Vector prints vector<T, N> for vector HVA members.
- Fixtures: clang/{linux,windows}/x86_64/abi_vectorcall.c. Docs: calls-abi x86-64 vectorcall section, ir-grammar chunk/void.
- Follow-ups: slate-lc0y (i686 vectorcall HVAs), slate-2910 (SysV records with vector members stay native_c), slate-clae (variadic vectorcall error).
