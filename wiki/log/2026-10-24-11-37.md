# Close libc identity signature check (won't do)

_2026-10-24 11:37:00_

slate-parser-dyd.64: considered requiring a builtin-registry signature match on top of system-header provenance for libc identity. Decided against it: genuine libc headers define the prototype, so provenance is sufficient, and slate-sysroots installs the libc headers for every target. The check would only matter for a non-libc header in a system include dir shadowing a libc name (compat shims, gnulib rpl_*), which is rare and absent from the corpus. No IR field or ir-spec change. Identity stays name + outermost system header in crates/slate/src/function_identity.rs (slate-5vj0.5.1). Revisit only if a corpus TU shows such shadowing.
