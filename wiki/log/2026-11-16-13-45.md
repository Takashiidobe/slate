# slate-f2zu.14.40.8 hoist_section_statics: hoisted link_section statics exported as \_\_slate_link_order_N lost their C symbol (227 modpost local symbol was exported)

_2026-11-16 13:45:56_

- bead: slate-f2zu.14.40.8
- kind: bug
- area: crates/slate/src/project/link_order.rs
- corpus: linux

Outcome: link_section statics hoisted to the crate root keep their C symbol
(export_name = "<C name>"), so exported kernel globals like cpu_khz and
boot_cpu_data are global symbols again.

Symptom: the first kernel relink after slate-f2zu.14.40.6 failed with 227
`ERROR: modpost: vmlinux: local symbol 'X' was exported` (cpu_khz,
boot_cpu_data, system_wq, \_\_per_cpu_offset, tracepoints, ...). 51 of 133
shards had a hoisted static that lost its symbol (~1435 statics).

Reproducer (two units, both placing a global in slate_shared_data):

```c
/* beta.c */
__attribute__((section("slate_shared_data"))) int shared_beta = 4;
/* main.c */
__attribute__((section("slate_shared_data"))) int shared_alpha = 3;
__asm__(".pushsection slate_symbol_refs,\"aw\"\n.quad shared_alpha\n.quad shared_beta\n.popsection");
```

Before: `rust-lld: error: undefined symbol: shared_beta`.

Cause: `hoist_section_statics` (crates/slate/src/project/link_order.rs) moves a
static whose section is shared by several units to the crate root as
`__slate_link_order_N` and leaves
`pub use crate::__slate_link_order_N as <name>` in the unit. It kept the
original attrs, so `#[no_mangle]` now exported `__slate_link_order_N`. Rust
references still worked through the alias; asm, ksymtab entries and other
shards' externs did not.

Fix: when hoisting, map `Attr::NoMangle` (and `CfgAttr(_, NoMangle)`) to
`Attr::ExportName(<C name>)`. Statics that were not exported (C `static`) keep
no symbol name as before.

Regression test:
crates/slate/tests/fixtures.release/link_order_static_symbol_name/ (main.c,
beta.c).

See: slate-f2zu.14.40.6, slate-f2zu.14.40.7
