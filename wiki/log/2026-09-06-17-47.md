# Consolidate inline-asm constraint/register parsing in asm.rs

_2026-09-06 17:47:27_

Follow-up cleanup to slate-3f8g.4.15.1, requested directly: centralize all GCC-constraint and x86-register-name string matching at the top of src/frontend/lowerer/asm.rs instead of scattering it across ad hoc functions. Added X86Reg (Eax/Ebx/Ecx/Edx/Esi/Edi) with from_spelling/sized_name/is_ebx_like/pick_ebx_scratch methods, replacing x86_register_letter_from_spelling, is_ebx_family_reg, x86_fixed_register_name, and pick_ebx_scratch_letter (all deleted). Renamed the .15.1 atom enum ConstraintAtom to Constraint and pre-declared the full storage-class table from wiki/concepts/inline-asm-support.md (ConstantEligible, Address, Memory, Offsettable, NonOffsettable, SseReg, AvxReg, ByteAddressableReg, EdxEaxPair) even though only Reg/General/FixedReg are consumed yet -- later slate-3f8g.4.15.{2,3,4,5,6,7} tickets get a real classification to match against instead of also writing the parser. Split asm_reg_for_constraint (now infallible) from a new resolved_asm_reg_to_backend, so intrinsics.rs's ebx save/scratch/restore workaround operates on typed X86Reg values instead of re-deriving the register family from a resolved string. AsmRegConstraint::FixedLetter now holds X86Reg instead of char. No behavior change: all 10 asm/gnu_asm/inline_asm fixtures pass unchanged. Also fixed an unrelated but discovered-in-passing bug in the global PostToolUse hook ~/.claude/hooks/strip-ai-comments.py (symlinked from claude/hooks/strip-ai-comments.py): its C block-comment stripper matched /_ anywhere in the text, including inside string literals, and deleted real code up to the next unrelated _/ it found -- it corrupted the '/_ {0:e} _/' Rust string literal this exact refactor emits. Fixed to require /\* be preceded only by whitespace since the last newline, mirroring the existing line-start rule for // comments.
