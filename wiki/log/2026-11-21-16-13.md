Outcome: every lowerer `__t` temp (`FunctionLowerer::next_temp`) is a Rust representation temp; none encodes C sequencing, so no IR transform was added and the inline-temps transform already sees all C-sequencing temps.

Why: C sequencing is already in the IR before lowering. Non-atomic `ValueKind::Update` (postfix, compound assignment) never reaches the lowerer: sema's effects normalization turns it into synthetic bindings (`%old_p` for `*p++`), which `inline-temps` then decides on. The lowerer reaches `Update` only with `ordering: Some(_)` (atomics), where the old value must come from one Rust `fetch_update`/`fetch_*` and cannot be split in the IR.

Method: `next_temp` temporarily tagged with `#[track_caller]`, `translate` over 3067 fixtures (tests/fixtures, gcc-torture, gcc-dg, c-testsuite, chibicc), counting temp creations per call site (creations, not surviving `let __t`). Instrumentation reverted.
