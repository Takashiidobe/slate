# slate-f2zu.14.34.36 lower_dispatch: BUG() ud2 then state store into a __builtin_unreachable block is an objtool unreachable instruction

_2026-11-16 21:12:53_

- bead: slate-f2zu.14.34.36
- kind: bug
- area: crates/slate/src/frontend/lowerer/control_flow.rs
- flavor: clang

Outcome: in a goto state machine, a transition into a block that starts with `__builtin_unreachable()` now lowers to `core::hint::unreachable_unchecked()` instead of `__slate_state = N; continue`, so the kernel's BUG() `ud2` is no longer followed by a state store that objtool flags as unreachable.

Symptom: objtool on the translated vmlinux.o:

    search_nested_keyrings+0x48e: unreachable instruction   (security/keys/keyring.c BUG_ON)
    assoc_array_walk+0x25d: unreachable instruction         (lib/assoc_array.c BUG_ON)
    ____bpf_prog_run+0x1c18: unreachable instruction        (kernel/bpf/core.c)

All three disassemble to `ud2; mov $N, %state; jmp <dispatch>`.

Reproducer (shape of the fixture):

    #define BUG() do { do { asm volatile("" ::: "memory"); } while (0); \
                       __builtin_unreachable(); } while (0)
    jumped:
      if (level & 1)
      consider:
        trace(...);           /* ({ if (0) printf(...); 0; }) */
      ...
      BUG_ON(x);
      ...
      if (...) goto jumped; else goto consider;

Before:

    6 => { asm!(...); if false { __slate_state = 6; continue } else { __slate_state = 5; continue } }
    5 => { core::hint::unreachable_unchecked(); if false { ... } else { ... } }

After:

    5 => { asm!(...); if false { __slate_state = 5; continue } else { core::hint::unreachable_unchecked(); } }

Cause: x86 BUG() is `do { instrumentation_begin(); _BUG_FLAGS(ud2...);
__builtin_unreachable(); } while (0)`. The inner do-while(0) ends its block, so
the unreachable starts a new dispatch block. LLVM does not thread the dispatch,
so the state store after the asm survives; objtool treats a __bug_table ud2 as
a dead end. clang emits nothing after the ud2. When structure_goto can
restructure the function, the do-whiles become loops and the problem does not
appear; it needs a CFG the rewrites leave as a dispatch (the fixture's label
inside an if body, as in assoc_array_walk). Not TrapUnreachable:
-Ztrap-unreachable=no would not help.

Fix: `FunctionLowerer::starts_unreachable` (lowerer/control_flow.rs) marks
blocks whose first non-comment node is a direct `__builtin_unreachable` call;
`lower_dispatch` shadows `jump` so every transition into such a block emits
`core::hint::unreachable_unchecked()`. The block itself becomes unreachable and
structure_goto drops it.

Verified on the kernel: the rebuilt lib/assoc_array.c unit is objtool-clean;
hand-editing keyring.rs the same way cleared both BUG sites there.

Regression test: crates/slate/tests/fixtures/goto_dispatch_unreachable_after_trap.c
(FileCheck shows the unreachable directly in the trap arm).

See: slate-f2zu.14.34.35, slate-f2zu.14.40.13.
