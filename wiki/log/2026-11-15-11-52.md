# slate-f2zu.14.34.15 asm specialization drop_unreferenced: static alias target (**do_sys_fork) deleted, so **x64_sys_fork alias never emitted

_2026-11-15 11:52:29_

- bead: slate-f2zu.14.34.15
- kind: parser
- area: crates/slate-parser/src/sema/asm_constants.rs
- target: linux

Outcome: asm-constant specialization no longer deletes a static function that is
only reached by name through `alias`/`ifunc`/`weakref`, so kernel
`SYSCALL_DEFINE0` targets like `__do_sys_fork` stay in the IR and
`__x64_sys_fork`/`__ia32_sys_fork` are emitted as `.set` aliases.

Diagnostic or IR fact that was wrong: in a TU where asm specialization runs (any
`"i"` operand that does not fold, which every kernel unit has),
`drop_unreferenced` removed internal functions that no body or initializer
referenced. An alias attribute names its target by string, not by `BindingId`,
so the target looked dead. A small snippet without such asm kept the target,
which is why the bead's hand-copied expansion did not reproduce it.

```c
struct key { int enabled; };
struct key k1;
static inline __attribute__((always_inline)) int branch(struct key *key) {
    asm goto("# %c0" : : "i"(key) : : yes);
    return 0;
yes:
    return 1;
}
static long do_fork(void) { return branch(&k1); }
long sys_fork(void) __attribute__((alias("do_fork")));
```

Before (-O2):

```
fn %6 @sys_fork() -> i64 [linkage=external] [alias="do_fork"];
```

(no `@do_fork` definition)

After:

```
fn %5 @do_fork() -> i64 [linkage=internal] [fallthrough=ub_if_used] { ... }
fn %6 @sys_fork() -> i64 [linkage=external] [alias="do_fork"];
```

Fix: `Lowerer::drop_unreferenced`
(crates/slate-parser/src/sema/asm_constants.rs) collects the `alias`, `ifunc`
and `weakref` names of every function and global and keeps any function whose
name is one of them.

Checked on kernel/fork.c (kernel compile_commands flags, preprocessed):
`__do_sys_fork` and `__do_sys_vfork` are now defined; before, both alias targets
were missing.

Fixture:
crates/slate-parser/tests/fixtures/clang/linux/x86_64/ir_asm_specialization_keeps_alias_target.c
(O2).

Limits: the match is on the C name; a target that is only named by its asm label
would still be dropped.
