# slate-f2zu.14.23 macro_keep Survey: parenthesized argument list spliced into a call kept as one $plist hole (ACPI_DEBUG_PRINT *const u8 vs u32)

_2026-11-14 18:58:53_

- bead: slate-f2zu.14.23
- kind: bug
- flavor: clang
- area: crates/slate/src/frontend/macro_keep.rs

Outcome: a macro whose single argument is spliced into several values (`#define DEBUG_PRINT(plist) ACTUAL_DEBUG plist`) is no longer kept as a template, so ACPI debug prints inline correctly.

Symptom: linux acpica dsargs.rs, dsdebug.rs, ...: `ACPI_DEBUG_PRINT!(512u32)` expected `*const u8`, found `u32` (56 errors). The template used `$plist` for every argument of `acpi_debug_print(...)`.

Reproducer:
```c
#define DEBUG_LEVEL(dl) (unsigned)dl, DEBUG_PARAMETERS
#define DEBUG_PRINT(plist) ACTUAL_DEBUG plist
DEBUG_PRINT((DEBUG_LEVEL(0x2), "exec\n"));
```

Cause: every piece of the parenthesized list carries `MacroArg { argument: 0 }`, and `lower_macro_hole` kept only the first value (`site.arguments[argument].get_or_insert`). The cover is not `CallArguments`, so `$plist__N` elements were not used either.

Fix: the keep `Survey` (frontend/macro_keep.rs) records each `MacroArg`'s printed value per (expansion, argument) in `argument_values` and rejects the expansion with `argument_split_across_holes` when two differ. Arguments with a `MacroCover::CallArguments` use are skipped, since their elements differ by design.

Regression test: crates/slate/tests/fixtures/macro_parenthesized_argument_list.c
