# Emulate cl.exe /source-charset /execution-charset /utf-8

_2026-10-25 13:15:22_

slate-3amj.5.7: msvc reads source and encodes plain literals in windows-1252 by default (wine's ANSI code page), as cl.exe 19.51 does; L"é" in a UTF-8 file is two units and u8"é" four bytes unless /utf-8 or /source-charset:utf-8. New crate::charset::Charset (utf-8, windows-1252 with MultiByteToWideChar's C1 fallback for the five unassigned bytes, '?' for unrepresentable characters). Source: Lexer::decoding (lexer.rs) splits each non-ASCII character into the windows-1252 characters of its bytes, keeping byte offsets, called from Preprocessor::parse*source with Dialect::source_charset(); a BOM'd file stays UTF-8. Execution: TargetInfo::execution_charset (set in Dialect::new) encodes plain literals in const_expr::execution_units, which now takes &TargetInfo. Options: /source-charset: and /execution-charset: accept utf-8, windows-1252, .65001, .1252, last wins; /utf-8 sets both, defines \_UTF8=1, and conflicts with either (D8016); an explicit execution charset sets \_MSVC_EXECUTION_CHARACTER_SET. All literal shapes (raw, \u, \x, wide, u8, char constants, BOM) checked byte for byte against cl. Fixtures: msvc/windows/x86_64/charset*_.c, error/msvc/windows/x86*64/charset*_.c; promoted slate msvc/flag*msvc*{execution_charset,utf8}.c. Follow-ups: slate-3amj.5.19 (-E output), .5.20 (C4566), .5.21 (other code pages). Note: the Bash tool turns a typed backslash-u escape into the character, so write C probes containing them with the Write tool.
