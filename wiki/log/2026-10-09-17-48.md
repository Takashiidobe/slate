# Validate and lower C2y named loop jumps

_2026-10-09 17:48:02_

slate-parser-cxg.20.13.
- Checker (sema/assertion.rs) tracks the labels leading to each loop or switch and resolves NamedBreak/NamedContinue to the innermost enclosing target with that label, recorded in TypeResolver::named_jumps. Errors: no enclosing loop/switch with that label, and continue naming a switch. Errors accumulate per item like other checker rejections.
- Flavor rules match each oracle. gcc: every label in a chain through labels, case/default labels, and attributes names the statement (c2y-named-loops-6), and named jumps are accepted in every mode (gcc only pedwarns before C2y). clang: only the label directly before the statement (attributes allowed); C2y/GNU2y only. MSVC follows the clang rule.
- Lowering maps loop/switch AST nodes to their IR ids (Lowerer::jump_targets) and emits Statement::Break/Continue with the target id; Slate already emits labeled Rust break/continue for non-innermost targets.
- gcc.dg c2y-named-loops-2/7 error lines match gcc exactly; clang flavor matches clang's error lines on c2y-named-loops-1/4/6.
- c2y-named-loops-4 (gcc run test) translated through Slate with --flavor gcc exits 0 like native. It cannot join Slate's gcc-dg suite: its clang C oracle rejects case-label naming. Added a clang-compatible differential fixture, crates/slate/tests/fixtures/named_loop_jumps.c, instead.
- Fixtures: gcc c2y_named_loops.c now IR in c2y/c23/gnu17 (was AST-only, C23 error); new clang twin (C23 rejected); error fixtures named_loop_invalid_targets.c for both flavors; gcc-dg c2y-named-loops-1/4/6 and c23-named-loops-1.
- The strip-ai-comments hook removes dg-options lines from Write-created C fixtures; re-added it with sed.
- Wiki: ast-spec named-jump rules, ir/control-flow named jump ids.
