# Accept __-named long double exports and callees

_2026-11-07 09:45:47_

slate-f2zu.10.1: lowerer/f80.rs refused long double bridges for any function name containing '__', since bridge symbols use '__' as a separator (__slate_ld__{entry}__r{tags}, __slate_{callee}__r{tags}). Bridge tags are alphanumeric and never contain '__', so the name round-trips if c_shim splits from the right: render_trampoline and header_for_shim_name now use rsplit_once. Removed the export-side check (long_double_export_name was then a passthrough; callers use long_double_entry_export_name). The call side now rejects only callees that would land in another shim family after __slate_ (names_shim_family: ld__, ldv__, vcall__, icall__, ldfp_, cb_); cb_ was already a latent misdispatch, as c_shim still treats __slate_cb_* as callbacks although nothing emits them. Fixtures: fixtures.library/long_double_dunder (cross-unit __ld_scale/__ld_twice, called from the C driver too), fixtures.library.unsupported/long_double_reserved_prefix (cb_half, ld__twice stay rejected). musl translate-project barriers 76 -> 13; remaining split into slate-f2zu.10.2 (complex long double exports), .3 (globals), .4 (nested case label). slate profile green.
