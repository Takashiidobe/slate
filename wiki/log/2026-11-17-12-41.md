# slate-3amj.56 classify_function: freestanding units no longer get Known libc identities, so memcpy/memset/atoi/strlen rewrites stop firing under -ffreestanding

_2026-11-17 12:41:31_

- bead: slate-3amj.56
- kind: bug
- area: crates/slate/src/function_identity.rs
- area: crates/slate/src/frontend/lowerer.rs
- area: crates/slate/src/backend/interproc/string_params.rs
- target: kernel

Outcome: in a freestanding unit (-ffreestanding/-fno-hosted, `Module.hosted`
false) libc names declared in system headers are no longer `Known`, so the
libc_call rewrites (memcpy/memset/strlen/strcmp/atoi...) and string-param
lifting through libc calls no longer fire; only `__builtin_*` symbols keep an
identity.

Symptom: with -ffreestanding and host <string.h>/<stdlib.h>, `memcpy(dst, src,
sizeof dst)` became `dst[..].copy_from_slice(..)`, `memset` became `.fill(..)`
and `atoi(s)` became a generated `__slate_atoi` helper, even though a
freestanding unit's library names have no standard semantics. slate-f2zu.14.34.3
had gated only std-introducing rewrites.

Reproducer:

```c
/* -ffreestanding */
#include <stdlib.h>
#include <string.h>
int main(void) {
  char dst[8], src[8] = "1234567";
  memcpy(dst, src, sizeof dst);
  return atoi(dst) == 1234567 ? 0 : 1;
}
```

Cause: `function_identity::classify_function` classified bodiless declarations
by name plus system-header provenance with no hosted check, so the lowerer gave
them `FunctionIdentity::Known`. `string_params::is_supported_libc_str_fn` also
matched callee names without looking at the call's identity.

Fix:

- `classify_function(name, system_headers, hosted)`: when not hosted, return
  `Unknown` unless `Known::from_builtin_symbol` matches. The lowerer passes
  `module.hosted`. Gated on hosted only, not `Runtime::Core`: -nostdinc hosted
  units (the kernel) keep libc semantics.
- `string_params` `Ctx::arg_use_allowed` takes `known_libc` (the call's
  `CallBinding::known()`), so a libc-named callee only admits a lifted string
  argument when the call is a recognized libc call. This also covers a hosted
  unit that defines its own `strlen`.

Regression test: crates/slate/tests/fixtures/freestanding_libc_calls_stay_plain.c

Limits: `length_lattice::utf8_owned_fill_proof` still matches "memcpy"/"memmove"
by name, but owned buffers are already off when any unit is Core, which covers
every freestanding unit.

See: slate-f2zu.14.34.3
