# Prototype unknown long double bridge callees

_2026-10-02 20:31:38_

slate-hi7g. c_shim::render_trampoline called non-callback bridge callees with no declaration in scope unless function_identity::Known supplied a header, so cc rejected the shim under -Wimplicit-function-declaration. Redis hit this with ld2string; the fixture uses libc qecvt/qgcvt, which are not in Known.

When a bridge has no known header, it now emits `extern <ret> __slate_extern_<callee>(<params>) __asm__("<callee>");` and calls that alias. The types come from native_c_type: long double for f80/ld, long double * for pf80, _Complex long double for cf80; otherwise c_type_for_tag. The asm label instead of a plain prototype is deliberate: the tags cannot tell long from long long, so a prototype could conflict with a header included for another shim. Callees with a known header keep the header path, so glibc redirects (strtold -> __isoc23_strtold) still apply.

Fixture long_double_unknown_extern.c failed first (implicit declaration of qecvt in slate_long_double.c) and passes now. The slate profile is green. The original link.rs long_double report is in a suite that is not in the slate profile (restoration is tracked under slate-p58o.6).
