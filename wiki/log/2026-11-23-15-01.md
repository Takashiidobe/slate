# slate-yar4.65 noreturn call lowering: _Exit tail returned unit and value calls appeared to return

_2026-11-23 15:01:40_

- bead: slate-yar4.65
- kind: bug
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/tests/fixtures

Outcome: Direct C noreturn calls diverge in generated Rust, including when an
ordinary Rust return type is needed for the call's surrounding expression.

**Symptom and reproducer**

```c
_Noreturn void _Exit(int);
_Noreturn int die(void) { _Exit(0); }
```

Before, `die` ended with `unsafe { _Exit(0i32) }` and rustc reported E0308
because the block had type `()` instead of `i32`. The IR already marked
`_Exit` and `die` as noreturn.

**Cause and fix**

`Tables::returns_through_unit` excluded library builtins along with codegen
builtins. The unreachable was also limited to standalone expression
statements. Treat library calls with ordinary Rust return types like other
direct calls and append `unreachable_unchecked()` after the call. In value
position, bind the call result before the unreachable to retain the operand's
type. A bare never-typed block cannot serve as the right operand of
`i32 + !`. Keep declared function and pointer signatures.

**Regression**

`crates/slate/tests/fixtures/noreturn_expression.c` checks a unit-returning
extern in the tail of an integer-returning function, a direct call in
arithmetic, and a function pointer with its declared integer return type.
The original CodeMetal `function_specifiers_c8a` translates, builds, and
exits 0 with the fixed Slate. Regenerated FileCheck for twelve fixtures whose
imported abort or longjmp calls now end in an unreachable.

See slate-f2zu.14.34.34 for statement-level lowering and pointer compatibility.
