# slate-f2zu.14.10 asm input_candidate: "i" operand from __builtin_constant_p ternary with __builtin_clzll (order_base_2) folds to imm at -O0

_2026-11-14 13:49:12_

- bead: slate-f2zu.14.10
- kind: parser
- area: crates/slate-parser/src/sema/asm.rs
- area: crates/slate-parser/src/ir/asm.rs
- corpus: linux

Outcome: when an asm input's constraint allows an immediate, a bit builtin with constant arguments inside it folds to a constant, so `"i"(order_base_2(64))` selects `imm` at every optimization level, as it does in gcc and clang.

Diagnostic or IR fact that was wrong: kernel/bounds.c `DEFINE(NR_CPUS_BITS, order_base_2(CONFIG_NR_CPUS))` was rejected with `no usable constraint alternative: [operand 0: NotConstant]`. The operand is `__builtin_constant_p(n) ? (... ilog2(n - 1) + 1) : __order_base_2(n)`, and the ilog2 inside it is `63 - __builtin_clzll(n)`. `__builtin_constant_p` already folded to 1, and `integer_with_objects` evaluates only the selected arm of a conditional. That arm still held a `call` to `__builtin_clzll`, because the bit-builtin fold from slate-f2zu.14.11 ran only inside static initializers. gcc and clang both accept this at -O0 too, so the bead's guess that it was an inlining limit was wrong.

Before (-O0, x86_64):
```
in 1 "i" [imm | sym] width 32 conditional<i32>(ne<i32>(const<i32>(1), const<i32>(0)), ... call<i32, signature=fn(u64) -> i32>(%14, ...) ...);
rejected: 0 (operand 1: not-constant);
```

After:
```
in 1 "i" [imm | sym] -> imm width 32 const<i32>(6);
```

Fix:
- `Lowerer::input_candidate` (crates/slate-parser/src/sema/asm.rs) sets `in_constant_initializer` while it lowers an input whose constraint `allows_immediate()` (a new helper on `AsmConstraint` in ir/asm.rs), then restores it.
- Only the bit-builtin fold reads that flag, and the fold applies only when every argument is constant. So `"ir"(__builtin_popcount(x))` with a runtime `x` stays a register call, and `"ir"(__builtin_popcount(0xf0u))` becomes `imm 4`.
- Spec: wiki/concepts/ir/builtins.md (bit operations).

Fixtures:

kernel/bounds.c now has no barriers.

Limits: the specialization-pass limits listed in the bead (tied inputs, InPlace/Memory operands, callees with static locals or nested functions) are still open. They moved to slate-f2zu.14.14, to be recounted after the next clang linux sweep, because no kernel site is known to need them.
