# Error fixture rendering matches between harness and updater

_2026-09-13 14:57:19_

Fixed slate-parser-niv: tests/filecheck.rs and tools/update_filecheck.py
rendered error fixtures differently.

- Root cause: run_error_fixture passed the original fixture (directives and
  CHECK lines included) to the binary, while render_error parsed a
  stripped copy in an isolated temp dir. A SLATE-FILECHECK-\* line above the
  code shifted diagnostic line numbers between the two.
- Second symptom of the same bug: a diagnostic whose span runs to EOF
  (atomic-errors.c) quoted the fixture's own CHECK lines in the harness.
  It was never caught because the harness cancels after a few failures.
- Rejected: making the updater render unstripped. Output then contains
  its own CHECK lines, so regeneration never reaches a fixed point.
- Rejected: line-preserving stripping (blank lines) in both tools. It keeps
  real line numbers but rewrites provenance line: values in 86 fixtures.
- Fix: run_error_fixture writes the stripped source to
  .<stem>.filecheck.<pid>.<slot>.c next to the fixture (as run_fixture
  already does) and rewrites that name to the fixture name in stderr.
  render_error now does exactly the same instead of using an isolated temp
  dir, so sibling includes (include-cycle.h) keep repo-relative paths.
- Consequence: diagnostics report stripped-source line numbers, same as
  normal-fixture provenance. asm-goto-no-labels-gcc.c keeps its directives
  above the code as the regression fixture.
- All 33 error fixtures regenerate byte-identical.
- Filed follow-up: harness error path ignores SLATE-FILECHECK-ISYSTEM.
