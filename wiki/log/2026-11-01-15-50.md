# Lower sizeof to size_of where the Rust layout matches

_2026-11-01 15:50:15_

slate-f2zu.9.5.12.20: sizeof now stays semantic in all output. IR: new ValueKind::LayoutQuery { query, amount } with LayoutQuery::SizeOf { ty, c }, printed size_of<size_t, T>(N); align_of and offset_of add variants in .24 and .25. Sema (size_query in sema/expression.rs) emits it for sizeof, except _Atomic operands, declared alignment and function operands, which stay const with size_of metadata. Constant readers (fold, integer_fits, x87, counted loops, sequencing, effects) read amount, so case labels and array bounds still fold. Lowering: lower_layout_query (lowerer/types.rs) prints std::mem::size_of::<T>() as size_t when Tables::rust_layout_matches_c holds and storage_of equals amount, else the number. T comes from lower_c_type, so sizeof(long) is c_long and merges across targets. rust_ast: Expr::LayoutQuery with TargetAmount, whose Eq/Ord/Hash ignore the value; otherwise identical bodies from two targets compare unequal and merge duplicates them. peel_casts collapses casts over a query when the amount fits, and drops as usize. length_lattice and libc_call const_len read amount, so malloc lifts and the fill rewrite keep firing. Gate excludes records holding long double or a u64 bit-field unit: on i686 their Rust layout differs from C (new bead under slate-yar4), previously hidden by the folded number. Merge fixtures: named_types goes from 2 gated to 0, cover_refine 7 to 3, hoisted size constants gone. Fixture: sizeof_fallback.c. Not run: zlib merge and its template remeasure. slate, parser and slate-targets profiles pass.
