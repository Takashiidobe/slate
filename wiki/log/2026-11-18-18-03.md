# slate-parser-6x05.38.9 pp #warning: ignored -Werror, -w and -Wno-cpp (Warning::Cpp)

Outcome: `#warning` now honors `-Werror` (becomes an error), `-w`, `-Wno-cpp` / `-Wno-#warnings` and `-Wno-error=cpp`, in clang and gcc flavors.

## Diagnostic or IR fact that was wrong
`record_directive_diagnostic` (crates/slate-parser/src/pp/mod.rs) pushed every `#warning` as `Severity::Warning` and bypassed `DiagnosticContext::severity`, so the driver flags never applied.

## Before and After
```c
#warning hi
int x;
```
Before: `slate-parser ir w.c -Werror` exits 0 and `-w` still prints `#warning hi`. After: `-Werror` fails with `× #warning hi` (exit 1); `-w`, `-Wno-cpp`, `-Wno-#warnings` print nothing; `-Wno-error=cpp -Werror` stays a warning.

## Fix
New `Warning::Cpp` (name `cpp`; clang's `-W#warnings` maps to it through `Warning::group`). `record_directive_diagnostic` resolves `#warning`'s severity with `context.severity(Warning::Cpp)` (default warning) and drops it when `None`. The printed diagnostic code is unchanged (`DirectiveDiagnostic.warning` stays `None`), so existing `#warning` fixtures keep their output. `#error` is untouched.

crates/slate-parser/tests/fixtures/error/clang/linux/x86_64/warning_directive_werror.c (`-Werror`). parser profile (9306) and slate profile (43) green.

Limits: `#warning` in a system header is still reported unconditionally, as before; the `-w` and `-Wno-cpp` paths were checked by hand, not by fixture.
