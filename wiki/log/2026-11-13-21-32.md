# slate-dghn.58 corpus numpy: clang-aarch64 cross flavor and aarch64 barrier report (NEON builtins, vector bit_cast)

Outcome: `e2e.py numpy --mode clang-aarch64 --setup` cross-builds NumPy for aarch64 with clang and writes an aarch64 barrier report; NEON builtins and vector `__builtin_bit_cast` are filed as slate-dghn.58.7 / .58.8.

- c_corpus_setup.py: new flavor `clang-aarch64` (CROSS table: triple, cpu family, sysroot `/usr/aarch64-linux-gnu`). Only `Configure` recipes with `meson_cross` properties support it (NumPy, `longdouble_format = 'IEEE_QUAD_LE'`). Setup writes `build-clang-aarch64/cross.ini` and passes `--cross-file`. CMake/Nmake flavor tuples are now spelled out so they don't pick up the cross flavor.
- e2e.py: `COMPILERS["clang-aarch64"] = "clang"`. `--target=aarch64-linux-gnu` survives `pp_diff.kept_args`, `--sysroot` is dropped (slate uses its own sysroots).
- The host CPython headers stand in for an aarch64 CPython (translation-only, nothing runs).

Result (2026-11-13): 151 TUs, 13 with barriers, 985 blocked (x86: 56, all SVML).
- 584 Convert: `__builtin_bit_cast` between vector types has no lowering on any target. clang's arm_neon.h uses it for every vreinterpret (slate-dghn.58.8).
- 401 function: 66 `__builtin_neon_*` builtins have no sema expansion and hit "vector C ABI" (38 also "builtin without a lowering"). slate-dghn.58.7 has the list.
- No SVE and no SVML on aarch64.

See: slate-dghn.58.6, slate-e36k.11, wiki/concepts/c-corpus.md
