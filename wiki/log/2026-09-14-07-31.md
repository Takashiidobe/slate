# Stop folding array bounds during parsing

_2026-09-14 07:31:37_

DeclaratorParser::parse_declarator (src/parser/declarator.rs) tried const_expr::Parser::evaluate first and folded successful array bounds into ExprKind::Integer, discarding the original expression (e.g. int a[1 << 3] lost the shift). It now always keeps the parsed Expr via const_expr::Parser::parse_expression.

Two size computations previously relied on the pre-folded Integer: const_expr::declarator_size and const_expr::ctype_size (both in src/const_expr.rs, used for #if sizeof and array-of-array sizing). They now call the new pub Parser::evaluate_ast(expr) to evaluate the kept Expr on demand.

tests/filecheck.rs's array_size() test helper (used when comparing against the clang oracle) had the same assumption; it now also evaluates via Parser::evaluate_ast instead of matching ExprKind::Integer directly, aliased as ConstExprParser to avoid colliding with parser::Parser.

Regenerated CHECK lines for ~30 fixtures whose array-bound dumps changed shape (Integer -> Binary/Paren/SizeOfType/...) via tools/update_filecheck.py --in-place. Removed the now-resolved migration row for this in wiki/concepts/ast-spec.md (was tracked as lh7.3.12).
