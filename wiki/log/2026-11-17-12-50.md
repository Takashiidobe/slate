# slate-yar4.47 asm_symbol: explicit "i"/"s" symbol operands for exported runtime symbols (memcmp, strlen) and ELF data aliases print the global name instead of sym of the local item

_2026-11-17 12:50:01_

- bead: slate-yar4.47
- kind: bug
- area: crates/slate/src/frontend/lowerer.rs
- area: crates/slate/src/frontend/lowerer/asm.rs
- corpus: linux

Outcome: an explicit asm symbol operand ("i"/"s", `AsmOperandKind::Symbol`)
naming an exported runtime-symbol definition (strlen, memcmp, ...) or an
exported ELF data alias prints the global symbol name in the template instead
of a `sym` operand bound to a local Rust item.

Symptom: in export mode `asm(".quad %c0" :: "i"(memcmp))` lowered to
`sym memcmp`, the private Rust body; the C-visible `memcmp` is the
`__slate_export_memcmp` wrapper, so the emitted address differed from `&memcmp`
(runtime_symbol_definitions printed `1 0` vs C `1 1`). `"i"(crypto_sbox)` for an
alias of a static lowered to `sym sbox`, a local symbol (what modpost rejects as
"local symbol was exported").

Reproducer:

```c
static const unsigned char sbox[4] = {1, 2, 3, 4};
extern const unsigned char crypto_sbox[4] __attribute__((alias("sbox")));
int memcmp(const void *a, const void *b, unsigned long n) { ... }
void refs(void) {
  __asm__ volatile(".pushsection .data.r,\"aw\"\n.quad %c0\n.quad %c1\n.popsection"
                   :: "i"(memcmp), "i"(crypto_sbox));
}
```

Before: `asm!("....quad {0}\n.quad {1}...", sym memcmp, sym sbox, ...)`.
After: `asm!("....quad memcmp\n.quad crypto_sbox...", ...)`.

Cause: `FunctionLowerer::asm_symbol` (frontend/lowerer/asm.rs) resolves a
binding to its Rust item. slate-f2zu.14.34.23 fixed only template words, by
leaving such names out of `asm_names`.

Fix:

- lowerer.rs: `asm_name_entries` builds the (name, binding, exported_elsewhere)
  list once; `asm_names` keeps its old result, and the new
  `Tables.asm_global_symbols` maps each exported-elsewhere binding to its link
  name, with the target's global prefix (`_` on Darwin and i686 Windows; a
  `\x01` asm label is verbatim).
- asm.rs: a symbol operand whose binding is in that map gets
  `Slot::GlobalSymbol` (no Rust operand) in both `lower_asm` and
  `lower_asm_block`; `asm_template` prints the name through the new
  `symbol_reference`, shared with the `{N}` path (modifiers, `$`, offset,
  `(%rip)`).
- The runtime wrapper may not exist (`runtime_export` returns None for
  non-castable signatures, and it is only known after the definition is
  lowered), so the literal name is used instead of `sym __slate_export_<name>`;
  it names the global symbol in both cases.

Regression tests: crates/slate/tests/fixtures.library/runtime_symbol_definitions
(`strlen_operand_ref`/`memcmp_operand_ref`), crates/slate/tests/fixtures.release/data_alias_units
(`emit_alias_operand_refs`, FileCheck shows the literal names).

Limits: memory operands whose address is such a symbol (`Slot::MemorySymbol`)
still use `sym` of the local item; same address, local binding.

See: slate-f2zu.14.34.23, slate-f2zu.14.29, slate-f2zu.14.34.16
