# Accept gcc's non-lvalue memory asm inputs and number hidden + inputs

_2026-10-10 15:20:51_

slate-parser-cxg.1. Two gcc.dg sweep gaps in asm operands.

Memory-only inputs: the sweep used gcc -fsyntax-only, which skips gimplify_asm_expr's 'memory input N is not directly addressable' check. With gcc -c, asm-10, tls/asm-1, 20010516-1, pr100501-1, pr100792-1, and asm-a on x86_64 are errors, so we were already right on those. The real gcc rule, probed against gcc -c on x86_64 and i686, accepts a non-void ?: (gcc takes the address of each arm), a comma or statement expression whose last operand qualifies, and an integer/pointer cast that keeps the precision (so _Bool, float, and array-decay casts are rejected) applied to an operand that qualifies. Tails that are bit-fields or register variables are rejected. The gcc flavor now accepts these in TypeResolver::gcc_memory_input (sema/asm.rs). Lowering trusts the checker and lowers them as spilled In(value) operands. clang rejects all of them and is unchanged.

Hidden inputs: gcc and clang both number one hidden input per + output after the explicit inputs and before goto labels ("+a"(b) makes %q1 valid). analyze_template now resolves those indices to the output they mirror, so the AST and IR shapes are unchanged. This applies to every flavor.

Fixtures: ir_asm_memory_gcc_rvalues.c, error/gcc/.../asm-memory-not-lvalue.c, ir_asm_read_write_operand_numbers.c (gcc and clang). Migrated gcc.dg torture/pr110228, torture/pr29119, and asm-a (new suites/gcc-dg/gcc/linux/i686). pr19345/pr27301 still fail on VLA struct members (noted on cxg.47). Wiki: ir/asm.md.
