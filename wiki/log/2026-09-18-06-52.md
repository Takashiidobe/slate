# Lower encoded string literals as values

_2026-09-18 06:52:48_

`sema::expression` no longer rejects `u"..."`, `U"..."` and `L"..."` used as
values. The string-literal arm now builds its array type with
`sema::types::string_literal_type` (the same helper `sizeof` already used), so
element width and signedness come from the encoding and the target instead of
being hardcoded to `char`.

`ValueKind::Bytes(Vec<u8>)` became `ValueKind::CodeUnits(Vec<u32>)`, displayed
as `code_units<ty>([...])`. The unit width is not stored on the variant: the
value's array element type already carries it, so a second copy could only go
out of sync. The variant was only ever constructed for string literals, so it
was repurposed rather than duplicated.

`u8"..."` still fails when assigned to `const char *` under `-std=c23`: the
literal gets `u8` elements while plain `char` is signed on this target. That is
the C17/C23 `char8_t` split tracked by slate-parser-47s.6, not a regression —
clang rejects the same code.

Fixture `tests/fixtures/sema/string_literal_sizes.c` grew utf16/utf32/wide
globals; all `bytes<...>` FileCheck lines were regenerated.
