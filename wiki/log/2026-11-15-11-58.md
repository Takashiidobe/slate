# slate-f2zu.14.34.16 lower_global_alias: data alias (crypto_aes_sbox \_\_alias(aes_sbox)) emitted no symbol

_2026-11-15 11:58:02_

- bead: slate-f2zu.14.34.16
- kind: feature
- area: crates/slate/src/frontend/lowerer.rs
- target: linux

Outcome: an exported `alias("target")` on a global variable now emits a
`global_asm!` `.globl`/`.weak` + `.set` symbol on ELF targets, as function
aliases already did. So `crypto_aes_sbox`/`crypto_aes_inv_sbox`
(lib/crypto/aes.c, EXPORT_SYMBOL) exist in the translated object.

Gap and why it mattered: `ModuleLowerer::declare` skips a global whose
`alias_target` resolves in-unit, and uses of the alias bind to the target's Rust
static. Nothing emitted the alias symbol itself, so other units, and modpost for
EXPORT_SYMBOL, failed with undefined references.

```c
static const unsigned char sbox[4] = {1, 2, 3, 4};
extern const unsigned char crypto_sbox[4] __attribute__((alias("sbox")));
```

Before: only `static mut sbox: [u8; 4] = [1, 2, 3, 4];`. A unit that reads
`crypto_sbox` fails with `rust-lld: error: undefined symbol: crypto_sbox`.

After: the unit also emits

```rust
global_asm!(".globl crypto_sbox\n.set crypto_sbox, {}", sym sbox);
```

Implementation (crates/slate/src/frontend/lowerer.rs):

- `lower_global_alias` runs over `module.globals` next to
  `lower_function_alias`. It needs an external alias that is exported
  (`export_symbols` or `include`), an ELF target (`elf_aliases`, shared with
  functions), and an `alias_target` that is a lowered static (`tables.statics`).
  It names the target through `binding_name`.
- `push_alias` holds the `.globl|.weak`, `.hidden|.protected` and `.set`
  emission. The function and global paths share it.
- The parser marks an alias global as `definition`, so `definition` is not used
  as the filter.

Fixture: crates/slate/tests/fixtures.release/data_alias_units/. impl.c defines a
static-target alias, a strong alias and a weak alias of arrays. main.c reads
them and writes through one alias. Cross-unit address equality is not checked,
for the same oracle-folding reason as function_alias_units.

Limits: the alias must have the same type as its target (`alias_target`). A
type-punned data alias still emits nothing.
