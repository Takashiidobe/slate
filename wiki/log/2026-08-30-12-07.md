# Hoist shared bitfield storage across translation units

_2026-08-30 12:07:15_

Closed slate-a28e.4.

Project translation previously hoisted shared record declarations without the CIR-derived bitfield storage wrappers used by field access lowering. Sibling modules therefore referenced __bitfield_N fields absent from the shared record.

Project loaders now merge bitfield storage metadata alongside CIR aliases. Shared-type lowering rebuilds bitfield-bearing records with positional storage fields, emits their wrapper module publicly in types.rs, and qualifies sibling-module wrapper references through the shared type module. Translation-unit-local wrappers remain private and are not duplicated.

Added shared_bitfield_record, a two-TU differential fixture that initializes ordinary and bitfield members in one module and reads them in another.

Validation: cargo fmt; cargo clippy; focused rewrites cross_tu test passed; full rewrites cross_tu suite passed 40/40 with 4 skipped.
