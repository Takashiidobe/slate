# Interned Ident for the worklist engine (slate-gfyj.2)

_2026-08-27 22:11:55_

Implemented slate-gfyj.2 from the rewrite-engine throughput epic
(slate-gfyj). Scope: interning for the worklist-based engine only, not a
whole-codebase Symbol overhaul.

rust_ast::Ident switched from an owned String to an interned, leaked
&'static str (new ident_intern module in rust_ast.rs). Equality/Hash compare
pointer identity, not string content -- this matters: deriving PartialEq/Hash
on a wrapped &str would silently fall back to byte-by-byte comparison, which
would have defeated the entire point. Public API (as_str/Display/From) is
unchanged so nothing outside rust_ast.rs needed to change; Ident is now Copy.

Considered storing just a u32 id with a lookup(id) -> &str table, but that
needs the interner's lock on every read, and as_str()/comparisons happen
constantly (codegen, string-literal matches). Storing the resolved &'static
str directly in Symbol means only intern() (new-string case) touches the
lock; reads are lock-free. Also dropped a redundant extra `id: u32` field
from an earlier draft -- pointer identity of the already-deduped leaked
string is sufficient, no separate id needed unless something later wants a
dense array index (e.g. def-use edges, slate-gfyj.3) rather than just
equality.

engine/arena.rs's NodeKind::Let/LetIf/For name fields switched from String
to Ident, converted at the build_stmt/reify_stmt boundary so the shared
rust_ast::Stmt (used by lowerer/codegen) stays String-based -- out of scope.
engine/rules/{zero_init,inline_temps}.rs's binding-name-threading helpers
(kind_reads_var, e_ident_count, locate_consumer, immediate_effectful_consumer,
etc.) now take Ident instead of &str, so declared == name comparisons are
O(1) pointer compares instead of byte comparisons -- this is the actual hot
path walked repeatedly per worklist iteration.

rewrites profile: 110/110 pass, including generated_differential.
