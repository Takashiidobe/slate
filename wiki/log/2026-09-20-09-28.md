# Source-location builtins and the __func__ family

_2026-09-20 09:28:57_

Implemented slate-parser-dyd.21 and dyd.22 together: they share the enclosing
function name, and the source-location half needed a real source map.

Key finding, which changed the design: Provenance is stamped per *logical
line*, not per token. pp::expand_line covers a line with Span::cover and
stamps every token on it with the first token's provenance. So
Provenance.line is exact for any token on that line, but a column taken from
it is always the line's first token. I had already added Provenance.column
and reverted it — it would have been wrong at every call site that is not
first on its line, and would have churned 6117 generated provenance blocks
across ~560 fixtures for a useless field.

Instead Files became the source map. The preprocessor already computed a line
table per file in parse_source; it now hands that table to Files, which gained
position(FileId, offset) -> (line, column), both zero-based. resolve_module
takes &Files and the Lowerer holds it, so a token's own Loc gives an exact
position. Line and column verified equal to clang on several layouts,
including a builtin on a continuation line and two builtins on one line.

dyd.22: __builtin_FILE, __builtin_FILE_NAME, __builtin_FUNCTION,
__builtin_LINE, __builtin_COLUMN. LINE/COLUMN fold to int constants, the rest
to an internal .strN global.

dyd.21: __func__, __FUNCTION__, __PRETTY_FUNCTION__ lower to the same kind of
global, as a char[N] lvalue via Lowerer::place, so sizeof, indexing and decay
all work without a synthetic binding. Name resolution skips the three names
when nothing else declares them.

__PRETTY_FUNCTION__ is a personality difference, confirmed by running both
compilers: for `static unsigned long n(int q, char *s)`, gcc prints "n" and
clang prints "unsigned long n(int, char *)". Split on CompilerFlavor.
The Clang spelling comes from a new CTypes::declaration_spelling, which
prints a type as a declaration of a name. That exposed a real renderer gap:
base() only emitted the separating space when the declarator was not a
suffix, so a bare identifier came out as "unsigned longn(int)". It now also
spaces when the declarator starts with an identifier character, which cannot
affect existing output because every other caller starts from an empty
declarator. Output is now byte-identical to clang's __PRETTY_FUNCTION__
globals.

Corpus IR sweep 2347/2674 -> 2354/2674, 0 regressions.
