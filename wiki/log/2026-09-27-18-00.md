# Support -masm=att|intel

_2026-09-27 18:00:24_

Added -masm=att|intel (slate-parser-25m.19). The value is parsed into CompilerOptions::asm_dialect (default att). sema::numeric::Context carries it, and sema/asm.rs uses it for x86 instead of hardcoding Att. That selects which side of a {att|intel} template alternation gets lowered, and it is printed as [dialect=...].

Oracle behavior (gcc 16, clang 22): both reject unknown values. Both reject the separate-argument form '-masm intel'; we accept it anyway, like every other value option (permissive). Neither changes predefines. On non-x86, gcc rejects the option and clang only warns that it is unused. Rules follow that: a GCC-branch target rule rejects it off x86, and MSVC lists it as unsupported.

Fixtures: sema/ir_asm_intel.c runs ir_asm.c's dialects() under -masm=intel, and the templates match gcc's assembly output exactly ('mov eax, %0', 'ac  f|g} i'). Error fixtures cover a bogus value, gcc with aarch64, and msvc.
