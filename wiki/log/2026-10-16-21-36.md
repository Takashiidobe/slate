# Give shadowed locals unique names inside the rewrite engine

_2026-10-16 21:36:01_

slate-5vj0.5.13: the arena keys defs and def/use by name, so two locals with the same C name (an inner block shadowing an outer one, sibling loops, a local shadowing a param) looked like one binding. remove_mut kept 'mut' on bindings only the other one mutated (including params), and slot_promote refused same-named dispatch slots.

- New engine/shadow.rs: a scope-aware walker over Stmt/Expr (lets, let-ifs, for patterns, closure params, match patterns, expression blocks, asm operands, atomic locals).
  - uniquify runs before arena::build. Every re-declaration of a name already used in the function (params included, '_' excluded) becomes '<name>__slate_shadow_N', and references are resolved to the nearest binding.
  - restore runs after reify. In creation order, each renamed binding goes back to its C name when it has exactly one binder and its scope mentions neither the C name nor another pending rename of it. Otherwise it gets the first free '<name>_N'.
- arena.rs: FunctionOptimizer keeps the rename table; source_name_bindings(name) returns all bindings sharing a C name. singleton_scopes uses it so flattening never creates avoidable '_N' names.
- Fixture shadowed_locals.c covers nested shadowing, a mutated inner shadow, a loop-body local reusing a later name, and a param shadow; all lose spurious mut and keep their C names.
- Baselines regenerated: asm_goto_statement_expr.c and statement_expr_local_label.c, whose two same-named dispatch slots now promote to plain locals (result, result_1).
