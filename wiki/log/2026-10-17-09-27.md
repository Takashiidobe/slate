# Model \_Float16 excess precision in sema and lower \_Complex \_Float16

_2026-10-17 09:27:59_

slate-kih1.4. clang evaluates \_Float16 (scalar and complex) + - * / in float and rounds to half once per operator chain on every target but aarch64 (native half on default cpus); slate's IR had plain add<f16>/mul<f16>, so a*b+c rounded twice (clang 0x1p-20, slate 0).

slate-parser: TargetInfo::float16_excess_precision (not AArch64); new ConversionReason::ExcessPrecision (printed excess_precision). Context::arith_value/unary_value wrap half binary ops (scalar emit_binary and complex_binary) as narrow<f16>(op<f32>(widen(x), widen(y))), unwrapping an operand that is already an excess-precision narrow so chains round once. Unary neg joins only when its operand is a chain. A same-type explicit cast retags the narrow as explicit (emit_convert_to now routes same-type casts through emit_arithmetic_conversion), ending the chain like clang's (\_Float16)(a\*b). Comparisons and stores see the rounded half value. Wiki: ir/operations \_Float16 excess precision, ir-grammar reason.

slate: complex<f16> is a lowerable type. Vendored num-traits 0.2.19 (crates/slate/vendor/num-traits) with Num/Zero/One for f16 behind an autocfg probe (has_f16, only on toolchains accepting #![feature(f16)]); num-complex depends on it by path, gets the same probe, real_arithmetic!(@values f16) and Complex<f16>::c_mul (native fast path, f32 Annex G fallback like libgcc **mulhc3) / c_div (via f32, like **divhc3). Needed for aarch64, where complex<f16> stays native. The harness and the CLI crate writer emit num-traits beside num-complex. Complex == real comparisons (either side) now lower the real side as a complex with zero imaginary part; num-complex has no PartialEq<T>, so this never compiled for any component type.

Fixtures: new float16_excess_precision (x86_64/i686/aarch64); promoted gcc-dg c23-imaginary-constants-7 and gcc-torture 20020227-1, pr56837 (mixed complex compares). Regenerated 6 parser FileChecks and float16.c. All four profiles green.
