# Corpus-driven raw lowering ratchet replaces phased migration focus

_2026-09-30 13:33:14_

Created epic slate-p58o.7 (P0) under slate-p58o and dropped every other open slate-p58o descendant (phases 1-6 and the Phase 3 lowering tickets) to P3. Decisions: legacy CIR suites are abandoned and in-scope single-file suites (tests/fixtures, gcc-torture, gcc-dg, c-testsuite, chibicc) switch to the slate frontend with no CIR fallback. The promotion gate is runtime parity (exit code plus stdout) of raw lowering only. Rewrites parity is deferred and stderr comparison stays off. All FileCheck blocks and region markers are stripped before failing fixtures move to unsupported buckets (tests/fixtures.unsupported, not *.ignored, which is for features Slate will never support). The existing git-mv supported/unsupported ratchet is reused, with no new fixture per lowering case and no caching beyond batch src/bin builds. Work is chosen from a per-function barrier report over ~/c-corpus/chibicc (clang mode, existing compile_commands.json); the milestone is translated chibicc passing its own test suite. Parser regressions from the ../slate-parser path dependency are accepted.
