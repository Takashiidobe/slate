# Generalize inline-asm constraint parsing beyond g/imr

_2026-09-06 17:31:41_

slate-3f8g.4.15.1: parse_reg_constraint (asm.rs) exact-string-matched only "r"/"g"/"imr", so alternative spellings containing 'r' ("ri", "rm", "mr") hard-errored despite the same soundness argument applying. Verified via CIR dump that Clang canonicalizes "g" to "imr" before reaching Slate, so no fixture ever exercised literal "g" — but "ri"/"rm" pass through unchanged. Fix: added a ConstraintAtom enum (Reg/General/FixedReg/Other) and a constraint_allows_generic_reg character scan, replacing the exact-string match. Also unified translate_asm_template's two independent constraint.contains('r') checks (deciding the :e/:x/:l/:r register-size modifier) into the same helper via constraint_wants_register_modifier — these had drifted from parse_reg_constraint's accepted spellings and could silently diverge again as more letters land in later slate-3f8g.4.15.\* work. New fixture tests/fixtures/gnu_asm_alternative_constraints.c covers "ri"/"rm". Memory (m/o/V), address (p), and register-class (x/y/q/Q/A) letters remain unsupported, tracked in sibling .15.{2,3,4,5,6,7} tickets.
