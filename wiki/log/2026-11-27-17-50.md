# slate-8ge7.24.23.1 block-flatten: declaration-free C blocks splice into their parent; loop-only labeled block dissolves onto its loop

_2026-11-27 17:50:26_

- bead: slate-8ge7.24.23.1
- kind: rewrite
- area: crates/slate-analysis/src/transform

Outcome: a new slate-analysis pass `block-flatten` splices every C block that binds nothing at its top level into its parent list, and labeled-blocks dissolves a labeled block whose whole body is one loop by retargeting its breaks to the loop, so lowering sees the plain loop body.

Before (emit-slate-ir --passes=all):

```c
int f(int a) { for (;;) { if (a > 9) break; a++; } return a; }
int g(int limit) { int i = 0; top: if (i >= limit) goto done; i++; goto top; done: return i; }
```

```text
for %12 ... body:
    {
        if gt(read(%4), 9) break %12;
        write(%4, add(read(%4), 1));
    }
block %23 {
    for %22 ... body:
        if ge(read(%9), read(%8)) break %23;
        ...
}
```

After: the for body is the two statements with no `{ }`; `block %23` is gone and the break is `break %22`.

Rule:
- `block_flatten::transform` (crates/slate-analysis/src/transform/block_flatten.rs): a `Statement::Block` whose top level has no `Let`, `Temporary` or `NestedFunction` splices into its parent (children first, so nested declaration-free blocks flatten all the way). A block that declares keeps its scope (shadowing, cleanup, VLA dealloc). The block's NodeId is retired. Runs after do-while-zero (which emits `Block(body)`), before labeled-blocks.
- `labeled_blocks::Pass::loop_block`: `LabeledBlock { id, [For|While|DoWhile] }` dissolves when every `break id` is reachable through `children()` (`nested_breaks == all_breaks`, so none sits in a statement expression); `retarget` rewrites `break id` to `break loop`. Covers structure_goto's `block %B { for { .. break %B } }`.

Measured: singleton_scopes::flatten over tests/fixtures/*.c + x86_64/ (857 files, SLATE_RULE_TRACE): 1617 fires / 369 files before, 1075 / 301 after.

FileCheck changes (all runtime-equal): decl-init now merges declarations that were behind a block (stdlib_fenv_access, stdlib_fp_contract, atomic_rmw_redis: `let mut x = 0; x = ..` -> `let x = ..`); cleanup_scoped_guard_for_goto's goto block label moves onto its `for`; macro template suffixes renumber (x86_header_expanded_builtins*, function_provenance, msvc/conditional_global_initializers), same bodies.
