# Block-scope typedefs and VLA {} initializers

_2026-09-19 14:29:46_

slate-parser-lh7.2.25. declaration() no longer rejects block-scope typedefs; block-scope tag definitions are still Unsupported ("block scoped tag definition").

The Lowerer never pushed TypeResolver scopes inside function bodies (only the static-assertion walker in assertion.rs did), so a block typedef would have leaked into file scope and later functions. New Lowerer::scoped(closure) push/pops around: the function body, Block, If then/else arms, Switch body, loop_body (While/DoWhile/For bodies), the whole For statement (init-clause scope), and statement-expression bodies. Labeled/case bodies are deliberately not scoped: they are not blocks.

typedef int T[n]; needed no new capture logic: declaration() already runs capture_extents on every non-global declarator before resolve_type, so the alias stores vla<i32, %e> with the captured extent, and every later T (objects, sizeof(T)) shares it even after n changes.

Aliases live in the module flat type table, so a block alias prints at module level as type @typeN T = vla<i32, %e>; naming a function-local extent. Left as is and documented in ir-spec.

VLA initializers: only an empty brace list is accepted, lowered directly to aggregate<vla<..>, zero_fill=true>() without going through initializer_value; anything else is now Invalid instead of Unsupported. The doubled c/c_canon metadata on an initialized typedef-typed local is pre-existing (fixed arrays do it too).

typedef in a for init-clause is invalid C (6.8.5p3), so the fixture does not use it. Fixture sema/variable_length_array_typedefs.c; ir-spec updated.
