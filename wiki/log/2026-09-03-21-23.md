# structure_goto stage 1: normalize the dispatch CFG

_2026-09-03 21:23:23_

slate-04q.85.3. The goto `__state`/`__dispatch` loop reached the rewrite engine full of
noise: arms whose entire body is `__state = M; continue` made up 8/15 states in
goto_nested_if, 9/16 in goto_irreducible, 6/13 in goto_switch_forward. Several
arms were unreachable outright.

structure_goto.rs (was a stub returning false) now jump-threads forwarding
arms, drops unreachable arms, and compacts the numbering. Output is still a
dispatch loop, so the change is contained: no lowering assertions moved, only
REWRITES snapshots.

Arms after normalization: goto_forward 6->2, goto_backward_loop 6->4,
goto_if_scope 9->5, goto_nested_if 15->7, goto_return_value 11->6,
goto_switch_forward 13->7, goto_multi_exit_loop 11->7, goto_irreducible 16->7.

Two things worth remembering:

- Threading stops dead on a forwarding cycle (`thread` returns the start state
  unchanged when the chain revisits). An earlier version returned a state on
  the cycle, which made the old->new remap non-injective and could collide two
  arms onto one pattern. Cycles here are `for(;;);` written with goto; giving
  up on them costs nothing.
- `arena.take()` bumps the slot generation and frees the id, so a later
  `set_kind` on that id silently does nothing. Rebuild a node's children via
  `get` + clone + `set_kind`, as structure_dispatch does.

Functions whose `__state` is assigned non-literally bail out entirely, so
computed_goto_ops.c and mem2reg_computed_goto.c are untouched — their jump
tables stay whole-function dispatch loops, which is stage 4's problem.
