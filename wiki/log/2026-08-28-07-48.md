# Pointer capability lattice: extended beyond c2rust

_2026-08-28 07:48:13_

Extends the c2rust-derived lattice in rewrite-worklist-engine.md with two
changes decided this session:

Key: W=write, U=unique, F=free, O=offset, G removed (see below), E=escape,
N=nullable, S=string (T in {u8,char}, nul-terminated + string-shaped use).

Core (Box<[T]> dropped -> always Vec<T> when owned+indexed; GROW fact
deleted from the lattice entirely, since Vec<T> is a strict behavioral
superset of Box<[T]> and differential testing can't distinguish them):

| W U F O | Resulting type |
| ------- | -------------- |
| . . . . | &T             |
| x x . . | &mut T         |
| x . . . | &Cell<T>       |
| . x x . | Box<T>         |
| . . . x | &[T]           |
| x x . x | &mut [T]       |
| . x x x | Vec<T>         |

String specialization (modifier, buffer rows only, T=u8/char + S fact,
reuses string_params/printf_format/ptr_len evidence):

| Base type (S) | Specializes to                                  |
| ------------- | ----------------------------------------------- |
| &[T] shared   | &str                                            |
| &mut [T] mut  | &mut str (needs extra UTF-8-safety fact, below) |
| Vec<T> owned  | String                                          |

&mut str caveat (burned on this in fixtures before): Rust requires &mut
str mutation to preserve UTF-8 validity. S alone is not sufficient
precondition for the &mut [T] -> &mut str row -- an arbitrary byte write
(memset-style) breaks it even when the buffer is otherwise string-shaped.
That row needs a stronger "all writes are ASCII/UTF-8-safe" fact or it
must fall back to un-specialized &mut [u8].

Full evaluation order: E (escape, short-circuits to raw *mut T/*const T)
-> core table -> S (buffer rows only) -> N (wraps result in Option<...>).
