# slate-yar4.48 crate_stack_protector: hosted crates whose units agree on -fstack-protector* build with -Zstack-protector; MachineCodegen carries stack_protector and stack_protector_guard

_2026-11-17 13:07:21_

- bead: slate-yar4.48
- kind: feature
- area: crates/slate-parser/src/ir/module.rs
- area: crates/slate-parser/src/compiler_args.rs
- area: crates/slate/src/main.rs
- area: crates/slate/src/backend/rust_ast.rs

Outcome: a translate-project crate whose units all set the same
`-fstack-protector`/`-strong`/`-all` level builds with
`-Zstack-protector=basic|strong|all`, so translated hosted C keeps its stack
canaries; mismatched, freestanding/-nostdinc, or custom-guard projects warn and
build without it.

Gap and why it mattered: slate-parser parsed the level into
`CodegenOptions::stack_protector` (only for the `__SSP*__` macros), but it never
reached the IR, and generated crates built with rustc's default (no protector).
Hosted C built with -fstack-protector-strong lost its canaries after
translation.

Before (`-fstack-protector-strong`, 8-byte overflow of a 16-byte local in
crates/slate/tests/fixtures.release/stack_protector_strong.c): C aborts with
`*** stack smashing detected ***`; Rust returned normally (exit 65).
After: the generated Cargo.toml has

```toml
cargo-features = ["profile-rustflags"]
[profile.release.package.stack_protector_strong]
rustflags = ["-Zstack-protector=strong"]
```

and the Rust binary aborts in glibc's `__stack_chk_fail` like C.

Implementation:

- slate-parser: `CodegenOptions.stack_protector_guard` (any
  `-mstack-protector-guard*` codegen-only flag); `ir::MachineCodegen` gains
  `stack_protector` and `stack_protector_guard`, printed in `machine [...]` as
  `stack_protector=off|on|strong|all|explicit` and `stack_protector_guard`
  (ir-grammar, ir/calls-abi, compiler-flags updated).
- slate: `rust_ast::Program.stack_protector`/`stack_protector_guard` from the
  module; `crate_stack_protector` (main.rs) maps On/Strong/All to
  basic/strong/all (Off, Explicit and unset are none) and returns a level only
  when every unit agrees, every unit is `Runtime::Std` (the kernel moves the
  canary off %fs:0x28, which rustc cannot express), and no unit set a guard
  option; otherwise it warns on stderr.
- `crate_manifest` writes the flag as package-scoped profile rustflags (merged
  with the link-order flags), so harness `RUSTFLAGS` overrides do not drop it.

Fixtures: crates/slate/tests/fixtures.release/stack_protector_strong.c; parser
clang and gcc linux/x86_64/codegen_flag_macros.c (new GUARD prefix; SSP, NOSSP,
SSPALL, KERNEL lines now show the fact).

Limits: `--merge` crates rebuild programs with defaults and get no flag
(slate-yar4.51). A program's own `__stack_chk_fail` stays private, so glibc's
handler runs (slate-yar4.50). `__attribute__((no_stack_protector))` and
`stack_protect` on single functions are not expressible and not warned about.

See: slate-yar4.50, slate-yar4.51, slate-f2zu.14.34.3 (Runtime::Core)
