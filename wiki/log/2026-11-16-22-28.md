Outcome: `e2e.py linux --until boot` (and `tools/corpus/kernel_boot.py <out>`) boots the native and translated bzImages under QEMU with a marker initramfs and diffs their normalized serial logs; the current kernel passes with 0 divergent lines.

Gap: boot checks were manual (`run-qemu.py` in slate-linux, interactive busybox), so a regression showed up only when someone booted by hand and read dmesg.

After:

    python3 tools/corpus/e2e.py linux --from boot --until boot
    == boot: ok {"marker": true, "native_marker": true, "seconds": 2.5, "failures": 0,
                 "only_translated": 0, "only_native": 0, "report": "boot.md"}

Implementation (tools/corpus/kernel_boot.py):

- initramfs: a static freestanding `/init` (raw syscalls: write marker, sync,
  reboot POWER_OFF) built with clang; the newc cpio is written in Python so it
  carries `dev/console` (5,1) without root. Cached under `<out>/boot/`.
- `make bzImage` in build-<mode> and build-slate when vmlinux is newer
  (`kernel_link.make` takes a target).
- QEMU: `-nographic -no-reboot`, `console=ttyS0 rdinit=/init panic=-1
  oops=panic`, KVM when /dev/kvm exists, else TCG (this host: TCG, ~2.5 s).
  Pass = marker seen and no failure line (panic, BUG, Oops, WARNING, RIP,
  UBSAN, lockup, RCU stall...) that native lacks after normalization.
- Normalization: SeaBIOS escapes and timestamps, hex, sizes and units, build
  number, CPU number, audit stamps, percpu/rodata layout sizes, slate_crate v0
  symbols demangled to the C name, `? ` unreliable frames; RTC time,
  sched_clock, stack-depth and TSC-refine lines dropped (calibrated on three
  native/translated boot pairs).
- Lines are compared as multisets, so async probe reordering is ignored;
  "first divergence" is the first translated-only line in boot order.
- boot.md: marker/timeout/failure table, new failure lines, first divergence,
  translated-only and native-only lines; raw and normalized logs in `<out>/boot/`.
- e2e.py: `boot` stage after `link`; `--from link` reuses the built shards,
  `--from boot` boots the linked vmlinux only.

Verified failure path: `--append rdinit=/missing` fails on the missing marker,
and the identical VFS panic in both kernels yields 0 new failure lines.

Limits: `--from link|boot` still rewrites translate.md as 0/0 shards (same as
`--from build` before). The layout difference (percpu static 187648 vs 175320
bytes, rodata 32768k vs 28672k) is normalized away, not checked.
