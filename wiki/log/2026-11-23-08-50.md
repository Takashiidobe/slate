# slate-8ge7.9.5 asm_direct_output: compatible locals receive register outputs directly

_2026-11-23 08:50:37_

- bead: slate-8ge7.9.5
- kind: feature
- area: crates/slate/src/frontend/lowerer/asm.rs

Outcome: Same-width integer and raw-pointer locals can receive register outputs directly in generated Rust.

Gap

Register outputs always went through an unsigned scratch local and a transmute.
The existing asm output rewrite cannot fold a cast or transmute writeback.

Before

C: `__asm__ volatile("addl $2, %0" : "+r"(value));` with an `int value`.
Rust: `inlateout(reg) value as u32 => __t0`, followed by a `u32` to `i32` transmute.

After

The same input emits `inlateout(reg) value => value`. The AArch64 exclusive loop emits
`out(reg) old` and `out(reg) status`, with both early-clobber constraints intact.

Implementation

`asm_direct_output` checks register and destination compatibility against the
scratch width. Once an output needs a separate writeback, subsequent outputs
also stay staged so a later direct write cannot move ahead of an earlier
possibly aliasing write. Repeated destinations stay ordered even when explicit
register operands print after positional operands. Keep encoded tied inputs
through explicit-register deduplication, then use the local in both AST fields
when the input and output refer to the same place.

Fixtures

`aarch64/asm_aarch64_exclusive_memory_constraint.c` covers two early outputs.
`x86_64/asm_dialect_switch.c` covers explicit and generic read/write registers.
`x86_64/asm_type_bridges.c` tests raw-pointer outputs and a staged write through
a pointer that aliases a later output local.

Limits: Init and dead-output elimination are separate.
See: slate-j3by.23 for the i686 `ms_asm_entry_labels` exit-code failure and
slate-xw0x.14 for the ARM `implicit_intrinsics` header failure.
