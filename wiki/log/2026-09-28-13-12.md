# Per-family GCC compiler headers

_2026-09-28 13:12:18_

slate-parser-cxg.38. GCC's installed include dir depends on the target: config.gcc sets extra_headers per cpu_type (i[34567]86 and x86_64 share one list from gcc/config/i386; aarch64 and arm have their own), x86 Linux adds mm_malloc.h from pmm_malloc.h (t-pmm_malloc), and ARM EABI installs libgcc/config/arm/unwind-arm.h as unwind.h plus ginclude/unwind-arm-common.h (t-bpabi). Linux sets use_gcc_tgmath=no, so there is no tgmath.h.

slate-sysroots (c6d039b) now writes compiler-headers/gcc-16.2.0/{x86,aarch64,arm}/include from one pass over the release tarball, with licenses and the manifest at the bundle root. CompilerHeaders::Gcc carries a GccFamily; the CLI takes 'compiler-headers gcc [x86|aarch64|arm]'. Verified: x86 matches the host gcc 16.2.1 and arm matches arm-none-eabi-gcc 16.2.0 byte for byte, apart from runtime-library headers (omp.h, gcov.h, sanitizer/, quadmath.h) and newlib's tgmath.h. aarch64 differs from the 16.1.0 cross gcc only in glimits.h, a 16.2 change.

slate-parser: TargetProfile gains gcc_headers: Option<GccHeaders>, which selects gcc-*/<family>/include for the gcc flavor (x86 for x86_64 and i686 Linux, aarch64, arm for armv7). The old flat gcc-*/include layout is no longer matched.

Effect: sampled vect tests that include cpuid.h via tree-vect.h go to 141/150. The emmintrin/nmmintrin repros now reach sema and fail on target builtins (cxg.43) and the hardcoded __m128 builtin names (v74.1.13). i686 and armv7 fail at #include_next into a missing libc sysroot (4abr).
