# FileCheck expectations ignore provenance line numbers

_2026-09-17 21:07:25_

Editing a header under the libc-shim isystem path shifted provenance line
numbers and restamped every fixture that reads it — 157 fixtures churned from
one header edit, with the diff carrying no signal.

`tools/update_filecheck.py` now emits `line: {{[0-9]+}},` for every rendered
provenance line number. The generator does this in
`escape_filecheck_literal`, next to the existing temp-path loosening; the
runner needed no change because FileCheck handles `{{...}}` natively. The
dump still prints the real line, so reading a fixture's expectations still
tells you it came from a header — only the exact number stops being asserted.

The loosening is scoped to system headers: `loosen_system_provenance` rewrites
a `line: N,` only when the preceding line is `kind: System,` at the same
indent. User-file provenance keeps its exact number, because those line
numbers live in the fixture itself and a wrong one is a real defect. This has
to run on the emitted block rather than in `escape_filecheck_literal`, which
sees one line at a time and would also escape the `{{` being inserted.

Regenerated the 560 fixtures that carry provenance lines: 7121 `line: N,`
expectations became regexes. All 7121 are `kind: System`; no fixture in the
corpus renders `kind: User`, so nothing exercises the guard (slate-parser-hxu).
Checked it directly instead: User kind, mismatched indent, and a missing
`kind:` predecessor all leave the number literal.

Two non-provenance lines also changed, in stat_struct.c and
stat_mtime_member.c: `rank: LongLong` -> `rank: Long`. That is the shim's
`__ino_t` moving from `unsigned long long` to `unsigned long` in
bits/types.h, from the "Verify Linux socketvar soundcard and stat headers"
shim commit. Correct for glibc x86_64, so accepted rather than reverted.

Gotcha for future batch regens: the shell here is fish, which does not
word-split a variable, so `python3 tools/update_filecheck.py $FILES` passes
one giant newline-joined path. Pipe to `xargs` instead.
