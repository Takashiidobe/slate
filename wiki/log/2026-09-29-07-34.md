# Checker reports type resolution, redeclaration and pragma rejections; lowering returns no Rejected

_2026-09-29 07:34:53_

slate-parser-cc94.5.6. A temporary hook logging every rejection that reached resolve_module found 33 across the gate: discarded TypeResolver errors (tag redefinition/kind mismatch, vector_size/ext_vector_type, __ptr32/__sptr, section on a field, ms_struct layout, unsupported _FloatN, enum constant folding), function redeclaration conflicts, and a malformed float_control pragma. After this change it finds none.
Checker::resolution reports the first Rejected per declaration from resolve/declarator_type (function, parameter, forward tag, declarators). declare_object applies inherit_convention and merges through the shared merge_redeclaration (function definitions also apply_convention of their attributes, as lowering does), so conflicts are reported at the declarator. The checker runs its own FloatingPragmas/FloatingRegion with lowering's placement and per-compound restore.
resolve_module passes item and finish_module errors through ResolveError::checked: any rejection lowering still raises is Internal.
Found by re-checking samples: the checker skipped typeof(type-name) operands, so an assignment in a VLA size inside one had no recorded conversion (gcc.dg vla-12.c internal error); lowering's place() had no __builtin_choose_expr arm though the typer calls it an lvalue (builtin-choose-expr.c). Both fixed and migrated to suites/gcc-dg/gcc.
Behavior change: a floating-point pragma right after a statement expression is now rejected like clang (lowering leaked compound_start out of the statement expression). parser_token_annotations.c used such a pragma mid-expression (clang rejects it too); it now uses GCC diagnostic push, same IR. Fixture fp_pragma_misplaced_after_statement_expression.c.
Spans: redeclaration conflicts point at the declarator. gcc-torture 20030224-1 now reports the gcc VLA struct member gap (cxg.47) before the later unresolved name.
Samples: cxg.31 is a default-error warning emitted by lowering (same class as cc94.5.7), not a ResolveError; v74.1.18 needs a matrix type.
