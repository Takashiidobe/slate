# Lower global string and array storage in the slate frontend

_2026-09-30 20:50:38_

slate-p58o.3.19 (also closes 3.37).

- Only compiler string-literal objects (.strN, a name no C identifier can have) still lower to read-only byte strings. User char arrays initialized from strings are now writable static mut arrays.
- ValueKind::CodeUnits lowers to an array literal, for globals and locals. Signed elements are sign-extended (0x80 -> -128 as i8) to avoid overflowing_literals.
- Static initializers accept array_decay of a string literal, so static char *names[] = {"a", "b"} lowers to b"a\0".as_ptr() as *mut i8 entries.
- New fixture global_char_array_storage.c: writable, padded, const, 2D and high-byte char arrays, pointer-to-literal array, writable local char array.
- Promoted: global_string_pointer_array, global_char_array_storage, 17 more local fixtures, 7 gcc-torture, 1 c-testsuite.
- Pointer-valued initializers other than literal decays remain 3.34. 3.13's named fixtures already pass; its bead is still open.
