# slate-f2zu.14.14 asm reselect: "i" after inlining with a tied input or a "g"/"rm" InPlace operand; static locals shared across clones

_2026-11-14 14:12:27_

- bead: slate-f2zu.14.14
- kind: parser
- area: crates/slate-parser/src/sema/asm.rs
- area: crates/slate-parser/src/ir/asm.rs

Outcome: at -O2, the always_inline specialization now resolves `"i"` operands in
asm that also has a tied input (`"0"(x)`) or a memory-capable lvalue input
(`"g"(*p)`, `"rm"`). A test confirms that clones of a callee with a block-scope
`static` share that one object.

Gap and why it mattered: `Lowerer::reselect` (sema/asm.rs) skipped asm with
`InOut { input: Some(..) }` and asm with an `InPlace` operand whose constraint
was not memory-only. A callee written like that kept
`no usable constraint alternative: [operand N: NotConstant]` even when every
call passed a constant. The bead also listed static locals as unsupported. In
fact a block-scope `static` lowers to a module global, so `specialize` already
cloned such callees, and all clones referenced the same global, which is
correct.

Before (`-O2`):

```c
static inline __attribute__((always_inline)) unsigned add_imm(unsigned x, int n) {
    unsigned out; __asm__("addl %2, %0" : "=r"(out) : "0"(x), "i"(n)); return out; }
```

`add_imm: no usable constraint alternative: [AsmRejection { alternative: 0, operand: 2, reason: NotConstant }]`

After: `add_imm__const1` with
`in 1 "i" [imm | sym] -> imm width 32 const<i32>(2)`. For `"g"(*p)`, the clone
has `in 1 "g" [reg | mem | imm | sym] -> mem ... place<u32>(deref(...))`.

Implementation:

- `reselect` no longer rejects tied inputs. A tied input stays in its output's
  slot, and the template pieces are already renumbered, so the identity mapping
  in `place_pieces` is right.
- An `InPlace` operand is reselected with its constraint narrowed to its memory
  classes (`AsmConstraint::retain_memory`, ir/asm.rs). The operand stays
  `InPlace`, selected as `mem`, which is the shape the first lowering gives a
  memory choice. Re-sourcing it as a register read would need a span that
  `reselect` does not have.
- An MSVC `Memory` operand still requires a memory-only constraint.
- Spec: wiki/concepts/ir/asm.md (immediates and symbols).

Fixture:

- crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/ir_asm_constant_after_inlining_tied_inplace.c
  (O2)
- crates/slate/tests/fixtures/x86_64/asm_immediate_after_inlining_tied_and_static.c
  (-O2). It covers a tied input, `"+r"`, a static counter shared across
  `counted(3)`, `counted(3)` and `counted(4)`, and `"g"(*p)`. The output matches
  clang -O2: `42 6 4 5 7 10`.

Limits:

- Callees with GNU nested functions are still skipped.
- An `InPlace` operand is always kept in memory after reselection, even where
  clang would pick a register. Both are valid for `"g"`/`"rm"`.
- I did not rerun the kernel sweep, so the real effect on the remaining
  NotConstant rows is unknown.
