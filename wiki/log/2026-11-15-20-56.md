# slate-f2zu.14.34.27 asm goto label: __slate_asm_target flag instead of __slate_state, so structure_goto structures asm-goto functions (objtool UACCESS false positives, ORC gaps)

_2026-11-15 20:56:36_

- bead: slate-f2zu.14.34.27
- kind: bug
- area: crates/slate/src/frontend/lowerer/control_flow.rs
- area: crates/slate/src/frontend/lowerer/asm.rs
- flavor: clang

Outcome: an asm goto label block now sets a local `__slate_asm_target` instead of `__slate_state`, so goto structuring handles functions with asm goto and they no longer stay `loop { match __slate_state }` state machines. objtool can now follow kernel stac/clac regions.

Symptom: objtool on the relinked vmlinux.o reported 59 UACCESS warnings in translated code: "return with UACCESS enabled" (fault_in_writeable, filldir, futex_get_value_locked, __se_sys_waitid), "recursive UACCESS enable", "redundant UACCESS disable" and "call ... with UACCESS enabled". The functions themselves were correct.

Reproducer (crates/slate/tests/fixtures/x86_64/asm_goto_loop_exit_label.c): early return, begin, then a loop over an asm goto whose label jumps to `out:`, then end. This is the kernel's user_access_begin / unsafe_put_user / user_access_end shape.

Cause: lower_asm emitted the label as `AsmOperand::Label { state: __slate_state, value }`, which prints as `label { __slate_state = N; }`. structure_goto::scan rejects any node that reads `__slate_state` without being a plain assignment, so every function containing asm goto kept its dispatch loop. That was 3993 of 4037 dispatch functions in the kernel shards. In machine code every edge went back through a compare ladder on the state register. objtool does not track register values, so it followed impossible paths from stac to the shared ret. On its first warning it abandons the function, so the instructions it had not reached yet got undefined ORC: 227 of 403 bytes of fault_in_writeable.

Fix: Node::AsmGoto in lower_dispatch (control_flow.rs) declares `let mut __slate_asm_target` (bool for one label, usize for several). lower_asm takes a label count, and each label block sets the target via asm_target_value. An if chain after the asm jumps to the label's state; otherwise it falls through to next. structure_goto now sees an ordinary branch. rustc -O folds the flag into the asm's direct jump, which I checked by hand on the fixture shape.

After (fixture):
    let mut __slate_asm_target: bool = false;
    core::arch::asm!("...je {3}...", ..., label { __slate_asm_target = true; }, ...);
    if __slate_asm_target { break; } else { i += 1 }

Verification: mm shard retranslated with the new binary. objtool --uaccess per object: 2 warnings -> 0. ORC: fault_in_writeable/fault_in_readable have no undefined ranges. Dispatch functions in the mm shard: 284 -> 6. The slate profile passes apart from FileCheck blocks, which were regenerated: 7 asm/asm goto fixtures, now all structured, plus the new fixture. msvc/x86_simd_intrinsics was regenerated too; its block was stale from a04ecd63b's `unsafe impl Sync for __SlateAlign16`.

Limits: the other shards' UACCESS warnings (readdir, futex, signal, rseq, socket, .altinstr_replacement recursive/redundant) are expected to clear but are unverified until the next kernel relink. .27 stays open until then.
