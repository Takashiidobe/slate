# gcc-torture: cast bit-count builtins to result width in parity lowering (slate-os0h.3.1.25)

_2026-08-30 19:13:38_

lower_parity (src/frontend/lowerer/arithmetic.rs) built count_ones() & 1
directly, without the same cast-to-result-type step lower_unary_method
already applied for trailing_zeros/leading_zeros/count_ones. Rust's
count_ones() always returns u32 regardless of receiver width, so when the C
builtin's result type was wider (e.g. __builtin_parityll returning through a
u64-typed local), the generated `let _vN: u64 = _v.count_ones() & 1;`
failed to typecheck (u32 != u64).

Fixed by casting count_ones()'s result to the target Rust type before the
`& 1`, matching lower_unary_method's existing pattern. Promoted
tests/fixtures.gcc-torture/builtin-bitops-1.c (git mv from .unsupported/).
Regenerated tests/fixtures/integer_bit_builtin_ops.c's FileCheck golden via
update_filecheck.py -- the u32 case now also carries an (harmless, correct)
explicit `as u32`. Full lowering (10/10) and rewrites (90/90) profiles green.
