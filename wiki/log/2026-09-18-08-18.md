# Enumerators carry attributes

_2026-09-18 08:17:58_

slate-parser-ixa.37. `enum E { A [[deprecated]] = 1 };` failed to parse:
`ast::Enumerator` was `{ name, value }` with no attributes field, the one
declaration-like AST node still missing it.

`Enumerator` gains `attributes: Vec<Attribute>` (skipped in Debug when empty,
so no existing fixture churn), and `parse_enumerator_list` calls the existing
`parse_attributes` between the name and the `=`. One construction site.

`ast-spec.md` already documented the field; the code had been lagging the
spec, so this brings them back in line.

Attribute validation followed the field: enumerator attributes now go through
`check_attributes` in `check_tag_definition`, closing a real inconsistency —
`__attribute__((aligned(n)))` with non-constant `n` errored on a struct field
but was silently accepted on an enumerator, where clang errors.

Bead correction. The acceptance criterion asked for the spellings to parse
"before and after the = value". The after-value position is invalid: C23
6.7.2.2 places the attribute-specifier-seq only between the enumeration
constant and the `=`, and clang 22 and gcc both reject
`enum E { A = 1 [[deprecated]] };` in either spelling. Implemented the real
grammar and added an error fixture pinning the rejection.

IR carries no attributes anywhere, so this stops at the AST.

Verified against clang and gcc over 12 placement/spelling cases, all matching.
Mutation-tested the new fixture.
