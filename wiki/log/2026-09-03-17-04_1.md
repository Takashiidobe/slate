# Fix C-unwind fn-pointer coercion + finish extern-block ABI regen

_2026-09-03 17:04:27_

Follow-up to 58791716 (turn external functions into extern C-unwind).
Investigated whether extern-block declarations (memcpy, free, read, etc.)
also needed C-unwind: no -- rustc's invalid_runtime_symbol_definitions lint
hard-requires exact "C" ABI for a fixed compiler-runtime symbol set, and the
pthread_cancel forced-unwind bug (see
pthread-cancel-forced-unwind-needs-c-unwind-abi.md) is per-frame on
slate-emitted function definitions, not on FFI declarations, so extern
blocks correctly stay "C".

Real bug found: cir_fn_type_to_type() always types function-pointer VALUES
(Option<fn>) as C-unwind, but Some(name) for a name backed by a raw "C"
extern declaration (free, or a __slate_ld_* long-double C-shim trampoline)
doesn't implicitly coerce across the ABI mismatch -- E0308. Fixed in
function_pointer_operand_expr (lowerer/values.rs): when the referenced name
is in the new self.externs-derived extern_fn_ptr_types map or in
long_double_shims, emit an explicit
transmute::<*const (), Option<TargetFnPtr>>(name as *const ()) instead of a
bare Some(name) -- a bare inferred transmute() (no turbofish) works for
simple let/call-arg contexts but fails to infer Dst under looser contexts
like `... as *const u8` comparisons (gnu_symbol_pragmas), so the turbofish
needed a real target type; added extern_fn_ptr_type()/extern_fn_ptr_types to
carry it from ExternFnDecl through to this call site.

Also finished regenerating the extern "C" -> "C-unwind" FileCheck text that
58791716 left stale across tests/fixtures/*.c (auto, via
just regen-filecheck) and the handwritten tests/fixtures.multi,
tests/fixtures.library, tests/fixtures.link fixtures (by hand) --
except genuine `unsafe extern "C-unwind" { ... }` block headers, which
were reverted back to "C" since those declare real external symbols.

All three profiles green: lowering 10/10, rewrites 92/92, libc 34/34.
