# x87 and MMX asm operands via memory spills (3f8g.4.17.19)

_2026-10-09 22:03:22_

Rust asm! has x87_reg/mmx_reg only as clobbers; GNU t/u/f and y/Ym operands now lower by spilling through memory.
- Parser selection: explicit st/st(1) (t/u) and x87_reg (f) inputs are usable for float/double/long double, else width (clang can't allocate {st} for an int). =f outputs stay rejected (both compilers reject). mmx_reg fits 32/64 bits; clang also widens a char, which we reject (barrier, not guessed). Other st(N), mm, tmm hard registers stay clobber-only.
- Slate: each spilled operand passes a temp's address in(reg). Stack layout probed against clang and gcc: t at st(0), u at st(1), f inputs below in operand order; loads go deepest first (flds/fldl/fldt). After the template, outputs pop in order (=t, then =u), then each untied input whose register isn't clobbered is popped with fstp %st(0). All 8 st registers are clobbered, so Rust guarantees an empty stack on entry, and the spill code leaves it empty.
- MMX pins a free mm register (avoiding clobbers and explicit operands), uses movq/movd, and clobbers it.
- Spilled outputs drop pure/nomem/readonly; spilled inputs turn nomem into readonly.
- Fixtures: x86_64/asm_x87_mmx_operands.c (fsqrt, fpatan, fsincos, fucomi with flag output and surviving inputs, f inputs, fildl, +t, paddw/paddd). gcc -O1+ disagrees with clang on atan2(-0.0, sqrt(1 - x*x)) == 0 when inlined, so that line was dropped; the torture test checks it as a double.
- Promoted gcc-torture 990413-2 from .ignored (its old note said this couldn't be fixed). Dropped its TRIAGE.md row.
- Parser fixtures ir_asm_classes.c (new spilled() cases) and ir_asm_alternatives.c regenerated.
- Validation: full slate and parser profiles green.
