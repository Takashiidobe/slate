# errno/stdio redirects lower correctly; wire msvc translate for non-aggregate fixtures

_2026-09-04 17:30:23_

slate-wlpp.4 (UCRT macro redirects): errno and stdin/stdout/stderr are already
declared correctly in the shim as macro redirects to `_errno()` and
`__acrt_iob_func()` (bits/msvc/{errno,stdio}.h). Since CIR sees post-
preprocessor C, these lower through the ordinary extern-call path with no
special-casing needed -- generated Rust calls `_errno()`/`__acrt_iob_func(N)`
directly, never inventing a data symbol for `errno`/`stdin`.

Found and fixed: libc-shim/include/errno.h was missing `#include <features.h>`
(every other public header includes it first), so any standalone `<errno.h>`
use failed with "Slate requires one supported target ..." errors before
_SLATE_LIBC and friends were defined.

Found and fixed: tests/differential.rs unconditionally skipped Slate's
translate step for every `msvc/` fixture (`FixtureFlavor::Msvc => None` for
translation_target, plus an early return in run_cross_target_fixture), a
blanket workaround for slate-wlpp.7 (CIR MSABI rejects tag-decl definitions)
added when aggregate-bearing fixtures joined the directory. tests/fixtures/
msvc/llp64.c already carried LOWERING-MSVC/REWRITES-MSVC FileCheck blocks from
before that disable and they were simply dead code -- confirmed they still
match byte-for-byte once re-enabled.

Added `msvc_translation_ready(name)` allowlist in tests/differential.rs so
non-aggregate msvc fixtures (`llp64`, new `errno_stream_redirects`) go through
real Slate translate + FileCheck + `cargo check --target x86_64-pc-windows-msvc`
(skips gracefully when that target isn't installed, as here), while aggregate-
defining fixtures stay on the compile-only oracle path until slate-wlpp.7 is
fixed. New fixture tests/fixtures/msvc/errno_stream_redirects.c locks in the
_errno/__acrt_iob_func call shape end to end.

lowering, rewrites, and libc profiles all green.
