# Lift macros used inside expressions by stopping hoisting at the expansion

_2026-11-01 13:25:24_

slate-f2zu.9.5.12.9: new ValueKind::MacroExpansion { expansion, evaluation } wraps an expansion covering one expression read as a value in function code. macro_structure.rs excludes constant contexts (case, array size, sizeof, static initializers), asm operands and expansions that are only their own argument. The hoister keeps effects in evaluation.statements; effects() still reports them, so && and ?: still branch.
A hoisted expansion cannot be unhoisted, so Sema::with_macro_keep runs macro_keep on a normalized module, restores the unnormalized bodies, strips rejected expansions and normalizes again. Stripped expansions hoist exactly as before. macro_keep also rejects compound literals, temporary objects and void value expansions.
Value templates end in Stmt::Return while rules run; codegen prints the expression or a block. The template self-check covers them.
Two bugs found building zlib: a block-like argument at a statement start failed to parse ('$b as T'), so codegen parenthesizes holes left of casts and binary operators; unreachable_stdio_helpers ignored template bodies and dropped strerror's extern declaration.
zlib: 37 of 58 macros lifted (was 22), 41050 lines (was 40892), no template mismatches, projection 1024/0/0, signatures 676/0, default-target cargo build passes. Fixture: fixtures.merge/macro_values.c, same output as C.
Run: project_merge 5/5, four parser macro fixtures. Not run: validate_merge on zlib, slate and parser profiles.
