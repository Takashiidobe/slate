# Fix gcc.dg hangs: zero-length initializers and sequencing blowup (cxg.21)

_2026-09-28 13:26:47_

slate-parser-cxg.21: four gcc.dg files hung. Two independent causes.

1. Zero-length aggregates under brace elision (init-excess-1.c, init-bad-6.c,
   Wmissing-braces-fixits.c). `int a[][0] = {1, 2}`: both the sema length walk
   (`consumed`) and the lowering builder (`init_into`) descended into the
   int[0] subobject, consumed nothing, and never advanced. Now an unbraced
   item aimed at an already-full subaggregate is consumed and discarded as its
   whole initializer; the empty member is still recorded so `finish` sees the
   length. Verified against gcc typeof probes: a4[][0]={1,2} -> 2,
   struct{int x[0]; int y;}[]={1,2} -> 1, {1,2,[3]=4} -> 4.
   gcc is erratic when the *element* type is zero-size (int[][0][2] = {1}
   gives length 2, {1,2,3} gives 4); only visible via typeof, not matched.
   clang rejects these ("aggregate with no elements requires explicit
   braces"); slate accepts under both flavors (permissive).

2. Excess elements in a full braced list are now dropped instead of erroring
   (gcc and clang both warn and drop). This also fixes cxg.41
   (gcc.dg/20000926-1.c, excess into a zero-length member).

3. torture/pr58830.c: 40-deep j[j[...]] + arithmetic took 2^n in
   sema/sequencing.rs. `walk_path` for Deref walked the pointer value (which
   visits every subscript amount) and then `offset_root` walked the amounts
   again, so each level recursed twice. `offset_root` now only collects the
   amounts; Index walks them once, Deref relies on its own walk. Same touches
   recorded, now linear.

Fixtures migrated to suites/gcc-dg/gcc/linux/x86_64: init-excess-1.c,
init-bad-6.c, Wmissing-braces-fixits.c, torture__pr58830.c, 20000926-1.c.
