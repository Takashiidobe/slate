# Fix Ctz/Clz/Popcount width mismatch (slate-sto1)

_2026-08-27 08:25:25_

Bug: cir.ctz/cir.clz/cir.popcount lowered to bare `.trailing_zeros()`,
`.leading_zeros()`, `.count_ones()` method calls with no cast. Rust's
integer bit-counting methods always return u32 regardless of the receiver's
width, but `materialize_expr` declares the temp with the CIR result type
(e.g. u64 for size_t), producing `let _v: u64 = x.trailing_zeros();` -
a type mismatch that fails to compile whenever the result type isn't u32
(e.g. shifting a size_t by a \_\_builtin_ctzll result).

Fix: in `lower_unary_method` (src/frontend/lowerer/arithmetic.rs), wrap the
method call in `Expr::Cast` to the declared result type when method is
trailing_zeros/leading_zeros/count_ones. Confirmed these are the only three
methods reached through lower_unary_method whose Rust return type isn't
Self - every other method routed there (float ops, reverse_bits,
swap_bytes) already returns Self.

Added tests/fixtures/builtin_ctzll_shift.c to cover
`(size_t)1 << (size_t)__builtin_ctzll(x)`. Verified with
SLATE_DIFF_FIXTURE=builtin_ctzll_shift and full lowering profile.
