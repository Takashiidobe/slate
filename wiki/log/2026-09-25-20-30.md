# Attach pointer declarator qualifiers to the right level

_2026-09-25 20:30:48_

slate-parser-97e. `parse_declarator` collected the `*` levels and wrapped them
innermost-first, so the first star became the innermost `Declarator::Pointer`.
`TypeResolver::derive` applies the outermost `Pointer` first, which is the C11
6.7.6.1 reading: in `T D1` with D1 = `* quals D`, D is a quals-pointer to T.
The two disagreed whenever pointer levels had different qualifiers:
`int *const *q` resolved as `int **const q`. The fix is to wrap in reverse.

Observable before the fix, all opposite to clang 22 / gcc 16:
- `q = p` was rejected and `*q = 0` accepted for `int *const *q`;
- `_Generic(q, int *const *: ...)` never matched, in the checker or the lowerer;
- `char **__restrict p` parameters lost `restrict`, so glibc strtol/strtod,
  asprintf, getline/getdelim, strsep and argz_*/envz_* declared the wrong
  parameters restrict. Call sites also gained spurious `pointer_cast`s;
- `int ***volatile s` / `int *volatile *e` put volatile on the wrong level
  (gcc-torture pr58277-2, pr64756).

Found while writing fixtures for slate-parser-dyd.38, where
`const __auto_type a = arr;` failed a `_Generic(&a, int *const *)` assertion
that both compilers accept. New fixture sema/pointer_qualifier_levels.c
(declarations, cast type name, _Generic, restrict; INNER_CONST/OUTER_CONST
error configs) was checked against clang and gcc. Six existing fixtures changed,
all toward the compilers.
