# Slate frontend variadic long double trampolines by function pointer

_2026-09-30 22:29:27_

slate-p58o.4.7: the slate-p58o.4.3 trampoline exported Rust variadic callees with #[unsafe(no_mangle)] under their Rust name, so a static C function named like a libc/runtime symbol (or two same-named statics in different TUs) collided. A static variadic named exit made rustc reject the program: 'invalid definition of the runtime exit symbol used by the standard library'.

- The trampoline is now __slate_vcall__r<ret>_<fixed tags>__<variadic tags>(void *_f, ...) and calls ((ret (*)(fixed, ...))_f)(...). The Rust call passes 'callee as *const ()' first.
- No symbol export: removed Context::exports and the NoMangle pass. Trampolines are keyed only by signature, so identical ones across TUs dedupe in the harness name set.
- call_long_double_bridge now takes pre-lowered args.
- Updated wiki/concepts/long-double-f80.md.

Fixture: long_double_variadic_libc_name.c (static long double exit(int, ...)).
Validation: full slate profile green.
