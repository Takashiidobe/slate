# Model C23 nullptr_t as a distinct type

_2026-09-28 12:46:31_

slate-parser-cxg.6 cluster D (c23-nullptr-1.c, c23-nullptr-2.c) and slate-parser-cxg.36 (filed then implemented in the same session at the user's request).

The static-assertion type path (Types::assertion_operand_type) had no NullPtrLiteral arm, so sizeof(nullptr) and typedef typeof(nullptr) nullptr_t failed ('nonliteral', and 'unknown typedef' because the typedef never registered). IR lowering typed nullptr as void *, which made _Generic(nullptr, void *: 1, nullptr_t: 2) wrong; gcc and clang treat them as distinct.

Added CTypeKind::NullPtr. It reuses ir::Type::Pointer to void (clang lowers to ptr too), rendered 'nullptr_t', so Slate sees c_canon="nullptr_t" in metadata. Conversions per C23 6.3.2.4, verified against gcc and clang: to any pointer (pointer_cast from an object, keeping side effects; null from the nullptr literal), to bool (ne against null), from a null pointer constant; all else Invalid (both compilers reject (long)n, returning int * as nullptr_t, (nullptr_t)void_ptr, n + 1). Equality lowering chose the comparison type by IR pointer-ness, which picked nullptr_t over a real pointer; it now prefers the C pointer operand. warn_comparison skips nullptr_t. __builtin_classify_type(nullptr) is -1 in both compilers, so type_class returns i32.

Docs: ir-spec.md 'nullptr_t' section; type-family-touchpoints.md lists the silent sites. Fixtures: {clang,gcc}/linux/x86_64/ir_nullptr.c, error/clang/linux/x86_64/ir_nullptr_invalid.c, gcc-dg c23-nullptr-2.c.
