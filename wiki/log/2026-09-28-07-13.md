# Parser checkpoints use an undo log instead of snapshots

_2026-09-28 07:13:05_

slate-parser-7mgf. windows_h_msvc.c took ~23s to parse (clang: 0.17s total).

Cause: Parser::checkpoint cloned the whole scope stack (every file-scope
name) and the whole pending annotation map (every unconsumed comment and
pragma in the TU). It is taken for every attribute/__declspec
(parse_attribute), every speculative type name (try_parse_type_name),
#pragma pack arguments and statement attributes: 4702 checkpoints on
windows.h spent 14.5s cloning plus more freeing. O(checkpoints x TU).

Fix: src/parser/undo.rs UndoLog<T> records changes only while a checkpoint
is live; a checkpoint stores log lengths. NameEnvironment logs
Entered / Exited(scope) / Bound{name, previous}; ParserInput::take_matching
logs (position, original entries). Rollback replays the tail in reverse,
which reproduces the old snapshot exactly, including scopes pushed and
popped inside the checkpoint. Commit keeps entries until the outermost
checkpoint ends so an enclosing rollback can still undo them. Tags keep
truncate-by-length.

Result: windows_h fixture 23s -> 3.3s (remaining is the 3.1s preprocessor,
slate-parser-fmzz). Full nextest 62s -> 11.5s. Rollbacks with non-empty
logs occur in the suite (6 name, 1 annotation), all passing.

Benchmark recipe: bd memory perf-benchmark-windows-h.
