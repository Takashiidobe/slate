# Empty () call fills the sole fixed parameter of a variadic macro

_2026-10-09 18:37:34_

slate-parser-cxg.7.3. The bead blamed GNU named variadic parameters (y...), but those and GNU , ## y comma elision already worked. gcc.dg/cpp/vararg2.c actually failed on gnu_repeat(0, 'x'), which reduces to _gnu_tail() with #define _gnu_tail(x,y...) y; the C99 _c99_tail(x,...) form fails the same way.

pp/expand.rs turned an empty () into one empty argument only for non-variadic macros with one parameter. For f(x, ...), f() therefore had zero arguments, failed the arity check, and stayed unexpanded. gcc and clang both read it as x empty with the variadic part omitted. The fix drops the !variadic guard. A variadic macro with no fixed parameters still gets zero arguments, so __VA_ARGS__ is empty.

Migrated gcc.dg/cpp/vararg2.c to suites/gcc-dg/gcc/linux/x86_64/cpp__vararg2.c (-std=gnu99). The parser profile passes: 7966/7966.
