# Materialize record rvalues as temporary places

_2026-09-20 20:16:50_

`f().x` failed with `expression is not a supported place`: `member()` only
projected fields out of a place, and a call returning a struct is a value.
Three gcc-torture fixtures hit this (20041124-1, 950628-1, pr30185).

Added `PlaceKind::Temporary { object, initializer }`, printed
`temporary %N = <value>`. When the base of a non-arrow member access is not a
place but is a record, `member()` now materializes it into one of these and
projects normally. Mirrors `PlaceKind::CompoundLiteral` in `effects.rs`
(place, stable_place, place_effects) rather than being flattened to a
`Statement::Temporary`, so the two stay side by side.

It is deliberately *not* a compound literal: a compound literal is an object
with a storage duration, a materialized rvalue is not. `temporary_rooted()`
walks Field/ComplexPart/Lane/Swizzle bases (not Deref/Index, which go through
a read value, so `f().p[1] = 3` stays legal) and rejects assignment
(`expression is not assignable`), compound assignment, `&` and
`__builtin_addressof` (`address of a temporary`).

Corpus IR sweep: 2569/2688 -> 2574/2688 accepted. No fixture CHECK lines
changed — the filecheck harness only renders `parse`, not `ir`.
