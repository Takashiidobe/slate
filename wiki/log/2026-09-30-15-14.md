# Short-circuit logical values in slate frontend

_2026-09-30 15:14:03_

slate-p58o.3.7. slate-parser already desugars && / || with side-effecting operands into if/else writing a synthetic bool temporary, so C sequencing is preserved in the IR before Slate sees it. ValueKind::Logical survives only when both operands are effect-free, typed bool.

Logical<bool> now lowers to Rust && / || over lower_condition(operand). Rust's operators short-circuit like C's, which still matters for effect-free operands that can trap (b != 0 && a / b > 1 must not divide). Nested/mixed grouping prints with correct parens ((a || b) && c, a && (b || c), !(a && b)).

Added tests/fixtures/short_circuit.c (call counters through pointers, assignment in the RHS, if/while conditions, division guards, mixed grouping). logical_ops.c still blocks only on its initialized static global (slate-p58o.3.18). Promoted gcc-torture compare-3.c. lowering profile green (against slate-parser with the uncommitted dfrt fix).
