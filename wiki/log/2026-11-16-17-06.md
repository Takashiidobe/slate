# slate-f2zu.14.40.13 translate-project link order: one codegen unit per C unit via incremental + -Zcodegen-source-order, hoist_global_asm/hoist_section_statics deleted, kernel_link places per-unit objects

_2026-11-16 17:06:32_

- bead: slate-f2zu.14.40.13
- kind: feature
- area: crates/slate/src/main.rs
- area: crates/slate/src/frontend/lowerer.rs
- area: tools/corpus/kernel_link.py
- area: tools/corpus/e2e.py

Outcome: link-order-sensitive crates compile one codegen unit per C unit in unit
order (incremental + -Zcodegen-source-order), and the crate-root hoisting of
global_asm!/#[link_section] statics is deleted.

Gap and why it mattered: every link-order bug so far (.40.4 initcall order,
.40.6 section statics, .40.8 symbol names, .40.9/.40.11 .set aliases, .40.12 asm
local labels) came from rustc picking object boundaries while C assumes one TU =
one object in link order. `project/link_order.rs` (`hoist_global_asm`,
`hoist_section_statics`) moved asm and statics into the crate root, parsed asm
text to decide what was safe to move, and added pub type/const/use aliases.

Before: each kernel shard was one `ld -r` object with hoisted
`__slate_link_order_<k>` statics; e2e split shards into `_rN` runs when ordered
sections interleaved with other shards.

After:

- `main.rs` `link_order_sensitive`: freestanding, or 2+ units with global_asm,
  or a link_section shared by 2+ statics, or asm beside section statics. Only
  then does `crate_manifest` add `cargo-features = ["profile-rustflags"]`,
  `[profile.release] incremental = true`, and per-package
  (`[profile.{dev,release}.package.<pkg>]`, so deps and core are unchanged)
  `codegen-units = 4096` +
  `-Zcodegen-source-order -Zhuman-readable-cgu-names -Zcross-crate-inline-threshold=never`.
  Hosted projects that do not trigger it keep the old Cargo.toml.
- Under incremental rustc keeps one CGU per module named
  `slate_crate.<h>-__slate_unit_<stem>[-<sub>]`; CARGO_INCREMENTAL=0 overrides
  the profile and gives size-sorted `-cgu.NN` units (the test harness now
  removes the variable; the user's fish config no longer sets it).
- `link-order.json` (`{"version":1,"units":[{"file","module"}]}`, link order,
  module null for the root unit) is written for link-order crates.
- C `__attribute__((used))` lowers to `#[used(compiler)]` (clang:
  llvm.compiler.used) instead of plain `#[used]` (llvm.used, SHF_GNU_RETAIN).
  With the retain flag, `ld -r` kept Rust and C `.init.setup` as two output
  sections, so every translated `__setup` entry sorted ahead of native ones.
  `UsedKind::Plain` is removed. The batch fixture harness build.rs now links
  bins with `-Wl,-z,nostart-stop-gc` like project crates (.40.7) so
  `used(compiler)` linker sets survive gc.
- `Item::Const`/`Item::TypeAlias` lost their `vis` field (only hoisting set it).
- tools/corpus: e2e builds with `cargo rustc ... -- -C metadata=<shard>` (shards
  shared one crate disambiguator), `link_order_runs` deleted (84 shards instead
  of 133). `kernel_link.swap` reads link-order.json, `ld -r`s each unit's CGU
  objects into one object placed at that TU's vmlinux.a slot,
  crate-root/fallback/volatile objects plus unlinked units at the root unit's or
  first unit's slot, shared core/compiler_builtins/deps as one `runtime.o`
  pulled with `-u` (skipped when nothing is needed), keep-globals = native
  exports + symbols other objects in the shard need. It fails on numbered CGUs,
  unlisted modules, an object defining another module's items, ordered sections
  in the crate root, or a strong global defined by two slate objects (weak
  `__weak` defaults are allowed).

Validation: init, arch_x86_kernel, net_core retranslated with e2e and relinked:
145/145 units placed, 0 link errors, initcall and `.init.setup` tables (scratch
tables.py) identical to native, boots to /init, loopback ping OK. Full slate
profile passes; 7 FileCheck fixtures regenerated (`#[used]` ->
`#[used(compiler)]`). Without the flags, link_order_statics and link_order_asm
print scrambled order.

Fixture: crates/slate/tests/fixtures.release/link_order_asm_cgu (asm local label
read from another unit, section-attributed alias).

Limits: `-Zcross-crate-inline-threshold=never` is a backstop: under incremental
rustc does no cross-crate-inline inference at the default threshold, so no
fixture fails without it (link_order_asm_cgu does fail with `=always`). Hosted
cross-unit order under incremental is alphabetical by module, not link order
(accepted). Full linux retranslate still pending for acceptance. See:
slate-f2zu.14.40.14, wiki/concepts/slate-architecture.md
