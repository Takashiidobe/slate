# Resolve __builtin_choose_expr during lowering

_2026-09-20 09:13:36_

Three of the builtins the corpus sweep reported as unresolved ordinary names
turned out to be three different things. Checked them against clang 22 and
Builtins.td rather than assuming.

They are Clang *keywords* (TokenKinds.def 463-473), not Builtins.td records,
which is why the generated registry has no entry:
__builtin_choose_expr, __builtin_offsetof, __builtin_va_arg,
__builtin_FILE/FILE_NAME/FUNCTION/FUNCSIG/LINE/COLUMN. We already handle
offsetof, va_arg, bit_cast and types_compatible_p as parser-level special
forms.

Implemented __builtin_choose_expr the way __builtin_constant_p is done —
recognized by callee name in sema, not a new AST node, since it takes only
expressions and parses fine as a call. The condition must be an ICE; the
selected operand is lowered in its place and gives the result type; the
unselected one is not evaluated. Verified against both clang and gcc that
the unselected operand IS still name-resolved and type-checked (both
diagnose an undeclared function there), so name resolution keeps visiting
all three arguments and only the callee identifier is skipped.
Touchpoints: expression.rs (recognizer, lowering arm, specially_lowered),
types.rs (constant folding), assertion.rs (ICE shape).

Two findings that did NOT become code:
- __builtin_exit is a GCC-ism. clang 22 rejects it outright ("use of unknown
  builtin"). Builtins.td only emits a __builtin_-prefixed alias where
  AddBuiltinPrefixedAlias is set. Since the default personality is Clang,
  rejecting it is correct and matches the oracle; the gcc-torture fixture
  that uses it should move to the gcc flavor once the personality rule
  exists. Filed as its own bead.
- __builtin_FUNCTION needs the enclosing function name during lowering,
  which sema does not track (Lowerer has in_function: bool only), and
  __builtin_COLUMN needs column information, which ast::Provenance does not
  carry at all. Filed with __func__, which needs the same name plumbing.

Corpus IR sweep 2345/2674 -> 2347/2674, 0 regressions.
