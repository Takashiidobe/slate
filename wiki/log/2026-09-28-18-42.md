# Expression typer covers vectors, __func__, statement-expression locals and null pointer constants

_2026-09-28 18:42:15_

slate-parser-cc94.4.4. Measured with a temporary SLATE_TYPER_LOG append wherever typed() failed: ~557 lowered nodes and 37 speculative operands unanswered before, 0 lowered and 33 speculative after.

Vectors: v[i] (lane lvalue carrying the vector's qualifiers, or an rvalue element), swizzles (.xy/.lo/.s01; an lvalue only when every lane is distinct), __builtin_shufflevector, unary -/~ on vectors, and compound assignment/++ on vector targets. swizzle and shuffle moved from the Lowerer onto TypeResolver so both share them. GNU ~ on a complex operand (conjugate) is typed too.

__func__/__FUNCTION__/__PRETTY_FUNCTION__: the Lowerer's function_name/pretty_function_name became TypeResolver::function_names (FunctionNames { plain, pretty }) with predefined_name choosing per flavor. The static-assertion checker sets it per function body, so _Static_assert(sizeof(__func__) == 2) inside a function now works.

Statement-expression locals: the typer types the body's top-level declarations into TypeResolver::locals before typing the result; object() consults entities, then locals. The checker's __auto_type/resolve_declarator dance and completed_array moved onto TypeResolver (declarator_type, completed_array) and the checker calls them.

Null pointer constants: one AST predicate, TypeResolver::integer_constant_zero (C 6.6p6 operand rules + value folds to 0), replaces the typer's literal-only integer_zero and lowering's evaluate_ast check. Explicit casts now pass their operand expression. This fixed too-strict rejections: *(1 ? p : (void *)(1 - 1)), (void *)(E0 + 0), (void *)(unsigned long)0, (void *)(int)0.0 were void * and failed with 'conversion from void'; clang and gcc accept all of them. (size_t)(void *)0 is no longer treated as null (it isn't an ICE) and now warns int-conversion as gcc's c90-const-expr-10 expects; (int) 0.0 lowers to null in c9x-const-expr-3.

Left: variably modified types in typeof/sizeof operands need an extent binding only lowering creates (slate-parser-cc94.4.5, blocks cc94.4.3).
