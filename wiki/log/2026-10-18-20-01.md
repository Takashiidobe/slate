# slate-o3gw.16: path-bind address-taken exports with C ABI kept

_2026-10-18 20:01:24_

Executable projects now bind non-liftable exports by Rust path too (backend/link/calls.rs, interproc::export_candidates).
- export_candidates splits unique exported defs into liftable (as before) and c_abi: address-taken, unsafe, or carrying a link_section (slate_distinct ICF guard). Both need is_path_bindable: C-unwind ABI, not main, not libc-named, attrs within NoMangle/Inline/Cold/MustUse/Deprecated/Allow/LinkSection.
- rust_bound runs on both sets with the same decl_identical check; bind_calls imports both but strips no_mangle and the ABI only from rust_bound defs. c_bound defs keep their C symbol and params, so stored addresses and function identity are unchanged.
- Re-scoped from retyping fn-pointer fields: loadext.c passes &sqlite3Apis to dlsym'd xInit, so sqlite3_api_routines must keep C-ABI fields.
Fixture: tests/fixtures.release/cross_unit_address_taken_exports (shared fn-pointer table; direct, table and local-pointer calls; identity compares).
sqlite amalgamation (shell + core): path-bound API imports in main.rs 3 -> 150; the 10 remaining extern sqlite3_* decls are variadic or va_list. slate profile 20/20.
