5 real failures triaged into slate-parser-wf8.5.{1..4} (990326-1.c and alloca-1.c share one root cause):

- wf8.5.1: **attribute**((aligned)) with no arguments (means 'max useful alignment') is rejected by sema as invalid -- the aligned attribute-argument parser in parser.rs only accepts an explicit int/expression argument.
- wf8.5.2: a leading **extension** prefix isn't stripped before parse_top_level_item's tag-keyword-index scan, so '**extension** union { ... } u = {...};' falls through to the wrong parse path. **extension** is already stripped at 3 other call sites in parser.rs, just not this one.
- wf8.5.3: const_expr.rs's compound-literal initializer-list parser only supports .field=/[index]= designators, missing the GNU old-style 'field: value' spelling that parser.rs's top-level initializer parser already supports -- two separate initializer-list parsers, one is behind the other.
- wf8.5.4: lexer.rs recognizes **const/**const** and **restrict/**restrict** GNU aliases but not **volatile/**volatile** (same class of bug as wf8.4.5's **const fix).
