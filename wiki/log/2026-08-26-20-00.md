# Fix \_\_builtin_frame_address bogus-constant bug (slate-vwe9)

_2026-08-26 20:00:59_

cir.frame_address was routed through lower_opaque_pointer, which fabricates a fake non-null pointer (1usize as \*mut u8) instead of reading anything real. return_address/block_address/stacksave stay on that path deliberately (no faithful Rust equivalent), but frame_address does have one: the address of any local variable in the current stack frame is a real, valid pointer into that frame.

Fix: lower_frame_address (src/frontend/lowerer/intrinsics.rs) declares a throwaway u8 local and returns std::ptr::addr_of_mut!(local) as <result_ty> instead of the fake constant. Ignores level (as the old code did) -- chasing saved frame pointers for level > 0 would need real register reads, out of scope here.

Repro fixture: tests/fixtures/gnu_frame_address.c (checks the address is a plausible large stack address, not a tiny literal -- failed before the fix, C=0 vs Rust=1). This also flipped tests/fixtures.gcc-torture.unsupported/frame-address.c to passing (a stronger check: frame ordering across nested calls), so it was promoted to tests/fixtures.gcc-torture/. Updated docs/src/features.md to check \_\_builtin_frame_address off.
