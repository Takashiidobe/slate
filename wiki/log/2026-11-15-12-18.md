# slate-f2zu.14.34.18 attributes_with: section/used after '*' (char * __init unpack_to_rootfs) dropped, so exported __init fns lost link_section

_2026-11-15 12:18:20_

- bead: slate-f2zu.14.34.18
- kind: parser
- area: crates/slate-parser/src/ast.rs
- target: linux

Outcome: symbol attributes written after a `*` in a declarator (`char * __attribute__((section(".init.text"))) f(...)`, i.e. kernel `char * __init unpack_to_rootfs(...)`) now apply to the declaration. So such a function or variable keeps its `section`/`used`/`visibility`/`alias`/... and gets `#[link_section]`.

Diagnostic or IR fact that was wrong: `DeclarationSpecifiers::attributes_with` collected attributes from the specifiers, the trailing list and the `Declarator::Attributed` layers, but not from `Declarator::Pointer` layers. GNU `__init`/`__initdata` expand to `__section(...)`, and with a pointer return type they land between `*` and the name. Clang and GCC move a declaration attribute found on a pointer chunk to the declaration. slate dropped it, so the exported function was emitted in `.text`, and modpost warned about section mismatches 156 times (unpack_to_rootfs, alloc_large_system_hash). The bead's two-line repros put `__section` before the return type, which is why they kept the section.

```c
int * __attribute__((section(".s2"))) g(void) { return 0; }
```

Before:
```
fn %1 @g() -> ptr<i32> [linkage=external] [fallthrough=ub_if_used] {
```
After:
```
fn %1 @g() -> ptr<i32> [linkage=external] [section=".s2"] [fallthrough=ub_if_used] {
```

Fix (crates/slate-parser/src/ast.rs):
- `Declarator::pointer_attributes` collects the attributes of every `Pointer` layer.
- `attributes_with` adds those that pass the new `Attribute::is_symbol_attribute`. That method lists the same attributes as `general_use`'s `Use::Symbol` arm in sema/attributes.rs, which stays an exhaustive match.
- Type-level pointer attributes (address_space, aligned, noderef, ...) are not moved.
- All 19 `attributes_with` users (function definitions, declarations, globals, reachability, assertion rules) see the attributes.

Checked: `translate-project` of init/initramfs.c with its kernel compile command now emits `#[unsafe(link_section = ".init.text")]` on `unpack_to_rootfs`.

Fixture: crates/slate-parser/tests/fixtures/clang/linux/x86_64/ir_pointer_declarator_section.c. It covers a section plus cold after `*` with a prior plain declaration, section plus used, visibility after `**`, and a `char *` global with `.init.data`.

Also regenerated: suites/gcc-dg/gcc/linux/x86_64/attr-weakref-1.c, where `static vtype* USED fv7(void)` and similar functions now carry `[used]` as gcc intends.

Limits: function attributes such as `cold` after `*` are still dropped. Only symbol attributes move.

See: slate-f2zu.14.34.6.
