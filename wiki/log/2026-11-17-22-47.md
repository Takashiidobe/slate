# slate-parser-dyd.71 Hoister::sequenced: later operand's hoisted effect moved ahead of an earlier sibling call (plain(p) + (g = 1))

_2026-11-17 22:47:02_

- bead: slate-parser-dyd.71
- kind: parser
- area: crates/slate-parser/src/sema/effects.rs

Outcome: side-effect hoisting no longer moves a later operand's effect ahead of an earlier sibling call; `plain(p) + (g = 1)` calls `plain` before writing `g`, matching clang and gcc.

## IR fact that was wrong

C11 6.5.2.2p10 leaves the call and the sibling store indeterminately sequenced, but slate documents left-to-right (clang) order. Hoisting kept calls as values and pushed the later operand's write into the shared statement list, so the write ran first and a callee reading `g` saw the new value.

## Before

    int plain(int *); int g; int f(int *p) { return plain(p) + (g = 1); }

    write<i32>(%g, const<i32>(1));
    return add<i32>(call<i32>(%plain, read(%p)), const<i32>(1));

## After

    let %5: i32 [synthetic] = call<i32>(%plain, read(%p));
    write<i32>(%g, const<i32>(1));
    return add<i32>(read<i32>(%5), const<i32>(1));

## Fix

`Hoister::sequenced` / `sequenced_pair` (crates/slate-parser/src/sema/effects.rs) lower each operand into its own buffer. If an operand hoisted statements, every earlier sibling that still has effects is spilled to a temporary before those statements are appended. Used by `Arith`, `Compare`, call arguments (indirect callee first), `PointerOffset`, `PointerDifference`, `Aggregate` and `Intrinsic`. Operands with nothing hoisted keep their calls inline (`plain(p) + plain(p)` is unchanged).

## Fixtures

- crates/slate-parser/tests/fixtures/clang/linux/x86_64/ir_effects_call_before_hoisted.c (sum, compare with `g++`, arguments, indirect callee, pointer offset, no-spill case)
- crates/slate/tests/fixtures/call_before_hoisted_effect.c: the callee records `g`. The output matches clang (`10 21 35 47 58`); slate's old order mismatched. gcc evaluates call arguments right to left (`pair` gives 707 instead of 507), so the fixture is clang-oracle only.
- Regenerated: suites/gcc-torture/{clang,gcc}/linux/x86_64/pr17377.c (`(char *)f(i) + x++` now calls f first) and crates/slate/tests/fixtures/va_arg_function_pointer.c (`first(x)` is spilled before the `?:` if).

Limits: assignment (`*f() = (g = 1)`), `Overflow`, `Lane` and `Shuffle` still lower their operands into one shared buffer.
