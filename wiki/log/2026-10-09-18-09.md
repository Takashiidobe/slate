# alloca follow-ups: __builtin_alloca_with_align, chibicc alloca ignored

_2026-10-09 18:09:31_

__builtin_alloca_with_align and __builtin_alloca_with_align_uninitialized now
lower like alloca. The second argument is the alignment in bits; slate passes
bits / 8 to __slate_alloca::alloca(size, align), and plain alloca passes 16.

Runtime change (src/frontend/support/alloca.rs): allocate() aligns the actual
address (base + offset) instead of the offset, since blocks are only 16-aligned.
A new or reused block must hold size + align bytes, so an over-aligned request
always fits in a fresh block. Alignments below 16 are raised to 16.

Fixture: tests/fixtures/builtin_alloca_with_align.c (8/64/4096-byte alignment
mixed with plain alloca, uninitialized variant, 1.1 MB over-aligned requests
that force a new block each round).

chibicc alloca.c moved from unsupported/ to ignored/: it asserts that successive
allocas sit exactly 16 bytes apart on a downward stack, which is chibicc
layout behavior gcc/clang do not guarantee and slate will not emulate.
