# Lower numeric bitwise and shift operators to IR

_2026-09-14 20:16:44_

sema::numeric now lowers `&`, `|`, `^`, `<<`, `>>`; assignment operators are deferred.

- ArithOp gains and/or/xor/shl/shr. ArithSema gains `Bitwise` (no metadata, e.g. `and<i32>(..)`) and `ShiftRight { fill: ShiftFill }` printing `fill=sign_extend` (signed) or `fill=zero_extend` (unsigned).
- Clang 22 emits plain and/or/xor/shl/ashr/lshr under both -fwrapv and -ftrapv, so signed `shl` is always `overflow=undefined`, unsigned `shl` wraps.
- Shift operands are not converted to a common type: node type is the left operand's, the amount keeps its own (`shl<i32>(const<i32>(1), const<u32>(2))`). Promotions not needed yet since all literals have at least int rank.
- Bitwise/shift on floating operands -> `InvalidOperands`; mixed-type bitwise -> `Conversion`.
- Assignment and compound assignment return `unsupported: assignment (requires place lowering)`. Decided with the user: numeric sema has no identifiers/places yet and `1 += 2` is not valid C, so defer until place lowering (lh7.2.6/lh7.2.7).
- Restored the div/rem/shl why-comment: a PostToolUse hook strips comments from Edit/Write, so it was lost in the previous commit; comments must be inserted via shell.
- Fixtures: bit/shift cases in sema/numeric_seed.c; flags_wrap.c and flags_trap.c show shl/and ignoring the flags; unsupported.c adds FLOAT_BITAND, FLOAT_SHIFT, MIXED_BITAND, and COMPOUND_ASSIGN (file-scope `void assign(int x)` since local declarations are rejected by the expression dump).
- wiki: ir-spec.md numeric seed and shr spelling, compiler-flags.md updated.
