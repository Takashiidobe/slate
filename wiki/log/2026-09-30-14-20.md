# Per-function slate lowering barriers

_2026-09-30 14:20:37_

slate-p58o.7.4. Removed the whole-module gate in src/slate_parser_frontend/lowerer.rs that rejected any nonempty Module.types. Sema already canonicalizes typedefs, so aliases need no lowering; a record/enum now only fails the function whose type/value mentions it (type @typeN / aggregate<@typeN>). Top-level asm stays a module-level barrier.

lower() is split into lower_module(module, Option<&mut Report>) with lower_extern/lower_function/lower_string_global helpers. Strict mode (report=None) returns the first error exactly as before. lowerer::report() continues past failures: Report.module holds top-level barriers (unsupported globals, module asm), Report.functions lists each defined function with None (ok) or its first barrier; failing extern declarations are also recorded. Report mode returns no Program, so it can never produce output that passes.

New CLI: slate lowering-barriers [compiler args] <file.c> prints '<fn>\t<ok|error>' and '<module>\t<error>' lines, exit 1 if any barrier.

Dropping the gate promoted 7 tests/fixtures cases (enums, sizeof, long_double_layout, printf_pointer, printf_pointer_rejected, pragma_pack_named_and_aligned, ctype_classify_param_unsupported); no corpus suite case changed state. All ratchet tests green on the lowering profile.
