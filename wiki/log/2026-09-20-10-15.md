# Lower GNU inline asm statements into IR

_2026-09-20 10:15:02_

slate-parser-dyd.2. Parsing was already structured (slate-parser-25m,
8/9 done); the gap was purely IR lowering, where `StmtKind::Asm` hit the
catch-all `ResolveError::Unsupported("module statement")`.

- `src/ir/asm.rs`: IR-owned asm types (`InlineAsm`, `AsmPiece`,
  `AsmOutput`/`AsmInput`, constraints, clobbers, `AsmRegister`). IR does
  not reuse AST data types anywhere, so these mirror the AST rather than
  importing it. Registers keep spelling + canonical name and drop width:
  a clobber clobbers the whole register, and an operand's width is its
  IR type.
- `Statement::Asm(Box<InlineAsm>)`; lowered in the new `src/sema/asm.rs`.
  Outputs become `Place`s (sema already rejects non-lvalue outputs),
  inputs become `Value`s, goto labels resolve to label `BindingId`s the
  same way `StmtKind::Goto` does.
- Hoisting case in `effects_statements.rs`, so `asm("":"=r"(p[n++]))`
  hoists its side effects ahead of the statement.
- Printer: `asm [volatile] [inline] [goto] "<raw template>"` plus a brace
  block with `template:` / `out N` / `in N` / `clobbers:` / `labels:`.
  Basic asm (no operands) prints as a one-line statement. Constraints are
  printed as a reconstructed GNU spelling, so the text round-trips the
  parse instead of echoing the source.
- Note: `%lN` in printed `template:` indexes the `labels:` list, not the
  source operand number, so `%l1` and `%l[done]` both print `%l0`.

Fixture `sema/ir_asm.c`. Sweep: the 22 remaining "module statement"
failures are nested functions / attributed statements / local labels
(slate-parser-dyd.26); memory-constrained operands still lower as loaded
values (slate-parser-25m.10).
