# Generalize libc_probe::resolve for FreeBSD/Bionic/Darwin/MSVC (sfzn.17.1)

_2026-09-08 13:59:47_

tests/support/libc_probe.rs::resolve() previously unreachable!()-panicked for
LibcVariant::Bionic/Darwin/FreeBsd/Msvc. Added real branches:

- FreeBSD/Bionic: ELF targets, structurally mirror the glibc x86_64 branch
  (clang self-links via --target/--sysroot). Sysroot comes from
  tools/bootstrap-freebsd-oracle.sh output (SLATE_FREEBSD_AMD64_SYSROOT/
  SLATE_FREEBSD_ARM64_SYSROOT, documented by that script) or
  tools/bootstrap-android-ndk.sh output (SLATE_ANDROID_NDK). Runner reuses
  the existing qemu_for(arch) path, same as musl/glibc arm/aarch64.
- Darwin: SDK via SLATE_MACOS_SDK or `xcrun --sdk macosx --show-sdk-path`,
  matching tools/bootstrap-macos-oracle.sh's discover_sdk(). aarch64-only
  (TestConfig already hardcodes arm64 defines/target for Darwin). runner is
  forced None (no Linux-qemu story for Mach-O).
- MSVC: crt/include + sdk/include/ucrt from tools/bootstrap-msvc-sysroot.sh
  output (SLATE_MSVC_SYSROOT), passed as -isystem flags since MSVC has no
  unified --sysroot layout. x86_64-only. runner is None because that
  sysroot is header-only (no .lib files) until slate-sfzn.17.5 adds a real
  oracle; linking will fail loudly there rather than silently skip records.

Verified against this host's already-bootstrapped oracles (target/freebsd-oracle,
target/android-ndk-oracle): resolve() finds the right toolchain/sysroot/target
and clang gets to compiling the (still Linux/glibc-shaped) probe source, failing
only on missing platform headers -- confirms resolve() itself is correct; wiring
a real per-platform probe source is sfzn.17.2/17.4's job. Darwin/MSVC skip
cleanly (no SDK / no libs yet) instead of panicking. musl/x86_64 existing path
reverified unchanged via libc_abi_matrix_suite.
