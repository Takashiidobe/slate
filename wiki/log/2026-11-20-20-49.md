# slate-8ge7.11 IR pointers: exported functions of an executable project lift across units (&mut T, &[T], dropped lengths) through resolved declarations

_2026-11-20 20:49:23_

- bead: slate-8ge7.11
- kind: feature
- area: crates/slate-analysis
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/src/backend/interproc
- area: crates/slate/src/project/merge.rs

Outcome: under SLATE_IR_POINTERS, an executable project's exported functions lift like static ones: `counter_add(c: &mut counter)` and `table_sum(values: &[i32])` with the length dropped, called from other units through `use crate::__slate_unit_x::f`.

Gap and why it mattered: the analysis Program already held every unit, but exported functions were never candidates and step 3 marked every cross-unit call site unproven, so fixtures.release/cross_unit_pointer_lift and cross_unit_shared_types stayed raw with the gate on (gate off, the Rust-side pointer_lattice lifted them).

Before (gate on):

```rust
pub fn counter_add(__v0: *mut counter, by: i32)
fn add_twice(c: *mut counter, by: i32) { unsafe { counter_add(c, by) }; }
shape_area_sum(shapes.0.as_slice(), 3i32)
```

After:

```rust
pub fn counter_add(c: &mut counter, by: i32)
fn add_twice(c: &mut counter, by: i32) { unsafe { counter_add(c, by) }; }
pub fn table_sum(values: &[i32]) -> i32 { let count: i32 = values.len() as i32; ... }
unsafe { table_sum(core::slice::from_raw_parts(heap as *const i32, count as usize)) }
shape_area_sum(shapes.0.as_slice())
```

Implementation:
- `Program::new(units, exported, closed)`: `merge::translate_units` passes `liftable_root.is_some()`. In a closed program an export is fixed only when pinned (`pinned_symbols`, `fixed_abi`): defined twice, target of alias/weakref/ifunc/fallback, named in global asm, declared in another unit with a different C name, arity, variadic or pointer-ness, or carrying section/used/retain/dll storage/selectany/constructor/destructor/naked/interrupt/weak_odr/discardable/target features/SME/non-C calling convention. Libraries (no liftable_root) keep every export fixed.
- pointer.rs: cross-unit call sites no longer seed UNPROVEN, and length-pair proofs accept sites in other units. `Program::same_type` compares array and allocation element types across units (named records with equal kind, size and align).
- After the join, each declaration resolved to a candidate gets the definition's parameter `PointerFact`s, keyed by its own parameter bindings.
- Lowering: `borrowed_parameters` includes declarations, so `lower_extern` lowers borrowed params with `borrow_type` and drops length params, and call sites reuse the same-unit path. `link::rust_bound` then sees identical decl and def types and binds the calls by path.
- interproc::run (gate on) panics if an extern declaration still has a slice parameter after `bind_calls`: `&[T]` has no C ABI, so the analysis decision must be honored by link.
- calls.rs: with a `&mut` sibling argument, a plain variable argument is hoisted into a `__tN` temporary only when a borrowed argument reads that variable (`by` no longer is).
- Release fixtures honor `// SLATE-ENV:` (translate_fixture_project).

Fixture: crates/slate/tests/fixtures.release/cross_unit_slice_lift (gated: `&[T]`/`&mut [T]` across units from a local array, an aligned array, a malloc buffer and a block-scope `extern` declaration).

Validation: gate on, every release fixture builds and matches C; constant_p_after_inlining, cross_unit_pointer_lift and cross_unit_shared_types differ from their gate-off FileChecks only by more lifting (`slot: &mut i32`, `counter_get(&local)`, `let tag` without mut). Gate off, release passes.

Limits: `same_prototype` checks pointer-ness, not full types, so a type mismatch link rejects would leave a thin reference in an extern block (ABI-identical to a raw pointer) or trip the slice panic.
See: slate-8ge7.10 (length pairs), wiki/concepts/slate-analysis.md (Pointer capabilities).
