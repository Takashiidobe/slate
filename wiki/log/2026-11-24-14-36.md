# slate-yar4.74 c_type_for_tag: preserve 128-bit scalar arguments in x87 bridges

_2026-11-24 14:36:54_

- bead: slate-yar4.74
- kind: bug
- area: crates/slate/src/frontend/c_shim.rs
- area: crates/slate/tests/fixtures.dylink/long_double_mixed_128
- target: x86_64

Outcome: Shared-library calls and callbacks preserve 128-bit scalar arguments
when the signature also passes x87 long double.

## Symptom

A native shared library exported functions of the form
long double add(__float128 a, long double b) and
long double add(__int128 a, long double b). The host called them via dlsym.
The library also called host callbacks with __float128 and unsigned __int128.

Clang printed 1 for all four comparisons. Slate printed 0 for all four.
After the fix, Slate matched the native output, including the integer
witnesses with significant bits above bit 64.

## Cause

c_type_for_tag rendered lq as long double and let i128 and u128 fall through
to void *. Those C types changed argument size and register assignment in
both the indirect trampoline and the exported callback wrapper.

## Fix

Render lq as __float128, i128 as __int128, and u128 as unsigned __int128.
The Rust-facing and native-facing sides use the same 128-bit scalar types.
