# slate-o3gw.15: shared types and Rust-path calls in executable projects

_2026-10-18 19:50:28_

Executable projects (one unit defines main) now link units in Rust (crates/slate/src/backend/link/).
- types.rs: before the interproc solve, partition refinement groups each unit's records/structs by shape and the groups of referenced types. __SlateRecordN names match by shape only; bit-unit wrappers count as shape; an opaque struct T {} (new RecordDef.opaque) joins the unique complete group named T. Types named in impl headers (incl. LongDouble), LongDouble and VaList fields stay local. Groups spanning >1 unit, plus the closure of their representatives' references, move to src/__slate_types.rs; units import them with use crate::__slate_types::S as local, so bodies are untouched.
- calls.rs: a liftable export whose every cross-unit decl is top-level, attribute-free and type-identical under those groups is bound by path: no_mangle and extern C-unwind are dropped, decls become use crate::__slate_unit_<stem>::f.
- string_params, length_lattice (signature facts and return buffers) accept bound exports as candidates.
- Item::Use gains vis and alias. chibicc harness copies __slate_types.rs.
- tools/benchmark/sqlite.py builds libsqlite3.so from a separate --crate-type cdylib translation (rust-library/), since app-mode sqlite3.rs drops C symbols.
Fixture: tests/fixtures.release/cross_unit_shared_types (bitfields, anon records, opaque merge with unit-local field type, path calls).
sqlite: 141 shared types, but only 3 API calls bound: 156/157 are address-taken via sqlite3Apis (follow-up slate-o3gw.16). Runtime diff passes; Rust/Clang 1.05/1.02/1.03.
Follow-ups: .16 address-taken lifting with fn-pointer fields, .17 slice lifts regressed in single-file mode since bae7a8b13, .18 unsafe/unused-import noise.
