Outcome: default MSVC accepts casts used as lvalues and /Za rejects them.

Gap: Slate rejected `void f(void *p) { ((int *)p)++; }` in both modes. cl.exe accepts it with C4213 at /W4 and rejects it with C2105 under /Za.

Before: both modes reported “expression is not assignable”.

After: default MSVC updates the pointer in its original slot. /Za rejects that update, assignment to a cast and taking a cast's address. /W4 diagnoses accepted cast stores and updates in default mode.

Implementation: the checker records an lvalue when the original expression is a scalar place other than a bit-field and the cast's storage width fits. Lowering uses the original address and a pointer cast to project the replacement type. Ordinary casts still evaluate as conversions. cl.exe assembly for `((unsigned char)*p)++` uses a byte load and store, which confirms the width rule. The diagnostic level uses the last /W option even when /Wall sticks in the predefine.

Fixtures: `error/msvc/windows/x86_64/za_cast_lvalue.c` and `msvc/windows/x86_64/cast_lvalue.c`.
