# CHECK-LABEL group absorbs rest of file when no closer follows

_2026-09-05 15:09:26_

check_groups() in tests/support/filecheck.rs only closed a CHECK-LABEL
group on the next CHECK-LABEL directive or EOF. A hand-written label block's
own closer line (// LOWERING: {{^}}}, normalizing to // CHECK: {{^}}}) was
pushed into the still-open group but didn't end it, so every subsequent
matching line to EOF got absorbed into that one group. expand_label_group
then failed because the group's last element wasn't the literal closer.

Fix: when pushing a check into the current label group, if it equals the
closer sentinel // CHECK: {{^}}}, close the group immediately instead of
waiting for the next CHECK-LABEL or EOF.

Verified: over_aligned_local, pointer_compare_address, volatile now pass
under --profile lowering differential. Full lowering profile run shows only
the two unrelated pre-existing failures (vec_masked_load_ops / slate-kgdw,
target_stack_builtin_ops / slate-ks17).

Fixes slate-6hrs.
