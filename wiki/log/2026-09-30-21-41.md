# slate-p58o.3.2: integer overflow contracts

_2026-09-30 21:41:24_

Closed slate-p58o.3.2 (Lower integer overflow contracts for arithmetic).

Change (lowerer.rs):
- Arith add/sub/mul with ArithSema::Integer { overflow: Wrap } (unsigned
  arithmetic) -> lhs.wrapping_{op}(rhs). Plain operators failed rustc's
  arithmetic_overflow lint when the operands were known constants (sub.c,
  mul.c) and panic in debug builds. overflow=ub keeps the plain operator;
  negation already handled wrap/ub; trap stays unsupported.
- ValueKind::Overflow (__builtin_{add,sub,mul}_overflow) -> a block that
  binds both operands as i128 once, stores exact.wrapping_op as the result
  type through the result place, and yields checked_op(..).is_none() ||
  truncated as i128 != exact. That matches GCC's 'infinitely precise result
  fits the result type' rule for mixed operand/result types up to 64 bits.
  Wider operands are refused.

Fixtures: integer_overflow_contracts.c (new; failed on overflow_add)
covers unsigned compound wrap, ++ past UINT_MAX, unsigned negation, u64
hash mixing, and overflow builtins with int->long, unsigned->int,
int->unsigned, u32*u32->long long, LLONG_MIN*-1, and ULLONG_MAX+2->unsigned.
Promoted: sub, mul, overflow_scalar_ops; c-testsuite case_00217;
gcc-torture pr56250.

Uninitialized locals whose address is taken still fail with E0381; that
belongs to 3.9.
