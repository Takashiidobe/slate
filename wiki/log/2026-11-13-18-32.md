# slate-dghn.59 lowering: static initializer storing a function or data address in size_t/uintptr_t failed rustc const eval (OpenBLAS gemm_small_kernel)

_2026-11-13 18:32:36_

- bead: slate-dghn.59
- kind: feature
- area: crates/slate/src/frontend/lowerer/globals.rs
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/src/frontend/lowerer/places.rs
- corpus: openblas

Outcome: a static whose initializer stores a constant address in a pointer-width integer (`static size_t k[] = {(size_t)fn}`, `(uintptr_t)&x + 4`, the same in struct fields) compiles and keeps the relocation, so OpenBLAS's cblas_dgemm translation checks, builds, links and passes the dgemm smoke test.

Gap: rustc const eval cannot turn a pointer into an integer (E0080 "unable to turn pointer into integer", or "pointers cannot be cast to integers during const eval"). Lowering emitted `transmute::<Option<fn>, usize>(..)` in the static's initializer, which C compilers resolve with a linker relocation. OpenBLAS interface/gemm.c `gemm_small_kernel[]`/`gemm_small_kernel_b0[]` hit it.

Before:
```rust
static mut gemm_small_kernel: __SlateAlign16<[u64; 8]> = __SlateAlign16([
    (unsafe { std::mem::transmute::<Option<unsafe extern "C-unwind" fn(..) -> i32>, usize>(..) }) as u64, ..
```

After:
```rust
type __SlateImage_kernels = __SlateAlign16<[u64; 3]>;
static mut kernels: std::mem::MaybeUninit<__SlateImage_kernels> = unsafe {
    let mut __t0: std::mem::MaybeUninit<__SlateImage_kernels> = std::mem::MaybeUninit::zeroed();
    let __t1 = __t0.as_mut_ptr();
    (std::ptr::addr_of_mut!((*__t1).0[0]) as *mut *const ()).write(transmute::<Option<fn..>, *const ()>(Some(add)));
    ..
    __t0
};
... (*(std::ptr::addr_of_mut!(kernels) as *mut __SlateImage_kernels)).0[i as usize]
```

Implementation:
- Tables::is_address_integer (frontend/lowerer/globals.rs): a pointer-width integer that is ptr_to_int of a constant address (not the null-offset offsetof idiom), a same-width integer conversion of one, or one plus/minus a folded integer. holds_address_integer walks aggregates. Tables.address_images holds the statics whose constant initializer contains one.
- lower_static emits `type __SlateImage_<name> = <storage>` (including __SlateAlignN or __SlateStorage) and a MaybeUninit static built by address_image: zeroed, then fill_aggregate in place over `(*ptr)`; address leaves become address_integer_write (`(&raw mut place as *mut *const ()).write(ptr)`, offsets via wrapping_byte_offset). Const eval accepts pointer bytes in MaybeUninit storage.
- lower_binding views the static as `*(&raw mut name as *mut __SlateImage_<name>)`; the over-aligned `.0` and flexible casts apply on top.
- fold_integer folds a reinterpret between same-width integers (`(intptr_t)sizeof(int)`). Side effect: divisors such as `(uintptr_t)16` now fold, so may_trip_known_panics no longer adds the crate `allow(arithmetic_overflow, unconditional_panic)`; 10 FileCheck blocks lost that line (align_builtins, alloca_layout*, object_alignment, packed_sds_headers, ...).

Fixture: crates/slate/tests/fixtures/static_address_integer_initializers.c (array, exported array, over-aligned, scalar, data address, +/- offset, const, struct array with designators, nested struct). A two-unit translate-project probe with `extern size_t kernels[]` in the other unit links and runs.

Limits: an address truncated to a narrower integer, other arithmetic on the address (mask, multiply), and leaves inside bit-fields, range designators or erased fields still fail (the latter three as barriers). Selectany statics are not covered.
