# Model SVE sizeless types in the parser (gcc aarch64)

_2026-11-01 21:08:43_

slate-78pa.1.3: new CTypeKind::Sizeless(&'static str) and ir::Type::Sizeless(String) (layout.rs, render.rs, abi.rs passes them as scalars, numeric.rs, target_info.rs). BuiltinType::Sizeless lets generated prototypes name them. The gcc plugin (tools/gcc_plugin/dump_builtins.cc) now flags non-constant vector types and records with a non-constant size as sizeless and emits type rows for them; dump_gcc_builtins.py also compiles arm_sve.h (-march=armv9-a+sve2); generate_gcc_arm_builtins.py puts the 15 __SV*_t vectors, their lowercase svint32_t-style aliases (canonical name = alias) and the 41 sv*xN_t tuples into GCC_AARCH64_TYPES. They are accepted as builtin type names via is_target_builtin_name and resolved by gcc_target_type (gcc flavor, aarch64 only). Rejected with 'sizeless type does not have a fixed size': sizeof, struct fields, pointer arithmetic (qualified_storage); arrays get 'array elements cannot have a sizeless type' (types.rs array declarator). Parameters, returns, locals and copies lower fine. Limits: the sv type names are builtin even without arm_sve.h, so a user typedef of svint32_t on gcc aarch64 would clash; sv* functions and the svpattern/svprfop enums are still missing (slate-78pa.1.4); the backend has no Rust lowering for Type::Sizeless. Fixtures: gcc/linux/aarch64/sizeless_types.c, error/gcc/linux/aarch64/sizeless-{sizeof,field,array,pointer-arithmetic}.c.
