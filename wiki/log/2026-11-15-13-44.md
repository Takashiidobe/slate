# slate-f2zu.14.34.19 weak after '*': kernel __weak defaults (arch_adjust_kprobe_addr, pcibios_setup) multiply defined in vmlinux link, fixed by .18

_2026-11-15 13:44:10_

- bead: slate-f2zu.14.34.19
- kind: bug
- area: crates/slate/tests/fixtures.release/weak_strong_override
- corpus: linux

Outcome: kernel weak defaults written as `T *__weak name(...)` translate with `#[linkage = "weak"]`, so the vmlinux relink has no `multiple definition` errors; the root cause was fixed by slate-f2zu.14.34.18 (3d3362c08) and this bead adds the regression case.

Symptom: vmlinux link (2026-11-15 11:04) failed with `multiple definition` for arch_adjust_kprobe_addr, arch_uretprobe_trampoline, execmem_arch_setup, pcibios_setup and cache_get_priv_group, each defined in a translated shard and in the x86 override.

Reproducer (two units):
```c
// a.c
int *__attribute__((weak)) f(void) { static int a = 1; return &a; }
// b.c
int *f(void) { static int b = 2; return &b; }
```

Cause: every weak default puts `__weak` after the `*` in the declarator (kernel/kprobes.c:1506 `kprobe_opcode_t *__weak`, kernel/events/uprobes.c:1746, mm/execmem.c:560, drivers/pci/pci.c:4179 `char * __weak __init`, drivers/base/cacheinfo.c:858). Before .18 the parser dropped symbol attributes in that position, so the default was a strong `extern "C-unwind" fn` and `SymbolOwners` never saw a weak definition.

Fix: none needed beyond .18. Retranslating the five weak-side units with the current binary gives `#[linkage = "weak"]` on all five (pcibios_setup also keeps `.init.text`). After retranslating kernel, kernel__packed, mm, drivers_pci and drivers_base in place and relinking, vmlinux.o links with no multiple definitions.

Regression test: crates/slate/tests/fixtures.release/weak_strong_override/ gains `pointer_fallback` (weak after `*`, strong override in overrides.c: non-owner unit imports it) and `lone_pointer_weak` (weak after `*`, keeps body and `#[linkage = "weak"]`).

See: slate-f2zu.14.34.18, slate-f2zu.14.34.10 (SymbolOwners), slate-f2zu.14.34.6.
