# Allow inline-only extern overloadable definitions

_2026-10-24 11:27:22_

slate-parser-6x05.50: glibc's clang fortify path defines open/openat/mq_open as 'extern **inline gnu_inline always_inline overloadable'; the checker rejected the definition ('definition of an extern overloadable function') because extern overloads need an Itanium-mangled symbol (6x05.41). An extern inline gnu_inline body never emits a symbol, so no mangling is needed. Checker::extern_inline_only (sema/assertion.rs) removes the id from external_overloads after declare_object when the definition is extern+inline and has gnu_inline or the dialect uses SupressDef semantics (not on the MSVC environment), mirroring the ExternInline/SupressDef arm of finish_functions. Calls then resolve normally. The enable_if (**fortify_clang_prefer_this_overload) tie-break was not needed: open(p,O_RDONLY) and open(p,O_CREAT,0600) pick the same overloads as clang (the extern variadic open loses on ellipsis rank). Libsodium randombytes_sysrandom.c and randombytes_internal_random.c now pass. A C99 inline-only overload (no extern, depends on later declarations) is still Unimplemented. Fixture: clang/linux/x86_64/ir_overloadable_inline_only.c. Parser nextest 8376 passed.
