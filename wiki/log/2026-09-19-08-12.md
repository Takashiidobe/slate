# Classify vector arguments and results per ABI convention

_2026-09-19 08:12:10_

Vectors no longer pass as `native_c`. `AbiPass::Direct` (`direct` in the dump)
is new: a value passed in registers as its own type, which is what a vector
that fits the target's vector registers does. `scalar` would have
misdescribed it and `native_c` claimed it was unclassified.

Classification per convention, taken from clang IR signatures for each target
(`sysv64`, `win64`, `x86_cdecl`, `aapcs64`, `win_arm64`, `aapcs32`,
`aapcs32_hard_float`) — the table lives in `wiki/concepts/ir-spec.md`. Two
corners are gcc inheritance rather than rules:

- `sysv64` passes a one-lane `double` vector in memory (`byval<align=8>`)
  while returning it `direct`; every other eight-byte vector coerces to
  `f64`. Clang carries the comment "gcc passes <1 x double> in memory".
- `x86_cdecl` coerces an eight-byte vector to `i64` only when its lanes are
  integers narrower than 64 bits — an MMX type. `vector<i64, 1>` and
  float-lane vectors of that size pass `direct`.

The classification is the target's baseline ISA. `-mavx` and friends keep
wider vectors in registers, which is exactly the `-Wpsabi` warning clang
emits on the 32-byte cases in the new fixture; this crate has no ISA feature
flags, so baseline is the only answer it can give.

`tests/fixtures/sema/ir_vector_abi.c` pins sysv64 (every size from 1 to 64
bytes, plus indirect and variadic call sites); each target's `abi_target.c`
gained the same vector block. Every line was diffed against clang 22 for
that target, including variadic vector arguments.
