# slate-yar4.62 object_size: fold ComplexPart designations by compiler flavor

_2026-11-23 10:08:42_

- bead: slate-yar4.62
- kind: bug
- area: crates/slate-parser/src/sema/object_size.rs

Outcome: Slate folds object-size queries for real and imaginary complex components with the enclosing object size and the selected compiler's subobject bounds.

## Symptom

Clang-flavor translation returned zero for the size of the imaginary component of a local complex value in mode 3.

## Reproducer

```c
unsigned long size(void) {
  double _Complex z;
  return __builtin_object_size(&__imag__ z, 3);
}
```

Before: the parser emitted `const<u64>(0)` for Clang's unknown minimum.
After: it emits `const<u64>(8)` on x86_64 Linux.

## Cause and fix

`TypeResolver::place_designation` dropped `PlaceKind::ComplexPart`. It now recurses into the enclosing place and advances to the imaginary half using the target storage size of one component.

Whole-object queries preserve the original allocation range. Clang subobject queries use the bounds of one complex value, including when it is an array element. GCC uses the selected scalar component. The two flavors return 16 and 8 respectively for mode 1 on the real half of a local `double _Complex`.

## Regression fixtures

`crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/builtin_object_size_complex.c` covers both halves in all four modes, nested fields and array elements, dynamic size with long double, and unknown bases.

Limits: GCC pointer arithmetic after a component projection still uses the LLVM fallback. Clang can still lose the base designation through an unsized array offset. See slate-yar4.63.
