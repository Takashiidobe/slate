# c2rust-style pointer capability lattice + libexpat benchmark

_2026-08-27 08:53:45_

Design input for slate-y0qs (rewrite pipeline performance). Two decisions:

1. Representation-unification phase (see rewrite-worklist-engine.md addendum)
   should use a c2rust-style capability lattice per pointer binding instead of
   ad hoc per-pass heuristics: {write, unique, free, offset} booleans map to
   one resulting pointer type (&T / &mut T / &Cell<T> / Box<T> / &[T] /
   &mut [T] / Box<[T]>). This gives representation decisions a small, fixed
   lattice height (bounded revisits per binding) instead of unbounded
   per-pass mutation, which is exactly the monotonicity guarantee the
   unification-phase proposal needed. Escape hatch: a call site that can't
   accept the inferred pointer type falls back to an accessor that returns
   the raw pointer, rather than blocking the whole binding's inference or
   forcing a global re-decision.
2. Pointers should also carry capability facts beyond this table (e.g.
   nullability, provenance/aliasing scope) so downstream passes can make
   finer representation choices without re-deriving them.
3. Benchmark/validation target for the worklist + unification rework:
   libexpat, not sqlite (sqlite is still blocked on slate-wcf7.2, the CIR
   memory blowup). Start translating libexpat now and track wall-clock as
   passes come back online, instead of waiting on the sqlite epic to unblock
   before getting real non-trivial-codebase signal.
