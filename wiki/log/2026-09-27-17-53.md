# Reachability roots inline definitions clang emits

_2026-09-27 17:53:30_

slate-parser-3e4d. Follow-up to d2w: filter_translation_unit (src/reachability.rs) skipped every inline function definition, so inline definitions clang emits from an included file were pruned, and a file-scope fn_t f; (function typedef) was rooted as an object definition.

emits_inline_definition mirrors clang's basicGVALinkageForFunction over all file-scope declarations of the name (function_redeclarations, reusing sema::function::attributes, now pub(crate)):
- gnu_inline on any redeclaration, or gnu89: plain inline kept, extern inline dropped.
- C99: extern inline, or inline with any non-inline or extern redeclaration.
- windows-msvc target (Microsoft ABI, either flavor): only dllexport or an extern redeclaration (clang weak_odr). The rest is linkonce_odr; clang sometimes emits an unused one depending on declaration order (inline def followed by a prototype), but it is discardable, so not a root. First attempt used the C99 rule on MSVC and pulled UCRT _CRT_STDIO_INLINE bodies into sysroot_crt_headers_*.c, which also exposed a sema error on their deprecated attribute arguments.

declares_function follows typedef names to a function declarator.

mark() now marks a kept declaration's own names, so redeclarations come along: without it, inline int f(){..} plus a later int f(void); in a header lost the prototype and sema printed inline_only where clang emits. No existing fixture changed.

Fixtures: tests/fixtures/reachable_inline_from_include{,_gnu89,_msvc}.c sharing one header; rooted sets match clang -emit-llvm in all three modes. ir-spec.md Validation and declaration pruning updated.

Filed slate-parser-7n0i: sema's definition=emitted ignores the MSVC rules (exported_inline prints inline_only).
