# slate-f2zu.14.34.25 Expr::typed_null: freestanding typed null fn-pointer printed extern C-unwind via type_to_string (E0308 in i915 shard)

_2026-11-15 15:34:10_

- bead: slate-f2zu.14.34.25
- kind: bug
- area: crates/slate/src/frontend/lowerer/pointers.rs
- area: crates/slate/src/backend/rust_ast.rs
- area: crates/slate/src/backend/engine/rules/null_compare.rs
- area: crates/slate/src/backend/interproc/pointer_lattice.rs
- corpus: linux

Outcome: a typed null pointer is now a structured `Expr::GenericPath` call
(`Expr::typed_null`), so its pointee type prints through the crate's `Codegen`
and follows `no_unwind`: a freestanding crate prints `extern "C"` there, as it
does everywhere else.

Symptom: cargo build of kernel shard drivers_gpu_drm_i915\_\_packed failed with
error[E0308]: mismatched types: expected "C" fn, found "C-unwind" fn
(i915_gem_context.rs, i915_gem_mman.rs), so the shard stayed native in the
vmlinux relink.

Reproducer (minimal C, -ffreestanding):

```c
typedef int (*extension_fn)(int *value, void *data);
int run_extensions(int *value, const extension_fn *tbl, unsigned count, void *data);
... run_extensions(&value, NULL, 0, &step);
```

Before:
`core::ptr::null::<Option<unsafe extern "C-unwind" fn(*mut i32, *mut ()) -> i32>>()`
passed where the parameter is `*const Option<unsafe extern "C" fn(...)>`. After:
`core::ptr::null::<Option<unsafe extern "C" fn(*mut i32, *mut ()) -> i32>>()`.

Cause: `Lowerer` (crates/slate/src/frontend/lowerer/pointers.rs) built the typed
null as `Expr::Var(format!("core::ptr::null::<{}>", type_to_string(&inner)))`.
`type_to_string` creates a fresh `Codegen` with `no_unwind` off. In project mode
the crate-wide freestanding decision (`Program::no_unwind`, slate-f2zu.14.34.14)
is set by translate-project after lowering, so a type baked into a string at
lowering time always printed `C-unwind`.

Fix:

- `Expr::typed_null(mutable, pointee)` and `Expr::is_typed_null()` in
  crates/slate/src/backend/rust_ast.rs build and recognise
  `Call { func: GenericPath { core::ptr::null|null_mut, [pointee] } }`.
- The pointer lowering uses `typed_null`. `null_compare::is_null` and
  `pointer_lattice::is_null_like` use `is_typed_null` in place of their
  `starts_with("core::ptr::null::<")` string matches.

Regression test: crates/slate/tests/fixtures/freestanding_null_fn_table.c
(failed with E0308 before the fix).

Limits: other lowering-time `type_to_string` strings remain (vla.rs
`size_of::<T>`, bitint.rs `<T>::...`). They cannot cause an ABI mismatch: size
does not depend on the ABI, and bitint types hold no fn pointers.

See: slate-f2zu.14.34.14, slate-f2zu.14.34.6.
