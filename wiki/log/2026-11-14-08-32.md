# slate-5q63.13 shadow restore: per-rename body walks made cpython translate 9x native compile; e2e excludes rustfmt via SLATE_NO_FORMAT

_2026-11-14 08:32:39_

Outcome: cpython translate-project drops from 55.2s (9.05x native compile) to 17.7s (2.57x), and the e2e harness no longer counts rustfmt in translate_seconds.

Gap: the cpython e2e translate stage took 55.2s against 6.1s for the native compile of the same 190 TUs, with only ~2.2 of 12 cores busy. Per-TU, Python/ceval.c alone took 27.9s (the critical path), pystate.c and pylifecycle.c ~13s each.

Cause 1 (ceval.c): perf showed 75% of samples in backend::engine::shadow::restore. For every renamed shadowed local it walked the whole function body twice (ScopeMentions to find binders and in-scope mentions, then Rename). _PyEval_EvalFrameDefault has thousands of renamed locals from macro-expanded opcode blocks, so this was O(renames x body).

Cause 2 (pystate.c, pylifecycle.c): 52% in the rustfmt subprocess formatting the ~3.6MB _PyRuntime initializer. pretty_rust only uses prettyplease when the source has no `//` or `/*`; slate carries C comments over as plain `//` (61k lines in cpython), and syn drops non-doc comments, so 188/191 files go to rustfmt.

Before: translate_seconds 55.2, native_compile_seconds 6.1, translate_over_compile 9.05.
After:  translate_seconds 17.7, native_compile_seconds 6.9, translate_over_compile 2.57, format_seconds 30.2 (untimed).

Implementation:
- shadow.rs restore: one ScopeMentions walk tracks every fresh name's binder count and in-scope mentions, using a frame stack of bound fresh names. It only records mentions of fresh or original names, since the conflict check reads nothing else. The decision loop maps mentions through renames already decided, so the output is unchanged; one Rename pass applies the whole map.
- format.rs: SLATE_NO_FORMAT=1 (any value but 0) makes format_rust and pretty_rust return the unformatted source, macro-list holes still restored.
- tools/corpus/e2e.py: the translate stage runs translate-project with SLATE_NO_FORMAT=1, then format_crate runs rustfmt --edition 2024 over src/**/*.rs in parallel; format_seconds and format_failures are reported next to translate_over_compile.

Verification: cpython translate-project output (formatted) is byte-identical to the pre-change output except the __TIME__ string in getbuildinfo.rs; after unformatted translation plus format_crate, the only other diff is one comment's indentation in obmalloc.rs. slate profile: 39 passed.

Limits: SipHash on Ident is still visible in the ceval.c profile (a faster hasher is tracked separately). Remaining translate time is 2.57x vs redis's 2.13x. cpython still fails cargo check (18 errors, slate-dghn.56.5-.9), so the test stage has not run; the recipe has no test command yet.
