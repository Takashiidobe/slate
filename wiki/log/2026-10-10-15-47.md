# Lex a stray backslash as its own token and drop a stringified final backslash

_2026-10-10 15:47:03_

slate-parser-cxg.7.17.

str(\) was not expanded: the lexer started an identifier at any backslash, and universal_character_name_end's fallback consumed two characters, so \) became one token and the ) was lost. A backslash now starts or continues an identifier only when it begins a UCN (\u, \U, or \N{, starts_universal_character_name). Otherwise it is a one-character token, like @. String and character literal scanning still uses universal_character_name_end for escapes.

Stringify: gcc and clang warn 'invalid string literal, ignoring final \' and drop it, so str(\) is "" and str(\\\) is "\\". stringized_source now drops a final unescaped backslash for both. msvc keeps it (cl /EP prints "\"), and cl /Zs then fails with C2001. Slate keeps the text for msvc but does not reject it yet: filed as cxg.7.24.

A literal UTF-8 identifier (caf with a real e-acute) still fails, as tracked by cxg.23. The fixture uses the \u00e9 escape.

Fixtures: {gcc,clang}/linux/x86_64/pp_stringify_backslash.c (lone, escaped, odd run, a backslash before an identifier, a backslash as a non-final argument, a UCN identifier; matches gcc/clang -E). Migrated gcc.dg cpp/strify2.c (c99). Wiki: preprocessor.md expansion.
