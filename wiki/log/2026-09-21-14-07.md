# Rescope the corpus-sweep warning beads to acceptance-affecting rules

_2026-09-21 14:07:40_

dyd.15-.17 came out of the corpus sweep's warning diff. Reviewed against the
rule that a diagnostic is worth implementing only when its underlying rule
decides acceptance or changes what we lower.

Measured with clang 22.1.8: -Wint-conversion and -Wincompatible-pointer-types
are default *errors* in C (since clang 16), so the "warnings don't change
behavior" premise is false for them. src/diagnostics.rs:74 models both as
default warnings, and neither fires at all today:

  int  *f(void){ return 3; }          clang: error   slate: lowers, rc=0
  char *g(void){ int *p; return p; }  clang: error   slate: lowers, rc=0

Filed as dyd.43 (P1) - a live accept/reject divergence, not a warning gap.
The severity model also has no notion of a default-error warning that
-Wno-... can still downgrade.

- dyd.15 retitled to attribute applicability. The question is applied vs
  ignored, observable in IR alignment/visibility/section/size; the named
  diagnostic is the byproduct. Overlaps dyd.37/.31/.35.
- dyd.16 split. Kept: shift count, division by zero, overflow in
  constant-expression contexts, where clang rejects the TU. Dropped:
  absolute-value, string-plus-int, non-constant constant-conversion,
  bitfield conversion.
- dyd.17 closed won't-do. return-type is already modeled as ir::Fallthrough
  (fallthrough=ub_if_used); format/format-extra-args is a format-string
  parser with no IR effect; missing-declarations, sizeof-array-argument and
  varargs are lint. Split out dyd.44 (unprototyped declarations: C23
  acceptance plus argument-passing ABI) and dyd.45 (incompatible library
  redeclaration must drop builtin status, feeding dyd.20/dyd.23).

The sweep's warning diff stays a cheap gap-finder - it is how dyd.43 was
found - not a parity target.
