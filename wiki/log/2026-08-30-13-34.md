# addr_of_mut! through const-cast field misses write observation

_2026-08-30 13:34:30_

slate-a28e.6: ClassifyCtx::expr()'s Ref/AddrOf handling in pointer_lattice.rs only observed ESCAPE when the operand was a bare Var, so `addr_of_mut!(&param->field)` (mutable AddrOf wrapping a Field/Deref/Cast chain) never marked the underlying param W, leaving it lifted to &T instead of &mut T; generic Var-fallback rewrite then re-cast it as *const, which addr_of_mut! rejects (E0596). Fix: when mutable is true and the operand isn't a bare Var, route through place(expr, true) (same place() traversal a28e.2 added for Field/TupleField) instead of falling to the read-only expr() path. Bug only reproduces at -O2+ (CIR mem2reg inlines the member address directly into the call arg instead of materializing a *mut local first) -- added ptr_param_field_addr_of_mut fixture with a -O2 fixture_clang_arg_overrides entry, mirroring goto_temp_cross_state. Regenerated FileCheck baselines for borrowck_hostile_aliasing/struct_field_2d_array (line-shift only, content unchanged, since pair_lo/fill_via_ptr already returned &mut and just moved by a line). Verified against a fresh transpile-zstd + cargo check: E0596 count 0 (was 4).
