# answer __has_c_attribute per flavor and expose __has_* to #ifdef

_2026-09-26 08:26:25_

slate-parser-dyd.66. `__has_c_attribute` was always 0 in const_expr. The preprocessor
now expands `__has_c_attribute(name)` and `(scope::name)` through
`attribute_support::has_c_attribute(spelling, flavor, standard, target)`:
- standard attributes: a hand table of per-flavor dates. clang returns each
  attribute`s own date (deprecated 201904, nodiscard 202003, ...) and 0 for
  unsequenced/reproducible; gcc 202311 for all eight; cl only in C23 mode,
  202311 for fallthrough/maybe_unused/nodiscard and 0 otherwise.
- scoped names: 1 when registered. Scope membership turned out to be per
  name (clang has gnu::packed but not clang::packed, only noinline under
  msvc::), so the generator now also probes __has_c_attribute(scope::name)
  and emits CLANG_{GNU,CLANG,MSVC}_SCOPE and GCC_GNU_SCOPE. These replace
  scope_registered and the gnu/clang whitelists in c23_attribute_name, which
  also makes the parser warn on [[clang::packed]] / [[gnu::overloadable]] /
  [[msvc::forceinline]] exactly as clang and gcc do.

No `__has_*` operator was visible to #ifdef/defined. is_defined_operator now
reports the ones slate evaluates, per flavor as measured (cl: __has_include
and __has_c_attribute only). This flipped glibc <string.h> onto its C23
const-preserving strchr/memchr/strstr _Generic wrappers (guarded by
#ifdef __has_extension), matching clang; c23_library.c and gcc-torture
20000910-2.c regenerated accordingly.

Verified against clang (linux c17/c23, windows), gcc (x86_64, aarch64) and cl
(clatest, c17): exact match, except cl before C23 rejects a scoped operand
(C2278) where slate answers 0 (permissive). Fixtures:
has-c-attribute-{clang,gcc,msvc-c23,msvc-c17}.c and
has-operators-defined-{clang,gcc,msvc}.c. Filed slate-parser-dyd.67 for the
three clang operators slate does not evaluate.
