# slate-f2zu.11.3 translate-project merge: cfg-gate unit mods compiled by only some manifest targets

_2026-11-13 20:25:00_

- bead: slate-f2zu.11.3
- kind: feature
- area: crates/slate/src/project/merge.rs
- area: crates/slate/src/project/matrix.rs
- area: crates/slate/src/project/plan.rs
- area: crates/slate/src/main.rs

Outcome: manifest targets may compile different source sets; translate-project --merge emits one crate in which a unit compiled by only some targets has its `mod` declaration gated with `#[cfg(...)]` from `TargetConditions::select`.

Gap and why it mattered: real projects pick platform files per target (win32/*.c vs unix/*.c). slate-f2zu.11.1 rejected such manifests with "manifest targets X and Y compile different sources".

Before (linux: main.c common.c unix.c; windows: main.c common.c win.c):
  error: manifest targets windows-x86_64 and linux-x86_64 compile different sources: only linux-x86_64 compiles unix.c
After (src/main.rs of the merged crate):
  #[path = "common.rs"]
  mod __slate_unit_common;
  #[cfg(unix)]
  #[path = "unix.rs"]
  mod __slate_unit_unix;
  #[cfg(windows)]
  #[path = "win.rs"]
  mod __slate_unit_win;
The report prints `<source>: not compiled` under each target lacking a unit and `only on <cfg>` under the unit.

Implementation:
- matrix.rs: `Matrix.sources` is the sorted union of every target's units; `Target::compiles(source)` and `Matrix::target(name)` added; `commands` yields only the target's own units. `MatrixError::DifferentSources` removed.
- plan.rs: `plan` plans each target's own sources only.
- merge.rs: `TargetUnit.present`; `prepare_target` explores present sources and pushes `absent_unit` placeholders so `units[index]` stays aligned with `matrix.sources`. Absent units get no compile jobs, are skipped by the signature check and the "no configuration translated" error. `merge_unit` already ignored targets with no compiled rows (cfgs are relative to the targets present), so items inside a gated unit need no target cfg of their own. `Merged.unit_cfgs` maps stem -> `conditions.select(present, everywhere)`; a unit defining main that some target lacks is an error (it is the crate root and cannot be gated).
- main.rs: `write_project_crate` takes `unit_cfgs` and wraps each `Item::Mod` in `Item::Cfg`.
- Cross-unit calls need nothing extra: units export by `#[unsafe(no_mangle)]` and callers declare `extern "C"`, so main.c links against whichever platform unit is compiled in.

Fixture: crates/slate/tests/fixtures.matrix/split/{manifest.json,build-linux,build-windows,main.c,common.c,unix.c,win.c,include/platform.h}. Test manifest_merge_gates_units_compiled_for_some_targets (tests/differential.rs) runs the merged crate on linux against clang main.c+common.c+unix.c and checks the three mod declarations. The merged crate also passed `cargo check --target x86_64-pc-windows-msvc` by hand (not part of the test).

Limits: the "main unit missing on a target" error has no test. The windows side is only type-checked, not run.
