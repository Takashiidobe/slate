# slate-oreg.7: initializer self-reference, compound-assignment order, prefetch side effects

_2026-10-18 14:38:54_

Promoted gcc-torture 20020529-1, pr39100, pr58943, builtin-prefetch-4.

- Self-referential locals (struct xx s = {0, &s}; struct E e[2] = {{0, &e[1]}}): FunctionLowerer.declaring (a Cell) is set by lower_binding when the variable being declared is referenced from its own initializer. Then the Let gets the default zero init, and the initializer becomes an assignment emitted right after it. lower_statement now returns Vec<Stmt> so a Let can emit two statements. Over-aligned locals are added to aligned_locals before the initializer is lowered, so self-references go through .0.
- Compound assignment (pr58943, x[0] |= foo()): clang evaluates the RHS before loading the LHS. sema update() now captures a side-effecting RHS in a Capture before the Update. The hoister inlines that capture again when the RHS is effect-free per its effect_free set (memory=none builtins), so pure RHS like popcount keeps the old shape.
- __builtin_prefetch evaluates its address argument (let _ = addr;) unless effect_free_value proves it pure (a conservative IR check in values.rs).
- Fixes a .9 regression: integer abs stays open-coded at call sites, but its extern declaration is emitted again, so taking abs's address (static_address_aggregates) compiles.

New fixture: fixtures/initializer_and_update_ordering.c. FileCheck churn: 33 slate and 76 parser blocks. All are the RHS-first reorder (va_arg and libm calls are now evaluated before the old value is read) or the restored abs extern.
