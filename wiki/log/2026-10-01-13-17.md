# Linear-time in-order aggregate initializer writes

_2026-10-01 13:17:50_

slate-parser-6x05.10: sema/initializer.rs Builder::write and Builder::partitions ran split_out (rebuilding the whole member Vec) plus retain on every element, so an n-element array initializer was O(n^2) memmove.

Builder now tracks:
- frontier: one past the highest Index/Range end written (a conservative upper bound; removals never lower it).
- tail_disjoint: the last member was appended past the frontier, so it overlaps nothing else.

Fast paths:
- write/partitions with an Index/Range target at or past the frontier append directly.
- partitions on the same target as a disjoint tail (each field of t[i] in a struct array) returns the tail without scanning; the Leaf check still errors as before.
Everything else (Field targets, unions, rewinding designators) takes the old slow path and clears tail_disjoint.

Results (ir): synthetic 20000-element array 4.8s -> 0.08s; curl tool_hugehelp.c 240s -> 1.1s; utf8proc.c 66s -> 1.55s. IR output byte-identical to the pre-change binary on tool_hugehelp (10MB) and utf8proc (23MB).
New fixture clang/linux/x86_64/initializer_in_order_writes.c pins the fast/slow transitions (rewinds, ranges after the tail, reopened struct elements, brace elision). Parser profile 7506/7506 before the fixture.
