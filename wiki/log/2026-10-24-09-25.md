# msvc: user __has_* shims expand instead of slate's builtin tables

_2026-10-24 09:25:42_

slate-parser-7xh6. Under --flavor=msvc, '#define __has_extension(x) 0' (SQLite sqliteInt.h:233-239) was ignored: expand_has_checks evaluated __has_attribute/__has_builtin/__has_feature/__has_extension from slate's tables for every flavor, and expand_condition protected any __has_* name from expansion. SQLite then picked __atomic_load_n with __ATOMIC_RELAXED (unresolved in 9 TUs).

- expand_has_checks (pp/mod.rs) evaluates a query only when is_defined_operator(name, flavor); the per-name flavor gates it replaced (__has_cpp_attribute gcc-only, clang-only queries) follow from that table.
- expand_condition (pp/expand.rs) protects a __has_* operand only for owned names, so a user macro of that name expands. msvc owns only __has_include and __has_c_attribute.
- cl.exe checked: shims take the false branch; defined(__has_builtin) && __has_builtin(x) is false.
- Unguarded '#if __has_builtin(x)' without a shim still errors where cl warns C4067 and takes the false branch; that is the general undefined-call case, filed as slate-pola.
- Fixtures: msvc/windows/x86_64/has-operators-user-shims.c (failed before), has-operators-unowned-guarded.c.
