# slate-f2zu.14.23 macro_sites: field-name and place macro argument printed as `*ident` (hybrid_var no rules expected `*`)

_2026-11-14 18:52:07_

- bead: slate-f2zu.14.23
- kind: bug
- flavor: clang
- area: crates/slate/src/frontend/lowerer/macro_sites.rs

Outcome: a kept macro whose parameter is both a field name (`->_var`) and a
place (`&_var`) now passes the place as an expr argument instead of a corrupted
`*ident`.

Symptom: linux intel_core.rs
`memcpy(hybrid_var__3!(pmu, *hw_cache_extra_regs), ...)`: no rules expected `*`
(17 errors).

Reproducer:

```c
#define hybrid_var(_pmu, _var) (*({ typeof(&_var) __Fp = &_var; \
  if (is_hybrid(_pmu)) __Fp = &(_pmu)->_var; __Fp; }))
memcpy(hybrid_var(&pmu, regs), source, sizeof(regs));
```

Cause: `finish_macro_site` took the `MacroParamShape::Ident` shortcut for any
parameter with a `MacroCover::Name` use, dropping its place argument. The
template still held the place-pointer hole for `&_var`, so
`finish_place_arguments` applied `place_of_argument` to `MacroName("regs")` and
printed `*regs`. With a `__SlateAlign16` global the place would also have needed
`.0`.

Fix: the ident shortcut requires `place.is_none()`. The field use stays a
literal field name in the template and `&_var` becomes an `addr_of_mut!(regs.0)`
expr argument.

Regression test:
crates/slate/tests/fixtures/macro_field_name_and_place_argument.c
