# slate-wbnu gcc #pragma ms_struct: gcc flavor on linux ignores the pragma instead of applying ms layout

_2026-11-18 00:06:06_

- bead: slate-wbnu
- kind: bug
- area: crates/slate-parser/src/parser/decl.rs
- flavor: gcc

Outcome: gcc flavor on Linux targets ignores `#pragma ms_struct` like gcc does, keeping gcc record layout; clang flavor still honors it.

Symptom: gcc 16 on x86_64/i686/aarch64 linux warns "ignoring #pragma ms_struct on [-Wunknown-pragmas]" and lays out records normally. slate's gcc flavor applied the pragma (sema/pragmas.rs `Walk::pragma`), so sizes diverged.

Reproducer:
```c
#pragma ms_struct on
struct on { char a : 3; int b : 4; char c; };
```
gcc: sizeof 4. slate --flavor=gcc before: 12 (ms layout).

Cause: `Parser` pragma parsing in parser/decl.rs produced `PragmaKind::MsStruct` for every flavor; gcc only registers the pragma on Darwin/Windows targets.

Fix: the `ms_struct` arm in parser/decl.rs is skipped when `flavor().is_gcc()` and target os is `TargetOs::Linux`, so the pragma falls through to `PragmaKind::Opaque` (unknown pragma). -mms-bitfields still makes every record ms_struct, so gcc and slate agree there.

Regression test: crates/slate/tests/fixtures/gcc/pragma_ms_struct_ignored.c (gcc: 4 4 4).

Limits: slate does not emit -Wunknown-pragmas for opaque pragmas, so gcc's warning is not reproduced. Non-Linux gcc targets (FreeBSD, Android) keep honoring the pragma.
