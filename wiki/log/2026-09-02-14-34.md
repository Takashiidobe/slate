# Wide _BitInt case ranges, and two live Or-of-guard bugs

_2026-09-02 14:34:58_

slate-c6jq.3. GNU `case a ... b` on a `bitint::BInt` selector cannot use a range
pattern — E0029 allows only `char` and numeric types — so it lowers to a guard.
Both endpoints now go through the same interned `const` items as discrete values
(slate-c6jq.2), so a guard reads
`__switch_sel if __switch_sel >= __CASE_B256_X && __switch_sel <= __CASE_B256_Y`
instead of re-parsing a decimal string on every comparison.

Two bugs this exposed, both confirmed by a failing fixture before the fix:

1. `structure_dispatch::pattern_of` joined an arm`s patterns with `Pattern::Or`.
   For an arm mixing a discrete value with a range that emitted
   `K | __switch_sel if guard`, which Rust parses as `(K | __switch_sel) if guard`
   — so the discrete value silently had to satisfy the range guard too. Wrong
   answers, not a compile error, in the arms that did parse. Guarded alternatives
   now merge into one `Guarded` whose cond is `||`-joined, with non-guard
   alternatives becoming `bind == K`; anything else bails the dispatch rebuild
   rather than guessing.

2. `Pattern::Guarded` hardcoded the bind name `"v"`. Harmless in the lowered
   selector match (arm body is just an index), but once the dispatch rebuild makes
   a real match the arm body is the case body, so `int v` in scope became the
   selector. Now `__switch_sel`.

Fixture `tests/fixtures/switch_case_wide_bitint_range.c` covers a plain range, an
arm mixing a discrete value with a range, and a case body referencing a local `v`.
`libc` profile has one pre-existing unrelated failure (pthread_cancel-points,
slate-os0h.19.3.6.3) that reproduces on a clean tree.
