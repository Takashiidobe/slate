# Bridge i686 records and large x86_64 records by value

_2026-11-07 16:56:44_

slate-yar4.23, slate-yar4.24: a bridged call (callee signature holds f80) passing or returning a record by value was a barrier unless it was an x86_64 align-16 f80 record (m<size>, s80). Tables::long_double_aggregate_tag (lowerer/f80.rs) now tags MEMORY-class records m<size>a<align>: every record on i686 (i386 Linux passes structs on the stack and returns them via hidden pointer, in C and Rust alike) and x86_64 records over 16 bytes without f80. Records holding vectors stay barriers. c_shim::memory_aggregate parses m<size> (align 16) and m<size>a<align> and renders struct __slate_<tag> { _Alignas(align) unsigned char v[size]; } (m<size> used long double v[size/16] before; same MEMORY ABI). Fixture: long_double_bridge_aggregates.c (indirect and direct calls with struct big (32, align 8), struct tagged, struct one), passing on x86_64, i686, aarch64, armv7. x86_64 records <= 16 bytes without f80 need the C SysV eightbyte classes: filed slate-yar4.34. Wiki long-double-f80.md updated. slate and slate-i686 profiles green.
