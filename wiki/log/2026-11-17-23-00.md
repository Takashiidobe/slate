# slate-78pa.9 Hoister arguments_reversed: gcc flavor on x86 evaluates call arguments right to left (pair(a(), b()) calls b first)

_2026-11-17 23:00:40_

- bead: slate-78pa.9
- kind: parser

- area: crates/slate-parser/src/sema/module.rs

- target: i686

Outcome: under `--flavor=gcc` on x86_64 and i686, slate evaluates call arguments right to left after the callee, matching gcc; gcc on aarch64/arm, clang and MSVC keep left to right.

## Gap and why it mattered

slate-parser-dyd.71 made hoisting keep left-to-right (clang) order. gcc on x86 calls `b()` before `a()` in `pair(a(), b())`, so a gcc-flavor translation that observed the order printed different output than the gcc oracle. Measured with gcc 16 and clang:

| | x86_64 / i686 gcc | aarch64 / arm gcc | clang |
|---|---|---|---|
| `pair(a(), b())` | b, a | a, b | a, b |
| `pick()(a(), b())` | p, b, a | p, a, b | p, a, b |
| `pair(i++, i++)` (unsequenced) | 21 | 12 | 12 |
| `a() + b()`, `{a(), b()}` | a, b | a, b | a, b |
| `__builtin_stdc_rotate_left(a(), b())` | a, b | | |
| `__builtin_memcpy(d(), s(), z())` | z, s, d | | |

The results were the same at -O0 and -O2.

## Before (`--flavor=gcc`, x86_64)

    int both(int *p) { return pair(plain(p), plain(p + 1)); }
    return call(pair, call(plain, p), call(plain, p + 1));   /* Rust runs plain(p) first */

## After

    let %18: i32 [synthetic] = call(plain, p + 1);
    return call(pair, call(plain, p), read(%18));

## Implementation

- `finish_module` (crates/slate-parser/src/sema/module.rs) passes `flavor.is_gcc() && target.family.is_x86()` to `effects_statements::normalize` as `arguments_reversed`.
- In the `Hoister` Call arm (crates/slate-parser/src/sema/effects.rs), operands are [callee, arguments reversed] and go through `sequenced`. When more than one operand still has effects, every effectful operand except the last one evaluated is spilled in evaluation order. The arguments are then put back in source order.
- Direct calls to `__builtin_stdc_*` (`source_ordered_builtins`) are exempt.

## Fixtures

- crates/slate/tests/fixtures/gcc/call_argument_evaluation_order.c: passes against gcc on x86_64, i686 and aarch64. The outputs differ by target (`202 303 703` on x86, `102 203 704` on aarch64).
- crates/slate-parser/tests/fixtures/gcc/linux/{x86_64,aarch64}/ir_effects_call_argument_order.c
- Regenerated, argument order only: 11 gcc-flavor x86_64 parser corpus fixtures (e.g. pr49712 `foo(a[b] = 0, bar())` now calls bar first); slate gcc fixtures nested_functions, openmp_parallel_gcc, c2y_if_declarations, compound_literal_thread_local, x86_64/asm_intel_address_modifier, i686/flag_{,no_}align_double_gcc.

Limits: gcc-flavor x86 output gains a `let` for each extra effectful argument, e.g. `printf(.., f(4), f(5))`, unless the callee is `[memory=none/read]`. Other gcc parser-expanded builtins (`__builtin_tgmath`, etc.) are not exempt if they lower to `Call`. MSVC argument order was not checked.
