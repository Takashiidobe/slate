# slate-a28e.8: propagate LLVM-intrinsic feature gates project-wide

_2026-08-30 13:58:04_

Multi-file translate-project crates were missing nightly feature gates
(`link_llvm_intrinsics`, `abi_unadjusted`, `portable_simd`, `simd_ffi`) on
any submodule that used `cir.call_llvm_intrinsic` (e.g. zstd's
`zstd_lazy.rs`), producing E0658. Root cause: `module_index::required_features`
(the structural CIR pre-scan that seeds the project-wide `crate_features`
set written once to `lib.rs`) didn't look for `Op::CallLlvmIntrinsic` at
all — only the per-file `Lowerer`'s `uses_llvm_intrinsics`/
`uses_portable_simd` `Cell`s did, and those get baked into that file's own
`#![feature(...)]` header, which only takes effect at the crate root.
Non-root submodules got the shim `extern "unadjusted"` block but no feature
gate anywhere the compiler would honor it.

Fix: `required_features` now walks each function body with
`walk_region_ops` and, on any `Op::CallLlvmIntrinsic`, adds all four
features unconditionally (no attempt to distinguish "used SIMD types or
not" — enabling unused nightly features is harmless, so it isn't worth
resolving arg/result types at this pre-lowering stage). Verified against
zstd (c-corpus): `zstd_lazy.rs` no longer appears in `cargo check` errors
at all; remaining ~28 errors are unrelated bitfield/pointer-type issues.
