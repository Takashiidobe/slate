# slate-f2zu.14.40.6 translate-project link_section statics: same-priority constructors and section entries from different units emitted in CGU order; moved to crate root in unit order

_2026-11-16 12:03:59_

- bead: slate-f2zu.14.40.6
- kind: bug
- area: crates/slate/src/project/link_order.rs
- area: crates/slate/src/backend/rust_ast.rs
- area: crates/slate/src/main.rs
- corpus: linux

Outcome: `#[link_section]` statics that two or more units place in the same
section are emitted from the crate root in unit (link) order, so same-priority
constructors run and linker-set entries iterate in C link order.

Symptom: after slate-f2zu.14.40.4 only file-scope `global_asm!` was ordered.
Section statics stayed in their unit modules, and rustc puts each module in a
codegen unit and orders CGU objects arbitrarily. Kernel: `.apicdrivers` (first
probing APIC driver wins), `.init.setup`, `__param`, `.x86_cpu_dev.init`,
`.lsm_info.init` all had entries from several units of one shard.

Reproducer (crates/slate/tests/fixtures.release/link_order_statics): 9 units,
each

```c
__attribute__((used, section("slate_static_set"))) static const struct slate_entry entry_u1 = {1, &entry_u1, value_u1};
__attribute__((constructor)) static void announce_u1(void) { printf("ctor 1\n"); }
```

plus enough code for one CGU per module. Before: constructors ran 6 3 8 1 5 7 2
4 and entries iterated in the same scrambled order; C runs 1..8.

Fix:

- `project::link_order::hoist_section_statics` (called from
  `write_project_crate` after `hoist_global_asm`): for each non-thread-local
  static whose `LinkSection` is used by statics in two or more ungated units,
  the unit gets `pub type __slate_link_order_type_<k> = <ty>;`,
  `pub const __slate_link_order_init_<k>: ... = <init>;` and
  `pub use crate::__slate_link_order_<k> as <name>;` in place of the static; the
  crate root gets `pub static __slate_link_order_<k>` with the original
  attributes. Names in the type and initializer still resolve in unit scope, and
  self-references go through the re-export. Unit struct/union/enum defs become
  `pub` (type privacy at the root use site).
- `rust_ast::Item::Const` and `Item::TypeAlias` gained `vis`.

Kernel check (translated with link-ordered compile_commands, built for
x86_64-unknown-none): arch_x86**packed (224 statics moved) and net**packed (575)
build. Every initcall level, `.init.setup` and `__param` lists units in link
order; `.apicdrivers` is x2apic_phys, x2apic_cluster, apic_physflat (native
vmlinux.a 180-182).

Limits: relies on rustc emitting one module's items in source order within its
CGU (deterministic span sort, not documented). A static and file-scope asm in
the same section from different units can still interleave differently (module
asm is emitted first). Initializers that a const cannot hold (a `&`/`&mut`
reference to a `static mut`) would fail to build; none seen in the two shards.
