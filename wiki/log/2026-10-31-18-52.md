# Keep rewrites from crossing macro invocation boundaries

_2026-10-31 18:52:51_

slate-f2zu.9.5.2: under --merge (named_c_types), lower_statement_list wraps a statement macro's expansion in Stmt::Scope { macro_region: Some(name) } and lower_value wraps its arguments in Expr::MacroArg { index, expr } (frontend/lowerer/macro_regions.rs). Shape-matching rules stop at the wrapper, so ASSERT(a == b, ...) keeps !(a == b) while the same expression outside a macro still becomes a != b; rules still rewrite inside an argument and analyses look through it. Regions hold the macro name rather than an invocation id, because ids differ between merge rows. Skipped: top-level let or temporaries, return, goto, computed goto, asm, labels, case, default, break or continue leaving the expansion. Bodies reading caller locals get their wrappers stripped and rewrite as before. backend/engine/macro_boundaries.rs strips both wrappers after the last rule pass, so codegen and the merge never see them; .9.5.3 must fold before that. Not done: expression-position macros such as PRINT(x); from #define PRINT(x) printf x, and restoring rewrites for regions that fail to fold, which .9.5.3 gets for free only if it strips before the rule passes finish. Fixture: fixtures.merge/macro_boundaries.c. Validated with the slate profile only (33 passed, including merge_filecheck's C/Rust differential and zlib_projection_sample), at the user's request; parser, clang, gcc, msvc and a full zlib regeneration were not run.
