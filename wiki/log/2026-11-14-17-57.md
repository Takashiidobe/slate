# slate-f2zu.14.21 bit_field_accessor: bit-field unit under a packed ancestor (packed struct -> union -> bits) autoref E0793

_2026-11-14 17:57:31_

- bead: slate-f2zu.14.21
- kind: bug
- area: crates/slate/src/frontend/lowerer/places.rs
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/src/frontend/lowerer/statements.rs
- flavor: clang

Outcome: bit-field reads and writes whose storage unit sits under a packed ancestor (packed struct -> plain union/struct -> bit-field unit) copy the unit out with `read_unaligned` and write it back with `write_unaligned`, so rustc no longer rejects the `&self`/`&mut self` accessor calls with E0793.

## Symptom

49 E0793 "reference to field of packed struct/union is unaligned" errors in 5 kernel shards (alt_instr cpuid/flags in arch/x86/kernel/alternative.c, ioam6_trace_hdr type bits in net/ipv6/ioam6.c, irte/msi_msg address bits in drivers/iommu, guc log buffer state in i915). Each site was `(*alt).__slate_anon_2.__slate_anon_0.__slate_bits_0.__get_cpuid()`.

## Reproducer

    struct alt {
        int off;
        union { struct { unsigned cpuid : 16; unsigned flags : 16; }; unsigned ft; };
        unsigned char len;
    } __attribute__((packed));
    p->flags = 5; return p->cpuid;

## Cause

`FunctionLowerer::bit_field_accessor` (frontend/lowerer/places.rs) returns the unit place, and the read (values.rs) and assignment (statements.rs) paths call the generated `__get_*`/`__set_*` methods on it directly. The bit-field methods take `&self`/`&mut self`. A packed record's own bit-field units are byte arrays (align 1), so that was fine; a unit inside a nested non-packed union/struct keeps its u32 storage, and autoref through the packed ancestor is E0793.

## Fix

- `bit_unit_in_packed` walks from the unit's record up through Field places and reports whether a packed record is crossed. It stops at the `erased_copy` place, because the erased-ancestor path already works on an aligned local copy.
- Reads: `std::ptr::read_unaligned(addr_of!(unit)).__get_x()`.
- Writes: `volatile_bit_field_write` became `bit_unit_write(place, value, volatile)`, a read-modify-write of the unit with read/write_volatile or read/write_unaligned.
- `place_in_packed`'s packed-record test is now `packed_record(ty)`.

## Regression test

crates/slate/tests/fixtures/packed_nested_bitfield_unit.c (pointer, array element, static and local receivers; get, set, compound assignment). Kernel TUs alternative.c, bpf/core.c, ioam6.c and drivers/iommu/amd/init.c each cargo check clean when translated alone.

Limits: a volatile bit-field write under a packed ancestor still uses read_volatile on a possibly unaligned address. That compiles, but the access is not aligned.
