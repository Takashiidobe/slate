# slate-f2zu.14.34.26 kernel_link.py shard_object: unreferenced compiler_builtins \_\_rust_probestack bare ret gave 58 objtool naked-return warnings

_2026-11-15 15:38:43_

- bead: slate-f2zu.14.34.26
- kind: bug
- area: tools/corpus/kernel_link.py
- corpus: linux

Outcome: kernel_link.py drops compiler_builtins' unreferenced
`__rust_probestack` section from each shard object, so objtool's 58 "'naked'
return found in MITIGATION_RETHUNK build" warnings (one per shard) go away.

Symptom: objtool on the relinked vmlinux.o reported a bare `ret` in
`__rust_probestack` once per swapped shard.

Cause: compiler_builtins defines `__rust_probestack` on x86_64 whatever the
target's stack-probe setting is (probestack.rs is gated only on
`unmangled-names`, arch and not-windows). x86_64-unknown-none already uses
`stack-probes: inline`, so nothing calls it. The bead's planned fix (stack
probes none) would therefore not remove it, and rustc has no flag for it anyway.
It reached each shard because `shard_object`'s `ld -r` pulls the
compiler_builtins member that holds it for that member's other symbols. In the
shard object it is a local FUNC in its own `.text._RNv...___rust_probestack`
section with zero relocations against it.

Fix: `shard_object` (tools/corpus/kernel_link.py) calls
`unreferenced_probestack`. If the object has exactly one
`.text.*__rust_probestack` section and no relocation names the symbol, it is
removed with `objcopy --remove-section`. If something does call it (a call-probe
target), the section stays and objtool still reports it.

Verified on the init shard: the section and symbol are gone,
`nm -g --defined-only` is identical to the previous shard object, no exported
symbols are missing, and objtool --rethunk ... --link reports 0 naked returns (1
before).

Limits: the full vmlinux relink has not run yet.
