# slate-f2zu.14.28 i686 asm: {N:r} address modifier and in("si")/esi clobber rejected on 32-bit x86; esi now saved/restored like bp

_2026-11-14 20:07:49_

- bead: slate-f2zu.14.28
- kind: bug
- area: crates/slate/src/frontend/lowerer/asm.rs
- target: i686

Outcome: i686 inline asm addresses memory operands and x87 spills with `{N:e}` instead of the x86_64-only `{N:r}`, and explicit `esi` operands/clobbers (which rustc always rejects on 32-bit x86) go through the reserved-register save/restore path used for `bp`.

Symptom (linux check stage, arch_x86_boot_m16 and _packed_m16, 23 errors): `invalid asm template modifier r for this register class` at every "m" operand (cpuflags fninit/fnstsw, pm.c lcallw, video*, a20, cpucheck set_bit), and `cannot use register si: esi is used internally by LLVM` in boot/string.c memcmp (`"+S"(s2)`).

Reproducer:
    unsigned short fsw;
    __asm__ volatile("fnstsw %0" : "+m"(fsw));
    __asm__("addl %%esi, %0" : "+r"(a) : "S"(b));
    __asm__("..." : "+r"(x) : : "esi");

Cause: `memory_reference` and `spill_instruction` (frontend/lowerer/asm.rs) hard-coded `:r` for the address register on every x86 family. `lower_asm` pinned "si" as `in("si")`/`out("si") _` on i686, where rustc reserves esi.

Fix:
- `address_modifier(family)`: `e` on `TargetFamily::X86`, `r` otherwise; used by `memory_reference` and `spill_instruction`.
- Explicit "si" on x86_32 joins the `bp` reserved arm (operand in a `reg` slot, scratch `out(reg) _` saves/restores %esi around the template); "si" clobbers on x86_32 join the bp/sp reserved-clobber path.
- `%V` and "R" auto-picked registers skip "si" on x86_32.

Regression test: crates/slate/tests/fixtures/i686/asm_esi_operand_and_memory_address.c (repe cmpsb with +D/+S/+c, "S" input, esi clobber, "+m" fnstsw/fnstcw, btsl on "+m", "+t" fsqrt spill).

Kernel: retranslated only the two m16 shards from their existing compile_commands.json; cargo check of _packed_m16 is clean, arch_x86_boot_m16 has 2 errors left (memcmp/strlen runtime-symbol signatures, slate-f2zu.14.29, previously masked).

Also fixed two stale i686 fixtures (slate-xw0x.9): static_init_constant_conditional used sizeof(long) == 8 (now sizeof(long long)), msvc/conditional_global_initializers i686 block regenerated for wrapping_offset.

Limits: x86_32 RegPair still offers ["ecx","esi"].
