# i686-pc-windows-msvc target

_2026-09-27 17:40:58_

slate-parser-9k8k. New TargetSpec i686-pc-windows-msvc (clang and msvc flavors): TargetInfo::i686_windows_msvc is windows_msvc(X86) with pointer 4/4, i64/f64 align 8 (i386 linux: 4), stack alignment 4 (clang datalayout S32). Predefines: clang-22.1.8_i686_windows_msvc.h is raw clang -dM minus ISA-generated macros (FXSR/LAHF/MMX/SSE*/pentium4) with i386 moved to slate_gnu_namespace_i386_windows.h (clang drops it under -std=c17); _M_IX86_FP 2 stays static because slate rejects -mno-sse2. msvc flavor uses the existing msvc_19.51.36256_x86_windows.h. Kept clang's raw _MSC_VER 1933 (the x86_64 file says 1940, aarch64 says 1933).
New AbiConvention::X86Win32 (x86_win32), clang's X86_32ABIInfo with IsWin32StructABI. Arguments follow x86_cdecl except: fixed record args with required alignment > 4 are byref, and the first 3 vector args are direct (XMM) with the rest byref. Results: register-sized (1/2/4/8) records whose non-empty fields are all register-sized, and such complex values, are coerce<iN>; everything else is sret with natural alignment.
Required alignment is new: RecordLayout.required_align (not printed) = max of record/field explicit alignment and nested records' required_align, mirroring clang's MS RequiredAlignment. It is why struct { long long x; } (natural align 8) still expands but _Alignas(8) int wrapped in a struct goes byref; a typedef aligned attribute on the record type does not count (clang checks the record layout, not the typedef).
ms_mixed_pointers_32_bit.c moved to sema/i686-pc-windows-msvc/ms_mixed_pointers.c. New fixtures there: layout, clang_predefines(+_strict), predefines, abi_target, sysroot_crt_headers_{clang,msvc}; target_registry.c gained both i686 windows prefixes. All shapes in abi_target.c were diffed against clang -emit-llvm.
Not done: windows.h on i686 needs MSVC __asm {} blocks (winnt.h Int64ShllMod32) -> slate-parser-g097 blocked on 25m.6. Found along the way: x86 cdecl expands char/packed records that clang passes byval (slate-parser-hy3i), and header typedefs used only inside a file-scope _Static_assert are 'unknown typedef' on every target (slate-parser-btxg).
