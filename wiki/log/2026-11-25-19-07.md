# slate-j3by.30 MSVC ARM64 __mulh and __umulh: share the widening multiply helpers

_2026-11-25 19:07:28_

- bead: slate-j3by.30
- kind: bug
- area: crates/slate/src/libc_catalog.rs
- area: crates/slate/vendor/slate-support/src/lib.rs
- flavor: msvc
- target: aarch64

Outcome: Slate lowers ARM64 Windows signed and unsigned high-half multiply through the same helpers as x64.

Symptom: The MSVC differential triage reported `__mulh: builtin without a
lowering` for the ARM64 fixture. ARM64 cl.exe compiled the same fixture with
`/W4 /WX` and emitted `smulh` and `umulh`.

Reproducer:

```c
#include <intrin.h>
__int64 signed_high(__int64 a, __int64 b) {
  return __mulh(a, b);
}
unsigned __int64 unsigned_high(unsigned __int64 a, unsigned __int64 b) {
  return __umulh(a, b);
}
```

Cause: The generated builtin catalog already supplied both signatures.
`MSVC_INTRINSICS` restricted the Rust bindings to x64, and the
`slate_support` helper definitions were inside the x86 machine module.

Fix: Give the two catalog entries both Windows triples and expose the
existing widening multiply functions on x64 and ARM64. The same wrappers
now call `slate_support::__mulh` and `slate_support::__umulh` and link for
`aarch64-pc-windows-msvc`. The ARM64 coverage entries are marked lowered.

Regression test: `crates/slate/tests/fixtures/msvc/aarch64/msvc_high_multiply_intrinsics.c`
compiles with cl.exe, builds the translated Rust, and FileChecks both helper
calls. The ARM64 harness is build-only on this host.
