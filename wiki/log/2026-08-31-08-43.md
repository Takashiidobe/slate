# Implement FreeBSD process, terminal, sysctl, and kqueue ABI

_2026-08-31 08:43:40_

slate-sfzn.10.8: implemented unistd.h/spawn.h/sys/wait.h/poll.h/termios.h/
pwd.h/dlfcn.h/regex.h/glob.h/fnmatch.h FreeBSD overlays, plus two new
FreeBSD-only headers sys/sysctl.h and sys/event.h (kqueue/kevent).
sys/select.h and grp.h needed no overlay - fd_set and struct group are
byte-identical to the shared shim, oracle-confirmed.

Key findings:
- struct termios: totally different flag bit numbering than glibc,
  NCCS=20 not 32, c_ispeed/c_ospeed are plain trailing fields (44B,
  c_cc@16, c_ispeed@36), not accessor-only like glibc.
- struct passwd: 3 extra FreeBSD fields (pw_change/pw_class/pw_expire/
  pw_fields), 80B total, pw_change@24, pw_gecos@40.
- posix_spawnattr_t/posix_spawn_file_actions_t are opaque pointers to
  incomplete structs (8B) - same pattern as pthread types from 10.6.
  POSIX_SPAWN_SETSIGDEF/SETSIGMASK bit values differ from the shim.
- sys/wait.h status macros use FreeBSD's _WSTATUS/_W_INT algorithm, not
  glibc's bit-shift scheme. idtype_t is a 16-member Solaris-ordered enum
  (P_PID=0...P_ALL=7), unrelated to the shim's 4-member enum.
- poll.h: nfds_t is unsigned int on FreeBSD, not unsigned long.
- dlfcn.h: RTLD_DEFAULT=(void*)-2, RTLD_SELF=(void*)-3 (shim used NULL).
- regex_t is a real 4-field struct (32B), REG_NOSUB/REG_NEWLINE bits are
  swapped vs the shim.
- glob_t has FreeBSD-specific callback/pluggable-fs-op fields; GLOB_*
  bits totally different; error codes negative not positive.
- fnmatch.h: FNM_PATHNAME/FNM_NOESCAPE are SWAPPED vs the shared shim
  (0x02/0x01 vs 0x01/0x02) - easy to miss, caught via oracle diff.
- unistd.h _SC_*/_PC_* are a full renumbering vs glibc; covered ~120 of
  ~125 real names, omitted _CS_* entirely (compile error is safer than
  a guessed value).
- sys/sysctl.h/sys/event.h are FreeBSD-only; used an empty-body #if
  (not #error) to avoid tripping the discover_public_headers stub-
  header exclusion, which text-matches literal-first-line #error and
  would have broken the Linux/glibc "compile every header" sweep -
  confirmed by an initial failing nextest run before the fix.

All sizes/offsets verified via _Static_assert sentinel trick against
both oracle sysroots. Added freebsd-process-headers.txt manifest + a
comprehensive header compile test. Full libc (30/30) and lowering
(10/10) nextest profiles pass; fmt/clippy clean.

End-to-end: slate translate + cargo check --target
{x86_64,aarch64}-unknown-freebsd for a posix_spawn/waitpid/termios/
getpwuid/sysctl/kqueue/fnmatch fixture - both clean. Hit and filed (not
fixed) an unrelated pre-existing lowerer bug: char* struct fields lower
to *mut i8 on aarch64 regardless of target, while char* locals correctly
lower to *mut u8 per AAPCS64's unsigned-char default. Filed as
slate-vd43.
