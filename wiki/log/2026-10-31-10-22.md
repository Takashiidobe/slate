# Carry the C type next to the width in the IR

_2026-10-31 10:22:14_

slate-nfq8.11: ir::Type stays the resolved width; Module::c_types (CTypeTable, ir/c_types.rs) adds the C type as a side table, so no Value/Place literal or existing consumer changes. It holds the sema interner and definitions (moved in after lowering), nodes (NodeId to QualType: values, fields, parameters, locals, globals, functions, aliases), bindings (declared types plus hoisted temporaries), and record_fields; place() derives a place's type, since places have no node id. Recorded at Lowerer::operand, finish_expr, apply_conversion, arithmetic_conversion and the declaration sites; Hoister copies entries to the reads and temporaries it creates. An entry always erases to its node's type, so comparisons have none. Dumps print [c="..."] by default, only when the written spelling differs from canonical: u64 plus uLong, never u64 plus uLong plus unsigned long. unsigned long stays in the table because the keyword cannot be recovered from the width (i686 u32 is unsigned int or unsigned long), and typedef names stay because the keyword is not portable (uint64_t is unsigned long on x86_64 linux, unsigned long long on i686 and windows). Regenerated 1915 fixtures, script-checked that only [c=...] suffixes changed; new fixture ir_c_type_table.c. Parser profile 8956/8956. slate translate of sqlite3.c is byte-identical to the previous build, 12.09s to 12.00s, peak 864 MiB both. The IR dump of sqlite3.c is 10.6% slower from rendering the spellings. Slate does not read the table yet; slate-nfq8.12 does. --dump-ir-types leaves it empty.
