# Scope-correct tag identity and forward declarations

_2026-09-19 21:04:20_

Phase 4 of slate-parser-8lv. Closes rsm and 9wx.

rsm turned out to be stale. Its guard in module.rs::declaration rejected every
block-scoped tag definition on the grounds that two functions each defining
'struct Local' would collapse onto one TypeId. They do not: Lowerer::scoped
already drives push_scope/pop_scope for function bodies, blocks, ifs and loops,
tag_ids is keyed by the AST TagId, and define_tag only looks for a previous tag
in the current scope. Removing the guard gives one() '@type0 Local {a: i32}'
and two() '@type1 Local {b: i64}', and produced no fixture churn at all.

9wx was real and had two halves. names.rs treated 'struct S;' as a tag
*reference*, so a declaration with no declarators failed with the spurious
'unresolved tag name S' before lowering ever ran. It is now a tag declaration.
Underneath, TypeResolver::declare_incomplete_tag creates the incomplete TypeId
in the current scope rather than looking outward, which is what C11 6.7.2.3p8
requires: a bare 'struct S;' hides an outer tag of that name instead of
referring to it. Verified against clang and gcc, which both reject sizeof of
the hidden-then-incomplete type.

Only two fixtures changed, both error fixtures, and both improved: a spurious
'unresolved tag name' became the genuine constraint violation. clang rejects
the same programs.

Filed slate-parser-30r: that genuine error reads 'incomplete field type' when
no field is involved. Pre-existing at file scope, not introduced here.
