# atomic.c fixture: fix test signatures, upstream-blocked on atomic inc/dec

_2026-09-03 14:34:56_

slate-6v25.3 triage: tests/fixtures.chibicc/unsupported/atomic/atomic.c had two
non-slate bugs, both fixed in the fixture:

1. Thread functions (add1/add2/add3) were declared `int (void *)`; the
   libc-shim's pthread_create (libc-shim/include/pthread.h:85) correctly
   requires `void *(*)(void *)` per POSIX/glibc/musl. chibicc is lax here and
   accepts the mismatch; real libcs don't. Changed to return `void *`.
2. `atomic_exchange(&x, 5)` was called on a plain `int`; C11 requires the
   pointee to be `_Atomic`. Changed `x` to `_Atomic int`.

Both were test-authoring bugs, not shim or slate bugs -- no shim/slate change
needed.

After the fix, translate-project still fails, but on a different, genuine
issue: `(*x)++` / `x--` on `_Atomic int` crashes clang -emit-cir with
"ClangIR code gen Not Yet Implemented: Atomic inc/dec"
(CIRGenExprScalar.cpp ScalarExprEmitter::emitCompoundAssignLValue). This is
an upstream ClangIR gap, same class as slate-6v25.2/slate-pcek.21. No
slate-side fix possible; bead marked blocked, promote via git mv once
upstream lands atomic inc/dec CIR emission.
