# Make lowered names independent of unrelated code

_2026-10-30 19:44:49_

slate-mbr2.1.3: generated names no longer use TU-wide ids. Temps, slots, VLA storage, break and continue labels, cleanup and OpenMP names use a per-function index (FunctionLowerer::local_index). Extern parameters are positional (arg0, arg1), so glibc __fd and musl unnamed parameters match. Anonymous records are __SlateRecord_<file>_<line>; duplicate record tags and internal statics are <name>__<line>, since a feature cannot move source lines. Static compound literals and asm strings include the owning item's name. Shadowing locals are <name>__<n>. Link hoisting keeps the record's name instead of renumbering.
Measured on zlib with a brace-depth item split, 360 items: glibc vs musl went from 30 changed items to 2 (gz_open, real O_* flag values); no-gzip 33 to 21; lit-mem 34 to 22; fastest 23 to 19. Sampled diffs for no-gzip, lit-mem, musl and aarch64 show real differences. aarch64 still changes 263 items, led by char signedness, which is slate-mbr2.1.8. Limit: a numbered temp still shifts within a function that really changes, so statement-level merging (slate-nfq8.3) needs more. _unnamed_cfstring_<id> in sema still uses a TU-wide id.
Tests: tests/fixtures.lowered-names with lowered_names_filecheck; update_filecheck.py regenerates them. All FileCheck blocks were regenerated in one batch. The full slate profile was not rerun after regeneration, at the user's direction.
