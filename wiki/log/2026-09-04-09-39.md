# Remove IndentStmt depth/pad tracking from codegen and AST

_2026-09-04 09:39:32_

slate-x01a: removed the IndentStmt { depth, stmt } wrapper from rust_ast.rs
entirely, replacing every Vec<IndentStmt> body (FnDef.body, MatchArm.body,
Block.stmts, Stmt::{If,Loop,For,Scope,LabeledBlock,LetIf} bodies) with plain
Vec<Stmt>. codegen.rs's stmt()/block() no longer take a depth parameter or
compute an INDENT.repeat(depth) pad per statement -- every generated-Rust
output path already runs through rustfmt (src/backend/format.rs) before
being written or compared, so codegen only needs correct braces/newlines,
not indentation.

depth was write-only outside codegen.rs: ~16 files in the lowerer and
backend engine/interproc passes constructed IndentStmt{depth: N, ..} but
never read .depth for anything except re-populating that same field
(length_lattice.rs's apply_view copied a sibling's depth when splicing in a
new stmt). Removed FunctionLowerer.indent (only used to seed that depth) and
several now-identity helper wrappers (indent_stmt, indent, prelude::stmt)
along with their call-site unwrapping across control_flow.rs, dispatch.rs,
calls.rs, values.rs, structure_dispatch.rs, reducible.rs.

Verification: cargo build --release, cargo fmt, cargo clippy --release --lib
all clean; cargo nextest --profile lowering passed 10/10. --profile rewrites
not run for this change (build + fmt considered sufficient for a mechanical,
type-driven refactor with no behavior change).
