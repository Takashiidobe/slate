# slate-f2zu.14.23 Compare lowering: function designator == NULL emitted `Some(f) == None` on a fn item (E0369)

_2026-11-14 18:55:44_

- bead: slate-f2zu.14.23
- kind: bug
- flavor: clang
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/src/frontend/lowerer/pointers.rs

Outcome: comparing a function designator with NULL (`fn == NULL`, `NULL == fn`,
also through a macro argument) lowers to a typed `Option<fn ptr>` comparison
instead of failing E0369.

Symptom: linux i915_request.rs, i915_sw_fence_work.rs, intel_context.rs:
`if Some(submit_notify) == None` binary operation `==` cannot be applied to
`Option<fn item>` (BUILD_BUG_ON((fn) == NULL) in i915_sw_fence_init, 7 errors).

Reproducer:

```c
static int notify(void *fence, unsigned state) { return (int)state; }
#define fence_init(fn) BUILD_CHECK((fn) == NULL)
fence_init(notify);
printf("%d %d\n", notify == NULL, NULL == notify);
```

Cause: `ValueKind::Compare` lowering pinned a function designator to its fn
pointer type (`let __slate_function: T = ...`) only when both sides were
`FunctionDecay`. With a null side, `Some(notify) == None` infers
`Option<fn item>`, which has no PartialEq.

Fix: pin either side that is a `FunctionDecay` (looking through `MacroArg`) when
the other side is a decay or `Null`. The pin is `lower_typed_function_address`
in lowerer/pointers.rs, which only wraps a lowered `Some(fn item)` or a macro
hole. Weak externs are already typed `Option` statics and stay unwrapped
(weak_undefined_function unchanged).
