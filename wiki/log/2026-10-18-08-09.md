# Lower i128 and generic atomics, used/atomic globals, f80 static conversion folds

_2026-10-18 08:09:52_

slate-9ox1.5 (gcc-dg atomics and global attributes) closed; all nine fixtures promoted.

- support/atomic128.rs -> support/libatomic.rs (module **slate*libatomic, dependency flag libatomic).
  Adds AtomicI128/AtomicU128 and AtomicGeneric<T> mirroring the std atomic API
  (from_ptr, load, store, swap, fetch*\*, fetch_update, compare_exchange{,\_weak}).
  i128 ops are CAS loops over **atomic*compare_exchange_16; generic types use libatomic's
  size-generic \_\_atomic*{load,store,exchange,compare_exchange}. Everything goes through
  libatomic so one object never mixes inline and locked paths. Linux only, as before.
- atomic_target falls back to AtomicGeneric (repr Value) for types with no std wrapper:
  f80, complex, records. AtomicTarget.wrapper now holds the full path.
- Volatile atomic f32/f64 loads/stores use from_ptr_raw + load/store_volatile on the bits.
- Globals: [used] lowers to #[used]; atomic statics are allowed when the type is not padded
  by \_Atomic (scalars, floats, complex). Atomic records stay a barrier because clang pads them.
- f80 static initializers: fold_long_double folds int_to_float (via a small fold_integer)
  and float_widen from f32/f64 constants; fold_complex_long_double folds complex_convert of a
  constant aggregate. The literal fold applies only inside static initializers; Arith folds
  in bodies can now see through int_to_float (long_double.c FileCheck updated: 7/2.0L -> 3.5).
- Complex ==/!= in static initializers (non-f80) lowers componentwise, so it stays const.
- New fixtures: x86_64/long_double_static_convert_init.c, complex_static_compare_init.c.
- Also promoted gcc-torture 960215-1, align-2, ieee\_\_copysign1/2, regstack-1.
- Renamed bitint WideInt::from_bytes -> bytes_literal (clippy wrong_self_convention).
  Validation: slate and slate-targets profiles green.
