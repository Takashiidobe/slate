# slate-5q63.25.2 ValueKind sensitive: counted_loops and x87_constant missed MacroArg/MacroExpansion, macro-bounded loops uncounted and i686 gcc x87 fold skipped

_2026-11-20 15:17:20_

- bead: slate-5q63.25.2
- kind: bug
- area: crates/slate-parser/src/ir
- area: crates/slate-parser/src/sema/counted_loops.rs
- area: crates/slate-parser/src/sema/numeric.rs
- area: crates/slate-parser/src/sema/effects.rs
- area: crates/slate/src/frontend/lowerer/places.rs
- flavor: gcc
- target: i686

Outcome: `ir::ValueKind` is `#[slate::sensitive]`; its audit found that sema analyses did not look through macro structure, which slate's frontend builds in every mode, so loops with a macro bound were not counted and i686 GCC x87 folding skipped macro-wrapped literals (wrong value).

Symptom 1 (counted loops): with macro structure on, `for (i = 0; i < N; i++)`, `i < TWICE(n)`, `BELOW(i, n)` and `i <= TWICE(4)` lost `counted:` and lowered to `while` loops.

Symptom 2 (x87 fold, i686 gcc): `ADD(1.0, 0x1.002p-53)` was not folded, so it ran through x87 and rounded twice to `0x1p+0`; GCC folds it to `0x1.0000000000001p+0` (checked with `gcc -m32`).

Reproducer:

```c
#define ADD(a, b) ((a) + (b))
double f(void) { double r = ADD(1.0, 0x1.002p-53); return r; }
```

Cause: `ValueKind::MacroArg` / `MacroExpansion` wrap values whenever `Sema::with_macro_structure(true)`, which `crates/slate/src/frontend.rs` `lower_parsed` sets for every translation (the wiki claimed only `--merge`). `counted_loops::{recognize, reads, invariant, integer_constant}` and `numeric::x87_constant` matched value shape without unwrapping. `effects::{is_constant, is_null_constant}` and slate's `places::is_null_constant` unwrapped `MacroArg` but not `MacroExpansion` (extra temporary, missed null-compare branch fold).

Fix: `Value::without_macro_structure()` (ir/mod.rs) unwraps `MacroArg` and statement-free `MacroExpansion`, the one audited list of wrappers; the sites above use it. `counted_loops::below_max` uses `fold::integer` so a folded `<=` bound counts. Reasoned expects on the resolved arms.

Regression tests: crates/slate-parser/tests/fixtures/clang/linux/x86_64/macro_counted_loops.c, crates/slate-parser/tests/fixtures/gcc/linux/i686/macro_x87_fold.c. slate fixtures x86_64/vector_reduce_builtins.c and vector_shuffle_convert.c regenerated: macro-bounded loops became `for i in 0..$n`.

Limits: 41 `ValueKind` hits remain untriaged (fold.rs, sequencing.rs, object_size.rs, asm*.rs, and slate lowerer atomics/complex/f80/float_fold/globals/intrinsics/pointers/stdio/values/macro_keep). Likely bug still open: `lowerer::intrinsics::constant_argument` does not unwrap macro structure, so an immediate passed through a kept macro would fail with "non-constant immediate".

See: slate-8ge7 (IR analysis crate), slate-8ge7.2 (macro-free value tree; this bug class), slate-8ge7.2.1 (strip-equals-plain invariant).
