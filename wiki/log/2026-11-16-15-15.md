# slate-f2zu.14.40 linux netif_change_flags: lo got no 127.0.0.1/::1 because zero_init::fold hoisted __dev_change_flags above the old_flags load

_2026-11-16 15:15:40_

- bead: slate-f2zu.14.40
- kind: bug
- area: crates/slate/src/backend/engine/rules/zero_init.rs
- area: crates/slate/tests/fixtures

Outcome: the translated linux kernel auto-assigns 127.0.0.1/8 and ::1/128 to lo on `ip link set lo up`, matching native; a fixture now pins the load-before-call order in zero_init::fold.

Symptom: under ./run-qemu.py, lo came up with no addresses and `ping 127.0.0.1` failed with "Network unreachable". Native got both addresses on link up.

Diagnosis: gdb hbreaks on inetdev_event/addrconf_notify showed only NETDEV_PRE_UP (14), never NETDEV_UP (1). A break on __dev_notify_flags showed old_flags=0x9 (already IFF_UP), equal to dev->flags, so `changes & IFF_UP` was 0.

Reproducer (net/core/dev.c netif_change_flags):

    int ret;
    unsigned int changes, old_flags = dev->flags, old_gflags = dev->gflags;
    ret = __dev_change_flags(dev, flags, extack);

Cause: shards/net_core was translated before 76bdf7605 (slate-f2zu.14.40.10). zero_init::fold (intervening_ok) let the impure first write cross the old_flags/old_gflags lets:

    let ret: i32 = __dev_change_flags(dev, flags, extack);
    let old_flags: u32 = unsafe { (*dev).flags };

This is the same root cause as the ps2_sendbyte guard reorder. HEAD already blocks crossing any let whose init is not zero or pure-and-closed, and a load through dev is not closed.

Fix: none needed in slate. Retranslated net_core (`e2e.py linux --from translate --shards net_core --until link`). Rebooting showed lo addresses and a working ping.

Regression test: crates/slate/tests/fixtures/zero_init_load_before_call_order.c. The 14.40.10 fixture covers only a guard-constructor call; this one covers a plain field load that the call then writes.

Limits: other shards translated before 76bdf7605 may carry the same reorder. A full linux retranslation at HEAD would clear them.

See: slate-f2zu.14.40.10, slate-gbgp.9 (comment added: a read-only let that loads through a pointer must still block an impure write).
