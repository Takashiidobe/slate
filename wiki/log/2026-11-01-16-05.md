# Lower alignof and offsetof to Rust layout queries

_2026-11-01 16:05:49_

slate-f2zu.9.5.12.24, .25: alignof and offsetof now stay semantic in all output, like sizeof. IR: LayoutQuery gains AlignOf { ty, c }, printed align_of<size_t, T>(N), and OffsetOf { ty, c, members }, printed offset_of<size_t, T, a.b>(N). Sema (layout_query in sema/expression.rs, replacing size_query) emits AlignOf unless the operand is _Atomic, a declared alignment applies to the type, object or member, the operand is a function, or the GNU preferred alignment exceeds the ABI one (__alignof__(long long) on i686). It emits OffsetOf unless the type is _Atomic or the path has an array index, constant or runtime; those keep the const with offset_of metadata. Lowering: lower_layout_query (lowerer/types.rs) prints std::mem::align_of::<T>() when rust_layout_matches_c holds and storage_of's alignment equals the amount, and std::mem::offset_of!(T, a.b) when that gate holds and offset_of_fields finds each member directly, not a bit-field or erased (MaybeUninit) field, with layout offsets summing to the amount. Anonymous members therefore fall back to the number. Unions are kept: offset_of! accepts union fields and nested paths on the pinned nightly without a feature, contrary to the bead's expected fallback. Macro templates visit the query type for all three variants. Fixtures: alignof_fallback.c, offsetof_fallback.c; 140 parser and 20 slate fixtures regenerated, query text only plus records now emitted because a query names them. Not run: zlib merge and template remeasure. parser, slate and slate-targets profiles pass.
