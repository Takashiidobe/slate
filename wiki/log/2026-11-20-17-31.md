Outcome: slate no longer runs rustfmt. `backend::codegen` prints formatted Rust itself through the Oppen printer vendored from prettyplease (`backend/printer/`), with comments as ordinary tokens.

Gap and why it mattered: after slate-5q63.26, rustfmt was 27.5% of sqlite translate-project CPU (`CharClasses::next` alone 20%). On sqlite3.rs (6 MB) rustfmt took 2.5-3.0 s; syn + prettyplease took 0.53 s but drops comments, so it was only used for comment-free single-file output. rustfmt was a stand-in for laying out comments.

Before: Codegen wrote unindented text with hard `\n`; `format_rust` piped every output file through `rustfmt --edition 2024` (`SLATE_RUSTFMT`, `SLATE_NO_FORMAT`), and `restore_macro_lists` rewrote `__slate_macro_list_x` holes afterwards. `pretty_rust` re-parsed with syn when the text had no comments.

After: Codegen emits words, breaks and boxes into `printer::Printer` (margin 89, indent 4, as prettyplease). Layout follows prettyplease's rules ported to our `rust_ast`: blocks are `cbox(INDENT)` with hard breaks; calls, struct literals, arrays, binary and cast chains, method chains, fn signatures and `if` expressions break as prettyplease does. Literal-only arrays fill lines. Trailing `// c` comments print after the statement, including after a block's `}`. Macro holes print directly: `$($x,)*` before a comma, `$($x),*` last in a macro call.

Implementation:
- `backend/printer/{mod,ring}.rs`: prettyplease 0.3 `algorithm.rs`, `ring.rs`, `convenience.rs` (MIT OR Apache-2.0, `NOTICE` and licenses alongside); margin is a parameter.
- `codegen.rs`: `Codegen` is no longer generic over `fmt::Write`; `program_to_string`/`item_to_string` use margin 89; `expr_to_string`/`stmt_to_string`/`type_to_string`/`cfg_to_string` use a 0x8000 margin so keys and diagnostics stay on one line (blocks still break).
- Macro invocations (`Expr::Macro`, `Item::Macro`, `vec!`) never get a trailing comma: generated `macro_rules!` matchers reject one.
- `format.rs` keeps only `write_if_changed`; `api::Error::Format` removed; `BuildScript::render` is infallible; `prettyplease` and `syn` dropped from `crates/slate`.
- `tools/corpus/e2e.py` no longer sets `SLATE_NO_FORMAT` (translate time now includes printing; `format_crate` still runs rustfmt as a check).

Measured (sqlite translate-project, single target): wall ~8.1 s with rustfmt -> 6.6-6.9 s; 5.6 s was the no-format floor. The output crate passes `cargo check`.

Fixture: every FileCheck block regenerated (layout churn accepted by the user); slate profile 43/43, merge 1/1. rustfmt also sorted `use` runs; codegen keeps emission order (follow-up slate-5q63.28).

Limits: types never break (long fn-pointer types overrun the margin); match-expression arms do not get prettyplease's brace wrapping; output style differs from rustfmt (run rustfmt for its style).
