# Unify asm operands with Rust-facing direction and fold ties

_2026-09-26 22:36:55_

Closed slate-parser-25m.12. `ir::InlineAsm` outputs/inputs became one `operands: Vec<AsmOperand>` in GCC order. `AsmOperandKind` is `In(Value)`, `Out { place, early_clobber }`, `InOut { place, input: Option<Value>, early_clobber }`; `direction()` gives in/out/lateout/inout/inlateout. Chose an enum over a direction field + two Options so the in/out payload cannot disagree with the direction.

Mapping (inverted from the naive reading): "=r" lateout, "=&r" out, "+r" inlateout, "+&r" inout. =/+ is read from the first alternative (clang checks Name[0]); & in any alternative makes it early-clobber, which is always safe to over-claim. IR constraints drop = + &; % and - stay.

Tie fold: an input matching output n in EVERY alternative ("0", "0,0", "[out]") becomes InOut { input: Some } on output n and is removed; template Operand indices are renumbered. Partial ties ("0,m") stay In for .15.

Verified with clang 22 / gcc 16 and added parser errors (clang wording) for shapes both reject and the fold depends on: output without =/+, =/+/& on an input, match past the outputs or to a + output, two inputs tied to one output. Flavor split: clang also rejects an input matching two different outputs, and counts any-alternative matches as ties ("0,m" + "m,0" is an error); gcc accepts both, so under gcc only full ties count. Fixture asm-partial-ties-gcc.c covers the gcc side.

Known deviation, filed slate-parser-25m.20: effects hoist places first then inputs in operand order, so a tied input's side effects move ahead of untied inputs written before it.

Fixture note: asm-statement.c and sema/ir_asm.c had an input spelled "+%-rm,0", invalid in both compilers; now "%-rm,r". The - (Pic) modifier inside a function is still rejected by both compilers but accepted by us (pre-existing, permissive).
