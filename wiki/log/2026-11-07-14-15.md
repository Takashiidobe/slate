# Type void-param slice views by their byte element, not ()

_2026-11-07 14:15:12_

slate-yar4.28: PuTTY crypto/arcfour.c arcfour_block(void *handle, void *vblk, int len) with blk = (unsigned char *)vblk; blk[k] ^= ... got the length-lattice view std::slice::from_raw_parts_mut(vblk as *mut (), len) and E0308/E0605 (() as i32) at the ^= site.
apply_view (interproc/length_lattice.rs) only replaced a void element type when it was Type::CLib(VOID); void pointees lower as Type::Unit here, so the view kept (). Both now fall back to the matched offset temp's type (u8 default).
Reproduced on linux as well, not msvc-specific. Fixture: tests/fixtures/void_param_byte_view.c (xor_block plus the arcfour_block shape; failed with E0308/E0605 before). slate profile 36/36. PuTTY arcfour.c alone now emits vblk as *mut u8.
