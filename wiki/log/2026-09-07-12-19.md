# ARM32 double _Complex arithmetic segfault is a rustc ABI bug, not slate (slate-3f8g.4.16.13)

_2026-09-07 12:19:21_

tests/fixtures/complex.c and stdlib_complex_cx_limited_range.c segfault under
qemu-arm-static on armv7-unknown-linux-gnueabihf. Root-caused to a rustc/LLVM
codegen gap, not a slate lowering bug.

Slate lowers double _Complex mul/div to extern "C" calls into libgcc's
__muldc3/__divdc3, returning a #[repr(C)] struct { re: f64, im: f64 }
(num_complex::Complex<f64>). Confirmed via a minimal hand-written Rust
program (zero slate involvement) that declares the same extern "C" signature
and calls __muldc3 directly: it segfaults identically. The equivalent C call
to the same libgcc symbol, same toolchain, same qemu-arm-static, returns the
correct value (-5.0, 10.0) with exit 0.

Root cause: armv7 hard-float AAPCS-VFP has a specific calling convention for
C's native '_Complex double' return type; rustc's generic small-aggregate
struct-return classification for a 2xf64 repr(C) struct does not match it on
this target. This is an upstream Rust ABI limitation for armv7, not fixable
in slate's lowerer.

Kept skip-listed in tests/differential_arm.rs with an updated reason
(environment limitation, not a slate bug). Bead closed as documented/blocked
per its acceptance criteria's alternate branch.
