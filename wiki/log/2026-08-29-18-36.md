# return-position Box<[T]> buffer lift (slate-y0qs.4.8.4)

_2026-08-29 18:36:08_

Adds owned return-buffer lifting to interproc/length_lattice.rs
(apply_return_buffers phase, single-shot, structural — no facts, no fixpoint).

A private fn whose ret type is *mut T and whose returned pointer traces to
malloc(COUNT*sizeof(T)) (COUNT a param or literal) is lifted to -> Box<[T]>:

- callee: ret type becomes Box<[T]>; each `return X` wraps to
  `unsafe { Box::from_raw(std::slice::from_raw_parts_mut(X as *mut T, COUNT as usize)) }`.
- call sites: `f(..)` -> `Box::into_raw(f(..)).cast::<T>()`, a uniform \*mut T
  drop-in, so NO caller gate / binding retype / free-removal is needed. The
  caller keeps its raw pointer + manual free; the Box round-trips through
  into_raw so free() reclaims the original malloc'd block (never dropped twice).

Scaling (the parent epic's concern): purely single-shot + local + no cascade.
Candidate detection is O(body) per pointer-returning fn; call-site threading is
one linear walk. Transitive/wrapper returns (indirect(){return alloc();}) are
NOT re-lifted in-pass -- their inner alloc() call is just threaded -- so a
lifted return only touches direct call expressions, never rippling the graph.

Fail-closed rejections (all verified by fixtures): nullable return (any
`return NULL` path -> Box is non-null), internal free (body_calls_free),
non-malloc/forwarded returns, and -- critically -- any var in the return's
resolution chain assigned more than once (value_defs is flow-insensitive, so a
multiply-assigned \_\_retval could otherwise resolve a NULL path to the later
malloc write). resolve_to_malloc now rejects multiply-assigned chain vars.

Fixtures: buffer_return_box.c (make param-count, make8 literal-count lift;
maybe nullable + allocfree internal-free stay raw). The 4
interprocedural_alloc_promotion* fixtures now lift alloc()->Box<[i32]> (was the
old *mut i32 baseline); regenerated full-program blocks.

Tooling note: tried region (@rewrite/@lowering) directives for these but they
CANNOT wrap a return-position observable (the @-end lands after `return`, is
dead code, and CIR drops it -> region never closes) NOR a whole function (Slate
hoists all top-level global_asm! markers above every fn, so file-scope markers
don't bracket the body). Full-program blocks are the right tool for
return-centric fixtures; region directives stay for normal-statement observables.

Full rewrites 110/110; lowering differential green.
