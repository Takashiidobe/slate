# parser.rs error-handling ergonomics: Loc + Cursor trait

_2026-09-12 08:45:30_

Added Loc (bundles code/offset/length, replacing error_at's 3 loose params)
and a Cursor trait (tokens/pos/set_pos + default peek/consume) shared by
Fragment (new: wraps a Parser + code fragment + token cursor for
parse_one_stmt/parse_body/parse_simple_keyword_stmt/try_parse_nested_function/
parse_function's `Loc`-based error construction) and DeclaratorParser.

DeclaratorParser's errors moved from bare String to a new structured
DeclaratorError enum (mirroring const_expr::ConstExprError's style), with one
ExpectedToken(Token, &'static str) variant covering the common "expected X
after/in Y" shape instead of ~10 near-duplicate variants. DeclaratorError
implements From<String> so `?` still composes with the free-standing
parse_attribute_groups family, which stays String (shared with non-declarator
callers, out of scope).

parse_one_stmt/parse_declarator/parse_function/parse_tag_definition now use
Loc/Cursor/expect instead of hand-built error_at(code, 0, code.len(), ...)
calls at ~60 call sites in src/parser.rs. Scope was deliberately limited to
slate-parser-1uq.1 (ergonomics only); const_expr::Parser was left alone since
it already returns a structured ConstExprError and wasn't part of this
issue's acceptance criteria.

cargo nextest and cargo clippy both pass.
