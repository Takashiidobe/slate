# Follow glibc32 default off_t in slate_support

_2026-11-06 22:15:08_

slate-yar4.20: i686 zlib bound lseek to the file64 libc binding (off_t i64) while C's default off_t is 32-bit, so cargo check failed with E0308. slate_support now declares off_t and the off_t-taking functions (lseek, pread, pwrite, preadv, pwritev, mmap, truncate, ftruncate, fseeko, ftello, lockf, posix_fadvise, posix_fallocate, fallocate, readahead, sendfile, sync_file_range) against the plain 32-bit glibc symbols on 32-bit linux-gnu. slate-libc-gen probes glibc32 with the default C ABI (no _FILE_OFFSET_BITS/_TIME_BITS), maps those functions to slate_support (providers.rs), and drops time_t-dependent bindings from the i686/armv7 catalogs; both tables regenerated. Lowerer: the off_t named type uses slate_support::off_t only when the C width matches (types.rs named_prim_item); -D_FILE_OFFSET_BITS=64 units get a local i64 alias and lseek64 local externs. Fixture: fixtures/i686/off_t_lseek.c. abi_defaults.rs no longer asserts slate_support::off_t is 8 bytes (FileCheck covers i64). Regenerated FileChecks for stale i686/aarch64 fixtures. Not re-translated: slate-zlib. Pre-existing failure: armv7 msvc/windows_sys.c (windows.h not found). Follow-up: slate-yar4.21 selects 64-bit bindings from _FILE_OFFSET_BITS.
