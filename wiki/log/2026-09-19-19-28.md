# Redeclaration merging moves onto C types

_2026-09-19 19:28:58_

slate-parser-9ve.4. declare_global and declare_function now merge on C types
via TypeResolver::merge_redeclaration: compatible declarations merge into their
composite (which is what completes int a[]; int a[5]; -- the special case for it
is gone), otherwise the conflict table decides. Deleted
function_redeclaration_conflict, same_layout_ignoring_sign and types::compatible
over ir::Type, the last of which was 9ve.3's deferred item.
__builtin_types_compatible_p now calls CTypes::compatible, so it and
redeclaration merging cannot drift apart.

Two things the plan did not anticipate.

The layout predicate had to survive. Plain ir_type equality makes
int y; unsigned y; an error, but all three compilers warn. So same_layout moved
into types.rs, ignoring integer signedness, documented as a layout question
rather than a type-identity one. The oracle showed this is MSVC's own rule and
not a convenience: C4142 "benign redefinition" fires exactly when the layouts
coincide (int/long, int/unsigned under LLP64), C2371 "different basic types"
when they do not (int/long long, distinct structs). That is what closes y47.

Functions are not flat. MSVC warns on any prototyped parameter-list difference
(C4028/C4030/C4031/C4052) whatever the layout, but applies the layout rule to
return types, so conflict_message splits the two. A single rule turned the
PARAMETERS fixture from a warning into an error.

The ordering trap is worth carrying into 8lv: both declare_* functions return
early when no entry exists, so the declared type must be registered ABOVE that
return. Registering it below made int x; long x; silently lower as i64 -- a
regression no fixture caught, since none covered that pair on LP64.

Regenerating every fixture changed none of them; the msvc-target y47 fixture is
the only addition.
