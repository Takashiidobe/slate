# slate-f2zu.14.8 lower_place: aligned automatic compound literal (EFI_GUID) and bit-field below a packed record's erased union field (msi_msg arch_data) were place barriers

_2026-11-14 13:30:34_

- bead: slate-f2zu.14.8
- kind: bug
- area: crates/slate/src/frontend/lowerer/places.rs
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/src/frontend/lowerer/statements.rs
- flavor: clang

Outcome: an over-aligned automatic compound literal lowers into an
`__SlateAlignN` wrapper, and reads/writes of a path below an erased
(`MaybeUninit`) field of a packed record go through an unaligned copy.

Symptom: 39 kernel functions in 21 TUs hit place barriers:

- `place compound_literal %N [storage=automatic] [align=4]` from `EFI_GUID(...)`
  (include/linux/efi.h:77): `efi_guid_t` is
  `typedef guid_t efi_guid_t __aligned(__alignof__(u32))` over a `u8[16]`
  struct, so the literal carries `align=4` above its natural 1.
- `place field0(field1(field1(deref(...msi_msg))))` for
  `msg->arch_data.vector = ...` (apic.c:2302, irq_remapping.c:1343,
  io_apic.c:1764): `struct x86_msi_data` is `__packed` around an anonymous union
  whose bit-field struct is `repr(align(4))`, so the record lowering erases that
  union field to `MaybeUninit<[u8; 4]>` and `lower_place` rejects any field
  below it.

Reproducer:

```c
typedef struct { unsigned char b[16]; } guid_t;
typedef guid_t efi_guid_t __attribute__((aligned(4)));
#define G(a) ((efi_guid_t){{a}})
typedef struct { union { struct { unsigned v : 8, m : 3; }; unsigned s; }; } __attribute__((packed)) data_t;
void set(data_t *d) { d->v = 0x31; }
```

Cause: `lower_place` only matched
`PlaceKind::CompoundLiteral { alignment: None, .. }`; erased fields were handled
only as the leaf of a read, write, or address (`erased_field_address`).

Fix:

- `lower_place` computes `over_alignment(ty, alignment)` for a compound literal
  (barrier only when the type has no storage). `lower_compound_literal` takes
  the wrapper: the hoisted local or static is `__SlateAlignN<T>` and every use
  goes through `.0`; an alignment at or below natural is dropped.
- `erased_ancestor` finds an erased field in a place's Field/Lane/ComplexPart
  chain. A read lowers as
  `let t = addr(erased).read_unaligned(); <read of the rest against t>`; an
  assignment binds the value, reads the copy, assigns into it, then
  `write_unaligned`s it back (the `lower_lane_write` shape).
  `FunctionLowerer::erased_copy` maps the erased place (by pointer identity) to
  the copy while the rest of the path is lowered; `with_erased_copy` scopes it.

Regression test:
crates/slate/tests/fixtures/packed_union_bitfield_and_aligned_literal.c
(EFI_GUID literals, msi_msg bit-field set/get through the packed union, and a
packed record at offset 1).

Limits: taking the address of a sub-place below an erased field
(`&msg->arch_data.subhandle`) is still a barrier, and only one erased level per
access is copied (a second erased field below the first stays a barrier). Array
subscripts in the chain are not walked.
