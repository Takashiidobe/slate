# Interproc passes operate over &mut [Program] with unit-qualified keys

_2026-10-18 19:03:33_

slate-o3gw.13 (rescoped): measured interproc on the sqlite amalgamation at 36ms (string_params) + 321ms (pointer/length lattice) of a 9.3s translate-project, so the planned summarize/solve/apply split for per-unit parallelism was dropped. .14 will run interproc once, sequentially, across all units between parallel lowering and parallel per-function rules.

Change: interproc/mod.rs adds FnKey {unit, name}, Symbols (resolve(unit, name), same-unit only for now; .14 extends it with cross-unit links) and fn_defs(&[Program]). CallGraph/scc_order/run_worklist key by FnKey. string_params::run, pointer_lattice::{solve, apply} and length_lattice::{compute, apply} take &[Program]/&mut [Program]; PointerBinding.function is FnKey; every callee lookup goes through Symbols::resolve; per-unit tables (global ptr mutability, field mutability, global arrays) are indexed by unit. Helpers that match a callee name inside a caller body keep comparing the written name. engine::apply passes std::slice::from_mut(program).

Validation: snapshot script translated every .c under fixtures, unsupported, c-testsuite, gcc-torture(+gcc-only), gcc-dg, chibicc (2752) plus fixtures.release/library/multi projects and the sqlite amalgamation (50) with the old and new binary: 4179 .rs files byte-identical (baseline run twice to confirm determinism). No nextest rerun: output unchanged.
