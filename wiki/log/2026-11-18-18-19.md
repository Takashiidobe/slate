# slate-yar4.26 c_shim render_variadic_export: C23 long double f(...) with no fixed parameters

_2026-11-18 18:19:53_

- bead: slate-yar4.26
- kind: bug
- area: crates/slate/src/frontend/c_shim.rs
- area: crates/slate/src/backend/c_emit.rs
- area: crates/slate/src/frontend/lowerer/f80.rs

Outcome: a C23 `long double f(...)` definition with no fixed parameters now translates and runs; the native entry uses va_start(ap).

Symptom: translate failed with "cannot lower long-double to Rust" (detail: export of <entry> with no fixed parameters).

Reproducer:
```c
long double first(...) { va_list ap; va_start(ap); long double v = va_arg(ap, long double); va_end(ap); return v; }
```

Cause: long_double_entry_export_name (lowerer/f80.rs) rejected a __slate_ldv__ export with no fixed params; c_shim::render_variadic_export needed the last fixed tag for va_start; the C emitter printed `(, ...)` for a variadic function with no params (backend/c_emit.rs ParamList).

Fix: removed the barrier; c_shim::va_start_args emits va_start(_ap) when there are no fixed tags; ParamList writes "..." without a leading comma when params is empty.

Regression test: crates/slate/tests/fixtures/x86_64/long_double_variadic_no_fixed_parameters.c (-std=c23).
