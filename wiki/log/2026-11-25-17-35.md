# slate-j3by.25 lower_bit_scan: MSVC BitScan returns status and writes the set-bit index

_2026-11-25 17:35:42_

- bead: slate-j3by.25
- kind: bug
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/tests/fixtures/msvc
- flavor: msvc

Outcome: Slate lowers all four MSVC BitScan intrinsics, including the
conditional output store when the caller discards the status.

Symptom: The MSVC fixture stopped at `builtin without a lowering` in
`lower_call` on x86, x64, and ARM64.

Reproducer:
```c
#include <intrin.h>
unsigned char scan(unsigned long *index, unsigned long mask) {
  return _BitScanForward(index, mask);
}
```

Cause: The parser emitted a direct builtin call with the output pointer,
mask, and status types. `lower_value_node` had no case for the BitScan names.

Fix: `lower_bit_scan` captures the pointer and mask once. Zero returns 0
without storing. Forward scans store the trailing-zero count. Reverse scans
subtract the leading-zero count from 31 or 63 and store the resulting index.
Both successful paths return 1. The reproducer now lowers to a Rust
conditional with a raw pointer write. `open_coded_builtin` suppresses the
extern declarations.

Regression test: crates/slate/tests/fixtures/msvc/msvc_bitscan_intrinsics.c
checks both directions, mask widths, and zero status where supported. It also
checks that discarding the status preserves the index write.
