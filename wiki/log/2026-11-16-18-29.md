# slate-f2zu.14.40.16 kernel_link link_units: generated units under build-clang/ (vdso64-image, asn1, capflags) kept native vmlinux.a member, init_vdso\*\_image initcalls ran twice

_2026-11-16 18:29:41_

- bead: slate-f2zu.14.40.16
- kind: bug
- area: tools/corpus/kernel_link.py
- target: x86_64

Outcome: generated kernel units that live in the native build directory
(vdso64-image.c, vdso32-image.c, capflags.c, \*.asn1.c, defkeymap.c,
consolemap_deftbl.c, shipped-certs.c) replace their native vmlinux.a members
instead of linking next to them, so the initcall table equals native.

Symptom: after slate-f2zu.14.40.13, link.md showed `_packed 107/118` and the
decoded initcall table had two extra entries, init_vdso64_image and
init_vdso32_image: the native C copy from
arch/x86/entry/vdso/vdso64/vdso64-image.o and the translated
`__slate_unit_vdso64_image::init_vdso64_image` both ran. The link succeeded
because the initcall functions are static.

Cause: kernel_link.link_units named each unit's member as
os.path.relpath(file.with_suffix(".o"), project_dir). For units under
build-clang/ that gives `build-clang/arch/x86/entry/vdso/vdso64/vdso64-image.o`,
while vmlinux.a (built with O=) names it
`arch/x86/entry/vdso/vdso64/vdso64-image.o`. swap() treated the 11 units as
"folded": their Rust CGUs went into the shard's \_\_root.o and the native
members were never removed.

Fix: link_units takes the native build dir (`project_dir / f"build-{mode}"`,
passed through swap from link_stage) and names units under it relative to that
dir. swap now fails when a unit's object exists in the build tree but is not a
vmlinux.a member under that name, instead of folding it and keeping both copies.

Verified:
`python3 tools/corpus/kernel_link.py ~/slate-translated/slate-linux --jobs 2`
(link stage only, about a minute): 0 errors, 60 objtool warnings (unchanged),
`_packed 118/118`. Decoded initcall and .init.setup tables (1046 entries)
identical to native build-clang. Boots to busybox under QEMU, loopback ping OK,
no WARN/Oops; dmesg matches native apart from timing, stack-depth, RTC and
percpu embed size (52 -> 55 pages/cpu).

Limits: verified on the --from build shards (old-binary translation with the
slate-f2zu.14.40.15 Guard hand patch), not a fresh --from translate run.

See: slate-f2zu.14.40.13, slate-f2zu.14.40.15
