# Carry align=1 on accesses through \_\_unaligned pointees

_2026-10-24 11:52:30_

slate-parser-v74.7: reads and writes through **unaligned int \*, S **unaligned _, and a LPUWSTR-style typedef printed plain read<T>/write<T>, so slate emitted aligned derefs. TypeResolver::reduced_alignment (sema/types.rs) now returns 1 when the accessed type carries the \_\_unaligned qualifier and its natural alignment is above 1, so Access::align=1 reaches the IR (read<i32, align=1>); char and plain int are unchanged. Reading an int _\_\_unaligned object also gets align=1 (ms-winnt-keywords.c regenerated, both flavors). New fixture ms-unaligned-access.c in clang/windows and msvc/windows x86_64. Verified end to end: translate-project --target=x86_64-pc-windows-msvc emits read_unaligned/write_unaligned/addr_of!(..).read_unaligned, and the cargo build runs under wine with output identical to the cl.exe build. Doc: ir/types.md.
