# Type-name aligned attribute per flavor

_2026-09-29 15:37:07_

slate-parser-8csg: __attribute__((aligned(N))) in a type name's specifiers was dropped.

Oracle probe (x86_64): gcc makes the whole type name aligned, like an anonymous aligned typedef.
- _Alignof(aligned(16) char *) = 16; the attribute applies after the declarator, not only to char.
- sizeof(aligned(16) char[3]) = 3.
- aligned(2) int has alignment 2, so it can lower alignment.
- Bare aligned means the biggest alignment.
- typeof and compound literals keep it.
clang warns 'aligned' attribute ignored when parsing type [-Wignored-attributes] and uses natural alignment.

Implementation:
- TypeResolver::resolve_type_name wraps the resolved type in CTypeKind::Typedef{alignment} under gcc. That reuses the existing aligned-typedef semantics: declared_alignment lets gcc lower alignment, and arrays inherit it. The name is the rendered underlying spelling, so diagnostics stay readable.
- resolve() itself is shared with declarations, where aligned is an object request, so only TypeName sites were switched: sizeof/_Alignof, offsetof, casts, _Generic, typeof, types_compatible, the _Alignas(type) operand, the typer, the checker, and lowering.
- The clang/msvc warning is emitted in the checker's type_name, which visits each type name once. Emitting it during resolution would duplicate it across passes.
- The compound literal alignment from cxg.53 now takes only _Alignas as the request, plus the literal's declared type. Before, clang flavor wrongly honored aligned there, and (T){..} with an aligned typedef T had lost its alignment.

Not handled: declarator-position aligned in a type name.
Fixtures: {gcc,clang}/linux/x86_64/type_name_aligned.c. The clang fixture checks the 8 warnings.
