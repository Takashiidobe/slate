# slate-5q63.29 release: Cargo packages vendored bitfields and bumps slate-analysis with Slate

_2026-11-23 15:42:21_

- area: crates/slate/build.rs

Outcome: The five Slate release crates bump together, and the packaged translator builds with its vendored bitfields dependencies.

Symptom

The five-crate publishing dry run reached translator verification, then failed when the generated `include_str!` calls could not read the vendored bitfields sources or manifests. The version bump also left `slate-analysis` at the old version.

Cause and fix

Cargo excludes nested packages when it sees their `Cargo.toml` files. The translator package now includes both bitfields vendor directories and uses `Cargo.toml.template` for their manifests. `write_vendored_crate` already maps the template names to `Cargo.toml` in generated projects. The differential harness materializes both manifests and preserves `proc-macro = true` while redirecting each library path to the vendored source.

`tools/release.sh` uses one dependency list for the four workspace requirements and their corresponding package versions. It also bumps `slate-c2rust` and updates the lockfile.

Verification

In an isolated checkout, `tools/release.sh minor` moved all five manifests, workspace requirements, and lockfile entries to `0.10.0`. A combined locked `cargo publish --dry-run --all-features` built all five packaged crates.

All 44 tests in the Slate release nextest profile passed.

Limits: The first `slate-analysis` publish needs the compatible `slate-parser` release on crates.io. Workflow integration follows that first manual publish in slate-5q63.30.
