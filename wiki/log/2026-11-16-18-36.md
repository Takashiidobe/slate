# slate-f2zu.14.40.3 compiler_args parse_arguments: unknown compiler flags warn once on stderr and are ignored instead of unknown option error

_2026-11-16 18:36:14_

- bead: slate-f2zu.14.40.3
- kind: parser
- area: crates/slate-parser/src/compiler_args.rs

Outcome: slate-parser warns on stderr once per unknown compiler flag and ignores it instead of failing the unit with `unknown option`.

Diagnostic that was wrong: any argument that no matcher in `parse_arguments`
(crates/slate-parser/src/compiler_args.rs) recognized returned
`invalid compiler argument `<flag>`: unknown option`, so a compile_commands entry with one
flag slate does not model could not be translated, and harnesses had to filter flags.

Before (`slate-parser parse u.c -fno-stack-protector-all`):

    Error:   × invalid compiler argument `-fno-stack-protector-all`: unknown option

After (`... -fno-stack-protector-all -fbogus -fno-stack-protector-all`):

      ⚠ unsupported compiler flag `-fno-stack-protector-all` ignored
      ⚠ unsupported compiler flag `-fbogus` ignored

and parsing continues.

Fix: the final `else` in `parse_arguments` calls `report_unsupported_flag`, which keeps a
process-wide `LazyLock<Mutex<HashSet<String>>>` so each flag prints once even when
translate-project parses thousands of units (and the matrix re-parses them). Unchanged
errors: known options the final flavor lacks (`unknown option for the <flavor> flavor`) and
bad values of known options. An unknown flag that takes a separate value also reports the
value as its own unsupported flag. The pp_diff.py SEMANTIC_FLAGS allowlist was already gone.

Fixtures: error/clang/linux/x86_64/no-stack-protector-all.c moved to
clang/linux/x86_64/unsupported_compiler_flag.c (warning fixture, shows dedup), and
error/.../include_option_unknown.c moved to clang/linux/x86_64/include_option_unsupported.c
(`-iwithprefix=` now warns). Parser profile 9180/9180. wiki/concepts/compiler-arg-rules.md
records the rule.

Limits: the slate profile was not run (no crates/slate code changed). Ignoring a flag that
changes semantics is silent apart from the warning; such a flag needs threading as an `Opt`.
