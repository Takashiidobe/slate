# Honor llvm.byval on non-variadic extern params

_2026-09-04 07:29:11_

`fopencookie(void*, const char*, cookie_io_functions_t)` takes a 32-byte
struct by value. On SysV that is MEMORY class: the caller copies the struct
into the outgoing-argument area. Clang encodes this in CIR as a pointer
parameter carrying `llvm.byval = !rec__IO_cookie_io_functions_t`.

Slate's variadic call path already unwrapped byval args
(`calls.rs`, `call_arg_byval_type_attr`), but the fixed-arg path did not:
`extern_fn_signature_as` built each param type from `rust_type(ty)` alone, so
`fopencookie` was declared with `_2: *mut _IO_cookie_io_functions_t`. Rust
then passed a pointer in a register where glibc reads 32 bytes off the stack.

This sometimes appeared to work: rustc happened to place the struct local at
`(%rsp)`, exactly the byval slot, so a standalone repro printed the right
answer. Under the differential harness's frame layout it crashed.

Fix:
- clang-ir `model::Function` now keeps the `cir.func` op's `arg_attrs`
  (it was already parsed on `FuncOp`, just dropped by the model view).
- `extern_fn_signature_as` strips one pointer layer for byval params, so the
  decl reads `_2: _IO_cookie_io_functions_t` and rustc classifies per target.
- The non-variadic call site wraps byval args in `std::ptr::read_unaligned`,
  matching what the variadic path already did.

`tests/fixtures.link/long_double/main.c` was silently affected too:
`ext_box_roundtrip`/`ext_nested_roundtrip` took byval structs and had the same
pointer-for-value mismatch. Its LOWERING snapshot was regenerated.

Note: `@lowering-fn-begin` cannot wrap a `static` function. Clang defers
emission of internal-linkage functions, so a static lands after every external
definition following it in the source; the tool's marker functions are
external and get hoisted above what they wrap, leaving an empty region. Slate
just follows CIR order. `tests/fixtures/gnu_cookie_stdio.c` uses in-body
markers instead. Tracked as slate-57do.
