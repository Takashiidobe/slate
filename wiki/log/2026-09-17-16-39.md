# Verify sys/sdt.h, sys/select.h, and sys/sem.h

_2026-09-17 16:39:37_

sys/sdt.h is glibc x86_64/i386-only (SystemTap probe macros, not part of the ARM/AArch64 cross sysroots or musl); ported it and sdt-config.h verbatim from the real oracle. sys/select.h and sys/sem.h are present on all eight descriptors. Converted select.h's FD_ZERO/FD_SET/FD_CLR/FD_ISSET/FD_SETSIZE/NFDBITS from function decls/enum constants to real macros matching glibc/musl shape. Added a glibc-gated <sys/types.h> include to bits/sem.h to match glibc's bits/sem.h -> sys/types.h transitive include that musl's sem bits lack. All seven non-i386 focused matrices pass for each header; glibc-i386 fails at the final link step for every header (old and new) on this host because /usr/bin/gcc defaults to 64-bit linking against --sysroot=/usr with no -m32 forwarded to the link command -- confirmed pre-existing via git stash against sys/quota.h and sys/random.h, so it is a host/harness gap, not a header regression. Full libc profile: same 4 pre-existing i386-only failures before and after.
