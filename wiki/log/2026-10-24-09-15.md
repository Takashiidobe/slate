# Accept block-scope typedef redefinition to the same type

_2026-10-24 09:15:22_

slate-parser-q1z8. void f(void){ typedef int T; typedef int T; } was rejected as 'duplicate ordinary name' because names.rs::bind_ordinary only reused an existing entry at file scope or for linked names. clang and gcc accept it (C11 6.7p3).

- bind_ordinary now also reuses the binding when a typedef redeclares a typedef in the same block scope; define_alias's existing compatibility check then rejects different types ('typedef redefinition with different types').
- New TypeResolver::reject_variably_modified_redefinition, called by the checker (assertion.rs) before the VM/non-VM split: if the binding already has an alias and either type is variably modified, reject 'redefinition of typedef for variably-modified type' (clang/gcc reject both orders). It lives in the checker because VM typedefs get a provisional alias there that lowering's define_alias would otherwise see as a previous definition.

- Docs: ir/declarations. Parser 8352/8352.
