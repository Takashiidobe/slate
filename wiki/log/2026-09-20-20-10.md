# Void types, GNU void arithmetic, and labeled statement-expression results

_2026-09-20 20:10:02_

slate-parser-dyd.6. Fifteen fixtures that clang accepts were rejected by
five separate defects, all reported as layout errors.

1. `require_complete` (renamed `require_pointer_element`, its only two
   callers are pointer difference and pointer offset) asked for a storage
   layout, so `void *` arithmetic failed with `unsupported scalar storage
   layout for void`. It now accepts `Type::Void`: GNU gives void size 1.
   `&&a - &&b` is this too, since a label address is `void *`.
2. The two `sizeof`/`_Alignof` sites went through `object_type`, which
   rejects void by design. They now use `ir_type` plus `sizeof_storage`,
   which answers 1/1 for void and defers everything else to
   `qualified_storage`.
3. `extern void _text;` — a GNU idiom for a linker symbol, accepted by both
   clang and gcc — reached `object_type` and failed. The global declaration
   path now uses `layout`, falling back to `ir_type` only for `extern`, and
   otherwise reports `object cannot have type void` as an `Invalid`
   diagnostic rather than an `Unsupported` one. `void x;` and `static void
   x;` are still caught earlier by validate.rs; block-scope `void x;` and
   `typedef void f; f x;` are caught here.
4. `define_alias` rejected `typedef void f;`. A typedef of void is legal;
   only declaring an object through it is not.
5. A statement expression only took its value from a trailing
   `StmtKind::Expr`, so `({ ... done: result; })` lowered to void and then
   failed conversion. `labeled_result` now peels the labels off the tail,
   emitting them with a null body so the label still lands immediately
   before the value, and uses the inner expression as the result. No
   duplicated evaluation; nested labels recurse.

`tests/fixtures/error/ir_pointer_arithmetic.c` lost its VOID configuration:
clang and gcc both accept `void *p; p++;` with a pedantic-only warning, so
per reject-only-on-compiler-consensus slate-parser must accept it.

Corpus sweep: 2554/2687 -> 2569/2688 accepted, no regressions. New fixtures
`sema/ir_void_types.c` and `error/ir_void_object.c`;
`sema/ir_statement_expressions.c` gained labeled and nested-label results.
