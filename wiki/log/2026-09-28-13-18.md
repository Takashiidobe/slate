# i686 and armv7 glibc sysroots

_2026-09-28 13:18:19_

slate-parser-4abr. slate-sysroots (12ffe58) installs three more glibc sysroots from Debian cross-toolchain-base, keeping the usr/<triplet> layout:
- i686-unknown-linux-gnu: libc6(-dev)-i386-cross 2.43-3cross8 + linux-libc-dev-i386-cross 6.12.38, in usr/i686-linux-gnu.
- armv7-unknown-linux-gnueabi: armel 2.36-8cross1 + linux 6.1.4 (Bookworm; Debian no longer builds armel cross packages), in usr/arm-linux-gnueabi.
- armv7-unknown-linux-gnueabihf: armhf 2.43-3cross8 + linux 6.12.38, in usr/arm-linux-gnueabihf.

Correction to the i386 removal entry: SysrootLayout::Unix { multiarch } is probed as usr/<triplet>/include, the cross-package layout, not Debian multiarch usr/include/<triplet>. Debian's i386 cross packages use i686-linux-gnu there, so the i686 profile goes back to i686-linux-gnu; the earlier switch to i386-linux-gnu (based on clang's multiarch search) was wrong. The armv7 profiles had no triplet and now probe arm-linux-gnueabi and arm-linux-gnueabihf. adding-a-target.md spells this out.

Verified: a program using stdio, stdlib, pthread, signal, sys/stat, unwind.h and linux/version.h with ILP32 static asserts parses in the gcc and clang flavors on all three targets; gnu/stubs.h picks stubs-soft.h on gnueabi and stubs-hard.h on gnueabihf (each sysroot ships only its own); i686 mm_malloc.h/cpuid.h resolve. Gate 7250/7250.
