# slate-8ge7.24.5 lowerer casts: peel_casts deleted, array decay and layout query casts emitted once, explicit same-type casts kept, no cast-canonicalize transform

_2026-11-21 17:18:37_

- bead: slate-8ge7.24.5
- kind: rewrite
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/src/backend/engine/rules
- area: wiki/concepts/slate-analysis.md

Outcome: the Rust rule `peel_casts` is deleted; the lowerer emits each cast once, explicit same-type casts the C wrote are kept, and no `cast-canonicalize` IR transform was added because measurement showed none is sound or needed.

Gap and why it mattered: `peel_casts` (priority 45, ~7.0k fires over 3067 fixtures) collapsed `(x as A) as B` from Rust types and a VarTypes map. 5.7k fires were string literals the lowerer itself spelled `(b"..".as_ptr() as *mut i8) as *const i8`; others were `buf.as_mut_ptr() as *mut i8` decays, `(size_of::<T>() as u64) as i32`, and the C's explicit `(int *)(char *)v`, which it merged against the slate-8ge7.24 policy.

Before (`char buf[8]; const char *t = buf; strlen(buf); f(buf); __alignof__(T)` as an int argument):
  let t: *const i8 = buf.as_mut_ptr() as *const i8;      (via peel of `as *mut i8`)
  fmt(buf.0.as_mut_ptr() as *mut i8, ..)
  let m: u64 = n;                                         (`(size_t)n` dropped)
  *(v as *mut i32)                                        (`(int *)(char *)v` merged)
After:
  let t: *const i8 = buf.as_mut_ptr() as *const i8;      (emitted directly)
  fmt(buf.0.as_mut_ptr(), ..)
  let m: u64 = n as u64;
  *((v as *mut i8) as *mut i32)
  check(.., core::mem::align_of::<T>() as i32)

Implementation (crates/slate/src/frontend/lowerer):
- `values.rs` ArrayDecay: `as_ptr`/`as_mut_ptr` gets no cast when `lower_type(element)` already gives the C pointer type.
- `values.rs` generic Convert arm: a `pointer_cast` of an array decay retargets the decay's own thin-pointer cast; a `widen`/`truncate`/`reinterpret` of a `LayoutQuery` retargets the query's integer cast (usize -> u64 -> T equals usize -> T for every T). Neither retargets a `Module::macro_values` operand: the `--merge` template lowering does not, and a mismatch fails merge ("macro template mismatch in report", fixtures.merge/stdio_bindings.c).
- `types.rs` `lower_layout_query`: no cast when the value type is `usize`.
- The same-type `reinterpret` arm now skips `ConversionReason::Explicit`.

Why no IR transform: an implicit pointer_cast of an implicit pointer_cast occurs in 0 of 3067 fixtures. An implicit same-type removal (476 fires) was built and broke `--merge`: `long f(int v) { return v; }` is `i32 -> i32` on LLP64 but lowers as `c_long`, and dropping it on one target split `from_int`, `from_uint`, `sum_long` per target in fixtures.merge/spelled_conversions.c. The lowerer arm keys on lowered types, so it stays.

Measured: 430 of 3067 translations changed, every exit code unchanged. New double casts appear only where the C wrote two explicit casts (`(long long)(long)sum` in gcc-torture/20001108-1.c) or an explicit same-type cast.

Fixture: the regenerated FileCheck blocks (tests/fixtures, fixtures.merge, fixtures.release, fixtures.dylink, fixtures.build) show the single casts; `fixtures.transforms/const-fold/explicit_kept.c` covers the explicit-kept rule on the IR.

Limits: `c"x".as_ptr() as *mut i8` stays where C passes a literal as `char *` (a real *const -> *mut cast). Libc rules still add `as *const c_char` over a C cast (`strlen((buf.as_mut_ptr() as *const i8) as *const core::ffi::c_char)`); that is slate-8ge7.24.12.

See: slate-8ge7.24, slate-8ge7.24.3 (triage), slate-8ge7.24.4, wiki/concepts/slate-analysis.md#casts-are-lowering-not-a-transform.
