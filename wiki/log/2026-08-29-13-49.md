# Match enum fields when disambiguating same-tag local records

_2026-08-29 13:49:44_

slate-ft0v.3. libexpat basic_tests.c has same-tag function-local records (struct CaseData x2, struct TestCase x3) with different layouts. Generated crate had 30 errors: one struct got the wrong (later) layout and its sibling was emitted empty.

Root cause in resolve_local_record_collisions (record_analysis.rs): it pairs CIR record aliases (CaseData, CaseData.0) to AST candidates by comparing field shapes. AST enum fields are CType::Enum(name); CIR lowers the same field to an integer (u32). normalize_record_shape left both as-is, so [Ptr, Enum] never equalled CIR's [Ptr, Int{u32}]. With no shape match, the resolver produced nothing and the fallback `records` BTreeMap (keyed by bare tag) collapsed both defs to the last one, leaving the base name with the later layout and the .0 name empty.

Fix: normalize CType::Enum(\_) and CType::Int{..} to a single canonical integer in normalize_record_shape, so enum<->int and width/sign differences no longer block same-tag pairing. The occurrence-sorted forward cursor still pairs equal shapes by source order (verified CIR occurrence order == source order for the libexpat clusters).

Fixture: tests/fixtures/local_record_same_tag.c (enum fields required to reproduce). libexpat generated-crate errors 31 -> 1 (remaining is the cross-TU anon-struct return-type identity, slate-ft0v.1). lowering 10 pass, rewrites 110 pass.
