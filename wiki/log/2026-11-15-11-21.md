# slate-f2zu.14.34.12 Reachability::mark_roots: file-scope asm from headers pruned (DEFINE_STATIC_CALL __SCT__ trampolines undefined at vmlinux link)

_2026-11-15 11:21:48_

- bead: slate-f2zu.14.34.12
- kind: parser
- area: crates/slate-parser/src/reachability.rs
- corpus: linux

Outcome: file-scope `asm(...)` that comes from an included header now reaches the IR and the generated `global_asm!`, as clang emits it.

Diagnostic or IR fact that was wrong: `Reachability::mark_roots` (crates/slate-parser/src/reachability.rs) roots header declarations that are pragmas, carry a retention attribute, or define an external symbol, but never `DeclKind::Asm`. So every header file-scope asm was pruned before sema. In the kernel, `CREATE_TRACE_POINTS` headers expand `DEFINE_STATIC_CALL` -> `ARCH_DEFINE_STATIC_CALL_TRAMP`, a file-scope asm that defines `__SCT__tp_func_*`. Swapping the block shard into vmlinux.a failed with `undefined reference to __SCT__tp_func_kyber_adjust` (35 symbols in block alone, every shard with tracepoints).

Before (`#include "h.h"` where h.h has `asm(".globl foo\nfoo: ret\n");`): the module has no `asm` line.
After:
```
asm ".pushsection .static_call.text, \"ax\"\n.globl __SCT__header_call\n..." [dialect=att];
```

Fix: `mark_roots` treats `DeclKind::Asm` like `DeclKind::Pragma` (always a root); `mark` already walks its operands.

Fixture: crates/slate-parser/tests/fixtures/clang/linux/x86_64/file_scope_asm_header.c (+ inputs/file_scope_asm_header.h). Regenerated: clang/freebsd/{aarch64,x86_64}/nullability_headers.c and crates/slate/tests/fixtures.merge/libc_symbol_paths.c, which now carry FreeBSD stdlib.h's `.symver __qsort_r_compat, qsort_r@FBSD_1.0` (clang emits it too).
