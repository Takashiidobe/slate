# Lower %V via pinned GPRs for in-template .intel_syntax switches

_2026-10-10 08:31:06_

slate-3f8g.4.17.7 (also closes slate-3f8g.4.17.21). {att|intel} alternations were already resolved by slate-parser (IR template holds only the AT&T branch), so no Slate work was needed there. In-template .intel_syntax noprefix regions: GCC does not track them either; %V is the user's tool. LLVM's assembler rejects %eax under noprefix (GAS accepts it), and Rust att_syntax always prints {N:e} as %eax, so an operand referenced with %V is pinned, the same way reg_legacy is, to the first free GPR (ax,cx,dx,si,di,r8-r15; reg_abcd: ax,cx,dx) and printed bare by explicit_reference, which also drops the % for %V. Promoted x86_64/asm_dialect_switch with the compare_intel_equal case that gnu_asm_flag_outputs had dropped (two %V inputs plus a flag output) and a 64-bit lea case.
