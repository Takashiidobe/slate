# Keep lib.c from colliding with the Rust library root

_2026-11-07 09:27:35_

slate-t32a: translate-project mapped a C unit lib.c to src/lib.rs, the same path as the generated library crate root, so the parallel writes raced. Libraries got 'circular modules: src/lib.rs -> src/lib.rs' (TRACTOR B01_organic/rev16_lib), and executables gained a stray Cargo lib target that failed on crate::__slate_types imports. unit_file_stem (crates/slate/src/main.rs) now reserves lib as well as main, mapping it to __slate_unit_lib.rs; the test-side copies in tests/differential.rs (release_unit_output), tests/dylink.rs and tools/update_filecheck.py follow. Regressions: fixtures.library/unit_named_lib (library with src/lib.c) and fixtures.release/helper_unit_named_lib (exe with a lib.c helper sharing a struct), both failing before the fix. TRACTOR rev16_lib now passes all 5 Cando vectors. slate profile green.
