# Design comment placement and doc comment promotion

_2026-10-05 18:44:23_

Compared sqlite backup.c with translated backup.rs: comments drift because they are free-floating spans re-anchored by source offset after lowering, which reorders items. File header, struct and field comments, and parameter comments all piled before unrelated functions; trailing local comments became leading; #endif labels leaked.

Decided (with the user), recorded in wiki/concepts/comment-placement.md:
- Parser classifies comments (leading, trailing, inner-trailing, interior, detached prologue/section, dropped preprocessor labels and tool annotations); owned comments are node fields through AST, IR, and Rust AST; detached ones anchor by node id.
- comment_group() must split at blank lines.
- One rewrite-engine helper migrates comments off removed nodes.
- Default //; doc only when certain. Positional promotion is the translate-project default; parameter comments fold into a # Arguments list; prologue becomes //!.
- Generated crate sets doctest = false and allow(rustdoc::all); no Markdown fencing.
- Definition comment wins over the prototype's.
- Items from a file are emitted in source order.
