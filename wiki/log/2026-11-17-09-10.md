# slate-3amj.58 -fsanitize=: sanitizer predefines, __has_feature(address_sanitizer) and name/conflict errors for gcc and clang flavors

_2026-11-17 09:10:36_

- bead: slate-3amj.58
- kind: feature
- area: crates/slate-parser/src/sanitizers.rs
- area: crates/slate-parser/src/compiler_args.rs
- area: crates/slate-parser/src/pp

Outcome: gcc and clang flavors now emulate -fsanitize=/-fno-sanitize=: the __SANITIZE_*__ predefines, the sanitizer __has_feature/__has_extension answers, and the compilers' name and conflict errors, instead of warning "unsupported compiler flag ignored".

Gap: every tools/testing kernel harness (slate-f2zu.14.35) compiles with -fsanitize=address -fsanitize=undefined. slate ignored the flag, so __has_feature(address_sanitizer) and __SANITIZE_ADDRESS__ were 0/undefined where clang and gcc set them.

Before (`slate translate -fsanitize=address -fsanitize=undefined s.c`):

    ⚠ unsupported compiler flag `-fsanitize=address` ignored
    static mut asan: i32 = 0;      // #if __has_feature(address_sanitizer)

After:

    static mut asan: i32 = 1;
    static mut gcc_asan: i32 = 1;  // #ifdef __SANITIZE_ADDRESS__

Implementation:
- src/sanitizers.rs: `Sanitizers` (u64 set of checks). `Sanitizers::resolve` replays -fsanitize=/-fno-sanitize= in argv order with per-flavor names and groups (`undefined` differs: clang has function/array-bounds/float-cast-overflow, gcc has bounds), drops clang's vptr (C) and object-size at -O0, checks the `CLANG_CONFLICTS`/`GCC_CONFLICTS` tables on the final set, the pointer-compare/subtract address rule (clang: any -fsanitize= given; gcc: final set, kernel-address too), and gcc shadow-call-stack off aarch64.
- `Opt::Sanitize`, `Opt::SanitizeChecks` (recover/trap lists, names validated); bare -fsanitize-recover/-trap, -fsanitize-address-use-after-scope, -fsanitize-undefined-trap-on-error, clang -fsanitize-minimal-runtime and -fsanitize-ignorelist= are CODEGEN_ONLY_FLAGS rows.
- `CodegenOptions::sanitizers`; pp predefines and `has_checks::has_feature` read it.

Fixtures: clang/ and gcc/linux/x86_64/sanitize_macros.c (17 and 12 prefixes, every value compared with clang 23 / gcc 16 output), error/<flavor>/linux/x86_64/sanitize-*.c (12).

Limits: translated code is not instrumented (slate-3amj.59). -fsanitize-coverage= is still unsupported (slate-3amj.60). Not emulated: clang target limits (memtag off aarch64, cfi without -flto are rejected as unknown names), minimal-runtime conflicts, ignorelist file existence.

See: wiki/concepts/compiler-flags.md#sanitizers, slate-f2zu.14.35.
