# slate-78pa.1.6 fixed SVE vector lowering: arm_sve_vector_bits types as Simd, scalable native signatures barrier

_2026-11-19 15:26:29_

- bead: slate-78pa.1.6
- kind: feature
- area: crates/slate/src/frontend/lowerer/functions.rs
- flavor: gcc
- target: aarch64

Outcome: fixed-length SVE vectors (`arm_sve_vector_bits`) lower to `core::simd::Simd<T, lanes>` and run against gcc under qemu; signatures that pass them to or from native code are a barrier.

Gap and why it mattered: after slate-78pa.1.1 the IR has `vector<T, N, sv*_t>`,
but AAPCS64 passes it in Z/P registers (`AbiPass::Scalable`), which a Rust
`extern "C"` Simd argument does not match.

Before: no translation (the parser rejected the type).

After (`-march=armv8.2-a+sve -msve-vector-bits=512`):
  static fixed_i32 scale(fixed_i32 a, int f) { return a * f; }
  =>
  unsafe fn scale(a: core::simd::Simd<i32, 16>, factor: i32) -> core::simd::Simd<i32, 16>

Implementation:
- The vector lowering already handled `Type::Vector`; only `..` patterns for
  the new `scalable` field changed.
- `function_abi` (lowerer/functions.rs) returns a barrier
  `fixed-length SVE vector passed in Z/P registers to or from native code`
  when `AbiSignature::passes_scalable()` and the function is a declaration or
  not internal. Internal definitions keep the Rust ABI, and the address-taken
  path already skips vector-typed functions, so their calls stay Rust-to-Rust.
- qemu-aarch64-static runs SVE at 512 bits by default, so the runtime fixture
  uses `-msve-vector-bits=512`.

Fixture: crates/slate/tests/fixtures/gcc/aarch64/sve_fixed_vectors.c (arith,
shifts, compare to GNU mask, to and from GNU, reinterpret, predicate ops,
struct holder layout); crates/slate/tests/fixtures.unsupported/gcc/aarch64/sve_fixed_native_signature.c.

Limits: exported or extern functions with fixed SVE parameters stay a
barrier until the Z/P-register ABI exists (slate-78pa.1.7). Conversions to the
sizeless type also wait for slate-78pa.1.7.

See: slate-78pa.1.1, slate-78pa.1.7
