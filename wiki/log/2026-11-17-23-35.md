# slate-5q63.17 auto-bead loop: auto label queue, needs_input status, 15m lease hook, driver for unattended single-agent bead work

_2026-11-17 23:35:17_

- bead: slate-5q63.17
- kind: feature
- area: tools/auto
- area: .claude/skills/auto-bead

Outcome: an unattended agent can work `auto`-labeled beads one at a time on main, sending design-shaped tickets back as `needs_input` with a written question.

Gap and why it mattered: every bead needed a supervised session. Low-stakes compatibility work (gcc/flag/torture/std-C/runtime bugs) could run unattended if the agent had a queue, a time box, and a way to hand back underspecified tickets.

Implementation:
- Queue: label `auto`. Seeded on open, non-epic, non-deferred descendants of slate-3amj, slate-3of2, slate-5exy, slate-78pa, plus bugs under slate-yar4 (103 beads). New bugs agents find are filed under the same parent without the label.
- Status `needs_input` (custom, category frozen, so `bd ready` skips it): `bd config set status.custom "needs_input:frozen"`. Agent comments Question/Found/Options/Recommendation/Unblocks with/WIP. Reopen by replying in a comment and setting `open`; the agent treats the latest reply as the spec.
- `tools/auto/lease.py`: `.auto/lease.json` (gitignored) holds run start/budget, the held ticket and its start time, per-session ticket count, history. `next` claims (`bd ready --label auto --claim`), `done <closed|stale|needs_input|wip|dry>` prints CONTINUE or EXIT. `hook` (only with SLATE_AUTO=1) injects `ticket <id> Nm/15m · run …` after every tool call and says stop once over 15 minutes.
- `tools/auto/driver.py`: refuses a dirty tree or non-main branch, records the start commit, runs `claude -p /auto-bead` sessions (exit after 4 tickets or any needs_input/wip), stops at the hours budget, empty queue, or a usage-limit message. If a session dies holding a ticket it saves dirty work to `<id>-wip`, comments, and sets needs_input.
- `.claude/skills/auto-bead/SKILL.md`: gates. Stale -> close with evidence, no log. Well-defined = failing fixture proven first, fix follows a named precedent (pattern-following, not pattern-setting), one reasonable approach, no invariant/wiki/flag-policy change, no loosened tests or unrelated fixture churn, fits 15 minutes including tests. A `[auto plan]` comment precedes code. Landing follows CLAUDE.md Session Completion. `dry-run` posts a verdict comment only and labels the bead `auto-dry`.
- `.claude/settings.json`: PostToolUse hook for the lease.

Usage: `python3 tools/auto/driver.py --dry-run --max-sessions 2` then review `bd comments`; real run `python3 tools/auto/driver.py --hours 5`; review `git log <start>..main`, `bd list --status needs_input`.

Limits: `.claude/` is ignored by the user's global gitignore, so the skill and hook are local to this checkout. Per-session context budget is not set by the driver. bd auto-export (~9s per write) stays on; it costs roughly 45s of each 15-minute ticket.
