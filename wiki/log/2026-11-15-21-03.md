# slate-f2zu.14.34.28 kernel rustflags -Zplt=yes: memset/memmove libcalls went through GOT + retpoline, objtool call to {dynamic}() leaves .noinstr.text (fixup_bad_iret, sync_regs, do_machine_check)

_2026-11-15 21:03:50_

- bead: slate-f2zu.14.34.28
- kind: bug
- area: crates/slate/src/project/build_target.rs
- flavor: clang

Outcome: freestanding (kernel) crates build with -Zplt=yes, so the memset/memmove/memcpy calls LLVM emits for struct copies and zeroing are direct PLT32 calls instead of GOT loads plus retpoline thunks.

Symptom: objtool on the relinked vmlinux.o: "call to {dynamic}() leaves .noinstr.text section" in fixup_bad_iret, sync_regs and do_machine_check.

Reproducer: any struct copy or zeroing in a noinstr function, e.g. sync_regs `*regs = *eregs`.

Cause: rustc defaults to -Zplt=no, which sets LLVM's RtLibUseGOT module flag, so compiler-emitted libcalls became `mov memset@GOTPCREL(%rip),%r11; call __x86_indirect_thunk_r11`. objtool cannot resolve an indirect call, so noinstr code appeared to call unknown text. Calls written in the source (__memcpy) were already direct. clang's default (-fplt) emits direct calls. I checked on the host with a struct copy: the default gives `jmp *memmove@GOTPCREL(%rip)`, and -Zplt=yes gives `jmp memmove` (R_X86_64_PLT32).

Fix: shared_flags in crates/slate/src/project/build_target.rs adds -Zplt=yes to the generated .cargo/config.toml rustflags for bare-metal x86 targets.

Regression test: freestanding_projects_build_for_bare_metal_targets (crates/slate/tests/differential.rs) now expects "-Zplt=yes" in the kernel config.

Verification: arch_x86_kernel and arch_x86_kernel_cpu shards retranslated and built. memset/memmove in fixup_bad_iret, sync_regs and do_machine_check are now R_X86_64_PLT32. GOT-indirect libcalls in those two shards went from 218 to 0, which also removes a retpoline thunk from every struct copy in kernel shards.

Limits: the noinstr check itself (the memset/memmove targets live in .noinstr.text) is confirmed only by the vmlinux.o objtool pass at the next relink. The other 2 {dynamic} calls (default_idle, acpi_safe_halt: pv_ops "m" operand lowered register-indirect) are slate-f2zu.14.34.33.

See: slate-f2zu.14.34.28, slate-f2zu.14.34.33.
