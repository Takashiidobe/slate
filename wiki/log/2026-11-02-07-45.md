# Target-aware LongDouble alignment

_2026-11-02 07:45:49_

slate-zbwn: Rust LongDouble was hardcoded repr(C, align(16)), so i686 records (C align 4) had wrong size and field offsets. long_double_prelude now takes the target F80 alignment (lowerer.rs reads tables.target); the C shim types use aligned(__alignof__(long double)). i686 long double records now match C layout. Fixtures: gcc/i686/long_double_record_layout.c; flexible_array_records and long_double_complex now pass on i686 (removed from the unsupported list). The sizeof/offsetof fallback gate (rust_layout_matches_c) is left for slate-yar4.9.
