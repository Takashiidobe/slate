# support __builtin_assume_aligned via cir.assume align bundle (slate-04q.47.2)

_2026-09-04 11:38:31_

CIR fully supports __builtin_assume_aligned: it lowers to the general-purpose
cir.assume op (already handled by slate since slate-04q.47.1) with
bundle_kind = AssumeBundleKind::Align and bundle_args = [ptr, align] or
[ptr, align, offset]; predicate is always the constant `true`. Baseline
lowering already returned the original pointer unchanged (the CIR store
uses the loaded pointer, not any assume result), satisfying the
"conservative raw pointer" half of the acceptance criteria for free.

The gap: lower_assume ignored bundle_kind/bundle_args entirely and emitted
`assert_unchecked(true)` for the align form -- a vacuous, no-op assertion
that threw away the alignment fact instead of recording it.

Fix (src/frontend/lowerer/arithmetic.rs, lower_assume/assume_align_cond):
when bundle_kind decodes to AssumeBundleKind::Align, build a real condition
from bundle_args -- `(ptr as usize).wrapping_sub(offset as usize) %
(align as usize) == 0` (offset defaults to omitted) -- and assert_unchecked
that instead of the trivial predicate. This documents the alignment fact
directly in the generated code and preserves the same UB contract as
slate-04q.47.1: correct if the C alignment promise holds, immediate UB via
assert_unchecked if not, matching the C builtin's own contract. No new
"fact" datatype was needed since PointerFact/pointer_lattice.rs is a
whole-program interproc analysis for reference/slice recovery, which
alignment isn't part of yet -- left for a future fixup to consume this
assert_unchecked condition if warranted.

Added tests/fixtures/builtin_assume_aligned.c covering both the 2-arg and
3-arg (offset) forms with a runtime differential proving the assertion
holds for a genuinely 32-byte-aligned buffer. rewrites profile (93 tests)
passes.
