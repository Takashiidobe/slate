# slate-3amj.36 TargetAbi: -mrtd stdcall default and -fpcc/-freg-struct-return result shapes; opt-in linux-i686 dylink leg

_2026-11-17 20:50:51_

- bead: slate-3amj.36
- kind: feature
- area: crates/slate-parser/src/compiler_args.rs
- area: crates/slate-parser/src/sema/abi.rs
- area: crates/slate/tests/dylink.rs
- target: i686

Outcome: `-mrtd` and `-fpcc-struct-return`/`-freg-struct-return` are parsed and set `TargetAbi` instead of being dropped as "unsupported compiler flag ignored"; `-mrtd` code links and runs against native `-mrtd` code, tested by a new opt-in `linux-i686` dylink leg.

Gap and why it mattered: all four flags (and `-mno-rtd`) were warned about and ignored, so a TU built with them got cdecl / memory-return ABI while the native code it links with used stdcall / register returns. The bead claimed this was unobservable in one TU; it is observable across a native lib boundary, which `fixtures.dylink` tests, but that harness had no i686 leg.

Before (`--target=i686-unknown-linux-gnu -mrtd`):

```
⚠ unsupported compiler flag `-mrtd` ignored
fn @plain(a: i32, b: i32) -> i32          (cdecl; native callee does ret $8)
```

After:

```
fn @plain(...) -> i32 [abi=x86_cdecl stdcall(scalar, scalar) -> scalar]
```

and `-freg-struct-return` prints `coerce<i32>`/`coerce<i64>`/`coerce<f32>`/`coerce<f64>` for register-sized record results.

Implementation:
- compiler_args.rs: `Opt::Rtd` (switch, gcc+clang) and `Opt::StructReturn` (`-fpcc-struct-return`/`-freg-struct-return`, last wins). `-mrtd` on i686 sets `default_convention = X86Stdcall`; `TargetAbi::main_takes_default_convention` is true for gcc (gcc makes `main` stdcall, clang keeps cdecl). x86_64: gcc ignores `-mrtd`, clang rejects; other targets reject. clang rejects both struct-return flags off 32-bit x86; gcc keeps `-fpcc-struct-return` everywhere (records to memory on x86_64/AArch64/ARM) and ignores `-freg-struct-return` off x86.
- sema/abi.rs `forced_struct_return`: registers on `x86_cdecl` use clang's `shouldReturnTypeInRegister` (`win32_returns_in_register`) plus the single-float-element rule (`single_float_element`); empty record is `void` (clang) or `sret` (gcc). Memory makes `x86_win32` records and gcc non-empty records on sysv64/aapcs `sret`. Complex results are unaffected, as in both compilers.
- tests/dylink.rs: per-fixture `dylink.json` (`platforms`, `args`); opt-in `linux-i686` leg; native builds via `support::compile_c_cached`, crate regenerated through `fresh_tree` so unchanged fixtures rebuild nothing (linux leg 11.4s -> 3.3s, windows 33s -> 14.6s on rerun). update_filecheck.py reads `dylink.json` platforms.

Fixtures:
- crates/slate/tests/fixtures.dylink/abi_mrtd (linux-i686, `-mrtd`): stdcall exports, host callbacks called 1000x by the lib, variadic stays cdecl; libc reached through cdecl-typed pointers since `-mrtd` makes glibc declarations stdcall.
- crates/slate-parser/tests/fixtures/{clang,gcc}/linux/i686/abi_convention_flags.c, gcc/linux/x86_64/abi_convention_flags.c, error/clang/linux/x86_64/abi-flag-*.c.

Limits:
- Slate ignores explicit pass shapes on C-convention signatures, so `-freg-struct-return` (and `-mregparm` on cdecl) are recorded but not honored; the dylink fixture for it crashes. Agreed fix: module fact + `-Zreg-struct-return`/`-Zregparm=N` (slate-3amj.36.1, fixture sources in the bead).
- `-msseregparm` and `-mabi=ms|sysv` are still ignored (slate-3amj.36.2).

See: slate-3amj.59 (crate rustflags from a module fact), slate-parser-xjv8.
