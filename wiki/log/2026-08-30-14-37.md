# asm: fixed-register x86 constraint support + fail-loud unsupported asm

_2026-08-30 14:37:58_

Fixed slate-a28e.12 (zstd cpuid: __asm_result = 1; E0308). Root cause: extended
inline asm with x86 fixed-letter register constraints (a/b/c/d/S/D) and GCC
explicit-register-variable syntax (asm("r0")) were not modeled; lower_asm fell
back to a broken scalar-materialization path that wrote a sentinel int literal
into the multi-output struct temp instead of real register bindings.

Added AsmRegConstraint{Generic, FixedLetter, ExplicitName} in asm.rs, parsed
from GCC/Clang constraint strings (including the {name} curly-brace form Clang
normalizes fixed letters and explicit-register-variables into on any arch).
asm_reg_for_constraint re-derives register width (8/16/32/64-bit spelling)
from the operand's actual type rather than trusting LLVM's canonical 16-bit
constraint spelling, which is wrong for Rust's asm! register-class sizing.

Per explicit direction: replaced every silent fallback/guess in
lower_extended_asm with diagnostics.error(...) + abort-this-statement, so
unrecognized constraint shapes fail loudly instead of emitting plausible-but-
wrong code. Also added "g"/"imr" (GCC general operand) -> generic register
class, since register is always a valid choice among that constraint's
alternatives — needed to keep gcc-torture pr81588 passing under the new
fail-loud path.

Caught two more bugs via standalone compile of generated Rust (not just
eyeballing): (1) register width defaulted to 16-bit ("ax") instead of the
operand's real width: fixed by threading operand Type through
asm_reg_for_constraint. (2) explicit-register operands were still referenced
in trailing template-placeholder comments, which rustc forbids outright even
in dead comment text: fixed via constraint_is_explicit_register gating in
translate_asm_template.

New fixture: tests/fixtures/asm_fixed_register_cpuid.c (cpuid leaf 1, a/c/d
fixed outputs + a fixed input, ebx clobber). Passes lowering+rewrites
differential/FileCheck, full rewrites suite (90/90), full lowering suite
(10/10).

Zstd re-check: original __asm_result E0308 gone. Surfaced two unrelated
issues, filed separately: slate-a28e.14 (real ZSTD_cpuid binds ebx too, which
rustc rejects as an explicit asm operand since LLVM reserves rbx internally —
needs a push/pop-rbx workaround, not a constraint-parsing fix) and the
pre-existing addr_of_mut FSE_repeat/u32 mismatch (untracked, separate bug).
