# for-range: recover counted loops through synthetic guard temporaries

_2026-09-02 17:17:38_

slate-y0qs.10: ForRangeRecover (for_range.rs) now sees through a break guard
routed through a pure, single-use boolean temp, and no longer requires the
induction variable's `let` to sit immediately before the loop.

## Two independent gaps closed
1. Guard temp: `let _v = i < n; if !_v { break; }` (produced whenever the
   comparison is computed before negation, e.g. loops nested inside an
   else-branch in giflib) wasn't recognized -- only the direct
   `if !(i < n) { break; }` shape was. Added negated_lt_guard_through_temp:
   resolves the guard by substituting the temp's init back into the if's
   cond (reusing Expr::substitute_var) and re-running the existing
   extract_negated_lt match, so the safety argument is identical to the
   existing bound-let case, not a new pattern.
2. Non-adjacent induction var decl: plan() required `let i` at list[index-2],
   immediately before `i = 0;`/loop. Real C code often declares `i` earlier
   in an outer block. Switched to arena.definition(ind_var) (existing O(1)
   def lookup) to locate the Let wherever it lives, and track its own
   (parent, list_index) for removal separately from the loop's list --
   apply() no longer assumes let_id and assign_start_id share a list.

## Guard notes
- negated_lt_guard_through_temp requires the temp be pure (no side effects)
  and single-use (arena.def_use_neighbors == [guard_if_id]) -- same
  adjacency-free-of-effects reasoning inline_temps.rs uses, not re-derived.
- Did NOT extend to `<=`, `>`, `!=`, or descending loops -- those need a new
  inclusive-range AST/codegen variant (`<=`) or different safety arguments
  entirely (`!=` can loop forever past a skipped bound); tracked as a
  follow-up, not attempted here.

Full `cargo nextest r --release --profile rewrites` (92/92) green, fmt/clippy
clean. giflib (translate-project --lib): for-loop recovery 4 -> 18 (loop{}
count 226 -> 220), matching the acceptance criteria directly. No new fixture
