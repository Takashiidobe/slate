# Accept AVX-512 opmask and broadcast decorators in MS __asm operands

_2026-10-12 08:05:31_

slate-parser-v74.1.15: clang-cl accepts `vaddpd zmm8 {k1}{z}, ...` and `[c]{1to4}` in __asm blocks; slate rejected at `{` because the MS-asm tokenizer treated every `{` as a block delimiter.

- parser/ms_asm.rs: decorator_end() classifies a `{` as a decorator when it follows a token on the same line that is not __asm, a newline, brace or semicolon; chained {..}{..} groups are consumed together. mark_ms_asm_statement and instruction_end skip them so depth tracking is unaffected.
- OperandParser::decorated wraps the operand in the new MsAsmExpr::Decorated { operand, decorators } (spellings like "{k1}").
- sema/ms_asm.rs: the decorator text is emitted right after the operand (no space, so zmm8{k1}; clang keeps the source space, LLVM's Intel parser accepts both); an empty decorator emits nothing so existing templates are unchanged. names.rs and reachability.rs recurse through Decorated.
- Not supported: operand-position decorators such as the trailing {rn-sae} operand.
- Fixtures: clang/windows/x86_64/ms_asm_avx512_opmask.c and the migrated suites/clang-test CodeGen__ms-inline-asm-avx512.c. Clang oracle accepts all of them. cl.exe x64 has no inline asm.
- Docs: ast-grammar, msvc-asm. Parser profile 8245/8245.
