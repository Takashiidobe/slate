# slate-3amj.36.4 AbiSignature: gcc -msseregparm marks sseregparm float/double signatures on i686 and slate rejects them

_2026-11-19 14:58:43_

- bead: slate-3amj.36.4
- kind: feature
- area: crates/slate-parser/src/sema/abi.rs
- area: crates/slate-parser/src/compiler_args.rs
- area: crates/slate/src/frontend/lowerer
- flavor: gcc
- target: i686

Outcome: gcc `-msseregparm` is parsed; on i686 every signature that would pass a float or double in XMM registers carries `sseregparm` in the IR and slate rejects it with a barrier instead of silently miscompiling.

Gap and why it mattered: the flag was ignored, so a `double f(double)` crossing a native boundary was passed on the x87/stack convention while gcc's side used XMM0. rustc has no such convention, so the only correct answer is a barrier.

Before (`--flavor=gcc -target=i686-unknown-linux-gnu -msseregparm`):

```
⚠ unsupported compiler flag `-msseregparm` ignored
fn @sq(x: f64) -> f64 [linkage=internal]
```

After:

```
fn @sq(x: f64) -> f64 [abi=x86_cdecl sseregparm(scalar) -> scalar]
call<f64, abi=x86_cdecl sseregparm(scalar) -> scalar>(read<ptr<fn(f64) -> f64>>(%f), ...)
slate: function sq: -msseregparm float or double in XMM registers rustc cannot pass
```

Implementation:
- compiler_args.rs: `Opt::SseRegParm` (gcc only; clang reports unknown option). `TargetAbi::sse_regparm` is set on 32-bit x86 only; gcc ignores it on x86_64.
- sema/abi.rs `from_parts`: `AbiSignature::sse_regparm` when the result is f32/f64, or the function is not variadic and a fixed parameter is f32/f64 (matches gcc: `double vr(int, ...)` returns in XMM0, `int vn(double, ...)` reads `d` from the stack). `long double` and vectorcall are unaffected. Printed ` sseregparm` after `regparm=`.
- crates/slate lowerer: `function_abi` rejects definitions and called declarations; `values.rs` rejects indirect calls carrying it. Unused `<math.h>` declarations are not lowered, so they don't trip it.

Fixtures:
- crates/slate-parser/tests/fixtures/gcc/linux/i686/abi_sseregparm.c (SSE, plus `-mabi=ms` as an i686 no-op), error/clang/linux/i686/abi-flag-msseregparm.c.
- crates/slate/tests/fixtures.unsupported/gcc/i686/sseregparm_float.c (barrier), crates/slate/tests/fixtures/gcc/i686/sseregparm_integers.c (integer-only code with `<math.h>` still runs).

Limits: an internal function whose address is never taken is rejected too, although both sides would be Rust.

See: slate-3amj.36.2 (-mabi=ms|sysv).
