# branch-hint builtins beyond __builtin_expect are already CIR-supported (slate-04q.47.3)

_2026-09-04 11:48:54_

Both remaining branch-hint builtins already lower correctly with zero
lowerer changes; CIRGenBuiltin.cpp (llvm-project/clang/lib/CIR/CodeGen/CIRGenBuiltin.cpp)
handles them directly:

- __builtin_expect_with_probability shares cir::ExpectOp with plain
  __builtin_expect (Builtin::BI__builtin_expect and
  BI__builtin_expect_with_probability are one switch case); the only
  difference is an extra `prob` FloatAttr on the op. slate's existing
  lower_expect (src/frontend/lowerer/arithmetic.rs) already ignores
  `expected`/`prob` and just returns `op.val`, so it was already correct.
  Note: at OptimizationLevel == 0 CIRGen skips cir.expect entirely and
  returns the argument value directly -- cir.expect is only emitted at
  -O1+, which is why the existing control_flow_builtin_ops.c fixture
  (built at the default -O0) never actually exercises Op::Expect despite
  using __builtin_expect.
- __builtin_unpredictable has no CIR op at all, at any optimization level:
  CIRGen's comment says LLVM has no corresponding intrinsic and metadata
  should attach directly to branch/switch instructions instead, so it
  always CIRGens to a bare `emitScalarExpr(arg0)` -- already identity,
  nothing to lower.

Added tests/fixtures/branch_hint_builtins.c (with a `-O1` clang-arg
override registered in tests/differential.rs so cir.expect is actually
emitted) covering __builtin_expect, __builtin_expect_with_probability, and
__builtin_unpredictable, each wrapping a side-effecting call (`bump`)
verified to run exactly once via a global counter. rewrites profile
(93 tests) passes.
