# slate-yar4.8 printf lowering: keep calls that read underaligned fields

_2026-11-23 14:13:32_

- bead: slate-yar4.8
- kind: bug
- area: crates/slate-analysis/src/printf.rs
- area: crates/slate/src/frontend/lowerer/printf.rs

Outcome: Slate preserves C `printf` for an underaligned field read and still
emits `println!` for an ordinary field.

Symptom: Rust emitted `println!("{}", tight.inner.value)` and rustc rejected it
with E0793. The C call reads the field by value, while the Rust macro borrows its
argument.

Reproducer:

```c
#include <stdio.h>
struct Inner { int value; };
#pragma pack(push, 1)
struct Tight { char tag; struct Inner inner; };
#pragma pack(pop)
int main(void) {
  struct Tight tight = {0, {42}};
  printf("%d\n", tight.inner.value);
}
```

Cause: the formatting pass looked for literals and calls in the Rust AST, which
lacks the argument place layout.

Fix: `slate-analysis` recognizes literal decimal formats on typed `printf` calls
and walks argument place projections. `lowerer/printf.rs` emits Rust formatting
from the facts. It finishes after the Rust shape rules and before unsafe
placement to preserve flush and writer-result handling. Macro template
validation and merge compare bodies with the format facts cleared.

Regression test: `crates/slate/tests/fixtures/printf_packed_field.c`. The packed
field call stays on the C path and flushes before `println!` prints the ordinary
field. `crates/slate/tests/fixtures.merge/macro_places.c` passes the packed
member directly to `printf` under `--merge`.
