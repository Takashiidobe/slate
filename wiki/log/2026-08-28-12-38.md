# pointer lattice: fix U-widening and W-on-ownership gaps

_2026-08-28 12:38:16_

The core pointer lattice table (pointer-capability-lattice.md) only listed 7
of 16 (W,U,F,O) combinations and fell through an implicit catch-all for the
rest. Two of those catch-all rows were bugs, not just undocumented:

1. `&T`/`&[T]` required `U=false`. `U` starts true and only flips false on
   disproof of aliasing, so the *common* case — a pointer with no aliasing
   evidence yet — never matched and fell to raw pointer instead.
2. `Owned`/`Vec` required `W=false`. Writing through something you own
   doesn't revoke ownership, but any mutated malloc'd buffer (the
   overwhelmingly common real case) missed these rows too.

Fixed `PointerFact::resolved` in `src/backend/interproc/pointer_lattice.rs`
to make `U` gate only ownership (paired with `F`) and exclusivity (paired
with `W`), never the plain reference rows; and to make `W` never block the
ownership rows. The new match is exhaustive over all 16 combinations (no
wildcard arm — rustc confirms exhaustiveness), replacing the old catch-all.
Doc table in `pointer-capability-lattice.md` updated to match, all 16 rows
now listed explicitly with the collapsed cases annotated.
