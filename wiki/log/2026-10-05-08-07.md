# Packed enums take the narrowest underlying type

_2026-10-05 08:07:33_

slate-parser-6x05.38.30: __attribute__((packed)) on an enum definition was ignored in every position, so sizeof stayed 4. The kernel spells it '} __packed;' (asm/cpuid/types.h cache/tlb table types, enum rw_hint) with static_assert(sizeof == 1).

Fix (sema/types.rs, TagBody::Enum): when the tag's attributes carry Packed and there is no fixed type, the candidate list for the underlying type starts with signed/unsigned char and short before int, long, long long. Signedness still comes from whether any value is negative. Enumerators keep int when every value fits.

Matches clang and gcc: { A = 200 } is u8, { -1, 200 } is i16, { 0x10000 } stays u32. Leading (enum __attribute__((packed)) E), trailing, trailing with a declarator, and typedef forms all apply. A later 'enum E __attribute__((packed));' after the definition does nothing (clang warns).

Fixture: clang/linux/x86_64/ir_packed_enum.c (failed before). Regenerated ms_struct_layout.c (i686, clang agrees P is 1 byte) and both gcc-dg enum-incomplete-2.c copies.

Filed: __mode__ on an enum definition is also ignored (gcc/clang size 1 for __byte__).
