# gcc-torture cluster: va_list, vectors, naked functions

_2026-08-16 00:00:00_

- **va_list fixture sweep** (`24d0bd18`, `1b7ddfa4`, `7c967396`): closed out remaining va_list gcc-torture failures. `24d0bd18` handles cloning a `va_list` inside a function (C's `va_copy` semantics) in `frontend/lowerer/storage.rs`; `7c967396` fixed codegen-level va_list issues (22 lines, `backend/codegen.rs`); `1b7ddfa4` wrote a 215-line `handoffs/va-list-handoff.md` design writeup (now the source for `wiki/concepts/va-list-lowering.md`) covering the native-vs-boxed dispatch and the va_list-pointer double-indirection bug.
- **Naked functions** (`2eb75eb1`): added `Attr::Naked` → `unsafe(naked)` codegen. Noted as blocked upstream in Clang IR for full coverage — CIR doesn't yet expose everything needed to lower a naked function's body faithfully, so this covers the attribute/declaration side only.
- **Vector ops via transmute** (`bfa69635`, `e57285c5`): closed out a set of vector-typed gcc-torture cases whose fix was routing the operation through a `transmute` between the CIR vector type and a `std::simd`-shaped Rust type, rather than a bespoke per-op lowering; `e57285c5` promoted the newly-fixed cases from `.unsupported` to the passing corpus.
- **The `.ignored` bucket** (`2567419b`): introduced `tests/fixtures.gcc-torture.ignored/` as a third triage bucket alongside supported/unsupported — for cases that are genuine C-standard UB (e.g. `strlen-5`, which reads past one struct member's bound into a sibling member's memory by relying on incidental layout — different from the flexible-array-member idiom, which is UB pre-C99 but a de facto supported contract). `.unsupported` is tracked work; `.ignored` is UB slate correctly declines to reproduce, and isn't scanned by any test so it doesn't count against triage progress.
- **`3562d625`**: fixed a case-testsuite regression where long double wasn't passed via pointer (by-value ABI) correctly in `runtime_support.rs`.
- **`695440b8`**: fixed most of the remaining va_args cases via a `cir/ir.rs` change to how variadic argument types are parsed.

- **`4a58eaaf`**: moved additional fixtures to unsupported after Clang IR itself dropped x86_64 struct padding representation in a CIR version bump — a corpus regression driven by upstream, not a slate bug.
