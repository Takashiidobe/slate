# GNU forward parameter declarations

_2026-11-08 21:32:56_

slate-parser-cxg.18.3: gcc accepts int f(int n; int (*a)[n], int n). In the gcc flavor parse_parameters (parser/declarator.rs) treats ';' as the end of a forward list; the lists go in the new ast::ParameterList::Prototype.forward, parameters is the list after the last ';'. Sema: names.rs bind_parameters binds forward names first and maps a later parameter of the same name (and repeated forward declarations) to that binding; the checker (assertion.rs declare_parameters) and lowering (module.rs parameters) declare forward types first, so VLA bounds that name a later parameter type and lower to reads of the real parameter. clang rejects forward declarations, so the clang flavor still errors. Fixture gcc/linux/x86_64/forward_parameter_declarations.c; migrated gcc.dg parm-forwdecl-2/3/4, Wmultiple-parameter-fwd-decl-lists, pr109970. ast-spec and ast-grammar updated.
