# Probe utime.h/threads.h/crypt.h; fix real cnd_t alignment bug

_2026-09-08 08:58:57_

Triaged tests/ header-usage grep for the next probe-expansion candidates
(slate-b66b.13.6, plus follow-on for .3). Added to tools/probes/linux-libc-abi.c:

- struct utimbuf (utime.h): size/align/offsets.
- thrd_t/tss_t/mtx_t/cnd_t/once_flag (threads.h): size/align.
- struct crypt_data (crypt.h): size/align, gated to musl-any-arch plus
  glibc x86/x86_64 -- the local arm/aarch64 glibc cross sysroots here don't
  bundle libxcrypt headers (a toolchain packaging gap, not an ABI
  difference); previously this would have hard-failed the entire oracle
  compile for those targets rather than just the crypt records.

The threads.h probe caught a real, pre-existing shim bug: align:cnd_t
mismatched on musl/arm (oracle=4, shim=8). libc-shim/include/threads.h
hand-rolled mtx_t/cnd_t using raw __aarch64__/__LP64__ compiler builtins
(inconsistent with the rest of the shim's __SLATE_ARCH_* macros) and a
hardcoded `long long __align` for cnd_t. Both real glibc and musl define
mtx_t/cnd_t as byte-identical to pthread_mutex_t/pthread_cond_t, which the
shim's bits/types.h already models correctly per arch/libc. Fixed by
aliasing mtx_t/cnd_t to pthread_mutex_t/pthread_cond_t directly, deleting
the duplicate logic.

Verified: tools/libc-abi-matrix.py green across all 4 arches x 2 libcs,
cargo nextest --profile libc 37/37.

Deprioritized for this probe (out of scope this pass): stdatomic.h (compiler-
provided header, no libc ABI variance), uchar.h/stdalign.h/stdckdint.h/
stdnoreturn.h (fixed-size language features, no struct layout to probe),
sys/prctl.h and unwind.h (only referenced from tests/fixtures.gcc-dg.unsupported,
not yet implemented in slate).
