# trust CIR field shape for arrays of vectors

_2026-09-06 10:44:27_

`torture__pr52402` failed to build: `struct T { v4si i[2]; }` lowered to
`i: [i32; 2]`, so `addr_of!(t.i[0])` gave `*const i32` where the vector
return type `[i32; 4]` was required.

The Clang AST loses the vector shape of a typedef'd `v4si`, so an array of
vectors arrives as `CType::Array(Int, 2)` while CIR has
`!cir.array<!cir.vector<4 x !s32i> x 2>`. The existing "trust CIR" rule for
record fields (added in 2309dc68) only fired when the AST type was _not_ an
array, which covered a bare `v4si` field but not `v4si i[2]`.

Replaced that guard with `cir_array_shape_is_deeper`: trust the CIR field
type whenever its array nesting depth exceeds the AST type's. Depth 0 vs 1
is the old bare-vector case; depth 1 vs 2 is the new array-of-vector case.
Applied at both sites that pick a record field type (`record_field_type_at`
and `lower_record_def`'s `lower_field`).

`tests/fixtures.gcc-dg/torture__pr52402.c` now passes. `flexible_array_member`
and the `gnu_symbol_pragmas` cross-TU FileCheck failures in the lowering
profile are pre-existing in the working tree (verified: generated output for
`flexible_array_member` is byte-identical with and without this change).
