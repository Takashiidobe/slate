# slate-p58o.3.38: va_list and va_* lowering

_2026-09-30 21:30:23_

Lowered va_list for slate-p58o.3.38 (lowerer.rs).

- ir::Type::VaList -> rust::Type::VaList (core::ffi::VaList<'_>, stable
  since 1.99). Locals declared without an initializer start zeroed; on
  x86_64 VaListInner is ints and raw pointers, so that is valid.
- va_start(ap) -> ap = __va_args.clone(), where __va_args is the C-variadic
  parameter a variadic definition will get (3.39).
- va_arg<T>(ap) -> unsafe { ap.next_arg::<T>() }.
- va_copy(dst, src) -> dst = src.clone(); va_end -> nothing (Drop is va_end).
- read<va_list> (passing ap to vprintf/vsnprintf or a user function) ->
  ap.clone(). VaList is passed indirectly in the C ABI, matching the x86_64
  array decay. The caller's ap is indeterminate after the call in C, so not
  advancing it is a valid outcome.
- Write statements now go through a shared lower_assignment helper.

Fixture: va_list_forwarding.c (unsupported). It covers vprintf/vsnprintf
forwarding, a va_list parameter helper, int/double/pointer/long long
va_arg, va_copy, and va_start restarted after va_end. Every function that
takes a va_list now lowers; the only remaining barriers are 'variadic
definition' (3.39). It uses vprintf because stdout hits an unrelated
_IO_FILE field barrier.

Full slate profile green, no promotions.
