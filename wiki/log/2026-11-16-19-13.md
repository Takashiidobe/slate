# slate-f2zu.14.34.34 noreturn call sites: calls to C noreturn functions lowered as returning, so LLVM inlined machine_real_restart's ljmp past objtool's STACK_FRAME_NON_STANDARD

_2026-11-16 19:13:19_

- bead: slate-f2zu.14.34.34
- kind: bug
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/tests/fixtures

Outcome: a statement-level direct call to a C `noreturn` function is followed by
`unsafe { core::hint::unreachable_unchecked() }`, like clang's
`call; unreachable`, so LLVM sees the call site as cold and stops inlining
noreturn callees.

Symptom: objtool on the translated vmlinux.o reported
`native_machine_emergency_restart+0x166: unsupported instruction in callable function`.
That was the `ljmp *(%rax)` of `machine_real_restart()`
(arch/x86/kernel/reboot.c), inlined into its caller. The kernel exempts only the
`machine_real_restart` symbol via `STACK_FRAME_NON_STANDARD`. Native clang keeps
it out of line.

Reproducer:

    void __attribute__((noreturn)) a(unsigned t) { flag = t; __builtin_unreachable(); }
    void c(int x) { if (x == 98) { a(0); flag = 113; } }

Before, `c` lowered `a(0u32); flag = 113;`: the IR's `[noreturn]` on `a` reached
only libc support signatures (`-> !`), so the call looked like it returned.

Cause (measured with a rustc/clang probe of the reboot shape, -O2):

- clang with noreturn: not inlined; clang without noreturn: inlined.
- rustc as slate lowered it: inlined, also with -Zinline-mir=no (LLVM inliner,
  not MIR). LLVM already infers `noreturn` on the callee, but the caller's block
  continues, so it is not cold.
- rustc with `-> !` or with `unreachable_unchecked()` after the call: not
  inlined.

Fix: `FunctionName.noreturn` carries `FunctionSemantics::noreturn`;
`Tables::returns_through_unit` holds for noreturn functions that are not
builtins and not libc support functions already lowered as `-> !`.
`lower_statement` (lowerer/statements.rs) appends the unreachable after an
`ir::Statement::Expression` that is such a direct call. Signatures stay `()`:
`-> !` would break function pointers to noreturn functions (`Some(finish)` into
`Option<unsafe extern "C-unwind" fn(i32)>`), and noreturn is not part of the C
pointer type.

Regression test: crates/slate/tests/fixtures/noreturn*call_site.c (noreturn and
\_Noreturn callees, dead C after the call, a pointer to a noreturn function).
Regenerated: assert*\*, c11, c23_language, gnu_attributes, noreturn_attribute,
noreturn_c11_spelling, noreturn_prototype, and
fixtures.merge/signature_compatible.c (the unreachable is `#[cfg(unix)]`: the
MSVC flavor ignores `__attribute__((noreturn))`, as cl.exe does). Also promoted
flag_declspec.c and flag_lax_vector_conversions.c, which pass since unknown
flags warn (slate-f2zu.14.40.3).

Limits: indirect calls and calls in expression position (`x = f() + die()`) are
not marked; the kernel objtool warning is verified only by the probe until the
next `--from translate` run. C code after the call stays in the output and draws
rustc's unreachable-code warning.

See: slate-jep.3 (earlier `-> !` lowering, lost), slate-f2zu.14.34.27
(cleanup-closure UACCESS warnings).
