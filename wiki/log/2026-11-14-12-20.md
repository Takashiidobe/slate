# slate-f2zu.14.5 asm: stack-pointer register variable operand (ASM_CALL_CONSTRAINT current_stack_pointer rsp) lowered, nostack cleared

_2026-11-14 12:20:19_

- bead: slate-f2zu.14.5
- kind: feature
- area: crates/slate-parser/src/sema/asm.rs
- area: crates/slate/src/frontend/lowerer/asm.rs
- target: x86_64

Outcome: an x86_64 asm operand bound to the stack-pointer register variable (kernel `ASM_CALL_CONSTRAINT`, `"+r"(current_stack_pointer)` with `register unsigned long current_stack_pointer asm("rsp")`) now lowers. The asm is no longer marked `nostack`, so a `call` inside it is sound.

## Gap and why it mattered

Every one of the 1169 'register variable needs explicit register lowering' barriers (518 kernel TUs) came from `ASM_CALL_CONSTRAINT`. It is used by preempt.h `__preempt_schedule`, uaccess.h get_user/put_user, `__arch_hweight32/64`, clear_pages, paravirt PVOP calls and sync_core. The template never names the operand. It exists to tell the compiler that the asm makes a call. Rust forbids rsp as an `asm!` operand.

A second problem was in the IR. The parser marked every extended asm `nostack`, so `asm volatile("call thunk" : "+r"(current_stack_pointer))` was `[options=nostack]`. That would let Rust keep live data in the red zone across a `call` that pushes.

## Before

    register unsigned long current_stack_pointer __asm__("rsp");
    asm volatile("call slate_sp_helper" : "+r"(current_stack_pointer) : : "memory");

`statement asm: register variable needs explicit register lowering`; the IR had `[options=nostack]`.

## After

    core::arch::asm!("call slate_sp_helper", options(att_syntax));
    core::arch::asm!("movq %rsp, {0:r}", lateout(reg) __t0, options(pure, nomem, att_syntax));

## Implementation

- Parser `options()` (crates/slate-parser/src/sema/asm.rs): `nostack` is off when an x86 operand selects `Explicit` with canonical `sp`.
- Slate operand loop (crates/slate/src/frontend/lowerer/asm.rs): an x86 `Explicit(sp)` operand pushes `Slot::Register("sp")` and passes no Rust operand. There is no read or writeback of the register global.
  - A template reference prints the register by name through `explicit_reference` (`%rsp`, or `%esp` under `%k`).
  - A referenced output or in-out stays a barrier ('stack pointer output referenced in the template').

## Fixture

- crates/slate/tests/fixtures/x86_64/asm_stack_pointer_operand.c: a `call` into a global_asm helper, popcnt with the constraint, and an `"r"(current_stack_pointer)` read. Output is "42 8 2 1".
- crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/ir_asm_stack_pointer_operand.c: no `nostack` with the stack pointer operand; another asm in the same file keeps it.

Kernel TUs: block/ioctl.c 19 -> 0 blocked, sound/core/pcm_native.c 28 -> 1, init/main.c 7 -> 5. No register-variable barriers remain in any of them.

Limits: i686 esp has no fixture, and aarch64 `sp` is not accepted by `holds()`.
