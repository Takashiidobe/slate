# slate-f2zu.14 e2e.py linux: kernel-wide lowering-barrier sweep and clustered barriers.md

_2026-11-14 11:13:01_

- bead: slate-f2zu.14
- kind: feature
- area: tools/corpus/e2e.py
- corpus: linux

Outcome: tools/corpus/e2e.py has a `linux` recipe, and `e2e.py linux --until barriers` runs lowering-barriers over every kernel TU and writes a clustered report to target/corpus/linux/clang/barriers.md.

- Recipe: TranslationOnly(required_args=["-D__KERNEL__"]) picks every compile_commands entry built with -D__KERNEL__ (3005 unique C TUs, including boot, vdso and realmode). The 194 host-tool entries (scripts/, arch/x86/tools) are excluded because they are build tools, not part of the kernel.
- barriers.md: cluster keys now drop global names and IR expression dumps, normalize @typeN, %N, operand and alternative numbers. Each cluster lists its top origins (the spelled-at macro location, else the site) and top scopes (enclosing function). A TU that fails before lowering records the miette `×` line instead of the last box-drawing line.
- Baseline 2026-11-14: 3005 TUs, 2571 with barriers, 29393 of 278876 functions and globals blocked. Filed as slate-f2zu.14.1 to .9, with the largest clusters being asm "i" operands that are constant only after inlining (arch_static_branch), enum type barriers in drm, static compound-literal initializers (DEFINE_SPINLOCK, static keys, tracepoints), and %a per-cpu get_current.
- Regression found: 11 TUs no longer parse because an empty macro argument after ')' is pasted as ')foo' (slate-f2zu.14.1).

Limits: the translate stage still runs translate-project over all units, which stops at the first barrier, so it is not useful for the kernel yet.
