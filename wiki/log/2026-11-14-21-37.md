# slate-f2zu.14.34.2 core paths: generated Rust uses core:: instead of std:: for ptr/mem/ffi/simd/atomic/cmp items

_2026-11-14 21:37:01_

- bead: slate-f2zu.14.34.2
- kind: rewrite
- area: crates/slate/src/backend
- area: crates/slate/src/frontend
- area: crates/slate/tests

Outcome: generated Rust spells every item that exists in core as `core::` (ptr, mem, hint, ffi, slice, str, simd, cmp, cell, ops, sync::atomic), in the translator's internal strings as well as the output, so hosted and freestanding crates share one spelling.

Before (any fixture): `unsafe { fflush(std::ptr::null_mut()) }`, `std::mem::zeroed()`, `argv: *mut *mut std::ffi::c_char`.
After: `core::ptr::null_mut()`, `core::mem::zeroed()`, `core::ffi::c_char`.

Rule: the string is changed at every emit site and every matcher together (rewrites compare paths as strings, e.g. `null_compare` `starts_with("core::ptr::null::<")`, `slot_promote` `core::mem::MaybeUninit::uninit`, `dead_store`, `literal_casts`, `inline_temps` volatile effects, `pointer_lattice` null detection), so no rewrite changes behavior. A print-time std->core mapping was rejected: internal and printed spellings would diverge. Changed: codegen.rs literals (atomic orderings, size_of/align_of/offset_of, addr_of!, transmute, copy_nonoverlapping, write_bytes, null_mut), lowerer strings and `["core", ...]` path segments, and the support modules (frontend/support: blocks, alloca's UnsafeCell/c_void, vector ops, libatomic, libgomp).

Still std (hosted-only, for slate-f2zu.14.34.3 to gate or rewrite): `std::io::stdout`/`Write::flush` (printf_format), `std::process::exit/abort` (libc_call, reducible), `std::env::var` (getenv_var), `std::thread::{scope,Builder}` (OpenMP), `std::arch::is_x86_feature_detected` (target_features), `std::alloc` in the alloca support module, and the build.rs `std::env` in c_shim (host build script, stays std).

Verification: full FileCheck regen (983 fixture files). Each changed block was compared with HEAD after mapping core:: back to std::. Leftover differences were checked by translating with the HEAD binary and the new one: rustfmt rewraps (core is one char longer); `__slate_intrinsic_<hash>` names (hash over signature text containing the path) and the declaration order that follows; macro_rules variant numbering (`SHOW__5`/`NULL_GUARD__2`, numbered by body text, call sites renumbered consistently); and blocks that were already stale but passed because FileCheck matches substrings (`11` vs `11i32`). slate profile 40/40.

Kernel: ~/slate-translated/slate-linux not re-translated; deferred to one full re-translation at the end of slate-f2zu.14.34.
