# slate-5q63.22.3 i386-unknown-none.json: TargetSpec serde struct replaces format!-built rustc target spec JSON

_2026-11-18 15:49:44_

- bead: slate-5q63.22.3
- kind: feature

- area: crates/slate/src/project/build_target.rs

Outcome: the freestanding i386 rustc target spec (i386-unknown-none.json) is a typed `project::target_spec::TargetSpec` serialized with serde_json instead of a format! raw string with {{ escapes.

Gap and why it mattered:
build_target::i386_spec returned a hand-written JSON string, spliced `cpu` and the -m16 feature suffix in with format!, and escaped the stack-probes object braces by hand. BuildTarget.spec was an opaque String.

Before:
    format!(r#"{{ "arch": "x86", "cpu": "{cpu}", ... "features": "-mmx,-sse,+soft-float{mode}", ... "stack-probes": {{ "kind": "inline" }} }}"#)

After:
    TargetSpec { arch: Arch::X86, cpu, features: Features(vec![Feature::off("mmx"), Feature::off("sse"), Feature::on("soft-float"), ..]),
                 stack_probes: StackProbes::Inline, .. }.to_json()

Implementation:
- crates/slate/src/project/target_spec.rs: `TargetSpec` (kebab-case Serialize, fields in rustc's order), enums for the fixed values (Arch, Os, PanicStrategy, RustcAbi, LinkerFlavor, RelocationModel, CrtObjectsFallback "false", StackProbes tagged `{"kind": "inline"}`), `Features(Vec<Feature>)` serialized as the comma-joined "+name"/"-name" string. `to_json` = to_string_pretty + newline.
- build_target.rs: `BuildTarget.spec: Option<TargetSpec>`; i386_spec adds +16bit-mode,-32bit-mode for -m16; write_config serializes it.

Verified: freestanding-m16 (differential::freestanding_projects_build_for_bare_metal_targets) writes JSON whose parsed values and key order equal the old template's; only the stack-probes object is now pretty-printed across lines. That test builds the crate with -Zbuild-std against the spec and passes; arch_mode_projects_select_their_rust_target passes.
