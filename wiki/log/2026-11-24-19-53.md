# slate-e36k.15 __builtin_bitreverse8/16/32/64: lower runtime bit reversal

_2026-11-24 19:53:32_

- bead: slate-e36k.15
- kind: bug
- area: crates/slate/src/frontend/lowerer/values.rs
- area: crates/slate/tests/fixtures

Outcome: Clang's four fixed-width __builtin_bitreverse variants translate on runtime operands on all four Linux test targets.

## Symptom and reproducer

```c
unsigned char reverse_byte(unsigned char value) {
  return __builtin_bitreverse8(value);
}
```

Translation previously reported `builtin without a lowering` despite
the typed IR declaring a call with matching unsigned argument and result widths.

## Fix

The direct-call branch in FunctionLowerer::lower_value now emits
the matching unsigned Rust type's `reverse_bits` associated function.
It supplies a concrete type for literals and evaluates the operand
once. open_coded_builtin uses the same lookup to keep the synthetic C
declarations out of the Rust extern block.

## Regression test

Promoted and extended crates/slate/tests/fixtures/builtin_bitreverse8.c.
It checks runtime operands at 8, 16, 32, and 64 bits, starting with
0x12 -> 0x48. The existing integer_bit_builtin_ops.c also passed the
unsupported ratchet on all four Linux targets and moved to the supported
suite.
