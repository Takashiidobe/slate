# Probe Phase 3 arithmetic, conversion, update, and static-local contracts e2e

_2026-10-01 08:27:02_

Beads closed: slate-p58o.3.25, .3.26, .3.27, .3.28, .3.30, .3.31. All ten named fixtures (shl, shr, void_int_cast_view, typedef_ptr_signedness, floats, casts, decrement, compound_assignments, lazy_singleton, static_globals) already passed raw slate lowering, but they were too thin to cover the acceptance contracts.

Added six UB-free differential fixtures (checked with clang -fsanitize=undefined,float-cast-overflow and -Wunsequenced):
- shift_contracts.c: mixed-width shift amounts, signed fill, promotion + truncation in <<=/>>=.
- pointer_enum_conversions.c: enum<->int edge values, ptr<->(u)intptr_t, null, (_Bool)ptr.
- float_arith_compare.c: NaN/inf/-0.0 comparisons and float-precision arithmetic.
- float_int_conversions.c: truncation, boundaries, int64->float rounding, f64->f32, float->_Bool.
- update_results.c: prefix/postfix results across types, a[i++]++ and ++*f() single evaluation.
- static_local_lifetime.c: persistence, init-once, recursion, loop-scoped statics.

Five passed as-is. static_local_lifetime exposed a real bug: slate-parser hoists static locals into module.globals under their bare C name, so two functions each declaring static int count emitted duplicate static mut count items. A static local named like a function would also collide, since fns and statics share Rust's value namespace.

Fix (lowerer/names.rs global_names, used by ModuleLowerer::new): an internal-linkage global whose Rust name is shared by another global id or a function becomes name_<id>. External-linkage names stay exact. The renamed set also feeds the local-shadowing check.

Rewritten-variant checks in the beads' acceptance criteria remain untestable until rewrites are enabled for the slate frontend.
