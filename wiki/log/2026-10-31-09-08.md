# Reuse --merge compiles with matching preprocessed output

_2026-10-31 09:08:41_

slate-nfq8.7: refined --merge now preprocesses each row and reuses the result of an earlier row of the same target and unit when a fingerprint matches. The fingerprint hashes nodes (Span hash skips the global NodeId), file paths, __BIGGEST_ALIGNMENT__ and directive diagnostics, so a row that only adds #error stays infeasible. --merge-full-table does not reuse. The parser splits parse_file into preprocess_for_parse and parse_preprocessed so a row is preprocessed once; frontend::PreprocessedUnit wraps them. Rows claim a fingerprint under a per-unit mutex because tokens hold Rc and cannot cross threads. Verified on zlib's full table, 16 targets: 2976 rows, 2544 fingerprints, 2416 programs, no fingerprint with two programs. Refined: 94 compiles per linux-x86_64 target (was 105), 1520 on 16 targets (was 1696), output byte-identical to the full table. Wall time did not measurably improve: 3.4-3.8s vs 3.4s on one target, 69s vs 60s on 16 targets, uninterleaved runs. Follow-up in slate-nfq8.8. Fixture: fixtures.merge/reused_preprocessing.c.
