# Vendor 5 recommended libc-test src_regression cases; found and fixed a real pthread_barrier_t ABI bug

_2026-09-08 10:49:38_

slate-b66b.5.5: vendored the 5 cases slate-b66b.5.3 recommended, using the same test.h+print.c merge recipe tools/filter-libc-test.sh already applies to functional/, into a new tests/fixtures.libc-test/regression/ (supported and unsupported) bucket mirroring the functional/api layout, plus tests/libc_test_regression_suite.rs (same three-test shape, minus the triage-report test).

Native admission (glibc, this host) rejected 2 of the 5 up front, so only 3 were actually vendorable here, reporting this rather than forcing them in.
sigaltstack.c fails to compile against this hosts glibc: glibc 2.34+ made SIGSTKSZ a sysconf() call, breaking the tests file-scope static char stack VLA declaration -- an upstream libc-test/glibc-version incompatibility, not a Slate issue.
fpclassify-invalid-ld80.c compiles, but its own assertions fail against real glibcs percent-La formatting of denormal-boundary x87 bit patterns -- the expected strings were authored against musls formatting, not glibcs.
Neither is vendorable through the existing native-admission gate on this host; noted in the triage doc rather than vendored broken.

tls_get_new-dtv.c dlopens its companion by a bare filename instead of the src/functional path convention every existing dlopen case uses, so it resolves via LD_LIBRARY_PATH instead. Generalized tests/support/mod.rs RunConfig with a new extra_files_dir field, default src/functional preserving every existing callers behavior via a manual Default impl, so a case can stage its companion at the run dir root instead.

tls_get_new-dtv.c initially crashed at runtime on both C and Rust sides with a futex facility error -- traced to a real pre-existing libc-shim bug: pthread_barrier_t in libc-shim bits/types.h was a plain one-byte-aligned struct instead of the union-with-align pattern every sibling pthread type uses, so real glibcs eight-byte-aligned barrier object was misaligned. Fixed the union plus align. Then added pthread_barrier_t and pthread_barrierattr_t size and align records to the shared ABI probe source (they were never in its family list at all, the actual gap that let this ship) and reran the native Rust libc_abi_matrix test, which immediately found 5 more real per-arch mismatches: pthread_barrier_t is 20 bytes on 32-bit arches not 32, and glibc aarch64s pthread_barrierattr_t is 8 bytes not 4. Fixed both with the same conditional union pattern already used for pthread_mutexattr_t and condattr_t. Full 8-target matrix now green, 4141 records, 0 failures.

This is exactly the kind of bug slate-b66b.5s premise predicted: runtime testing catches what compile-only ABI probing misses. Adding the missed fields to the static probe closes the same gap for future regressions.

Verified: cargo fmt clean, cargo clippy clean, full cargo nextest release profile libc green, 39 of 39, about 8 seconds. Checked cargo nextest release profile rewrites two pre-existing failures (gcc_dg_supported_tests_match_c and generated_differential over c11, setjmp_recovery cases, struct_field_2d_array, and others) -- none of the failing fixtures reference pthread or barrier, confirming they predate this change and are out of scope here.
