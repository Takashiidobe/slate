# slate-yar4.10 printf_format STDOUT_WRITER_EXTRA_NAMES: _unlocked stdio writers reordered against println!

_2026-11-18 09:20:36_

- bead: slate-yar4.10
- kind: bug
- area: crates/slate/src/backend/engine/printf_format.rs

Outcome: putc_unlocked, putchar_unlocked, fputc_unlocked, fputs_unlocked and fwrite_unlocked are now treated as stdout writers, so printf-to-println! rewrites flush around them and output order matches C.

Symptom: printf("a\n"); putc_unlocked('b', stdout); printf("c\n") piped to a file printed a, c, b: the println! was buffered by Rust's stdout and the unlocked C write bypassed it.

Reproducer:
    printf("a\n"); putc_unlocked('b', stdout); putc_unlocked('\n', stdout); printf("c\n");

Cause: STDOUT_WRITER_EXTRA_NAMES in crates/slate/src/backend/engine/printf_format.rs listed putc/putchar/fputc but not the _unlocked variants, so no flush was inserted around those calls.

Fix: added the five _unlocked names to STDOUT_WRITER_EXTRA_NAMES.

Regression test: crates/slate/tests/fixtures/stdout_unlocked_writers_order.c
