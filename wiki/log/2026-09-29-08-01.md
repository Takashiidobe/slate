# Accept too-strict operand rules from cxg.46 per flavor

_2026-09-29 08:01:02_

slate-parser-cxg.46. Verified each case with clang 22, gcc 16 and cl first.

- Conditional with pointers to incompatible types: all three accept. TypeResolver::conditional_pointers (shared by the typer, lowering and the checker) falls back to unqualified void * for clang (new -Wpointer-type-mismatch, default warning) and gcc (-Wincompatible-pointer-types, so still an error from c99 on, a warning in c89), and to the left operand's type for MSVC (C4133). The checker emits the warning. Both clang and gcc drop pointee qualifiers here (checked with _Generic).
- Ordered pointer/integer comparison (p < 1): clang and gcc warn. The typer accepts pointer against integer; lowering converts the integer to the pointer type the way equality already did. warn_comparison warns only for a non-null integer, matching both (no warning for p < 0).
- __builtin_bit_cast to a fixed array (clang; gcc has no such builtin in C): lowered as bit_cast into a temporary and decayed through Lowerer::read, the same path as a returned struct's array member. A VLA destination is still rejected, as clang does.
- Atomic fetch on a pointer object: fetch_rule takes the flavor. clang accepts a floating offset for add/sub, converted to ptrdiff_t; gcc accepts and/or/xor/nand, lowered as ptr_to_int, the bitwise op on size_t, then int_to_ptr (gcc -S confirms it operates on the address).
- TypeResolver::flavor accessor added.
- Fixtures: clang/linux/x86_64/ir_lenient_operand_rules.c, gcc/linux/x86_64/ir_lenient_operand_rules.c (c89, so the conditional is a warning).
- wiki/concepts/diagnostic-severity.md: pointer-type-mismatch row.
