# slate-j3by.23 needs_dispatch: C goto into MS asm keeps its entry jump

_2026-11-23 09:12:17_

- bead: slate-j3by.23
- kind: bug
- area: crates/slate/src/frontend/lowerer/control_flow.rs
- flavor: msvc
- target: i686

Outcome: C goto into a Microsoft asm block starts at the named entry label.

Symptom

ms_asm_entry_labels returned exit code 3 in translated Rust and 0 in C.
In c_to_asm(9), the translation ran `mov result, 1` and returned 10.

Reproducer

    int result = 0;
    goto inside;
    __asm {
      mov result, 1
    inside:
      mov eax, value
      add result, eax
    }

Cause

The IR retained both the goto and the EntryLabel. needs_dispatch only
recognized asm with outgoing goto labels. residual included the C goto
and left the target asm in straight-line lowering, so lower_asm received
no entry binding and omitted `jmp 2f`.

Fix

Recognize asm entry labels when finding dispatch regions. Graph::statement
already registers the entry edge and passes the selected binding through to
lower_asm; the same source now starts at `2:` and returns 9.

Regression test

Regenerated fixtures/msvc/i686/ms_asm_entry_labels.c after its runtime check
passed. It also covers a loop through an asm entry label and a block that
can jump back out to C.
