# ARM 'l'/'h' register constraints resolved

_2026-09-07 09:30:22_

slate-3f8g.4.16.1: added ARM 'l' (Thumb1 low regs r0-r7) to
parse_constraint_atoms as a Generic-reg atom, gated on
target_arch == TargetArch::Arm. Threaded TargetArch through
Constraint::parse/parse_reg_constraint/constraint_allows_generic_reg/
constraint_is_constant_only/strip_memory_marker so the ARM-only letter
can't leak onto other targets.

Key finding: no Thumb-mode tracking needed. Rust's ARM `reg` class already
narrows itself to r0-r7 whenever a function compiles Thumb1-only and expands
to r0-r12+r14 under Thumb2/ARM (confirmed via Rust reference + rustc
target-spec-json: armv7-unknown-linux-gnueabihf always carries +thumb2), so
`reg` is sound for 'l' the same way it's sound for bare 'r'.

'h' (Thumb r8-r15) needed no code change: it was already an unrecognized
atom, so Constraint::parse already falls through to Unsupported with a
clear diagnostic. Confirmed via real clang codegen that 'h' is a genuinely
separate register set (not a subset of 'reg'), valid under -mthumb but
rejected under -marm, and Rust has no register class for it at all (like
x86 'y'/'A') -- so erroring is correct, not just currently-unimplemented.

Added tests/fixtures/asm_arm_general_low_reg.c (+r/+l), generated with
update_filecheck.py --target ARMV7-GNU=..., passes arm-lowering and
arm-rewrites under qemu-arm-static. Skip-listed by name in
differential_aarch64.rs (no FileCheck-prefix auto-filtering there, unlike
tests/differential.rs). Wiki: new ARM section in inline-asm-support.md.
