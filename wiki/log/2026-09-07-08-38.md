# byte-sized Q/q abcd widen hack for asm inline output/input

_2026-09-07 08:38:55_

Implemented slate-3f8g.4.15.10: byte-sized operands under GCC's Q (always) or
q (32-bit target) inline-asm constraint now lower successfully instead of
bailing with `unsupported!`. Rust's reg_abcd class has no i8 arm, so
asm_reg_for_constraint's ByteAddressableAbcd/ByteAddressableGpr branches no
longer refuse operand_bits==8; the caller (intrinsics.rs) binds a widened,
uninitialized i32 temp through reg_abcd instead, seeding it from `value as u8
as i32` on entry (inputs/tied reads) and narrowing back via `widened as u8 as
OrigTy` after the asm block (register_output_exprs/asm_outputs read the
narrowing expression directly - no post-asm statement needed since it's a
pure read of an already-let-bound var).

Important correction from the bead's original plan: empirically verified
(via clang -O0 -S) that GCC/clang ALWAYS loads/stores a byte-typed "Q"/"q"
operand through the LOW byte alias (al/bl/cl/dl) regardless of what modifier
the hand-written template uses - the modifier only controls how the operand
NAME is rendered, not where the compiler's own data-movement code puts the
value. So `%h` on a genuinely byte-sized operand reads/writes a disconnected
register half in real compiled C (confirmed: `incb %h0` on a "+Q" byte
operand loaded via %al left the value completely unchanged). The widen hack
therefore only supports the `%b`/`:l` (low-byte) view; `%h` on a byte-sized
operand now bails via `unsupported!` rather than emitting incorrect
shift-by-8 glue, since no faithful translation exists for it.

`%h` continues to work correctly (via the existing, non-widened path) for
operands whose C-declared type is already >= 32 bits under "Q" - there the
whole register is genuinely populated and `ah` really is the true high byte;
confirmed differentially (asm_x86_high_byte_view_wide_operand.c).

New fixtures: asm_byte_abcd_widen_hack.c (tied output + separate input, both
%b/low-byte), asm_x86_high_byte_view_wide_operand.c (wide-operand %h
regression guard). Indirect/addressed (memory-deref) byte-sized abcd outputs
remain unsupported (bail) - out of scope, no post-asm write-back glue built.
