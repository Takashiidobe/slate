# slate-xw0x.11 test speed: translate_slate retranslated every fixture and each wine run cold-started wineserver; merge_filecheck moved to merge profile

_2026-11-17 21:31:39_

- bead: slate-xw0x.11
- kind: bug
- area: crates/slate/tests/support
- area: .config/nextest.toml
- flavor: msvc

Outcome: generated_differential runs in ~3s alone on a no-change run (was 21s) and ~13s inside the slate profile (was ~50s); merge_filecheck runs only in the new `merge` nextest profile.

Symptom: with merge_filecheck out of the profile, the slate profile was no faster, since generated_differential (50s in profile, 21s alone at 3 jobs) was the long pole. Alone it used only 34 CPU-seconds in 21s; more SLATE_TEST_JOBS barely helped (17s at 12).

Cause (verified with strace execve timelines and direct timings):
- Rust and C builds were already cached (0 rustc/clang compiles on a no-change run), but `support::translate_slate` re-ran `slate translate` for all ~800 fixtures every run: 12.8s wall at 3 jobs, 38 CPU-s. It also serves gcc-torture, gcc-dg and c-testsuite.
- The msvc fixtures run C and Rust exes under wine (74 runs). No wineserver stays up, so every run cold-started one: 0.7s per run vs ~8ms with a warm persistent server. That was a serial ~8s tail no job count could hide.

Fix (crates/slate/tests/support/mod.rs):
- `translate_slate` writes `<out>.translate-key` after a successful translation and skips the slate run when the key matches and the output exists. The key hashes the slate binary's size and mtime, the sysroot root path, the args, the fixture path and bytes, and every non-`.c` file under the fixture's directory (local headers, #embed files; hashed once per directory). Host and slate-sysroot headers are deliberately not in the key: they rarely change; delete target/difftest-generated (or rebuild slate) after updating them. Failed translations are not cached.
- `keep_wineserver_warm` (once per test process, before the first wine run): `wineserver -p30` then `wine cmd /c exit`, all stdio null. The null stdio matters: services.exe inherits the first wine's pipes and a piped caller hangs until the server exits.
- .config/nextest.toml: `default` and `slate` profiles exclude `project_merge::merge_filecheck`; new `merge` profile runs only it. AGENTS.md and wiki/concepts/differential-fixtures.md say to run `--profile merge` for --merge or tests/fixtures.merge/ changes.

Measured (no-change runs): generated_differential alone 21s -> 11.4s (translation cache) -> 2.4-3.8s (warm wine). Slate profile 18-19s; build_filecheck (19s) is now the slowest test. Editing comments_preserved.h changed its key and retranslated.

Limits: inside the profile the windows leg still takes ~7s (no-op cargo build 2s plus wine under contention). A header update under /usr/include or the sysroots does not invalidate cached translations.
