# pointer lattice: guard Vec->String specialization on write

_2026-08-28 12:49:08_

The earlier fix in this session made the Vec row of the pointer lattice
match regardless of W (owned buffers stay owned even when written through).
But specialize_string() unconditionally turned any Vec row with S set into
StringOwned, so a written, string-shaped owned buffer would now specialize
to String -- reintroducing exactly the UTF-8-validity problem the doc
already calls out for &mut [T]->&mut str (slate-y0qs.4.4), just on the
owned side instead of the borrowed side.

Fixed: specialize_string only converts Vec->StringOwned when !self.write;
a written Vec<T> stays Vec<T>. Broadened slate-y0qs.4.4 to cover this case
and to note the deeper gap: S ("string-shaped usage observed") doesn't
prove per-element UTF-8 validity even in the read-only case -- it's usage-
pattern evidence (strlen/strcpy/nul-check), not a value-domain fact. Real
fix needs a new fact tracking observed element validity/provenance, out of
scope for this session.
