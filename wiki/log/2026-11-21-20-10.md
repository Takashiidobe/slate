# slate-8ge7.24.10.3 structure-goto: backward goto to an earlier label becomes do-while or for(;;) loop on the IR

_2026-11-21 20:10:20_

- bead: slate-8ge7.24.10.3
- kind: rewrite
- area: crates/slate-analysis/src/transform
- area: crates/slate/src/frontend/lowerer

Outcome: backward gotos whose label is an earlier sibling become IR loops (`do … while` for a single trailing `if (c) goto L;`, otherwise `for (;;)` with `continue`), so retry loops and state-machine `for (;;) switch` functions with gotos lower structured instead of through lower_dispatch.

Gap: after .10.2 only forward gotos were structured; any backward goto still sent the whole function to lower_dispatch (zeroed slots, one big unsafe, dispatch rules).

Before (goto_backward_loop.c):

    let mut i: i32 = unsafe { core::mem::zeroed() };
    unsafe { ... '__slate_dispatch: loop { match __slate_state { ... } } }

After:

    loop { sum += i; i += 1; if i >= 5 { break; } }

Implementation (crates/slate-analysis/src/transform/structure_goto.rs, `wrap_loop`):
- For a `Label` at j, gotos may now sit in later siblings [j, end). If every goto to the label is in earlier or later siblings, the backward range is wrapped first, then the forward block as before.
- Range = label body + siblings up to the last backward goto statement. If the only backward goto is the range's last statement `if (c) goto L;` (no else), it becomes `do { range } while (c)`. The trailing Let/Temporary statements the condition reads (transitively) move into the condition's evaluation, so `while (--n > 0)` style conditions stay in scope (`condition_prefix`).
- Otherwise `for (;;) { range; break; }` with gotos retargeted to `continue`; a trailing `continue` is dropped and no `break` is added after a jump.
- Same bail rules as forward (declaration read after the range, cleanup/VLA locals, foreign case labels).

Lowerer (crates/slate/src/frontend/lowerer):
- `counted_loops` set renamed `direct_continues`; a `For` without increment joins it, so its `continue` lowers to `continue 'label` and no `'__slate_continue_N` block is emitted.
- `control_flow::endless`: a final `for (;;)` with no `break` to it counts as ending in return, so no `unsafe { core::mem::zeroed() }` fallthrough tail.

Fixtures: crates/slate/tests/fixtures.transforms/structure-goto/backward.c (retry, spin, restart, two_edges, entered, scoped) and state_switch.c (zlib inflate shape: `for (;;) switch (mode)` with fallthrough cases and `goto leave` from a macro, slate-f2zu.9.16). 13 tests/fixtures blocks and fixtures.release/constant_p_after_inlining.c regenerated; all now lower structured.

Limits:
- `do { … } while (0)` from a non-kept macro (one holding a goto) lowers as `loop { …; if true { break; } }`; IR transform is slate-f2zu.9.17.
- A loop whose body is a switch where every arm returns or continues (`classify` in goto_project_control_flow.c) keeps a dead `break;` and the zeroed fallthrough tail.
- Irreducible regions and labels with gotos from non-sibling positions still use lower_dispatch (.10.4).
