# slate-f2zu.14.15 asm constant_asm_operands: cleanup destructor with static-branch asm dropped by drop_unreferenced, unknown callee (guard(mmap_read_lock))

_2026-11-14 15:03:45_

- bead: slate-f2zu.14.15
- kind: bug
- area: crates/slate-parser/src/sema/asm_constants.rs
- area: tools/corpus/e2e.py
- corpus: linux

Outcome: above -O0, a cleanup destructor that reaches a static-branch asm (guard(mmap_read_lock)) is kept with its calls specialized, instead of being dropped and leaving the local's cleanup pointing at a missing function.

Symptom: arch/x86/kernel/alternative.c, kernel/futex/core.c and kernel/time/namespace_vdso.c failed lowering-barriers with `<invalid> ... unknown callee %N`. e2e.py reported them as `exit 1` because barrier_rows dropped 3-column `<invalid>` rows.

Reproducer (-O2, x86_64):
```c
struct key { int enabled; }; struct key k1;
static inline __attribute__((always_inline)) int branch(struct key *key) {
    asm goto("# %c0" : : "i"(key) : : yes); return 0; yes: return 1; }
static inline __attribute__((always_inline)) void release(int **p) { if (branch(&k1)) **p = 0; }
int guarded(int *x) { int *guard __attribute__((cleanup(release))) = x; return *guard; }
```
Before: `guarded: unknown callee %5` (release missing from the IR).
After: `release` is kept and calls `branch__const1`; `guarded` keeps `[cleanup=%release]`.

Cause: `Uses` in sema/asm_constants.rs recorded direct calls and binding reads but not `Variable::cleanup`. class_mmap_read_lock_destructor is always_inline and reaches a tracepoint static branch through mmap_read_unlock, so it was unresolved. `Redirect` already specialized the branch call in its body, but `drop_unreferenced` saw no reference to it (the cleanup is not a call) and removed it. guard(mutex) was unaffected because its destructor has no asm.

Fix:
- `Uses::statement` adds a `Let`'s cleanup target to `callees`, so it counts for unresolved propagation and as a reference in `drop_unreferenced`.
- tools/corpus/e2e.py barrier_rows reports `<invalid>` rows as kind `invalid`, with their scope and site.
- wiki/concepts/ir/asm.md records the rule.

Regression tests:
- crates/slate-parser/tests/fixtures/{clang,gcc}/linux/x86_64/ir_asm_cleanup_after_inlining.c
- crates/slate/tests/fixtures/x86_64/asm_immediate_cleanup_after_inlining.c

The three kernel TUs now lower with no barriers.
