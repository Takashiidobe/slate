# block-address diff dispatch: bridge through local store/load (pr70460)

_2026-09-05 06:59:53_

slate-os0h.3.1.5 was not a CIR frontend limitation: CIR happily emits
`#cir.block_addr_diff<@fn, "lhs", "rhs">` for `&&lhs - &&rhs` in a static
initializer, and slate's parser/lowerer already understood the attribute
(block_addr_labels, block_addr_globals, block_addr_element_ptrs).

The gap was narrower: `void *a = &&base + table[x]; goto *a;` stores the
resolved dispatch-state expression into a real local (`a`) before the
indirect goto reads it back. `lower_load`/`lower_ptr_stride` already
propagated `indirect_target_values` through a chain of SSA values, but
`lower_store` never bridged that value into the destination pointer, so a
later `lower_load` of `a` found nothing and fell back to opaque-pointer
placeholders -- silently producing an unreachable dispatch state instead of
an error.

Fix: track `indirect_target_places: BTreeMap<ptr, Expr>` in FunctionLowerer.
`lower_store` records it when the stored value already resolved to a target
expr; `lower_load` checks it (after `block_addr_dispatch_expr`) before
falling through to the generic path. Same mechanism as the existing
`block_addr_array_values` -> `local_block_addr_arrays` bridge for arrays,
just for the ptr_stride+alloca case instead of the GetElement case.

Verified against the 5 existing goto-* fixtures (20040302-1, 20041214-1,
920501-4/5, 980526-1) and computed_goto_label_delta.c -- no regressions,
since those either resolve inline or already had a bridge for their pattern.

pr70460 promoted to tests/fixtures.gcc-torture/. Closed slate-os0h.3.1.5.
