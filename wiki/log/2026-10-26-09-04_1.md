# Emulate clang -ffp-model=precise|strict|fast|aggressive

_2026-10-26 09:04:17_

slate-3amj.6: clang -ffp-model (compiler_args.rs, MathSwitch::Model). Each model first resets fast-math like -fno-fast-math (new MathOptions::reset_keeping_environment), keeping -frounding-math and trapping; slate's -fno-fast-math used to reset those too and now keeps them, as clang does. precise: contract on, range full. strict: precise + contract off, trapping, rounding-math. fast: unsafe math, no math-errno, no rounding-math, contract fast, range promoted, finite math off (no __FAST_MATH__, __FINITE_MATH_ONLY__ 0). aggressive: -ffast-math. fp_contract() tracks whether the contraction came from an umbrella (fast models, -ffast-math, -funsafe-math-optimizations), so a later -fno-unsafe-math-optimizations/-fno-fast-math restores the last -ffp-contract only then; precise/strict set it without counting. Checked against clang 23 -dM and -###.
Not modelled: -Ofast -ffp-model=precise, which clang turns into a hybrid (math-errno, contract fast, range basic); slate gives precise.
gcc and msvc reject -ffp-model. Fixtures: slate-parser clang/linux/x86_64/fp_model.c (11 prefixes), error fixtures for unknown models and gcc/msvc; slate promoted flag_fp_model_fast.c.
flag_fp_model_strict.c sits in fixtures.unsupported: the backend lowers rounding=environment arithmetic to plain Rust ops, which rustc folds in round-to-nearest. Filed slate-3amj.47 (noinline C shims compiled with -ffp-model=strict, inline asm later if the call cost matters; black_box is not sound against code motion).
