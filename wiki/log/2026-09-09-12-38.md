# slate translate --targets: matrix-compile + equality merge (nfq8.1)

_2026-09-09 12:38:20_

Added `slate translate --targets=<t1>,<t2>,...`: compiles once per target
against libc-shim's portable headers, then merges the resulting Programs by
structural Item equality instead of #if source-region membership. Items
identical across all targets emit once ungated; differing items get
#[cfg(target_arch = "...")] and are duplicated. No source-visible #ifdef is
needed -- proven on SYS_preadv (295 x86_64 / 69 aarch64), which has zero #if
chains in test.c; the divergence comes entirely from which arch-specific
libc-shim header gets included.

Verified beyond unit tests: built the generated Rust natively and with
`cargo build --target aarch64-unknown-linux-gnu`, ran the aarch64 binary
under qemu-aarch64-static -- same generated source, correct value per target.

Composes with the existing macro-#if axis without cross-product blowup
(tests/fixtures.cfg/target_and_macro_divergence.c): a user #ifdef and a
target-driven libc difference in the same file each get their own
independent #[cfg], not multiplied together. Found and fixed a real bug
getting there -- the merge's "no target gate needed" check was
`groups.len() == 1`, which broke when a macro-cfg'd item's two branches were
each themselves fully target-invariant (two distinct items sharing one key).
Fixed to check per-group `vis.len() == variants.len()`.

Closes slate-nfq8.1. Corpus-wide divergence survey (how often real fixtures
hit item-level duplication vs. clean boundaries) moved to slate-nfq8.2, since
it gates whether that stage's hoist-to-const work is worth building at all.
