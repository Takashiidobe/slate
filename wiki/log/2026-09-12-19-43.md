# Support \_Generic as an embedded primary expression (wf8.2.4)

_2026-09-12 19:43:59_

Removed parser.rs's duplicate top-level \_Generic special case (Expr::Generic / GenericAssociation in ast.rs), which only matched when the whole expression span was exactly \_Generic(...). All \_Generic now flows through const_expr::Parser::parse_primary's existing depth-aware ConstExpr::Generic, so it works embedded (e.g. \_Generic(x, int: 1) != 1). Also fixed a latent panic: DeclaratorParser::parse_declarator's grouped-declarator case used assert! instead of returning Err on a mismatched ), which crashed const_expr's speculative try_parse_type_name whenever a \_Generic controlling operand was a call expression (e.g. stdckdint-1.c's \_Generic(ckd_add(&a,1,1), bool: 1, default: 0)). Regenerated FileCheck expectations for gcc-dg/c23-bool-1.c, gcc-dg/stdckdint-1.c, and generic-statement-expressions.c. Verified via full before/after fixture diff (temporary catch_unwind instrumentation, reverted) that no other fixture regressed. Filed slate-parser-5cr for an unrelated pre-existing gap: C23 true/false not usable in #if without stdbool.h.
