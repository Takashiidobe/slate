# Fold pointer arithmetic and member addresses in integer constant expressions

_2026-10-16 17:10:33_

Closed slate-parser-6x05.43. The checker's constant evaluator (TypeResolver::constant_value_with_context) gave Unimplemented for pointer +/- integer, pointer difference, pointer comparisons and !p, and Rejected for &((T *)0)->m. clang, gcc and cl fold all of them in case labels, enumerators, bit-field widths, _Static_assert and array bounds. The checker has layout and sema/fold.rs does not, so the checker folds them: constant_pointer_binary handles ptr+-int (scaled by the pointee size, void and function pointees step 1), ptr-ptr (wrapped to the pointer width, divided by the element size), the six comparisons and &&/||; constant_place walks &-operands through ->, ., [] and * to an address plus ir type via offsetof_field. Results are an int_to_ptr of a constant or a plain integer constant, so lowering's fold needs no change. fold::pointer_address exposes the existing address evaluator. Unary ops other than ! on a pointer now give Rejected('nonconstant unary expression') instead of Unimplemented, since they are invalid C or non-constant. Fixture: clang/linux/x86_64/ir_pointer_arithmetic_constants.c, values hand-checked against struct layout and clang -fsyntax-only accepts it. Parser profile: 8257/8257 pass. Not done: static_assertion_error still prints an Unimplemented error as a rejection message; gcc and msvc fixtures not added.
