# gate x86-only aarch64 skips on real dejagnu directives

_2026-09-05 08:35:40_

differential_aarch64.rs's skip_reason() hardcoded 14 x86-only asm/intrinsics
fixture names in Rust. Replaced that with real dejagnu directives read from
the fixture files themselves: added target_clause_matches() (a real glob/
negation selector evaluator, tests/support/mod.rs) and
fixture_target_restriction(path, triple), which scans a fixture for a
`{ dg-do run { target x86_64-*-* } }` line and reports why it doesn't apply
to a given Rust target triple. Wired into differential_aarch64.rs::fixtures()
in place of the 14 removed skip_reason arms (the remaining arms are real
bugs -- slate-sdks.1/.2/.3 and the stat_struct bug -- not target
restrictions, so those stay in Rust).

Also folded fixture_clang_arg_overrides()/fixture_c_ref_std_override() (two
5-entry Rust tables in tests/support/mod.rs) into the same directive
mechanism: `{ dg-options "..." }` applies identically to both the CIR-
emission clang call and the C reference compile; `{ dg-additional-options
"..." }` applies only to the CIR-emission side, preserving the existing
asymmetry for the 3 fixtures that intentionally test optimization-dependent
lowering without changing the C reference's behavior.

Added the directives to the 19 affected tests/fixtures/*.c files via sed
(not Edit) since the project's comment-stripping hook fires on Edit/Write.
Regenerated gnu_asm_register_variable.c's FileCheck block via
update_filecheck.py -- its file-scope check now literally asserts the two
directive lines as forwarded /// doc-comments on fn main, since slate
forwards leading source comments onto the next item.

Verified: lowering, rewrites, and aarch64-lowering profiles for
differential/differential_aarch64 all pass; the aarch64 run's skip log now
attributes the 14 skips to the directive, not the Rust table.
