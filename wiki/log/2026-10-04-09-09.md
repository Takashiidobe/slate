# Compiler args: options declare their flavors (slate-parser-ivo1.1)

_2026-10-04 09:09:30_

- Filed epic slate-parser-ivo1 (parse compiler args once, validate, pass one typed configuration everywhere) with children: ivo1.1 flavor-aware options, ivo1.2 slate builds compile commands from slate-parser's typed parse instead of re-scanning argv, ivo1.3 one set of Dialect helpers for flavor, standard and target questions. slate-parser-asmblk and 6x05.36 now depend on ivo1.1; ivo1.2 is related to slate-i3nv.
- ivo1.1: ParsedCompilerArgs.present (BTreeSet<Opt>) became occurrences: Vec<(Opt, argument)>. Opt::accepted_by is an exhaustive match giving each option's flavors, and CompilerArgParser::parse runs check_flavor right after the full parse, so the flavor is final even when --flavor comes after the option. A missing option is 'invalid compiler argument <arg>: unknown option for the <flavor> flavor', which matches clang's 'unknown argument' and gcc's 'unrecognized command-line option'.
- No selector pre-scan: it can't tell an option from another option's separate value (-include <file>) without duplicating the option table.
- Replaced by table entries: msvc_rules' UNSUPPORTED list (msvc branch is now empty), gcc's 'stack alignment is a Clang option', clang's 'preferred stack boundary is a GCC option', and Opt::Outline from 6x05.21.1 (now CLANG_CODEGEN_ONLY_M_FLAGS / Opt::ClangCodegenOnly). gcc's MS-mode rule stays a rule: gcc has the flag, slate doesn't emulate it.
- 9 error fixtures re-expected (message only; the old msvc message said 'MSVC stack alignment options: MSVC does not support O' for -O2). Added error/gcc stack-alignment-clang-only.c and error/clang preferred-stack-boundary-gcc-only.c; both oracles reject those flags. mimalloc still 28/28. compiler-arg-rules wiki updated.
