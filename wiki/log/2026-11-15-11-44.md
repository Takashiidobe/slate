# slate-f2zu.14.34.14 Codegen::abi: freestanding crate prints C-unwind as C, so panic=abort emits no .gcc_except_table/.eh_frame orphan sections (vmlinux link)

_2026-11-15 11:44:21_

- bead: slate-f2zu.14.34.14
- kind: feature
- area: crates/slate/src/backend/codegen.rs
- area: crates/slate/src/main.rs
- area: crates/slate/src/backend/rust_ast.rs
- corpus: linux

Outcome: a freestanding (no_std, `Runtime::Core`) crate prints every `*-unwind`
ABI as its non-unwinding spelling (`extern "C"`, `"sysv64"`, ...), so
panic=abort no longer gives callers abort landing pads, and the
`.gcc_except_table`/`.eh_frame` orphan sections are gone from the vmlinux link.

Gap and why it mattered: with panic=abort, rustc gives every function that calls
a C-unwind function an abort landing pad, which emits `.gcc_except_table.*` and
`.eh_frame`. The kernel links with `--orphan-handling=error`, and its linker
script places neither section:
`unplaced orphan section .gcc_except_table._RNv..blk_done_softirq from vmlinux.o`.
C-unwind exists for pthread_cancel forced unwinds through translated frames
(wiki/log/2026-10-01-09-28.md), and that cannot happen in a core-only crate.

Before (crates/slate/tests/fixtures/freestanding_no_std.c):

```rust
extern "C-unwind" fn main() -> i32 {
```

After:

```rust
extern "C" fn main() -> i32 {
```

Implementation:

- `rust_ast::Program::no_unwind`. The lowerer sets it to `!runtime.has_std()`.
  `translate-project` (main.rs) overrides it on every output file with the
  crate-wide `freestanding` decision, the same one that adds `#![no_std]`, so fn
  pointer types agree across units.
- `Codegen::abi` prints `Abi::foreign_block()` instead of `spelling()` when
  `no_unwind` is set (except `Abi::Rust`). The lowering and the interproc passes
  still see `Abi::CUnwind` internally, so `is_path_bindable` and the convention
  checks are unchanged.
- The one remaining `.eh_frame` comes from a compiler_builtins member, and
  tools/corpus/kernel_link.py already strips it.

Fixtures (FileCheck regenerated, no new fixture): freestanding_no_std.c,
freestanding_void_main.c, nostdinc_no_std.c, whose `main` went from C-unwind to
C.

Measured earlier on the block shard (sed C-unwind->C): all 175
`.gcc_except_table` and 33 of 34 `.eh_frame` sections were removed.

Limits: a mixed crate (some hosted units) keeps C-unwind in every unit,
including the core ones.
