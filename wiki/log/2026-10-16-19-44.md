# remove_mut rule demotes unneeded let and parameter mut

_2026-10-16 19:44:57_

slate-5vj0.5.2. The lowerer emits every binding as 'let mut' (transliteration), and inline_temps, bool_ternary and return_cleanup::slot only match immutable lets, so inline_temps never fired. Rather than teach the lowerer mutability, a new worklist rule remove_mut (priority 0, Let nodes) clears 'mut' on a let with an initializer when no def-use neighbor mutates it: no assignment rooted at the binding (through fields/indexes, not derefs), no &mut / addr_of_mut! / mutable ArrayPtr of it, no method call on a non-scalar place rooted at it (prims, raw pointers, fn pointers and refs take self by value), no macro taking it as a place; inline asm, atomics, LetIf and shadowing count as mutation. demote_params applies the same test to parameters after the worklist settles (rename_param still ORs mutability back in). Written fresh for the arena, not ported from the old salsa RemoveMut.

Follow-ons: raw_ptr_alias matched only 'let mut' pointer lets and went to 0, so it now ignores mutability. inline_temps counted pointer and integer arithmetic methods (offset, add, sub, cast, wrapping_*) as calls, blocking 'let t = s; s = t + *a.offset(i)'; they are now pure, which gives 's += ...'.

Coverage: remove_mut 9866 hits in 1165 fixtures, inline_temps::late 0 -> 4889 (678 fixtures), compound_assign 223 -> 1297, effectful_forward 0 -> 11. bool_ternary is a separate shape mismatch (int ternary compared with != 0), filed as slate-5vj0.5.9; inline_temps const_args/asm_output still idle. slate profile 17/17; 61 fixture checks regenerated.
