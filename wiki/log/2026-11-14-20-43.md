# slate-f2zu.14.30 deref_nullptr: macro called with NULL whose body derefs it behind a null check rejected by rustc; units now allow deref_nullptr

_2026-11-14 20:43:49_

- bead: slate-f2zu.14.30
- kind: bug
- area: crates/slate/src/frontend/lowerer/places.rs
- area: crates/slate/src/frontend/lowerer.rs
- area: crates/slate/src/main.rs
- area: crates/slate/src/backend/rust_ast.rs

Outcome: a unit whose IR dereferences a null pointer constant (a macro called
with NULL whose body does `if (p) *p = v` or `p && p->f`) now gets
`#![allow(deref_nullptr)]`, carried to the crate root in project mode, so rustc
accepts the dead `*std::ptr::null_mut()`.

Symptom (linux check stage, drivers_pci: 4, net**packed: 12 errors):
`dereferencing a null pointer: this code causes undefined behavior when executed`.
drivers/pci PCI_FIND_NEXT_CAP inlined with a NULL prev_ptr gave `if
null_mut::<()>() != null_mut::<()>() { \*null_mut::<u8>() = **prev_pos;
}`; net/wireless trace.h CHAN_DEF_ASSIGN macro_rules called with `null_mut::<cfg80211_chan_def>()`expands`(\*$chandef).chan`.

Reproducer: #define ASSIGN(d, e) do { if ((d) && (d)->chan) (e)->band =
(d)->chan->band; } while (0) ASSIGN((struct def _)NULL, e); #define
FIND(prev_ptr) ({ ... if (prev_ptr) _(prev_ptr) = \_\_prev; ... })
FIND((unsigned char \*)NULL);

Cause: rustc's deny-by-default `deref_nullptr` is a late HIR lint that fires on
`*ptr::null_mut()` even inside `if false`, and inside a macro expansion where
the null is only at one call site. Folding the null comparison cannot remove the
macro_rules case, so the allow is the faithful translation: the C is dead, and
UB if it ever ran, same as the Rust.

Fix:

- `rust::Lint::DerefNullptr` ("deref_nullptr").
- `places::is_null_constant` (peels Convert and MacroArg to ValueKind::Null);
  `lower_place` on `PlaceKind::Deref` of such a pointer sets
  `Dependencies::null_deref`, which emits the unit allow.
- `write_project_crate` now carries a set of lints
  (SuspiciousRuntimeSymbolDefinitions, DerefNullptr) from unit CrateAttrs to
  lib.rs or the executable root, replacing the runtime-symbols-only flag.

Regression test: crates/slate/tests/fixtures/null_deref_macro_args.c (do/while
and statement-expression macros called with a pointer and with NULL).

Kernel: re-translated only drivers_pci and net\_\_packed in
~/slate-translated/slate-linux; cargo check is clean for both (4 and 12 errors
to 0).

Limits: a null base reached through `PlaceKind::Index` (`((T *)0)[i]`) is not
flagged. See: slate-f2zu.14.29, slate-f2zu.14.27
