# -m[no-]outline accepted for clang; builtin catalog pointer-to-vector params; mimalloc and libdeflate join the trophy case

_2026-10-04 08:50:35_

- mimalloc passes -mno-outline for clang builds and every TU was rejected as an unknown option. clang accepts -moutline/-mno-outline on every target without changing predefines; gcc rejects it. New Opt::Outline: parsed and ignored for clang, rejected by gcc_rules ('moutline is a Clang option') and msvc_rules. It is not in ignored_option because that list is flavor-independent. Fixtures clang/linux/x86_64/outline_flags_ignored.c, error/gcc/linux/x86_64/outline-clang-only.c. Closed 6x05.21.1.
- generate_clang_builtins.py parsed clang's _Vector<64, char const *> as a vector of 64 const char pointers. Clang's emitter applies qualifiers and pointers written inside _Vector<> to the vector (old .def spelling V64cC*), so the parameter is ptr<const vector<i8, 64>>. Vector::vector now splits the element tokens at the first * or &, moves the suffix after the vector, and puts base qualifiers on the vector. Regenerated clang_builtins.rs from the same llvm-project: 94 parameter types change (masked loaddqu/storedqu, expand/compress loads and stores) and nothing else. Every call to these builtins was previously rejected, so no accepted program changes. Fixture clang/linux/x86_64/builtin_pointer_to_vector_param.c. Closed 6x05.23.1.
- mimalloc v3.5.3-1-g31d034d9 28/28 and libdeflate v1.26 25/25: added to the trophy table, closed 6x05.21 and 6x05.23.
