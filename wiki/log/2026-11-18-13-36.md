# slate-5q63.20 slate-cargo-toml: generated Cargo.toml and .cargo/config.toml built from typed serde structs, not format! templates

Outcome: every generated Cargo.toml and .cargo/config.toml is built from typed serde structs in the new `slate-cargo-toml` crate and serialized by `toml`, instead of format!/push_str templates.

Gap and why it mattered:
Manifests were assembled as strings: `crate_manifest` in crates/slate/src/main.rs (10 args,
`#[expect(too_many_arguments)]`), `BuildTarget::write_config`, the slate-libc-gen probe crates,
and tests/support `generated_crate_manifest` plus `.replace("path = \"src/lib.rs\"", ..)` on the
vendor templates. Quoting was hand-rolled (`"\"{flag}\""`, `{:?}`), so a rustflag or path with
`"` or `\` produced broken TOML, and the test manifest had drifted from the real one.

Before (build_target.rs):
    let mut config = format!("[build]\ntarget = \"{}\"\n", target.triple);
    config.push_str(&format!("rustflags = [{}]\n", flags.join(", ")));

After:
    CargoConfig { build: Some(BuildConfig { target, rustflags }), unstable: ... }.to_toml()

Implementation:
- crates/slate-cargo-toml: `Manifest`, `Package`, `Lib`, `Dependency` (untagged Version |
  Detailed), `Profile` (with per-package overrides), `LintTool`/`LintLevel`, `CargoFeature`,
  `Edition`, `Panic`, `CargoConfig`/`BuildConfig`/`UnstableConfig`/`StdCrate`. `Manifest` and
  `Package` keep unmodeled keys in a `#[serde(flatten)] extra: toml::Table`, so vendor templates
  (libc, num-complex, slate-support) round-trip losslessly.
- main.rs: `crate_manifest(package, lib_crate_types)` builds the base; the translate path then
  applies `make_manifest_freestanding` and `add_manifest_rustflags`, and inserts cc / slate-blocks /
  features. `cargo-features = ["profile-rustflags"]` is derived from `Profile::uses_rustflags`.
  The always-empty `[[test]]` targets argument went away with the old signature.
- tests/support/cargo_toml.rs: `read_manifest`, `render_manifest`, `read_cargo_config`,
  `config_rustflags`, `render_package_profiles`. differential.rs asserts on typed config fields;
  project_merge.rs renders profiles through the helper instead of scanning `[profile.` lines.

Output change: dependencies are now `[dependencies.<name>]` tables, keys are sorted, and the merge
fixtures print `[profile.dev.package."<crate>"]`.

Limits: the `toml` serializer emits a child table before its parent header when an earlier
sibling is an implicit table; harmless, and the merge-test renderer serializes one profile per
document to keep the fixture readable. tools/corpus/e2e.py still joins strings (slate-5q63.21).
