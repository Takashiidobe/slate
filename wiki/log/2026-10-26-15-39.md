# Lower __builtin_object_size at clang -O2 semantics

_2026-10-26 15:39:53_

slate-yar4.1: __builtin_object_size / __builtin_dynamic_object_size are now CustomBuiltin::ObjectSize (sema/builtins.rs, typer.rs checks a pointer and a type in [0, 3], expression.rs object_size_builtin). sema/object_size.rs folds what clang's tryEvaluateBuiltinObjectSize folds: declared objects, string and compound literals (whole object), members of any base including p->m (closest sub-object), constant pointer offsets; arithmetic out of the sub-object, or stepping a non-array sub-object by another element size, drops the sub-object; type 1 on a trailing array of an unknown base is not folded, with the trailing-array rule taken from -fstrict-flex-arrays (closes slate-3amj.22). Side-effecting arguments give the unknown constant unevaluated; unfolded type 3 is 0 (gcc flavor defers to LLVM). The rest becomes intrinsic llvm.objectsize(p, min, false, dynamic), lowered by slate's existing intrinsic path, so rustc resolves p = local and malloc(n) like clang -O2 (user decision: target -O2, not -O0). release_build_differential now builds the C oracle at -O2 with the fixture's dg-options. Fixtures: promoted constant_object_query_ops.c, dynamic_object_size_ops.c (optimizer-dependent lines moved to fixtures.release/object_size_optimized.c), gnu_builtins_core.c (setjmp guarded to x86; clang rejects it on aarch64), new object_size_subobjects.c; flag_strict_flex_arrays.c moved to fixtures.release; parser fixtures builtin_object_size.c and error builtin-object-size-type.c. Known gap: static initializers using __builtin_object_size are not folded through constant_value. Locals over-aligned to 16 are padded by slate, so LLVM sees the padded size for unknown-pointer queries.
