# Multi-TU slate translate-project; chibicc self-hosts as Rust

_2026-10-01 10:07:41_

slate-p58o.7.7: translate-project --frontend=slate translates compile_commands projects through slate-parser.

- Each TU lowers to its own module (root TU defining main -> src/main.rs, others -> mod <stem>).
- LowerOptions { export_symbols, imported_commons }: external-linkage definitions get #[unsafe(no_mangle)] (functions also C-unwind ABI, inline_only excluded); undefined symbols stay in extern "C" blocks, so the linker resolves cross-TU references exactly like C.
- -fcommon tentative definitions: the driver picks one owner per symbol (a strong definition wins, else the first TU); other TUs import it as an extern static.
- TUs parse sequentially: ir::Module is !Send because Span.macro_origin is Rc (bead filed to switch to Arc).
- compile_commands normalize now drops -g*; -O stripping moved to the CIR consumer so slate-parser keeps -O (__OPTIMIZE__/__OPTIMIZE_SIZE__).
- Bit-unit structs are emitted in a private __slate_bits inline module: the bitfields macro's expansion binds locals (i, j, bits, value, offset, length) that collided with C statics (chibicc's function-local static int i). Promoted gcc-torture 930126-1.
- chibicc_suite runs through slate and is in the slate nextest profile. All fixtures but builtin (gnu23) hit the unprototyped-definition barrier and moved to unsupported (slate-p58o.7.11).

Result: ~/c-corpus/chibicc translates with zero barriers, the crate builds, and the Rust chibicc passes make test (41/41 + driver.sh) and test-stage2 (self-compiled chibicc passes 41/41 + driver.sh). Verified manually in a scratch copy; not yet an automated test.
