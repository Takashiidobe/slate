# Naked functions as FunctionSemantics::naked

_2026-09-27 08:41:35_

slate-parser-25m.17. __attribute__((naked)) (on any declaration, merged via
FunctionDeclarations) now sets FunctionSemantics::naked, printed [naked]. Fallthrough is ub
(clang emits unreachable after the body). Asm statements lowered while
Lowerer::in_naked_function leave options None, since naked_asm! takes no options.

Scope changed from the ticket: it said 'naked and body is a single basic asm'. Oracle
(clang 22, gcc 16): clang accepts any number of asm statements, basic or extended with
non-parameter operands ("i"(42)), and null statements; it rejects other statements and
parameter references. gcc accepts anything. All clang-accepted shapes fit one naked_asm!
(join templates; i operands become const/sym). Keying the kind on body shape would silently
give other naked functions a prologue, so it keys on the attribute alone. We do not add
clang's errors (permissive); the emitter must still check the body is asm-only.

Fixture: sema/ir_naked.c (single basic, two basics, const operand, naked prototype then
plain definition, normal function with asm). Regenerated optimization-attributes.c and
sema/unknown_attributes_clang_{linux,windows}.c for the new [naked].
