# Lift type, field-name and callee macro arguments

_2026-11-01 13:50:02_

slate-f2zu.9.5.12.7: MacroStructure::of now keeps expansions whose arguments are types, names, callees or call-argument lists; only Statements, Decl and Split still strip. Probe of 14 macros went from 0 lifted to 12, same output as C.
Types: the parser records each type argument's TypeName (TranslationUnit.macro_type_arguments, skipping spellings with { or (). Sema resolves it when the expansion opens into CTypeTable.macro_type_arguments. finish_macro_site replaces that Rust type in lets and non-literal casts with $T:ty, and in the identity key's hole types. SWAP(int/long/my_uint/struct pair) is now one template.
Names: MacroCover::Name carries the identifier; field accesses become $f:ident, via Expr::MacroName. Substituting by equality is sound because filling a parameter gives back that site's body; a parameter with no occurrence is dropped, leaving the concrete spelling (sizeof(T), struct tag, bit-field).
Callees: a hole on a function designator made calls indirect ($f.unwrap()), so callee() peels MacroArg and keeps Callee::Direct, with the name in the body. A function pointer stays $f. Call lists: each element is its own $args__N, so a different count is a different template.
Bug found by the self-check: a bit-field write with a hole value lowers through a temporary inside a template but not inline; macro_keep keeps those inline.
Known cost, noted on .13: printf-bodied templates gate per target with identical final text, and hole types split otherwise identical templates (SET_FIELD). Left for .8: macro_params' word scanner and the List shape.
Fixture: fixtures.merge/macro_arguments.c. Run: project_merge 5/5 and parser macro_ fixtures 12/12; clippy and fmt ran after those with no rerun. Not run: slate and parser profiles, validate_merge, zlib translate, so the zlib lift count is unmeasured.
