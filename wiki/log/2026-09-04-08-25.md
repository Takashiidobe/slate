# Per-fixture system-library linking (slate-3f8g.5.12)

_2026-09-04 08:25:27_

Added tests/fixtures.syslink/: a new directory-per-fixture bucket (main.c +
sibling libs.txt, one system library name per line) for fixtures that need
an extra -l<lib> on both the C and Rust sides. Distinct from tests/fixtures.link
(native .o cross-TU linking) and tests/fixtures.multi (multi-TU project
semantics) -- neither of those names fit "needs a companion system library".

New tests/syslink.rs harness reads libs.txt, appends -l<lib> to the C compile
via compile_c_multi_with_std_include_and_args, and builds the Rust side with
a new support::compile_rs_cargo_with_syslibs. That helper gives each fixture
its own Cargo crate (like chibicc/cross_tu, not differential.rs's shared batch
crate), so the build.rs it writes emits cargo:rustc-link-lib=<lib> scoped to
just that one binary -- the batched differential crate can't do this without
linking every fixture in the run against every declared lib.

Proven with fixtures.syslink/gnu_crypt (crypt(), -lcrypt): links and
differentially matches C. crypt_r stays out -- slate-3f8g.5.11's shim
struct crypt_data (260B vs libxcrypt's 32768B) would smash the stack.

Scoped to tests/ only. The real `slate translate-project` CLI has no
extra-library mechanism; adding one there was out of scope for slate-3f8g.5.12.
