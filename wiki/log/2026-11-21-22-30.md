# slate-8ge7.24.11.4 loop lowering: while/for/do-while emit Rust while and only used labels; delete loop_to_while

_2026-11-21 22:30:33_

- bead: slate-8ge7.24.11.4
- kind: rewrite
- area: crates/slate/src/frontend/lowerer
- area: crates/slate/src/backend/engine/rules

Outcome: C while/for/do-while lower straight to Rust `while`/`loop` with only the labels they need, and the loop_to_while rules (LoopToWhile, LoopElseBreakToWhile) are deleted.

Before (C `while (k < 8) { k++; switch (n + k) { case 5: continue; case 9: break; } total += 10; }`, lowerer output that rules then cleaned up):

    'brk: loop { if !(k < 8) { break } 'cont: { k += 1; match .. { 5 => break 'cont, 9 => break 'brk, .. } total += 10; } }

After (lowerer output, final Rust):

    while k < 8 { k += 1; match n + k { 5 => { continue; } 9 => { break; } _ => {} } total += 10; }

Rule (crates/slate/src/frontend/lowerer/statements.rs, Statement::While/For/DoWhile):
- `while` with no hoisted condition statements -> Stmt::While; with them, `loop { prefix; if !c { break } { body } }`. C continue is a direct `continue` (it re-tests the condition), so no continue block.
- `for` with increment keeps a continue labeled block only when the body continues this loop (continue_block); otherwise a Scope. A head condition without hoisted statements makes it a `while`.
- `do`/`while` keeps the continue block only when used.
- structure::label_needed keeps the break label only when a jump to it sits under a nested loop or labeled block, or the body has statement expressions (stmts_have_stmt_exprs, same guard as label_elide::drop_loop_label); otherwise it unlabels every jump.
- lower_exit_condition lost its `head` flag (it only existed so LoopToWhile could recover `while c`).
- A head `if (c) break;` the C wrote stays `loop { if c { break } .. }`: faithful lowering, no rewrite the source did not do.
- lower_dispatch (structure.rs tree) emits `while` for its own loop headers (header_test), since there the C wrote a for/while that dispatch took apart (goto_backward_into_loop, x86_64/asm_goto_loop_exit_label keep their old output, including `for i in 0..3`).
