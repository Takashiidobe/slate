# K&R (old-style) function definitions

_2026-09-13 13:17:30_

Added support for parsing K&R/old-style C function definitions, e.g.
`int uname(name)\n  struct utsname *name;\n{ ... }`.

Two-part fix in src/parser.rs:

1. signature_node_span() now detects when a top-level parenthesized list
   consists only of bare identifiers that aren't typedef names (helper
   bare_identifier_names()). When it does, it no longer stops the
   signature span at the first top-level `;` (that would be one of the
   K&R parameter declarations) and instead keeps scanning until the real
   `{`. Without this, the top-level dispatcher misclassified the whole
   `name(x) type *x; {` blob as a plain declaration statement and choked
   on it.
2. parse_function() now special-cases that same bare-identifier-list
   parameter form: it parses the identifier list itself (skipping
   DeclaratorParser::parse_parameters, which would otherwise mis-treat a
   bare identifier as a type name), then parse_kr_parameter_declarations()
   consumes the `type declarator;` lines between `)` and `{`, matching
   each declarator's name (via Declarator::name()) back to the K&R
   parameter list. Any parameter left undeclared defaults to implicit
   `int`, per C89.

No new AST variants were needed -- Parameter/Declarator already support
this shape (Some(Declarator::Name/Pointer/Array...)).
