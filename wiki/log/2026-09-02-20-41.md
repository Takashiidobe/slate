# Fix structure_dispatch duplication-budget miscounting raw temps

_2026-09-02 20:41:48_

structure_dispatch (switch-fallthrough recovery, priority 1) runs before compound_assign/inline_temps (priority 41-70), so arm bodies are still raw un-folded arena statements when rebuild() counts tail-duplication cost: out += N is 4 nodes (let _v=N; let _v=out; let _v=_v+_v; out=_v;) not 1. MAX_DUPLICATED_STMTS=24 was gated on this inflated count, so switches with only a few real duplicated source lines (grouped fallthrough arms plus a non-tail if-break, e.g. case 1: case 2: ...; case 3: ...; if (cond) break; ...; default: ...; case N:) blew the budget ~4x faster than intended and silently fell back to the untouched '__switchN: loop trampoline -- a real, reproducible recovery bailout, not a rounding edge case.

Fix: duplicated count now skips Stmt::Let bindings whose name is a compiler temp (_vN, via the existing temp_index() helper) -- is_compiler_temp_let() in structure_dispatch.rs. Only statements a human reading the C source would recognize count against the budget. structure_dispatch.rs:222,345-349.

Added tests/fixtures/switch_torture.c: a wide-range convoluted switch (negative and 500-wide case ranges, grouped scalar+range or-patterns, two independent non-tail if-breaks, default mid-chain, tail fallthrough with no explicit break) exercising this exact combination, differentially verified over x in -600..1000 before adding FileCheck blocks via update_filecheck.py. rewrites profile: 92/92 passed, 0 regressions.

Noted but not fixed: duplicated copies of an if-condition's constant operand (e.g. x % 2 == 0) sometimes don't get re-inlined by later cleanup passes the way the primary arm's copy does (let _vN: i32 = 0; if x % 2 == _vN). Cosmetic, not correctness -- worth a follow-up bead if it recurs elsewhere.
