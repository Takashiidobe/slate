# Apply declarator-position type attributes to their own declarator

_2026-09-25 21:39:27_

slate-parser-dyd.61: the parser folded vector_size, ext_vector_type and mode from every declarator of a declaration into the shared specifier. So in 'int x, y __attribute__((mode(QI)));' x changed too, and an attribute inside declarator parentheses ('int (__attribute__((mode(QI))) x)') was ignored.

- The fold helper moved to ast.rs as TypeSpecifier::with_type_attributes, alongside Attribute::is_type_attribute and Declarator::grouped_attributes.
- parse_declarator_list now folds only specifier-position attributes, which apply to every declarator. Parameters and type names still fold every attribute, since they have a single declarator.
- New TypeResolver::resolve_declarator (and Lowerer::resolve_declarator_type) wraps a copy of the specifier with that declarator's own type attributes (grouped, leading and trailing) before resolving. Used for object and typedef declarations (module.rs), record fields, the typedef type view, and the assertion pre-pass.
- Verified against clang AST: globals, locals, statics, typedefs and fields, attributes before or after a later declarator, grouped attributes, vector_size followed by mode, and scoped sizeof(struct S) in a local declarator's vector_size. The existing mode-on-pointer error still fires.
- New fixture tests/fixtures/declarator_type_attributes.c. No existing fixture changed.
- Filed slate-parser-dyd.62: validate.rs rejects enum constants in aligned/vector_size operands (pre-existing).
- ast-spec updated; the known-gap note is removed.
