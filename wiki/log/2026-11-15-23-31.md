# slate-f2zu.14.40.1 translate-project: -ffreestanding crates get #![no_builtins] so strlen's loop is not rewritten into a call to itself (kernel boot hang, strlen = ud2)

_2026-11-15 23:31:10_

- bead: slate-f2zu.14.40.1
- kind: bug
- area: crates/slate/src/main.rs
- area: crates/slate/src/backend/rust_ast.rs
- area: crates/slate/src/frontend/lowerer.rs
- corpus: linux

Outcome: a translate-project crate containing any -ffreestanding unit
(module.hosted == false) gets #![no_builtins], so LLVM no longer turns a
strlen/memset loop into a call to the function itself.

Symptom: the translated kernel hung right after 'Booting the kernel'. lib strlen
and seq_buf_puts compiled to `endbr64; ud2`; the early exception printer called
strlen, trapped, and looped on #UD.

Reproducer (minimal C, -O2 -ffreestanding, built as a staticlib):

```c
__attribute__((noinline)) static size_t count_bytes(const char *s) {
  const char *sc;
  for (sc = s; *sc != '\0'; ++sc)
    ;
  return sc - s;
}
size_t strlen(const char *s) { return count_bytes(s); }
```

Before: count_bytes became `jmp strlen`, and strlen called count_bytes, so it
recursed until the stack overflowed (on the kernel target it folded to ud2).

Cause: LLVM loop-idiom recognition rewrites the loop into a libcall. It skips a
loop inside a function that is itself named strlen, but the kernel's exported
strlen is an asm alias of a mangled Rust fn, so the guard misses. clang does not
do this because -ffreestanding implies -fno-builtin; slate had no equivalent.

Fix: rust_ast::Program.no_builtins (set from !module.hosted in the lowerer),
CrateAttr::NoBuiltins, emitted by translate-project on the crate root when any
program has it (main.rs). Crate-wide on purpose (user choice): in the kernel's
lib shard only lib/string.c is -ffreestanding, so the other units lose libcall
folding too. llvm.memcpy/memset intrinsics, struct copies and ptr::copy are
unaffected.

Regression test: crates/slate/tests/fixtures.library/freestanding_no_builtins.

Hand-tested on ~/slate-translated/slate-linux (lib shard edit + rebuild +
kernel_link.py, about 1 minute): strlen is a loop again and boot gets to the
next blocker.

See: slate-3amj.37 (pointer wrap, same session), slate-f2zu.14.40.2 (next boot
blocker).
